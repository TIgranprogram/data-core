# Рабочая панель счёта — 2026-11-03

Класс L: единый сценарий снабжения с проверкой архитектуры, только PWA и эталоны UI; backend/API/данные не меняются. Лимит: один architect-проверяющий, один frontend-исполнитель, один designer-проверяющий. Координатор — основной читатель аудита, QA и выпуск. Базовая версия v1.481.

## Запрос

Клик по самому счёту внутри сгруппированной заявки открывает правую панель именно этого счёта. Внутри — позиции таблицей, быстрая разрешённая правка и сохранение, понятное добавление. Пользователь не увидел обещанного улучшения правого интерфейса — нужна заметная, но каноническая иерархия, не перестановка прежних полей.

## Подтверждённые находки до правки

- requests.js:335–340 и kit/board.js:170–188: заголовок счёта — только сворачивание группы, ссылки на счёт нет; таблица requests.js:294 показывает номер некликабельным span.
- invoices-tab.js:139–164: счёт раскрывается под строкой, не панелью. Позиции191–286 — список вместо таблицы; внутреннее `const actions=[]` затеняет импортированную actions-фабрику (строка224), потенциальный runtime TDZ при editable-счёте.
- invoices-tab.js:200 вычисляет блокировку только по видимым received; API get возвращает authoritative receiptBoundaryAt в документе счёта (но не вычисляет lockReason). Скрытая приёмка/отменённый приход не должны разблокировать интерфейс; partial запрещает финансовую правку.
- addPositions168–187 — modal и первые200 строк без листания/поиска; paid-add требует причины, удаление оплаченной строки запрещено. partial-счёт менять целиком нельзя (API assertWhole).
- request-step.js:319–388 — отдельная дублирующая форма счёта внутри заявки; пути редактирования надо объединить.

## Решение

Единая маршрутизируемая карточка `of=invoicecard&open=<invoiceId>` через main.js lazy + штатный openCard, без прямого второй drawer поверх первой. Группировка: название счёта — отдельная ссылка на панель, сворачивание остаётся отдельным действием. Те же ссылки — таблица заявок, вкладка «Счета», краткий блок счёта в заявке. Фильтры и позиция списка не сбрасываются.

Вид панели: понятный заголовок «Счёт №…»/дата/поставщик, статус; строка цифр количество/текущая сумма/исходный факт оплаты с соблюдением money. Открытая секция «Позиции» — kit.table с названием, количеством и единицей, ценой за единицу и точной суммой строки, статусом и действиями. Реквизиты, файлы/договор, история корректировок — отдельные канонические секции; редкое свёрнуто. Таблица прокручивается внутри, страница не растягивается.

Правка строки — внутри ТОЙ ЖЕ панели, штатный form/build или выбранная строка + форма, не новое окно. Одна операция за сохранение: реквизиты / одна строка / добавление выбранных заявок. Не выдавать последовательность разных endpoints за атомарное общее сохранение. Несохранённый ввод охватывается штатным guard openCard; закрытие/смена строки не теряет ввод. Точная lineAmount не пересчитывается из округлённого unitPrice. PATCH строки передаёт свежую version; 409 показывает сообщение и обновление только по явному действию, не повторяет POST.

Добавление существующих заявок — внутри панели с выбором/поиском и пагинацией (не ложное «нет», если первые200 уже привязаны). Создание позиции не требуется новой backend-операции: отдельная понятная ссылка на существующую новую заявку, не молчаливое сохранение промежуточных данных. Если новая позиция невозможна на месте — честная подсказка, не слепая кнопка «+».

Блокировки: lockReason/receiptBoundaryAt authoritative, visible received только запасной fallback. cancelled — просмотр; partial — просмотр и явная причина; paid без приёмки — строка/добавление с обязательной причиной, нельзя DELETE или merge. Без canMoney финансовые колонки/поля/суммы/оплата не рисуются, metadata зависит canEdit. Сервер остаётся последней проверкой.
