Таблицы

        
      

      
Справочник коллекций MongoDB, сгруппированный по категориям. У каждой таблицы есть русское описание и тип: действующая (за ней стоит модуль), связевая (создаётся из нескольких таблиц, сама по себе не самостоятельна) или CRM kppdf (таблицы CRM на общей базе — модуля в data-core нет, удалить нельзя); приложение — данные из /api/apps. Нажмите строку, чтобы раскрыть поля — типы, заполненность и пример значения. Чувствительные значения маскируются на сервере.

Подключение

      

      
Как подключить к базе любое приложение, Google-таблицу, скрипт или ИИ-агента. Нужно всего два значения: адрес API и ключ. Всё остальное клиент узнаёт из API сам.


      

        

          
1. Адрес API

          

          
Из интернета — этот адрес. Из домашней сети можно и напрямую http://<IP-VM>:3001/api.

        

        

          
2. Ключ

          
Одна интеграция — один ключ с минимальными правами. Для таблицы менеджера: «Чтение и запись»; для отчётов: «Только чтение». Ключ показывается один раз.

          
          
Каждый запрос: заголовок Authorization: Bearer kppd_…

        

      


      

        
3. Для ИИ-агента — готовый промт

        
Скопируйте и отдайте агенту (Claude, ChatGPT, Gemini…), подставив ключ. В промте — адрес, правила и актуальная схема таблиц; полную инструкцию агент прочитает сам по /meta/guide.

        
        

          
          
          
          
        

      


      

        
4. Примеры кода

        
Свои данные приложения живут в /apps/<приложение>/<коллекция> — коллекция создаётся при первой записи, сервер дорабатывать не нужно.

        

          
          
        

        

          
          
          
          
        

        

        

        
      


      

        
5. Схема базы

        
Таблицы и поля из моделей сервера (GET /meta/schema). * — обязательное поле, → — ссылка на другую таблицу. Секретные поля не показываются.
