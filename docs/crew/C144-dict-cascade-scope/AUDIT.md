# C144 — аудит каскада «тип паспорта → что предлагают»

Чтение кода, без стенда и без правок. Контракт API не ломать: пустая строка `categories` остаётся хранением.

**Вердикт: после 🔴.** Справочник материалов, покрытий, частей и способов установки уже говорит правду в таблице. Элементы и чип «Для всех» у частей — нет. Пока 🔴 не закрыты, фильтр «как у изделия» врать не должен.

## Карта каскада

Тип берётся с изделия (`passportCategory.code`: своё → вид → группа). Дальше каждый список режет сам.

| Шаг | Справочник | Пустое `categories` | Где режется | Прячет чужие |
|---|---|---|---|---|
| 1. Тексты | `passportPhrases` | не «для всех»: нужен флаг `allCategories` | `phrase-tree.ts:50-51` `matchesCategory`; воронка `GET /passports/funnel?category=` | да, на сервере |
| 2. Элементы | `passportElements` | **никому** (сервер) | `passport-gaps.ts:23-27` `elementFits`; книжка/заполнение `fill/control.js:12` | да |
| 3. Способ установки | `passportInstall` | для всех | `passport-gaps.ts:188` `forCat`; `fill/index.js:55-57`; `wire-form.js:30`; карточка изделия `form-fields.js:164` | да, выбранный чужой остаётся с пометкой |
| 4. Материалы | `passportMaterials`, не покрытие | для всех | `materials-spec.js:58-62` `own` без `strict` | нет: свои сверху, остальные в группе «Другие» |
| 5. Покрытия | те же, `kind=coating` | для всех | `tagPick` `mine` `pick.js:180-182`; подсказка `materials-spec.js:256-259` | да, кнопка «Показать все» |
| 6. Части | `passportParts` | **не в коротком списке** | `materials-spec.js:155` `strict: true`; бейдж `dicts-sort.js:27-30` | да, «Показать все части» |
| 7. Сортамент | `passportSortament` | типа нет: режет код материала | `materials-spec.js:133` | — |
| 8. Дефекты | `passportDefects` | поля `categories` нет; связь — `applies` | в списках паспорта по типу **не** режется | — |

Порядок на экране директора: тип → тексты (воронка книжки) → элементы → установка → таблица (часть, материал, размер) → покрытие. Сортамент и оформление (`passportStyle.category`, одно поле) в этот каскад не входят.

Два разных «части»: `productParts` (`dicts.defs.ts:228`, пусто = для всех, работы заказа) и `passportParts` (`dicts.defs.ts:832`, пусто = не в коротком списке паспорта).

## Семантика пустого `categories`

Закон ТЗ и код, который ему следует:

- **Материалы и покрытия — пусто = для всех.** Подсказка `dicts.defs.ts:777`. Клиент `materials-spec.js:57-62` (`strict` только у частей). Покрытия: `pick.js:182` (`!(o.cats||[]).length`). Колонка: `dicts-sort.js:18-19` и бейдж «Для всех типов» `dicts-sort.js:32-34`. Форма: `dicts.js:373`.
- **Части — пусто = не в коротком списке.** Подсказка `dicts.defs.ts:832`. Короткий список `materials-spec.js:155`. Фильтр справочника `dicts-sort.js:18` (`passportParts` → только `list.includes`). Форма честно пишет это в hint `dicts.js:371-372`. Бейдж строки `dicts-sort.js:27-30`.
- **Способ установки — пусто = для всех** (как материалы). `dicts.defs.ts:865`, `passport-gaps.ts:188`, `fill/index.js:56-57`, `wire-form.js:30`. Расхождения нет.
- **Элементы — пусто = никому.** Комментарий и код `passport-gaps.ts:23-27`: код обязан быть в списке. То же `fill/control.js:12` `fitsElement`. Подсказка поля это не говорит (`dicts.defs.ts:763` — «отметьте нужные», без «пусто — для всех»).

Хранение одно: пустая строка. Менять контракт не нужно. Менять смысл чипа и колонки — нужно, иначе одна пустота читается тремя способами.

## Дыры UI справочника

Колонка «Кому предлагают» у материалов, частей, элементов, установки и дефектов не отрезается лимитом: `dicts-sort.js:188-206` (`isScope` не входит в `extra > 2`). Фильтр «Как у типа паспорта» есть: `dicts.js:109`, `dicts.js:115-121`. Имена типов — из `passportCategories` / `CAT_NAMES`, не коды в ячейке (`dicts-sort.js:25`, `38`).

🔴 **Элементы врут «для всех».** `offeredInPassportList` для не-частей считает пусто предложением (`dicts-sort.js:19`). Бейдж — «Для всех типов» / «В любом выпадающем списке» (`dicts-sort.js:32-34`). Hint формы — ««Для всех» — любому типу» (`dicts.js:373`). Сервер такой элемент в список «Что это за изделие» не кладёт (`elementFits`). Надпись фильтра обещает совпадение с изделием (`dicts.js:131-132`) — для элементов это ложь.

🔴 **Чип «Для всех» у частей значит обратное.** `catChips` при пустом значении включает чип «Для всех» и пишет в базу пустую строку (`cat-chips.js:8`, `16-17`, `32`). У части пусто = спрятана. Таблица говорит «Не в коротком списке», открытая форма горит чипом «Для всех». Hint под чипом уже верный (`dicts.js:372`); подпись чипа — нет. Нажатие «Для всех» снимет часть со всех коротких списков.

🟡 **Дефекты в том же фильтре.** `SCOPE_DICTS` включает `passportDefects` (`dicts-sort.js:8`). Поля `categories` у дефектов нет (`dicts.defs.ts:840-851`, есть `applies`). Колонка всегда «Для всех типов», фильтр типа ничего не отсекает. Это не каскад типа паспорта.

🟡 **Карточка записи показывает коды.** `fmt` для `categories` — сырая строка (`dicts-sort.js:233`). Форма чипами это перекрывает (`startEdit`), просмотр карточки — нет. Подсказки сервера всё ещё «TRN, WRK…» (`dicts.defs.ts:832`, `dicts.passport-phrases.ts:40`); форма справочника hint подменяет, запасной текстовый ввод — нет.

🟡 **Тексты без фильтра типа.** Дерево пишет имена (`.pt-cats`, `passport-tree.js:62`, `83`). Фильтра «как у BLG» нет — только пустые/дубли (`passport-tree.js:69`). Карточка узла склеивает коды (`passport-tree.js:218`).

🟢 Чипы справочника прячут DIO/DSP, пока они не выбраны (`dicts.js:375`, `later`). Детские отложены (`common.js:18`). Главные TRN / WRK / BLG в списке есть.

## Дыры паспорта и книжки

Книжка материалов зовёт ту же таблицу со scope типа изделия (`book-side-edit.js:95-99`). Части и материалы в самой таблице совпадают со справочником. Покрытия при пустом типе — все, и это написано (`materials-spec.js:257-259`).

🟡 **Покрытия без основания, когда тип уже есть.** `pick.js:200`: при `scope` подпись `sub` стирается. `materials-spec.js:247` кладёт в `sub` «для всех типов» или имена. После `setScope` свои и «для всех» выглядят одинаково. Скрин «все покрытия сразу» — это закон «пусто = для всех» плюс стёртая подпись: неотмеченные покрытия не отличить от явно своих. Чужие скрыты до «Показать все».

🟡 **Материал в комбо не говорит, почему он свой.** `groupOf` (`materials-spec.js:67`, `116`) кладёт и явно отмеченный, и пустой `categories` в одну группу «Для этого типа паспорта».

🟡 **Новая часть из таблицы рождается пустой.** `materials-spec.js:232` `POST { name }` без `categories`. По закону частей она сразу не в коротком списке; чип станет «Не для этого типа паспорта» (`materials-spec.js:166-167`).

🟡 **Промпт книжки шире списка.** `book-side-edit.js:31-35`: пустые `categories` у частей проходят (`!list.length`). Таблица их не предлагает. ИИ получит части, которых в коротком списке нет.

🟡 **Элементы на карточке изделия — закон tagPick, не сервера.** `form-fields.js:175-180` и старая форма `form.js` / `wire-form.js:26`: `mine` считает пустые `cats` своими (`pick.js:182`). Заполнение книжки и gaps — `fitsElement` / `elementFits`, пустые не предлагают. Два экрана, два списка.

🟢 Способ установки везде один: пусто или свой код; чужой выбранный остаётся с пометкой (`wire-form.js:30-34`, `form-fields.js:164-166`, `fill/index.js:55-57`).

🟢 Воронка текстов книжки отдаёт категорию на сервер (`book-choices.js:61-65`). Сервер показывает лист, если `allCategories` или код в списке (`phrase-tree.ts:50-51`, `72`). Пустой тип в подписи книжки падает в зашитый `V2_CATS` и иначе показывает код (`book-choices.js:11`).
