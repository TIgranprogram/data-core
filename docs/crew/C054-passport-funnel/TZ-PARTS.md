# C054-P — Разметка «Части изделия» по категориям паспорта

**Класс:** M · **Роль:** data-steward · **Код не писать** · Только план + JSON для apply.

## Суть
В таблице материалов поле «Из чего» для тренажёра (TRN) предлагало калитку, задвижку, дугу. Причина: у 39 из 43 `passportParts` поле `categories` пустое; UI раньше считал пустое = «для всех».

## Вход
- Список: `docs/crew/C054-passport-funnel/data/dict-passportParts.json` (43 записи с прода)
- Категории: TRN (уличный тренажёр), WRK (воркаут), BLG (благоустройство / перголы / МАФ), DIO (детское игровое), DSP (детское спортивное)
- Уже с TRN: Гриф, Маятник, Накопитель дисков, Ногоступ

## Задача
1. Для **каждой** из 43 частей: поле `categories` — одна или несколько кодов через запятую (как в справочнике). Не оставлять пустым без явной причины в колонке «почему».
2. Предложить **новые** части (имя + genSingular/genPlural + categories), которых нет, но обычно нужны:
   - TRN: рукоять/ручка рычага, каретка, грузовая рама, трос, подшипниковый узел, противовес… (по ГОСТ Р 57538 и типовым паспортам уличных тренажёров)
   - WRK: перекладина турника, брусья, шведская стенка-стойка…
   - BLG: ламель, столбик перголы, приствольная решётка-секция, вазон…
   - DIO/DSP: по типовым ДИО/спортплощадкам
3. Можно опереться на открытые каталоги/ГОСТ/типовые паспорта; в отчёте — 3–5 ссылок-источников.

## Выход (только эти файлы)
- `docs/crew/C054-passport-funnel/parts-categories-plan.json` — массив `{ id, name, categories, action: "patch"|"keep", note }`
- `docs/crew/C054-passport-funnel/parts-new-suggest.json` — массив `{ name, genSingular, genPlural, categories, note }` (ещё не создавать на проде)
- `docs/crew/C054-passport-funnel/REPORT-parts.md` — ≤40 строк: правила разметки, спорные, что проверить глазами
