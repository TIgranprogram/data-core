# C276 — транзакционный склад по умолчанию

- Штатные create, patch, archive и восстановление default используют одну транзакцию. Общий guard `stock_warehouse_guards/default` обновляется до выбора склада. Он не содержит складских данных и подготавливается при старте с majority write concern. В переданной транзакции используется та же сессия.
- При одном действующем default обычное чтение обходится без блокировки. Если одновременно есть ошибочный флаг на неактивной строке, следующий штатный выбор убирает лишний флаг. Из архивных записей новый склад не назначается. При снятии последнего склад появится только при следующем штатном чтении.
- Схема `warehouses`, права CRM и переключатели C260 не менялись. Гарантия сериализации действует для процессов API с новым guard. Эксплуатация Mongo standalone и одновременная запись прежним Mongo-писателем в эту гарантию не входят. Переход на новый код требует штатного окна выпуска без одновременных писателей.
- DTO бронирований опубликован через `stock/index.ts`. OpenAPI, маршруты и пределы пагинации сохранены.
- Hermes Hy4 Flash отметил три обязательные ветви проверки. Конкурентный первый default, откат после неудачной записи и та же внешняя сессия. Независимый архитектурный обзор дополнительно поймал сочетание одного активного и одного неактивного default. Статические проверки и 246 складских модульных тестов прошли.
- Первый изолированный прогон Mongo 4.4 выявил несовместимость сброса фикстуры с snapshot-транзакциями. `deleteMany` вне транзакции с локальным подтверждением ещё не был виден в snapshot. Отдельные последовательные HTTP-запросы сохранили первый default и штатно передали его по явному назначению. В фикстуре сброс и посев выполняются с тем же порядком guard и majority.
- Повторный изолированный прогон Mongo 4.4 прошёл все 9 сценариев, включая два подключения, rollback после ошибки, передачу внешней session, архив, снятие у неактивного склада и отключённый C260. Ещё 43 e2e прошли на финальном коде в `stock-supply`, `stock-zones`, `stock-items-bulk` и `search-empty`. После правки быстрый путь дополнительно прошёл 21 адресный юнит. Одноразовые контейнеры остановлены.
