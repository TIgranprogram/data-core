# ТЗ БЗ-13 — переносной пакет (шаг 1: скрипты, без запуска на VM)

**Зачем (словами пользователя):** всё приложение в одном архиве — чтобы пережить потерю VM и переехать на новую.

**Роли:** исполнитель (скрипты деплоя) ☑ · архитектор ☐ (проверка перед первым запуском)

## Что сделать
1. `deploy/synology/bundle.sh` (запуск на VM): `git archive` data-core и kppdf; `mongodump --archive --gzip` всей `datacore` (Mongo 4.4, внутри контейнера `datacore-mongo`, авторизация — как в `backup.sh`); `uploads/` обоих; конфиги (compose, `.env` обоих, nginx `/db/` и kppdf, crontab туннелей, systemd `kppdf-tunnel`); `MIGRATE.md` для агента (как развернуть); `manifest.json` (дата, коммиты, число документов по коллекциям, sha256 файлов). Папка назначения — параметр (`BUNDLE_DIR`, по умолчанию общая папка Synology, если смонтирована, иначе `/opt/datacore-bundles`).
2. `deploy/synology/bundle.cmd` + `bundle-pc.sh` (на ПК, Git Bash): меню 1) собрать на VM и скачать в `C:\datacore-bundles\<дата>.zip` (повтор при обрыве, сверка sha256); 2) проверить пакет (распаковка + сверка manifest); 3) развернуть на новую VM — пока только печать шагов из `MIGRATE.md` (без автоматики восстановления поверх живых данных).
3. Раздел «Переносной пакет» в `deploy/synology/README.md`.

## Файлы
- В рабочей копии ожидаются правки: `docs/DB-AUDIT.md` (хранитель), `docs/roles/tz/SKLAD.md`, `docs/QUESTIONS.md` (аналитик) — не трогать.
- читать: `deploy/synology/README.md`, `deploy/synology/backup.sh`, `deploy/synology/deploy.py` (как ходим на VM, адрес/ключ из `config.env` — сам файл не выводить).
- менять: только `deploy/synology/bundle.sh`, `bundle.cmd`, `bundle-pc.sh`, `deploy/synology/README.md`.

## Нельзя
- Запускать что-либо на VM, читать/выводить секреты (`config.env`, `.env`, `CREDENTIALS.md`), `set -x` в скриптах с `.env`. Пакет содержит секреты — в скрипте явно: права 600 на архив, не класть в репо.
- Никаких `mongorestore --drop` по умолчанию.

## Критерии приёмки
- [ ] `bash -n` всех `.sh` — без ошибок; shellcheck, если есть.
- [ ] Скрипты не печатают секреты; архив создаётся с правами 600.
- [ ] README описывает запуск и проверку.
