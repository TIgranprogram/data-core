## Перед записью

1. Свежая полная сверка счетов и заявок через API: поставщикИНН + точныйномер + дата, плюс хэш вложения. Старый снимок не доказывает отсутствия документа. Суффиксы/версии не склеивать по сумме.
2. Payload-data не является готовым DTO. Все ID компании/заказа/статьи выбираются после проверки живого контракта. sourceSku — артикул поставщика, не ID расходной статьи. Печатные суммы строк авторитетнее произведения округлённой цены.
3. Готовность документа не означает доказанную оплату. По умолчанию documentOnlyDraft=true: не выпускать мнимый долг для уже оплаченного счёта. Для71 прямых дат доказан текст ответа и день, но сумма частичного платежа/фактический плательщик отдельно не восстановлены автоматически. paymentValidation содержит единственность ответа, дату>=счёта, RUB, покупателя, контекст с номерами строк и маркеры частичной/другой суммы. Отсутствие маркеров формирует shortlist для координатора, а не разрешение записи. Отдельные кандидаты назначения имеют linenumbers и не превращены вID.
4. У24334 время08:41 есть, заголовка дня в начале переписки нет. Сегодняшнюю дату не подставлять. Ставку НДС, отсутствующую в оригинале, не вычислять по сумме и не наследовать молча от поставщика.
5. Привязки purpose вне4 вручную проверенных документов оставлены кандидатами. ID заказа/объекта не назначались. Не считать соседнее сообщение надёжной привязкой.
