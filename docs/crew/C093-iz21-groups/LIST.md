## Почему счётчики `/showcase/groups` дают 404, а не 490
Причина найдена в `showcase.service.ts:187–189` (`groups()`). Изделия группируются по `categoryId` как есть, потом строится `new Map(String(_id) → n)`. У группы «Тренажёры» в ответе `count: 1`, а изделий в ней 87 (проверено по списку изделий). Суммы разделов: 168 + 34 + 202 = 404; не хватает ровно 86. Вывод: у 86 изделий «Тренажёров» `categoryId` записан иначе (скорее всего строкой, а не ObjectId), `$group` даёт две записи с одним ключом, и `Map` оставляет последнюю (1). Прямо из API тип поля не видно — подтвердить одним запросом в Mongo (`typeof categoryId` у изделий группы 10). Правка (не моя зона): суммировать в Map (`n.set(k, (n.get(k)??0)+c.n)`) и привести `categoryId` к ObjectId. 491-е изделие, «6104.0000.0000», без группы — это 490 + 1.

## Изделие 3905 «Арт объект Деревянные указатели»
«Раздел» = «Оборудование для благоустройства территории», группа «Информационные стенды и указатели» (BLG, № 39), ручная категория BLG. Всё согласовано. «Четвёртый раздел Благоустройство» есть в `categories` как пустой старый раздел (без групп с изделиями; также пустые «Воркаут», «Вывески», «Мебель», «Качели», «Детский игровой комплекс», «Уличный тренажёр», «Упаковка»). В витрине их нет (счётчик 0), изделий в них нет. Рабочих разделов с изделиями три. Предложение: пустые разделы убрать из справочника «Разделы изделий» (мягко) — решает владелец.
