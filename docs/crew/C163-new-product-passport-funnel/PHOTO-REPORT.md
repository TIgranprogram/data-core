# C163 — исправление резервного общего вида (19.11.2026)

## Изменено

- `showcase.service.ts::present` использует новый пакетный `showcase-photos.ts`: собственные `products.photoIds` → актуальный `productphotos` (`purpose=passport`, `kind=overview`, `deletedAt=null`) → прежние `productpassports.images`.
- Для нескольких общих видов порядок: `sortOrder`, `createdAt`, `_id` по возрастанию. Старые паспорта сохраняют прежнюю сортировку `date`, `_id` по убыванию. При битой ссылке проверяется следующий кандидат.
- Кандидаты резервного фото читаются только для изделий без разрешившихся собственных фотографий. Невалидные id, отсутствующие/удалённые фото и небезопасные ссылки пропускаются. Ссылка оригинала проверяется существующим `safeUploadPath`; неисправный thumb/medium заменяется оригиналом.
- Все чтения пакетные: максимум два запроса источников резерва и четыре запроса фотографий на весь набор, независимо от количества изделий. Для полностью собственных фотографий запросов резервных источников нет.
- Резерв возвращается только как `photo`, `photoSource:'passport'`. `photos` сохраняет только собственные изображения и их порядок.
- `products.js` показывает резерв крупно через существующий `kit.carousel`. Эта галерея доступна для чтения и увеличения. Она не получает обработчиков удаления, перестановки и загрузки.
- Существующая кнопка «← своей обложкой» перенесена из «Подробнее» непосредственно под резервное изображение. Только явное нажатие записывает `photoIds`; читатель кнопки не видит. Штатная загрузка собственного фото остаётся в отдельной общей галерее.
- Применены `datacore-design`, `datacore-verify`, `datacore-docs-sync`. Новых компонентов/CSS/маршрутов/DTO/схем нет. Данные, импорт Inventor, паспортные снимки и выпуск не изменены.
