# C098 — автоматическая подгрузка списков

Класс L: общий механизм нескольких экранов и режимов прокрутки, frontend + access + designer (до3 ролей). Пользователь: в заявках «Показано100из250», кнопок следующей страницы нет, автоматическая подгрузка не срабатывает. Просит исправить общий механизм везде. Скриншот приложен в чате12.11.2026. Без деплоя и изменений рабочих данных.

## Исполнитель frontend

Ownership: `backend/pwa/ui/kit/list.js`, `auto-more.js`, относящиеся к прокрутке правила kit/list CSS и тесты рядом. Сначала установить причину, затем минимальный общий фикс. Другие исполнители работают в C097 (atlas, help-guide-data, docs/DESIGN): их изменения не откатывать и не включать. Сервер/паспорта/общий редизайн не трогать.

Прочитать CANON, UI-ACCEPTANCE, актуальный MAP и skill design/verify. Начальные места: list.js:275 watch/watchIn, load append, rewatch; auto-more.js IntersectionObserver. Проверить фактический scroll-container таблицы и положение sentinel, галерею/карточки, повторный вызов после первой добавки. Показать root найденную причину. Проверить остальные потребители общего auto-more, не переписывать все экраны.

## Результат и приёмка

- При достижении конца автоматически появляются следующие записи, пока total не исчерпан: в том числе100→200→250. После последней страницы запросы прекращаются.
- Таблица с внутренней прокруткой, карточки/галерея с прокруткой страницы, изменение размеров окна. Фильтр/поиск/сортировка сбрасывают старую пагинацию; запоздалые ответы не смешиваются, параллельные append не дублируются.
- Ошибка загрузки не стирает уже показанные записи; повтор доступен. Если автоматический observer недоступен, пользователь не остаётся без пути к остальным данным: существующий kit fallback, без отдельного дизайна.
- Значимые регрессионные тесты по причине; smoke импорты+guards. Живой QA через datacore-access: заявки с >100, ещё один общий список и потребители autoMore;390/1024/1920/2560, обе темы по изменённым состояниям. Сравнить IDs/API total, нет дублей/пропусков на стабильных данных. Списки читать, новые тестовые данные создавать только при нехватке, без прод.
- Дизайнер принимает новое поведение по доказательствам. Отчёт IMPLEMENT.md: причина/границы/проверки; полный прогон сервера не нужен без серверных правок. Коммит/push — координатор, только свои пути; учесть запрет смешивать kit и sections в одном коммите.

Экономия: одна реализация + точечная приёмка, не весь аудит сайта. Если проблема шире общего компонента — сначала доказательства координатору, без самовольного большого этапа.
