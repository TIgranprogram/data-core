# Заявки — аудит удобства (usability), 2026-10-28
Проверено по коду (без стенда). Логику этапов не трогаю — это аналитик.

## 1. Путь сейчас (клики)
1. Создать: «+ Заявка» (или строка «Быстрая заявка», requests.js:357) — 3-4 клика, форма в панели; «Поставщик и счёт» открыта, «Детали» свёрнуты (:141).
2. Заказать у поставщика: в строке/доске кнопка «В заказ» → «Заказано» (:246) — 1 клик, но «В заказ» ≠ «Заказано» (два похожих слова). Поставщик не требуется. Мультивыбора нет.
3. Внести счёт: в карточке нет «внести счёт» вообще. Ключ — «+ Счёт» в шапке (:189): создаёт НОВЫЕ заявки с позициями (invoice.js:221), а не привязывает счёт к существующей. Путь: «+ Счёт» → № → дата → поставщик → «Категория» → «Позиция» из списка → кол-во → сумма → «Внести» ≈ 12+ кликов на позицию. Рискует задвоить заявку.
4. Оплата: «Оплачено» (:246) без проверки; № и дата счёта — только подсказка текстом (:236) и поля в свёрнутом по смыслу блоке формы (:148-156). Кнопка не открывает поля.
5. Приём: «Принять» (:243) — окно: сколько, куда, на склад. 3-4 клика, понятно.

## 2. Топ-7 проблем
1. Счёт отделён от заявки: «+ Счёт» создаёт дубли, не цепляется к имеющейся (invoice.js:221, requests.js:189).
2. «Оплачено» без данных: кнопка меняет статус, поля счёта не просит (:246-249); потом «needsFill» (:212) ловит постфактум.
3. Выбор позиции в счёте — каскад «Категория → Позиция» + «Нет в списке — создать» (invoice.js:60-82), тяжело и неочевидно.
4. Подсказки «что делать» спрятаны в строке hints (:232) и видны только в таблице; на доске их нет.
5. Кнопки шага названы по-разному: «В заказ» / «Заказано» / «Оплачено» / «→ Заказано» / «Оприходовать на склад» (:246, :324-325) — не глаголы действия.
6. Два пути смены статуса: кнопка, «Сменить статус…» (:98), перетаскивание (:261) — правила разные, в окне статуса «Получено» и «Отменено» без причин.
7. Нет мультивыбора: 10 позиций одному поставщику = 10 нажатий; «+ Из таблицы» (:188) путает с заказом.

## 3. Раскладка (предложение)
- Доска по умолчанию; в шапке колонки — строка «что делать» (из hints) и сумма; в карточке — серый чек-лист недостающего и ОДНА кнопка-глагол: «Заказал у поставщика», «Счёт оплачен», «Принять».
- Нажатие без нужных данных → правая панель заявки, блок «Следующий шаг» сверху, нужные поля подсвечены и сфокусированы; кнопка «Сохранить и ...» двигает этап. Не ошибка, не пустая попытка.
- Мультивыбор (чекбокс на карточке/строке, на телефоне — долгое нажатие) → полоса снизу «Выбрано 3 · Заказал у поставщика»; поставщик спрашивается один раз для всех.
- Счёт — это блок «Счёт» в панели заявки/нескольких выбранных: № · дата · сумма · компания · файл. Одна форма на пачку позиций (общий счёт на несколько заявок), не выбор из выпадающего списка.
- Отдельная страница «Счета»: для работы с заявкой НЕ нужна. Нужен только список/фильтр «Счета» (группировка по № счёта) для бухгалтера и календаря; позже, не в этой задаче. «+ Счёт» оставить как «внести уже оплаченный» (редкий случай), переименовать: «Счёт без заявок».

## 4. Телефон 390
- Доска: горизонтальный скролл колонок допустим как жест, но сама страница не уезжает; вместо колонок — переключатель этапов сверху (чипы).
- Главная кнопка карточки ≥ 44 px и не вплотную к карточке-ссылке (случайные нажатия).
- Полоса мультивыбора не перекрывает нижнюю навигацию; чекбокс ≥ 44 px.
- Панель «Следующий шаг»: клавиатура не закрывает кнопку, поля сумма/дата с нужной раскладкой (inputmode).
- Окно «Принять» (:52), строки счёта (.inv-main, invoice.js:87): три поля в ряд помещаются? Долгие подписи не обрезаются.
- Чек-лист недостающего читается в обеих темах (контраст серого ≥ 4.5:1).
