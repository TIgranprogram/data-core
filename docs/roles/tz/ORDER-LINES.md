# ТЗ ORDER-LINES — позиции заказа: изделие / новое изделие / услуга (блок В; 5.5, 6.1, 6.1а/б, 6.2/6.3)

**Зачем (словами пользователя):** менеджер добавляет позицию в заказ: сначала ищет среди существующих изделий, не нашёл — «новое изделие» (буфер), либо услуга (Доставка/Монтаж). Проектировщик потом оформляет буфер в настоящее изделие. В производство идут только подтверждённые изделия.

**Класс:** XL (данные прода, `incomes`, новая коллекция) · **Max agents:** 5 (backend, frontend, designer, qa; analyst — этот документ) · **Reviewers:** qa ☑ architect ☑ designer ☑ · **Max review loops:** 2 · **Проверки:** full
**Язык менеджера:** да — «Новое изделие», «Услуга», «Не распределена»; без кодов `auto/none/matchStatus` на экране · **Приёмка:** сайт глазами: форма заказа, карточка заказа, «Проектирование → Заявки на создание изделия», «Продукция».

## Решения (QUESTIONS.md 2026-10-29/30) и что принято по умолчанию
- Цена (`unitPrice`) нового изделия и услуги обязательна при создании позиции (отв. 4).
- «В производство» — запрещать, пока есть неподтверждённые позиции (отв. 6; сейчас уже запрещено для несопоставленных — `production-orders.service.ts:95-99`, расширяем).
- Порядок: поиск среди существующих → не нашли → «Новое изделие» (отв. 5).
- ПО УМОЛЧАНИЮ (вопросы 3 и 5 ещё не поняты пользователем — формулировка в QUESTIONS 286-288): одна заявка на одно название (повторное «то же новое изделие» в другом заказе цепляется к существующей открытой заявке; при похожем названии — подсказка «это то же?»). Отклонить заявку = «это дубль»: проектировщик выбирает существующее изделие, все позиции заявки перепривязываются сами.

## Что проверено в коде (факты)
- `incomes` — коллекция **только data-core** (`income.schema.ts:11-16`: «своя коллекция», CRM не читает). Поля `matchStatus/productId` уже есть (`:23-27`, «CRM не читает»). Новые необязательные поля добавлять можно.
- `products` — **общая с CRM** (`src/common/catalog/product.schema.ts`, есть `sku` required, `status` new/active/archived/draft). Схему не менять; буфер в `products` НЕ класть (иначе виден в «Продукции» и в CRM).
- Состояние сопоставления: `matching/matching-rules.ts:12-18` (`confirmed|none|legacy|auto|unmatched`); API `matching` (`matching.controller.ts`: suggest, unmatched, unmatched/count, confirm, none, bulk). Окно в приложении: `pwa/sections/salesorders-matching.js`, очередь `matching-queue.js`.
- Позиции создаются `POST /incomes` (`incomes.controller.ts:49`, `incomes.service.ts create`), в форме заказа «+ Позиция» открывает правую панель `of:'orders'` (`salesorders.js:292`).
- «В производство»: `production-orders.service.ts:80,95-99`, готовность — `order-readiness.ts`.
- «Проектирование»: вкладки `['orders','Заказы'],['board','Доска']` — `pwa/sections/design.js` через `ui/design-board.js:539`; уведомления зон — `modules/zones/zone-events.ts`.
- Виды работ: модуль `work-type` (справочник «Виды работ»); значений «Доставка»/«Монтаж» в коде нет — это записи справочника.

## Контракт (новое)
- `incomes`: `lineType` enum `product|new_product|service` (необязательно; нет = как сейчас, по `lineState`); `workTypeId` (ObjectId, для service); `productRequestId` (ObjectId, для new_product); `description` не нужно — берём `notes`; фото — существующие `photoIds`.
- Новая коллекция data-core `productrequests`: `title`, `description`, `photoIds[]`, `qtyTotal` (вычисл.), `status` `open|confirmed|rejected`, `productId` (после подтверждения), `createdBy`, `confirmedBy/At`, `deletedAt`. Индексы — через `scripts/ensure-indexes.js` (запускает координатор).
- Правила `POST/PATCH /incomes`: `lineType=service` → обязателен `workTypeId` из справочника (только Доставка/Монтаж; иначе 400), `unitPrice` > 0; `new_product` → обязательны `title`, `qty`, `unitPrice` > 0, без `productId`; `product` → обязателен `productId`. Проверка — только при создании и правке (старые не ломать; флаг как `requireFields`).
- `GET /product-requests?status=open` (+ `/count`), `GET /product-requests/:id` (с позициями и заказами), `POST /product-requests` (создать из позиции или найти открытую по названию), `POST /product-requests/:id/confirm` `{sku, categoryId, passportCategory…, group, certification}` → создаёт изделие в `products` через существующий сервис каталога (обязательные поля как в «+ Создать изделие», `product-block.js:126`), ставит позициям `productId`, `matchStatus:'confirmed'`, статус заявки `confirmed`; `POST /product-requests/:id/reject` `{productId}` → привязывает позиции к существующему изделию, статус `rejected`. Роли: создавать — admin/manager; confirm/reject — роль проектирования (как `design`).
- `GET /matching/unmatched`, счётчики и «В производство»: позиция `service` считается сопоставленной; `new_product` пока заявка `open` — «не подтверждена» (блокирует производство, текст ошибки: «Есть позиции без подтверждённого изделия»).

## Критерии приёмки
- [ ] Если добавляю позицию «Новое изделие» без цены — не сохраняется, подсказка у поля. Услуга без цены — то же.
- [ ] Если тип «Услуга», выбор только Доставка/Монтаж; «создать вид работ» из заказа недоступно.
- [ ] Если создаю «новое изделие», оно не видно в «Продукции» (и в CRM); в «Проектировании» растёт счётчик вкладки, зона получила уведомление.
- [ ] Если то же название добавляю в другой заказ — карточка одна, позиций две (или подсказка «это то же?»).
- [ ] Если проектировщик подтверждает с артикулом — изделие в «Продукции», позиции обеих заказов привязаны сами, счётчик «не распределено» падает.
- [ ] Если «Это дубль» и выбрано существующее — позиции перепривязаны, новое изделие не создано.
- [ ] Если в заказе есть неподтверждённая позиция — «В производство» отказывает с понятным текстом; услуга не мешает.
- [ ] Старые заказы и импорт открываются и сохраняются как раньше (без lineType).
- [ ] full: tsc 0, весь юнит, e2e, строка TEST-LOG; `node --input-type=module --check` по правленым pwa-файлам; ширина 390 px.
