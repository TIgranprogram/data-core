# ТЗ DESIGN-KIT — единая библиотека эталонов («одинаковые коробки»)

**Зачем (словами пользователя, 2026-10-31):** «на складе все коробки одинаковые — я беру ту, что есть, и не рисую новую. На сайте один канбан крупный, другой мелкий. Нужны переиспользуемые компоненты: эталонные карточки 2–3 варианта, везде по назначению. И чтобы больше никогда не появлялись самодельные виды».

**Класс:** XL · **Роли:** frontend, designer, qa · **Отвечает:** координатор · **Проверки:** design-lint v2 = 0, pwa-guards, full перед выкладкой.

## Что сейчас (2026-10-31)
- `backend/pwa/ui/screens.css` — 1917 строк, ~60 разделов со своими префиксами (`td-` 126, `ops-` 63, `gt-` 50, `hp-`, `pt-`, `ff-`, `pg-`, `wk-`, `inv-`, `q-`, `ol-`, `dr-`, `so-`…).
- Дубли компонентов: две доски `ui/board.js` (work, list) и `ui/design-board.js` (design, design-order); фильтры `cat-chips` / `facet-filter` / `funnel` / `step-funnel`; выборы `select` / `combo` / `tag-pick` / `suggest`; таблицы `rows-table` / `list`.
- `docs/DESIGN.md` §4 описывает классы base.css, а не компоненты. `design-lint.mjs` ловит только цвета/пустые состояния/служебные слова и идёт только ночью; ворота (`preflight.sh:50`) его не запускают.

## Решение (совет opus, принято координатором)
1. **Папка `backend/pwa/ui/kit/`**, вход `kit/index.js`; раздел импортирует компоненты только оттуда. Фабрики с вариантами, без классов от раздела: `kit.card({ size:'S'|'M'|'L', tone, title, meta, badges, actions, onClick })`.
2. **Семейства:** card S (строка/плитка) · M (карточка доски) · L (шапка сущности); board (`density`), table, panel, filter (chips | facets | funnel), pick (single | multi | tags | combo), badge/status, button (primary/secondary/ghost/danger × S/M), empty, tabs, stat, toolbar, dialog, toast, layout (grid | split | stack); timeline — Гант как особое семейство.
3. **CSS-слои** `@layer tokens, kit, layout, section`; классы kit — `k-…` в `kit/*.css`. В CSS раздела — только раскладка; цвет, фон, рамка, тень, радиус, шрифт — запрещены.
4. Старые `ui/*.js` на время миграции — тонкие обёртки над kit; удаляются, когда потребителей 0.
5. **Витрина `/app/#kit`:** каждое семейство × все варианты × светлая/тёмная тема × пусто / длинный текст / ошибка. Новый вариант сначала появляется в витрине.

## Роли (правила навсегда)
- **ТЗ вида** (`docs/roles/TZ-TEMPLATE.md`): «какие эталоны kit используются» и «нужен новый вариант? да/нет + почему». Новый вариант — отдельный шаг: kit и витрина, потом экран.
- **frontend:** нет подходящего эталона — стоп и вопрос координатору; «похоже» сделать нельзя; свои классы и свой CSS, кроме раскладки, запрещены.
- **designer:** проверяет 1) экран только из kit (импорты и классы); 2) вариант по назначению (S список, M доска, L сущность); 3) одна плотность на тип сущности; 4) design-lint v2 = 0; 5) витрина обновлена. Снимки — только витрина нового эталона и первая миграция семейства (до/после), с разрешения пользователя.

## Не трогать
Печать паспортов и мастер паспорта; админку (позже переиспользует kit); «большой взрыв» — каждое семейство отдельной выкладкой.
