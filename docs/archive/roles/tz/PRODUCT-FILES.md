# ТЗ PRODUCT-FILES — фото и файлы в изделии, паспорт только читает (класс XL)
Решения пользователя 6–9 — docs/audit/PASSPORT-FLOW-AUDIT.md. Совет opus (2026-11-01):
1. Модель: `productphotos` (product-photo.schema.ts) + поля `purpose` ('showcase'|'passport'|'drawing'; нет поля = showcase) и `kind` (PASSPORT_IMAGE_KINDS, product-passport.schema.ts:10). Индекс {productId, purpose, kind} + ensure-indexes.js. Схему не ужесточать (общая с CRM). Витрина и CRM читают только showcase/пусто.
2. Перенос: скрипт план→--apply с бэкапом productphotos; паспорт с наибольшим updatedAt (сначала выпущенный); по kind из images[] — запись purpose:'passport' с тем же photoId (файлы не копировать); идемпотентно; расхождения — в план. Паспорта не трогать. Photo с живыми ссылками не удалять; удаление в изделии — мягкое по productphotos.
3. Рендер: черновик/предпросмотр — изделие (purpose:'passport' по kind) → иначе старый images[]; при выпуске заморозить photoId в images[]. Правила по категории — одна функция в passport-rules.ts (её же зовут check и экран); обязательность рисунков — из правила.
4. Экран: правая панель редактора изделия, блок «Фото и файлы», группы-аккордеон, внутри ui/gallery.js; «Для паспорта» — слоты по kind (русские подписи), только нужные по правилу категории. Мастер паспорта: шаг «фото» → ссылка «Загрузить в изделии».
5. Порядок: a) purpose/kind в схеме, DTO, GET /products/:id/photos?purpose= (по умолчанию showcase); b) скрипт переноса; c) рендер; d) экран; e) убрать загрузку из паспорта. Чертежи DWG/PDF (хранилище не-картинок в photos) — позже.
Ловушки: forbidNonWhitelisted (DTO), @Roles на фильтр, Mongo 4.4 (новейший — сортировкой), deletedAt:null в сыром чтении.

## Без дублей (решение 9, совет opus 2026-11-01)
Модель изделия — в изделии; паспорт хранит только экземпляр (номер, дата, заказчик, заказ, приход, продажа, монтаж, note, textSnapshot, pdfIssuedAt, strict) и снимок при выпуске.
- **Категория:** одна — `products.passportDefaults.passportCategory`. Цепочку группа→раздел→справочник (`passportCategoryFor`) при выпуске не читать — только подсказка «предложить категорию» в редакторе изделия. Скрипт passport-category-groups переделать: писать категорию сразу в изделия (план→--apply, бэкап), поле у групп не удалять (никто не читает). Черновик и мастер категорию не хранят и не спрашивают. Выпущенные — снимок, не трогать. Поле `category` (строка kppdf) не трогать.
- **Источник для черновиков — изделие:** name/article/productCode; height/length/width/weight/seatWidth/seatHeight/supports/shipVolume; description/purpose/textChoices; materials/materialIds/materialsSpec/elements; installationTypeId; isKit/schemeSource/siteLength/siteWidth/maxUsers/возраст/рост/вес/высота падения/срок службы; certificate/manufacturerOrgId/warrantyMonths/supplier; images/photo → productphotos purpose:'passport'; bom → состав. Поля из схемы паспорта не удалять (общая с kppdf).
- **Переход:** сначала перенос из последнего паспорта (passport-fields-to-product, passport-images-to-product), потом убрать эти поля из мастера/редактора паспорта → строка «Изменить в изделии →». check считать по изделию. ~10 черновиков с расхождениями — списком пользователю, молча не перезаписывать.
