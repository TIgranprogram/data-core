## 3. Итоговое правило (CLAUDE.md + README)
| Класс | Агентов max | Проверяющие | Проверка |
|--|--|--|--|
| S — 1–2 файла | 0 (сам) | нет | smoke |
| M — модуль / экран | 2 | вид → designer; данные прода → steward или architect | smoke |
| L — сервер + экран, несколько модулей | 4 | qa; architect (модули/общие коллекции/скорость); designer (вид) | smoke; full перед выкладкой |
| XL — новая возможность, данные прода, схема общей с CRM коллекции | 5 | analyst до кода; architect + qa после; designer, если вид | full |
Циклы «проверка → правка» ≤ 2. Аудит L/XL — один основной читатель, остальным — только слепые зоны. Две роли на одни файлы — только со scope в ТЗ. Вторая сессия — worktree + готовое ТЗ + одна роль.

## 4. Удалённые дубли
- «Экономия токенов / проверка по размеру / снимки» — была в CLAUDE, памяти, verify §0, README, каждом агенте → правило в CLAUDE.md, детали — verify §0, в агентах одна отсылка.
- «Сначала skill design, правая панель» — CLAUDE, память, AGENTS, skill, агент → CLAUDE (когда) + skill (как); память удалена.
- «Лимиты 80/85 %, коммит после задачи» — дважды в CLAUDE + память → одна строка в CLAUDE; память удалена.
- «Команда агентов / мелочь сам» — CLAUDE, память, README → матрица в CLAUDE, подробно — README; память удалена.
- «Коротко отвечать» — CLAUDE, память ×2, AGENTS → CLAUDE; `short-replies` удалена.
- «Охрана зоны / эскалация / формат отчёта» — README + каждый агент своими словами → README; в агентах общая шапка из 5 строк.
- «Постоянные требования пользователя» в README: правая панель и «данные с бэкапом» убраны (есть в CLAUDE/AGENTS), остальные сжаты в одну строку.
- AGENTS «Коммитить — только когда просит пользователь» противоречило CLAUDE «коммит после каждой задачи» → отсылка к CLAUDE.
- Длинные чек-листы architect/designer → must-keep (данные, безопасность, модули, скорость / панель, токены, единообразие, ширины, путь с пустой формы).

## 5. Что сильнее всего режет токены
1. Лимит агентов по классу + «один основной читатель» на аудит — сегодня 4 роли на один аудит прочитали ~360 тыс. токенов; по правилу было бы 1 + 1 на слепую зону.
2. Запрет второй «команды» в параллельной сессии — убирает второй оркестратор со своим CLAUDE/AGENTS и своими ролями.
3. CLAUDE.md −62 % и память −7 файлов — меньше always-on в каждом ходе каждой сессии; плюс data-steward на sonnet вместо Opus.

## 6. Риски качества и как матрица закрывает
- Меньше проверяющих → пропуск ошибок стыка: на L обязателен qa, при сервере + экране — контракт в shared pack ТЗ.
- Вид без дизайнера на M: обязателен designer, если меняется вид; в его чек-листе — «единообразие» (случай меню справочников).
- Данные прода: XL всегда — analyst до кода, architect + qa после, скрипты план → `--apply` + выгрузка для отката (сохранено).
- Бесконечные круги правок: ≤ 2, дальше решает координатор.
- Сохранено: зоны ролей, `review-scope.mjs`, карты ролей (+ обязательные якоря файл:строка в конце), release/verify, plan → apply.
