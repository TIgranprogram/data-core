## Вопросы пользователю (внести в `docs/QUESTIONS.md`, с вариантом по умолчанию)
- В1. Пороги п.10: высота > ? м, масса > ? кг. По умолчанию: не вводить пункты, пока пороги и норма не названы.
- В2. Нормативы для периодичности осмотров и для «внеочередной осмотр после шторма/наезда»: ГОСТ/СП из какого документа? По умолчанию: периодичность остаётся из справочника дефектов; нового не пишем.
- В3. Проверка текста — сразу «ошибка» или сначала «предупреждение» на 601/603? По умолчанию: сначала предупреждение.
- В4. Откуда брать «высоту над грунтом» и «массу без фундамента»: вводить в карточке вручную (по умолчанию) или из чертежа/PDM?
- В5. «Тип» (опорный столб, указатель…): новое поле или считать видом изделия (`passportKinds`, есть)? По умолчанию: вид изделия.

## Дорого / спорно
- Дорого: п.10 (числовые условия + нормы), п.11 (модуль проверки + прогон по всем 342 паспортам), п.1 (6 новых полей карточки + экраны + миграция).
- Спорно: п.6 автозамена слов; п.3 «слить по смыслу» — нужен критерий (по умолчанию: одинаковое название после нормализации).
- Основной риск по данным: правки шаблонов — на проде (`ALL_V2`), а не в json; без новой версии шаблона и без `--apply`-скрипта «было→станет» изменения не вступят. Выпущенные снимки (`textSnapshot`, 342 шт.) трогать нельзя.
- Не нарушать: «Гарантии» и «Рекламации» смысл (`json:66-98`); общие с CRM коллекции (`products`, склад) — только `passportDefaults` внутри изделия.
