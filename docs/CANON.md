## 0. Как работать, чтобы ничего не терялось

1. Работа идёт **только по чек-листу** в [TASKS.md](TASKS.md). Взял пункт → отметил «в работе» (`[~]`) → сделал → проверил по «Готово, когда» (§7) → `[x]` + одна строка в [HISTORY.md](HISTORY.md).
2. Лимит/обрыв может случиться в любой момент. Поэтому: после **каждого** завершённого шага чек-лист на диске обновлён. Новая сессия начинает с TASKS.md — первый `[~]` или `[ ]` сверху.
3. Большой пункт дробится на подпункты не больше ~1 часа работы, каждый проверяемый отдельно.
4. Не начинать новый раздел, пока предыдущий не прошёл §7 целиком. Лучше один раздел доделан, чем три начаты.
5. Не «улучшать» то, о чём не просили, и не менять дизайн/устройство вне канона. Новая идея → строка в TASKS «Предложения», не код.

## 1. Общение с пользователем

Пользователь — не программист. Ему важен результат, а не процесс.
- Писать по-русски, коротко, **человеческими словами**: что теперь работает, что проверить и где нажать, что дальше и сколько это займёт.
- Не писать: названия файлов, коллекций, эндпоинтов, коммитов, тестов, ошибок компилятора — это внутренняя кухня (она в TASKS/HISTORY).
- **Не говорить «готово», пока не проверено в браузере** (§7). Если что-то не проверено — прямо сказать «не проверил X, потому что Y».
- Спрашивать только решения, которые может принять только пользователь (что нужно бизнесу). Технические решения — принимать самому и отвечать за них.
- Видишь, что просьба приведёт к проблеме или есть способ лучше — сказать прямо и предложить.

## 2. Интерфейс — единый вид

Одно визуальное ядро на приложение и админку: `backend/pwa/ui/` (токены и компоненты). Ничего не рисовать «с нуля» в разделе.

**Стиль** (утверждён пользователем 2026-10-19) — «бумага и чернила» CRM kppdf: холодная светлая канва, графитовый текст, тёмное меню, **золотой акцент** (активный пункт меню, выделение, главная кнопка на «Главной»), холодный синий — для действий. Шрифт Inter (свой, `pwa/fonts/`, лицензия OFL — внешние шрифты запрещены CSP).

**Раскладка.** Меню **слева** (тёмное, 248px: Сегодня · Снабжение → Заявки · Склад → Остатки, Движения; внизу Корзина, Администрирование, пользователь, Выйти; у пунктов — счётчики). Сверху — поиск по всему (клавиша `/`). Содержимое — **на всю ширину экрана** (поля 32px, на планшете 20px, телефоне 12px), без ограничения ширины — у пользователя широкие мониторы, пустых полей по бокам быть не должно. Планшет (<1100px): меню свёрнуто до иконок. Телефон (<720px): меню выезжает по кнопке ☰.
**Проверять на ширинах 1920, 2560, 1024 и 390 px** (снимки — headless Edge, как в skill `datacore-verify` §3а).

**История и кнопки ‹ ›** (2026-10-21, НВ): новый шаг истории — смена раздела, открытие карточки (шаг помечен «карточка»), переход по ссылке; без шага — фильтры, страницы, сортировка, вкладки, соседняя запись в открытой карточке. Закрыть карточку, открытую шагом, — это «назад» (без лишних записей и петель); иначе — убрать `open=` без шага. ‹ неактивна на первом шаге сеанса, › — когда впереди ничего; подсказка «Назад: Склад». «Назад» (кнопка, браузер, жест Android) при открытом окне сначала закрывает окно; при несохранённой форме — одно «Выйти без сохранения?», «Отмена» — остаёмся с вводом. Всё — в `core/router.js` + `core/nav-stack.js`; в разделах `history.*` и импорты с именами глобальных объектов не использовать (тест `src/pwa-guards.spec.ts`).
**Тёмная тема** (2026-10-19): кнопка «Тема» в меню (как в системе → светлая → тёмная), выбор — в браузере (`localStorage 'dc-theme'`), общий для приложения и админки (`pwa/theme.js` подключается в `<head>` до стилей — без вспышки). Гамма по просьбе пользователя — «зелёный на графите»: текст мягкий мятно-серый (не белый), заголовки/кнопки/ссылки/выбранный пункт — зелёные, жёлтый — только «требует внимания». Тёмная тема — это **только** переопределение токенов `:root[data-theme='dark']`; цвет, зашитый в разделе, в тёмной теме сломается — поэтому запрещено. Новые токены: `--heading`, `--on-primary`, `--on-danger`, `--link`, `--row-hover`, `--row-selected`, `--hint-bg`, `--side-text-hi`. Проверка — снимки в обеих темах (`QA_THEME=dark`).
**Переходы.** В меню приложения и админки: «Администрирование» ↔ «Рабочее место», «CRM» (только на сервере, путь `/db/…` → CRM на корне домена), «Тема». Админка (`backend/admin/`) — тот же каркас: меню слева, токены `../app/ui/tokens.css`, на всю ширину.

**Токены** (CSS-переменные в `ui/tokens.css`, свои цвета в разделах запрещены):
- шрифт Inter, базовый 14px; таблица 13.5px; цифры — `tabular-nums`;
- **выпадающие списки** (2026-10-21, ВС): в открытом списке текст не обрезается — панель шире поля, пункт переносится, у края экрана разворот, на телефоне — лист снизу; правило живёт в общих `ui/combo.js`, `ui/suggest.js`, `ui/popup.js`, `ui/select.js`, `base.css` — в разделах свои списки не рисовать;
- **иерархия текста** (2026-10-20, жалоба «заголовки от текста не отличить»): h1 страница 26/700 · h2 карточка/окно 19/650 · h3 блок/очередь/панель 16/650 — все цвета `--heading`; текст 14/400; подпись 12.5 `--muted`; метка заглавными 11.5 (`--fs-label`: шапка таблицы, раздел карточки). Шапка очереди — полоса `--surface-2`. Заголовки задавать только тегами h1–h3, свои размеры в разделах запрещены; ячейки таблицы не переносятся (длинное — колонка `clip`); два статуса подряд — с промежутком;
- отступы кратны 4: 4/8/12/16/24/32;
- радиус 10px (карточки, панели), 7px (поля, кнопки); тени `--shadow` и `--shadow-lg` (панели поверх);
- цвета: `--bg`, `--surface(-2,-3)`, `--text`, `--muted`, `--border(-strong)`, `--side*` (меню), `--gold*`, `--primary*`, `--danger`, `--ok`, `--warn`, `--info` + `*-soft`; статусы — только из набора бейджей `ui/badges`.

**Принципы рабочего стола (утверждено 2026-10-19 — «никаких прыжков и моргания»):**
1. **Действие не уводит со страницы.** Кнопка в строке / карточке делает дело на месте (статус, приём на склад, новая заявка из склада открывается панелью тут же — параметр `of=<раздел>`). Переход на другую страницу — только по явной ссылке «Все →» или пункту меню.
2. **Без моргания.** Экран строится один раз; фильтр, страница, сортировка, поиск — `list.update()`: строки остаются видны (приглушены), сверху бежит тонкая золотая полоска, затем меняются. Скелетон — только при первой загрузке.
3. **Карточка рядом со списком.** На экране ≥1400px карточка пристыкована справа (`.drawer.docked`, без затемнения, список кликается), второстепенные колонки (`md-hide`) прячутся. Клик по другой строке / ↑↓ меняет содержимое той же панели. Уже — панель поверх с затемнением.
4. **Спокойный вид.** Статус — точка + обычный текст, без цветных плашек; фильтры статусов — вкладки с подчёркиванием; кнопки действий в очередях нейтральные, синие — только у строки под курсором; золото — только «текущее/выбранное/требует внимания».
5. **Поиск: пусто = всё** (2026-10-21, ПО). Стёрли строку (до пусто, крестиком, Esc) — список целиком, `q` уходит из адреса; поиск в шапке — возврат на экран, откуда начали. Везде один компонент `ui/searchbox.js`; ответы старых запросов отбрасываются.
5. **Паспорт = экземпляр, модель — отдельно** (2026-10-21, ПС). Номер паспорта, талон (ГГГГМ-№) и номер изделия выдаёт сервер, выданные не меняются молча; новый паспорт — выбором модели (подставляются габариты, материалы, описание, картинки), остаётся заказчик и дата. Категории — один общий список без дублей.
5. **Быстро, с клавиатуры.** `/` — поиск, `N` — новая запись, ↑/↓ — соседняя запись, Esc — закрыть, Enter в быстрой строке — добавить. Быстрое добавление одной строкой (`ui/quick.js`, `section.quick`) — для частых записей; полная форма — в карточке.
6. **Каждое изменение статуса можно отменить** (кнопка «Отменить» во всплывающем сообщении).
7. **Каждый список подсказывает, что делать** (`list.hints` — строка под вкладками для текущего фильтра) и даёт **кнопку следующего шага в строке** (`list.rowAction`, можно несколько): Заявки — «В заказ / Заказано / Оплачено / Принять»; Остатки — «+ Приход / − Списать / Заказать»; Движения — «Отменить»; Заказы — «Отгружено / Оплачено». Журналы группируются по дням (`list.groupBy`).
8. **Перетаскивание** (доска) — своё, на pointer-событиях: карточка поднимается и едет за курсором с тенью, на месте — пунктир, колонка-цель подсвечена золотом, Esc — отмена; палец — долгое нажатие. Встроенный drag&drop браузера (полупрозрачный призрак, значок «нельзя») не использовать.

**«Сегодня»** (`sections/home.js`) — не витрина, а список дел: строка цифр (клик прокручивает к очереди), быстрая заявка, очереди «Нужно заказать» → [Заказано], «Ждём поставку» → [Оплачено] [Принять], «Ждут решения» → [Отменить] [В заказ], «Закончилось на складе» → [Заказать], лента движений. Клик по строке — карточка справа. **Доска** (`ui/board.js`): колонки по статусам слева направо, карточки перетаскиваются между колонками (= смена статуса; в «Получено» — через окно оприходования). Переключатель «Таблица / Доска» — у раздела с `list.board`. **Плитки** над списком (`list.tiles`) — быстрый фильтр (категории склада).

**Склад — «Операции»** (2026-10-20): несколько позиций — одной операцией, как на кассе: слева подбор (поиск «м10 гайка», кнопки-фильтры из названий: тип → резьба → длина → стандарт), справа список с количеством, одна кнопка; «Отменить» отменяет всю операцию. Режимы: списание (под заказ), приход (без заявки, новая позиция на месте; приёмка машины по счёту), пересчёт (дата пересчёта). Одиночные «+ Приход / − Списать» в строке «Остатков» остаются.
**Артикул ≠ внутренний код** (2026-10-21, АР): «Артикул (поставщика)» — из заявки, таблицы или руками; «Внутр. код» — автоартикул `СКЛ-<год>-<№>` (ставится, когда своего нет: поле обязательно в общей схеме) и `sku`. СКЛ-… за артикул не выдаём. Артикул заявки переносится в позицию только вместо пустого / СКЛ-… (`stock/article.ts`); свой артикул не перезаписывается — расхождение и дубли в «Требуют заполнения» («Артикул в заявке другой»); артикул уникален (409).
**Вес — способ ввода, склад хранит штуки** (2026-10-21, НО): «штуками / по весу» — один компонент `ui/weight-count.js` (новая позиция, приход, пересчёт, ⚖ в «Операциях»); по весу: вес 1 шт. (из карточки или образец N шт = M г) · партии − тара → ≈ штук, считает сервер (`stock/weight.ts`), расчёт — в примечании движения. Вес 1 шт. вводится и показывается в граммах, хранится в `weightKg` (кг) с пометкой `weightUnit: 'kg'`; старые записи без пометки — граммы (миграция — `scripts/weight-grams-to-kg.js`, после «да»).
**Пересчёт** (2026-10-21, ФИ): человек вводит, **сколько лежит всего, вместе с забронированным** (бронь физически на складе); разницу считает сервер от своего остатка (`move type:'count'`, `expected` — что было на экране, разошлось — 409), не браузер. До сохранения — предпросмотр «по учёту → станет, свободно станет»; без изменений «Сохранить» неактивна; меньше брони, ноль или изменение больше 50% — второе нажатие подтверждает; ниже брони сервер без `force` не пропускает (и в «Операциях»). В журнале у корректировки — «было → стало».
**Завершённое не копится** (фаза М): «Получено», «Отменено», выполненные заказы — по месяцам (текущий раскрыт, прошлые — строкой с количеством и суммой, прошлые годы — строкой года). Отдельного архива нет.
**Против дублей**: в новой заявке подсказки «уже заказывали / есть на складе» (с фильтром по категориям); выбор заполняет наименование, ед., категорию, поставщика.

**Роли и деньги** (2026-10-20): роли по старшинству — директор ⊃ бухгалтер ⊃ менеджер ⊃ наблюдатель; администратор — всё и пользователи. Суммы, оплаты и платёжный календарь видят только администратор, директор и бухгалтер: в разделах денежная колонка/поле помечается `money: true` (список и форма сами скрывают), в карточках — проверка `session.canMoney`; сервер скрывает суммы сам (`MoneyMaskInterceptor`) — интерфейс лишь не показывает пустое.
**Деньги — только факт по сегодня.** Будущие даты в календаре и сводке не показываются; будущее — только во вкладке «Прогноз» (БЗ-1), факт и прогноз не смешиваются. Минус красным — только у реального остатка денег, введённого пользователем.
**Фото** в карточке — общий компонент `ui/photos.js`: перетащить, Ctrl+V, выбрать файл; раздел подключает `card.photoAdd/photoRemove`.

**Кнопки.** Главное действие экрана — одна синяя кнопка справа вверху («+ Заявка»). Опасные — красные, только в карточке, никогда в строке списка. Каждая кнопка: понятный глагол («Сохранить», «Удалить», «Оприходовать»), состояние «идёт сохранение…» (выключена), результат — всплывающее сообщение.

### Экран-список (одинаковый во всех разделах — компонент `ui/list.js`)
- Сверху: заголовок + счётчик («Заявки · 163»), строка поиска, фильтры (выпадающие списки/чипы статусов), кнопка «+ Создать».
- Компьютер: **таблица** с колонками, клик по заголовку — сортировка ▲▼. Телефон (<720px): та же выборка карточками.
- **Постранично**: 25 / 50 / 100 строк, «‹ 1 2 3 … ›», «Показано 26–50 из 163». Страницы, поиск, сортировка, фильтры — **на сервере** (параметры `page, limit, search, sort, фильтры`).
- Состояния: загрузка (скелетон), пусто («Заявок нет. Создайте первую» + кнопка), ничего не найдено («Сбросить фильтры»), ошибка («Не удалось загрузить. Повторить»).
- Фильтры и страница сохраняются в адресе (`#requests?status=ordered&page=2`) — «Назад» и обновление страницы их не сбрасывают.
- Клик по строке — карточка записи.

### Карточка записи (`ui/card.js`)
- Открывается боковой панелью справа (компьютер) / на весь экран (телефон).
- Режим просмотра: поля подписями; кнопки «Изменить», действия раздела (напр. «Оприходовать»), меню «⋯» → «Дублировать», «Удалить».
- Режим правки — форма (`ui/form.js`, поля из описания раздела): обязательные помечены *, ошибки — под полем, по-русски; «Сохранить» / «Отмена».
- Длинная форма делится на цветные блоки по смыслу (`{ section, tone: main|info|money|who, collapsed?, fixed? }` в полях): первым — самое частое (блок `fixed`), редкое — свёрнуто; свёрнутый блок показывает заполненное, состояние помнится, при ошибке блок раскрывается сам. Ширина поля в блоке — `span: 1|3` из 4 колонок (по умолчанию 2, `wide` — вся строка). Выбор из 2–4 вариантов — `type: 'segment'` (кнопки), не выпадающий список. Образец — форма заявки (`sections/requests.js`). Закрытие с несохранёнными правками → «Выйти без сохранения?».
- Внизу — «История»: кто и когда менял (из журнала аудита).
- Связанные записи — ссылками (заявка → позиция склада, заказ → оплаты/заявки).

### Удаление
- Всегда с подтверждением: «Удалить заявку №123 «Болт М8»? Её можно будет восстановить из корзины».
- Удаление = мягкое (`deletedAt`). После удаления — сообщение с кнопкой «Отменить» (10 сек).
- Раздел «Корзина» (в меню слева): удалённое, «Восстановить».
- Нельзя удалить то, на что ссылаются (позиция с остатком/движениями, контрагент с заказами) — сообщение, **почему** и что сделать.

### Тексты
Только по-русски, без технических слов («Не удалось сохранить: нет связи с сервером», а не «HTTP 500»). Даты `19.10.2026`, деньги `12 500,00 ₽`, количества без лишних нулей.
**Ошибки (ОШ, 2026-10-23):** пользователю — только русский текст «что случилось + что сделать» («Нет связи с сервером. Проверьте интернет и повторите»). Технические детали (TypeError, стек, английский текст сервера) — только в консоль и служебное поле `detail`, никогда в окно. В приложении любой текст ошибки — через `errText(e)` (`ui/errors.js`), всплывашка — `toastError`; необработанные ошибки ловит `installGlobalErrors`. На сервере — `message` по-русски; новый английский текст исключения без перевода валит юнит `error-messages-ru.spec` (страж).
**Сбор ошибок (ОШ2, 2026-10-25):** все сбои приложения уходят на сервер в таблицу `clienterrors` (без данных форм, токенов и параметров адресов); в браузере ошибки не показываются и не копятся для человека. Нет связи — сбой ждёт в очереди и уходит при первой возможности. Чинить — по топу с сервера (`GET /client-errors/top`), а не по жалобам; топ читает агент `datacore-access`, после каждой выкладки — проверка.

## 4. Сервер (backend)

- Каждая сущность приложения — полный CRUD: `GET /x` (список), `GET /x/:id`, `POST /x`, `PATCH /x/:id`, `DELETE /x/:id` (мягко), `POST /x/:id/restore`.
- Список: `?page=1&limit=25&search=&sort=-date` + фильтры полями; ответ `{items,total,page,limit}` (+ `counts` для чипов, `sum` где есть деньги). Разбор параметров — общий `common/list-query.ts` (сортировка только по разрешённым полям, иначе 400). Приложение просит 25/50/100; сервер принимает до 1000 (совместимость со старыми клиентами).
- Удаление проверяет ссылки и отвечает 409 с русским `message`, почему нельзя.
- Ошибки — `message` по-русски, пригодный для показа пользователю.
- Новая сущность — по skill `datacore-new-module`. Общие с kppdf коллекции (склад, снабжение) — схемы не ломать (kppdf заморожена, но работает с ними).
- Контракт `/api/...`, ключи `kppd_`, форма ответов — не ломать (AGENTS.md).
- **Загрузка файла** — новая точка загрузки = опции как `photos/image-upload.options.ts` (10 МБ, белый список mime, без SVG, имя `randomUUID()`); путь к файлу из базы — только через `safeUploadPath` (`common/uploads/safe-path.ts`). (ARCH-PLAN М7.1, М1)
- **Новый модуль «Рабочего места» — сразу со spec** (хотя бы на сервис: создание, правка, удаление). (М7.2)
- **Чужую схему не регистрировать копией** `XSchema` в `forFeature` — импортировать модуль-владелец. (М7.3)
- **Модули общаются через публичный сервис-фасад**; события (EventEmitter, брокер) не вводить без сценария «A не должен знать о B». (М7.4)
- **Сырой `db.collection()`** — помнить про мягкое удаление (`deletedAt: null`) явно; единый слой — задача АБЗ-3. (М7.5)
- **Тяжёлый расчёт списка** — через кэш по версиям данных (`DataVersionService.cached`, ARCHITECTURE «Кэш тяжёлых списков»): указать все коллекции, из которых считается.

## 5. Данные

- **Ограниченный набор значений → справочник и выпадающий список (требование пользователя, повторено много раз; 2026-10-23):** поле, у которого разумно 5–100 вариантов (сортамент, марка стали, ед. изм., категория, вид, способ, статус, цвет, покрытие…), — **не свободный текст**: значения — в «Справочниках» (своя группа по разделу), в форме — выпадающий список с поиском (`combo`/`enhanceSelect`), новое значение можно вписать — оно предлагается добавить в справочник. Так нет двух написаний одного и то же, и фильтры по полю работают точно. Свободный текст — только для по-настоящему разных значений (название, примечание, адрес). Перед новой формой — проверить каждое поле по этому правилу.
- **Варианты списка грузятся при открытии списка, а не формы** (требование 2026-10-23): тяжёлые списки (склад, заявки, изделия) — по первому фокусу поля; короткие справочники — один запрос с кэшем.
- **Заказчик = контрагент (2026-10-21, ЗЧ):** список «Заказчик» везде (заявка, заказ, позиция заказа, фильтры) — один: контрагенты-заказчики + заказчики заказов (`partners/customer-names.ts`). Вписанные когда-то тексты и список Google-таблицы вариантами не становятся; новый — только явным «+ Новый заказчик «…»» (заводит контрагента); участок / объект — в «Объект СМР / уточнение», не через запятую в «Заказчике».
- **Справочники — в одном месте (2026-10-21):** люди — только `persons` («Справочники → Сотрудники»): «кто подал», «кому выдано», ФОТ берут их оттуда; единицы, категории, цвета, виды работ, графики выплат, типы счетов, услуги — только из «Справочников» (`/api/dicts`). Свой список в разделе (массив в коде, строки в настройках) не заводить — расширять справочник.
- **Одна сущность — одна таблица (2026-10-23):** данные не принадлежат приложению; сотрудники, организации, цвета, изделия… хранятся в одном месте, любое приложение (data-core, kppdf, будущие) подключается к нему. Новую таблицу под уже существующее понятие не заводить — расширять существующую (план объединения дублей — TASKS БЗ-14).
- Данные священны: никаких массовых удалений/перезаписей на проде без «да» пользователя; перед изменением структуры — бэкап.
- Один хозяин у данных: правит приложение. Внешний импорт (Google-таблицы) не перезаписывает то, что изменено в приложении, и не возвращает удалённое (PRODUCT «Решения»).
