- [ ] Сравнить варианты с владельцем и согласовать правила видимости полей. До этого решение остаётся экспериментом.

Витрина сохраняет только учебные значения в браузере. Рабочий API не подключён. Календарь в тёмной теме использует нативную тёмную тему браузера.

## Вариант после сравнения с примером владельца

Оставили меню витрины и правую панель. Из примера взяли шапку со сводкой, открытый блок доставки и подписи к свёрнутым разделам. Позиции открыты: видно, что заказали, сразу после полей. Оплата, договор, файл и история показывают краткое содержание в закрытом виде. Оплата в витрине зависит от учебного сценария; в рабочей карточке её берём из фактических платежей.

Первый шаг внедрения после согласования: в существующей карточке счёта собрать открытый блок «Доставка» из штатных полей, а в «Реквизитах» оставить данные документа. Переиспользовать существующий частичный PATCH двух полей, проверку прав и обновление карточки после сохранения. Тот же экран и маршрут, без нового API. Состояние ожидания даты оплаты требует отдельной проверки перед переносом. Затем отдельно добавить сводки в заголовки готовых блоков.

Chromium PASS: восемь пунктов меню, сохранение и очистка, черновик при смене статуса, просмотр части позиций, раскрытие файла, ширины 1280 и 1920. Оба снимка просмотрены. Это эксперимент для сравнения, решение пока не закреплено в стандарте.
