## Задача 1: адаптивный grid внутри `passportFill` (M-UI)

**Файлы-кандидаты:**
- `backend/pwa/sections/passports/fill/paint.js` — paintSlots рисует слоты
- `backend/pwa/sections/passports/fill/index.js` — сборка секций
- `backend/pwa/ui/kit/kit.css` — добавить `.p-row`, `.p-photo-side`

**Суть:** в `passportFill` каждый слот-фото сейчас рендерится как отдельный полноширинный блок. Нужно обернуть слот + относящиеся к нему поля в `div.p-row.p-photo-side`; когда панель ≥ 580 px (класс `wide` на `.detail`), grid становится `150px 1fr`, иначе `1fr`.

**Критерий пользы:** чертёж габаритов и действующие поля «Длина», «Ширина», «Высота» в миллиметрах видны рядом без лишней прокрутки.

**Минимальный тест:**
```js
// в passports/fill/paint.spec — снимок DOM: при wide=true slot и fields в одной строке grid
assert(slotWrapper.classList.contains('p-photo-side'));
```
Также: `dc check` (tsc + unit зелёные).

## Задача 2: `wide`-класс и drag-resize на `.detail` (M-UI)

**Файлы-кандидаты:**
- `backend/pwa/ui/panels.css` (или `base.css`) — правила `.detail.wide .p-photo-side`
- `backend/pwa/core/prefs.js` — сохранять/восстанавливать ширину панели
- `backend/pwa/sections/*.js` — подключить ResizeObserver при монтаже

**Суть:**
1. Добавить drag-handle (8 px) на левый край `.detail` с pointer events.
2. ResizeObserver на `.detail` — ставить/снимать класс `wide` при 580 px.
3. Сохранять ширину в `prefs` (ключ `detailW`), восстанавливать при загрузке.
4. `max-width: min(760px, 60vw)`, `min-width: 320px`; основная область не схлопывается ниже 480 px.

**Критерий пользы:** resize без прыжков фокуса, содержимое перестраивается плавно, значение не сбрасывается при переходе между разделами.

**Минимальный тест:**
- Ручной smoke: потянуть панель до 300 px → нет горизонтального скрола, нет вертикальных букв.
- `dc check`.

## Задача 3: компактная шапка и scroll-контейнер (S-UI)

**Файлы-кандидаты:**
- `backend/pwa/ui/base.css` — `.panel-head`, `.topbar`
- `backend/pwa/sections/passports/fill/index.js` — шапка passportFill

**Суть:**
1. `.panel-head`: убрать лишние `padding-top/bottom`, зафиксировать `position: sticky; top: 0`.
2. Убедиться что прокрутка ровно одна: `overflow-y: auto` только на `.panel-scroll`, не на `.detail`.
3. Topbar 56 px — шапка `.page-head` без `margin-top` внутри `page-content`.

**Критерий пользы:** последний элемент формы достижим прокруткой без двойного скроллбара. Шапка не тратит > 56 px.

**Минимальный тест:**
- Элемент «Сохранить» виден при прокрутке вниз без вспомогательного скрола.

## Задача 4: единые компоненты paste-zone и fileButton в kit (M)

**Файлы-кандидаты:**
- `backend/pwa/ui/kit/photos.js` — `pasteTarget`, `fileButton`
- `backend/pwa/ui/kit/kit.css` — `.paste-zone`, `.photo-slot-actions`
- `backend/pwa/sections/passports/fill/paint.js` — использовать новый API

**Суть:**
1. `pasteTarget` уже есть; добавить aria-атрибуты (`tabindex`, `role=button`, `aria-label`) в kit.
2. Переиспользовать `fileButton` из kit. Видимое действие получает фокус клавиатуры и открывает выбор файла по Enter и Space.
3. Для заполненного слота постоянно показывать кнопку «Заменить». После загрузки сохранить фокус на том же действии. Подпись назначения и обязательность читаемы в обеих темах.

**Критерий пользы:** пользователь с клавиатуры может добавить/заменить фото (Tab → Enter → диалог файла).

**Минимальный тест:** Tab → Enter → выбор → превью → Space → замена; проверить видимый фокус, отмену, вставку, касание и второй потребитель фото. Измерить контраст текста и фокуса на фактических фонах в обеих темах. Дополнить проверкой `axe-core`.
