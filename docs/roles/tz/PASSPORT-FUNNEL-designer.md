## 1. Где «глаза разбегаются»
Форма паспорта (sections/passports/form.js): около 55 полей в 9 блоках одной панелью. Изделие (поиск, 5 чипов категорий, список до 60, «+ Создать», «нет в Продукции»); «Данные изделия» (7 полей); «Категория и состав» (7: категория, нормативы, элементы, таблица материалов + покрытие + текст, способ установки, «разобранный», «схемы узлов»); «Ограничения» (10 чисел); сертификат (3); «Запомнить» (1); «Выпуск» (3); «Описание» (4); «Картинки» (3 + ~8 свёрнутых); комплектность; «после печати» (8).
Лишнее на глазах:
- 🟡 «Готовность к выпуску» (wire-form.js:135) — уже почти воронка «чего не хватает», но вверху мелким серым списком ссылок и дублируется внизу (.pp-need-foot). «Не хватает» и «всё есть» выглядят одинаково серо.
- 🟡 «Данные изделия» (имя, артикул, 4 размера, «Категория каталога») — копия изделия, менеджер их не выбирает, а они на виду как поля ввода.
- 🟡 «Ограничения и техданные» — 10 чисел всегда; нужны только поля категории (allowedFields уже есть в справочнике).
- 🟡 Служебные настройки как шаги: «Поставляется разобранным», «Схемы узлов», «Запомнить для следующих паспортов» (подпись «Да — категория, состав, ограничения, срок, гарантия» длинная), «Свой текст для этого паспорта», «Описание целиком».
- 🟡 «Назначение» и «Установка» — выпадающий список всех текстов категории (это и есть «15 текстов вместо 2–3 вариантов»).
- 🟡 «Категория паспорта» и «Категория каталога» рядом — путаются.
Справочники паспортов (dicts.js:59–66, passport-texts.js): в меню 10 справочников подряд + «Разделы и тексты →». Два места для текстов: «Готовые тексты паспорта» (плоская таблица: раздел / категории строкой «TRN, WRK» / текст; коды вписываются руками, опечатка = текст пропал; дубли и пустые не помечены) и «Разделы и тексты» (дерево пунктов-абзацев; вариантов нет вовсе, только «общий / заменяет общий»). Чипы «Детское игровое (позже)», «Детское спортивное (позже)» — лишнее. 🟢 Само дерево с правкой справа и меткой «общий» сделано хорошо.

## 2. Вид «воронки» (правая панель section.form, модалок нет)
Сверху вниз:
1. Изделие: миниатюра · название · «Сменить» (есть .pp-prod-sel). Под ним строка-сводка серым: «Воркаут · 1500×800×2300 мм · 120 кг — из изделия · править в изделии» (ссылка открывает изделие в панели). Поля имя/артикул/размеры/каталог — не поля, а эта сводка; «Править здесь» — свёрнутый details.
2. «Осталось сделать: N» — крупная плашка (.fill-note), только незаполненное; каждая строка — кнопка-чип «Выбрать монтаж», «Добавить общий вид» (прокрутка + .fill-here). Всё есть — зелёная строка «Паспорт готов, можно выпускать». Плашка липкая под шапкой панели; нижний дубль убрать.
3. Шаги-воронка «Назначение», «Монтаж», «Материалы»: заголовок h3 + 2–3 крупных чипа-варианта (.pf-opts/.pf-opt: название + одна строка пояснения, role=radiogroup). Вариант один — выбран сам, пометка «подставлено». Уже определённый шаг сворачивается в строку «Монтаж: анкерное крепление · Изменить». Под выбранным — текст в 2 строки + «Развернуть» (aria-expanded) и «Править текст» (переход в справочник на этот пункт, с возвратом к паспорту — как createProductFor; вложенных панелей нет). «Свой текст» — последний чип, не отдельный сегмент.
4. Свёрнуто со сводкой «заполнено 4 из 6»: «Ограничения» (только поля категории), «Картинки», «Комплектность», «Сертификат», «После печати».
5. «Выпуск»: дата, поставщик, гарантия — одной строкой подставленного, правка по клику.
Пустая форма: пока изделие не выбрано, остальное скрыто (pp-locked, уже так); кнопка «Сохранить черновик» неактивна, рядом «Сначала выберите изделие».
Ширины: 1920 — чипы в одну строку по 3; 1024 — панель поверх, чипы переносятся; 390 — панель во весь экран, чипы колонкой не ниже 44px, длинный текст 2 строки + «Развернуть», горизонтальной прокрутки нет, выпадающие списки — листом снизу (ui/popup.js).

## 3. Справочник текстов паспорта
Один экран «Тексты паспортов» вместо двух (плоскую «Готовые тексты» убрать из меню, данные — в дерево):
- Слева дерево: раздел (Назначение, Монтаж, Материалы…) → вариант («Анкерное», «Бетонирование») → при нужде подкатегория. У строки варианта метки .badge словами: «пусто», «дубль · N» (warn), «для всех» (info). Над деревом фильтр-чипы «Все · Пустые · Дубли».
- Справа карточка: название варианта, текст (textarea), «К каким категориям» — галочки-чипы (.tag) из справочника категорий, первым «Для всех» (выбран — остальные гаснут); переменные (details, как сейчас); «Где используется: N»; «Объединить с…» (для дублей; окно из одного поля — допустимое быстрое действие) и «Убрать».
- Категории чипами вместо кодов «TRN, WRK» — убирает ошибки в кодах.
- Ширины: 1920 — дерево 360 + карточка; 1024 — дерево 300 + карточка; 390 — сначала список на весь экран, нажатие открывает карточку («← К списку»).
Общий компонент для всех справочников целиком — нет: плоские списки хорошо живут в .dict-table. Общими сделать два кусочка: (а) выбор категорий галочками-чипами (tag-pick есть; новый тип поля в dicts.defs вместо строки кодов — подойдёт и элементам, материалам, способам установки); (б) метки качества записи «пусто / дубль · N» + фильтр-чип «Пустые / Дубли» над таблицей любого справочника. Дерево + карточка — только для текстов.
