## 2. Чего не хватает до «несколько КП от разных фирм»

| Область | Сейчас | Нужно |
|--|--|--|
| Связь КП одного пакета | `copyOf` — только «копия от исходного», пакета не видно | необязательное поле `packId` (общий для КП пакета) |
| Создание за раз | одна копия за 4 действия | `POST /offers/pack`: общее тело + `companies:[{companyId, markupPercent}]` → N черновиков |
| Цены разных фирм | одна цена изделия; у копии — общая наценка % | наценка % на фирму (в пакете). Своя цена на фирму — не нужна, пока владелец не скажет (вопрос 1) |
| Номера | один общий счётчик `CommercialOffer` («КП-N») для всех фирм | вопрос 2: нужны ли раздельные ряды по фирмам |
| Экран | три карточки без связи | экран пакета: N КП в ряд, суммы, «PDF всех» |
| Принято одно КП | остальные остаются «Отправлено» | подсказка «отменить остальные КП пакета?» (вопрос 3) |
| Корзина | список фирм из `/incomes/lookups` (`kp.js:66`), т.е. без «только для КП»; `/offers/defaults` не зовёт | брать `/offers/companies` и `/offers/defaults` |

**Фирмы и бланки.** Сколько их — у меня нет данных прода. Последний снимок (KP-2, 2026-11-06): три — СИЮ, ССЮ, «Приват-деал»; ИНН у СИЮ и ССЮ пуст; у «Приват-деал» загружен старый бланк стр. 1; ИНН спорный (KP2-1). Число фирм в коде не ограничено. **Проверить на проде:** у каждой ли есть бланк стр. 1 и стр. 2, ставка НДС (`organizations.vatRate`), стандартные тексты.
**КП фирмы без бланка (риск).** `resolve()` (`offer-backgrounds.service.ts:125-143`): выбранный → бланк фирмы → общий «по умолчанию» → **встроенный** (фон СпортИН-ЮГ с логотипом, реквизитами, подписью и печатью, `AUDIT-KP.md §3`). Фирма без бланка получит чужой бланк, и ошибки менеджер не увидит. Нужно: метка «нет бланка» у фирмы в выборе и запрет/предупреждение при создании пакета.
Подписи и печати отдельно нет — они в картинке бланка (решение К10), поэтому «подпись фирмы» = наличие бланка.

## 3. Варианты устройства пакета

| | A. Пакет = метка на обычных КП (`packId`) | Б. Пакет — отдельная сущность `offerpacks` | В. Одно КП с вариантами фирм внутри |
|--|--|--|--|
| Суть | N обычных КП, у всех общий `packId`; создаются одним вызовом из базового тела | коллекция «пакет» со строками, заказчиком, списком фирм; КП порождаются из неё, правка пакета обновляет черновики | один документ, внутри `variants[]` по фирмам, N PDF |
| Плюс | всё готовое работает: статусы, версии, заказ, PDF, поиск; поле необязательное — контракт цел; без новой коллекции | один «центр правки»: поменял строку — обновились все | один номер, одна карточка |
| Минус | правка строки в одном КП не меняется в остальных (нужна кнопка «применить ко всем» позже) | новая коллекция, синхронизация, что делать с КП, уже отправленным | у каждой фирмы свой статус и номер — ломает статусы, заказ, список; большой переписанный код |
| Объём | M | L–XL | XL |

**Рекомендация: A.** Причина: статусы, номера, бланки и «заказ из КП» уже на уровне одного КП; пакет нужен менеджеру как «вместе созданные и вместе показанные», а не как новый документ. Реализация без транзакций (Mongo 4.4): сначала проверить все фирмы (есть, бланк), потом создавать по очереди; при сбое — мягко удалить уже созданные. Позже, если понадобится «правка во все», добавить кнопку, а не сущность.

| Срок действия | константа | 14 дн. в корзине, 10 в форме — **расхождение** | единое значение (вопрос в К2) |
| Доставка | прошлое КП | нет | подставлять |

| Бланк | фирма | да | предупреждать, если нет |
