# C155 — план порученного выпуска

19.11.2026. Владелец поручил в конце выложить результат на сайт. Первоначальный запрет автоматической выкладки заменён этим отдельным поручением; замена базы, перенос старых паспортов и финансовые записи не разрешались.

## Что меняется

Только DataCore: сервер шаблона/нового short, интерфейс книжки и правой панели, ссылки iLogic, словарные связи. CRM и Mongo не перезапускаются. Старые документы не переводятся в новый формат. Для защиты повторного создания нужен один unique sparse индекс `productpassports.creationScopeKey_1`; это служебный индекс собственного модуля, без изменения документов и общих схем CRM.

## Ворота и порядок

1. Принять только свои изменения, commit/push; чужие C157/C158 и pult/todo сохраняются. Штатный preflight обязан завершиться «ВОРОТА: ОК». Никаких force/пропуска проверок.
2. Через штатный `remote-access/run-script.sh passport-creation-index` получить план; `--apply` с обязательным бэкапом создаёт только этот индекс; повторный план подтверждает готовность. Несовместимость — остановка, не удаление чужого индекса. Общий `ensure-indexes --apply` не использовать для этой выкладки.
3. Запустить `remote-access/deploy.sh` с рабочего ПК. Один штатный полный выпуск: бэкап, прежний образ/код, архив только Git HEAD, сборка и перезапуск backend, проверки. Данные Mongo и CRM не заменяются. Секреты обрабатывают штатные инструменты и не выводятся.
4. Агент доступа сверяет фактические `/db/app/version.json`, health, вход, новый GET шаблона и доступность файлов, CRM и doctor. Тестовые паспорта/номера на рабочем сайте не создавать.
5. После подтверждения нового сервера агент доступа добавляет через API проверенные 25 словарных веток/32 фразы из `dictionary-content-plan.json`, с сопоставлением существующих частей/видов/критериев по ключам, повторным GET и журналом ID. Три кандидата и десять широких видов без подтверждённого состава не активировать. Сами рабочие изделия автоматически не переклассифицировать; менеджер выбирает недостающее один раз в новом шаблоне.
6. Повторно прочитать шаблоны и воронку на сайте, сверить число/связи новых фраз и отсутствие новых документов. В HISTORY/CONTROL/REPORT зафиксировать реальный hash, номер версии, результат и ограничения, затем сохранить документацию в GitHub.

## Откат

При нарушении health/hash/основного пути остановить добавление контента и использовать штатный rollback сохранённого образа/кода, не восстанавливая базу поверх рабочих данных. Новые словарные записи имеют отдельный журнал ID: если потребуется откат уже добавленного контента, отключать только созданные C155 ветки через API с сохранением ссылок и выданных снимков; исходные записи не удалять.
