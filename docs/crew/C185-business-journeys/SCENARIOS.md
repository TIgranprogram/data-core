# Проверка по ролям пользователя

Источник бизнес-правил — [PRODUCT.md](../../PRODUCT.md). Для прогона роль получает один сценарий с ожидаемым результатом и тестовыми данными. При сомнении в правиле менеджер записывает вопрос аналитику. Воспроизводимый дефект передаётся владельцу участка через [реестр](../../roles/ownership.json).

| Роль | Цель и вход | Что должно получиться |
|---|---|---|
| Менеджер заказов | Из «?» понять новый заказ, открыть этап и найти, где следить за отгрузкой. Есть заказ с одной тестовой позицией. | Видны последовательность и вход в заказ. Отгрузка относится к существующему заказу. Из окна этапа можно вернуться к карте. |
| Менеджер снабжения | Из «Требуют заполнения» открыть связанный счёт и затем заполнить дату несвязанной заявки на фикстуре. | Связанная запись открывает карточку счёта. Быстрый ввод доступен для заявки без связи. Направление затрат остаётся полем заявки. [Существующее доказательство](../C085-cursor-routine-2/REPORT.md) |
| Сотрудник производства | Из этапа «Производство» понять, как исходная позиция и наличие материалов влияют на работу. | Видна ветка «Заявки → Остатки», раздел «В работе» находит нужный этап. Проверка записи выполняется только на специально выделенной фикстуре. |

В отчёте записать роль, стартовый экран, результат и первый конкретный тупик. Для проверки полномочий использовать соответствующую роль, подтверждённую через `/api/auth/me`. Реальный пароль и данные клиентов в отчёт не передавать.
