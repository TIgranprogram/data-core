## Этапы

### Э0а — меню в карточке изделия (S/M) — в работе
Вкладки: **Техописание** отдельно от **Паспорт**; кнопки «Техописание» / «Паспорт» на виду; блок «Выпущенные паспорта» вместо «Документация».  
Файлы: `products/tabs.js`, `products.js`, `products/card-blocks.js`.

### Э0 — порядок ввода (M) — сделано 2026-11-09
Таблица материалов: колонки **Часть → Материал → Размеры** (было «Из чего» → переименовали в «Часть»).  
Файлы: `backend/pwa/ui/materials-spec.js`. Фильтр частей/покрытий по категории — C054.

### Э1 — один состав кормит ТО и паспорт (L)
- Окно «Техническое описание» пишет/читает `materialsSpec` изделия (не одноразовый черновик без сохранения).
- Паспорт по-прежнему снимает `materialsSpec` при выпуске.
- Подпись в UI: «Техническое описание», не «ТО».

### Э2 — печать трёх вариантов (L)
- API/UI: `passport` | `tech` | `combined` (один PDF: паспорт, затем техописание, или наоборот — решить в Э2 по образцу заказчика).
- Не путать с `variant=short|full`.

### Э3 — описание функциональных элементов (L)
- В форме паспорта/шаблона: явный блок «Функциональные элементы» с текстами из справочника (inDescription, usageRules).
- Аудит заполненности `passportElements` по TRN/WRK/BLG/DIO/DSP → план data-steward (как C054 parts).
- В PDF раздел «Описание» показывает перечень выбранных элементов, не пустой абзац.

### Э4 — часть → материал (M, после Э0)
Поле у `passportParts` или таблица связей: какие `passportMaterials` бывают у части; UI сужает список материала.
