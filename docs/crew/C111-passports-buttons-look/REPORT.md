## Допущения и находки
- **На копии базы нет ни одного выпущенного паспорта, связанного с заказом.** Все 9 групп «По заказам» — по номеру текстом, без `salesOrderId` (заказ № 31 — не заказ в базе). В 44 заказах нет готовых и выпущенных позиций. Поэтому выпущенные состояния проверены подменой ответа плана в браузере; окна печати (заказа и одного паспорта) открываются. Скачивание PDF заказа на живых данных не проверено.
- Следствие для владельца: на проде кнопки «Печать паспортов…» в «По заказам» появятся только у заказов, где паспорта привязаны к заказу. Привязка старых паспортов по номеру заказа — вопрос данных → в C112 (замер Э0).
- Кнопка панели переименована «Печать…» → «Печать паспортов…» — одно название во всех трёх местах (Shared pack ТЗ).

## Приёмка дизайнера (`UI-REVIEW.md`) — правки внесены
1. `//` в середине строки (`order-passport-plan.js`) — вынесены отдельными строками.
2. Класс раздела `.do-group > .k-headbar` убран → вариант эталона `headbar(…, …, { inset: true })`, показан в витрине `#kit`.
3. `scrollbar-width: thin` у всех `.chips` → только `tabs({ scroll: true })` (главные вкладки «Документации»); у фильтров — `none`.
- Замечание «кнопки S на 390 около 30 px» — свойство эталона `kit.button` size S, в разделе не чинится. Проверит `dc audit` (правила g/m на 390).
