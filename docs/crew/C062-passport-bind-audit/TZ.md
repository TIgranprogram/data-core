# ТЗ C062 — номер паспорта: фирма, списки, файл

**Зачем (словами пользователя):** при создании номера привязать к продукции/позиции; у изделия несколько паспортов (несколько фирм); повторная печать тем же №; файл к номеру; выпадающие списки в нужных местах.

**Зачем — глаголом:** менеджер за 2–3 выбора (изделие, фирма, при заказе — позиция) выпускает паспорт, видит номер в списке изделия с фирмой и печатает снова без нового номера; при своём PDF — печатает файл.

## Глубже
- **Результат:** номер только у экземпляра `productpassports`; вкладка изделия — список с фирмой; нет второго живого на позицию; опциональный файл печати на экземпляре.
- **Сырьё:** `CODE-MAP.md`, `ANALYSIS.md`; фирма уже = `supplierOrgId` (наши компании).
- **Метод:** бланк строгой отчётности; UI — kit `combo`/`select`.
- **Внешний судья:** юнит выпуска/повторной печати/замка позиции; `node --input-type=module --check` по PWA.
- **Смелая планка:** повторная печать — 1 клик по строке, 0 новых номеров.

**Класс:** L · **Max agents:** 2 (backend + frontend) · **Reviewers:** qa ☐ designer ☐ · **Max review loops:** 2 · **Проверки:** smoke  
**Язык менеджера:** да · **Приёмка:** «Новый паспорт», вкладка изделия «Паспорт», печать из списка выпущенных.

## Shared pack
- Решение: гибрид C; ПР-1…6 приняты. Фирма = `supplierOrgId` (не новое поле). Файл печати = новое поле только data-core.
- Контракт:
  - `POST /passports` — `productId` обязателен (кроме внутреннего draft-all с productId из позиции); `supplierOrgId` обязателен при ручном.
  - `POST /passports/:id/print-file` — multipart PDF → сохраняет путь; ответ паспорт с `printFile: { name, hasFile:true }`.
  - `DELETE /passports/:id/print-file` — снять файл.
  - `GET /passports/:id/pdf` — если есть файл → отдать его; иначе сборка как сейчас.
  - Список/present: `supplierOrg`, `printSource: 'file'|'app'`, в таблице выпущенных — имя фирмы.
  - Создание с `incomeId`: если уже есть живой (не annulled, не soft-deleted) — 409.

## Что сделать
### Backend
1. `create` / funnel draft: требовать `productId` + `supplierOrgId` на ручном пути; `ourSupplierId` — только fallback если одна фирма, иначе 400 «выберите фирму».
2. Замок: перед create/issue с `incomeId` — нет второго живого; без unique-индекса на проде.
3. Поле `printFile` на схеме: `{ path, originalName, uploadedAt, uploadedBy? }` (добавление, CRM не читает).
4. Upload/delete print-file; pdf отдаёт файл при наличии.
5. `showcase` список выпущенных: добавить `productCode`, имя фирмы (`supplier`), `printSource`.
6. Юниты на замок и pdf-файл.

### Frontend
1. Воронка/новый паспорт: список **фирм** (все `isOurCompany`), не первая молча; изделие уже есть.
2. Из заказа: явный выбор позиции, если не открыто из позиции.
3. Вкладка изделия «Паспорт»: колонки №, заводской №, фирма, метка «Файл»/«С сайта»; фильтр фирмы если фирм > 1; «Печать» по строке.
4. Карточка экземпляра: «Прикрепить PDF» / «Убрать файл»; печать использует API pdf.
5. Язык менеджера, kit only.

## Критерии приёмки
- [ ] Ручной выпуск без изделия или без фирмы (если фирм > 1) — нельзя.
- [ ] Во вкладке изделия видны номер, фирма, метка источника; повторная печать строки — тот же №.
- [ ] Файл прикреплён → pdf отдаёт файл; снят → снова сборка сайта.
- [ ] Второй живой на ту же позицию — 409.
- [ ] Несколько фирм на одно изделие — несколько строк в таблице.
- [ ] tsc 0; юнит паспортов; syntax-check изменённых js.

## Нельзя
