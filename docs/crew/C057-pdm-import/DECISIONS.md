# C057 — решения (сводка; совет opus 2026-11-09 + решения пользователя)

Источник решений пользователя — `ANALYSIS.md` разд. 5а (п. 1–12). Здесь — то, что из этого следует для кода. Расхождение с `ANALYSIS.md` — верно то, что здесь.

## Данные
1. **Деталь** = `materials`, `materialKind:'part'`, `article` = обозначение. Состав детали — одна строка сырья: `{сырьё-сортамент, quantity: расход (м² | м), unit, overrideDimensions: заготовка}`.
2. **Сортамент (Л13, вариант A).** Позиция `raw`, без формата, `isProfile:true`, `unit` = `м²` (лист, фанера) или `м` (труба, брус, прокат), `scrapFactor` (по умолч. 1). Складской формат — `raw` с `profileId` → сортамент, `isDefaultFormat` у одного формата. Детали ссылаются только на сортамент.
   - «Что купить»: Σ(расход × количество по дереву) по сортаменту × `scrapFactor` − остатки всех его форматов (в м²/м) → вверх до штук основного формата.
   - Цена м²/м = `lastPrice` основного формата / его площадь (длину).
   - Склад и снабжение скрывают `isProfile` и `part` (Л1). Заявка — только на формат.
3. **Новые поля** (только добавление — CRM не ломается):
   - `materials`: `pdmCode` (метизы, покупные; индекс unique с `partialFilterExpression: {pdmCode: {$type:'string'}}`), `pdmAliases[]` (индекс по массиву, partial), `pdm{fileId, version, state, path, configuration, syncedAt}` (детали), `dimSource` (`dxf|pdm|manual`, детали), `isProfile`, `profileId`, `isDefaultFormat`, `scrapFactor`, `needsName` (bool).
   - `productmodules`, `products`: `pdm{…}`, `needsName`.
   - **Не хранить** `matchKey` — считать на лету одной общей функцией (таблица приведения Л/К, `х/×`, `,/.`, синонимы) при предпросмотре и для отчёта дублей. CRM пишет `materials` и не пересчитала бы ключ.
   - **Не нужен** `consumptionUnit` — это `unit` сортамента.
4. **Название обязательно** (`materials.name`, `productmodules.name`) → при создании `name` = обозначение, `needsName:true` → «Требуют заполнения». Менеджер вписывает название — флаг снимается.
5. **`materials.sku`** — уникальный на всю базу: загрузка `sku` **не заполняет**.
6. **Изделие уже есть** (пользователь п. 9): пустое дополняем; расхождения «Сайт | PDM» — выбор человека; «Обновить всё из PDM». Смена `sku` существующего изделия — только явным выбором человека в расхождениях, с предупреждением «артикул указан в N заказах/паспортах».
7. **Конфигурации детали**: одно обозначение, родители на разные конфигурации → разные размеры. Ключ записи = обозначение; вторая конфигурация с другими размерами → `warning` в предпросмотре, загрузка этой строки блокируется до решения (пока — редкий случай, проверить частоту на каталоге).
8. **Поиск «уже есть»** — с удалёнными (обход soft-delete); нашли удалённую — восстановить и обновить (Л5).

## Файлы
9. Новая коллекция **`pdmfiles`**: `ownerKind` (product|module|material), `ownerId`, `designation`, `docKind` (pdf|dxf|assembly|install), `name`, `pdmFileId`, `pdmVersion`, `pdmState`, `modified`, `sha256`, `size`, `path`, `isCurrent`, `organizationId`. Уникальный: `{organizationId, designation, docKind, pdmVersion}`. Тот же `sha256` — не грузим повторно.
10. Путь: `uploads/pdm/<обозначение>/v<версия>/<имя>`. Обозначение и имя — строгий regex (`^[A-Za-zА-Яа-я0-9._-]+$`), иначе 400 (защита от `../`). Папка `pdm` — в `UPLOAD_FOLDERS`; `/uploads/pdm/*` — `attachment` + `nosniff` в `main.ts`. Сигнатура PDF/DXF, ≤ 50 МБ.

## Импорт
11. `POST /api/pdm-import/preview` → план сохраняется в **`pdmimports`** (id, хэш дерева, версии/`updatedAt` найденных записей, план). `apply` принимает `planId` + решения. Повтор того же `planId` — прежний итог. Записи изменились после preview → 409 «Данные на сайте изменились — проверьте ещё раз».
12. **Одна транзакция** на дерево. Порядок: сортаменты → детали → метизы и покупные → модули от листьев → изделие. Сбой — откат всего. Файлы — вне транзакции, после apply.
13. **Подвох:** `CompositionLineService.validateReference` (`composition-line.service.ts:47-95`) читает `findById` без сессии → в транзакции не видит только что созданное. Решение: проверять план в памяти до записи (все ссылки — из плана или существующие) и писать составы напрямую, либо передать `session` во все `findById`. Аудит-плагин и optimistic lock — с сессией.
14. Лимиты: тело ≤ 2 МБ, ≤ 5000 позиций, транзакция < 60 с. Составы — только `composition`; старые `materials`/`productModuleIds` не трогать.
15. Права: `admin`. Журнал — `pdmimports` (кто, когда, что создано/обновлено).
