# МЦ-7. Независимая браузерная приёмка

**PASS.** Цепочка до выпущенного PDF подтверждена на QA :3102. Независимый сценарий выполнен отдельным headless Chromium через штатный доступ. Доказательства находятся в `evidence/mc7-ui/`.

| Шаг через интерфейс | Независимая проверка |
|---|---|
| Заявка → счёт → выставление → оплата → приёмка | Ответы и ID созданных сущностей, позиция находится поиском по уникальному названию |
| Связать складскую позицию со справочником и заполнить два ручных текста | GET позиции возвращает сохранённые значения |
| Выдать 4 м под позицию заказа на 2 изделия | Предложение состава показывает 2 м на изделие |
| Принять предложение, открыть техописание и «Взять из состава» | Значения видны в предложении до сохранения. После сохранения оба текста находятся в таблице изделия |
| Открыть шаблон паспорта, скачать предпросмотр и техописание | Браузер получает два действительных PDF. Проверка текста в PDF выполняется локально |
| История недавно открытых карточек | Отдельная браузерная матрица после готовности функции |

API допускается для выделенных фикстур, независимого чтения результата и уборки по точным ID. Запросы записи из браузера ограничены собственными ID тестового сценария. Предпросмотр и фактический выпуск учитываются отдельно.

## Первый прогон на 375 px, светлая тема

**PASS для закупки и приёмки.** Через интерфейс созданы заявка и счёт, сохранены реквизиты, проведены оплата и приёмка. Ответы 201/200, после приёмки на складе найдена новая позиция с уникальным названием теста. На трёх снимках переполнение панели равно нулю.

**FAIL при записи блока «Для паспорта».** Форма приняла материал, размер и два текста. После «Сохранить» обычный PATCH складской позиции ответил 200, а PATCH паспортной спецификации не отправился. Общее поле-виджет уже вернуло разобранный объект, который `savePassportSpec` повторно передал в `JSON.parse`. Ожидается исправление и повтор с уже созданной складской позицией.

## Повтор после исправления складского виджета

**PASS для сохранения и выдачи.** PATCH паспортной спецификации ответил 200. GET складской позиции подтвердил ручной паспортный текст. Затем через «Выдать» проведены 4 м под строку заказа. POST складской операции ответил 201. Предложение состава показывает 2 м на одно изделие. В первом проходе нижнюю кнопку принятия предложения на 375 px перекрыл тост после выдачи. Повтор начинается со свежей браузерной вкладки и той же выдачи по сохранённому ID.

[Предложение после выдачи](evidence/mc7-ui/light-375-05-suggestion.png).

## Принятие состава и два PDF

**PASS.** Предложение принято через «Добавить в состав» (POST 200). «Взять из состава» подготовило строку с обоими ручными текстами. До подтверждения таблица в изделии оставалась пустой. После «Сохранить и скачать PDF» запись таблицы ответила 200, GET изделия вернул обе фразы. Предпросмотр паспорта скачан из карточки шаблона.

На странице 1 техописания находится техническая фраза, на странице 3 предпросмотра паспорта — паспортная. В обоих документах фраза другого назначения отсутствует. Ручной текст помещается целиком и не получает автоматически складской размер. Это проверено извлечением текста и просмотром рендера.

[Предложенная таблица](evidence/mc7-ui/light-375-06-proposed-materials.png), [страница техописания](evidence/mc7-ui/light-375-tech-1.png), [страница паспорта](evidence/mc7-ui/light-375-passport-3.png), [протокол поиска в PDF](evidence/mc7-ui/light-375-pdf-text.json).

## Фактический выпуск на QA

**PASS.** После сохранения таблицы материалов на своём тестовом изделии через UI пройден выпуск с выбором собственной фирмы. В выпуске выбран вариант «Без заказа». Заказ и его строка до этого использовались для складской выдачи и вычисления состава. Привязка самого выпуска к строке заказа отдельно не подтверждена. Первый автоматический выбор вернулся к общему выбору изделия. Причина перехода не изолирована, поэтому дефект интерфейса по этому запуску не заявлен.

Черновик создан ответом 201, выпуск ответил 200, GET подтвердил статус issued и паспортную фразу в снимке. Из окна печати скачан PDF 108 915 байт. В выпущенном буклете ручная паспортная фраза видна целиком на физической странице 3, техническая фраза отсутствует. Номер в снимке относится к тестовому стенду.

## Матрица экранов материалов

Заполненные формы склада и техописания открылись в четырёх сочетаниях тем и ширин 375/1920 px. Оба текста склада и предпросмотр паспортной фразы на месте, переполнение 0, исключений JS нет. Трассировка зафиксировала отдельный дефект в истории движений: `stock.js` объединял DOM-узел назначения выдачи со строкой через `join`, что превращало его в `[object HTMLSpanElement]`. Защита убирала ошибочную подпись. После исправления четыре прогона прошли без исключений, телеметрии мусора и переполнения. На 375 и 1920 px подпись «Выдано под…» видна с номером строки заказа.
