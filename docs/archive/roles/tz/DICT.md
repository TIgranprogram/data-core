## Находки аудита (важно для всех)
1. **Переименование ломает ссылки.** `update()` (`dicts.service.ts:160`) только `$set` имени. Но у 9 справочников значение в данных — **строка**, а не id: единицы (`unit`), цвета, причины списания, сортамент/марки стали, формы оплаты, типы счетов, сотрудники (`requestedBy` — «Имя Фамилия»), размеры материалов (`products.materialsSpec.rows.sizes`). После переименования позиции остаются со старой строкой, `used` падает до 0, и «удалить» разрешено. Сейчас переименование без каскада — тихая потеря связи. **Каскад нужен.** Справочники по id/коду (категории склада, группы/разделы, виды работ, графики, все «Паспорта» кроме размеров и сотрудников) — переименование безопасно.
2. **Тяжёлое:** `list()` (`:79`) на каждое открытие считает `used` для ВСЕХ строк: `tally` (aggregate с `$unwind` по всей коллекции) на справочник; у «Паспортов» — N×(countDocuments + обход `dict_values`) на строку (кэш `versions.cached` только там); у `withProducts` — countDocuments по `products` на строку. `get()` (`:98`) заодно вызывает `list(key)` целиком ради `refs` — тяжёлая цепочка на каждый клик. `related` — ещё 2–4 запроса со списком по 15.
3. **`used` неполон:** «Сотрудники» считают только `requestedBy` (не `stockmovements.issuedToPersonId`, не ФОТ); «Услуги» и «Причины списания» не считают ничего (`usage` не задан) → удалить можно всегда, хотя значения лежат в данных. «Формы оплаты» — только `incomes`.
4. **Удаление** (`remove`, `:171`): занято → 409 «объедините». Мягкое (`deletedAt`), `restore` есть. Слияние (`merge`, `:191`) переносит ссылки (`reassign`) и убирает источник в корзину с `mergedInto`; **обратно ссылки не вернуть** (в аудите только число `moved`).
5. Справочников в `DICTS` — **24** (не 21) + два «не справочника» (`ptexts` — Общие разделы, дерево `passportPhrases` — свой экран).

Взамен: (а) статически в шапке справочника — «Применяется в: …» из описания (`sections` в `DictDef`, без запросов); (б) по требованию — `GET /dicts/:key/:id/usage` (см. п. 3), один быстрый запрос на открытие карточки / диалога. Счётчик слева в навигации (`count`) — оставить (один `countDocuments` по справочнику, дёшево).

## (3) Единое поведение «занято»
Один диалог для любого справочника (добавить в `dicts.js`, правая панель — `modal`/форма как у `mergeDialog`).
- **Открыл карточку / нажал ✎ или ✕:** запрос `GET /dicts/:key/:id/usage` → `{ sections: [{ id, label, count }], total }`. Показ: «Используется в: Остатки, Заявки». `total === 0` — «Нигде не используется».
- **Переименовать:** занято → предупреждение «Новое название поменяется везде: Остатки, Заявки (N записей)». Сервер: `PATCH` с `refBy:'name'` справочника делает каскад (новое поле `rename` в `DictDef`; по умолчанию = `reassign(cur, {...cur,...set})` ТОЛЬКО для справочников «строка»; для id/код — не вызывать: у `ppUsage.reassign` при `from._id===to._id` pull-after-push стирает ссылки). Всё в одном обновлении; в аудит `dict.renamed {moved}`.
- **Удалить, не занято:** подтверждение «Удалить? Восстановить можно из корзины» (как сейчас).
- **Удалить, занято:** вместо тоста-отказа (`remove.blocked`, `dicts.js:317`) — диалог: «Используется в: … (N). Выберите: [Заменить на … ▾] [Только переименовать] [Отмена]». «Заменить» = существующий `POST :key/:id/merge` (переносит ссылки, источник — в корзину). Кнопка «Удалить» видна всегда (админ вправе); ответ 409 остаётся серверной защитой для прямых вызовов API.
- **Права:** ✕ занятого значения — роль `admin`/владелец (на сервере `@Roles`: `merge` сейчас менеджер; для ✕-с-заменой — нужен admin; manager — только добавить/переименовать). `editRoles` паспортов сохраняются.
- **Обратимость:** слияние необратимо без бэкапа → в тексте подтверждения: «Это нельзя отменить кнопкой»; перед массовым переносом (> 50 записей) сервер пишет в аудит список затронутых id (`dict.merged` дополнить `movedIds` до 500). Данные прода — резерв `backup.sh` уже по cron; ничего удалять физически нельзя (только `deletedAt`).
- **Добавить** (`+ Добавить`) — как сейчас; «Найти в данных…» оставить (не тяжёлое, по клику).
