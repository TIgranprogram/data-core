# Импорт и автоматическое обновление запасного сервера

20.11.2026 соседний координатор сообщил: при согласованном окне записи C157 импорт получил 503 READ_ONLY; refresh завершился 05:56:29–05:57:56 UTC (08:56:29–08:57:56 МСК). Это сообщение второй сессии, время и инициатор уточняются GET-сверкой. Наш чат не выполнял prod refresh/release и не менял продовое расписание.

Код установленного e89b11b3 проверен через git show: autoRefresh() независимо проверяет интервал и вызывает refreshPeer(true), записывает autoAt после постановки. Обычное согласование окна между чатами не приостанавливает серверный таймер. В предыдущем readonly baseline интервал был 15 минут; это делает таймер вероятным источником, но без совпадения lastAt/job или журнала инициатора не доказывает источник конкретного запуска.

Урок: не обещать беспрерывное окно записи на основании запрета ручных refresh/release. Сначала проверить активное расписание и текущий job. Для гарантированного окна нужен явно подтверждённый временный запрет автоматического обновления с последующим восстановлением; не выключать защиту readonly и не повторять финансовые записи вслепую. Не менять .env/таймер на проде ради проверки гипотезы.

В C166 две настройки расписания позволяют явно приостановить плановые обновления после выпуска. Автоматическая блокировка расписания на время импорта пока не реализована и не должна объявляться готовой. Возобновление импорта после 503 — только по его сохранённому журналу с проверкой частичного результата.
