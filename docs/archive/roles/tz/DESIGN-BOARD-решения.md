# DESIGN-BOARD — решения совещания (architect/opus + designer, 2026-10-25); ПЕРЕБИВАЮТ tz/DESIGN-BOARD.md при расхождении

## Сервер (architect)
- Коллекция `designorders {orderId (unique, индекс БЕЗ deletedAt), addedBy, addedAt, deletedAt}`; в `salesorders` (общая с CRM) поле НЕ добавлять.
- Добавление заказа — upsert по `{orderId}`: `$set{deletedAt:null}` + `$setOnInsert{addedBy,addedAt}`, обязательно `setOptions({includeSoftDeleted:true})` (иначе плагин мягкого удаления → повторное добавление упадёт на 11000). «Убрать» = поставить `deletedAt` (409, если у заказа есть открытые задачи — понятным русским текстом).
- В GET в базу НИЧЕГО не писать. Список заказов доски = живые `designorders` ∪ `distinct orderId` открытых задач (queue/work/paused); заказы, удалённые в CRM (`salesorders.deletedAt`), отсекать. Миграции не нужно.
- Upsert метки в `insert()`/`fromOrder()` — ПОСЛЕ создания задачи, необязательный шаг (try/catch + лог): сбой метки не даёт 500.
- Задача создаётся ОДНИМ POST `{incomeId,status,assigneeId?,pauseReason?}` (не «создать, потом PATCH»). С левой стороны сброс разрешён только в queue/work/paused (создание сразу в done не ставит замок `openIncomeId` — запретить). 409 на гонку остаётся (уже есть, service:131).
- `GET /design-board` (один запрос при открытии): заказы доски (кап 200 + total), счётчики по статусам одним `$group {orderId,status}`, открытые задачи (кап 500 + total); позиции заказа — только для раскрытых: `GET /design-board/:orderId/lines`; «Завершены» — существующим `/design-tasks?status=done` порциями по 20. Проекции без тяжёлых полей, одно фото, сборка через `$in` как в `presentTasks`. `cached` не использовать. Без цен.
- `POST /design-board {orderId, distribute?}` — добавить (distribute=true → создать задачи queue на все позиции без задач, пакетом); `DELETE /design-board/:orderId`. Права: `@AppSection('design')`, чтение — все 4 роли, запись — admin/manager. Существующие `/design-tasks*` не менять. Индекс `designorders.orderId` добавить в `scripts/ensure-indexes.js` MODELS; на проде после выкладки `ensure-indexes --apply`.

## Экран (architect + designer)
- Движок: НОВЫЙ `ui/drag.js` (`draggable(el,{canStart,onDrop,targetSel,scroller})`) только для новой доски, `ui/board.js` НЕ трогать. Исходная карточка слева остаётся приглушённой (opacity .5), в колонку вставляется временная карточка, при неудаче удаляется. На карточке `pointerdown` — `stopPropagation`; перерисовку по `data-changed` откладывать на время перетаскивания. Классы `drag-ghost/placeholder/drop/body.dragging` общие. На 390 и с клавиатуры — только меню «Статус» (bottom sheet).
- Новая доска — вид по умолчанию (`design.js`); старый плоский — `?view=flat` (запасной, удалить позже). Колонки: Распределение · В работе · Приостановлены (узкая, свёрнута если пусто) · Завершены (ORDER в design.js:18 поправить на queue,work,paused,done).
- Левая колонка «Заказы» 300 px (260 при 1024): карточка заказа `.db-order` с цветной полоской 6px, шеврон, «ЗНП …» + заказчик, срок/приоритет, счётчики ненулевых статусов, меню ⋯ («Открыть», «На распределение все позиции», «Убрать из проектирования»); раскрытый — вложенные `.db-line` (фото 36px, «поз. N · название»), полоска 3px. Справа `.tcard.db-task`: рамка + левая полоса 4px цвета заказа, чип «ЗНП …». В колонках группы по заказу (подзаголовок: точка цвета + «ЗНП … · Заказчик»), «Без заказа» — серая группа.
- Цвет заказа: чистый хеш `orderId` → 12 токенов `--oc-1…--oc-12` (+ `--oc-N-soft`) в обеих темах (hsl из макета: 265 55 50 · 320 55 48 · 20 65 45 · 185 55 35 · 240 50 55 · 335 60 45 · 85 45 38 · 280 40 45 · 30 55 38 · 210 45 45 · 165 40 33 · 0 0 45; тёмная — L 62–68%, S −5%; soft: светлая L94% S40%, тёмная альфа .16); цвет не единственный признак — всегда текст «ЗНП №».
- «+ Добавить заказ»: popover под кнопкой (на 390 — лист снизу): поиск «№ заказа или заказчик», строки «ЗНП … · Заказчик» + срок и «N поз.», у выбранной две кнопки «Добавить и на распределение» / «Только добавить». Пусто: «Нет подходящих заказов. Добавлены все заказы в работе, либо заказа нет — проверьте раздел «Заказы»».
- Перенос: drag (десктоп) + кнопка «Статус» (⋯ 44×44 → bottom sheet «Куда перенести «…»?»: Распределение, В работе, Приостановить, Завершить, Вернуть на распределение; текущий — «сейчас»). В «В работе» без исполнителя — окно «Кто проектирует?» (select + «Назначить и взять в работу», пусто → «Выберите исполнителя», отмена — ничего не создаётся). Тост «Взято в работу · Отменить» (отмена = DELETE задачи). 409 → «Позицию уже взяли» + перечитать. Уже взятая позиция слева: приглушена, бейдж статуса + «в колонке «В работе» →».
- Правая панель `.drawer`: заказ — открыты «Заказ», «Изделия к проектированию», «Как идёт проектирование»; свёрнуты «Что в позициях», «Заказчик и доставка», «Файлы и чертежи», «История». Изделие — открыты «Состояние», «Исполнитель и срок»; свёрнуты «Изделие», «Примечание»(открыт если есть), «История». Цен нигде, кодов (incomeId, queue) на экране нет.
