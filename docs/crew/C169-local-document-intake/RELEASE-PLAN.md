# C169 — конкретный план выпуска

Поручение владельца: закончить пульт, проверить, commit/push и выложить готовое. Новая серверная часть нужна для устойчивой загрузки оригиналов и атомарного счёта: существующая цепочка отдельных POST не гарантирует безопасное восстановление.

1. Принять полный QA, независимые UI/архитектуру и сквозной изолированный прогон. Готовый candidate сохранить в GitHub/main, preflight без обхода ворот.
2. Штатный `deploy/synology/release.sh`: резервная копия, замена кода, только backend, health/статика/CRM/version hash. Рабочих тестовых документов не создавать.
3. В backend runtime передать через stdin проверенный `backend/scripts/c169-intake-indexes.js` (SHA-256 `66ef8e8e8407d026400874977278afb43ae8faef337407caaa079d35ddfed928`), сначала только план. Скрипт не входит в Docker image и не требует копирования секретов.
4. Если план совместим, применить только перечисленные 5 индексов: Photo UID, SupplyInvoice UID/business key/source SHA и неуникальный fileIds. Никакого backfill, удаления/замены индексов, переписывания документов или общей схемы SupplyRequest. Повторный план должен показать все 5 ready; конфликт останавливает процедуру. До готовности индексов новые маршруты возвращают 503 до мутации.
5. Независимым API GET подтвердить новую версию, работу маршрутов (404 для несуществующего UID после проверки индексов), сохранность основных паспортных показателей, отсутствие активной опасной операции и актуальное расписание. Проверка настоящего импорта на проде — только будущие пользовательские документы.
6. Пульт получает код через Git/штатное автообновление. Поручение «Настроить папку разбора…» открывает новый раздел. Папка/контур/модель хранятся отдельно на ПК, пароль/сессия только в памяти.

Откат — штатный rollback образа и согласованных экранов. Добавленные служебные индексы обратно автоматически не удаляются. Они разреженные, исторические документы без новых полей не требуют переноса.

Из проверок общего репозитория: areas2031/2031 PASS, карточки0 сломанных (2 устаревших). `atlas --check` нашёл существовавший уже в origin/main долг C166: servers переведён plan→legacy в 3fe6b35d, legacy18 при baseline17. C169 карту не менял. Повышать baseline или объявлять соответствие эталону только ради зелёного результата нельзя; отдельная сверка эталона серверного экрана остаётся в очереди C166.
