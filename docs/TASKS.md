## 💡 Предложения под главную цель («любое приложение легко работает с базой»)

- [ ] **P1. Универсальное хранилище данных приложений** — сейчас под каждую новую таблицу нужен модуль на бэкенде (skill `datacore-new-module`). Предложение: `/api/apps/:app/:collection` — CRUD JSON-документов без кода на сервере: `GET` (фильтр/сортировка/пагинация `{items,total,page,limit}`), `GET /:id`, `POST`, `PATCH /:id`, `DELETE /:id` (soft-delete). Хранение в коллекциях `app_<app>_<collection>` (VISION принцип #4), имена — `[a-z0-9_]`, лимиты размера документа/коллекций, служебные поля `createdAt/updatedAt/createdBy`, аудит, опциональная JSON-Schema на коллекцию. Появляется в админке «Таблицы» как `kind:'app'`. Решение за пользователем: делать ли, и нужна ли схема-валидация с первого дня.
- [ ] **P2. Ключи с ограниченными правами.** Сейчас `kppd_`-ключ действует с правами выдавшего (обычно admin) — утечка ключа одного приложения = полный доступ. Предложение: при выдаче ключа задавать scope: `read` / `read+write`, список приложений `apps:[...]` (для P1) и/или разделов; `JwtAuthGuard` пересекает права ключа с правами пользователя. Аддитивно: старые ключи = текущее поведение.
