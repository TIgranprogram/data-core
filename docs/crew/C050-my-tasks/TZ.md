# ТЗ C050 — «Мои задания»: вход рабочего по роли + роль «Мастер»

**Зачем (слова пользователя, 2026-11-08):** у сотрудников свои входы по ролям; открывается только экран по задачам, без цен: представление задачи, выполнено, отложено. Красиво, с хорошим функционалом. Мастер распределяет работу в Ганте. У сотрудника может быть несколько ролей — выбирает директор. Рабочим платят по часам; ставки и суммы на рабочих экранах не показывать.
**Глаголом:** рабочий открывает телефон, видит свои задачи на сегодня и нажимает «Начал» / «Закончил» за 2 касания, без поиска заказа. Мастер за 1 касание видит «Отложено» и «Проблема» и перераспределяет в Ганте.

## Глубже
- **Результат:** цель «Производство»: факт часов ставится на участке, а не потом в «Составе» (C048 набл. 7: сейчас 4–5 шагов, нужно ≤ 2); данные для табеля (C048 набл. 1) становятся надёжными.
- **Сырьё:** `orderlineplans.steps[]` на проде (сколько шагов с `assigneeId`; у скольких `persons.userId` заполнен — по коду не заполняется, `design.service.ts:113`); число сотрудников с видами работ. Замер через координатора и access до старта Э1.
- **Метод профи:** цеховой терминал MES: список «моё на сегодня», одна крупная кнопка действия, причина простоя из короткого списка; мастер разбирает «светофор» отклонений.
- **Внешний судья:** e2e «рабочий» (токен роли) — чужие задачи и деньги не приходят в JSON; дизайнер на 390 px по чек-листу `docs/DESIGN-MOBILE.md` §8; число касаний на стенде.
- **Смелая планка:** «Начал» → «Закончил» = 2 касания; список < 300 мс; 0 денежных полей в ответе рабочего.

**Класс:** XL · **Max agents:** 5 (backend, frontend, qa, architect, designer) · **Max review loops:** 2 · **Проверки:** full
**Язык менеджера:** да (без кодов; статусы словами; пустое состояние «На сегодня заданий нет») · **Приёмка:** стенд на 390 px, под токеном рабочего.

## 1. Роли и вход (что есть → что меняется)
Есть по коду: у пользователя одна строка `role` (`user/user.schema.ts:44`); своя роль = `baseRole` + `appSections` + «Деньги» (`common/roles-hierarchy.ts`, `app-sections.ts`); меню по `session.sees()` (`pwa/core/api.js:46`); роль-образец «Ассистент кладовщика» — один раздел `stock-mobile`, меню скрыто (`api.js:57`). Связь пользователь ↔ сотрудник: `persons.userId` читается, но нигде не пишется. Отметка шага `POST /orderline-plans/:id/steps/:stepId/mark` — только admin/manager (`order-line-plan.controller.ts:57-59`), без проверки исполнителя. У `persons` есть `salaryRate`, `hoursPerDay` (`dicts.defs.ts:567,578`).

Решения (минимум, без поломки users/CRM):
1. **«Рабочий»** — своя роль на `baseRole: user`, `appSections: ['my-tasks']`, галочка «Деньги» выключена. Новый раздел `my-tasks` добавить в `APP_SECTIONS` и NAV. Вход: как «Ассистент кладовщика» — меню скрыто, сразу «Мои задания».
2. **«Мастер»** — своя роль на `baseRole: manager` с разделами «В работе», «Гант», «Мои задания» (мастер тоже работает руками), «Деньги» выкл., ФОТ не виден. Мастер правит Гант и разбирает «Проблемы». Менеджер распределять тоже может (допущение, вопрос 1).
3. **Несколько ролей.** `users.role` остаётся одной (CRM читает её). Добавляем необязательное `users.extraRoles: string[]` (по умолчанию пусто). Права = объединение `effectiveRoles` по всем ролям; разделы меню = объединение `appSections`; «Деньги» = если хоть одна роль даёт. Задаёт только директор/админ в карточке сотрудника (мульти-выбор «Роли»). Меняются `effectiveRoles`, `openSectionsFor`, `canSeeMoney` (ядро + юнит), в `/auth` — `user.sections` объединённые, `user.roles`.
4. **Сотрудник ↔ вход.** Поле `persons.userId` (необязательное) заполняет директор выбором «Вход в систему» в карточке сотрудника (список активных пользователей, один пользователь — один сотрудник). Без связи экран пишет «Ваш вход не привязан к сотруднику — скажите директору» и ничего не показывает.
5. Старые пользователи и CRM не затронуты: новые поля необязательны, `role` не меняется.

## 2. Экран «Мои задания» (телефон-первый)
Эталоны: kit `mobile` (`ui/kit/mobile.js`: `screen`, `bigButton`, `choice`, `textField`, `done`, `error`), образец `sections/stock-mobile.js`; стандарт `docs/DESIGN-MOBILE.md`. Новый вариант эталона не нужен (карточка задания собирается из `screen` + `bigButton`); если дизайнер скажет иначе — сначала kit и витрина #kit.

**Список** (сверху «Сегодня», затем «Позже», внизу свёрнуто «Готово сегодня»). Карточка: название изделия, часть, вид работ, № заказа, срок, метка статуса. Крупная кнопка по состоянию. Тап по карточке — подробности: фото и чертёж изделия (просмотр), примечание мастера, норма «≈ N ч» (не деньги).
**Статусы** (слова): «Ждёт» · «В работе» · «Отложено» · «Проблема» · «Готово».
**Действия:** «Начал» → «Закончил» (тот же `mark`, пишет факт-часы — `recordStep`); «Отложить» — причина из списка (нет материала, нет чертежа, ждёт другого участка, поломка, другое + короткий текст) и «на когда» (по умолчанию завтра); «Проблема мастеру» — причина + необязательное фото/текст. Один «Начал» одновременно: второй — подсказка «Сначала закончите текущее» (допущение).
**НЕ видно:** любые цены, ставки, суммы, часы к оплате; чужие задачи; остальные разделы. Фильтр на сервере: `assigneeId = мой person`, ответ без `MONEY_FIELDS`.

### Сценарии (число касаний от открытия приложения)
1. Начало работы: список → «Начал» = **1** касание (список уже открыт).
2. Конец работы: «Закончил» в той же карточке = **1**; всего 2 на задачу.
3. Нет материала: «Отложить» → причина «Нет материала» → «Готово» = **3** (срок по умолчанию завтра).
4. Проблема: «Проблема мастеру» → причина → «Отправить» = **3**; +1 если с фото.
5. Посмотреть чертёж: тап карточки → «Чертёж» = **2**.
Правило: оффлайн/повтор — по `DESIGN-MOBILE.md` §7; полноценная работа без связи — C051, здесь только не терять нажатие (отметка с `clientTime`, повтор безопасен).

## 3. Откуда задачи и как видит мастер
- Единственный источник — шаги планов `orderlineplans.steps[]` с `assigneeId` (решение C047). Старые `worktasks` в «Мои задания» не входят (допущение; иначе двойной счёт). Запуск позиции уже создаёт шаги; задача рабочего = шаг, где `assigneeId = его person` и план запущен.
- Новые необязательные поля шага: `status` (`deferred|problem`), `reason`, `reasonNote`, `deferUntil`, `reportedAt/By`; история в журнале (`AuditAction`). Отдельной сущности «проблема» не заводим.
- Серверные точки (новые, узкие): `GET /my-tasks` (свои шаги, без денег), `POST /my-tasks/:planId/:stepId/{start|finish|defer|problem}`. Роль-проверка: шаг принадлежит текущему сотруднику, иначе 403. Существующий `mark` не расширяем (остаётся admin/manager).
- Мастер: в Ганте полоса «Отложено» (штриховка) и «Проблема» (красный маркер + причина во всплывающей панели шага); в «Сегодня» мастера — счётчик «Проблем: N», тап открывает список; уведомление `notifications` мастеру при «Проблема» (канал уже есть, `notification.schema.ts`). Отложенное сдвигает полосу на `deferUntil` только после подтверждения мастера (авто-сдвига нет — допущение).

## 4. Этапы
| Э | Что | Кто |
|--|--|--|
| Э1 сервер | `extraRoles` + объединение прав; `persons.userId`; `/my-tasks*`; поля шага; фильтр денег; юнит + e2e | backend |
| Э2 карточка сотрудника | «Роли» (мульти), «Вход в систему», создание ролей «Рабочий»/«Мастер» сидом (`appSections`) | frontend + backend |
| Э3 экран | «Мои задания» (kit mobile), скрытое меню, пустые состояния | frontend, designer |
| Э4 мастер | статусы в Ганте, счётчик в «Сегодня», уведомление | frontend |
Порядок: Э1 → Э2 → Э3 → Э4. Нужен C047 Э1 (фильтр людей по видам работ) — до него Гант показывает лишних людей. После Э3 — `node backend/scripts/pwa-preload.mjs`.

## Критерии приёмки
- [ ] Если рабочий под своим токеном запрашивает `/my-tasks` — приходят только его шаги, ни одного поля из `MONEY_FIELDS`; чужой `planId/stepId` → 403.
- [ ] Если у рабочего роль «Рабочий» — после входа видна только «Мои задания», меню скрыто; остальные API разделов → 403.
- [ ] Если у пользователя две роли — права и разделы объединены; снятие роли у директора убирает права со следующего входа.
- [ ] Если нажать «Начал», «Закончил» — шаг получает `startedAt/finishedAt`, факт-часы записаны; повтор того же запроса ничего не дублирует.
- [ ] Если «Отложено» с причиной — мастер видит статус и причину в Ганте и счётчике за ≤ 1 обновление; «Проблема» шлёт уведомление мастеру.
- [ ] На 390 px: кнопки ≥ 48 px, 2 касания на задачу, чек-лист `DESIGN-MOBILE.md` §8 пройден; сценарии 1–5 по числу касаний.
- [ ] Старые пользователи/CRM: вход, `role`, существующие тесты зелёные; smoke по этапам, full перед выкладкой + строка TEST-LOG.

## Риски
- Объединение ролей трогает ядро прав (`roles-hierarchy.ts`) — самый рискованный кусок; только за юнитами и e2e, `role` — приоритетная, `extraRoles` лишь добавляют.
- `persons.userId` на проде пуст — без заполнения директором экран пустой; нужен пункт `pult/todo.json` «Привязать сотрудников ко входам».
- Фото задач в публичном `/uploads` (VL-1): чертёж отдавать по тикету, не ссылкой.
- Табель: «Закончил» не равен оплачиваемым часам; деньги по факту — отдельное решение (C048 вопрос про зарплату).

## Заметка про C051
Работа без связи на участке: очередь действий (старт/финиш/отложить/проблема) с `clientTime` и серверной защитой от дублей; кэш списка и чертежей на смену. Решает C051, здесь только идемпотентность.
