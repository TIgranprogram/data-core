# C028. Аудит блока «Элементы» (2026-11-07, аналитик; решение принято координатором — варианты по умолчанию)

## 1. Зачем элементы нужны
- Из `passportElements` собираются разделы PDF: «Описание» и «Назначение» (`describeProduct`, `inDescription` — passport-compose-parts.ts:73), «Правила пользования» (`usageRules`) и таблицы осмотра (`inspect`) — passport-compose-parts.ts:86, 102–144. Тексты заполнены у 27 из 56 элементов.
- Выпуск: `elements` обязательны для всех категорий, кроме BLG (passport-rules.ts:225); элементы закрывают «Назначение» (rules.ts:222).
- Шаг «Чего не хватает» (passport-gaps.ts:60–80) показывает весь справочник: `forCat` пропускает 11 элементов с пустым `categories` и режет только по категории, не по группе.

## 2. Данные
- `elements` заполнены у 22 паспортов из 342 (TRN 8, WRK 6, BLG 9). У 320 нет — PDF без правил и осмотра.
- 56 элементов: изделие/снаряд ≈ 35; деталь ≈ 14 (Втулка, Ось, Маховик, Педаль, Каркас, Каретка, Косынка, Накладка, Опорная пластина, Подшипниковый узел, Ограничитель хода, Основание…); крепёж 5 (Анкер, Закладная деталь, Крепёж, Заглушка, Кронштейн); прочее 1 (Информационная табличка).
- `passportParts` (43) — склоняемые «части» для текста, не элементы. Анкер и закладная деталь дублируют «Способ установки».
- В `facets-seed.json` поля `elementIds` нет (ANALYSIS §3 его описывает).

## 3. Решение
1. Элементы подставляются сами из `elementIds` значения признака (и записываются в умолчания изделия). Пользователь их не выбирает.
2. Шаг показывается, только если признак элементов не дал (редкие изделия): список строго по категории, без деталей и крепежа, выпадающие списки, подпись «Что это за изделие».
3. Детали и крепёж в паспорт не идут: крепление — «Способ установки», комплектность — спецификация (`bom`).
4. WRK/DIO/DSP/TRN: без элементов паспорт не выпускается (иначе в PDF нет правил и осмотра). BLG — как было, не требуются.
5. Юридически: состав приходит из утверждённого значения признака, а не из ручного выбора среди 30 меток.

## 4. Данные (скрипт план → --apply по «да»)
- `passportElements.kind`: `product` / `part` / `fastener` (по §2); `categories` у 11 пустых — по смыслу.
- `facets-seed.json`: `elementIds` (коды/названия элементов) у значений признаков TRN, WRK, DIO, DSP.
- Старые 22 паспорта не трогать.
