# C096 Э2 — реализация формы

Статус: код реализован; визуальная приёмка PARTIAL (не выполнена этим агентом). Без коммита, деплоя, доступа к БД.
Использованы datacore-design, datacore-verify, datacore-docs-sync. Область только E2-TZ; form.js/common.js и сервер не изменены.

## Изменения
- Общий inert заменён точной картой наследования: сохранённый черновик использует fromProductFields, новый — непустые источники полного изделия, materialsSpec→_mspec. Сертификат, seat*, supports, shipVolume и прочие поля экземпляра доступны. Непустые гарантия/элементы/тексты изделия блокируются с видимой меткой источника и переходом к правке. Блокировка выпущенного через lockIssued сохранена.
- Реальные поля изделия сохраняют источник. «Изменить в изделии» открывает вложенную правую панель с возвратом и обновлением подставленного. Ссылка готовности на заблокированное поле вызывает этот переход.
- «Сменить» сразу очищает productId и блокирует сохранение. Ручное сохраняется; при следующем выборе старые автоматические значения очищаются.
- У числовых умолчаний и установки явное «Принять», подпись «не сохранено». Закрытие и проверка готовности больше не записывают предложения.
- Частичные размеры и очистка отправляются по существующему PATCH (parseDimensions допускает отсутствующие координаты); сантиметры/метры переводятся в миллиметры. Неизвестная единица требует исправления. Вес допускает очистку. Ошибочный ввод сообщает причину.
- Сохранения шаблона выстроены последовательно: полный PUT умолчаний не теряет соседнюю запись.
- Ненайденный элемент справочника больше не выбрасывается молча.
- Ошибка проверки готовности содержит «Повторить» в обычной форме и заполнении.
- Предпросмотр через существующий POST /passports/preview доступен при заполнении и перед выпуском, номер не занимает.
- Готовый файл отмечает dirty до успешного сохранения. Номер обязателен и передаётся явно, включая предложенный.
- Удаление картинки черновика требует подтверждения. Добавление не меняет r.images до успешного PATCH.
- Использованы текущие kit-компоненты и существующая группировка fill; новый CSS не добавлен.

## Исправление после проверки координатора
- Подтверждён риск молчаливого перезаписывания элементов/текстов/гарантии productPatch. Прежняя широкая разблокировка заменена точной картой.
- По возврату из изделия сохранённый черновик получает свежие fromProductFields. У новых карта вычисляется по непустым источникам, включая false/0 и алиас материалов.
- Ручной выбор textChoices, таблица материалов и очищенные вручную значения при applyProduct не перетираются. Если ручное значение конфликтует с наследуемым, поле блокируется с явным предупреждением о замене сервером.
- Ручные purpose/installationMethod при включённом «Свой текст» доступны: серверная diffPatch имеет именно это исключение.
- Переход к недостающему choice также открывает источник, если textChoices заблокирован.
- Тестируется фактически вызываемая lockProductFields из product-block.js, а также applyProduct через VM: серверная карта, aliases, снятие устаревших замков, новые источники, ручные соседние значения и очистка.
- Устранено затенение сетевого api объектом формы в resetOwn: используется requestApi.
