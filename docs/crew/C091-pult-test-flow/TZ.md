## Результат
Один основной путь в разделе ИИ-тестировщика: «Проверить сайт» → подготовка → запуск → состояние → отчёт.
Пользователь выбирает только длительность. Ошибка подготовки останавливает цепочку и показывает следующий шаг; второй обход не стартует.
Отчёты остаются в существующих tools/logs/ai-tester, запуск пульта — в pult/logs. Ничего не очищать автоматически.

## Приёмка
1. Главный экран раздела: статус, одна главная кнопка запуска, длительность, доступный «Результаты»; «Остановить» только при активном обходе.
2. Служебные установки/снимки/очистка — «Дополнительно», без потери доступности.
3. Уже установленно разведчиком: run.mjs:638–657 внутри --detach сам проверяет готовность/пробует setup до фонового запуска. Переиспользовать ait-run, не вызывать отдельный ait-check и не дублировать подготовку. Проверить код, при ошибке показывать неуспех; не считать read-only, не запускать во время другого обхода.
4. Пульт не объявляет detached запуск завершённой проверкой: отличать запущен/работает/закончен/нет отчёта/сбой.
5. Отчёт можно открыть после перезапуска пульта; путь к сохранённым ошибкам виден. Пустое состояние понятно.
6. Тесты цепочки с подменой процессов: success, подготовка fail, повторный запуск, уже идёт, stop, отсутствующий отчёт. Существующие тесты пульта зелёные; gen-docs.
7. Browser-fixture безопасный: реальные UI файлы, API-заглушки; проверить кликами узкую/широкую раскладку, работа/ошибка/готово. Сохранить до 3 целевых снимков. Дизайнер независимый после реализации; не выдавать фикстуру за реальную длительную проверку.
