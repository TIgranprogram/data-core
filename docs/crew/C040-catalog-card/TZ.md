# ТЗ C040 — «Каталог номенклатуры»: убрать лишние кнопки, полная карточка позиции с аналитикой

**Зачем (словами пользователя, 2026-11-07):** «В галерее кнопка „Все списком“ дублирует „Таблицу“ — убрать. „Очередь «Связать с позицией»“ — непонятно, о чём; переименовать понятно или убрать. Правая панель номенклатуры — мало информации: сверху не видно, что я открыл; кроме истории цен нужна история поставщиков; цены — последние по порядку; где что находится; сколько заказывалось, когда; аналитика — отдельным блоком без кнопок, красиво, эталонно; заказчики, количества. Остальное — по блокам, табличные блоки, раскрывающиеся по нашим эталонам. Привести в полный порядок.»
**Зачем — глаголом:** снабженец открывает позицию и за 5 секунд видит: что это, где лежит и сколько, у кого брали и почём (динамика), сколько и когда заказывали и выдавали, на какие заказы и каким заказчикам ушло — без кнопок и переходов.

## Глубже
- **Результат:** одна правая панель «Позиция номенклатуры» = полный паспорт позиции; аналитика — отдельный блок только для чтения.
- **Сырьё (что уже есть):** `GET /stock/items/:id/ordered` (`stock-search.service.ts:~205–230`: `suppliers[{name,count,lastDate,lastPrice,lastQty}]`, `open[]` заявки в пути, `inTransit`); `GET /stock/items/:id/history` (движения); `GET /materials/:id/where-used`, `GET /materials/:id/prices`; `storageitems` (остатки по складам/местам). Экран: `backend/pwa/sections/supplier-catalog.js` — посадочная :130–142, карточка `card:` ~:330–360; действия — `supplier-catalog-actions.js`.
- **Метод профи:** паспорт позиции как в ERP: шапка-тип → ключевые числа (KPI-строка) → блоки «Где лежит», «Поставщики», «История цен», «Заказы и выдачи» → «Аналитика» (график по месяцам + топ заказчиков). Одна сводка с сервера одним запросом, не 6 запросов с экрана.
- **Внешний судья:** юнит сервиса сводки; e2e не обязателен; на проде через access: сводка по 3 реальным позициям — ответ < 300 мс; дизайнер; `dc audit` без новых находок.
- **Смелая планка:** карточка открывается < 500 мс, ни одной кнопки в блоке «Аналитика», 0 служебных кодов на экране.

**Класс:** L · **Max agents:** backend + frontend + designer · **Проверки:** smoke; full — перед выкладкой. **Язык менеджера:** да.

## Shared pack — контракт
`GET /api/materials/:id/summary` (роли как `GET /materials/:id`; деньги — только если `canMoney`, иначе поля цен `null`, как в `itemOrdered`). Только чтение. Ответ:
```
{
  id, name, article, unit, categoryName,
  stock: { total, free, reserved, places: [{ warehouseName, place, qty }] },
  suppliers: [{ supplierId, name, count, totalQty, firstDate, lastDate, lastPrice, minPrice, maxPrice }],   // все, кто поставлял (полученные заявки) + предложения каталога без закупок (count 0)
  prices: [{ date, price, supplierName, source: 'purchase'|'catalog' }],                                  // по дате возрастанию, ≤ 50 последних
  requests: { total, open, lastDate, items: [{ id, num, date, qty, statusLabel, supplierName }] },         // ≤ 20 последних заявок
  issued: { totalQty, items: [{ date, qty, orderId, orderNum, customerName, workType }] },                // выдачи со склада, ≤ 20 последних
  monthly: [{ month: 'YYYY-MM', ordered, received, issued }],                                             // 12 месяцев
  customers: [{ name, qty, orders }],                                                                      // топ-10 заказчиков по выданному/зарезервированному количеству
  usedIn: { products: n, orders: n }                                                                       // из where-used
}
```
- Источники: `supplyrequests` (по `materialId`), `stockmovements` (выдачи, тип расхода, связь с заказом → `salesorders.customer`), `storageitems`, `supplieritems`. Переиспользовать `stock/purchase-history.ts` (`foldPurchases`). Общие с CRM коллекции — только чтение, схемы не менять. Mongo 4.4.
- Агрегации — с ограничением по `materialId` и индексам, которые уже есть; если нужного индекса нет — записать в отчёт, не создавать.

## Что сделать
1. **backend:** маршрут и сервис сводки (`material` модуль или `stock`, где удобнее по зависимостям — без циклов модулей), юнит-тесты, строка в `docs/MAP.md`.
2. **frontend — посадочная** (`supplier-catalog.js:136–142`): убрать кнопку «Все списком» в шапке посадочной (переключатель «Таблица» уже есть); в пустом состоянии «Категорий пока нет» — оставить одну кнопку «Показать таблицей». Блок «Очередь „Связать с позицией“» переименовать: заголовок «N строк прайса не связаны с позицией склада» + пояснение «Свяжите их, чтобы цена и поставщик подставлялись в заявку» + кнопка «Связать» (тот же переход). Фильтр `FLAGS` :27 — подпись «Не связаны со складом».
3. **frontend — карточка** (правая панель позиции; для предложения с `materialId` — тот же паспорт позиции + блок «Это предложение» сверху):
   - Шапка: тип открытого — «Позиция номенклатуры» / «Предложение поставщика» (подзаголовок/надзаголовок kit), имя, артикул, категория.
   - KPI-строка (эталон kit — числа-плашки, что есть): остаток · в пути · заказано за год · выдано за год · последняя цена.
   - Блоки (секции kit, раскрывающиеся там, где длинно): «Где лежит» (таблица мест), «Поставщики» (таблица: поставщик, сколько раз, всего, последняя дата, последняя / мин–макс цена), «История цен» (таблица по дате, последняя — сверху или снизу, но порядок по дате; отметка поставщика), «Заявки» (последние 20), «Выдачи» (последние 20, заказ и заказчик).
   - Блок «Аналитика» — только чтение, без кнопок: столбики по месяцам (заказано / получено / выдано) + топ заказчиков. Если в kit нет эталона мини-графика — **сначала** добавить вариант эталона в kit (`ui/kit/` + витрина `#kit`, отдельный шаг, по skill `datacore-design`), потом использовать. Пустые данные — понятная подсказка («Пока не заказывали»).
   - Действия (Ш6) — остаются в футере и «⋯».
4. **designer:** приёмка по коду и стенду (если доступен).
