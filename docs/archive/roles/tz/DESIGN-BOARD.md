# ТЗ DESIGN-BOARD — «Проектирование»: заказ → изделия по статусам

**Зачем (словами пользователя, 2026-10-25):** проектирование = беру заказ из списка и «проектирую» его. Слева колонка «Заказы» (те, что я выбрал, добавляю из выпадающего списка или «кидаю на распределение»). Справа канбан по статусам. Заказ раскрывается прямо в колонке, изнутри я вытаскиваю карточку изделия и тащу по статусам. Связь с заказом видна: карточка в карточке, у каждого заказа свой цвет, изделия того же цвета. Клик — справа панель с полной информацией по категориям (главное сверху, справочное свёрнуто).

**Класс:** XL (новая коллекция + новый экран) · **Max agents:** 5 · **Reviewers:** qa ☑ architect ☑ designer ☑ (макет — ДО frontend) · **Max review loops:** 2 · **Проверки:** full
**Язык менеджера:** да — без кодов D-N как главного заголовка, без «incomeId/queue»; пустые состояния с подсказкой · **Приёмка:** сайт глазами (390 px и десктоп): добавить заказ, раскрыть, перетащить позицию в «В работе», открыть панель

## Shared pack
**Что уже есть (оставить):**
- Сервер `modules/design` (`design.service.ts`, `design-present.ts`, `design-task.schema.ts`, `design.controller.ts`), коллекция `designtasks`: **задача = изделие/позиция заказа** (`incomeId` → `incomes`, `productId` → `products`), статус `queue|work|done|paused`, исполнитель, срок/приоритет «из заказа» (`manual.*` — свои), пауза с причиной, замок «одна открытая задача на позицию» (`openIncomeId`), `from-order` без дублей. Всё это — модель карточки изделия; **менять её не нужно**.
- PWA: `sections/design.js` (список/доска/форма/карточка, `moveTask` с причиной паузы и проверкой исполнителя, `dueNode`), `sections/order-design.js` (блок «Проектирование» в карточке заказа, «Передать выбранные/все») — **оставить как есть**, это второй вход.
- `ui/board.js` — общая доска (перетаскивание на pointer-событиях: мышь 6 px, палец — долгое нажатие 350 мс) — **не ломать**, другие разделы.

**Что переделать:** сейчас доска плоская (4 колонки задач, заказ виден только строкой «ЗНП…»), «взять заказ в проектирование» как понятия нет: единственный путь — кнопка в карточке заказа. Нужны: (а) сущность «заказ на доске проектирования», (б) новый вид доски «заказы слева + статусы справа», (в) панель заказа.

**Решения по умолчанию (без вопросов пользователю):**
1. Статусы колонок справа: **Распределение · В работе · Приостановлены · Завершены** (= `queue/work/paused/done`, ярлыки уже в `DESIGN_STATUS`, `ui/badges.js:26`). «На проверке» не вводим: данных/процесса проверки нет; добавим, когда пользователь назовёт. «Приостановлены» — узкая колонка справа, по умолчанию свёрнута, если пусто.
2. «Заказ взят в проектирование» = запись в **новой** коллекции `designorders` `{orderId (unique), addedBy, addedAt, deletedAt}`. Поле в `salesorders` НЕ добавляем (коллекция общая с CRM). `designorders` — только data-core (индекс в `ensure-indexes.js`, `kind` в реестре не нужен).
3. Левая колонка = записи `designorders` ∪ заказы, у которых есть открытая (не `done`) задача (ленивый «подхват» уже существующих задач, без миграции прод-данных; запись создаётся при первом чтении). Убрать заказ из колонки можно, только если у него нет открытых задач (иначе 409 «В заказе N задач в работе — завершите или удалите»); задачи при этом не удаляются.
4. Позиция заказа без задачи — «изделие в заказе, ещё не взято»; живёт внутри раскрытого заказа слева. Перетаскивание такой позиции в колонку справа **создаёт задачу** (`POST /design-tasks {incomeId,status}`); перетаскивание задачи между колонками — `PATCH` (`moveTask`). «Кинуть на распределение» = `from-order` для всего заказа (все позиции → `queue`).
5. Цвет заказа — **только на клиенте**: стабильный хеш `orderId` → индекс в палитре 10–12 оттенков (токены, не status-цвета ok/warn/danger/info, чтобы не путать со статусом). Поля в базе нет. Цвет никогда не единственный признак: рядом всегда «ЗНП № …» (коллизии палитры возможны, это нормально).
6. Права: читать — раздел `design` (`@AppSection`), писать (добавить/убрать заказ, перенос, исполнитель) — admin и manager (как решено ПРЖ-3, `QUESTIONS.md:118`). Остальным — доска только на просмотр, перетаскивание и кнопки скрыты (`session.canEdit`). Цен в выдаче нет (как в `design-present.ts`).
7. Таблица (`?view=table`) и текущая форма «Новая задача» остаются: свободные задачи без заказа (`orderId` пуст) — в доске в отдельной группе «Без заказа» справа внизу каждой колонки, слева не показываются.

**Контракт backend ↔ frontend (новое, в `modules/design`):**
- `GET /design-board` → `{ orders: [{ orderId, orderNo, customer, deadline, priority, stage, note, addedAt, lines: [{ incomeId, lineNo, title, qty, productId, sku, photo, task: {id, code, status, assignee, deadline, priority, pauseReason}|null }], counts:{queue,work,paused,done,free} }] }` — выдача пакетом (как `presentTasks`, один `$in` на заказы/позиции/изделия, без N+1). Без цен.
- `POST /design-board {orderId, distribute?: boolean}` → запись + при `distribute` вызов `fromOrder` → `{orderId, created, skipped}`; повтор безопасен (unique по `orderId`; уже есть — 200 без ошибки).
- `DELETE /design-board/:orderId` → `{orderId, removed:true}` или 409 (есть открытые задачи).
- Выпадающий список заказов — существующий `activeOrders()` (`sections/salesorders.js:239`), клиент вычитает уже добавленные.
- Существующие `/design-tasks*` не меняются (кроме п. 2 ниже — upsert `designorders` при создании задачи по позиции).

## Критерии приёмки (проверяет qa)
- [ ] Если добавить заказ из списка — он появляется слева с цветом и «ЗНП №»; повтор того же заказа не создаёт дубль; уже добавленные в списке не предлагаются.
- [ ] Если «Добавить и на распределение» — у заказа появляются задачи на все позиции в колонке «Распределение»; повтор не плодит новые.
- [ ] Если раскрыть заказ — позиции видны прямо в колонке; если перетащить позицию без задачи в «В работе» — спрашивается исполнитель, затем создаётся задача; отмена окна — ничего не создано.

- [ ] Если убрать заказ с открытыми задачами — отказ с понятным текстом; без открытых — исчезает, задачи остаются в таблице.
- [ ] Клик по заказу / карточке — справа панель: «главное» открыто, «справочное» свёрнуто; цен нет нигде.

## Нужен совет opus: переиспользовать ли drag-движок `ui/board.js`

Моя рекомендация по умолчанию: **(Б)** сейчас, (А) отдельной задачей позже.
