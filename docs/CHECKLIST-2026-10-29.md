# Чек-лист «Паспорта, отгрузки, история заказа» (пожелания 2026-10-28) — готов к запуску

ТЗ: `docs/roles/tz/PASSPORT-PRINT-BW.md`, `docs/roles/tz/SHIPMENTS-PASSPORTS.md`. Вопросы ОП-1…ОП-5 — `docs/QUESTIONS.md` (идём по ответам «по умолчанию», пока пользователь не скажет иначе).
Порядок: 1 → 2 → 3 → 4 → 5. Каждый экран — designer после; данные прода — план, затем apply.

## 1. Паспорт — строгий ч/б (S/M, backend: product-passport PDF)
- [ ] Ч/б режим — единственный (без переключателя `bw`).
- [ ] Обложка: шапка и нижняя полоса без заливки → линия (`passport-pdf-v2-cover.ts:59,95`), плитки 10 % → рамка (`:19`).
- [ ] Шапки таблиц без 12 % заливки → полужирный + линия (`passport-pdf-v2-layout.ts:116`).
- [ ] Стенд A3: шапка, плитки, плашка «Не более N человек», полоса → линии (`passport-pdf-v2-stand.ts:45,71,80,113`).
- [ ] Водяной знак убрать (`passport-pdf-v2.ts:44`).
- [ ] Серый текст `#444/#333/#666` → `#000`; красный «!» → контурный (`passport-pdf-v2-common.ts:41`).
- [ ] Критерий: заливка < 5 % площади листа, кроме фото изделия. Проверка — PDF обложки, таблицы ТО, стенда.

## 2. Очередь паспортов (M, backend + pwa «Документация»)
- [ ] `GET /passports/queue`: позиция с изделием + задача проектирования `done` + нет выпущенного паспорта; типовое изделие без задачи — если есть фото/модель (ОП-1). Сортировка по сроку отгрузки, «горит» ≤ 3 дней.
- [ ] Паспорт ↔ позиция: необязательное поле `incomeId` в паспорте; старые — правило «тот же заказ + то же изделие» (осторожно с двумя одинаковыми изделиями в заказе).
- [ ] «Документация» → вкладка «Нужно сделать паспорт» (первая), кнопка «Выпустить» в строке.
- [ ] «Сегодня» → карточка «Паспорта к сроку · N»; заказ → бейдж у позиции «нужен паспорт».

## 3. Отгрузки (XL, сначала architect по рискам)
- [ ] architect: этап `partly` («Частично отгружен», ОП-2) — фильтры active/done, «Сегодня», sheets-sync не перетирает этап; старые заказы `shipped` без записей отгрузки.
- [ ] Своя коллекция `shipments` {orderId, date, number, lines[{incomeId, qty}], who, reason, note}; остаток = qty − Σ отгружено; больше остатка — 400; позиции без qty — подсказка заполнить.
- [ ] Этап заказа сам: первая отгрузка → `partly`, остаток 0 → `shipped`. Со склада не списываем (ОП-3).
- [ ] Заказ → «Отгрузить» (правая панель): позиции, количество по умолчанию = остаток, причина при частичной (ОП-5).
- [ ] Печатная форма — внутренняя накладная ч/б (ОП-4): наша компания, заказчик, № и дата, таблица позиций с кол-вом и остатком, подписи «Отпустил / Получил».
- [ ] Список отгрузок в заказе и в «Документации».

## 4. История заказа (M)
- [ ] `GET /salesorders/:id/history`: одна лента — изменения (audit), задачи проектирования, паспорта, отгрузки, оплаты, выдачи со склада; суммы — только денежным ролям.
- [ ] Карточка заказа → вкладка «История»: поиск, фильтр по типу, кто/когда/что/почему.
