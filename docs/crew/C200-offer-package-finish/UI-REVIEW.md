# C200 — пакет КП из корзины

22.11.2026. Chrome, 1440 px, вложенная правая панель шириной 576 px. Светлая и тёмная темы. Штатные клики «В КП» и «КП (1)» на изолированной браузерной модели. Выбрать три фирмы с наценками 0 %, 3 % и 5 % можно из заполненной корзины через «Собрать пакет КП».

Проверено сохранение ручных цены, количества, единицы, цвета, размера, заказчика и общих условий. Автоусловия одной фирмы убираются при переходе в режим пакета. НДС и бланки каждой фирмы вычисляются на сервере. При отказе введённые поля остаются, после подтверждённого успеха открывается первое КП. Дизайнер принял проверенные состояния. [Светлая тема](proof/light.png) · [тёмная](proof/dark.png) · [отказ](proof/refusal.png).

В локальной копии у всех трёх фирм есть бланки. На тестовой MongoDB 4.4 проверена выдача трёх черновиков и отдельных многостраничных PDF, включая бланк без отметки «По умолчанию» и белое продолжение вместо чужой страницы. 11 HTTP и 85 модульных проверок, TypeScript и ESLint модуля прошли. Результат последующего браузерного прогона приведён ниже.

## Приёмка корзины, архива и печати

22.11.2026. Отдельный MongoDB 4.4 rs0, приложение с обычным REST API и строгой валидацией. Chrome на компьютере, размер окна 1440 × 940. В таблице «Продукция» добавили кнопкой «В КП» шестнадцать изделий с фотографиями. В корзине ввели заказчика, изменили количество первой позиции на 2 и цену на 1 450 ₽. Выбрали три фирмы с индивидуальными наценками и нажали «Создать 3 КП». Открылась карточка первого предложения. До исправления карточка оставалась в корзине после успешного создания. В итоговом прогоне переход сработал без повторного нажатия.

«Скачать ZIP (3 PDF)» выдало ZIP с тремя файлами. Проверены CRC архива и кириллические имена. В каждом документе все 16 артикулов встречаются по одному разу, заголовок таблицы повторяется на следующем листе, итог стоит после последней позиции. Проверены цены всех 48 строк. Встроенные JPEG бланков побайтово совпали с соответствующими эталонами. Из блока «Пакет» открыли соседние документы и для каждого нажали «Печать» в редакторе. Шесть страниц виртуального принтера Chrome пиксельно совпали с соответствующими страницами ZIP при 110 dpi. ### Закрытая проверка действующих бланков

Тот же путь отдельно прошли с тремя действующими JPEG первых страниц, на вымышленных товарах и заказчике. Перенесены настройки верхней и нижней границы текста каждой фирмы. Во всех трёх случаях собственный бланк продолжения отсутствовал. Получились документы в 3, 2 и 2 страницы. Каждый первый лист содержал точную копию соответствующего подготовленного бланка. Все продолжения были белыми. Все семь страниц из ZIP совпали с виртуальной печатью. При проверке областей печатных символов на первых страницах тёмных элементов исходного рисунка под текстом не обнаружено. Фактические реквизиты и изображения в доказательствах репозитория не публикуются.

[Браузерный сценарий](browser-check.mjs) проверяет состав и цены, переходы между карточками, скачивание и три задания печати. [Сверка PDF](pdf-check.py) проверяет наполнение ZIP, текст, фирменные фоны и растры страниц.
