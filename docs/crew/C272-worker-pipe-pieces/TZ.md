# C272 — трубы в штуках, порядок и цвета металла

Явное новое решение владельца26.11, **переопределяет прежний ввод в исходной unit C242/C269**: рабочий ввод/основное число в native pipe — количество физических труб в штуках. Приложение переводит его в метры по длине конкретного столбца, а метры показывает небольшой подстрокой числа. Пример:2шт×6м=12м;2шт×12м=24м. Данные/API продолжают использовать прежнюю исходную unit, массового пересчёта БД нет. SHEET не переводить автоматически в площадь: у него свой принцип, дальнейшая C271 подстрока общая.

## Ввод и перевод

- Для raw unit `м` и достоверной конечной положительной длины в мм: число труб→число×длина/1000 в API. expected — исходный raw quantity в метрах, замороженный на начало ввода. Отображение raw метров→штук только если делится на длину целиком с разумной float-погрешностью; не округлять и не придумывать число труб.
- Если существующий метраж не кратен длине, сохранить и показать его; поле штуки не заполнять выдуманной дробью/округлением. Пустое поле с понятным placeholder «шт» позволяет ввести реальный пересчёт. Подтверждение явно: «Было7м → 2шт×6м =12м». До подтверждения запроса нет.
- Для raw unit `шт` количество вводится напрямую, без второго умножения при записи. Метры можно вычислить для подписи, если длина достоверна. Unsupported/неизвестная unit или неизвестная длина для метров — fail-closed: не отправлять неправильный count. Сохранить single/countMode и readonly. Ввод физических труб — неотрицательное целое; все проверки конечности/пустоты/ошибок/отмены сохранены.
- Эта же модель применяется к короткому добавлению: человек задаёт число труб, в create DTO quantity не появляется, отдельный count — в исходной unit. Подтверждение единиц видно. Частичный сбой не повторяет create. Реальные БД при UI-тестах не менять.
- Перенос остатка между мытой/немытой: только целые трубы из достоверного доступного прироста, source/target каждый в собственной unit. При7м→12м для6м труб прирост5м не даёт одну целую трубу. Не переносить дробную трубу, не переинтерпретировать старые остатки, не обходить server expected/reservation guards. Кнопки/отмена/фокус/UUID и обе подтверждаемые стороны сохраняются.

## Очистка и группировка

Убрать зачёркнутые на снимке видимые названия/артикулы вида «Труба профильная… СКЛ… PRO…» из основных ячеек pipe. Внутренние materialId, tooltip/доступные названия и уникальные действия сохраняются; разные материалы не суммируются/не сливаются. Ошибку неизвестного/расходящегося сечения не скрывать под достоверным числом. Остальные статусы и примечания остаются в подстроке по C269/C270.

Новое уточнение владельца: сначала **все таблицы обычной стали**, затем **все таблицы нержавейки**; не чередовать по сечению/мойке. Обе группы различаются спокойным цветом шапки/акцента и явной подписью металла; не использовать красный (он для нулей). Внутри групп сохраняется числовой порядок размеров/длин. Для pipe и sheet. Использовать существующую каноническую классификацию материала/марок; не определять материал произвольной догадкой по похожему названию. Если явного типа нет, описать детерминированное правило/неизвестное в отчёте, не перезаписывая данные. Цвета по существующим токенам, обе темы и контраст по datacore-design.
