# C074 — очередь заданий для Cursor (паспорта и КП)

**Дата:** 2026-11-11 · **Заказчик:** координатор по слову владельца. Лимит координатора на исходе: Cursor идёт по этому списку сам, сверху вниз, без вопросов владельцу.

Приоритет владельца: **1) паспорта, 2) КП**. Упор — быстрое заполнение, максимум само (из изделия, группы, категории, заказа), руками только недостающее, по шагам, без лишних надписей и блоков. ИИ не подключать.

## Как работать (читать один раз)

1. Перед началом: `git pull`, `AGENTS.md` (жёсткие правила), `docs/PATTERNS.md` П-1, `docs/CANON.md` (правая панель, язык менеджера), `docs/DESIGN.md` §0–6 по заголовкам.
2. Одно задание — одна папка `docs/crew/<код>/` с `REPORT.md` (до 30 строк: сделано, коммиты, числа тестов, допущения, не сделано).
3. После задания: поставить `[x]` в этом файле и одну строку результата; строку в `docs/crew/BOARD.md`; сделанный пункт `docs/TASKS.md` — в `docs/archive/TASKS-DONE-2026-11.md`.
4. На прод не ходить. Не выкладывать. Данные прода не менять. Проверять на локальном стенде (`:3001`); вход на стенд — можно создать себе тестового пользователя (разрешение владельца 2026-11-11, только локальный стенд).
5. Контракт API не ломать: новые поля и параметры необязательные. Новый DTO — сначала собрать поля, которые экран шлёт сейчас (`forbidNonWhitelisted`). Mongo 4.4, без транзакций.
6. Экран: только компоненты `backend/pwa/ui/kit/`, без новых цветов и классов; ввод — в правой панели (окно — только 1–3 поля); только русский, без служебных кодов; одна главная кнопка на шаг. Синтаксис — `node --input-type=module --check < файл`.
7. Коммит только своих путей (`git commit -- <файлы>`); правку `ui/kit` и `sections` в один коммит не класть. Метки перед эстафетой: `Класс: …`, для экранов `Дизайнер: не принято` (приёмку делает координатор), `Проверка: …`. После каждого задания — `tools\dc.cmd check` зелёный.
8. Меняется маршрут — перегенерировать `docs/openapi.json`, строка в `docs/MAP.md`. Меняется путь менеджера — `backend/pwa/sections/help-guide-data.js`.
9. Неясно — допущение и строка в отчёте. Задание упёрлось в решение владельца — записать вопрос в `docs/QUESTIONS.md` (раздел 1), пометить `[~]`, идти к следующему.
10. Пуш — после каждого задания (владелец разрешил пуш принятого; выкладку — нет).
