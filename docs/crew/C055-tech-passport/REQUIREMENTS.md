# C055 — Техописание изделия ↔ паспорт (целостный комплект)

Автор: координатор, 2026-11-09. Код не менял. Источники: `PASSPORTS-V2.md` §1, `tech-sheet.js`, `passport-v2-text.ts`, `passportElements`, C054 части/материалы.

## 1. Что хочет пользователь

1. **Техописание** — отдельный документ/раздел продукции: из чего состоит изделие (части, материалы, размеры, допуски). **Сохраняется в изделии.**
2. **Паспорт** — как сейчас (ГОСТ, монтаж, обслуживание, гарантия…).
3. **Целостность:** одни и те же «из чего / материал / размер» кормят и ТО, и паспорт; не два разных мира.
4. **Печать:** «только паспорт» · «только техописание» · «паспорт + техописание» (один PDF).
5. **В договоре** — свой снимок состава+паспорта (номер, архив); правка договора не меняет продукцию.
6. **Описание функциональных элементов** в паспорте — по категории и изделию.
7. Порядок ввода: **часть → материал → размер**.
8. **Меню интуитивно:** в продукции техописание отдельно, паспорт отдельно; не смешивать с очередью «Документация / Шаблоны / Выпущенные».

## 1а. Карта входов (представление)

| Куда зашёл | Зачем | Что меняет |
|--|--|--|
| Продукция → изделие → вкладка **Техописание** | Состав модели (части, материалы, размеры) | `materialsSpec` изделия |
| Продукция → изделие → вкладка **Паспорт** | Шаблон паспорта модели + список выпущенных | `passportDefaults`; выпуск — новый документ |
| Продукция → кнопки «Печать…» | Скачать PDF без блуждания по меню | ничего / или выпуск по сценарию |
| Раздел **Паспорта** (#docs) | Очередь по заказам, выпущенные, печать пачкой | экземпляры паспортов, **не** шаблон изделия |
| Договор / заказ → паспорт позиции | Паспорт+состав **этого** заказа | снимок у позиции/паспорта |

Запрет путаницы: кнопка «Паспорт» на изделии **не** открывает вкладку «Шаблоны» раздела Документация без пояснения.

## 3. Дыры (чего не хватает в данных/экране)

1. **Единый «состав для документов»** на изделии: сейчас ТО правится в окне и пропадает; паспорт берёт снимок `materialsSpec` / elements отдельно.
2. **Связь часть → допустимые материалы** (чтобы после выбора «сиденье» предлагалась не любая труба).
3. ~~**Порядок колонок**~~ — сделано Э0: Часть → Материал → Размеры.
4. **Описание по элементам в паспорте:** поля в справочнике есть (`inDescription`, `usageRules`), но воронка/экран слабо ведут к заполнению «перечень функциональных элементов + правила по ним» как в PASSPORTS-V2 §1.1 п.3–5.
5. **Печать «паспорт+ТО»** одним файлом — нет; две разные кнопки/API.
6. **Тексты описаний по категориям** для элементов: не везде заполнены/привязаны; пустые categories у части справочников уже чиним (C054).
7. Риск имени: в паспорте «ТО» = техобслуживание, не техописание → в UI говорить **«Техническое описание»**, не «ТО».

## 4. Целевая модель (по умолчанию, пока нет ответа)

| Решение | По умолчанию |
|--|--|
| Источник правды состава | `products.materialsSpec` (+ `passportDefaults.elements` / joints) — одно место |
| ТО | Не отдельная коллекция; PDF из того же состава + допуски; окно правит `materialsSpec` изделия |
| Печать | Три режима: `passport` · `tech` · `passport+tech` (один PDF) |
| Колонки таблицы | часть → материал (сужение по части, когда будет связь) → размер |
| Описание элементов | Справочник `passportElements` + выбор на изделии/паспорте; в PDF раздел «Описание» = перечень + inDescription/usageRules |
| Состав CRM | Не смешивать с ТО (себестоимость остаётся отдельно) |

## 6. Критерий приёмки (черновик)

1. В карточке изделия: таблица состава для документов с порядком часть→материал→размер.
2. «Техническое описание» PDF совпадает по частям/материалам с тем, что уйдёт в паспорт.
3. Печать: три варианта без ручного копирования текста.
4. В паспорте TRN виден перечень функциональных элементов с текстами из справочника категории.
5. Калитка не предлагается для тренажёра (уже C054 на стенде).
