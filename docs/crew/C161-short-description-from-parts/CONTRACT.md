# C161 — добавочный контракт описания

Действующие GET/PATCH `/showcase/:id/passport-template?variant=short` сохранены. `changes` и `expected` должны содержать одинаковый наборключей. Дляавто:

```json
{"changes":{"simpleDescription":{"mode":"parts","partIds":["<ObjectId>"]}},"expected":{"simpleDescription":null}}
```

Собственное хранимое `defaults.simpleDescription` возвращает mode+ids без вычисленного text. Для последующего CAS передаётся оно целиком. Прежнее `{text,partIds}` остаётся ручным; допустим mode:'manual'. `null` снимает собственное значение и возвращает применимый словарный текст C155. Пустая ручная строка/пустая авто-выборка/неживые ссылки/неизвестный режим/ключи дают адресный400; устаревшее expected даёт409 без записи.

Дляauto проекция содержит `simpleDescriptionSource:{kind:'parts',partIds,text,invalidPartIds?}` и готовый `textSnapshot.description`. Неоднозначные окончания не угадываются: либо полный родительныйединственного, либо весь переченьname. При удалении выбранной части весь перечень не готов, нужен ремонтссылки. UI показываетпредпросмотр и явные действия для ручного изменения/возвратаauto, не сохраняет при отмене.

Выданный/аннулированный v1/parts использует собственные замороженные textSnapshot/printSnapshot. Явный POST `/passports/:id/snapshot` в этих состояниях возвращает409, не читает новый справочник и не меняет номер/редакцию/историю. Пересмотр — штатная новая редакция, не тихая пересборка. Full/legacy и прежний ручной формат сохраняют поведение.
