# ТЗ C058 — Два сервера: довести до рабочего состояния (синхронизация + переключение)

**Исполнитель:** Cursor (координатор этой задачи). **Класс:** XL — живые серверы и данные прода. **Агентов:** ≤ 3 роли по очереди (architect → backend/deploy → qa), без параллельных читателей одних файлов.

**Зачем (словами пользователя, 2026-11-10):** «Автосинхронизация, переключение серверов до сих пор не работает. Неделю прошу доделать. Всё, что связано с двумя серверами — рабочий и домашний — пусть починит полностью».
**Зачем — глаголом:** пользователь в админке на экране «Серверы» видит, что запасной сервер (Sportin) свежий (копия не старше 15 мин), и одной кнопкой переключает рабочий сайт на запасной и обратно за ≤ 5 минут, без потери данных и без повторного входа.

## Глубже
- **Результат:** цель `docs/CONTROL.md` «сайт переживает поломку дома». Слово «работает» — только после учебного переключения туда и обратно (A7) с записью в `docs/TEST-LOG.md`.
- **Сырьё:** живое состояние обоих серверов (шаг 0), а не пересказ доков. Сначала факт, потом правка.
- **Метод профи:** runbook переключения: замер до/после (время, число записей в 5+ коллекциях, фото, вход), откат на каждом шаге, один шаг — одна проверка.
- **Внешний судья:** экран «Серверы» в админке (enabled, версия, возраст копии), `GET /api/control/switch/status` на обоих, `doctor.sh`, сверка счётчиков коллекций до/после.

## Шаги
0. **Диагностика, только чтение (без «да»).** Дом: `bash deploy/synology/api.sh prod GET /api/control/switch/status`, `/api/health`; Sportin: то же через его адрес (как в `SRV-ERP/refresh-copy.sh`). Запиши в `DIAG.md`: enabled на обоих, версии (v и b), возраст последней копии на запасном, жив ли мост, когда последний `refresh` и чем кончился, есть ли туннель/задача на VPS. Найди **точную причину**, почему «автосинхронизация не работает» (нет заявки refresh? мост не запущен? ключ/ssh? выключено `HA_SELF`?). Каждую причину — с доказательством (вывод команды).
1. **План по факту** — `PLAN.md` этой папки: какие из A1/A4/A7, C045-6/8 и найденных в шаге 0 причин чинить, порядок, откат на каждом шаге. Сложная развилка (данные, каскады) — сначала совет одного агента opus (CLAUDE.md п. 4а).
2. **Правки кода** (если шаг 0 нашёл баг): `backend/src/modules/control/switch/*`, `deploy/ha/switch/*`, `SRV-ERP/*`. Юнит-тесты к каждому багу. `tools/dc.cmd check` зелёный. Код Sportin не форкать — отличия только `.env` (AGENTS п. 10).
3. **Выкладка** дома — кнопкой/`release.sh` (skill `datacore-deploy`); запасной обновить с кодом (`refresh-copy.sh --code`), версии v и b совпали.
4. **Включение (A1) и закрытие :8080 (A4)** — только после «да» пользователя в чате на каждую запись на сервер.
5. **Автосинхронизация:** доказать, что запасной сам обновляется (заявка refresh каждые 15 мин на главном) — два подряд обновления с отметкой времени на экране «Серверы». Тревога, если копия старше 30 мин (C045-6): строка в `dc data`/обзор.
6. **Учебное переключение (A7)** — ночью, пользователь рядом, по чек-листу C045 REPORT: Дом → Sportin → Дом. Замер времени каждого направления, сверка счётчиков (C045-8: набор «наших» коллекций из реестра), фото открываются, вход без перелогина. Итог — строка в `docs/TEST-LOG.md`.
7. **Доки:** `docs/audit/SERVERS-STATUS.md` — переписать «как есть» после работы; `docs/CONTROL.md` — цель и проверка; `docs/BACKLOG.md` п. 0а и `docs/TASKS.md` «ПЕРЕКЛЮЧАТЕЛЬ…» — отметить; кнопки, которые нужны человеку (переключить/вернуть), — в пульт (`pult/catalog.mjs`, без `extra`) или админку.
