## Вопрос → чем отвечаем

| Вопрос | Инструмент | Где запускать |
|--|--|--|
| Прод сейчас здоров? | `bash deploy/synology/doctor.sh` — итог ✓ / ⚠ / ✗ | агент `datacore-access`, только чтение |
| Код не сломан? | `npx tsc --noEmit`, `npx jest --silent` | из `backend/` |
| Главные цепочки работают? | `npx jest --config ./test/jest-e2e.json --runInBand --forceExit` | нужен Mongo |
| Экраны открываются? | `QA_DIR=… node backend/scripts/qa-smoke.mjs [ширина]` | стенд `:3002`, skill `datacore-verify` §3а–3б |
| Выкладка безопасна? | `release.sh`: ворота, бэкап, откат при красной проверке | `bash remote-access/deploy.sh` с работы |
| Копия восстановится? | `bash deploy/synology/restore-drill.sh` | на VM, раз в месяц, запускает пользователь |
| Карта кода не отстала? | `node backend/scripts/check-map.mjs` | сам идёт в preflight |

## Цепочки и их тесты

| Цепочка | Тест | Что доказано |
|--|--|--|
| Заказ → проектирование → работа → отгрузка | `chain-order-to-ship` | этапы, остатки, очередь паспортов |
| Заявка → счёт → оплата → приход | `chain-supply-to-stock` | остаток, цена, движение; двойное «Принять» не удваивает |
| Склад при одновременной работе | `chain-stock-race`, `stock-scope` | остаток не уходит в минус, бронь не больше остатка |
| Оплата позиции | `chain-payment-form` | форма не стирает платежи, повтор не задваивает |
| Удаление и корзина | `trash-lists` | 10 списков; возврат заказа с позициями |
| Паспорт | `passports` | номер, выпуск, аннулирование, редакции |
| Деньги | `finance` | частичные оплаты, календарь, ФОТ |
| Вход и роли | `auth`, `custom-roles`, `app-sections` | закрытые разделы выборочно |

## Ритм

- **Каждая правка:** проверка по размеру (skill `datacore-verify` §0).
- **Перед выкладкой L/XL:** полный прогон и обход экранов; строка в `docs/TEST-LOG.md`.
- **После выкладки:** `doctor.sh`; через 1–2 ч — `post-check.sh`.
- **Раз в неделю:** `doctor.sh`, разбор каждого ⚠.
- **Раз в месяц:** `restore-drill.sh`, число в `drill.log`.

## Если случилось

| Что | Первый шаг |
|--|--|
| Выкладка прошла, сайт ведёт себя плохо | На VM: `cd /opt/data-core && bash deploy/synology/rollback.sh`. Данные откат не трогает |
| Сайт не отвечает | `bash remote-access/check.sh`: связь, контейнеры, диск. Логи: `docker logs --tail 50 datacore-backend` |
| Диск полон | `docker builder prune -f --max-used-space 10GB`, затем старые копии в `/var/lib/datacore/backups` |
| Испортили данные | Остановить работу людей. Не восстанавливать поверх: развернуть копию во временную базу (как `restore-drill.sh`) и сверить. Решает пользователь |
| Сервер погиб | `deploy/synology/README.md` «Восстановить из копии вне дома». Без настроенных копий вне сервера этот путь не работает |

## Что не проверяется автоматически

- Обход экранов только открывает и читает: кнопки записи на экранах нажимает человек.
- Содержимое PDF: тест видит, что файл отдан, но не что внутри.
- Роли проверены выборочно: матрицы «роль × экран» нет.
- Модули `design`, `work`, `passport`, `dicts` архитектор смотрел поиском, не построчно.
- Стенд `:3002` содержит мало данных: на копии прода обход надёжнее (skill `datacore-verify` §3а).
