## 1. Паспорт на заказ — фирма от заказа

| Что проверено | Есть / нет | Где |
|--|--|--|
| Заказ хранит нашу фирму; в форме заказа поле «Наша компания» обязательное | есть | `salesorders.js:676`, `salesorders.service.ts:341-347`, `dto.ts:9` |
| Фирма паспорта: явная, иначе фирма заказа (наша), иначе единственная наша; несколько наших и не из чего взять — 400 | есть | `passport-queue.ts:122-130,167-169`, `passport-bind.ts:15-26` |
| Воронка предвыбирает фирму заказа, можно сменить | есть | `funnel/issue.js:97-98` |
| «Паспорта заказа»: нет фирмы у заказа и наших фирм больше одной → строка «Выберите фирму» | есть, но тупик | `passport-order.ts:80-86` |
| На экране плана фирмы не видно, выбрать её негде; рядом только ссылка «Шаблон паспорта» | нет | `order-passport-plan.js:66-76` |
| Вкладка «Паспорта» в заказе подсвечена на этапе «Отгружено» | есть | `order-stage.js:29`, `salesorders.js:319` |
| Подсказка следующего шага при «Отгружено»: текст про паспорта, кнопка только «Завершить заказ» | частично | `salesorders-next.js:38`; счётчика паспортов в `orderCounts` нет (`:6-16`) |

**Что увидит менеджер.** Заказ создан с фирмой → открыл «Паспорта заказа» → всё готово, фирма подставилась тихо (на экране её не видно). У старого заказа без фирмы и при двух наших фирмах: все позиции «Не хватает данных: Выберите фирму», сделать с этим нечего. После отгрузки карточка доски зовёт «Завершить заказ», а не «Паспорта» — путь к паспортам есть только через вкладку.
**Задача П10 (класс M, frontend; backend — мелко).** Цель: «закончили заказ → паспорта» в два нажатия, фирма видна и выбирается.
1. Карточка доски, этап «Отгружено», паспортов нет: главная кнопка «Паспорта заказа», «Завершить» — второй. Нужен счётчик паспортов в строке заказа.
2. В панели «Паспорта заказа» — строка «Фирма: СИЮ» (из заказа). У заказа без фирмы — один выбор «Какая фирма оформляет заказ?» на весь заказ; выбор записывается в заказ (`companyId`) и идёт всем позициям (П-1: спрашиваем один раз, остальное подставляем, запоминаем).
3. Выпущенный паспорт другой фирмой не перепечатывать (ПР-7).
Места: `order-passport-plan.js:28-91`, `salesorders-next.js:38`, `orderCounts`, `passport-order.ts:41-95` (вернуть `firm`, `firmChoices`), `salesorders.service.ts:341`. **Слить с П7** — там уже стоит «выбор фирмы».

## 2. Свой вид паспорта у каждой фирмы

| Элемент PDF | Откуда берётся сегодня | Настройка без кода | Где |
|--|--|--|--|
| Логотип на обложке (нет — название текстом) | карточка фирмы, слот «логотип» | да | `passport-pdf-v2-cover.ts:58-61`, `partners.js:44-83` |
| Название, ИНН/КПП, телефон, почта, торговая марка | карточка фирмы | да | `passport-pdf-v2-cover.ts:63-67`, `passport-pdf.ts:11-14` |
| Колонтитул «Фирма · Паспорт № …» | название фирмы | только текст названия | `passport-pdf-v2.ts:53` |
| Талон: должность и ФИО продавца, печать, подпись | карточка фирмы | да | `passport-pdf.ts:88-104`, слоты `seal`, `signature` |
| Лист для стенда: название, телефон, почта, логотип | карточка фирмы | да | `passport-pdf-v2-stand.ts:107-110` |
| Цвет, рамка, фон обложки, пиктограммы правил | справочник «Оформление» (`passportStyle`): привязка к категории, не к фирме | частично | `dicts.defs.ts:901-913` |
| Макет страниц, шрифт, поля, обложка, чёрно-белая шапка | зашито в коде | нет | `passport-pdf-v2-cover.ts:51-94` |
| Фоновый бланк картинкой | у паспорта нет; у КП есть, привязан к фирме (`companyId`) | нет | `offer-backgrounds.service.ts`, `offer.schema.ts:98` |

Важно: виды «фон обложки» и «рамка» в справочнике можно завести, но печать их не читает — работают только «цвет категории» и «пиктограмма правил» (`passport-pdf-v2-refs.ts:7-26`). Цвет в обложке не используется (шапка чёрно-белая, `cover.ts:55`). Фирмы без логотипа и печати печатаются молча; предупреждение есть только в карточке паспорта (`passports.js:151`).
**Что увидит менеджер.** У СИЮ и ССЮ паспорта отличаются только шапкой: логотип, реквизиты, марка, печать. Макет и цвета одинаковые. «Своего дизайна» нет.
**Задача П11 (класс L: серверная часть M + вид PDF; дизайнер смотрит PDF; идти после ответа ПФ-1 и образцов).** Цель: у каждой фирмы свой вид, настраивается без программиста. Что привязать к фирме:

| Поле оформления фирмы | Вариант по умолчанию (ПФ-1 а) | Если б / в |
|--|--|--|
| Цвет акцента (линии, плашка категории, рамка) | да | да |
| Логотип, печать, подпись, реквизиты, торговая марка | уже есть | уже есть |
| Вариант шапки обложки (логотип слева / по центру / полоса цвета) | 2–3 готовых варианта | то же |
| Колонтитул: своя строка (сайт, слоган) | да | да |
| Фон обложки (картинка A5) | нет | да, с зоной текста |
| Фон всех страниц (бланк, как у КП) | нет | в: да |
| Чёрно-белый / цветной вариант | цвет по галочке | то же |

Шаги экрана (П-1): карточка фирмы → блок «Вид паспорта» → выбрать вариант шапки → цвет → «Предпросмотр» (тестовый паспорт этой фирмы) → «Сохранить». Места: `passport-pdf.service.ts:214-264` (`orgOf`, `styleOf`), `passport-pdf-v2-cover.ts`, `passport-pdf-v2-refs.ts` (приоритет: фирма+категория > фирма > категория > общее), `dicts.defs.ts:901` (поле «Фирма» в «Оформлении» — самый короткий путь) или поля в `organizations`; `partners.js:81-83`. Архитектору решить: поле в `passportStyle` против поля в организации против образца с `offerbackgrounds`.

## 3. Нумерация и список по номерам

| Что хочет владелец | Есть / нет | Где |
|--|--|--|
| Колонка «№», сортировка по номеру (по убыванию по умолчанию) | есть, но основной вид — галерея по категориям, номер мелко | `passports.js:50,89-95,112`, `passport-consts.ts:5` |
| Поиск по номеру (также талон, номер изделия, заказчик, заказ) | есть, но шумный: «224» найдёт и заказ № 224 | `passport-queries.ts:45`, `passports.js:56` |
| Фильтр по фирме | есть (воронка слева) | `passports.js:74`, `passport-queries.ts:201,231` |
| Колонка «Фирма» в таблице | нет (в карточке есть) | `passports.js:110-120,151` |
| Фильтр «номера от — до» / «последние N» | нет | `filterOf`, `passport-queries.ts:189-217` |
| «Последний паспорт №» | есть, общий; не по фирме | `numbers-strip.js:15`, `passport-numbers.ts:27-31` |
| Метка «Файл» / «С сайта» в списке | нет (в карточке и вкладке изделия есть) | `passports.js:152` |

Счётчик: один общий на все фирмы, без годов — `counters{entity:'passport', prefix:'passportNumber', year:0}`; «последний» = max(счётчик, максимум по паспортам). Номер выдаётся при выпуске, в одной транзакции (`passport-issue.ts:40-58`, `passport-numbers.ts:18-46`). Год стоит только в талоне («202611-№», `passport-rules.ts:11`). Правка «следующего №» — директор, админ, владелец.
**Что увидит менеджер.** Открывает «Паспорта» → картинки по категориям; сверху «Последний паспорт № 343» (если открыть). Чтобы увидеть «по номерам», надо переключиться в таблицу, колонки «Фирма» нет, диапазона нет.
**Задача П12 (класс S–M, frontend + мелко backend).** Цель: «паспорта по номерам» одним взглядом.
1. Таблица по номерам запоминается как вид по умолчанию (переключатель «Плитки / По номерам»).
2. Колонки: №, Фирма, Дата, Название, Заказчик·заказ, Источник («Файл» / «С сайта»).
3. Над таблицей: «Последний № 343 · СИЮ 343 · ССЮ 340» (последний выпущенный у фирмы, дата) — полоска `numbers-strip.js`, запрос — агрегат по `supplierOrgId`.
4. Чипы «Последние 20»; поле «№ от … до …» (параметры `numFrom`, `numTo` в `filterOf`, поле `passportNo`).
5. Поле поиска: ввод «№224» или «224» сначала ищет номер.
Если ПФ-2 = «ряд у каждой фирмы»: класс L (счётчик с ключом по фирме, миграция 343 номеров, талон, замок уникальности `assertFree`, ПР-1…) — не начинать без ответа.

## 4. Готовый паспорт (файл)

Как сегодня, шаг за шагом:

| Шаг | Что делает менеджер | Что есть |
|--|--|--|
| 1 | «Паспорта» → «Новый паспорт» → воронка: категория, изделие, фирма, позиция | `funnel/issue.js` |
| 2 | Заполнить все обязательные поля до «Выпустить» (без них кнопка серая: «Не хватает для выпуска…») | `passport-issue.ts:36-37` → `readiness` (`passport-rules.ts:130-230`) |
| 3 | «Выпустить» — тут появляется номер | `passport-issue.ts:30-58` |
| 4 | В карточке блок «Файл для печати» → «Прикрепить PDF»; печать отдаёт файл | `card-blocks.js:123-153`, `product-passport.controller.ts:309-317`, `passport-pdf.service.ts:88-93` |

Что не получается: создать запись «готовый паспорт» без шагов 1–3 (категория и поля нужны только для сборки текста — для готового файла они лишние); номер у черновика не выдаётся, значит файл прикрепляется к записи без номера; на одну позицию заказа один живой паспорт (`passport-bind.ts:32-43`, 409); «Печать всех» по заказу и «PDF пакетом» файл не берут (`passport-pdf.service.ts:129-140,202-212`: собирают с сайта или пропускают); склеить файлы нельзя — библиотеки PDF-слияния в проекте нет (`package.json`: только pdfkit). Метка «Файл» есть в карточке, в списке нет.
**Что увидит менеджер.** Кнопки «Добавить готовый паспорт» нет. Чтобы получить номер для чужого файла, нужно выдумать категорию и заполнить 10–17 полей, потом прикрепить PDF.
**Задача П13 (класс M: backend + одна панель).** Кнопка «Добавить готовый паспорт» в шапке «Паспорта», на вкладке «Паспорт» изделия и в «Паспорта заказа». Шаги (П-1, четыре, ничего лишнего):
1. Файл: перетащить PDF (название берётся из имени файла).
2. Фирма: предвыбор из заказа или последней использованной, запоминается.
3. Изделие: поиск; можно пропустить («Без изделия»).
4. Заказ: «Без заказа» или заказ → позиция (заменить файл, если паспорт уже есть, ПФ-4).
Кнопка «Добавить и присвоить №» → номер выдаётся сразу и показывается крупно с «Скопировать». Категорию, размеры, материалы, картинки не спрашиваем.
Сервер: признак «готовый» (`source: 'file'`), выпуск без `readiness` при наличии файла, номер из общего счётчика (ПФ-3), та же транзакция; PDF из текста, стенд, пакет для такого паспорта — понятный отказ «У этого паспорта готовый файл»; в список — колонка «Файл». «Печать всех» — отдельно: готовые файлы класть рядом в архив, не склеивать (без новой зависимости). Места: `product-passport.service.ts:361`, `passport-issue.ts:30`, `passport-pdf.service.ts:79-140,202`, `card-blocks.js:123`, `passports.js:110`, `funnel/open.js`, `schema` (поле, CRM не читает).
