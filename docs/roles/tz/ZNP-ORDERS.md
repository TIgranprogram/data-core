# ТЗ: заказы на производство (ЗНП) — номер в заказе, новые заказы, задачи «Проектирования» по ЗНП (класс XL — схема + данные прода)

Источник правды — Excel «Заказ на производство №N-26.xlsx» в `для анализа/Заказы на производство/<N-26>/` (YouGile больше не используем — решение пользователя 2026-10-27).
Разбор уже сделан: `для анализа/znp-parsed.json` (шапка + строки), `znp-match.json` (ЗНП → наш заказ → позиция → задача YouGile), `znp-img.json` + `znp-img/` (картинки по строкам), план для пользователя — `для анализа/plan-znp.xlsx`.

## Решения пользователя (2026-10-27)
1. У заказа **два номера**: входящий (`orderNo`, как сейчас) и **№ на производство (ЗНП)** — новое поле.
2. Несколько наших заказов в одном ЗНП (3-26 → 12, 17, 18; 6-26 → 19, 20; 8-26 → 90-П, 109-П; 12-26 → 110-П, 111-П, 114-П, 115-П; 4-26 и 5-26 → 25) — у всех **один** № на производство. Задача «Проектирования» — одна на строку ЗНП.
3. **Нумерация ЗНП:** `N-ГГ`, N — сквозной с начала года, ГГ — год (2026 → «-26»). Следующий номер — max N за год + 1 (сейчас занято 1…20 → следующий 21-26).
4. ЗНП 15-26…20-26 — заказов у нас нет → **создать 6 заказов** из ЗНП (заказчик, отгрузка, ответственный, позиции, № на производство). Входящий номер неизвестен (у 16-26 — закупка 0318300017526000116).
5. Задачи создавать **только для позиций с артикулом**, у которых задачи нет (покупное без артикула — без задачи).
6. Заказ 14 — две разные компании; 2-26 → заказ 14 **ООО Академия Благоустройства**.
7. D-65 «Навес ДПС, ул. Тургенева» — **новый ЗНП 21-26** (по очереди).

## Порядок
1. Сервер: поле `salesorders.productionNo` (строка, индекс, поиск по нему в `TEXT`/`tokensFilter`), DTO create/update, ответ списка и карточки; `GET /api/salesorders/next-production-no?year=2026` → «21-26». Общая ли коллекция с CRM — `salesorders` своя (не `orders` kppdf). e2e + юнит; openapi.json, MAP.md.
2. Приложение: поле «№ на производство» в карточке/форме заказа (правая панель), колонка/поиск в списке, кнопка «Следующий» рядом с полем. skill `datacore-design`.
3. Выкладка (`remote-access/deploy.sh`), бэкап.
4. Скрипт данных `backend/scripts/znp-apply.js` (план → `--apply --out`): заполнить `productionNo` у 14 заказов; создать 6 заказов 15-26…20-26 с позициями; задачи — название/примечание по колонкам ЗНП (Арт., кол-во, габариты, крепление, **ударопоглощающее покрытие**, цвет RAL, доп. информация), превью — картинка строки из ЗНП (сжать ≤1600 px JPEG); привязка к позиции заказа = пересоздать задачу (incomeId менять нельзя): перенести статус, исполнителя, срок, приоритет, фото, примечание; старую — мягко удалить; новые задачи для позиций с артикулом без задачи; D-65 → ЗНП 21-26.
5. Проверка: `/api/design-board` по колонкам, 3–5 задач и 2 заказа глазами.

Колонки строки ЗНП: № п/п · Артикул · Внешний вид (картинка) · Наименование · Кол-во · Ед. изм. · Габаритные размеры (ДхШхВ) · Тип крепления к основанию · Ударопоглощающее покрытие · Цветовое решение (RAL) · Доп. информация.
Вход на прод: лимит 5/мин и **20/час** (2026-10-27 упёрлись) — скрипты входят один раз и перевходят только на 401.
