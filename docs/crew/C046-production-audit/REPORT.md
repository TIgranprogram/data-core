# C046 — журнал наблюдений по разделу «Производство»

Читал код и доки, ничего не правил; серверы/скрипты не запускал. Путь пользователя пройден по коду: заказ → позиции → проектирование → состав → запуск → распределение → факт/нормы/срок/себестоимость → отгрузка.

## 1. Карта раздела (экраны → назначение → связи)
| Экран (id) | Что это | Связи |
|--|--|--|
| Заказы `salesorders.js` | Шапка заказа (salesorders) + позиции (incomes), стадии «В производство → Готово → Отгрузить», блок «В работе» (order-work.js) | создаёт incomes; запускает работу; ведёт к «Составу» |
| Заказы-доходы `orders.js` | Строки заказов = доходы (`/incomes`), деньги | читает те же incomes, но со стороны денег |
| Проектирование `design.js` | Доска задач чертёжки (designtasks), исполнитель — из «Сотрудников» | из заказов; с планом/Гантом НЕ связана |
| Сопоставление `matching-queue.js` | Позиция без изделия → подобрать изделие (правая панель `?of=matching`) | до проектирования |
| В работе `work.js` | Доска заданий (worktasks) по видам работ; вид «Гант» = `ui/gantt.js` | из «Запустить в работу»; карточка = исполнитель/примечание/отмена |
| Состав позиции `work-composition.js` | `workPlan` (план позиции: части×работы, проверено, факт, срок, себестоимость) + `productRoute` (маршрут изделия) | читает/пишет `orderlineplans`, `work-routes` |
| Запуск `work-launch.js` | Панель «Запуск в работу»: итог плана, предупреждения | из блока «В работе» заказа |
| Гант `work-schedule.js` | Планировщик по шагам планов позиций (`/work-schedule`), `ui/kit/planner.js`; панель шага `wsstep` | правит `orderlineplans.steps[]` |
| Факт/нормы/себестоимость `work-facts.js` | Блоки в карточке изделия и панели позиции | читает `/work-facts/*` |

## 5. Сотрудники и виды работ (дополнение пользователя)
- **Как сейчас:** связь есть — `persons.workTypeIds[]` (+ legacy `workTypeId`), чтение `common/catalog/person-work-types.ts`, задаётся в «Справочники → Сотрудники» (dict `persons`, поле «Вид работ» = одиночный select; несколько видов — только через API `workTypeFields`). `/work-tasks/people?workTypeId=` уже фильтрует исполнителя в карточке задания (`work.service.ts:274-278`); на «Видах работ» (dict `worktypes`) видно число сотрудников (`usage`), но назначать там нельзя.
- **Чего не хватает:** (1) в «Ганте» (`/work-schedule`) — все сотрудники, без фильтра (п.2); (2) в UI «Сотрудники» нельзя задать несколько видов работ одной карточкой (multi-select), а это главный экран руководителя; (3) при переносе полосы на строку другого человека не проверяется, что у него есть этот вид работ.
- **Где задавать (рекомендация):** в **карточке сотрудника («Управление → Сотрудники»)** — мульти-выбор «Виды работ» (заменить одиночный select). Это то же место, где сотрудника ведут, и уже туда смотрит «В работе». «Виды работ» оставить только справочником-названием (туда добавить ставку ₽/ч, уже сделано в C041 Э3).
- **Где действовать:** строки Ганта «По людям» — только сотрудники с ≥1 видом работ; панель шага «Исполнитель» — только с видом работ шага (+ «Показать всех»); перенос полосы на строку другого человека — допустим, только если у него этот вид работ; запуск/распределение — то же правило.
