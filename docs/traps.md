# Редкие ловушки (вынесены из AGENTS.md 2026-10-25)

Частые — в `AGENTS.md` «Известные ловушки». Общие с CRM таблицы `kind:'crm'` — AGENTS «Жёсткие правила» №4.

- Мусорный ObjectId → `CastError` → глобальный фильтр отдаёт **400** (не 500).
- Mongoose `ValidationError` → тоже **400** с полем и `missing`; у ответа 500 есть `errorId` — тот же код в журнале: `docker logs datacore-backend | grep 'сбой КОД'` (журнал теряется при пересоздании контейнера выкладкой).
- Rate-limit: глобально 10/с и 100/мин, `/auth/login` — 5/мин и 20/час. Серия запросов без пауз → 429, это не баг.
- `GET /api/admin/users` через `kppd_`-ключ → `total:0`: owner-админ скрыт от не-owner актора (TZ-AUTH-306). Не баг.
- `AuditService.log` приводит `entityId` к ObjectId — не-hex строку туда не клади (пиши в `details`).
- **Никогда не запускай `bash -x` / `set -x` на скриптах, которые читают `.env`** — трассировка печатает секреты (инцидент 2026-10-18, T22).
- Windows/Git Bash: `docker exec` с путями `/tmp/...` ломается → `MSYS_NO_PATHCONV=1`.

- **api.sh входит заново при каждом вызове** (2026-10-27): цикл «по запросу на заказ» упирается в лимит входа 5/мин — 35 из 37 запросов отказали. Массовая выгрузка — один вызов на список (`limit=500`) или пауза ≥ 13 с между вызовами.

## Печать документов

- Метки и пустые значения в PDF — только через `backend/src/common/print` (`fill-text.ts`: `fillBlanks`, `printSafe`; `safe-doc.ts`: `guardDoc` на каждый `new PDFDocument`). В PDF не уходят `{…}`, `undefined`, `null`, `NaN`, `[object Object]`, `Invalid Date`: рукописное поле (число, ФИО, дата) → линия `____`, необязательная фраза без значения не печатается, остаток ловит предохранитель (предупреждение в лог `print`, без ошибки).
- Паспорт: списки линий и необязательных фраз — `product-passport/passport-blanks.ts`; новая метка в `passport-texts.v2.json` без записи в `LABEL_SOURCES` валит тест.
- Новый PDF-документ: `guardDoc(new PDFDocument(...), "название")` + тест в `common/print/print-documents.spec.ts`.

## Экран роли по её названию (2026-11-09)
- Экраны «Труборез» (трубы, котики) и «Лазер лист» (листы, собачки) включаются по **названию роли** (`roleLabel`), а не по коду: `isPipeRole`/`isSheetRole` в `pwa/main.js`, `isStockRole` в `pwa/sections/help.js`.
- **Что случилось:** в коде было точное сравнение с «Трубарез» (опечатка). На проде роль переименовали грамотно — «Труборез». Сравнение перестало совпадать: труборез видел обычные «Остатки» вместо своей таблицы, котики пропали. Ошибок в журнале нет — сайт «работал».
- **Почему допустили:** название роли может менять любой админ, а код держался за точное написание. Тест на это место не было.
- **Правило:** роль узнаём по шаблону, терпимому к написанию (`/^\s*труб[ао]рез/i`, `/^\s*лазер\s+лист/i`). Правильное слово — **Труборез**. Новый экран для роли — тот же подход; переименовали роль на проде — проверить, что её экран открывается (вход «Смотреть как» или меню «Экран «Труборез»» у админа).

## design-lint и концы строк (2026-11-06)
- Правило L3 (`design-lint.mjs`, `CLS … (.*)$`) **не видит классы в файлах с CRLF** (`\r` в конце строки). Baseline снят на CRLF-копии. Агент сохранил файл в LF → всплыли старые замечания файла, коммит отклонён. Лечение: вернуть файлу CRLF; правильный фикс — `split(/\r?\n/)` в линтере с пересъёмом baseline (отдельная задача).

- **Плавающий список в выезжающей панели (2026-11-09):** у `.drawer` есть `transform`, поэтому `position: fixed` списка отсчитывается от панели, а не от экрана. Кроме того, CSS-правило `top: 100%` у `.combo-list` при открытии вверх сжимало список до 2 px, и список выглядел пустым («Добавить заявку» в счёте). `placeList` (`pwa/ui/popup.js`) снимает `top` при открытии вверх и после расстановки мерит место списка и сдвигает его на разницу. Проверка — макет `pwa/fixtures/invoice-workspace.html?scenario=draft` на широком экране (launch `pwa-fixture`).

## Выкладка: быстрый путь после полного дал 404 у /app и /admin (2026-11-10)
- v1.675: полный путь (выложен v1.674, контейнер пересоздан) → через ~40 мин быстрый путь («только экраны», sync-dir на месте) → `/app/` и `/admin/` 404, откат `--screens-only` тоже 404, health 200.
- Починка: `bash remote-access/deploy.sh --full` — контейнер пересоздан, привязки папок заново, 7/7.
- Причина (разобрано 2026-11-10): полный путь делает `mv backend backend.replacing-TS` и кладёт новую папку; если образ не менялся, `compose up -d` контейнер НЕ пересоздаёт — привязка остаётся на старой папке, которую выкладка потом удаляет; быстрый путь кладёт экраны в новую папку, контейнер их не видит → 404.
- Исправлено в release.sh: полный путь — `up -d --force-recreate`; быстрый путь перед заменой сверяет inode /app/pwa и /app/admin в контейнере с backend/pwa, backend/admin на диске и при расхождении пересоздаёт контейнер.

## Выкладка: сервер не виден в домашней сети (2026-11-14)
- Симптом: `release.sh` → «ВЫПУСК: СТОП (код 255)», `ssh: connect to host 192.168.1.52 port 22: Connection timed out`; сайт при этом работает (health 200).
