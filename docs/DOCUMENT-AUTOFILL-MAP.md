# Карта автозаполнения документов для ИИ

Решение владельца19.11.2026: минимум выбора → максимум автоматически заполненных достоверных данных. Общие правила сохранения/редактирования критериев и истории — [PATTERNS.md, П-1](PATTERNS.md). Это карта источников, а не второй набор текстов. Тексты живут в действующих справочниках и источниках приложения.

## Как агент начинает задачу

1. Найти раздел через `dc atlas <раздел>` или JSON-сводку. Для паспорта — блоки `docs`, `products`, `dicts`. Они показывают входы, зависимости и файлы; не перечитывать весь репозиторий.
2. Установить контекст: тип документа, изделие/позиция/контрагент, шаблон или экземпляр, черновик или выданный снимок. Название изделия и последний найденный документ не заменяют точные ID и связи.
3. Получить разрешённую серверную проекцию/метаданные. Точный контракт — нужный путь в OpenAPI и схема модуля по MAP. Не воспроизводить наследование и выбор применимых текстов самостоятельно в клиенте или чате.
4. Сначала использовать сохранённые критерии и явный выбор, затем однозначные применимые связи справочников. Единственный подходящий вариант подставить. Если остаются несколько разных результатов, задать только вопрос, различающий их. Сходство названий/рисунка даёт предложение, а не подтверждённый факт.
5. Показать источник заполненного текста и место редактирования. Общий ответ сохранять у владельца данных, разовую формулировку отделять от общего умолчания. Конфликт с параллельной правкой не перезаписывать молча.
6. Проверить проекцию/образец до выпуска. Выпуск фиксирует снимок и номер по правилам документа. Изменение справочника не переписывает выданную историю.

## Действующая цепочка нового упрощённого паспорта C155

`изделие → категория/вид/подтверждённые признаки → применимые словарные ветки → текст/части/инструкции → шаблон → образец → явный выпуск`

Код и точные изменения: [MAP.md, C155](MAP.md), [контракт C155](crew/C155-passport-owner-queue/CONTRACT.md). Реализацию C155 сначала принимают на копии; наличие этой карты не означает, что новый сервер уже выпущен на рабочий сайт.

| Что заполняется | Источник и выбор | Где хранить/редактировать |
|---|---|---|
| Категория и вид изделия | Изделие и разрешённые умолчания/группа; собственный подтверждённый выбор главнее наследуемого | Карточка/настройки изделия; определения видов — `passportKinds`, категорий — `passportCategories` |
| Критерии воронки | `productFacets` и `productFacetValues`; применимость к категории/виду, сохранённые `facetValueIds` | Определения/значения — существующие справочники; ответ — изделие. Не дублировать признак отдельным полем одного документа |
| Краткое описание | Своя формулировка изделия → явно выбранный применимый лист → однозначный словарный вариант. `passportPhrases.section=simple-description`, ограничения по виду/группе/признакам | Общая фраза и применимость — справочник; `passportDefaults.textChoices/textOverrides` — выбор/исключение изделия; `simpleDescription` — необязательная собственная замена |
| Названия частей | `passportParts`, ссылки `partIds` словарной фразы или своей формулировки; грамотные формы `genSingular/genPlural` | «Части изделия (для паспорта)». Это функциональные названия, не производственные детали/BOM |
| Назначение, правила, монтаж, обслуживание | Применимые существующие фразы, элементы, способ установки и шаблон категории; точный сборщик — `passport-v2-text.ts` | Соответствующий справочник/шаблон, сохранённый выбор изделия; ручной текст отделён от унаследованного |
| Габариты, масса, рисунки | Фактические поля изделия, паспортные изображения с `purpose=passport`, effective/standard images; вход из Inventor/iLogic | Изделие и его рисунки. Рисунок не доказывает массу, нагрузку, толщину, скрытые узлы или глубину бетонирования |
| Фирма, заказ и позиция | Явный контекст выпуска; заказ необязателен. В заказе проверяются связанные productId/incomeId/salesOrderId | Экземпляр документа, не общий текст категории. Шаблон/образец не требует компании и номера |
| Номер, текст и источники печати | Явный выпуск; повтор запроса не создаёт второй документ/номер | Снимок экземпляра и история редакций. Старые документы нового формата не получают автоматически |

### Безопасные входы для чтения и сборки

- Шаблон: `GET /api/showcase/:id/passport-template?variant=short`, включая `document`, `defaults`, `readiness`, `simpleDescriptionSource`, `simpleDescriptionSuggestions`. Он не создаёт экземпляр/номер.
- Воронка: `GET /api/passports/funnel` с контекстом изделия и `presentationVersion=1&variant=short`. Сервер отбирает применимые ветки, неизвестное оставляет выбором, несовместимое исключает.
- Частичное сохранение шаблона: PATCH того же ресурса `{changes,expected}`. Не отправлять вместо него полный старый объект и не стирать богатые данные full.
- Старый документ для нового UI: `GET /api/passports/:id?readOnly=1`; PDF/пакеты также с `readOnly=1`. Не вызывать синхронизацию старого черновика ради просмотра.
- Справочники: штатные `/api/dicts/:key`, метаданные полей/прав и `/usage` перед объединением/удалением. Доступ — по правилам AGENTS, авторизация только через агента доступа/API helper.

## Добавление нового типа документа

Для предложений, счетов, договоров и будущих документов применяется тот же П-1, но паспортные поля и правила нельзя механически копировать. До реализации добавить в соответствующий блок карты сайта и этот реестр:

| Обязательная запись карты | Что указать |
|---|---|
| Контекст | Тип документа, точные связи и граница шаблона/экземпляра |
| Результат | Поля/разделы текста, которые должны заполниться |
| Источники | Действующие сущности/справочники и серверная проекция |
| Критерии и приоритет | Что сужает выбор, где подтверждённый ответ, что можно вывести автоматически |
| Память и правка | Владелец сохранённого ответа, экран редактирования, разовое исключение |
| Неизвестное/конфликт | Один нужный вопрос, допустимый пропуск и реальный блокер |
| История | Когда фиксируется снимок, как выполняется явная редакция |
| Приёмка | Количество вопросов, отсутствие повторов, повторное открытие, изменение критерия и неизменность выданной истории |

Сейчас подробно описан паспорт. Прочие документы добавляются по отдельным задачам; эту карту нельзя выдавать за готовую универсальную функцию всех документов.
