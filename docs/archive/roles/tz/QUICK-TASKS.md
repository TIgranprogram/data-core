# Быстрые задачи «+ Задача» и «План» (ЗД, аналитика 2026-10-29)

Класс XL. Аналитик до кода. Вопросы — `docs/QUESTIONS.md` «ЗД». Связано с `RESPONSIBILITY-ZONES.md` (ЗО).

## 1. Что есть сейчас
| Что | Где | Годится? |
|--|--|--|
| Чат `messages` | `modules/messages/message.schema.ts` (from→to, текст, readAt) | Нет: только «человек→человек», нет срока, привязки, статуса |

## 2. Решение по модели
**Одна новая сущность `tasks` (только data-core, CRM не читает).** Чат, уведомления, design-note и designtasks не расширяем: у них другой смысл. Таблиц на каждый вид объекта нет — привязка полем.

Поля:
- Ввод: `text` (≤ 500), `dueDate` (ГГГГ-ММ-ДД, необязательно), `assigneeId` (persons) **или** `zoneCode` (зона), `link: { type, id, lineId?, label }` (необязательно).
- `link.type`: `salesorder` | `orderline` | `supplyrequest` | `contract` | `document` | `passport` | `product` | `supplier` | `person`. `label` — снимок названия, чтобы показать без запроса.
- Пишется само (аналитика): `createdAt` (дата постановки), `createdBy`, `status` (`open` / `done` / `cancelled`), `doneAt`, `doneBy`, `dueMoves` (сколько раз перенесли срок), `dueHistory[{from,to,at,by}]`, `linkedAt` (привязана позже). Просрочка не хранится: считается из `dueDate` и `doneAt` (или «сегодня»).
- Задачи проектирования (`designtasks`) остаются; их сроки в «Плане» уже есть видом `design`. Подписи: «Задача проектирования» и «Задача».

Адресация (как ЗО §4.6): личный исполнитель → уведомление `task_assigned` ему (нужен `persons.userId`, ЗО-1); иначе зона → люди зоны; в зоне никого → «Руководство» + «Не назначено». Смена исполнителя — запись в `handoffs` (ЗО-5), `entity:'task'`.
Без исполнителя и зоны — личная, видна только поставившему.
Права: задача показывает только `label`; объект открывается по правам роли.

## 3. Экраны
1. **«+ Задача»**: «Сегодня» (шапка и день «Плана»), карточки заказа / позиции / заявки / паспорта / сотрудника (привязка уже заполнена). Ввод — только правая панель.
2. **Панель «Новая задача»**: текст → срок (кнопки «Сегодня / Завтра / Пятница / +неделя / Другая дата» и календарь `input type=date`) → исполнитель (по умолчанию «Я»; «Зона…») → «Привязать к…» (необязательно) → «Создать». Дата постановки — подпись «Поставлена сегодня», не поле. Минимум: текст + «Создать».
3. **Воронка объекта** (плитки, «Назад», «Без привязки»): категория (Заказ, Заявка, Договор, Документ/паспорт, Изделие, Поставщик, Сотрудник) → список с поиском → у заказа ещё шаг «позиция с фото / весь заказ».
4. **«План»**: сегодня + 6 дней. Клик по дню раскрывает список дня и «+ Задача на этот день». В день попадают: мои задачи, отгрузки (`shipDate`), поставки (`neededBy`), сроки проектирования, платежи; значок вида. Сверху «Просрочено». Пусто — подсказка «Нажмите на день, чтобы запланировать».
5. **У объекта**: блок «Задачи» (открытые сверху, выполненные свёрнуты, история переносов по клику).
6. **У исполнителя**: «Сегодня» → «Моё» (ЗО-4) и фильтр «Мои задачи»; «Сделано» одним кликом; «Перенести» (считает `dueMoves`).

## 4. Компонент выбора объекта
Новый `pwa/ui/object-picker.js`: `objectPicker({ onPick, types? }) → { el, value() }`. Общее (`orderLines`, `picBox`, `lineCode`) вынести из `target-picker.js` в общий модуль; `target-picker` переходит на него без смены вида. `step-funnel.js` и `funnel.js` не трогаем. Изделие — миниатюра `photoId`. Категорию без данных не показываем.

## 5. Фазы и приёмка
| Фаза | Класс | Что | Приёмка |
|--|--|--|--|
| ЗД-1 | M | `tasks` + CRUD + поля аналитики; панель «+ Задача» на «Сегодня» (текст, срок-кнопки), личная задача | Если ввести текст и нажать «Создать», то задача в списке с сегодняшней датой постановки. Если выбрать «Пятница», то срок — ближайшая пятница. Если перенести срок, то `dueMoves` +1. Если нажать «Сделано», то `doneAt`/`doneBy` заполнены |
| ЗД-2 | M | «План» по дням + «+ Задача на этот день» | Если создать задачу из среды, то срок — эта среда. Пустой день показывает подсказку. Просроченная — в «Просрочено» |
| ЗД-3 | M | `object-picker` + вынос общего; привязка при создании и позже | Если выбрать Заказ → позиция, то видно фото позиции. Если привязать позже, то `linkedAt` заполнен и задача видна у объекта. Выдача (`target-picker`) выглядит как раньше |
| ЗД-4 | M | Блок «Задачи» в карточках заказа, позиции, заявки, сотрудника | Если открыть заказ, то видны его задачи и задачи его позиций; «+ Задача» оттуда сразу с привязкой |
| ЗД-5 | M | Исполнитель-человек, `task_assigned`, «Мои задачи». **После ЗО-1** | Если назначить сотрудника со входом, то у него уведомление. Без входа — подсказка «Вход не связан: уведомление не придёт» |
| ЗД-6 | L | Адресация на зону + `handoffs`. **После ЗО-2, ЗО-3, ЗО-5** | Если адресовать зоне «Склад», то уведомление получают люди зоны; зона пуста — директору «Не назначено» |
| ЗД-7 | S | Категории «Документ/паспорт», «Поставщик» в воронке | Нет данных — категория скрыта |

## 6. Порядок относительно зон
- Не ждут ЗО: ЗД-1…ЗД-4 (исполнитель выбирается, но уведомление не дойдёт — подсказка).
- Ждёт ЗО-1: ЗД-5. Ждёт ЗО-2/3/5: ЗД-6. ЗО-4 желательно до ЗД-5.
- Порядок: ЗО-1 → ЗД-1 → ЗД-2 → ЗД-3 → ЗД-4 → ЗД-5 → (ЗО-2…5) → ЗД-6.

## 7. Риски
- Две «задачи» в приложении: разные названия и места.
- Отгрузки/поставки уже в ленте — не дублировать задачами.
- Индексы `{assigneeId,status,dueDate}`, `{link.type,link.id}` — в `scripts/ensure-indexes.js`.
- `zones` и `today.service` правятся в рабочей папке (не закоммичено): ЗД стартует после коммита ЗО-1.
