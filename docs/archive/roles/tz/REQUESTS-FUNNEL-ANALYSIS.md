# Заявки — воронка и счёт: разбор (analyst, 2026-10-28)

## 1. Как сейчас
- Этапы: Ожидает → Заказать (`requested`) → Заказано (`ordered`) → Оплачено (`ordered`+`paid=true`, не отдельный статус: `supply.service.ts:176,317`) → Получено (только кнопка «Принять», `:330,366`) / Отменено. Подпись — `requests.js:35,43,263`.
- Счёт в заявке — только два поля на строке: `invoiceNo`, `invoiceDate` (`supply-request.schema.ts:118,148`; форма `requests.js:154-156`). Сущности «Счёт» нет; сумма счёта = сумма строк. Ворот нет: статус меняется выпадающим списком или перетаскиванием без проверки полей (`requests.js:150,263`), «Оплачено» ставит `paidAt` без № и даты счёта.
- Счёт заводится отдельным экраном `invoice.js` («+ Счёт», `requests.js:189`): там позиции берутся из справочника заново (`invoice.js:115,216`), создаёт НОВЫЕ заявки сразу в выбранном этапе (`:26-28`, `:221`), а приход — `:226`. Существующие заявки «Заказать» туда не подтягиваются → дубль работы и риск дублей заявок. Так менеджер и потерялась.
- Деньги: расход ложится на `invoiceDate`, не на `paidAt` (`finance.service.ts:50`, аудит «Деньги»); без даты счёта позиция не видна в календаре (`supply.service.ts:186-188` — «needsFill»).

## 2. Предложение
**Этапы** (названия те же): Ожидает → Заказать → В работе (заказано у поставщика; счёт создан) → Оплачено → Получено; Отменено. Новых статусов нет — только «В работе» = `ordered` без `paid` (как сейчас «Заказано»).

**Счёт = новая коллекция `supplyinvoices`** (отдельно от `supplyrequests`): `no, date, amount, supplierId, companyId (плательщик), fileIds[], status (draft|issued|paid), paidAt, createdBy`. Заявка получает необязательное `invoiceId` (старые `invoiceNo/invoiceDate` остаются как копия-снимок для CRM и календаря).
- Один счёт — много заявок (один поставщик). Сумма счёта по умолчанию = сумма строк, можно править (доставка).
- Автосоздание: выбрал N позиций в «Заказать» → «В работу» → сервер создаёт один пустой счёт (`draft`, без №/даты/суммы/файла), ставит позициям `ordered` и `invoiceId`. Разные поставщики → по счёту на поставщика (спросить подтверждение в панели).
- Позиция вошла в «В работу» одна → тоже авто-счёт на одну строку.

**Ворота:** Заказать→В работу: поставщик, кол-во, ед. Счёт draft→issued: № + дата + сумма (файл — не обязателен). В работе→Оплачено: счёт issued + компания-плательщик; Оплачено→Получено: «Принять» (склад). Ожидает/Отменено: причина.

**Автоматом:** «Счёт оплачен» одной кнопкой переводит ВСЕ заявки счёта в `paid`, ставит `paidAt`. Дата/сумма счёта, заполненные один раз, копируются в строки (`invoiceDate`, пропорциональный `lineTotal`) → платёжный календарь сам. «Принять» — по строкам (частичный приход уже есть, `supply.service.ts:413`); все строки получены → счёт закрыт. Отмена последней строки — счёт снимается/аннулируется. Склад: меняется только на «Получено» (как сейчас).

## 3. Отдельная страница?
Нет для заявок: хватает доски (колонки = этапы, чек-лист и главная кнопка — как в `REQUESTS-FUNNEL.md`). Счёт — одна карточка в правой панели + вкладка/чип «Счета» в том же разделе (список: №, поставщик, сумма, статус, «не хватает: № / дата / сумма»). Экран `invoice.js` («+ Счёт») оставить только для «счёт, которого не было в заявках», а выбор позиций там заменить на «из заявок Заказать».

## 4. Сервер / приложение
Сервер: схема `supplyinvoices` (+модуль в supply); `POST /supply/invoices {requestIds[]}` (авто-счёт), `PATCH /supply/invoices/:id`, `POST …/:id/pay`; проверка ворот в `supply.service.ts` (400 с текстом) — только для запросов с `source=app`, чтобы CRM/таблицы не ломались. `supplyrequests`: добавить только `invoiceId?` (не ломает CRM; её код поле игнорирует). Для `supplyinvoices` — запись в UNIFIED-DB-MAP, openapi/MAP обновить. Миграция: старые заявки с `invoiceNo` группировать в счета по (поставщик, №) — отдельным скриптом, на копии, с «да» пользователя.
Приложение: доска с воротами, групповое «В работу», панель счёта, чип «Счета», правка `invoice.js`.

## 5. Вопросы пользователю
1. Один счёт может покрывать позиции разных поставщиков? По умолчанию — нет (счёт на поставщика, система делит сама).
2. Оплата — для всей группы сразу, или часть позиций счёта может быть оплачена отдельно? По умолчанию — только всем счётом.
3. Старые заявки с № счёта сгруппировать в счета задним числом? По умолчанию — нет, только новые (старые остаются как есть).
