## Shared pack
- Модуль = сборка (`productmodules`). Деталь = `materials` + `materialKind:'part'`. Части паспорта ≠ детали.
- Модуль: детали, вложенные модули, покупное, сырьё. Изделие: модули, детали, покупное, другие изделия; **сырьё в изделие нельзя**.
- Детали модуля не копируются в изделие — ссылка на модуль, раскрытие по цепочке.
- «Обеспечить» = сырьё/метизы/покупное → бронь или заявка. Модули/детали не закупаются.
- API: `/modules`, `/materials?materialKind=part`, `/showcase/:id/composition`, purchase-needs, workTypes.
- Эталоны: `funnel`, `list`/`table` как продукция, `openCard`, create-with-return (C094).

## Порядок (строго)

### A. Сейчас первым — воронка состава в книжке
1. Заменить плоский «Изменить состав» в правой колонке книжки на: дерево текущих строк + воронка «Добавить».
2. Шаги воронки: **Что** (модуль / деталь / покупное) → **Какую** (список/поиск из наших данных) → **Сколько** → «В состав».
3. «Создать модуль/деталь» из шага → мини-форма → возврат в воронку с выбранной строкой (C094).
4. У модуля в дереве — раскрытие детей (детали) read-only.
5. Сохранение: PUT composition, номера строк сохранять (C127 w1).
6. Владелец смотрит выбор в паспорте.

### B. Паспорт читает дерево
7. Черновик PDF / блок состава на листе — прямые дети + подписи; раскрытие модулей согласовано с ANALYSIS критерии 1,5,6.
8. Техописание «Взять из состава» — по цепочке, не пустой список при модулях.

### C. Разделы меню Модули и Детали
9. Навигация после «Продукция»: Модули, Детали.
10. Списки с фильтрами/поиском/карточкой — эталон как продукция.
11. Состав модуля — тот же паттерн воронки.
12. Карточка детали: сырьё (заготовка), виды работ (C122).

### D. Виды работ и связки
13. Работы изделия / модуля / детали на своих карточках; сумма по дереву — план (не блокирует A–C).
14. Atlas и help уже отражают дерево; добить help при смене меню.

### E. Обеспечить
15. Один экран/кнопка: дерево → остаток → бронь и/или заявка после подтверждения (C068-4).

### F. Вычистка
