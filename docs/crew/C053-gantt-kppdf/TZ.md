**Зачем (пользователь 2026-11-08):** в старом проекте kppdf-8.0 Гант нравился: смотришь и по людям, и по заказам, листаешь, группы раскрываются деревом, цвета различаются, всё видно. Решение: **один Гант — вкладка «Гант» в «В работе»**, лишние Ганты убираем; берём принцип представления kppdf, склеиваем с нашими данными (планы позиций `orderlineplans.steps[]`, исполнители по видам работ, факт, срок/просрочка, «в проектировании»), добавляем лучшее сверху.

## Отчёт каждого анализа (`AUDIT-claude.md` / `AUDIT-deepseek.md`, до 150 строк)
1. Паттерн: название + 5–8 строк сути.
2. Как устроен Гант kppdf: оси, дерево, раскрытие, цвета, полоса, навигация, взаимодействие, легенда — с местами в коде.
3. Сравнение с data-core таблицей: аспект · kppdf · data-core · вывод (взять / уже есть / наше лучше / не нужно).
4. Чек-лист изменений по этапам: Э1 сервер (данные для дерева и цветов), Э2 эталон kit `planner` (дерево, раскрытие, цвет, легенда, масштабы), Э3 экран «В работе → Гант» (единственный Гант; `#workschedule` и `ui/gantt.js` убрать или перенаправить), Э4 полировка (наши улучшения сверху).
5. Риски и что проверить глазами.
