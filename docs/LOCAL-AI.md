## Hermes для DataCore

На Windows из папки репозитория запусти `pwsh -File tools/hermes-data-core.ps1 -Setup`. Скрипт проверяет `HERMES_OK` через текущее подключение, связывает рабочую папку с проектом DataCore и выбирает `hy4flash` в текущем профиле Hermes. На другом ПК нужен установленный Hermes CLI и настроенное там подключение QW35Lab. Ключ остаётся в конфигурации Hermes.

Для отдельного поручения передай UTF-8 файл с целью, фрагментами и конкретным вопросом через `-TaskFile`. Подготовь только те данные, которые нужны для анализа. Обычный запуск использует `hy4flash` и лимит 70 с. `-Deep` явно выбирает `glm-5.3` и лимит 100 с. Оба запуска передают пустой набор инструментов. Координатор проверяет выводы по коду и тестам, затем сам вносит правки. При ошибке Hermes сообщает причину, задача продолжается без него.

По [каталогу QW35Lab](https://qw35lab.icu/api/models) на 26.11.2026 у `hy4flash` минимальный коэффициент 0,001×, у `glm-5.3` — 1×. Hy4 Flash справился с пересчётом единиц, обработкой 409, разбором повторных запросов и предложением регрессионного теста. На открытом ревью складского кода GLM 5.3 нашёл пропуск записи при повторном вводе нуля после частичного сбоя. C274 воспроизвёл и исправил дефект. Сервер отклоняет повторное имя с 409. Для совпадающей координаты под другим историческим именем нужен отдельный контракт. [Доказательство и сценарии приёмки](crew/C274-agent-architecture-audit/STOCK-COORDINATE-CONTRACT.md).

## PDF в Пульте

Сначала Пульт читает текст PDF. Для спорных реквизитов PyMuPDF готовит изображения выбранных страниц в памяти и передаёт их локальной модели в LM Studio. Готовность черновика зависит от подтверждения полей и сумм по источнику. Ответ по изображению без текстового подтверждения сохраняется отдельно. Документ остаётся на сверке. Для повторяющихся счетов Пульт может запоминать проверенный шаблон строки и читать её заново из следующего PDF.

Источники реализации: [рендер PyMuPDF](https://pymupdf.readthedocs.io/en/latest/page.html#get-pixmap), [Chat Completions LM Studio](https://lmstudio.ai/docs/developer/openai-compat).

## Как подбирать загрузку (правило)
1. `lms load <модель> --gpu <доля> --parallel 1 -c <контекст> --estimate-only` — оценка памяти без загрузки.
2. **Оценка LM Studio занижает на ~1,5 ГБ** (qwen3-coder: оценка 14,1 → на деле 15,7 ГБ). Цель — оценка ≤ 13,5 ГБ, чтобы в видеокарте оставалось ~1,5–2 ГБ запаса.
3. `--parallel 1` всегда: по умолчанию LM Studio держит 4 параллельных запроса — это лишний кэш в видеопамяти, нам не нужен.
4. Модель больше 16 ГБ (MoE «A3B/A4B») — частичная выгрузка `--gpu 0.6–0.7`: остальное в ОЗУ, скорость падает в 3–6 раз, но работает.
5. Консольный `lms` **сам запускает LM Studio** — в фоновых опросах только проверка процесса (урок 15.11, пульт).

## Итоги сравнений
- **Тестировщик (15.11):** gpt-oss-20b — 93 % заданий, 83 % сам заканчивает, «по кругу» 2 %; Gemma 12B — 82/61 %; Qwen3-30B — 80/70 %, 5× медленнее.
- **Аналитик C126 (16.11, `docs/crew/C126-local-analyst/REVIEW-home.md`):** Gemma 4 26B — лучшая по фактам (9/9, 11/11, 42≈41, верные файлы, 4/4 больших файла), ~2 мин; qwen3-coder и gpt-oss ошибаются в счёте.

## Выбор (16.11)
