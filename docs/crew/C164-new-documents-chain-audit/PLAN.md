## Требования к доработке, уже следующие из поручения

Договор покупателя должен храниться без выдуманного производственного заказа. Стабильные ссылки: наша организация → покупатель → договор → редакция спецификации / исходящий счёт → позиции → фактические поступления и распределение на позиции. Производственная группа и объект — отдельные необязательные связи. Суммы юридического документа, НДС, валюта и исходный PDF сохраняются снимком; изменение справочника не переписывает прошлое.

Нужны состояния подписания и подтверждающие файлы, условия доставки/монтажа, договорные сроки и этапы оплаты с основанием события. План оплаты отделён от факта: выставленный счёт не подтверждает зачисление. КП — отдельная версия предложения, его принятие/конверсия не должны терять покупателя, объект, налоги и условия. Противоречивые условия сохранять с пометкой проверки.

Сохранить существующий контракт API и идентификаторы. Не использовать supplyinvoices/suppliercontracts для продажи. Миграция существующих договоров — только план → проверка → применение без автоматического создания производственных групп и проектных задач.
