# Задача: настроить агентную систему data-core на минимум токенов без потери качества

Ничего «от себя» сверх ТЗ не изобретай. Опирайся на текущие файлы и на спецификацию ниже. После правок — только отчёт, без лишней прозы.

## Цели
- Меньше always-on токенов (CLAUDE.md / дубли).
- Меньше ролей на одну тему и без повторного чтения одних файлов.
- Все субагенты явно на sonnet (включая data-steward).
- Классификация задач S/M/L/XL + caps.
- Короткие отчёты ролей, жёсткий scope из ТЗ.
- Не ухудшить качество: зоны ролей, review-scope, контракты ТЗ, release/verify, plan→apply — сохранить.

## Обязательные правки

### 1) `.claude/agents/datacore-*.md` (все 7)
- В frontmatter явно: `model: sonnet` (особенно data-steward).
- В начало body (кратко, без воды):
  - читать только пути/якоря из ТЗ; если scope пустой — стоп, 1 вопрос;
  - не пересказывать ТЗ;
  - отчёт ≤ 12 строк в формате: статус | сделано | файлы | проверки | риски;
  - не коммитить; не трогать чужую зону;
  - не читать DESIGN/CANON/HISTORY/TASKS целиком — только указанное в ТЗ.
- Сжать длинные чеклисты architect/designer до минимума must-keep; убрать дубли skill verify (одна отсылка).

### 2) `CLAUDE.md`
Сжать до короткого always-on (целевое: существенно короче, без историй с датами).
Должно остаться:
- роль координатора;
- @AGENTS.md;
- матрица S/M/L/XL → кого звать (кратко);
- S — сам; M — 1 executor (+ reviewer по матрице); L/XL — по матрице;
- hard cap: M ≤ 2 агента, L ≤ 4, XL ≤ 5; review loops ≤ 2;
- запрет: ≥2 роли не читают одни и те же файлы без split scope в ТЗ;
- на L/XL audit: сначала 1 primary reader, остальных — только на слепые зоны / split;
- ТЗ по шаблону docs/roles/TZ-TEMPLATE.md;
- UI skill design: не для S; для M только если паттерн/layout; для L-UI — да;
- verify: smoke vs full (full перед release/XL);
- коммит+пуш+эстафета после задачи;
- лимиты 80%/85% — без агентов;
- ответ пользователю 1–3 строки по умолчанию.
Истории решений с датами перенести в docs (HISTORY или docs/roles/lessons-coordinator.md), в CLAUDE не держать.

### 3) `AGENTS.md`
- Убрать явную воду/дубли с CLAUDE, где повторяется слово в слово.
- В карте доков: TASKS/HISTORY не читать целиком (только grep/хвост/расследование).
- Редкие ловушки вынести в docs/traps.md, в AGENTS оставить частые + ссылку.

### 4) `docs/roles/README.md`
Переписать как on-demand playbook координатора:
- матрица S/M/L/XL с примерами;
- когда обязательны architect / designer / qa / analyst;
- caps агентов и review loops;
- правило shared pack + split files;
- запрет параллельной «второй компании» (вторая сессия = worktree + готовое ТЗ + 1 роль, без полного оркестратора);
- убрать дубли «постоянных требований пользователя», если они уже в CLAUDE/AGENTS.

### 5) `docs/roles/TZ-TEMPLATE.md`
Добавить поля:
Класс S|M|L|XL; Max agents; Shared pack; Читать запрещено; Проверки smoke|full; Reviewers; Max review loops; формат отчёта ≤12 строк; явный контракт backend↔frontend если оба.

### 6) Skills
- `datacore-verify`: явные уровни smoke vs full и когда что.
- `datacore-design`: когда применять / когда нельзя тащить на мелочь (согласовать с CLAUDE).
- Убрать повтор длинных «экономия токенов», заменить отсылкой к CLAUDE/AGENTS.

### 7) Память проекта (`MEMORY.md` + дублирующие файлы, если доступны)
- Из always-on памяти убрать законы, уже записанные в CLAUDE/AGENTS/skills (token-economy, agent-team, limits, short-replies, ui-design-skill-first и т.п.).
- Оставить только пользовательский профиль и уникальный runtime-опыт.
- Если править память нельзя из этой сессии — явно напиши в отчёте, что вычистить вручную.

### 8) Карты ролей
- В docs/roles/README или в каждом map: роль в конце работы дописывает якоря file:line / «где X», чтобы следующий раз не сканировать дерево.

## Не делать
- Не удалять роли architect/designer/qa.
- Не трогать business-логику сайта, backend/src, pwa, admin (кроме docs/agent config).
- Не добавлять hooks/CI, если пользователь этого не просил.
- Не раздувать новые простыни: каждый новый абзац must-earn place.

## Проверка после правок
1. Покажи diff-stat (пути + сколько строк было/стало) для CLAUDE.md, AGENTS.md, agents, skills, roles docs.
2. Подтверди: у всех 7 агентов model: sonnet.
3. Таблица: класс задачи → агенты → reviewers → verify level (итоговое правило).
4. Список удалённых дублей (что где повторялось и куда схлопнули).
5. Оценка: какие 3 изменения сильнее всего режут токены.
6. Риски качества и как матрица их закрывает.
7. OPEN: что не смог сделать (например memory).

Пиши код/правки сразу. В конце — отчёт по пунктам 1–7 проверки. Без предложений «могу ещё».
