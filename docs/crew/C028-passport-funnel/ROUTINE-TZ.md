## R1 — подсказка признака по названию (скрипт, без ИИ)

**Зачем.** Когда менеджер делает паспорт на старое изделие без признаков, приложение предлагает: «Похоже: Силовой — верно?». Подсказка строится по словам из справочника признаков. Скрипт проверяет и настраивает эти слова на нашей продукции.

**Вход.**
- `tools/logs/c028/products.json` — 483 изделия (`items[]`: `id, sku, name, group, type, ppCategory, …`).
- `docs/crew/C028-passport-funnel/facets-seed.json` — `categories[].facets[].values[].words` (корни через `|`; правило — поле `wordsRule`).

**Сделать.**
1. `backend/scripts/c028-suggest-facets.mjs` — node без зависимостей. Чистая функция `suggest(name, category, seed)` → `[{ facet, value, word }]` по `wordsRule` (без регистра, ё = е, подстрока, первое совпадение по `order`). Экспорт функции + запуск из командной строки: `node backend/scripts/c028-suggest-facets.mjs` → пишет выходные файлы.
2. Прогнать по 483 изделиям. Изделие берёт признаки своей категории `ppCategory`.
3. Поправить **только поля `words`** в `facets-seed.json`, пока не выполнены нормы ниже. Остальные поля seed не менять.

**Выход.**
- `backend/scripts/c028-suggest-facets.mjs`
- `tools/logs/c028/suggest.json` — `[{ id, sku, name, category, facet, value, word }]`
- `docs/crew/C028-passport-funnel/suggest-report.md` — покрытие по каждому признаку-шагу (сколько изделий получили подсказку из скольких), 30 случайных строк «название → подсказка» для глаз, список изделий без подсказки по шагу 1 TRN и WRK.
- правки `words` в `facets-seed.json`.

**Готово, если.**
- Покрытие шага 1 (`trn.kind`, первый признак WRK) ≥ 85 % изделий своей категории.
- В 30 случайных строках нет явных ошибок (например, «Скамья для пресса» не стала «Турник»). Сомнительные — в отчёт.
- Скрипт запускается повторно и даёт тот же результат.

**Модель:** маленькая (Haiku 5.5 или похожая). Работа механическая: код ≈ 80 строк и подбор слов.

## R2 — черновики текстов паспорта по категориям

**Зачем.** В паспортах не хватает текстов для части нашей продукции (`ANALYSIS.md` §5). Менеджер выберет их из выпадающего списка своей категории.

**Вход.**
- `ANALYSIS.md` §5 — темы по категориям TRN, WRK, BLG, DIO, DSP.
- `tools/logs/c028/texts-tree.json` — нынешние тексты по категориям (разделы `sections[].key/title/paragraphs`). Ключи разделов брать только отсюда.
- `tools/logs/c028/dict-passportPhrases.json` — нынешние фразы (не повторять).
- `tools/logs/c028/dict-passportStandards.json` — список ГОСТ. Ссылаться только на ГОСТ из этого файла.
- `docs/crew/C028-passport-funnel/facets-seed.json` — коды значений признаков (`code`) и групп.

**Сделать.** Для каждой темы из §5 — один черновик.

**Выход.** `docs/crew/C028-passport-funnel/texts-drafts.json`:
```json
[{ "category": "TRN", "facetValue": "trn.load.weights", "group": null, "section": "maintenance", "title": "Обслуживание грузового блока", "paragraphs": ["…"] }]
```
`facetValue` — код значения признака, если текст для признака; иначе `group` — название группы (BLG). Одно из двух.

**Правила текста.**
- Своими словами. Не копировать чужие паспорта и тексты из интернета.
- Деловой стиль паспорта изделия. Предложение ≤ 25 слов. Одно требование — одно предложение.
- Не больше 6 абзацев на черновик.
- Подстановки — только `{name}` `{heightMin}` `{weightMax}` `{maxUsers}` `{ageFrom}` `{ageTo}`.
- Числа (нагрузки, моменты затяжки, сроки) не выдумывать. Нужна цифра, которой нет во входных файлах, → `[уточнить]`.
- Не повторять то, что уже есть в `texts-tree.json` той же категории.

**Готово, если.** Все темы §5 закрыты черновиком; JSON читается (`node -e "require('./docs/crew/C028-passport-funnel/texts-drafts.json')"`); в отчёте — список тем и мест с `[уточнить]`.
Черновики проверяет аналитик. В базу они попадают только после проверки.

**Модель:** средняя (Sonnet 5.5 или похожая). Маленькая модель путает нормативный стиль и выдумывает цифры.
