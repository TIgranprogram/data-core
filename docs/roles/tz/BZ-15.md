# ТЗ БЗ-15 — фото продукции из паспортов (обложка), «сначала с фото», таблица по умолчанию везде и запоминание вида

**Зачем (словами пользователя, 2026-10-24):** «у изделия в паспорте фото есть, а в продукции нету… хотя бы для начала подтянуть из паспортов — потом поменяю, если не понравится рисунок (нужна обложка). Сначала показывать с рисунками (сортировка по умолчанию). Везде по умолчанию табличное представление, потом запоминает, если поменяли. Можно хранить в браузере кеш — у всех много оперативки».

**Роли:** аналитик ☐ · архитектор ☑ (кеш, общая коллекция `products`) · backend ☑ · frontend ☑ · qa ☑ · дизайнер ☑

## Что сделать
1. **Обложка продукции из паспорта.** Если у изделия (`products`) нет своих фото (`photoIds` пуст), показывать «Общий вид (фото на обложку)» (`images[kind=overview]`) из его паспорта (`productpassports.productId` = изделие; паспортов несколько — самый свежий выпущенный, иначе самый свежий). Поле ответа `/showcase` — `photo` (как сейчас) + `photoSource: 'own' | 'passport'`.
   - Архитектор решает: (а) только подстановка в ответе, без записи в базу (рекомендую: обратимо, kppdf не задет), или (б) разовый скрипт «план → `--apply`», дописывающий `photoIds`. Скрипт на проде — только по «да» пользователя.
   - В карточке изделия: метка «фото из паспорта» + кнопка «Сделать своей обложкой» (кладёт фото в `photoIds` первым) и обычная замена/удаление своих фото. Своё фото всегда главнее паспортного.
2. **Сортировка «сначала с фото»** — по умолчанию в «Продукции» (таблица и галерея): сначала с фото (своё или из паспорта), внутри — как сейчас (по названию / разделу). Пользователь выбрал другую сортировку — работает она.
3. **Таблица — вид по умолчанию во всех списках** (`ui/list.js`): убрать `gallery.default` у «Продукции» (и других, если есть). Переключил на «Галерея»/«Доска» — запоминается для этого раздела: `core/prefs.js` (браузер + `users.uiPrefs`, как ширины панелей ШП), ключ `view.<раздел>`. Явный `?view=` в адресе главнее сохранённого.
4. **Кеш в браузере.** Справочники, категории, списки для выпадающих (`sections/lookups.js`, `ui/dict-options.js`) и миниатюры — держать в памяти/`localStorage`/Cache Storage (service worker уже есть) со сверкой версии (`/api/meta` версии коллекций — модуль `versions`, если подходит; иначе ETag). Архитектор: что кешировать, предел объёма, сброс при выходе пользователя. Цель — повторное открытие раздела без ожидания.
