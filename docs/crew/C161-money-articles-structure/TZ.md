# C161 — гибкие статьи и табличные доходы/расходы

Статус19.11.2026: реализовано, архитектурные условия и адресная визуальная приёмка закрыты; после сведения61558531 выполняется полный combinedQA перед выпуском. Задание владельца: исправить табличный вид доходов/расходов, добавить недостающие связи, дать редактирование названий/родителей в справочниках и разнести существующие статьи по главным группам. Названия будущих расходов заранее неизвестны: структура должна меняться данными, без исправления программного кода при каждом переименовании.

Класс: XL — финансовая аналитика, справочники и сохранение существующих связей. Реализация ведётся в отдельной рабочей копии C158; данные прода до отдельного плана не меняются. C158 остаётся владельцем фактов оплаты; C161 строится поверх его готового источника, не создаёт параллельную модель платежей.

## Сырьё и что уже существует
- Живой снимок:183узла expensearticles,14корней и169детей,2уровня; файл C158/data/snapshot-expense-articles-flat.json. В выдаче только живые записи; type/archived/usage отсутствуют. Эти признаки и использование в фактах не восстановлены наугад.
- Уже есть «Справочники → Статьи расходов»: изменение name, parentId, categoryIds; права менеджера и старше, ссылки использования, soft-delete/restore/merge. Не создавать вторую копию этого справочника.
- Ограничения: родитель выбирается только среди корней, buildTree/выбор статьи/агрегация зашиты на2уровня; системный payroll нельзя перенести; его сид частично ищет родителя по названию.
- Уже есть «Деньги → По статьям»: годовая таблица месяц/квартал, раскрытие групп/контрагентов и операций по сумме; календарь, сводка, прогноз, долги. Нужны исправление и единый табличный сценарий, а не ещё один финансовый раздел с другим источником.
- Доходы сейчас группируются по заказчику/заказу; отдельного income-articles в живом контракте нет, в Income/IncomeDto отсутствует articleId. Расходам articleId уже доступен в заявках/expenses, а C158 сохраняет его в распределении платежа.

## Глубже
- Результат: менеджер добавляет/переименовывает/переносит статью без потери платежей; директор видит доходы, расходы и их денежный итог в таблице, раскрывает сумму до конкретного подтверждённого факта.
- Истина: источник фактов C158 + существующие платежи incomes/payroll/expenses. Название/положение статьи не порождает денежную операцию.
- Метод: независимые измерения (статья, наша компания, объект, направление затрат), стабильные ID, аудит классификации и сверка итогов до/после изменения справочника.
- Доказательство:183ID/имени сохранены планом; после rename/reparent/archive суммы/даты/количество фактов неизменны; после переклассификации меняется только аналитический разрез, общий денежный итог тот же.
- Приёмка вида: заполненные таблицы/редактор справочника в двух темах на компьютере, общий kit/treeTable/list/card, отсутствие обрезанных значений и прыжков экрана. Мобильные замечания — отдельным списком, не блокируют текущую задачу.

## Что сделать в интерфейсе
- «По статьям» — сводная таблица с деревом и периодами; «Операции» — строки фактов. Смена режима сохраняет фильтры и положение по URL/устойчивым ID, не сбрасывает выбранную компанию/объект.
- Строка факта: дата, поступление/выплата, сумма врублях, наша компания, статья/путь, контрагент, объект/заказ, направление затрат, документ и источник. Длинное значение можно прочитать; номер/дата/сумма не обрезаются.
- Фильтры: период, направление поступление/выплата, наша компания, статья со всеми потомками, объект, направление затрат, контрагент, источник и «Без статьи». Не вводить две разные истины одними и теми же фильтрами.
- Итоги по полному отфильтрованному набору, не по текущей странице: поступления, выплаты, денежный результат. Это не бухгалтерская прибыль. Будущие оплаты только в прогнозе; начисленный ФОТ не становится кассовым фактом из-за названия группы.
- В «Справочниках»: название, тип, родитель, порядок, группа/статья, активность выбора; понятный путь и число связей; выбрать нового родителя из любого допустимого уровня. Циклы/собственные потомки/другой тип недоступны и отклоняются сервером.
- В выборе статьи: короткая воронка по type → группа → подходящая статья/поиск по всему пути; выбранный сохранённый ID не теряется после rename/reparent. Архивная старая статья видна в документе, но не предлагается для новой классификации.
