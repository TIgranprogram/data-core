# C095 — Паспорт сборного изделия

Название утверждено. Ниже минимальная форма и состав PDF для согласования перед реализацией.

## Сценарий

В текущей форме выбрать изделие, подтвердить название как в договоре и выбрать один или несколько вариантов модуля. По каждому варианту проверить рисунок и габариты, указать количество и открыть предпросмотр. Один вариант выпускается по тем же правилам, что и несколько. Заказ и адрес установки необязательны.

Нужны структурированный состав экземпляра, серверный расчёт, ведомость, привязка чертежей и проверка полноты.

## Поля и PDF

| Что | Как заполняется |
|---|---|
| Название изделия | Подставляется из карточки или заказа, можно уточнить по договору |
| Вариант модуля | Выбрать хотя бы один. Название отличает варианты в ведомости |
| Габариты варианта | Подставить имеющиеся или указать одной строкой с единицей измерения |
| Рисунок варианта | Подставить имеющийся или выбрать через текущий механизм изображений. Если рисунка нет, блок печатается без пустой рамки |
| Количество варианта | Целое число больше нуля, в штуках |

В PDF использовать действующий титул, реквизиты и тексты категории. Для каждого варианта напечатать название, габариты, количество и один рисунок при наличии. Для нескольких вариантов показать общее количество модулей простым сложением указанных количеств. При одном варианте достаточно его количества. Полей нагрузки, массы, площади и расчёта длины в этом режиме нет.

## После утверждения

Расширить текущую форму и PDF опциональным списком вариантов. Фиксировать данные выпуска для повторной печати. Проверить паспорт с одним вариантом и с тремя (например 20, 5 и 2 шт., всего 27), вариант без рисунка, обычный паспорт, нумерацию и экспорт. Использовать datacore-design, datacore-verify и UI-ACCEPTANCE. При изменении API обновить MAP/OpenAPI.
