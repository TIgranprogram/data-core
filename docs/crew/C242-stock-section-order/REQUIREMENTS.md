# C242 — бизнес-требования к четырём таблицам склада

23.11.2026. Analyst. Основание: TZ, EXPLORER, PROD-FIELDS, ARCH-PLAN C242. **Матрица принята для stage B; фактическая приёмка UI и разрешение миграции этим не подтверждены.** Код и прод повторно не читались и не менялись.

## Матрица колонок

Фото и выбор строки — служебные колонки. «Первый столбец» означает первый предметный. ID/код, исходное название и примечания доступны отдельно.

| Вкладка | Предметные колонки по порядку | Учётные величины | Default |
|---|---|---|---|
| Основной | Наименование → категория/тип → материал → марка → применимые размеры → длина единицы → единица учёта → остаток → бронь → свободно | Исходная unit. Заголовки «Остаток, ед. учёта», «Бронь, ед. учёта», «Свободно, ед. учёта» плюс видимая unit; не общая подпись «шт» | Имя в смешанном списке; в явно трубном контексте сечение по возрастанию. Явный sort=name пользователя сохраняется |
| Трубы | **Сечение, мм** → материал → марка → мойка/состояние → **длина единицы, м** → остаток → бронь → свободно → код/источник | Текущие 91 позиция — м: учётные колонки подписаны метрами. При другой unit показывается исходная единица; метраж только отдельной доказанной проекцией | Профильные → круглые → неопределённые; внутри rect(B,H,t), round(D,t), далее длина/марка/состояние, стабильное имя/ID |
| Листовой материал | Материал → марка → поверхность/рифление → толщина, мм → ширина, мм → длина, мм → лист/обрезок → unit → остаток → бронь → свободно | Целый лист в unit «лист»; обрезок в unit «шт» остаётся штукой. Разные единицы не суммируются в общий итог | t→W→L по возрастанию внутри видимой группы материала/марки, если группировка сохранена |
| Деревообработка | Материал/название → код → категория → ширина, мм → высота/толщина, мм → длина, мм → unit → остаток → бронь → свободно → примечание | Исходные м/м²/шт и прочие unit. Не добавлять расчётные м³/«доски». Неприменимые размеры расходника не являются ошибкой | Материал/категория, внутри W→H/t→L; пользовательский sort по оси применяется ко всему набору |

Сечение трубы — самостоятельный составной параметр поперечного профиля: B×H×стенка или ØD×стенка. В него не включаются длина хлыста, ГОСТ, марка и мойка. Числовые компоненты имеют отдельные поля проекции; допустимо отображать их одной ясной подписью. Если выведены отдельные оси, заголовки B/H/D/стенка подписаны в мм. B/H автоматически не переставлять. У дерева высота и толщина не универсальные синонимы: использовать реальную ось источника.

## Факты, расчёты и неизвестные

- Остаток, бронь, свободно — в исходной unit материала. Размеры источника — мм; перевод длины единицы трубы мм→м является только отображением.
- `quantity/(length/1000)` — **расчётный эквивалент**, не фактическое число труб. Даже целое частное не доказывает однородность партии. Для первого выпуска убрать вычисляемую колонку «Шт»; ни floor, ни round не превращают деление в инвентаризацию.
- Физические целые трубы в штуках допускаются только по подтверждённому составу/однородности и фактическому количеству. Подтверждения сейчас нет. Отдельный учёт партий/кусков в C242 не вводится. unit=шт подтверждает учётную единицу, но сама по себе не доказывает целый стандартный хлыст.
- Куски с известным общим метражом и неизвестными длинами: метраж виден, длина единицы «Не определена», физическое количество «Требует пересчёта». Никаких выдуманных длин/штук. Изменение описательной длины не пересчитывает ledger.
- Ноль — известное 0. Пустое/unknown — «Не указано» или прочерк с подсказкой. Неполное — «Уточнить размеры», конфликт источников — «Данные расходятся». Неприменимое отличается от неизвестного; нули вместо пропусков запрещены.
- Материал и марка различаются. «Нержавеющая сталь» не доказывает AISI304. Общий материал допускается как честная проекция источника, точная марка остаётся неизвестной; исходное значение доступно. Новое поле/справочник заранее не требуется.
- washed=true/false — мытая/немытая; null не превращается в false. «Не применимо» используется только при доказанной неприменимости. Из washed нельзя вывести новую/б/у/коррозию.
- Пустые размеры расходника не ошибка; пустой формат листа и неполное сечение трубы показываются как пробел. Данные не дополняются из похожего названия или фотографии.

## Полнота, сортировка, разные ID

Порядок операций: доступ/зона/фильтры → числовая сортировка **всего набора** → страницы → отображение. Размеры сравниваются по компонентам: 20<40<100; 2<2,5<3,5. Круг и профиль группируются по матрице, диаметр не сравнивается с шириной как одна ось. ГОСТ/марка/длина из имени не попадают в tuple.

Unknown/incomplete/conflict идут в конец при asc и desc; равные ключи стабильны по имени→materialId. Явные дополнительные ключи длины/марки/состояния предшествуют последнему tie-breaker. Выбранный размерный порядок сильнее скрытого attentionRank; срочность обозначается, но строки молча не переставляются. Экспорт использует ту же зону, фильтры и sort.

В снимке 571 уникальная зонная позиция, 503 в общей выдаче; дополнительные 68 — нулевые трубы/листы. Не требовать равенства общего held-списка объединению зон: его прежний смысл сохраняется. В зонных таблицах все разрешённые нулевые позиции остаются доступны. limit10000 первой страницы не доказывает полноту. Пустая Деревообработка остаётся пустой: пять деревянных кандидатов Основного туда автоматически не переносятся.

Предпочтение — одна строка на materialId. Разные ID/марки/длины/единицы/состояния не сливаются по одинаковому сечению. Если сетка остаётся, коллизия раскрывает список и блокирует агрегированную правку. Тихая перезапись row.cells[key] и исчезновение одного ID — дефект.

## Метаданные: plan → review → apply с CAS

1. План фиксирует ID, точные before/after разрешённых метаданных, источник, причину, неоднозначности, защищаемые поля и обратный план. Исходные имена/описания сохраняются. `40 x 40 x 2 мм` → `40×40×2` только при однозначном разборе.
2. Нормализуются только подтверждённые описательные размеры/сортамент/марка/мойка. Категория, материал или зона не назначаются догадкой. **unit, quantity, reservedQty, minQuantity, движения, брони, связи не меняются.** Не объединять и не удалять материалы.
3. Координатор принимает конкретный plan до применения. Запись — через API/access. Текущий updateItem не даёт клиентского expected-before: GET→PATCH не является CAS. До stage C требуется принятая архитектором optional precondition с проверкой внутри транзакции. Stage B read-only от этого не зависит.
4. Параллельная правка CRM/data-core и stale-before → конфликт/409 без затирания. После потерянного ответа перечитать результат. Повтор apply не стирает свежую правку; повтор plan по исправленным данным даёт 0.
5. После apply перечитать метаданные и инварианты unit/quantity/reserved/free/history. Обратный план также CAS, не безусловный откат старого снимка. Измерение кусков и пересчёт остатка — отдельная штатная операция.

## Бизнес-дыры: границы допуска stage B

| Дыра | Принятое решение / блокер |
|---|---|
| EXPLORER допускает штуки при целом частном, ARCH-PLAN строже | Принят строгий вариант: физические штуки из деления не показывать. Если UI сохраняет недоказанную «Шт» — FAIL до исполнения |
| 53 профильные трубы без W/H; два неоднозначных сечения | Для B строгая read-only проекция из assortment, без backfill. До кода зафиксировать rect/round и оси; не достраивать квадрат/стенку |
| 10 труб без length, три положительных куска | Честный unknown не блокирует таблицу. Физические штуки/ввод штуками блокированы до фактической проверки |
| Нет отдельного точного материала/марки, washed=null | Источник виден, точная марка неизвестна. Это не блокер B и не разрешение обещать полную чистоту БД |
| Листы «лист» + обрезок «шт» | Нужна явная unit и раздельные итоги; общий заголовок «листы» над обрезком в шт — FAIL |
| Сеточная коллизия нескольких ID | До UI выбрать одну строку на ID либо раскрытие. Тихая потеря/суммирование разных материалов недопустимы |
| Деревообработка пуста, height терялась | Заполненные fixtures на копии обязательны; пустой экран не даёт PASS четвёртой таблицы |
| Доступ/readonly C240 и складские действия | Сохранить guards, зоны, пересчёт в базовой unit. Несогласованная дельта общих mount/guards блокирует исполнение |
| CAS отсутствует | Не блокирует read-only stage B, жёстко блокирует stage C apply |

Идеально заполненная БД не является предварительным условием B. Настоящие блокеры перед исполнением — не определённые правила единиц/осей/коллизий/физических штук и пересечение с C240. После принятия этой матрицы и архитектурных границ можно делать честную таблицу с явными unknown.

## Критерии приёмки

- Труба 100×50×2: длина единицы 6 м и остаток 42 м отдельны; «7 физических шт» из деления не появляется. При 20 м/6 м нет «3» или «3,33» как фактических штук.
- Три положительных куска снимка сохраняют 1/1/2 м; длины и количество не придуманы. Профиль 100×50×2 не становится 50×100×2; неполные 40×20 и 40×1,5 не достраиваются.
- Числовые fixtures 20/40/100, 2/2,5/3,5, круг/профиль, unknown/conflict работают asc/desc через три страницы; поиск/зона/priority/export не меняют смысл порядка. Height/depth/isImmutable не теряются при правке другой оси.
- В разрешённой зонной нулевой выдаче доступны все 91 труба и 46 листов текущего снимка; набор >10000 не теряет хвост. Основной и пустая wood сохраняют прежний scope.
- Лист Ст3 3×1250×2500: параметры отдельно, факт 4 листа. Обрезок AISI304 640×500×6: 1 шт, без перевода в целый лист. Два материала одной ячейки не скрывают ни один ID.
- Wood проверена на копии: пиломатериал W/H/L, плита с толщиной, расходник с неприменимыми осями и разными unit; все четыре таблицы имеют заполненную desktop-приёмку.
- Проекция/метаданные не меняют unit, quantity, reserved/free, историю, брони и производственные связи. Ненулевая бронь и fully-reserved fixture обязательны: reserved=0 в снимке не заменяет регрессию.
- Stage C на копии проверяет stale CAS, параллельную CRM-правку, повтор/потерянный ответ и обратный план. Без серверного CAS прод apply не выполняется.
- Параметры читаются в своих колонках с единицами; C240 readonly и роли/зоны сохранены. Старые API/name sort не ломаются, новый default ограничен трубным контекстом.

**Бизнес-PASS для адресного stage B в границах ARCH-PLAN.** Проверка реализации, фактическая миграция, визуальная приёмка и выпуск ещё не выполнены.
