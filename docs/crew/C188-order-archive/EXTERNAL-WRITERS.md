# C188 — внешние писатели договора

Прямые команды сопоставления, уточнения классификации дохода и создания/подтверждения/отклонения заявки на изделие занимают `salesorders.passportGuard` внутри своей транзакции. При архивной цели возвращается `ORDER_ARCHIVED`. Подтверждение заявки сохраняет товар, заявку и связи позиций вместе. Переносы каталожных записей из заказов и паспортов, переименование/объединение справочников и контрагентов переносят только доступные ссылки. Архивные цели и неразрешимые ссылки пропускаются. Справочники и актуальные карточки товаров можно менять отдельно. В массовом ответе справочника/витрины `archiveSkipped` показывает число пропущенных каскадных целей за вызов, возможны несколько попыток по одной записи.

| Путь | Защита |
|---|---|
| `matching.bulk` и `confirm/none` | Общий claim всех найденных договоров до первой записи строки, весь набор в одной транзакции. Алиасы, заполнение названия товара и запуск проектирования идут после commit. |
| `FinancialClassificationService.apply` | Claim договора источника `incomes`, включая синтетический платёж. Повтор ранее проведённой классификации читает квитанцию. Аналитика отдельного расхода не редактирует договор. `IncomePaymentIdentitiesService.materialize` защищён в зоне основных писателей. |
| `ProductRequestsService.attachIncome/confirm/reject` | Повторное определение живых строк и claim, запись заявки/изделия/связей в той же сессии. Начисляются только будущие номера товаров. Автопроектирование и уведомления идут после commit. |
| `DictsService.update/merge` и `dicts.moved` | Для всех вызовов `reassign` сессия каскада общая с записью справочника. `cascade.writableCascadeRows` разрешает владельца шапки, позиции, паспорта, вложения и заявки снабжения. Признак `archiveProtected` вложения продолжает действовать после возобновления. |
| `PartnersService.renameCustomer/merge` | Текстовые связи шапки, строк и заявок снабжения обрабатываются в общей сессии. Карточки контрагентов доступны для самостоятельных правок. |
| `ShowcaseService.fromOrders`, `ShowcaseFromPassports.fromPassports` | Каталожная запись и связь разделены. Привязка разрешена только для проверенных экземпляров и позиций, с claim в той же транзакции. Если в момент привязки все цели недоступны, новая общая карточка может остаться без связей. |
| `CollectionsAdminController`, `meta-schema.describeModels` | `salesorderarchives`, `salesorderarchivereopens`, `salesorderarchivechunks` исключены из списка и meta. Просмотр примеров, документов, drop по прямому имени возвращают отказ. Удаление неизвестных алиасов и любых коллекций, кроме `kind: app`, уже закрыто. |

Штатный `release.sh --data` теперь передаёт `order-archive-write.js` вместе с `import-orders-xlsx` и `add-our-company`. Каждый договор обрабатывается в своей транзакции, архивные договоры пропускаются с отдельным итогом. Фото Excel подготавливаются до записи Mongo и убираются после подтверждённого abort. При сбое процесса возможны файлы без ссылки. `import-passports` защищает обновление/откат с проверкой старых и новых связей. `incomes-payments-migrate`, `migrate-passport-status`, `passport-dicts-cleanup`, `passports-category-from-product` проверяют действующего владельца в транзакции. Последний использует скомпилированный общий барьер, чтобы работать через штатный `node -`.

Физические прямые записи старой CRM и ручные команды DB-администратора находятся вне гарантий API. Источники архива отгрузки должны пройти проверку связи DataCore из контракта. Исторические скрипты в `backend/scripts/archive/` не относятся к штатному пути. При переносе актуального сценария из архива его писатели должны пройти ту же проверку до запуска.

## Проверка

Адресные фикстуры в `backend/test/e2e/c188-external-writers.e2e-spec.ts` прошли **6/6** на отдельном MongoDB 4.4 rs0, база `datacore-test-c188-external`. Проверены смешанная пачка сопоставления, смешанный каскад формы оплаты, конкурентная классификация, отказ заявки/товара для архивной строки, запрет общего просмотра архивных коллекций и реальный запуск CLI привязки компании. По изменённым модулям прошло **233/233** юнит-теста, `tsc --noEmit`, ESLint, `node --check` для скриптов и `bash -n` для `release.sh`. Живые API и база не использовались. Полный `--data` с реальным Excel и выпуск входят в общую приёмку C188.
