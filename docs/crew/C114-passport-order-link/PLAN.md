# C114 — связать старые паспорта с заказами (план, без записи)

Класс: XL (данные прода, коллекция `productpassports` общая с CRM). Запись — только по кнопке пользователя.

## Зачем
Вкладка «По заказам» печатает весь заказ по полю паспорта `incomeId` (позиция заказа).
Новые паспорта получают `incomeId` при выпуске. Старые (до очереди «Нужно сделать», импорт, CRM) — нет.
Итог: старые паспорта не попадают в печать заказа.

## Поля (product-passport.schema.ts:180–188)
- `orderNo` — номер заказа текстом (бывает у старых).
- `salesOrderId` — ссылка на заказ (бывает у CRM-паспортов).
- `incomeId` — позиция заказа; только data-core, CRM поле не читает → запись безопасна для CRM.

## Как подбирать (скрипт `backend/scripts/passport-link-orders.js`)
1. Берём паспорта без `incomeId`, не удалённые.
2. Ищем заказ: сначала `salesOrderId`, затем `orderNo` (точное совпадение номера).
3. В заказе ищем позицию: тот же `productId`; нет — совпадение названия позиции и паспорта.
4. Уверенно = ровно одна подходящая позиция, у неё ещё нет паспорта, кол-во паспортов не больше `qty`.
5. Всё остальное — «спорно» (несколько позиций, нет заказа, нет изделия) — не трогаем, в список менеджеру.

## Порядок
1. Скрипт без `--apply`: отчёт `tools/logs/passport-link-*.md` — «уверенно N / спорно M / без заказа K», по каждому: паспорт → заказ → позиция → почему.
2. Прогон на стенде (копия прода) + проверка печати «По заказам» глазами.
3. Пользователь читает сводку и жмёт кнопку пульта «Связать паспорта с заказами» (`--apply`, только «уверенно»).
4. Перед записью — бэкап; запись только `$set: { incomeId }` там, где поле пустое; откат — `--undo <файл отчёта>`.
5. «Спорно» — чек-лист менеджерам (вручную в карточке паспорта).

## Не делаем
- Не меняем `orderNo`, `salesOrderId` и другие поля CRM.
- Не создаём паспорта и позиции.

## Неизвестно
- Сколько старых паспортов имеют `orderNo`/`salesOrderId` — покажет первый прогон без записи.
