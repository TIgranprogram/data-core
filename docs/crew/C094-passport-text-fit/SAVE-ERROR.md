# C094 — ложная ошибка после «Готово» в шаблоне

12.11.2026, заполненная копия `http://localhost:3102`, шаблон указателя 3905. Воспроизведено без изменений полей: открыть шаблон и один раз нажать **«Готово»**.

## Причина

Старый `card.js` подставлен только для одного GET модуля в отдельном incognito-контексте. Остальное — живой стенд. После одного клика карточка вернулась в режим просмотра, затем показалась ошибка. Новый запрос сохранения на этот клик не ушёл. Перехвачены запись консоли и отчёт:

```text
TypeError: Cannot read properties of null (reading 'beforeClose')
    at cancel.onclick (http://localhost:3102/app/ui/kit/card.js:357:127)
action: сохранить
```

`h(...,{onclick})` регистрирует первый обработчик через `addEventListener`. Для readonly-формы отдельно назначался второй обработчик через свойство `onclick`. Первый открывал просмотр и обнулял `form`, второй обращался к `form.beforeClose()`. Поэтому ошибка появлялась после перехода в просмотр, даже если пользователь ничего не менял.

## Проверка исправления

- На текущем `card.js` одиночное «Готово» без изменений и обычный двойной вызов возвращают в просмотр без ошибки. Живые правки текста элемента и индивидуального текста на копии дали HTTP 200. Вариант бетонирования выбран, отдельного PUT в этом шаге не было: выбор уже совпадал с сохранённым.
- [Фактический стек и журнал действий](evidence/ui-save-error/results.json). Ошибка только в базовой версии. Первую матрицу выполняли с двумя разрешёнными маршрутами записи на стенд. Прод не менялся.
- Для отложенного значения браузеру подставили недостающее поле с default, фактическую запись перехватили и задержали на 550 мс. Двойное «Готово» отправило ровно один запрос и вернуло карточку в просмотр после 200. При 500 форма сохранилась открытой, «Готово» снова активна, диагностика содержит отказ записи. [Результаты задержки и отказа](evidence/ui-save-error/close-tests.json).
- Открыты и оценены [ошибка на старой версии](evidence/ui-save-error/baseline-error.png) и [режим просмотра после исправления](evidence/ui-save-error/fixed-3905.png). На исправленной версии без искусственного отказа сообщение об ошибке не появляется. Проверка целевого поведения — **PASS**.
