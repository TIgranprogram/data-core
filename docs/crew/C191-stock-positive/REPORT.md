# C191 — PASS на изолированных данных

- «Остатки», выдача, категории, поиск, признаки и счётчики используют положительное физическое количество доступных материалов. Полная бронь видна с нулём в графе «Свободно».
- Без `held=1` общий запрос сохранил прежнюю выборку. Нулевые покупные позиции доступны в каталоге, приёмке и расчёте закупки. Собственные детали остаются в «Деталях». Модули и изделия принадлежат отдельным коллекциям, размещение CRM с `productId` не попадает в рабочий список материалов.
- `stockzones` определяет доступ по категориям и включениям/исключениям. Количество собирается из действующих размещений CRM основного физического склада. Имена полок `zoneName` не используются в правах.
- Источник ошибочного «Сечения», разбор артикулов и отличие снимка от синтетической проверки — в [аудите фасетов](FACET-AUDIT.md).
- Проверены типы, ESLint изменённых модулей, 389 файлов PWA, 0 новых нарушений дизайна, 23 адресных набора Jest / 560 тестов и 16 тестов фасетов и истории. На MongoDB 4.4 rs0 прошли 60 HTTP E2E в пяти отдельных наборах. C191 проверяет реальный приход, бронь, две полки и отказ 403 для чужой зоны.
- Edge прошёл сценарий на 1920, 2560 и 1024 пикселях. Покупное с нулём найдено в каталоге, деталь — в «Деталях». Выбор типа и переключение склада закрывают карточку из предыдущей выборки. [Снимки и условия](UI-REVIEW.md).
- На локальной копии :3102 оба метиза из снимка найдены в общем запросе и отсутствуют в `held=1`. У каждого остаток, бронь и свободное равны нулю. Описания подтверждены по `assortment`. [Поля карточек](FACET-AUDIT.md).
