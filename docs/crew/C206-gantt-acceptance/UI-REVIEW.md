**Итог проверки.** Интерфейс и сценарии на фикстуре — PASS. Два входа на реальных данных — PASS для чтения. Сохранение, факт, норма, перенос и отмена на серверной копии — PARTIAL, на копию ничего не записывали. Мобильная приёмка отложена по текущему приоритету владельца.

**Автоматические проверки.** `node --test tools/design-checks/work-schedule.test.mjs` — 6/6. Проверки PWA — 386/386. Проверка синтаксиса и импортов — 392 файла, ошибок 0. Дизайн-линтер — 0 новых нарушений. Серверный файл `order-line-plan.e2e-spec.ts` — 7/7 на отдельной тестовой базе.

**Конкуренция.** GET `/work-schedule` возвращает `rev` для полос плана позиции. Первый перенос и сохранение передают полученный `rev`. Отмена передаёт `rev` ответа переноса, сохранение после отметки факта — `rev` ответа отметки. Серверная проверка подтвердила 409 для повторной записи с устаревшим `rev`. У старых заданий W свой контракт. Бросок на другого исполнителя сохраняет исходные даты, сдвиг в той же строке сохраняет исполнителя. Перенос и отмена делают по одному запросу.

**Итоговый повтор.** Оба входа на свежей сборке показали по 8 полос. В браузере также проверен диагональный перенос как у плана позиции, так и у старого задания. Предпросмотр и подсказка сохраняют текущую дату при переходе на другого исполнителя. Полный локальный прогон записан в [журнале](../../TEST-LOG.md).
