# ТЗ C057-Э0 — подготовка номенклатуры прода к загрузке из PDM

**Зачем:** до первой загрузки номенклатура должна сопоставляться автоматически: у позиций проставлен вид, разобраны тип/стандарт/марка/размеры, найдены дубли, исправлен вес, заведены сортаменты.
**Класс:** M (скрипты + отчёты; прод — только по «да») · **Max agents:** 1 (`datacore-data-steward`) · **Проверки:** скрипты в режиме плана на копии/стенде; `node --test` для разборщика.
**Читать:** `DECISIONS.md` п. 2, 3, 16, 17; `ANALYSIS.md` 5в (таблица полей, примеры прода). Схема — `backend/src/modules/material/material.schema.ts`.

## Что сделать (каждый скрипт: по умолчанию **план** в `docs/crew/C057-pdm-import/data/*.json|md`; `--apply` — только по команде координатора)
1. `backend/scripts/c057-kind.js` — `materialKind` по категории: «Метизы»→`fastener`, «Покупные изделия»→`purchased`, «Листовой металл» и прочее сырьё→`raw`, «Оборудование»→`other`; ИБП с `raw` → `other`. **Сначала** проверка: позиции, которые станут `raw` и стоят прямо в составе изделия (`products.composition` `lineType:'material'`) — в отчёт, не размечать (иначе изделие не сохранится).
2. `backend/scripts/c057-parse-names.js` — разбор названий только в **пустые** поля: «Болт мебельный, M10х120, DIN 603» → `typeName`, `standardRef`, `dimensions` (`diameter` 10, `length` 120); «Лист AISI 304, 0,5 мм, 1250×1980» → `typeName` «Лист», `materialGrade`, `assortment`, толщина/формат. Нераспознанное — в отчёт. Разборщик — общий модуль, юнит-тесты на 30 названий прода.
3. `backend/scripts/c057-weight-report.js` — вес: только **отчёт** (позиция, вес, вероятная единица, похожие позиции). Решает человек.
4. `backend/scripts/c057-dupes-report.js` — дубли по ключу сравнения (`common/catalog/match-key.ts` из Э1; до него — локальная копия правила, потом заменить импортом). Только отчёт.
5. `backend/scripts/c057-profiles.js` — сортаменты: по листам/трубам склада создать позиции-сортаменты (`isProfile`, `unit` м²/м, `scrapFactor` 1) и связать форматы (`profileId`, `isDefaultFormat` — самый частый формат). План → `--apply`. **Зависит от полей Э1** — делать после коммита Э1 п. 1.

## Файлы
- Только `backend/scripts/c057-*`, `backend/scripts/lib/` (если нужен общий разборщик), `docs/crew/C057-pdm-import/data/`, `REPORT-E0.md`.
- Не трогать: `backend/src` (Э1), `apps/` (Э2), `backend/pwa`.
- Данные прода: чтение — через `datacore-access` (`deploy/synology/api.sh prod GET …`). Запись — **никогда** сама; `--apply` запускает координатор после «да» пользователя.

- [ ] Разборщик: ≥ 90 % метизов и листов прода разобраны; остаток — списком.
- [ ] Отчёт дублей и веса — понятен человеку (русский, таблица).
- [ ] `--apply` идемпотентен (второй прогон — 0 изменений), проверено на стенде.
