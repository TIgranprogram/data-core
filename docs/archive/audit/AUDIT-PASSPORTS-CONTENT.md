| От нас | Загрузка файла в правой панели изделия → предпросмотр «нашли / не поняли» → вы подтверждаете → заполняется таблица материалов. Сопоставление названий с «Частями» по ключевым словам и спискам синонимов (стойка/столб/опора) |
| Объём | ~1,5–2 дня исполнителя + проверка; без ИИ. Вопрос в формате столбцов (нужен **один ваш реальный файл**) |
| Риск | пока в модели «Деталь1…», разбор вернёт пусто. До этого — 5.2 |

### 5.2 Имена деталей в дереве модели → части паспорта
Имена в дереве попадают в спецификацию, поэтому 5.2 — это 5.1 с **дисциплиной именования**. Предлагаю: из §4 сформировать **шпаргалку** «категория → список имён» (1 страница), и называть детали в модели ровно так («Стойка», «Перекладина», «Опорная пластина»). Тогда сопоставление почти 100 %. От вас: привычка + шаблон имён; от нас: страница-шпаргалка (1 час) и синонимы. Реально, дёшево.

### 5.3 iProperties / Custom Properties (масса, материал)
- **Само считается**: масса и объём — **если задан материал** (плотность берётся из него). Без материала в модели получится ерунда (масса «воды» или ноль) [?: поведение по умолчанию различается в системах]. Габариты (Д×Ш×В) — из ограничивающего параллелепипеда: в Inventor через iLogic/параметры, в SolidWorks — свойства списка вырезов [?]; проще всего **снять с чертежа** общего вида.
- **Заполняется вручную один раз**: в шаблоне детали (.ipt/.sldprt) завести стандартные свойства: Название, Материал, Описание. Тогда каждая новая деталь рождается уже со стальным материалом (сталь Ст3 / 09Г2С [?]), в BOM попадает «Материал».
- От вас: настроить шаблон (1–2 часа один раз; я могу подготовить список свойств, но интерфейс CAD не проверю). От нас: читать столбцы «Материал» и «Масса» из BOM и показывать как подсказку (масса изделия — в техданные, если вы захотите: В-6). Объём: +0,5 дня к 5.1.

### 5.4 ИИ по фото, названию и категории → черновик перечня и описания
- **Сейчас (без разработки)**: вы присылаете в диалог фото + название + категорию, я возвращаю таблицу: части (из справочника §4), материалы (по умолчанию «сталь, порошковая окраска»), одну фразу описания и назначения. Вы правите и подтверждаете; потом данные вносятся (или импортируются, если появится 5.1). **Ограничение честно:** по фото ИИ видит *что за детали*, но **не видит диаметр и стенку трубы** — размеры только из чертежа/BOM; предположения помечаются «?».
- **Позже (кнопка в приложении)**: нужен ключ ИИ-сервиса, правила хранения секрета, защита от «выдуманных» данных (в юридическом документе недопустимо без подтверждения), расход денег. Объём 3–5 дней. **Сейчас не рекомендую**: 5.1 + шаблон «типовой набор частей по элементу» дают 80 % пользы без риска.
- **Дёшево и без ИИ — «типовой набор по элементу/категории»**: выбрали элемент «Турник» → предложен набор [Стойка, Перекладина, Опорная пластина, Заглушка, Крепёж] с галочками. Нужна связь «элемент → части» в справочнике (поле, схема только добавляется). ~1 день + наполнение (мы).

### 5.5 STEP / виды из модели → картинки паспорта
- STEP в приложении **не показывать** (нужен 3D-движок в браузере: дорого, мало пользы, 5+ дней).
- Реально: из CAD сохранить **PNG/JPG видов** — общий вид (изометрия, светлый фон), чертёж с габаритами (вид спереди/сверху), зона безопасности (вид сверху с размерами), схема фундамента. В приложении виды картинок уже есть (`pwa/core/passport-kinds.js`: overview, dimensions, safety, mounting, overview_callouts, nameplate, foundation, holes, assembly). Вам — шаблон чертежа и 10 мин на изделие.
- **Выгода от именования**: чертёж общего вида с **позициями** (баллонами с номерами) + BOM = готовая картинка «Части изделия со стрелками» (`overview_callouts`). Это самый полезный из фото-видов для категорий с требованием подписи частей.

### Порядок (предлагаю)
1. Завтра: §1 + правки контента 1–4. 2. Неделя: 5.2 (шпаргалка) + один ваш файл BOM для оценки 5.1. 3. Дальше: 5.1 (импорт), «набор по элементу», затем решение по 5.4-кнопке.
