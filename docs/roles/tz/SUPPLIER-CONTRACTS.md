# ДП — Договоры поставщиков (класс XL, 2026-10-29)

Пожелание: счёт поставщика привязывать к договору; на заявке, когда появился счёт, выбрать договор из списка или тут же создать.

## Аудит
- `supplyinvoices` — только data-core, CRM её не знает (`supply/supply-invoice.schema.ts:7-11`). Общие с CRM только заявки/склад. Добавить поле безопасно.
- В коде нет коллекции договоров. `contracts` в `docs/UNIFIED-DB-MAP.md:37` — след старого модуля `counterparty` (удалён): имя НЕ брать. Репо kppdf (`D:\kppdf-8.0`) с этой машины недоступно: проверить на работе, нет ли там `suppliercontracts` (если есть — не ломать).
- Договоры покупателей — `salesorders.contractNo`, текстом. Не смешивать. Имя новой сущности — `suppliercontracts` («Договор поставщика»), чтобы позже мог появиться `customercontracts`.
- Счёт: правка `PATCH /supply/invoices/:id` (`dto-invoice.ts:14-23`, whitelist — поле `contractId` добавить в DTO), создание `supply-invoice.service.ts`, удаление `:261`. Экраны: `pwa/sections/invoice.js:207` (внесение счёта), `request-step.js:138-149` (шаг «оплачено»), `invoices-tab.js` (таблица счетов), `requests.js:288` (колонка «Счёт»), карточка поставщика `partners.js`.
- СВ-11 «поступление без договора» (incomes) — про заказы покупателей. Не путать, не трогать.
- Зоны уведомлений «Договоры»: в `modules/notifications` ничего нет; уведомление «договор истекает» — не в этой задаче (вопрос ДП-3).

## Модель `suppliercontracts` (модуль supply)
- `supplierId` (ObjectId, обяз., ref Organization), `supplierName` (снимок), `no` (обяз., trim ≤100), `date` (обяз.), `subject` (≤300), `validTo?`, `amount?` (≥0), `fileIds[]` (photos), `status` active|closed (по умолчанию active), `createdBy`, `deletedAt`.
- Индексы: `{supplierId, deletedAt}`; уникальный частичный `{supplierId, no}` при `deletedAt: null`. Повтор — 409 «У этого поставщика уже есть договор № …».
- `supplyinvoices.contractId?` (ObjectId, ref, index) — только добавление. Копию в заявки не пишем (читаем через счёт).

## API (`/api/supply/contracts`, формат `{items,total,page,limit}`)
- `GET ?supplierId=&status=&q=&page=&limit=` (lookup для combo = `?supplierId=X&status=active&limit=100`); `GET :id`; `POST`; `PATCH :id`; `DELETE :id` (soft).
- Каждому полю DTO — валидатор (whitelist). `AuditAction`: `supply.contract.created|updated|deleted`; добавить в `audit/action-ru.ts`.
- Права: читать — все роли снабжения/склада; создать/править — admin, manager, supply; удалить — admin, manager.
- `PATCH invoice` с `contractId`: договор должен существовать, не удалён и быть того же поставщика, иначе 400 «Договор другого поставщика». `""` — снять. Смена поставщика счёта сбрасывает `contractId` с предупреждением.
- `DELETE contract`, если есть живые счета с `contractId`: 409 «К договору привязано N счетов (№ …). Сначала отвяжите их». Закрытый договор (`closed`) выбирать в счёте нельзя, у старых счетов показывается.
- В ответ счёта добавить `contractNo`, `contractDate` (обогащение при чтении).

## Экраны (pwa, вид — skill datacore-design; ввод только в правой панели)
1. Поле «Договор» в счёте (`invoice.js`, шаг «счёт» в `request-step.js`, панель счёта): combo договоров выбранного поставщика, пункт «+ Создать договор». Не обязательно для сохранения счёта.
2. «+ Создать договор» открывает в той же правой панели мини-форму: № и дата обязательны, предмет, срок, сумма, файл. После «Сохранить» договор сразу выбран в счёте.
3. Карточка поставщика (`partners.js`): блок «Договоры» — список (№, дата, предмет, до, статус, число счетов), создать/правка/закрыть/удалить.
4. Таблица счетов (`invoices-tab.js`) и колонка «Счёт» на заявках: колонка «Договор» (№) или серая пометка «без договора»; фильтр «Договор: все / есть / без договора».
5. Язык менеджера: без кодов; пустой список — «У поставщика пока нет договоров. Создайте первый». Один поставщик в счёте без выбора — combo пуст с подсказкой «Сначала выберите поставщика».
