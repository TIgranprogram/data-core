# ТЗ C124 — «Подвал заказа»: действия над всем заказом или отмеченными позициями

**Зачем (словами владельца, 15.11):** «У каждого изделия свои паспорта — зашёл, видишь, редактируешь. Остаётся то, что относится ко всему заказу: все паспорта, акты выполненных работ, отгрузка — всё, что делается со всеми позициями. Не только всё — галочками несколько. Будущие документы и акты пойдут сюда же. Сделать красивый подвал, как верхушку заказа: ничего лишнего. Эталонный — потом будем использовать в других меню».
**Зачем — глаголом:** менеджер отмечает 3 позиции из 12 и за 2 касания печатает их паспорта / акт / отгружает; без галочек — то же для всего заказа.

## Глубже
- **Результат:** в карточке заказа внизу — постоянный подвал «Весь заказ»; у позиций — галочки; подвал показывает «Все позиции (12)» или «Отмечено: 3» и действия к ним. Блок «Документы заказа» (`salesorders.js:334 docsPane`, `:449`) упразднён — его действия в подвале.
- **Сырьё:** что уже есть для заказа целиком: «Паспорта заказа» (`order-passport-plan.js:13,28` — панель `of=orderpass`), «Печать паспортов…» (`:62,92`), PDF и вложения заказа (в «⋯» шапки), «Отгрузить» (`order-line-more.js:87`, по одной позиции), ZIP вложений (`order-attachments-zip.js:74`).
- **Метод профи:** шаблон «панель массовых действий» (bulk action bar) из Gmail / Linear / 1С: выбор → счётчик → действия; «Отменить выбор». Один эталон kit, а не разметка раздела.
- **Внешний судья:** снимки стенда 390/1024/1600 (подвал пустой выбор / 3 отмечено / действие выполнено), `dc audit` без новых находок, дизайнер.
- **Смелая планка:** любое действие над набором позиций — ≤ 2 касания после выбора; подвал не выше 64 px на 1024 и не перекрывает последнюю позицию.

**Класс:** L (новый эталон kit + экран заказа; сервер — только если массового маршрута нет) · **Max agents:** 4 · **Reviewers:** designer ☑ qa ☑ analyst ☑ (до кода — состав действий) · **Проверки:** smoke; full перед выкладкой
**Язык менеджера:** да · **Приёмка:** заказ 11-26 на стенде: отметить 3 позиции → «Паспорта» → печать только их.

## Shared pack
- **Решение координатора:**
  1. Новый эталон kit `footerBar` (подвал карточки) — витрина `#kit`, затем заказ. Позже — в других карточках (владелец: «в будущем будем использовать в меню как подвал»).
  2. Выбор позиций — галочка в строке позиции (эталон kit `pick`, как на досках `board.js` multi). Нет отметок = «весь заказ».
  3. Действия в подвале — группами: **Документы** (паспорта: выпустить/печать; акт выполненных работ — план; накладная — план; ZIP вложений), **Работа** (отгрузить отмеченные; в работу), **Изменить** (общее поле для отмеченных: срок, фирма — по решению аналитика). Будущих документов кнопками-пустышками не показываем (CANON: без «скоро»); они добавляются строкой в реестр действий, когда готовы.
  4. Реестр действий подвала — один массив в коде раздела `{ group, label, run(lines), enabled(lines) }`: новый документ = одна строка реестра.
- **Контракт:** если массового маршрута нет — `POST /api/salesorders/:id/bulk` не делать; использовать существующие поштучные вызовы последовательно с прогрессом (решение архитектора).

## Что сделать
1. analyst: список действий над всем заказом сегодня и в ближайшем будущем (акты, накладные, отгрузка, смена фирмы паспортов набора) → `ANALYSIS.md`, ≤ 30 строк.
2. frontend: эталон `footerBar` в kit + витрина; галочки позиций в заказе; подвал с реестром действий; перенос «Паспорта заказа», «Печать паспортов…», ZIP в подвал; убрать «Документы заказа».
3. designer: приёмка 390/1024/1600 по снимкам стенда.
4. Обновить `atlas-data.js` (salesorders: шаг «Весь заказ»), `docs/DESIGN.md` §3 (новый эталон).

## Критерии приёмки
- [ ] Без отметок подвал говорит «Весь заказ · N позиций»; с отметками — «Отмечено: K» и «Снять отметки».
- [ ] Печать паспортов из подвала берёт только отмеченные позиции.
- [ ] Отгрузить отмеченные — одна команда, итог «отгружено K».
- [ ] «Документы заказа» больше нет; ничего из него не потеряно.
- [ ] Эталон в `#kit`, design-lint 0 новых, `dc audit` без новых находок, дизайнер «принято».
