# C171 — начальный подэтап A: локальные черновики

Ветка `codex/wip-2026-11-21-c171`. Подэтап не является выпуском этапов 1–3 ТЗ.

## Сделано

- `tools/document-intake/preflight.mjs`: проверка Windows, свободного места, реальное извлечение PDF, реальный ответ локальной модели по закрытой схеме и чтение прав выбранного DataCore. Никаких установок и записей в DataCore.
- `analysis.mjs`: отдельная очередь счетов с `batchId`, хешем оригинала, страницами, исходным кандидатом, доказательствами и локальными версиями. Неверные кандидаты сохраняются до проверки. Один испорченный файл не прерывает следующие; общая недоступность ставит очередь на паузу. События и heartbeat различают продвижение и активность.
- Исправление через библиотечный `reviseDraft`: общий файловый lock, expected version, история, повторная проверка цитат/полей/сумм/ИНН. Редактирование в UI и серверный CAS ещё отсутствуют.
- `checked` означает только «Проверено локально». Публичного `ready`/отправки для C171 нет: серверные версии и дубликаты пока не проверены.
- Маркер `.intake/c171-review.json` запрещает C169 `run/resume/retry` в папке C171. Workflow и пачка фиксируются в первом журнале `claim`; восстановление `claiming` использует C169 reconciliation. Незавершённая старая очередь не присваивается C171 — нужна другая папка.
- `pult/document-intake.mjs`: новые `POST analyze`, `GET reviewreport`, `POST draft`, подготовка перед запуском, heartbeat и остановка. Права/контур привязаны к текущей сессии; пароль/JWT не сохраняются. Старый отчёт C169 исключает поступления C171.
- UI: отдельные счётчики, причины, поля/строки и выбор цитаты с номером страницы в правой панели. Просмотр текста страницы — дополнение; PDF рядом с полями пока не реализован.

## Следующие подэтапы

1. Серверные B1–B5 по [ARCH-PLAN.md](ARCH-PLAN.md): служебный черновик/CAS, повторные проверки, карантин оригинала, восстановление файлов и квитанций. Старый upload-first нельзя подключать к кнопке отправки C171.
2. Добавление файлов/drag-and-drop, полноценный PDF рядом с полями, разрешённые исправления оператора и XLSX с версиями/защитой формул.
3. Утверждённые установочные пакеты и профили моделей с контрольными суммами/возобновлением, установка и восстановление на новом Windows-профиле.
4. Ограниченный журнал исключений, подтверждение всей пачки, обрывы/повторы и обратная сверка.
5. Эталон ≥30 счетов с вручную проверенными полями, показатели качества/времени оператора и отдельная приёмка. Синтетические тесты не заменяют этот набор.
6. Договоры и внешняя модель — после отдельной приёмки и решений из ТЗ; в этом подэтапе не включаются.

## Границы приёмки

Стенд поднят из существующей отдельной копии: [STAND.md](STAND.md). Настоящий синтетический PDF прошёл реальную модель и readonly API без записи: [LIVE-ANALYSIS.md](LIVE-ANALYSIS.md); воспроизводимый сценарий `tools/document-intake/live-analysis.fixture.mjs` копируется агентом доступа в `tools/logs` и запускается только с stdin-сессией стенда. Backend-контракт и коллекции не менялись; OpenAPI не требует регенерации. Полный ночной прогон, новый профиль Windows, готовая установочная поставка, отправка и эталонный набор остаются открытыми. Результаты текущих проверок — в REPORT и профильных отчётах.

Урок: наличие старого автоматического обработчика требует блокировки на уровне корня очереди до первого захвата, а не только отсутствия кнопки отправки.
