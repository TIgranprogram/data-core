# C086 — защита обязательных рисунков при выпуске и PDF

12.11.2026. Исправление поручено координатором после PDF-DATA-CHECK. Стенд не перезапускался, данные не менялись, нормативные тексты не правились. Коммита нет.

## Результат

- Штатная генерация PDF проверяет, что обязательные виды рисунков реально прочитаны и декодированы. При отсутствии/повреждении — 400 с русским назначением («Чертёж с размерами», «Схема фундамента» и т. п.) и просьбой загрузить заново. Неполный файл не выдаётся.
- Правила обязательности общие: `imageRules`, категория, short/full, способ установки. Необязательные рисунки не блокируют PDF. Стандартные схемы установки засчитываются только после успешного чтения.
- `readiness` перед обычным выпуском проверяет реальные файлы обязательных видов: статус issued не присваивается одной лишь ссылке с kind. Используется тот же безопасный загрузчик/декодер, что для PDF.
- Ошибки чтения не остаются в кэше: повторная загрузка исправного файла позволяет печатать без перезапуска.
- Preview черновика доступен до загрузки: PDF явно помечен «ЧЕРНОВИК», отсутствующие обязательные рисунки показаны рамками с русским назначением и инструкцией загрузки. Строгий отказ действует для выпущенного/нечернового PDF. Техописание и обложка-образец не затронуты.

Файлы: `passport-pdf.service.ts`, новый `passport-image-files.ts`, `passport-pdf-images.spec.ts`, `product-passport.service.ts`, `passport-pdf-v2.ts`, `passport-pdf-v2-types.ts`, `passport-pdf-v2-layout.ts` в модуле product-passport. Дополнительно `passport-order.ts/spec.ts`: группы и родители фильтруются `deletedAt: null`.

## Проверка create / особые пути

Обычный `create` сохраняет draft; проверку файлов проходит последующий issue. Исторический create с явно переданным passportNumber сразу сохраняет issued (перенос старых паспортов); эта семантика не менялась. C072 `createReadyPassport` принимает уже готовый PDF, а не генерирует рисунки. Штатная генерация PDF защищена для всех статусов; приложенный пользователем готовый PDF возвращается как раньше. PDF №600 до исправления автоматически не меняется.

## Как загрузить настоящие PNG на тестовом стенде через UI

Для проверки достаточно подготовленных обычных PNG, но при приёмке содержания нужны действительные фото/чертежи, а не надписи C086.

1. В тестовом «Рабочем месте» открыть изделие «Деревянные указатели» → вкладка «Паспорт» → правка шаблона/заполнение паспорта. Рисунки находятся здесь, не во вкладке старых файлов изделия.
2. В нужных слотах «Фото изделия», «Чертёж с размерами», при бетонировании — «Схема фундамента» нажать «Заменить» у уже привязанного рисунка (даже если миниатюра не загружается), либо «Выбрать файл» у пустого. Выбрать соответствующий PNG. Возможны drop и вставка с фокусом в нужном слоте. Дождаться сообщения «Рисунок сохранён/заменён» и видимой миниатюры.
3. Повторно открыть форму и предпросмотр: PNG должны попасть в PDF. Проверить содержимое, а не только HTTP 200. После этого выпускать новый тестовый черновик через обычный процесс.
4. Замена рисунка изделия НЕ меняет замороженные ссылки уже выпущенного №600. Для него нужна штатная «Новая редакция» паспорта с заменой рисунков в её форме, либо новый отдельный тестовый черновик для проверки пути. Не выдавать исправление изделия за исправление старого PDF. Старый паспорт/позицию заказа не удалять и не аннулировать ради теста.

Тестовые действия должен выполнить ответственный за стенд после интеграции серверного кода. Этот агент не выполнял их и не перезапускал чужой стенд.

## Финальная дельта — ложная готовность по kind (12.11)

После FINAL-UI проверка реальных обязательных файлов добавлена в `check`: `productGaps` и план заказа используют этот результат без повторной сборки текстов. При существующей записи overview с утерянным файлом возвращается `img_overview` и русская инструкция загрузки, план не показывает ready.

`imageRules` включает overview всегда: это уже было безусловным требованием `missingFields`, теперь состав requiredImages формы/PDF/выпуска совпадает, даже если справочник категории пропустил overview.

Общий `readPassportImage` кэширует успешное декодирование (до 60 файлов, включая одновременные обращения), проверяя перед использованием размер/mtime/ctime через stat. Удалённые и заменённые файлы не сохраняют ложную готовность; ошибки не кэшируются. PDF использует этот же кэш вместо отдельного кэша изображения, обходившего проверку файла. Photos читаются одним пакетным запросом на проверку изделия, а в orderPlan повторные позиции одного изделия используют одну проверку шаблона.

Изменены только: `passport-image-files.ts`, `passport-rules.ts`, `product-passport.service.ts`, `passport-pdf.service.ts`, `passport-pdf-images.spec.ts`, `passport-order.ts/spec.ts`. Новые изменения журналов PDF от другого исполнителя не затронуты; UI и роли не менялись.

Регрессии: check и выпуск одинаково отклоняют overview с отсутствующим файлом; успешное декодирование повторно не читает байты, удаление файла инвалидирует кэш; два невыпущенных вхождения одного изделия вызывают одну проверку и оба блокируются. Типы и ESLint семи файлов PASS. До последнего теста повторов полный модуль — 50 suites / 554 tests PASS; после него дельта `passport-pdf-images` + `passport-order` — 2 suites / 20 tests PASS. Общий full ведёт QA отдельно.
