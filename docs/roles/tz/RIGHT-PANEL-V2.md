# Правая панель v2 — единое представление сущности (задание пользователя 2026-11-05)

Класс: XL (рефакторинг всех карточек сущностей). Первыми: designer → analyst, потом frontend по одному экрану. Не придумывать компонентов вне библиотеки эталонов (kit); эталон карточки — ДС-1 (`card()` с variant, `k-hover`).

## Устройство панели сверху вниз

1. **Заголовок «где мы находимся».** Название раздела, из которого открыта сущность (например «Деньги»), и сама выбранная сущность.
2. **Главный блок раздела (первым).** Всё, что относится к сущности в контексте этого раздела: фото (первым), данные, кнопки действий. Оформлен карточками одного стиля; если внутри таблица — табличная карточка того же стиля.
3. **Связанные разделы (ниже, тоже карточками).** Все разделы, у которых есть связь с этой сущностью, по одной карточке на связь.
4. **Переключение между разделами внутри панели.** Нажатие на связанный раздел меняет контекст, а страница, с которой человек пришёл, остаётся на месте:
   - верхний заголовок меняется на выбранный раздел;
   - главный блок показывает кнопки и данные именно этого раздела;
   - остальные карточки остаются: это связи той же сущности.
5. **Вид карточек.** Все однотипные, одного стиля (фирменного); адаптивные: заполняют ширину, растягиваются и сужаются под содержимое; длинный текст — длинная карточка.
6. **История изменений — внизу, всегда свёрнута.** Раскрывается только по нажатию и показывает историю по этой сущности.

## Открытое (вопросы к пользователю — по умолчанию в скобках)

- Что значит «страница остаётся»: список слева остаётся открытым, а панель переключает контекст (да).
- Сколько карточек в ряд: по ширине панели, минимум 240 px (как плитки склада).
- Порядок связанных карточек: по частоте использования сущности (по журналу прода), иначе по алфавиту.

## Порядок работ

1. Designer: чертёж панели на 390 / 1024 / 1920 по эталонам, список всех сущностей и их связей (analyst: таблица «сущность → разделы-связи»).
2. Frontend: общий каркас панели `ui/entity-panel` (заголовок, главный блок, связи, свёрнутая история) — без перевода экранов.
3. Перевод экранов по одному: заказ → изделие → счёт/заявка → контрагент → остальные; каждый — `dc audit` и приёмка дизайнера.
4. Автопроверка в `tools/site-audit.mjs`: структура панели (заголовок, главный блок, связи, история свёрнута).

## Принцип «картотека» (пользователь 2026-11-05)

Приложение — не набор страниц, а картотека/библиотека: карточки и блоки, внутри группы аккуратные таблицы-карточки. Видно, с чем связана сущность; можно зайти в связанную карточку и увидеть, что с ней делается. Правила:
- кнопки не повторяются и не стоят там, где не нужны; действие живёт в одном месте;
- экраны не прыгают: левое меню остаётся как при входе, работа идёт в правой панели, переключение связей меняет только правую часть;
- один стиль карточек и таблиц везде; адаптивные, но не «расплывчатые»;
- если аудит показывает развилку стиля — пользователю показывают 2–3 варианта на витрине (`#kit`), он выбирает.
