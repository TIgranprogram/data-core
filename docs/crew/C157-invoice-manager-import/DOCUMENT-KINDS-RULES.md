# C157 — виды документов, деньги и исполнение
19.11.2026. Будущие бизнес-требования; не проект бухгалтерии и не блок текущего импорта доказанных финансовых фактов.
Основа: PRODUCT §1–2, §5; C157/GAPS.md и QUESTIONS-SOURCE.md; C164/AUDIT.md и FIELD-MAPPING.md; примеры координатора. Код/API здесь не проверялись; новые поля не объявляются отсутствующими.

## Независимые признаки
1. Вид источника: договор / счёт / акт / платёжное подтверждение / акт сверки / предложение; отдельно роль «закупка / продажа». Вид не доказывает оплату, подписание или исполнение.
2. Экономический смысл обязательства/строки: товар / услуга / право пользования / возвратное обеспечение / погашение прежнего долга; смешанный документ различать по строкам. Статья затрат остаётся отдельной аналитикой.
3. Деньги: поступление / выбытие; наша компания, контрагент, фактическая сумма и дата, подтверждение. Направление относится к платежу: возврат поставщика — поступление по закупке, не новая продажа.
4. Исполнение: неизвестно / ожидается / частично подтверждено / подтверждено / прекращено; способ подтверждения — получение товара, оказание услуги, предоставление права. «Не применимо» — для обеспечения и денежного расчёта без нового исполнения.
5. Происхождение: текущая работа / исторический ввод, исходный файл/внешний ключ и время ввода. Историчность не доказывает завершение; неизвестное исполнение не означает реальное ожидание.

## Правила и проверяемая приёмка
6. Если оплачены интернет №7077 (7455 ₽), уплотнение №8 (22300 ₽) или перевозка №700 (16000 ₽), то сохраняется доказанный платёж; без подтверждения оказания исполнение неизвестно, складского прихода нет.
7. Если у исторического оплаченного документа нет сведений об исполнении, то он виден как «Оплачен · исполнение не уточнено»; в «Ждём поставку» попадает только подтверждённое ожидание товара. Действие «Принять на склад» не заменяет подтверждение услуги.
8. Если импорт создаёт SupplyInvoice и заявки, то это не разрешение на приёмку: в C157 складские действия запрещены. Будущие отметки исполнения должны сохранять основание, автора, дату и объём; частичное исполнение не закрывает остаток.
9. Если одна оплата отражена у счёта, то повторный импорт/ссылка на договор/акт не создаёт второй денежный факт. Документы описывают одно обязательство; стоимость не суммируется повторно по каждому основанию.
10. Если выдан возвратный залог №75176/З, то доказанное выбытие входит в движение денег, но не становится стоимостью аренды/услуги. Возврат — отдельное поступление; зачёт — связь с погашаемым обязательством, без вымышленного нового перечисления.
11. Если №3834 погашает прежний долг, то платёж уменьшает прежнее обязательство, не создавая повторную закупку/стоимость. Акт №4039 подтверждает остаток 11150 ₽, сам по себе не является денежным движением и не распределяет оплату по четырём поставкам.
12. Если распределение платежа неизвестно, то оно хранится как нераспределённое по известным сторонам/основанию; FIFO и суммы по отдельным строкам не угадываются. Оборот денег и стоимость приобретения показываются раздельно.
13. Если дата полной RUB-оплаты неизвестна, то действует выпущенный C165: подтверждение без датированного денежного факта и ложного долга. Сегодняшняя дата не подставляется; C158/C162/C165 повторно не проектируются.

## Что потребуется далее
14. Сохранить устойчивые связи: оригинал → вид/номер/дата/стороны → обязательство и его строки → оплаты и распределения → подтверждения исполнения; исправление редакции связывать с прежней, не удваивать обязательство. Каталог не заменяет снимок источника.
15. Нужны различимые смыслы из пп.1–5 и связи из п.14; конкретные поля/переиспользование существующих выбирает архитектор после проверки схем. Для продаж C164 уже подтвердил отдельные пробелы: юридические оригиналы/статус, покупатель-ID, исходящий счёт, налоговый снимок, событийный график; закупочный SupplyInvoice их не заменяет.
16. Реальные вопросы владельцу уже сохранены в C157/QUESTIONS-SOURCE.md и доступны через QUESTIONS.md: возврат/зачёт залога и основание; распределение прежнего долга, подтверждение №4686. По умолчанию — обеспечение не расход услуги, долг не новая покупка, распределение неизвестно. Новых вопросов об устройстве БД владельцу нет.
