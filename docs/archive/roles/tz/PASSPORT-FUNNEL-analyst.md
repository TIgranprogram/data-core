# ПВ — требования аналитика: паспорт «воронкой» (2026-10-25)

Опираюсь: слова пользователя (`PASSPORT-FUNNEL.md`), `docs/PASSPORTS-V2.md` (§2 нормативы, §3 справочники, §10 черновик/выпуск), `dicts.defs.ts:538–720`, `passport-v2-text.ts`, `passport-compose-parts.ts`, `passport-rules.ts`, `showcase/passport-defaults.ts`, `scripts/passport-texts.v2.json`. Прод-данные не видел: где нужен факт — «проверить на проде».

## 0. Что есть сегодня и в чём корень путаницы

Текст паспорта складывается из ТРЁХ независимых источников, и у «монтажа» три хозяина:
1. **Шаблон категории** (`passporttemplates`, сид `passport-texts.v2.json`): ALL = общие разделы (общие указания, монтаж-общий, ТО, ремонт, хранение, перевозка, гарантия, рекламации, утилизация, журналы, приёмка), у TRN/WRK/DSP/DIO/MAF — свои «правила пользования/проверки». Живёт вне «Паспорта → справочники», правится отдельно.
2. **Части из справочников по составу изделия**: элементы (описание, назначение, правила, ТО), материалы («изготовлено из», уход), дефекты (таблицы ТО), **способ установки** (`passportInstall.montage` — шаги, основание, рисунки).
3. **Готовые тексты** (`passportPhrases`): одна-две фразы «Назначение» и «Установка» (напр. «…методом бетонирования закладных деталей»). Это и есть дубль монтажа: фраза в «Готовых текстах» + шаги в «Способах установки» + общий раздел «4 Монтаж» в ALL.

Вывод: воронка уже наполовину есть (изделие хранит `passportDefaults`: категория, элементы, материалы, способ установки, числа). Не хватает: (а) единого справочника «раздел → вариант → текст», (б) выбора вариантов как шага, (в) галочек категорий там, где их нет, (г) закрытия дублей монтажа.

## 1. Воронка по категориям

Принцип: из изделия берётся всё, что там уже есть (категория, элементы, материалы, габариты, вес, числа, фото). Менеджер отвечает только на то, чего **нет в изделии** и что **не вычисляется**. Шаг показывается, только если у раздела для этой категории **больше одного** подходящего варианта; один — подставляется молча (с пометкой «выбрано само»); ноль — раздел пропускается, если он необязательный, иначе в «не хватает».

Автоматически (для всех категорий): название, артикул, габариты, масса, материалы (таблица МИ → «Изготовлено из…»), части, элементы → «Описание», «Назначение», «Правила пользования», ТО-таблицы по дефектам, фото. Все числа — из изделия; пустое обязательное → в «не хватает» со ссылкой на поле (уже есть: `missingKeyed`). Из «Для всех» подставляются без вопросов: общие указания, хранение, перевозка, гарантия, рекламации, утилизация, журналы, приёмка.

Разделы паспорта (по ГОСТ Р 2.610 и по v2): Титул · Основные сведения · Тех. данные/ограничения · Описание · Назначение · Эксплуатация/правила · ТО · Ремонт · Монтаж · Хранение/перевозка · Утилизация · Гарантия/рекламации · Свидетельство о приёмке · Журналы · Приложения (комплектность, габариты, зона безопасности, схемы).

### Выборы воронки (универсальный набор шагов; в категории показываются не все)

| Шаг | Вопрос менеджеру | Ответы (2–3) | Что за ним стоит |
|--|--|--|--|
| В1 Установка | «Как изделие крепится?» | Бетонирование стоек/опор · Анкеры к готовому основанию · Свободностоящее/на покрытие | раздел «Монтаж»: текст + требования к основанию + обязательные рисунки (`foundation`/`holes`/`mounting`) |
| В2 Основание (подвопрос В1) | только если В1 = бетонирование или анкеры | Бетонирование: в грунт · в основание под покрытием (резина/газон) / Анкеры: на бетонную плиту · на закладные | уточнение: требования к бетону/щебню/покрытию; один подвариант — подставляется сам |
| В3 Площадка (ДИО, ДСП) | «Покрытие площадки?» | Резиновое/травмобезопасное · Газон/песок · Другое (вручную) | таблица покрытий по ГОСТ 34615 и зона приземления |
| В4 Сборка | «Поставка?» | Готовое (сварное) · Разборное (на сборку) | `isKit` → раздел «Сборка» + рисунки `assembly`; по умолчанию из изделия |
| В5 Эксплуатация | «Площадка с табличкой правил?» | Табличка с правилами в комплекте · Нет | информационный стенд / пиктограммы правил (`passportStyle`) |
| В6 Сертификат | «Есть сертификат/декларация?» | Да (ввести №, срок) · Нет | знак ЕАС и идентификационные сведения печатаются только при «Да» (уже так в схеме) |

Реально для менеджера: **2–4 клика**, потому что В2–В6 в большинстве случаев берутся из изделия по умолчанию (`passportDefaults`) и показываются как «выбрано: …» с кнопкой «изменить». Спрашиваются только пустые.

|--|--|--|--|--|

## 2. Структура справочника текстов

**Один справочник «Тексты паспорта» вместо «Готовых текстов» + части «Способов установки» + шаблонов-как-файла.** Одна запись — один смысл:

`раздел → вариант → (подвариант) → текст`, поля:
- **Раздел** (выбор из фиксированного списка, который знает программа): `purpose` Назначение · `installation` Монтаж · `operation` Эксплуатация/правила · `maintenance` ТО · `repair` Ремонт · `storage` · `transport` · `disposal` · `warranty` · `claims` · `acceptance` · `custom`.
- **Вариант** (название для менеджера, коротко: «Бетонирование в грунт»), **Подвариант** (необязательно, вторая ступень, ссылка на родителя).
- **Текст** (с подстановками `{name}`, `{std:КОД}`, числа), **шаги** (по строке) — для монтажа/правил.
- **Категории**: галочки TRN / WRK / DSP / DIO / MAF + «Для всех» (ALL). Пусто запрещено: либо ALL, либо хотя бы одна. Список галочек строится из справочника категорий (сейчас код `PASSPORT_CATEGORY_CODES` зашит — новую категорию добавить нельзя без правки кода; **нужно от архитектора** — читать из справочника).
- **По умолчанию** (одна галочка на раздел+категория: подставляется сама, когда менеджер не выбирает), **Порядок**, **Обязательный раздел** (см. §4.3), **Требуемые рисунки** (только у монтажа), **Норматив** (код).
- **Условия показа**: «разборное», «есть сертификат» — переменные, не новый механизм.

Остаётся без изменений (это разные смыслы, не дубль): `passportCategories`, `passportStandards`, `passportElements`, `passportMaterials`, `passportSortament`, `passportParts`, `passportDefects`, `passportStyle`.

Сливается:
| Было | Куда |
|--|--|
| `passportInstall` (шаги монтажа, основание, рисунки, схемы) | в «Тексты паспорта», раздел «Монтаж» (варианты/подварианты). Схемы-картинки остаются как поля записи. Ссылка `installationTypeId` в паспорте и изделии сохраняется (указывает на запись; id не меняем, чтобы выданные/черновики не оборвались) |
| `passportPhrases` (section=installation) | то же — это фразы «Монтаж»; дубль «Бетонирование опорных стоек» ×4 — сводится в один вариант |
| `passportPhrases` (section=purpose) | раздел «Назначение»; но назначение элемента остаётся в элементе (`purpose`) — «Назначение» как раздел используется, когда элементов нет или нужна общая фраза категории. Правило: если у элементов есть `purpose` — берётся оно, иначе вариант по умолчанию категории |
| Шаблоны `passporttemplates` (JSON-сид, версии) | абзацы ALL и категорий становятся записями «Тексты паспорта» с разделами; версионность не нужна (снимок при выпуске уже хранит текст) — упрощаем |

Что **не** делаем: не дробим на 15 текстов на раздел — потолок на шаге воронки 3 варианта (если больше — это сигнал свести дубли).

Дубли: объединять как в справочниках (`merge`), лучший текст остаётся, остальные — в корзину. **Старые тексты не переносим** (слова пользователя); эталоны `PASSPORT-TEXTS-ETALON.xlsx` и `passport-texts.v2.json` — основа новых универсальных текстов, не старые паспорта. Прод-проверка: сколько записей `passportPhrases` непустые, сколько уникальных после нормализации (`passport-text-dupes.js`).

## 3. Правило «изделие → паспорт»

1. **Где живёт выбор:** в изделии (`products.passportDefaults`) — категория, элементы, материалы/МИ, вариант и подвариант монтажа, `isKit`, числа, срок службы, гарантия. Новое: `defaults.sections = {раздел: id варианта}` для остальных выборов воронки. Паспорт копирует их при создании («от изделия»).
2. **Создание паспорта от изделия:** всё подтягивается; чего нет — «не хватает» наверху, ведёт на поле. Менеджер правит выбор **в паспорте только для этого паспорта** (см. 3.5) или идёт в изделие (если хочет изменить навсегда). Два пути, без третьего.
3. **Клон изделия:** копируются все выборы, категория и числа; **артикул, серийные, фото — по правилам клонирования изделия**, не паспорт. После клона система предлагает «проверьте: размеры/вес/название» (в таблице нельзя оставить габариты как у оригинала молча — подсказка серым). Выпущенные паспорта оригинала не копируются.
4. **Правка справочника:** черновики (`draft`) при следующем открытии/печати пересобираются из справочника (если менеджер не правил раздел вручную; вручную правленые разделы помечены и не перезаписываются). Выпущенные (`issued`) и аннулированные — снимок `textSnapshot`, не трогаем никогда. Это уже соответствует §10 PASSPORTS-V2.
5. **Ручная правка раздела в паспорте:** переключатель «изменено вручную» (уже есть `manualText`) — остаётся; кнопка «перенести в справочник» только director/admin.
6. **Нет категории у изделия:** воронка не стартует, в паспорте красная плашка «Выберите категорию» (сейчас без категории паспорт считается v1 — **с 2026-10-23 PDF без категории даёт 400**, оставляем: категория — первый обязательный выбор). Для изделий каталога без категории — список «без категории» для массового проставления (хранитель данных).
7. **Изменился вариант в справочнике (удалён/архивирован):** выпущенные не страдают; в черновике/изделии выбор помечается «вариант удалён — выберите заново», PDF не печатается, пока нет замены.

## 4. Подводные камни

1. **Нормативы по категориям** (по `PASSPORTS-V2.md` §2, статус на 22.10; перед выпуском сверить в «Нормативах» — поле «проверено»):
   - ТР ЕАЭС 042/2017 — **только ДИО** (и ДСП детские игровые). В TRN/WRK/MAF этот документ и знак ЕАС не ставить.
   - TRN — ГОСТ Р 57538-2017 (действует, изм. 2022). Рост пользователя ≥ 1400 мм — из ГОСТ, подсказка в категории.
   - ДИО: серия ГОСТ 34614 — **по частям разные редакции** (напр. .5 → 2024 вместо 2019): ссылка по коду из «Нормативов», не вшита в текст; статус «проверить» должен давать предупреждение (механизм уже есть).
   - Ошибочный «ГОСТ Р 55674-2013» (на самом деле брусья) — убран; не вернуть при сведении текстов.
   - СНиП 12-03 — не ссылаться как на обязательный; Приказ Минтруда 883н — в тексте.
   - Мой запрос на проверку: перед запуском сидов универсальных текстов разработчик/ассистент сверяет коды из `passportStandards` со статусами в Росстандарте; результат — в `checkedAt`.
2. **Универсальный текст не должен врать.** «Бетонирование» — не подставляется изделию с анкером. Обязательно: у варианта монтажа свой набор «обязательных рисунков»; несоответствие (вариант «бетонирование», а рисунка `foundation` нет) → в «не хватает», а не молчаливый PDF.
3. **Обязательные разделы нельзя выключить:** общие указания (срок службы, запрет изменений), гарантия, хранение, перевозка, утилизация, свидетельство о приёмке; для ДИО/ДСП/TRN — правила пользования и ТО; для ДИО — идентификационные сведения. «Обязательность» хранится в записи/категории; снять её может только director, с подтверждением. Для MAF обязательны: описание, монтаж, гарантия, срок службы.
4. **Падежи и подстановки:** фразы в справочнике даны уже в нужном падеже («Изготовлено из… стальной трубы»; `genSingular/genPlural`). Универсальный текст пишем с подстановками `{name}`, `{maxUsers}`, но **не склоняем название изделия** (в тексте — «изделие»/«изделия» без подстановки имени, имя только именительным в начале). Нет значения → подстановка не должна оставить `{x}` в PDF — это ошибка выпуска («не хватает»).
5. **Общие с CRM поля:** `productpassports` и `products` общие с kppdf. Только добавлять поля (правило); `purpose` и `installationMethod` (строки) kppdf может читать — при воронке продолжаем **записывать в них итоговый текст** (из выбранного варианта) для совместимости. `PASSPORT_CATEGORY_CODES` зашит — для новой категории (подвид благоустройства) правка кода; лучше читать из справочника. Не менять и не удалять `installationTypeId` (по нему и usage, и PDF).
6. **Сид без старых паспортов:** тексты берём из эталона и сида v2; в справочник сперва — по одному варианту на раздел+категорию (чтобы воронка сразу подставляла «сама»), лишние варианты — по запросу пользователя.
7. **Скорость:** выбор варианта и сборка текста — на сервере из уже загруженных справочников (как сейчас `buildV2Text`); новых запросов на шаг не добавлять.
8. **Права:** справочник правят director/admin (как сейчас), менеджер только выбирает.

## 5. Критерии приёмки

Справочник
- [ ] В «Паспорта → Тексты паспорта» запись имеет раздел, вариант, текст и галочки категорий (в т. ч. «Для всех»). Запись без категорий не сохраняется.
- [ ] «Бетонирование опорных стоек» и «Анкерное крепление» представлены **одним** вариантом каждое; монтаж нигде больше не повторяется («Способы установки», «Готовые тексты» не хранят тот же смысл отдельно).
- [ ] У раздела+категории ≤ 3 варианта на шаге воронки; если вариант один — подставляется сам.
- [ ] Для TRN в выборе монтажа нет варианта, помеченного только DIO, и наоборот.

Воронка
- [ ] Изделие TRN с заполненными категорией, элементами, материалами, габаритами, весом → «Создать паспорт» → не больше 3 выборов (обычно 0–2) → «Проверка» без пустых обязательных → PDF строится.
- [ ] Изделие DIO без возраста/высоты падения → «не хватает: Возраст от, Высота свободного падения…» со ссылкой на поле; выпустить нельзя.
- [ ] Изделие MAF (скамья): 1 выбор (монтаж) → готовый короткий паспорт; ТО-таблиц и правил пользования нет в PDF, ЕАС и ТР ЕАЭС не упоминаются.
- [ ] Изделие без категории: воронка не открывается, показано «Выберите категорию».
- [ ] Разборное (`isKit`) → появляется раздел «Сборка» и требование рисунка `assembly`; не разборное — нет.
- [ ] Выбран «бетонирование», нет рисунка `foundation` → «не хватает: схема фундамента».
- [ ] В готовом тексте нет `{…}` и нет двойных пробелов/«;.» (проверка по PDF-тексту).

Изделие → паспорт
- [ ] Выборы воронки, сделанные в изделии, попадают в новый паспорт без повторного ввода; правка в паспорте не меняет изделие.
- [ ] Клон изделия сохраняет все выборы и числа; артикул у клона новый; выпущенные паспорта оригинала не копируются.
- [ ] Правка текста в справочнике → открытый черновик показывает новый текст (кроме вручную правленых разделов); выпущенный паспорт — прежний текст (сравнить `textSnapshot`).
- [ ] Удалён вариант, выбранный в черновике → «вариант удалён», PDF не печатается; в выпущенном — прежний текст.

Нормативы
- [ ] В TRN, WRK, MAF нет ссылок на ТР ЕАЭС 042 и знака ЕАС; в ДИО/ДСП — есть.
- [ ] Ссылка на норматив со статусом ≠ «действует» или проверкой старше 12 мес даёт предупреждение (как сейчас).
- [ ] В текстах нет «ГОСТ Р 55674-2013» и СНиП 12-03-2001 как обязательного.

## 6. Что нужно от архитектора
- Список категорий читать из справочника, а не из `PASSPORT_CATEGORY_CODES`.
- Модель «раздел→вариант→подвариант» поверх `dict_values` (родитель в записи) или расширение `passportPhrases`; судьба `passportInstall` (слить vs ссылка), совместимость `installationTypeId`.
- Где хранится выбор по разделам в изделии/паспорте (предложение: `passportDefaults.sections`) и пересборка черновиков.

## 7. Вопросы пользователю (записаны в `docs/QUESTIONS.md`)
См. П1–П4 в таблице «Открытые» — коротко: (1) набор разделов обязательных для MAF; (2) подкатегории благоустройства — отдельные категории или фильтр; (3) разрешать ли менеджеру менять «обязательное»; (4) ДСП и ДИО — оставить две категории или объединить (воронка у них почти одинаковая).
