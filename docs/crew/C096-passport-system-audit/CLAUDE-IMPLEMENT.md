## Выполнение по порядку
1. Сначала регрессионные тесты на устаревший автоматический текст и потерю ручного пункта. Используй существующие fake DB/service harness, без живых данных.
2. Выдели единый безопасный путь построения снимка черновика. Не расширяй частичные списки `textChanged` бесконечно: сравнивай детерминированный результат сборки без служебного времени с текущим содержимым. Учитывай текущие исходные поля, шаблон и справочники. Не сохраняй документ, если содержимое и производные поля не изменились.
3. Автоматический текст обновляется при открытии/печати черновика и после сохранения относящихся к тексту полей. Исключи рекурсию findById → sync → snapshot → findById. На одно действие не должно быть многократной полной сборки. Сохрани существующие кэши/пакетные чтения; не делай полную пересборку списка паспортов.
4. Ручные пункты (`edited`, `original`, ключ раздела + ключ пункта) переносить в новый снимок без изменения текста. `manualText` purpose/installationMethod тоже сохранять. Если исходный пункт изменился, сохраняй пользовательский текст и обнови базовый original согласованно, сохранив edited. Если ключ исчез/неоднозначен, не сохраняй новый снимок и не выдавай номер: понятный 409 с указанием конфликта. Старый документ и ручной текст остаются целы. Не делать молчаливый reset editedAt.
5. Смена категории при ручном снимке: не присваивать новую категорию отдельно от решения конфликта. Сначала построить и проверить перенос; при конфликте оставить паспорт прежним и дать понятную ошибку. Не откатывать изменение самого изделия.
6. Выпуск должен использовать тот же безопасный путь, без безусловной потери ручных пунктов. Выпущенные и аннулированные документы не пересобирать автоматически. Явную «Новую редакцию» и явную команду обновления текстов сохранить; изучи существующий контракт подтверждения ручных изменений, не убирай его.
7. В form.js сбрасывать st.revisionFor только после успешного PATCH. Неудача PATCH сохраняет полный повтор с newRevision=1; успешный PATCH + неудача последующего GET не должны создавать повторную редакцию.

## Обязательные проверки
- Изменить название, размер, возраст, textOverrides: автоматический текст черновика отражает новое значение, если переменная используется шаблоном.
- Изменить шаблон категории/значимый справочник: следующий просмотр черновика обновляет автоматический текст, даже без изменения passportPhrases.
- Неизменное повторное чтение: нет повторного save из-за at/порядка сериализации; отсутствие рекурсивных вызовов.
- Ручной абзац + изменение другого автоматического пункта: ручной остаётся, автоматический обновлён; выпуск сохраняет оба.
- Исчезновение ручного ключа/смена категории с конфликтом: ошибка до записи снимка/категории и до номера; исходный документ сохранён.
- Пустой источник не стирает старые сведения; собственная категория по-прежнему главнее наследуемой.
- Выпущенный паспорт не меняется при изменении изделия/справочника. Новая редакция остаётся явным действием.
- PATCH редакции падает → повтор отправляет полный payload с newRevision; PATCH успешен, GET падает → повтор не создаёт ещё одну редакцию.
- Запусти typecheck, целевые unit; затем обязательный набор по datacore-verify для затронутого кода. Полный unit по AGENTS. E2E без доступной тестовой БД — честный SKIP, не запускать на datacore.
- JS проверять как ES-модуль. Новые публичные поля/маршруты не нужны; если обнаружена необходимость — передай Codex, не меняй контракт сам.
