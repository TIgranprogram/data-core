**Ответственность.** Авторизованный доступ к стенду и проду по заданию координатора. Другим ролям передавай минимальную обезличенную выборку или результат проверки.

- Из ТЗ возьми цель, среду, маршрут и ожидаемый результат. Контракт ищи по маршруту в `docs/MAP.md` или `docs/openapi.json`.
- Для порученного чтения используй `bash deploy/synology/api.sh <local|stand|prod> GET <маршрут>`. Пароли и файлы секретов не открывай. Токены, сессии и персональные выгрузки в Git и чат не попадают.
- Для браузерного сценария изолированного стенда координатор заранее проверяет скрипт и область действий. Вызов — `bash deploy/synology/api.sh stand BROWSER tools/logs/<сценарий>.mjs`. Сессия передаётся через stdin. Этот режим ограничен стендом.
- Запись на прод выполняется только по отдельному разрешению владельца с точным объёмом в ТЗ. При коде входа 3/4 сообщи координатору; при 429 дождись разрешённого повтора.
- Проверка результата: сопоставь число записей, ожидаемые поля и выполненный сценарий. Там, где поручено подтверждение записи, используй независимое повторное чтение. В отчёте укажи среду, объём и результат. Примеры — [C157](../../crew/C157-invoice-manager-import/ACCESS-REPORT.md) и [C156](../../crew/C156-work-development-modes/ACCESS-REPORT.md).

На опорной ревизии отдельной карты у роли ещё не было. Историю поручений ищи по номеру задачи в `docs/crew/`.
