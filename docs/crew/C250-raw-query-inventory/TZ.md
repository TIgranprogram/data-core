# ТЗ C250 — Инвентаризация писателей + raw-query (без массового перевода)

**Программа:** [C246/CHECKLIST](../C246-architecture-modularity/CHECKLIST.md) · этап 4  
**Зачем:** карта реальных писателей до проектирования хозяев; безопасный хелпер отдельно от смены выдачи.  
**Класс:** M · **Проверки:** юнит хелпера; tsc; INVENTORY.md

## Что сделать (два законченных куска в одном этапе, но **не** смешивать перевод)

### A. Инвентаризация (обязательно)
Таблица `INVENTORY.md`: сервис/скрипт/админка → коллекция → чтение/запись → способ  
(`db.collection` / Mongoose-модель чужого модуля / `bulkWrite` / scripts / admin).  
Покрыть минимум: incomes, salesorders, products, materials, storageitems, stockmovements, reservations, warehouses, supplyrequests.

### B. Хелпер (обязательно, без массового перевода)
`common/raw-query.ts`: `liveFilter`, `rawFind` / `rawCount` / `rawAggregate` с `deletedAt: null` по умолчанию и `includeDeleted`. Юнит на хелпер.  
**Поведение рантайма не менять:** не переводить существующие запросы на новый фильтр в этом этапе (новый фильтр способен изменить выдачу). Образец 1–2 чтений — только если тесты явно подтверждают ту же выдачу.

## Критерии
- [ ] INVENTORY.md полный по способам записи выше
- [ ] хелпер + spec; массового перевода нет
- [ ] приложение как до этапа

## Нельзя
- Массово менять все `db.collection` / модели в одном коммите с созданием хелпера.
- Трогать данные прода.
