# C175 — доказанный случай «для пресса»
Срез C175 LIVE: вид «Тренажёр для пресса» 6af707fdc451d4c05df6a049, тип TRN, purposeLeafId=6adb5ab2edd024ba63d7f193. Назначение «Пресс» существует: «Предназначено для тренировки мышц брюшного пресса». Это section=purpose, не краткое описание.
Для этого вида нет ни одной связанной kindIds строки section=simple-description в passportPhrases-LIVE. Выбор вида поэтому не доказывает наличие готового краткого описания. UI simpleChoiceOptions берёт только server simpleDescriptionSuggestions при readiness choice, а не текст назначения.
Отдельный вид «Скамья для пресса» относится WRK; его root краткого описания существует и привязан к другому kindId. Подменять им TRN тренажёр нельзя.
Поиск «пресса» в полном C181 тексте уже находит текст назначения и WRK ветку. Поиск по имени в другом справочнике может не находить «Пресс» из-за буквального substring: морфологии нет. Утверждать точный экран/фильтр пользователя без live-снимка нельзя. Номер изделия не угадывался.
Минимальное действие: из пустого краткого описания открыть «Тексты паспорта» с exact-kind и section=simple-description контекстом, показывая человекочитаемый выбранный вид и объясняя, что назначение отдельно. Если связанной ветки нет, показать явное отсутствие с переходом в карточку выбранного вида/действием для директора; не выдавать весь справочник за подходящий набор. Менеджеру — запросить директора, либо текущие «Части изделия»/«Изменить текст».
API/подбор/бизнесданные не менять, состав не придумывать. Перед изменением контекстного фильтра согласовать узкий scope с координатором.
