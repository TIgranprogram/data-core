# C092 — КП: «Разобрать заявку» ИИ (К7) — экран

Класс: L · агентов: ≤ 4 (frontend → designer, architect) · прод: не трогать.

## Что уже есть (ветка `wip/c092-kp-intake`, коммит ae421d8d; в main пока нет)
- `GET /api/offers/intake` → `{ enabled: boolean }` — подключён ли ИИ (ключ на сервере).
- `POST /api/offers/intake` `{ text }` (до 20000 знаков) → `{ items: [{ asked, quantity, unit, variants: [изделие витрины, до 3] }], total, found }`. В базу не пишет. Ошибки: 400/503 с русским `message` («ИИ не подключён…», «ИИ сейчас занят…»). Лимит: 2 запроса за 10 с.
- Изделие в `variants` — та же форма, что у `GET /showcase` (`id, name, sku, price, colors, sizes, photo…`).

## Сделать (только `backend/pwa/sections/offers/funnel/`)
1. `api.js`: `intakeStatus()` и `parseIntake(text)`.
2. `items-step.js`, шаг «Изделия»: над поиском — кнопка «Разобрать заявку» (только если `enabled`). По нажатию — поле вставки текста (многострочное), подсказка «Текст уйдёт в ИИ Claude только по этой кнопке. Каталог и цены не отправляются», кнопка «Разобрать».
3. Пока ждём — индикатор «Разбираю заявку…» (до 90 с), кнопка неактивна.
4. Результат — список строк «как назвал заказчик · кол-во ед.»; под каждой — до 3 вариантов изделий (название, артикул, цена). Первый вариант выбран; можно выбрать другой или «Не добавлять». Строка без вариантов — «Не нашли в каталоге — добавьте поиском ниже».
5. Кнопка «Добавить выбранные (N)» — каждое выбранное изделие через существующую `add(p)` с количеством из заявки (не +1).
6. Ошибка сервера — его `message` через failBlock/hint с «Повторить»; поиск остаётся рабочим.
7. Ввод — в той же правой панели воронки (CANON). Язык менеджера, без кодов.
