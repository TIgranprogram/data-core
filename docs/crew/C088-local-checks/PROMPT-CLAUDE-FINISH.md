## Ограничения

- Рабочий стол, мышь, клавиатуру и открытые окна пользователя не трогать. Браузер — отдельный headless-процесс.
- Тестовая модель — только локальная LM Studio. Никаких облачных моделей и платных API для обхода.
- Прод, CRM, рабочую БД и чужие Docker-ресурсы не изменять. Доступ и сессии — через datacore-access штатным способом.
- Секреты не выводить, не логировать и не коммитить.
- Не перезагружать ПК и не останавливать чужие процессы. Не создавать расписаний и второго runner.
- ИИ для КП (C092) не трогать: разрешение касается только локального тестировщика C088.

## Работа

1. Проверь фактическую готовность Docker, локальной модели, её инструментов и собственного изолированного стенда. Loopback сам по себе не доказывает изоляцию.
2. Подтверди через API роль manager. Admin не заменяет менеджерскую приёмку.
3. Программно исключи внешние адреса модели и рабочие адреса приложения. При неверной конфигурации — понятный отказ.
4. Проверь обновление сессии после истечения access-токена, штатную остановку и безопасное продолжение.
5. Раздели результаты запусков: run ID, версия кода, настройки без секретов, длительность, итог и артефакты. Старые ошибки не должны делать новый успешный запуск красным.
6. Различай подтверждённый дефект сайта, гипотезу модели и сбой тестировщика. «Не смог выполнить» не означает ошибку сайта.
7. Подтверди уборку только записей собственного запуска по сохранённым ID. Не удаляй записи массово по названию.
8. Проверь сохранность uploads при обслуживании стенда. Не пересобирай стенд во время обхода.
9. Кнопки пульта: готовность → короткая проба → длительный запуск → статус/отчёт → остановить. Используй существующие команды. Обнови генерируемую справку.

## Приёмка

- Тесты затронутого кода и `tools/dc.cmd check` проходят. Если меняется backend/src или backend/test — проверки по datacore-verify.
- Реальная проба минимум 20 минут: manager, создание и сохранение через интерфейс, истечение access-токена, уборка.
- Затем восьмичасовой прогон на собственном стенде. Не объявляй завершённым до окончания. Если условия отсутствуют — укажи препятствие, не подменяй результат короткой пробой.
- Несколько находок проверь независимо по действиям, запросам и снимкам. Оцени ложные тревоги. Не исправляй сайт по одному пересказу модели.
- Восстановление после сбоя проверяй управляемо на своём процессе; реальную перезагрузку ПК не делай. Непроверенные варианты пометь явно.
