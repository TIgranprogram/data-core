# C182 — понятный выбор источника данных паспорта

**Статус:** будущее явное требование владельца, 21.11.2026. Только ТЗ; код/данные/выкладка не входят в текущее поручение. Печать №20-26 завершена; реализация планируется дома отдельным этапом. Основания: AUDIT.md, C178, ПС-05/07/09/10/12; ПС-08 остаётся отдельным открытым этапом.

## Результат для менеджера

Менеджер в редакторе видит, откуда взято значение, сравнивает доступные отличающиеся варианты и сохраняет выбранный текст **в этом паспорте**, без разработчика и без изменения изделия, договора или справочника. По умолчанию название нового generated-паспорта — `Product.name`. Сам выбор источника до сохранения меняет только образец.

## Объём

1. Обязательный первый этап: название, происхождение текущего значения, сравнение с названием связанной позиции и ручной текст; черновик и действующий issued, short/full и standalone.
2. После проверки реальных точек чтения/записи: назначение, краткое/полное описание и объект установки. Использовать существующие choices/overrides и локальное редактирование. Не предлагать источник, в котором такого поля нет.
3. Монтаж: объяснить происхождение текста, но сохранить единую применимость физического способа C179. Не разрешать текстом «бетонирование» обойти выбранные анкеры/обязательные рисунки.
4. Не входят: массовое переименование старых паспортов; изменение номеров/даты/талона; свободная замена связей и фирмы; редактирование содержимого готового PDF; новый архив; правка Inventor; автоматическое изменение исходных справочников; мобильная приёмка.

## Правила

- Для названия доступны «Из изделия», «Из позиции заказа» и «Свой текст». «Из договора» добавлять только после подтверждения отдельного фактического источника; если это тот же Income.title, один пункт с ясной подписью.
- Всегда показать фактически печатаемое значение и происхождение. При неизвестном legacy-происхождении написать «Сохранено в паспорте; источник не установлен», не угадывать по совпадению текста или manual-флагу.
- Не показывать постоянный большой selector у каждого поля. Рядом с редактируемым значением — понятное действие выбора/сравнения; конкретную форму согласует дизайнер. Равные варианты можно объединить с перечислением источников.
- Пустой/удалённый источник недоступен для подстановки с объяснением и следующим действием. Текущее сохранённое значение остаётся. Пустой Product.name не вызывает молчаливую подстановку из договора; предложить заполнить изделие либо собственный текст с проверкой готовности.
- Выбор «в этом паспорте» не обновляет Product/Income/SalesOrder/dicts. «Исправить в изделии/справочнике» — отдельный переход с проверкой прав и ясным предупреждением об области изменения.
- Выбор «Из изделия/позиции» означает явное принятие показанного актуального значения при сохранении. Issued после этого хранит снимок, а не живую подписку на источник. Поведение автоматического обновления draft и возврата с ручного режима должно использовать один согласованный resolver, а не локальные приоритеты разных экранов.
- Выдавать единый результат разрешения: значение, фактический источник, доступные кандидаты, причина недоступности/расхождения, область сохранения. Технический контракт утверждает архитектор; совместимость с текущими API/manualText/instanceManualText/choices/overrides обязательна. Новые обязательные параметры внешним клиентам не вводить.
- В issued явное действительное изменение — одна новая редакция, прежний номер; старые текст, изображения и print sources воспроизводимы. Отмена и повтор идентичного сохранения не создают лишней редакции. GET/PDF не мигрируют документ.
- Сохранение сверяет актуальность паспорта и выбранного источника. При изменении между показом и сохранением — конфликт и повторное сравнение, без частичной записи. Не терять правки другого менеджера.
- Роли и binding проверяются сервером. Annulled и ready-file не становятся редактируемым generated-паспортом. Архивные ограничения применять через существующий/будущий общий серверный guard; полную оплату и фиксацию не определять новым UI-флагом C182.

## Приёмка и регрессии

| Если | То / проверка |
|--|--|
| Product.name отличается от Income.title | Новый паспорт из изделия и обеих заказных ветвей получает Product.name; выбор позиции показывает точный альтернативный текст |
| Менеджер сохраняет своё название draft/issued | После GET/issue/PDF текст прежний; для issued номер прежний, новая редакция, старый PDF воспроизводим |
| Источники одинаковы / выбор отменён / сохранение повторено | Нет ложного расхождения, записи при отмене и лишней редакции |
| Источник пустой, удалён или связь сломана | Нет стирания/случайного fallback; объяснение и конкретный следующий шаг; повреждённые binding не обходятся |
| Источник или паспорт изменён другим пользователем | Контролируемый конфликт до записи, сохранённые данные целы |
| Выбран текст только для этого паспорта | Изделие, строка заказа, договор и справочник неизменны; второй паспорт того же изделия неизменен |
| Открыт старый issued с неизвестным происхождением | Печать/GET не меняют значение и историю; происхождение честно неизвестно |
| Меняются назначение/описание | Ручные абзацы и short/full не смешиваются; действуют прежние применимость и readiness |
| Установка ANCHORS, CONCRETE или неизвестна | Текст и схемы соответствуют одному профилю; свободный текст не снимает обязательные поля |
| Standalone без строки заказа | Недоступная альтернатива не предлагается; ручное имя работает в разрешённых старых сценариях |
| Нет роли / annulled / прикреплённый PDF / архив | Прямой HTTP не обходит запрет; объяснение соответствует реальному ограничению, без ложного обещания готового ПС-08 |

Доказательства: адресный realMongo для различных исходных строк, истории и гонки; PDF до/после; desktop-сценарий менеджера «сам выбрал источник и распечатал» со снимками. Проверить title на обложке и всех повторениях документа. Полные обязательные проверки — по datacore-verify на итоговом SHA; результаты FAIL/SKIP сохранять честно. Не заменять независимую C173 этим ТЗ.
