# Откуда взялись название и «Сечение»

| Код | В выгрузке PDM 6104 | Вывод |
|---|---|---|
| 0000.0000.0020 | Деталь, исходный лист 2 мм | Импорт сохраняет как `materials.materialKind=part`. Складской позиции при импорте не создаёт. |
| 0000.0000.1001 | Деталь, исходная труба ВГП 25×2,8 мм | Классификация и путь на склад такие же, артикул служит следом проверки. |
| SK06.070.PRSH | Метиз, `Сортамент` «Саморез констр. с прессшайбой, 6х70, Torx 30» | «Сечение» показывало текст из `assortment`. Он подходит как название при импорте имени-обозначения. |
| SHP10.D125 | Метиз, `Сортамент` «Шайба плоская, M10, DIN 125» | M10 в названии шайбы не доказывает наличие резьбы. Размер и стандарт доступны как фильтры при заполненных полях. |
| PI.0001 / PI.0002 | Покупные колпачок и заглушка, полные названия в `Сортаменте` | Покупное остаётся номенклатурой. Эти названия больше не образуют значения «Сечения». |

Источник — [дерево PDM 6104](../C057-pdm-import/samples/6104.pdm-tree.json). Для новых метизов и покупных импорт пишет обозначение в `name` и `article`, `vars.Сортамент` в `assortment`, `vars.Материал` в `materialGrade`. Прежняя воронка использовала необработанный `assortment` как «Сечение» у позиций вне ветки труб. В складском списке самостоятельного поля `materialName` нет.

- Своё имя сохраняет приоритет. Если в имени стоит обозначение, используем реальное длинное название, название из счёта или текст сортамента импортированного метиза/покупного. Название и код в отдельных полях интерфейса. Когда описания нет, остаётся известный код.
- Для труб используем профиль и размер, для листов — толщину из `dimensions`; числовые признаки прочих позиций берём из `dimensions`, стандарт — из `standardRef`. Текст M10 из названия сам по себе не создаёт резьбу.
- Прежняя смена фильтра сохраняла `open` в адресе. Изменение подбора или склада закрывает открытую из списка карточку. Входы по прямым ссылкам из журнала и каталога остаются доступны.

## Сверка карточек на локальной копии

Штатные GET списка склада и карточки материала подтвердили оба артикула. У каждого `name`, `article` и `pdmCode` совпадают с обозначением, `materialKind=fastener`, `materialGrade` — «Оцинкованная сталь». `assortment` содержит ровно те описания самореза и шайбы, которые указаны в таблице. Длинное название, название из счёта, структурированный стандарт и размеры пусты. Самостоятельного `materialName` в ответе нет.

Складской записи у обоих метизов нет. Остаток, бронь и свободное равны нулю. Общий запрос возвращает по одной позиции на артикул, а запрос с `held=1` — по нулю. Точные данные двух PDM-деталей из первых строк таблицы подтверждены по выгрузке, их карточки на копии в эту сверку не включались.
