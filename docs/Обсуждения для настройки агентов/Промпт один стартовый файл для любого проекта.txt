# Задача: пакет «старт любого проекта»

Создай в корне репо (или в docs/, если в корне нельзя) папку:

`старт любого проекта/`

Внутри — **ровно один** файл:

`СТАРТ.md`

Код продукта (backend/pwa/admin) не трогать. Новых агентов не плодить. Это не про data-core как бизнес, а **переносимый каркас**, который пользователь потом копирует в пустую папку любого нового проекта и пишет: «вот СТАРТ.md, дальше опишу продукт».

## Откуда брать смысл (выжимка, не копия простыней)
Опереться на уже настроенное у нас:
- CLAUDE.md → Автопилот, матрица S/M/L/XL, caps, ответы, лимиты
- AGENTS.md → как входить в проект, жёсткие правила-шаблоны (обобщить)
- docs/roles/README.md + TZ-TEMPLATE → роли, ТЗ, audit 1 reader
- skills/verify, design — только принципы (smoke/full; design не на мелочь)
- стиль пользователя: голос/бизнес-слова, приёмка = сайт глазами + версия
- экономика токенов: always-on короткий, sonnet, без второй «компании»

Убрать всё узкое data-core: паспорта, CRM-коллекции, release.sh-имена, пути backend/pwa — заменить на **плейсхолдеры** (`{product}`, `{app}`, `{deploy}`).

## Что должно быть в СТАРТ.md

Структура строго такая (коротко, по делу, на русском; без воды и без историй с датами):

### 0. Как пользоваться этим файлом
- Положить в корень нового проекта.
- Первый сообщение пользователя: «прочитай СТАРТ.md — это закон проекта; продукт опишу следом».
- AI создаёт по этому файлу: `CLAUDE.md`, `AGENTS.md`, `.claude/agents/` (минимум ролей), `docs/roles/TZ-TEMPLATE.md`, короткий `docs/roles/README.md` — **только когда** пользователь сказал «разверни каркас» или это первый день проекта.
- До развёртки — работать уже по правилам из СТАРТ.md (файл = always-on закон).

### 1. Роль координатора (автопилот)
- Пользователь не рулит процессом: не пишет класс/модель/@ролей.
- Пишет «что вижу / что хочу»; класс и агентов решает координатор молча.
- «Всё / подтверждаю» ≠ безлимит — только caps матрицы.
- Сначала сам; агент только если M+ и без него хуже.
- Ответ пользователю всегда 3–6 строк:
  Сделано · Выложено (версия|нет) · Глазами (2–5) · Дальше/жду только при риске.

### 2. Матрица задач
| Класс | Когда | Агентов max | Проверки |
| S | 1–2 файла, подписи, меню, явный баг | 0 | smoke |
| M | один модуль/экран | ≤2 | smoke; reviewer по делу |
| L | сервер+UI / несколько модулей | ≤4 | qa; audit 1 primary; full перед релизом |
| XL | прод-данные, схема, безопасность, новая крупная возможность | ≤5 | plan first; architect; full |

- Review loops ≤ 2.
- Аудит: 1 основной читатель; 2-й только слепая зона; никогда 3–4 на одни файлы.
- Parallel-сессия с полной «компанией» — запрещена (только отдельный scope + 1 роль, если очень надо).

### 3. Роли-шаблон (компания)
Описать компактную таблицу ролей (имя файла агента → зона → когда звать → model sonnet):
- coordinator (основной чат)
- analyst (требования, редко)
- architect (review границ/данных/безопасности, без правок кода)
- backend / frontend (или full-stack, если один стек — указать как выбрать)
- qa
- designer (только UI-паттерн/раскладка, не копирайт-мелочь)
- data-steward (опционально: скрипты данных plan → apply)

Для каждого: отчёт ≤ 12 строк, scope только из ТЗ, не коммитить сам (коммитит координатор — если так принято; иначе пометить плейсхолдер).

### 4. ТЗ (мини-шаблон)
Встроить короткий TZ-TEMPLATE:
Класс · цель · scope файлы/якоря · out of scope · shared pack · reviewers · smoke|full · max loops · контракт API если server+UI · язык для человека на экране · приёмка глазами.

### 5. Always-on vs on-demand
- Короткий CLAUDE.md (закон + автопилот + матрица).
- AGENTS.md: что за продукт, команды запуска, жёсткие запреты, карта docs.
- Длинные плейбуки — skills/docs, не в always-on.
- Не дублировать одно правило в 5 файлах.
- HISTORY/TASKS не читать целиком.

### 6. Экономия токенов (обязательные запреты)
- Не читать весь репозиторий «на всякий».
- Не звать консилиум на мелочь.
- UI-копирайт/меню/единый текст — S, сам.
- Мелочи — пачка → один release.
- Лимит >80%: только S/M, коммит/эстафета, без L/XL-агентов.
- Основной чат: sonnet-default; opus только явная развилка, лучше новый короткий чат.
- Новый чат на новую крупную тему / после тяжёлого контекста — не один роман на неделю.

### 7. Качество и приёмка
- DoD пользователя = «открыл продукт, понятно и работает» + версия сборки/выкладки если есть.
- «Язык человека»: без служебных кодов на UI, понятные заголовки, пустые состояния с смыслом.
- Секреты, wipe прод, .env — deny.
- Данные прода: только plan → показ → apply + откат.
- verify: smoke (точечно) vs full (перед релизом/XL).

### 8. Первый день на новом проекте (чеклист для AI)
Когда пользователь закинул только СТАРТ.md и описал продукт:
1. Прочитать СТАРТ.md + описание продукта.
2. Предложить (коротко) стек/структуру папок, если ещё нет — не писать тонну кода.
3. По команде «разверни каркас» — создать CLAUDE.md, AGENTS.md, .claude/agents/*.md (sonnet), docs/roles/*, минимальный README.
4. Зафиксировать в AGENTS.md: как запускать, что нельзя трогать, где доки.
5. Дальше — автопилот, мелкие итерации, без «сделаем всю платформу одним махом».

### 9. Плейсхолдеры для заполнения под проект
Список полей в начале СТАРТ.md (пустые, заполняет AI после описания продукта или пользователь):
- Название продукта
- Стек
- Команды: dev / test / lint / deploy
- Где UI, где API, где данные
- Что считается XL в этом проекте
- Как выглядит «версия выкладки»
- Кто коммитит (координатор / человек)

### 10. Запрет раздувания
СТАРТ.md должен быть **плотным**: ориентир 120–200 строк, не роман. Каждое правило — 1–3 строки. Без кейсов «как-то раз в октябре».

## Как сделать
1. Создай папку и файл.
2. Напиши СТАРТ.md целиком по структуре выше.
3. В конце СТАРТ.md — блок «Копипаст первого сообщения в новом проекте» (5–7 строк, что сказать AI).
4. Короткий отчёт сюда:
   - путь к файлу
   - число строк
   - что сознательно выкинул из data-core-специфики
   - как пользователю переносить (1–2 предложения)
Без длинных рассуждений. Без правок других правил, кроме создания этой папки/файла.
