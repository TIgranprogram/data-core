## Принятые архитектурные решения
1. Каталог и нормативный профиль не объединять физически. Категория каталога — основной выбор сотрудника, паспортный профиль наследуется через существующую связь. Собственное исключение изделия сохраняется, показывается явно. Миграции сейчас нет.
2. Изделие — источник общих характеристик. Паспорт — экземпляр, дополнительные поля и снимок выпуска. Свои поля экземпляра не блокировать под подписью «из изделия».
3. Пустое значение источника не является разрешением стереть историческое/ручное значение. До введения явного происхождения сохранять текущую политику пустых; в интерфейсе будущего этапа показывать «в изделии не заполнено», а не ложное наследование.
4. Автоматический снимок черновика должен соответствовать текущим исходным значениям. Ручные абзацы сохраняются по стабильным ключам раздела/пункта; исчезнувший или неоднозначный ключ — явный конфликт, без молчаливой потери.
5. Выпущенные паспорта автоматически не обновлять. Изменение через существующую новую редакцию; историческое оформление не нормализовать задним числом.
6. Сначала законченный этап корректности данных и сохранения (CLAUDE-IMPLEMENT.md). Далее UX, печать, карта. Codex не дублирует реализацию, проводит независимую приёмку.
