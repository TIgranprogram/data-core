## Схема и этапы

- Один локальный обработчик: выбранная папка → Inbox/Processing/Question/Ready; журнал, SHA, устойчивый UID и восстановление. Исходные файлы сохраняются.
- Локальная модель только извлекает предложение с цитатами. Исполнитель проверяет его и работает через существующие C164 API. Неизвестное и неоднозначное — исключения, а не придуманные факты.
- Первое сквозное покрытие: PDF договоров и КП через действующие защищённые C164 маршруты. Для RUB-счетов поставщика добавляется атомарный серверный импорт по SUPPLIER-IMPORT.md; валютные и неизвестные форматы остаются честными исключениями. Не выдавать извлечённый текст за завершённую загрузку.
- Загрузка оригинала: отдельный устойчивый UID/SHA, серверная квитанция и чтение для reconcile. Старый upload не менять по смыслу. Перед повтором всегда сверять исход и байты.
- Интерфейс пульта: папка, локальная модель, явный адрес контура, вход менеджера без сохранения пароля в журнал; Разобрать / Отчёт / Возобновить. Без автоматического переключения адресов/модели.
- Завершение: независимое чтение сущности, строк и оригинала; Ready только при совпадении. Права модели не включают API или shell. Старые документы не перезаписывать.

## Границы исполнителей

- backend: только backend/src/modules/photos и адресные backend/test; устойчивый upload/read-proof. Не трогать pult и tools.
- engine: tools/document-intake, тесты рядом; очередь, извлечение, модель, проверка, API C164 и CLI. Не трогать pult/backend.
- pult: pult сервер/экран/каталог/тесты/доки; engine через согласованный интерфейс. Не трогать backend и engine.
- координатор: интеграция контрактов, общие документы, приёмка, коммиты, push и выпуск после проверок.
