- Стек, контракт API, guard'ы, плагины soft-delete/аудита (05 «Устойчивые решения»).

## Последовательность и зависимости

1. **Неделя 1 — защита (п. 1–4).** Не зависит от решений, кроме пароля и места копии (владелец). Риск необратимой потери — выше любой функции.
2. **Неделя 1–2 — внедрение и КП (п. 5–6).** Параллельно с защитой; нужны 2–3 часа владельца на сценарии.
3. **Неделя 2 — данные (п. 7).** Пункты в «Требуют заполнения» уже есть — нужна дисциплина, не код.
4. **После решения владельца — CRM (п. 8).** Зависит от ответа «нужна ли CRM».
5. **Постоянно — темп и процесс (п. 9–10).**
6. **Потом** — производство, мобильный склад, PDM, роль «Мастер», офлайн: только когда метрики п. 5 покажут, что текущими разделами пользуются.

## Как проверять каждый этап

| Этап | Критерий готовности |
|--|--|
| Защита | акт учебного восстановления (время, сверка числа записей); копия вне дома открывается ключом; пароль сменён; `/uploads/<файл>` без входа → 401 или имя неугадываемо; страж прав красный при снятом декораторе |
| Перезапись | e2e: две параллельные правки заказа → вторая получает 409 |
| Внедрение | журнал: ≥ 4 не-админа активны каждую неделю; директора открывают сводки |
| КП | ≥ 5 КП в неделю; есть заказы с `offerId` |
| Данные | «Требуют заполнения» по деньгам → 0 |
| Выкладка | 0 расхождений «тег ≠ код на сайте» за 2 недели |

## Что отложить до доказательств

- Второй сервер с автоматическим переключением — пока не проведено восстановление основного.
- Новые разделы (C050, C051, C057-дальше) — пока нет роста использования текущих.
- «AI Knowledge Engine» из `db_ai/план развития.txt` (PostgreSQL + pgvector + Celery + Ollama): у проекта уже есть MAP, atlas, `dc find/doc`, MCP-сервер. Новый отдельный продукт — ещё одна система на одного владельца. Сначала измерить, где агентам реально не хватает знаний.
- Единый слой сырых запросов (885 вызовов) — большой рефакторинг без видимой пользы пользователю; делать по частям при правке модулей.

## Рискованные изменения

- Массовые миграции данных на проде без восстановления под рукой.
- Остановка CRM без проверки, кто ей пользуется.
- Рефакторинг общих с CRM коллекций, пока CRM пишет напрямую.
