# C011 — аудит бизнес-логики «Рабочего места» (2026-11-03)

Код не менялся. Правки — `FIX-TZ.md`. Файлы — `INVENTORY.md`.

## 1. Резюме

- Пользователи: владелец (admin) и менеджер (снабженец, кладовщик, офис). Телефон кладовщика — отдельный сценарий «Склад (телефон)».
- Канон цепочки: заявка (`supplyrequests`, снимок `title`) → счёт (`supplyinvoices`) → «Принять» (`SupplyService.receive`) → остаток (`materials` + `storageitems`) → бронь / выдача → заказ (`salesorders` + позиции `incomes`) → проектирование (`designtasks`) и «В работе» (`worktasks`) → паспорт с изделия → отгрузка (`shipments`) → деньги считаются из оплат, отдельной кассы нет.
- Покупное — `materials`. Каталог поставщика — цены, не вторая номенклатура. Изделие — `products`. Прайс не пишется в поля CRM `pricePerUnit` / `supplierId`.
- «Оплачено» у заявки — это `status=ordered` и флаг `paid`, не отдельное значение в схеме. Этапы заказа: Новый → В производстве → Готов к отгрузке → Частично → Отгружен → Закрыт.
- Запрещено: вторая номенклатура, правка общих с CRM enum статусов, удаление коллекций, офлайн-очередь (сайт без связи не сохраняет).
- Уже не дыры (старые аудиты устарели): запрет правки позиций с «Готов к отгрузке» есть (`incomes.service.ts:283`); календарь берёт `paidAt`, затем дату счёта (`finance.service.ts:18,86`).
