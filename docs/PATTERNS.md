# PATTERNS — паттерны поведения «Рабочего места»

> Паттерн поведения — как экран ведёт менеджера к цели. Вид (цвета, компоненты) — `docs/DESIGN.md`; здесь — **порядок вопросов и логика**. Новый экран выбора или ввода сначала сверяется с этим файлом.

## П-1. «Воронка с памятью» (эталон — создание паспорта, C028, принят пользователем 2026-11-07)

**Суть одной строкой:** экран сам ведёт сверху вниз — сначала отсекает лишнее, потом спрашивает только то, чего не хватает, и запоминает ответ там, где он живёт, чтобы второй раз не спрашивать.

Известные близкие названия: guided selling (воронка подбора), progressive disclosure (раскрытие по шагам), faceted narrowing (сужение по признакам). Наш паттерн добавляет к ним **память** и **подсказку следующего шага**.

### 7 правил (все обязательны)

| № | Правило | Как в паспорте | Анти-пример |
|--|--|--|--|
| 1 | **Сверху вниз, от широкого к узкому.** Первый шаг отсекает больше всего. | Категория → Группа → признаки → Изделие | Сразу поле «Найдите изделие» среди 483 |
| 2 | **Каждый шаг сужает следующий.** Значения — только те, что есть в срезе, с числом рядом. Пустых значений нет. | «Силовой (61)», «Кардио (19)» | Список всех значений справочника |
| 3 | **Пропускать очевидное.** Одно значение в срезе или ответ уже известен — шаг не показывается. | Группа у тренажёров одна — шаг пропущен | «Выберите группу: Тренажеры» из одного пункта |
| 4 | **Спрашивать только пустое.** Всё, что выводится из уже выбранного, подставляется само. | Элементы — из признака; срок службы — из категории | Повторно выбрать категорию в форме |
| 5 | **Запоминать в источнике.** Ответ пишется туда, где живёт (в изделие, договор, контрагента), а не в одноразовую форму. | Признаки и умолчания паспорта — в изделие | Ответ остаётся только в черновике паспорта |
| 6 | **Подсказывать, а не заставлять.** Угаданный ответ — одной кнопкой «Похоже: … — верно?»; подставленное помечено, ручное главнее. | «Похоже: Ноги и ягодицы — верно?» | Молча записать угаданное |
| 7 | **Всегда видно, где ты и что дальше.** Пройденный шаг — строка «Категория: … ✎» (можно вернуться), над шагами — «Дальше: …», в конце — одна главная кнопка. | «Дальше: укажите способ установки» → «Выпустить PDF» | Длинная форма без подсказки, что заполнить |

### Как сделать на новом экране (чек-лист)

1. **Данные.** Есть ли иерархия (раздел → группа) и признаки, которые делят объекты? Нет — сначала аналитик: какие признаки реально делят **наши** данные (числа по выгрузке прода). Признаки — справочник, правит пользователь.
2. **Сервер.** Один маршрут среза: по выбранному отдаёт шаги со значениями и числами + список объектов (как `GET /passports/funnel`). Второй — «чего не хватает» объекту (как `GET /showcase/:id/passport-gaps`): только пустое, с умолчаниями и подсказкой.
3. **Память.** Решить, куда пишется каждый ответ (поле объекта-источника). Повторный проход того же объекта начинается с последнего шага.
4. **Экран.** Только эталоны kit: правая панель (`entityPanel`/`panel`), шаги — `funnel` (kit), выбор — `pick` (длинный список — combo с поиском, не стена меток), объекты — `table`/`row` с фото, блоки — `section`, пусто — `empty` с подсказкой.
5. **Выход.** Одна главная кнопка в конце. Не хватает — рядом список, что осталось, со ссылкой на шаг.
6. **Проверка.** Сценарий на стенде: путь от первого шага до результата не длиннее, чем было вручную; повторный проход того же объекта короче первого.

### Вид — эталон kit funnel

`funnel({ steps, onChange(key, value), next?, recent? })` из `ui/kit/` (`funnel.js`, витрина #kit). Шаг: `{ key, label, value, values:[{id,label,count,thumb?}], multi?, skip?, optional? }`.
- Экран хранит выбранное сам: в `onChange` обновляет `value`, сбрасывает нижние шаги, зовёт `update({ steps })`; пустое value — вернуться к шагу (✎).
- Следующий шаг не виден, пока не выбран предыдущий; `skip` или одно значение — шаг пропущен; `optional` — шаг не задерживает следующих (признаки).
- ≤ 7 значений — вкладки с числом, больше — список с поиском (сам); `multi` — фишки с галочками.
- «Дальше: …» — от первого невыбранного шага или `setNext(текст)`; `recent` / `setRecent([{title,meta,onClick}])` — «Недавно: …»; `update({done:true})` — остаются только строки пройденного.
- Примеры: `passports/funnel/pick-steps.js`, `stock-ops-pick.js`.

### Когда НЕ применять

- Выбор из 3–7 вариантов — хватит обычного выпадающего списка.
- Ввод свободного текста (примечание, описание).
- Экран просмотра, где менеджер ничего не выбирает.
