# C164 — UI: применимость и приёмка

Frontend ownership: backend/pwa/** и backend/admin/**; сервер/общие проектные документы не меняются этой ролью. CONTRACT.md обязателен до вызовов новых API. Используем существующий orderCard/positionsTable/screenCard, kit.section/stack/warnCard/readonly/actions/buildForm. Нового CSS/визуального варианта не требуется.

| Контекст | Показывать/спрашивать | Источник и приоритет | Сохранение |
|--|--|--|--|
| Договор без заказа | Номер/дата документа, компания, покупатель; объект может быть пустым | Исходник и ручное подтверждение; юридический адрес не объект | SalesOrder и типизированный профиль по CONTRACT; productionNo пустой |
| Строки договора | Исходное название/размер/количество/единица/цена; «Не сопоставлено» | Оригинальная спецификация; каталог только ручным действием | Income source snapshot отдельно productId |
| КП с исключением | Все исходные строки, исключённая строка отмечена; исходная и согласованная сумма | Оригинал17.11 + решение владельца20.11, дата исключения неизвестна | Offer history/source profile; не править исходныйPDF |
| Неизвестные сведения | Список причин и конкретный «Заполнить» | Review issues; не заменять неоплату/неподписанность отрицанием | Заполнение поля закрывает только соответствующий пункт |
| Оригиналы/исходящий счёт | Вид, дата, номер, редакция, файл | Typed ownership; существующий file ID | Не прикладывать комплект к первой позиции |
| Привязка к производству | «Без заказа» → «Привязать к заказу» | Менеджер выбирает новый/существующий заказ | Несколько договоров, без копирования строк/ID |

## Матрица приёмки

1. Заполненные44/45/46:19строк,3шапки без productionNo/оплат/автомэтча. Обе темы1920/1024. Таблица первой, warning под таблицей; список/карточка/правая форма/reopen.
2. КП17.11:9исторических строк,6я исключена,3131000₽ исходно/2061000₽ согласовано. Предпросмотр и оригинал, дата ввода отдельно. Несопоставленное ручное действие не меняет цену/исходное название.
3. Поле неизвестного адреса пустое, заметка видна; «Заполнить» открывает конкретную правую форму. Отмена ничего не пишет. Ручная правка сохраняется и видна после reopen.
4. Очередь «Без заказа»: выбрать два договора→один заказ; до сопоставления понятная причина блокировки, если это правило сохраняет backend. Без догадок о productionNo.
5. Документ: загрузка PDF и reopen без дубля, открытие файла, корректное длинное имя, noMoney/readonly роли без финансовых утечек.
6. Ошибка409 не скрывает сохранённый черновик и не повторяет мутацию; повтор исходного пакета по stable UID не дублирует документ/строки.

Внешний исполнитель UI-сценария — access через reviewed stand script, без авторизации в файлах/отчёте. Макеты/код не означают PASS. Итоговые доказательства — UI-REVIEW.md, открытые PNG + сохранение/reopen.
