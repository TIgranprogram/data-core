Я — исполнитель (не координатор), правила — CLAUDE.md / AGENTS.md проекта. Задача C064: паспорт изделия в PDF выглядит плохо, когда у изделия не заполнены часть данных (вес, габариты, возраст, рост, гарантия, рисунки, материалы, конструкция). Найти и починить, как печать обходится с пустыми значениями.

1. Где смотреть: сборка текста `backend/src/modules/product-passport/passport-v2-text.ts`, `passport-compose*.ts`, PDF — `passport-pdf*.ts`, общие правила печати — `backend/src/common/print/` и `docs/traps.md` «Печать документов» (в PDF не уходят `{…}`, `undefined`, `null`). Подстановка переменных `{weightMax}`, `{maxUsers}` и т. п. — найти grep «не заполнено».
2. Собрать 5 «плохих» случаев на тестовой базе (`datacore-test`, e2e-харнесс) или юнит-тестом сборки текста: изделие без веса и габаритов; без возраста/роста; без рисунков; без материалов; без конструкции. Для каждого — какой текст получается (предложение с пустым числом, «[… не заполнено]», висящие запятые и двоеточия, пустые таблицы/заголовки разделов, пустые места под рисунки).
3. Правило починки: предложение, в котором переменная пуста, не печатается целиком (а не «[… не заполнено]» в выпущенном паспорте); пустой раздел/таблица/рисунок — без заголовка и без пустого места; в ЧЕРНОВИКЕ (предпросмотр) — заметная пометка, что не заполнено, чтобы менеджер видел. Выданные паспорта не перепечатывать.
4. Тесты: юнит на каждый случай (текст без «undefined/null/{…}/[… не заполнено]»), существующие passports-тесты зелёные, `tools/dc.cmd check` зелёный, e2e passports.
5. Не трогать данные прода, не выкладывать. Коммит только своих файлов, метки по CLAUDE.md. Отчёт ≤ 15 строк в `docs/crew/C064-passport-pdf-gaps/REPORT.md`: было/стало по 5 случаям, файлы:строки, что не проверено глазами.
