# ТЗ C084 — «Доходы и расходы» в виде для директора

> Аудит — `AUDIT.md` рядом. Исполнитель читает только это ТЗ и перечисленные места. Отчёты — `backend.md`, `frontend.md`, `designer.md`, `qa.md` в этой папке.
> Задание можно отдать другому ИИ целиком: этапы независимы, у каждого свой чек-лист.

**Зачем (словами владельца):** «чтобы директору очень понравилось: компактная таблица, нажимаешь — раскрываются списки по статьям; строка выделяется; внизу результат, который складывается с предыдущим».
**Зачем — глаголом:** директор открывает «Деньги» и за 10 секунд видит доходы, расходы и результат года; за 2 нажатия доходит от статьи до конкретного счёта.

## Глубже
- **Результат:** вкладка «По статьям» заменяет директору таблицу Excel и даёт то, чего в Excel нет: раскрытие, подсветку, доли, переход к счёту.
- **Сырьё:** прод 11.11 — `tools/logs/c084-1-by-articles-2026.json` (3 статьи, 10 подстатей, 12 операций без статьи, доходы 0). Проверять и на стенде с данными, и на пустом годе (2025).
- **Метод профи:** отчёт о движении денег с раскрытием (drill-down): сверху итог, глубже — причина; не больше 3 уровней; на экране не больше 25 строк без прокрутки.
- **Внешний судья:** юнит `by-articles.spec.ts`; `node --input-type=module --check`; `dc audit` (обход экрана `#money`); приёмка `datacore-designer` по стенду.
- **Смелая планка:** раскрытие строки < 100 мс без запроса к серверу; от статьи до счёта — 2 нажатия; 0 прыжков страницы.

**Класс:** L · **Max agents:** 4 · **Reviewers:** qa ☑ architect ☐ designer ☑ · **Max review loops:** 2 · **Проверки:** smoke; full перед выкладкой
**Язык менеджера:** да · **Приёмка:** сайт глазами — «Деньги → По статьям»: раскрыть статью, нажать сумму, переключить «Кварталы», раскрыть «Доходы».

## Shared pack
- Решения координатора: только факт, плана нет (владелец, 06.11). Доход — по дню платежа, расход — по дню оплаты. Адрес вкладки и параметры не меняются. Новых вкладок нет.
- **Контракт (добавки, старые поля не трогать):**
  - `GET /api/finance/by-articles` → новое поле `incomeRows`: `[{ id: 'cp:<имя>', name: <заказчик | «Заказчик не указан»>, level: 1, values: number[12], total, pct /* доля от всех доходов */, children: [{ id: 'ord:<doc>', name: <«заказ 123» | «Без заказа»>, level: 2, values, total }] }]`, сортировка по `total` убыв.
  - Там же: у **каждой** подстатьи `children: Leaf[]` (контрагенты), если контрагентов ≥ 2 или единственный — не «Контрагент не указан». Сейчас — только у «Субподрядных работ».
  - Там же: расход, у которого `articleId` — статья верхнего уровня, идёт в эту статью строкой-подстатьёй `{ id: '<id статьи>:self', name: 'Без подстатьи' }`, а не в `unassigned`.
  - `GET /api/finance/by-articles/ops`: `articleId` принимает `<id статьи>:self`; новый необязательный `counterparty` (точное имя; `Контрагент не указан` / `Заказчик не указан` — пустое) — фильтр на сервере; необязательный `doc` — для строки заказа в доходах.
  - `GET /api/finance/summary` → новое поле `expensesByArticle: [{ article, total, byCompany }]` (статьи верхнего уровня + «Без статьи»), сортировка по `total` убыв. `expensesByCategory` остаётся.
