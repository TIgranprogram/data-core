# ТЗ ОТГ/ОП — очередь паспортов, отгрузки, история заказа (XL, аналитик, 2026-10-28)

**Зачем (пользователь):** «Не пропустить паспорт и сдать вовремя». «Отгрузить весь заказ или часть, остаток виден, всё в истории: что, когда, сколько, кто, почему».
Свои коллекции: `salesorders`, `incomes`. Общая с CRM: `stockmovements` — общая (не трогаем). Паспорта (`productpassports`) — только новое необязательное поле.

## Что есть сейчас (факты из кода)
- Этапы заказа: `common/text/order-key.ts:8` — `new, production, ready, shipped, closed, cancelled`. «Отгружен» есть, ставится руками. Своего учёта отгрузок нет.
- Позиция заказа = `incomes` (`qty`, `shipDate` кэш шапки, `productId`). Срок — `salesorders.shipDate`.
- Проектирование: `design-task.schema.ts` — `incomeId`, `status` (queue/work/done/paused), `completedAt`.
- Паспорт: `product-passport.schema.ts` — `salesOrderId:163`, `productId:59`, `readiness:69` (ready = выпущен, notReady = черновик, rework). Привязки к позиции (`incomeId`) НЕТ.
- `issuedByLine` в карточке заказа — выдача материалов со склада под позицию. Это НЕ отгрузка заказчику; не смешивать.
- История: `/audit-logs/record` — изменения одной записи; `/audit-logs/app` — общая.

## А. Очередь паспортов
**Правило попадания (позиция `income`):** заказ не `closed/cancelled`, не удалён; у позиции есть `productId`; есть задача проектирования по `incomeId` со `status=done`; нет паспорта этой позиции с `readiness=ready`.
- «Паспорт этой позиции»: новое поле `productpassports.incomeId` (необязательное, data-core). Для старых паспортов — запасное правило: `salesOrderId` = заказ И `productId` = изделие позиции.
- Подстатус в строке: «нет паспорта» / «черновик» / «доработать» (rework).
- Сортировка: `salesorders.shipDate` по возрастанию (пусто — в конец), затем приоритет заказа, затем `completedAt`.
- «Горит»: до отгрузки ≤ 3 дней (как СГД-1.2) или просрочено — красная метка.
- Позиции без проектирования не попадают (вопрос ОП-1).

**API:** `GET /passports/queue?limit&search&due=overdue|soon|all` → `{items:[{incomeId, orderId, orderNo, customer, lineNo, title, productId, productName, shipDate, priority, designDoneAt, passportId|null, passportState:'none'|'draft'|'rework', hot}], total, counts:{none,draft,rework,hot}}`. Только чтение, без денег.
`POST /passports` и создание из очереди принимают `incomeId` (подставляет заказ, изделие, фото модели — фото из `design`/изделия).

**Где показать:**
1. «Документация» — первая вкладка «Нужно сделать» (таблица из очереди, кнопка «Сделать паспорт»).
2. «Сегодня» — карточка «Паспорта к сдаче: N (горят: K)» → ведёт во вкладку.
3. Карточка заказа — бейдж у позиции «Паспорт: нужен / черновик / готов»; в шапке — «Паспорта 2 из 5».

## Б. Отгрузки
**Модель — своя коллекция `shipments`** (soft-delete, audit):
`{ orderId, number ("ОТГ-<№заказа>-<n>", счётчик), date, lines:[{incomeId, title, unit, qty>0}], who (userId + имя), reason? (почему частично), note?, docNo? (УПД/ТН поставщика-перевозчика), receiver? (кто принял), createdAt }`.
- Остаток позиции = `incomes.qty − Σ shipments.lines.qty` (по неудалённым отгрузкам). Хранить не нужно — считать.
- Нельзя отгрузить больше остатка → 400 «Осталось N». Позиция без `qty` — отгрузка не разрешена, подсказка «укажите количество».
- Этап заказа автоматически: первая отгрузка → новый этап `partly` «Частично отгружен»; остаток 0 по всем позициям → `shipped`. Отмена (удаление) отгрузки → этап назад (`partly` или прежний `ready`). Ручной `closed/cancelled` не трогаем. Новый этап — добавить в `ORDER_STAGES`, счётчики, фильтры, подписи (вопрос ОП-2).
- Склад не списываем (готовое изделие не на складе) — вопрос ОП-3.

**API:** `GET /salesorders/:id/shipments` (список + `remaining:[{incomeId, qty, shipped, left}]`); `POST /salesorders/:id/shipments` {date, lines, reason?, note?, docNo?, receiver?}; `PATCH /shipments/:id` (note, docNo, receiver, date); `DELETE /shipments/:id` → корзина + пересчёт этапа; `POST /shipments/:id/restore` (проверка остатка); `GET /shipments/:id/print` → PDF. Права: читать — все; создавать/отменять — admin/manager. Обновить `openapi.json`, `MAP.md`.

**Печатная форма (А4, ч/б, одна страница на ≤ 25 строк):** шапка — наша компания заказа (название, ИНН, адрес, телефон); «Накладная на отгрузку № … от …»; заказ № и дата; заказчик (название, ИНН, адрес доставки/контакт); таблица: № / наименование / артикул / ед. / кол-во в заказе / отгружено сейчас / остаток после; итого штук; примечание и причина; подписи «Отпустил ____ / ФИО», «Принял ____ / ФИО», дата, М.П. Это внутренняя форма, не замена УПД/ТОРГ-12 (вопрос ОП-4).

**Экран:** в карточке заказа кнопка «Отгрузить» → правая панель: строки позиций с остатком > 0, поле «Сколько» = остаток, галочка у строки, «Всё» / «Ничего»; дата (сегодня), причина (обязательна, если отгружается не весь остаток), примечание, № документа. «Отгрузить и напечатать». В позиции — колонка «Отгружено 5 из 15». В карточке — блок «Отгрузки» (номер, дата, кто, строк, печать, отменить).

## В. История заказа (единая лента)
- `GET /salesorders/:id/history?type=change|line|design|passport|shipment|payment|stock&search&from&to` → `{items:[{at, type, who, title, text, link}]}`, новые сверху.
- Источники: audit по заказу и его позициям (`incomes`: изменения, оплата = смена `paidDate`/`status`), `designtasks` по orderId/incomeId (создана, статусы, done), паспорта заказа (создан, выпущен, rework), `shipments` (кто, сколько, почему), выдачи склада (`stockmovements` по `salesOrderId`, только чтение).
- Деньги в тексте — только денежным ролям. Закрытый раздел роли — его события не показывать.
- Экран: вкладка «История» в карточке заказа: поиск по тексту, чипы по типу, период.

## Г. Этапы работ
1. ОТГ-1 backend: `shipments` + API + авто-этап + `partly` (architect — до кода: этап и счётчики).
2. ОТГ-2 печать PDF (через `document-render`). 3. ОТГ-3 экран отгрузки (pwa, designer).
4. ОП-1 поле `incomeId` в паспорте + `/passports/queue`. 5. ОП-2 вкладка, карточка «Сегодня», бейджи.
6. ИСТ-1 `/history` + вкладка. 7. qa: юнит + e2e, full перед выкладкой.

## Критерии приёмки
1. Если позиция с изделием, проектирование done, паспорта нет — то она в «Нужно сделать»; выпустили паспорт — пропала.
2. Если два заказа с отгрузкой 30.10 и 05.11 — то 30.10 выше; до отгрузки ≤ 3 дн. — метка «горит».
3. Если паспорт в черновике или rework — то позиция в очереди с подписью «черновик»/«доработать».
4. Если урн 15, отгрузили 5 — то в позиции «Отгружено 5 из 15», в окне по умолчанию 10, этап «Частично отгружен».
5. Если ввести 11 при остатке 10 — то ошибка «Осталось 10», ничего не записано.
6. Если отгружен остаток по всем позициям — то этап «Отгружен» сам.
7. Если отгрузку отменили — то остаток вернулся, этап пересчитан, в истории запись «отменил, кто, когда».
8. Если нажать «Печать» — то PDF ч/б с шапкой, заказчиком, таблицей и подписями; номер и дата совпадают с карточкой.
9. Если в истории выбрать «Отгрузки» и ввести «урна» — то видны только отгрузки с урнами: дата, кол-во, кто, причина.
10. Если роль без денег — то в истории нет сумм оплат.
11. CRM: схемы `stockmovements`, `materials` не изменены; паспорт с новым полем читается CRM без ошибок.

## Риски
- Новый этап `partly`: фильтры active/done, «Сегодня», sheets-sync (лист «Заказы» может перетирать этап) — проверить architect.
- Старые паспорта без `incomeId`: запасное правило может дать ложное «готово», если в заказе два одинаковых изделия.
- Отгрузки, сделанные до внедрения: заказы уже в `shipped` без `shipments` — остаток не считать, показывать «отгружено до учёта».
- `incomes.qty` пустой у части строк из листа — отгрузка блокируется.
- Вопросы ОП-1…ОП-5 — `docs/QUESTIONS.md`.
