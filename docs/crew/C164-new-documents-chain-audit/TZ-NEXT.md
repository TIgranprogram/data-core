# C164 — требования следующей доработки

Статус: подготовлено по аудиту, разработка не начата. Это продолжение поручения владельца; неизвестные сведения о конкретных сделках перечислены отдельно в QUESTIONS-SOURCE.md. Архитектуру согласовать с существующим SalesOrder, не создавать параллельный второй договор.

## Обязательное поведение

1. Сохранить договор покупателя без назначения производственного заказа. Явное действие «привязать к заказу» выполняется позже; после него сохраняются ID, денежные связи и история. Старый автоматический режим создания не ломать для существующих клиентов API.
2. Стабильные ссылки на нашу компанию и покупателя по ID, исходные юридические реквизиты сторон снимком. Покупатель не определяется только свободным текстом. Переименование контрагента не меняет юридическую редакцию договора.
3. Юридический оригинал и редакции: вид, номер, дата, валюта, НДС и способ включения, суммы строк/итогов, связанные PhotoDoc ID, sourceSHA, автор/время, статус и основание подписания. Исправленная редакция сохраняет прежнюю и причину. Не менять PDF или доказанный текст автоматически.
4. Исходящий счёт покупателю связывает договор и строки спецификации. Отдельно хранить номер/дату/итог/НДС/оригинал и статус документа; повторная обработка SHA или бизнесключа не создаёт дубль. Счёт не создаёт денежное поступление сам по себе.
5. План оплаты: процент/сумма этапа, база расчёта, событие начала срока (подписание, зачисление аванса, уведомление, приёмка), срок/календарный способ расчёта. Событие неизвестно — дата не вычисляется из даты шапки. План отличается от подтверждённых банковских фактов; частичные поступления/возвраты/распределение сохраняются отдельными фактами с историей.
6. Объект, доставка, монтаж, договорный срок и фактическое исполнение разделены. Возможны два договора в одной производственной группе и договор без группы; объект не подставляется из юридического адреса. Спорные условия видны как «требует проверки» с исходными значениями.
7. Конверсия КП сохраняет компанию/покупателя/объект/условия/налоги/исходные файлы и выбранную редакцию; отличающийся состав нельзя незаметно объединить. Без принятия КП сохраняется предложением.
8. Отчётная цепочка: компания → покупатель → договор → счёт/позиции → поступления/распределения → заказ/объект при наличии. Фильтры «Все», «Без привязки», конкретный договор/заказ; итоги не умножаются из-за нескольких документов/связей. Ограниченные права маскируют суммы во всех новых ответах.
