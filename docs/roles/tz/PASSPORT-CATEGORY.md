# PASSPORT-CATEGORY — категория паспорта у изделия (анализ по коду, прод не смотрели)

## Причины
1. «Воркаут» в окне паспорта. Цепочка `backend/pwa/sections/passports/product-block.js:113`:
   `d.passportCategory (products.passportDefaults) || full.passportCategory.code (справочник) || p.ppCategory || categoryByName(name)`.
   - Справочник у скамьи не сработал (карточка пишет «не найдена»), значит «WRK» пришёл либо из `passportDefaults.passportCategory` (самый сильный источник), либо из `categoryByName` (`models.js:66-73`, регулярки по названию, WRK стоит раньше BLG).
   - Главная версия: изделие создано из старого паспорта (`showcase-from-passports.ts:101-105` копирует `passportCategory` паспорта в `passportDefaults`) или сохранено флажком «Запомнить» (`passports/form.js:207`). Паспорт тогда был с «Воркаут» (старые категории → `OLD_TO_V2`, `dialogs.js:113`) — остаток «паспортов: 1».
   - Не проверено (нужен прод): `products.passportDefaults` этой скамьи и полное название изделия. Название «Скамья парковая» по регуляркам даёт BLG; если в названии есть «брусь/стенк/ворот/кольц…» — WRK.
   - Плохо по сути: явно сохранённая категория изделия молча перебивает связь «группа → категория», хотя пользователь её не выбирал.
2. Подсказка «не найдена». `showcase.service.ts:205` → `passportCategoryFor` (`form-values.ts:39-46`): ищет название группы, затем раздела в тексте `catalogNames` (через запятую) каждой записи справочника `passportCategories`. У «Скамьи» и «Оборудование для благоустройства территории» нет ни в одной записи. Текст подсказки `products.js:338-339` не называет, что искали, и ведёт в глубокий справочник. Дополнительно: `passportDefaults` не учитывается в этой строке карточки (показывается только справочная связь), поэтому карточка и окно паспорта расходятся.

## Справочники: дубли?
Не дубли, а две оси: каталог (`categories`: раздел → группа, ~оборудование; десятки значений, у каждой — номер группы/артикул) и 5–6 кодов паспорта (ALL/TRN/WRK/BLG/DIO/DSP — определяют шаблон текста, поля, картинки). Связь многие группы → одна категория паспорта. Сейчас она есть, но спрятана: текстовое поле `catalogNames` у категории паспорта (обратная карта «в обратную сторону», ввод вручную, опечатки, незаметно).
Решение: явное поле «Категория паспорта» у группы каталога (`categories.passportCategory`, код), наследование: изделие → (своя `passportDefaults`, только если задана ВРУЧНУЮ) → группа → раздел → пусто. `catalogNames` оставить как запасной источник на переходный период, затем убрать из формы. Выбор в «Каталог / Категории» (одно место), не в справочнике паспортов. `categoryByName` (регулярки) убрать из пути подстановки: угадывание по слову — источник ошибок; допускается только как подсказка «возможно: Благоустройство» без автоподстановки.

## Новая подсказка (карточка изделия, `products.js:338`)
- Не найдена: «У группы «Скамьи» не задана категория паспорта. Выберите её в «Продукция → Категории» (строка группы, поле «Категория паспорта»)». Если группы нет: «У раздела «…» …».
- Изделие переопределяет: «Категория паспорта: Воркаут — задана в самом изделии (у группы «Скамьи»: Благоустройство). [Сбросить]».
- В окне паспорта серая подпись «из изделия» → «из группы «Скамьи»» / «из изделия (задана вручную)».
