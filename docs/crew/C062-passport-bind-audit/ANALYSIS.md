# C062 — куда вешать номер паспорта

Аналитик ([аудит](be7ee5b2-7189-4a6f-93c8-f2e2e0350d52)), 2026-11-11. Код не писался. Черновик ТЗ — `TZ-DRAFT.md`. Карта — `CODE-MAP.md`.

C060 (`passport-texts-number`) и C061 (`trainers-load`) не трогать.

## 1. Что хочет пользователь

Менеджер за одно действие получает номер и может напечатать его снова тем же номером.

1. Вручную добавляет паспорт и привязывает к продукции. Во вкладке «Паспорт» изделия номер остаётся.
2. Паспорт, собранный сайтом, сам получает номер и пометку «С сайта».
3. Повторное нажатие «Печать» по той же строке печатает тот же номер. Новый номер — отдельное действие.
4. К номеру можно прикрепить файл. Печать тогда отдаёт файл, а не собранный заново PDF.
5. Новый номер не должен затереть другие номера того же изделия и не плодить второй живой паспорт на ту же позицию заказа.

**Если … то …**

- Если выпуск вручную с выбранным изделием — у экземпляра есть продукция, номер виден во вкладке «Паспорт» и не пропадает при следующем открытии.
- Если печатают уже выпущенный паспорт — номер тот же, счётчик не растёт.
- Если к номеру прикреплён файл — «Печать» отдаёт файл и пометку «Файл». Если файла нет — PDF собирает сайт и пометка «С сайта».
- Если у изделия десять заказов — в таблице до десяти номеров. Последний заказ не затирает прежние.
- Если черновик не выпущен — номера нет (как сейчас, НМ).
- Если у позиции заказа уже есть живой паспорт — повтор не создаёт второй.

## 2. Шаблон и выпущенный экземпляр

| | Шаблон модели | Выпущенный экземпляр |
|--|--|--|
| Где | `products.passportDefaults` + тексты категории `passporttemplates` | `productpassports` |
| Номер | нет. `hasPassport` — флажок, не номер | `passportNumber`, заводской `productCode`, талон `warrantyCode` |
| Когда | пока готовят модель | номер только при выпуске (НМ, §10) |
| Правка | меняет следующие выпуски | снимок `textSnapshot`; справочник выданный не меняет (ВП-4) |
| Экран | вкладка «Паспорт»: готовность шаблона (C056) | та же вкладка: таблица № / дата / заказчик / заказ. Заводского номера в таблице нет |

Один `productId` — много паспортов. Так задумано (уникальность «один паспорт на изделие» снята в ПС.1). **Решение пользователя 2026-11-11:** у изделия несколько паспортов, потому что несколько фирм (наши компании) — одно поле «текущий номер» на продукции нельзя. Количество в позиции заказа не равно числу паспортов: одна строка — один документ (C060).

## 3. Куда вешать новый номер

**A. Только продукция.** Одно поле «текущий номер» на `products`. Повторная печать простая, но десять заказов одного турника сотрут друг друга. Ломает ПС.1, снимок договора (C055: правка договора не меняет продукцию) и таблицу выпущенных (C056).

**B. Только позиция заказа.** Номер живёт на `incomeId`. Печать из договора уже почти так (связь есть). Паспорт без заказа (вручную, со склада, старые) остаётся без места, хотя пользователь просит привязку к продукции.

**C. Гибрид (рекомендую).** Учётный объект — выпущенный экземпляр в `productpassports`. Продукция обязательна при ручном выпуске: номер виден во вкладке «Паспорт». Заказ и `incomeId` — когда паспорт из заказа. На модель номер не пишем. Файл — вложение этого экземпляра, не шаблона.

## 4. Рекомендация

Брать **C**. Это совпадает с уже решённым и не заводит новую таблицу (§3.4).

- «Сохранить номер у продукции» = строка в таблице выпущенных, не поле на модели.
- «Повторный клик» уже есть для того же документа: повторный выпуск не берёт новый номер (§10); редакция `newRevision` номер сохраняет. C060 добавляет то же после «аннулировать и выпустить заново» для пары позиция+изделие (отчёт есть, на прод не выложен).
- «Изготовление на сайте» = PDF собрал сайт (`source: app`), номер в момент выпуска, пометка «С сайта». Отметка цеха «изготовлено» номер не тратит (иначе дыра в счётчике до печати).
- Файл к номеру — новое. Сейчас PDF каждый раз собирается `GET /passports/:id/pdf`, файла у номера нет (`pdfIssuedAt` — только дата скачивания).
- Дыра: индекс `incomeId` не уникальный. Правило «один живой паспорт на позицию» в черновиках заказа есть, ручное создание второй живой записи не закрыто. Как закрыть индексом — архитектору.
- Несколько фирм: сейчас выпуск берёт **одну** нашу организацию (`isOurCompany`, первая). Нужны поле фирмы на экземпляре, колонка «Фирма» и **выпадающие** (изделие / фирма / позиция / номер) — зафиксировано пользователем 2026-11-11, таблица в `TZ-DRAFT.md`.

## 5. Что не делать

- Не писать «текущий номер» одним полем на `products`.
- Не заводить новую коллекцию. Поле файла — только добавление на `productpassports` (CRM его не читает). Куда класть байты — архитектор.
- Не пересобирать и не перенумеровывать уже выданные (ВП-4, НМ).
- Не тратить новый номер на повторную печать и на отметку цеха.
- Не плодить паспорт на каждую штуку, пока нет ответа: сейчас 1 строка = 1 документ.
- Не начинать код по этому черновику и не трогать незакоммиченное C060.
- Не вешать файл на шаблон модели.

Норму ГОСТ на «номер только у модели» не искал: вопрос учётный, не текст паспорта. Идентификация экземпляра (заводской номер в основных сведениях) уже в `PASSPORTS-V2.md` §1.1.
