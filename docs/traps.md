## Экран роли по её названию (2026-11-09)
- Экраны «Труборез» (трубы, котики) и «Лазер лист» (листы, собачки) включаются по **названию роли** (`roleLabel`), а не по коду: `isPipeRole`/`isSheetRole` в `pwa/main.js`, `isStockRole` в `pwa/sections/help.js`.
- **Что случилось:** в коде было точное сравнение с «Трубарез» (опечатка). На проде роль переименовали грамотно — «Труборез». Сравнение перестало совпадать: труборез видел обычные «Остатки» вместо своей таблицы, котики пропали. Ошибок в журнале нет — сайт «работал».
- **Почему допустили:** название роли может менять любой админ, а код держался за точное написание. Тест на это место не было.
- **Правило:** роль узнаём по шаблону, терпимому к написанию (`/^\s*труб[ао]рез/i`, `/^\s*лазер\s+лист/i`). Правильное слово — **Труборез**. Новый экран для роли — тот же подход; переименовали роль на проде — проверить, что её экран открывается (вход «Смотреть как» или меню «Экран «Труборез»» у админа).

### C155: unit метрик и реальные uploads

`control.service.spec.ts` проверяет сбой БД через `collectNow`, который также измеряет диск/папки. На ПК с фотографиями настоящий `dirSize(uploads)` делал эти unit нестабильными под параллельной нагрузкой (таймаут5с). В этом describe изолировать disk-fs и fs.statfs; поведение обработки БД/latency продолжает проверяться. Не увеличивать глобальный таймаут и не объявлять красные ворота зелёными после одного удачного запуска. Измерения самого disk-fs проверяются его отдельными тестами.


### SSH ProxyCommand из desktop Windows

Если штатная выкладка/план скрипта падает с PowerShell «exec не распознано», OpenSSH получил SHELL от запускающего desktop. Сам ключ/сервер не виноваты. В Git Bash для SSH устанавливается SHELL=/usr/bin/bash (только OSTYPE=msys/cygwin; установленный Git здесь сообщает cygwin); release.sh и remote-access/run-script.sh делают это сами. На Linux поведение прежнее. Проверка — штатный read-only план passport-creation-index; SSH-конфиг и ключи не править и не печатать.


### C155: не путать ошибку браузерного сценария с ошибкой сайта (19.11.2026)

- **Первое заполнение проверять без заранее выбранного вида.** Прогон только на заполненном шаблоне пропустил неверный старт через обязательную ручную формулировку. Нужны отдельные исходные состояния: вид отсутствует → один вопрос → подтверждение конструкции → словарный текст; затем повторное открытие без вопросов. Исходные рабочие изделия ради теста не менять. Контроль сохранности — хеши ранее выпущенных паспортов до и после на копии.
- **Сначала фактический DOM, затем локатор.** Имя кнопки может включать обязательную отметку; вложенный `label.field > span` при поиске внутри того же label не находит контрол. Не менять сайт из-за такого таймаута. В отчёте разделять ожидание кнопки, нажатие, появление поля и сохранение; при сбое сохранять обезличенный снимок и состояние DOM. Для штатного выбора использовать точный `name` и видимый native select либо его фактический `.sel-wrap`; не подбирать селекторы серией слепых запусков.
- **Очередь берётся из реальных данных копии.** У QA1067 не хватало исходного фото, поэтому первым оказался `img_overview`, а состав попал в «Ещё». Не считать это доказательством поломки главной кнопки на рабочем сайте. Перед проверкой прочитать fill-queue, выбрать точное действие состава и честно указать проверенный вход; файлы или данные не подгонять молча под тест.
- **Дата сборки не равна свежести PWA.** `development.json.code.builtAt` относится к сборке backend. При подозрении на старый интерфейс сравнивать HTTP-содержимое изменённых PWA-модулей с текущими файлами. Если совпало, повторная сборка и восстановление БД не нужны.
- **Переключение вкладки не раскрывает её секции.** «Заполнить» должно сделать целевое действие видимым и доступным: открыть секцию, перевести фокус, прокрутить до неё. Нужны проверки уже активной вкладки, другой вкладки и повторного нажатия. В unit нельзя ограничиваться подтверждением вызова `openTab`.
- **Единственное поле выбора занимает строку.** В правой колонке стандартная половина form-grid обрезала «Тренажёр для ног». Для одиночной настройки использовать штатный `wide: true`, затем проверить обе темы. Не вводить отдельный CSS экрана, когда проблему решает параметр компонента.

Доказательства: `crew/C155-passport-owner-queue/FIRST-TIME-ACCEPTANCE.md`, `FIRST-TIME-AUTOFILL.md`, `FILL-BUTTON.md`. Эти причины и меры повторно сверяются при следующем изменении соответствующего пути.

### Как сохранять найденные причины — решение владельца 19.11.2026

Каждую подтверждённую полезную находку фиксировать в отчёте текущей crew-задачи: симптом → установленная причина и доказательство → исправление → проверка → что нельзя повторять. Повторно применимую меру добавлять сюда; изменение общего правила — также в соответствующий канон/инструкцию. Предположение отделять от установленной причины. Ссылаться на существующую запись вместо размножения одинаковых отчётов. Где возможно, закреплять урок проверкой поведения, чтобы следующий агент не зависел только от памяти.
