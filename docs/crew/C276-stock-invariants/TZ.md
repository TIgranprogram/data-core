# C276 — склад по умолчанию и публичная граница склада

Аудит C274 воспроизвёл два склада по умолчанию при одновременном назначении. Зафиксирован и отдельный прямой импорт DTO склада из заявки поставки.

**Класс** L · **Ответственный** backend · **Проверяют** архитектор, data-steward и QA.

## Техническое задание

1. Все изменения `isDefault` в API должны проводиться одной транзакцией владельца `stock`, включая первый склад, замену при снятии, явное назначение и восстановление отсутствующего default во время чтения. Сериализация должна работать между разными процессами. Использовать уже поддерживаемую Mongo 4.4 и переданные сессии. Не менять схему `warehouses`, CRM или права пользователей.
2. У рабочего набора с хотя бы одним активным складом есть один действующий default. Поведение архива последнего склада сохраняется, новый склад создаётся только штатным чтением, когда он действительно нужен. Правила деактивации и старых записей обосновываются в отчёте до выпуска. Конкурентные транзакции не теряют живой default при сбое вставки или изменения.
3. C260 проверяется отдельно. При выключении флага ручные маршруты подчиняются прежнему контракту. Одновременная прямая запись старым приложением требует согласованного эксплуатационного переключения.
4. DTO пагинации бронирований предоставить через публичный вход `stock/index.ts`. Сохранить значения 1 и 20 по умолчанию, предел 100, путь, OpenAPI и валидацию. Другие частные импорты и исторические циклы в этот этап не входят.
