# Цепочка материалов: купили → вошло в изделие → записано в паспорте

Аналитик, 2026-10-24. Задание пользователя: старые паспорта не трогаем; шаблон паспорта нового изделия собирается из справочников; тексты справочников правит сам пользователь. Тех. описание, возможно, уйдёт из паспорта в отдельный документ (решим позже).

## 1. Как сейчас (по коду и докам)

1. **Покупаем:** заявка снабжения (`supplyrequests`) -> позиция склада (`materials` / `storageitems`): наименование, сортамент (`assortment`), марка (`materialGrade`), размеры (`dimensions`), цвет.
2. **Входит в изделие:** `products.composition` (строки «материал» со ссылкой на позицию склада). Копится из выдач (SK-7) или вводится руками в окне «Состав изделия».
3. **Паспорт:** в изделии и в паспорте есть таблица «Материалы изделия» (`materialsSpec`: материал из справочника, размеры, части; покрытие). Из неё сам собирается текст «изготовлено из…» (МИ.1–МИ.5 готовы).
4. **Мост уже есть, но слабый:** кнопка «Взять из состава» (`showcase-materials.ts`) склеивает название + сортамент + марку позиции склада в строку и **угадывает по тексту** материал и размер в справочниках. Что не угадано, идёт в список `unmatched`.

## 2. Где разрыв

- Позиция склада не знает, какой она материал паспорта. Связь каждый раз **угадывается по словам**: «Труба проф. 40х20х2 ст3» может не опознаться, и человек вводит строку руками. Тот же материал в десяти изделиях опознаётся десять раз.
- Нет места для текстов: «как эта покупка звучит в паспорте» и «как в тех. описании» нигде не записано при материале. Тексты живут только в «Материалах и покрытиях», на уровне вида материала. Размер (∅89×3) при этом берётся из названия.
- Покрытие (порошковая краска, цвет) не связано ни с покупкой (краска), ни с заказом.
- Если состав пуст (изделие новое, выдач ещё не было), «Взять из состава» ничего не даст.

## 3. Варианты цепочки

**А. Связь в карточке позиции склада (рекомендую).** У позиции необязательные поля: «Материал паспорта» (из справочника) и «Размер» (из «Сортамента»). Заполняются один раз при заведении позиции, с подсказкой по названию («похоже на: Труба стальная ∅89×3 — да/нет»). Дальше «Взять из состава» берёт связь, а не угадывает. Угадывание остаётся для старых позиций, без связи.
- Плюс: один раз на позицию, а не на каждое изделие. Опирается на уже готовые справочники и кнопку.
- Минус: надо один раз пройти существующие позиции склада (подсказка массово, подтверждает человек).

**Б. Только улучшить угадывание.** Больше синонимов у материалов, разбор «40х20х2», «ст3».
- Плюс: ничего не меняется в карточках. Минус: всегда будут промахи, а пользователь спросил про «грамотно и само».

**В. Отдельная таблица «позиция склада -> материал паспорта».** Плюс: не трогаем общие с CRM коллекции вообще. Минус: ещё один справочник для поддержки, расходится с карточкой. Годится как запасной ход, если архитектор запретит поля в `materials`.

**Рекомендация: А** (по запрету на схему общих коллекций — см. п. 6; если нельзя, то В), Б как дополнение для старых позиций.

## 4. Быстрый подбор материалов к изделию (что когда)

| Способ | Когда | Как работает |
|--|--|--|
| Из состава | изделие уже со составом (из выдач или руками) | «Взять из состава»: по связи позиций (вариант А), что не опознано, видно списком |
| Как у похожего изделия | новое изделие, похожее на старое | кнопка «Скопировать таблицу из…» (выбор изделия, только та же категория); человек правит |
| Шаблон по категории | изделие без состава и без аналога | в «Категории» заранее типичная таблица (качели: труба ∅89×3, лист 2 мм, детали…) |
| Из выдач | изделие делают сейчас | SK-7 пополняет состав, затем «Взять из состава»; отдельной кнопки не надо |

Порядок подсказок для человека: состав -> похожее изделие -> шаблон категории. Любой способ только **предлагает**, записывает человек.

## 5. Тексты: что где живёт

| Уровень | Что | Пример |
|--|--|--|
| Вид материала («Материалы и покрытия», уже есть) | падежи, шаблон размера, фраза «изготовлено из», уход, дефекты | «стальной трубы» / «∅{d}×{s} мм» |
| **Позиция склада (новое, необязательно)** | материал + размер; при желании свои тексты: «пункт для паспорта» и «пункт для тех. описания» | «из стальной трубы ∅89×3 мм» / «Труба стальная электросварная, ГОСТ 10704, сталь 20» |
| Категория / изделие | какие части, какое покрытие, итоговая сборка | «Состоит из стоек, перекладин…» |

Правило: пункт для паспорта по умолчанию **собирается из справочника** (материал + размер); отдельный текст у позиции нужен только если отличается (нержавеющие цепи: «цепь из нержавеющей стали»). Пункт для тех. описания - поле на будущее, сейчас не печатается.

**Если тех. описание уйдёт из паспорта:** тексты уже раздельные (паспортный и технический), поэтому уходит только вывод в печати, ничего не переписывается и не теряется. Старые паспорта не меняются.

## 6. Что нельзя

- Менять выданные (напечатанные) паспорта и их снимки текстов.
- Ломать схему общих с CRM коллекций (`materials`, `storageitems`, `products`): только новые **необязательные** поля, синхронно с kppdf (AGENTS №4, UNIFY-SUPPLY-WAREHOUSE). Решение, можно ли это в `materials`, - за архитектором; запасной ход - вариант В.
- Массово переписывать позиции склада без «да» пользователя: подсказка и подтверждение человеком, прод - только бэкап и `--apply`.
- Ставить деньги и цены в тексты паспорта.

## 7. Шаги

- МЦ-1 (архитектор): где хранить связь «позиция склада -> материал паспорта + размер» (поля в `materials` или отдельная таблица), влияние на CRM kppdf. Готово: короткая записка в этом файле.
- МЦ-2 (backend): связь у позиции (необязательные `passportMaterialId`, `passportSizeId`), подсказка по названию (`GET` вариантов, ничего не пишет), «Взять из состава» сначала берёт связь, потом угадывает. Готово: юнит; позиция без связи работает как раньше; openapi и MAP обновлены.
- МЦ-3 (frontend, skill datacore-design): в правой панели карточки позиции склада блок «Для паспорта»: материал, размер, подсказка «да/нет». Готово: сохраняется в одно действие; 375 px.
- МЦ-4 (data-steward): скрипт-подсказка по существующим позициям: список «позиция -> предложение -> уверенность», план, затем `--apply` только по «да» (файл с планом пользователю). Готово: отчёт, неуверенные отдельно.
- МЦ-5 (backend + frontend): «Скопировать таблицу из изделия…» и шаблон таблицы в категории. Готово: копия не пишет без нажатия «Сохранить»; только та же категория.
- МЦ-6 (backend + frontend): необязательные тексты у позиции («для паспорта», «для тех. описания»); сборка использует их, если заполнены. Готово: пусто -> текст как раньше.
- МЦ-7 (qa): цепочка как человек: заявка -> позиция со связью -> выдача -> состав -> «Взять из состава» -> текст -> паспорт -> PDF; старый паспорт печатается как был.

## 8. Вопросы пользователю (решаем сами по умолчанию, ответа ждать не надо)

1. Тексты у позиции склада («для паспорта», «для тех. описания») нужны сразу или достаточно связи с материалом и размером? По умолчанию: сначала связь (МЦ-2…4), тексты у позиции позже (МЦ-6).
2. Откуда брать покрытие («окрашено порошковой краской»)? По умолчанию: выбирает человек в таблице; для категории можно задать обычное покрытие (МЦ-5).
3. Нержавеющие цепи и им подобное: материал «Цепь нержавеющая» отдельной записью справочника, а не «сталь + оговорка»? По умолчанию: да, отдельной записью.
4. Позиции склада, которые не опознались, - вы сами подтверждаете список (МЦ-4) или оставить без связи, пока не понадобятся? По умолчанию: подтверждаете списком, один раз.
5. Тех. описание в паспорте: пока печатать как сейчас, решение об отдельном документе - позже? По умолчанию: да.

**Решено координатором 2026-10-24:** вопросы 1–5 — по умолчанию (сначала связь «позиция склада → материал + размер», тексты у позиции — позже; покрытие выбирает человек, у категории — обычное покрытие; нержавеющая цепь — отдельная запись справочника; существующие позиции — подтверждение списком один раз; тех. описание пока печатается в паспорте).
