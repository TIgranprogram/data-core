# C155. Проверка первого открытия короткого шаблона

Прежняя приёмка начиналась с уже заполненных вида и конструкции 1066. Она подтвердила подстановку из словаря, но пропустила первый вход, где оба поля ещё пусты. Подготовлен план сброса на копии. Изменения начнутся после фиксации кода и разрешения координатора.

## Исходное состояние

На `localhost:3102`, копия `2fd2723433a343191577b795`, менеджерский GET подтвердил готовый short-шаблон изделия 1066 `6ae1269ae36900370537a2f3`. Вид «Тренажёр для ног» `6af707fdc451d4c05df6a046`. Сохранены «Нагрузка» `6aeea9373b8b9255839ab43b` и конструктивный вариант `6afef7e93b40fac6985f6306`. Описание приходит из словаря, лист `6afef7ee3b40fac6985f630f`, корень `6afef7893b40fac6985f62ec`. Собственной фразы и ручного выбора для этого корня нет.

## Сброс на изолированной копии

1. Перечитать шаблон и изделие. Начать только при совпадении вида и обоих признаков с исходным состоянием. Проверить, что собственное описание пустое. Если появился выбор короткой фразы из другого теста, проверить ожидаемый ID и согласовать снятие именно этого ключа до записи.
2. `PATCH /api/showcase/6ae1269ae36900370537a2f3/passport-template?variant=short` с `expected: {kindId: "6af707fdc451d4c05df6a046"}` и `changes: {kindId: null}`. В текущем состоянии `textChoices` передавать не требуется. Если к моменту сброса существует согласованный выбор этого конкретного корня, снять его через `expected.textChoices[rootId] = текущий id` и `changes.textChoices[rootId] = null`. Корни назначения и монтажа не трогать.
3. Заново прочитать `facetValueIds`. Текущий PATCH карточки не принимает `expected` для этого поля. На выделенной копии, без параллельного редактирования 1066, сравнить исходный массив с `["6aeea9373b8b9255839ab43b", "6afef7e93b40fac6985f6306"]`, затем `PATCH /api/showcase/6ae1269ae36900370537a2f3` только с `facetValueIds: ["6aeea9373b8b9255839ab43b"]`. Сохраняемое значение «Нагрузка» не добавляет элементов по своей справочной записи. Немедленно прочитать результат. При любом несовпадении остановить проверку.
4. До открытия интерфейса перечитать шаблон. Ожидаются пустой вид и своя фраза, отсутствие словарного источника, категория `TRN` от группы, сохранённые «Нагрузка», назначение и монтаж. Размеры, масса и фото остаются прежними. GET выпущенных паспортов выполнять с `readOnly=1`.

## Проверка интерфейса и сохранности выпуска

Открыть шаблон впервые после сброса под менеджером. На первом шаге выбрать вид «Тренажёр для ног». Затем выбрать «Две платформы для ног и рукоятка» в штатном контроле. Для этого пути ручное поле «Своя формулировка» не должно становиться обязательным. После сохранения и повторного открытия ожидаются тот же вид и выбранный лист `6afef7ee3b40fac6985f630f`, источник `dictionary`, видимый текст и отсутствие повторного вопроса. Выбор хранится в `textChoices`. Своя фраза остаётся пустой, в карточке остаётся исходная «Нагрузка». Проверка завершится чтением прежних паспортов без повторного выпуска или генерации PDF.

Хеши считаются по каноническому JSON с сортировкой ключей объектов и сохранением порядка массивов. Сравнить после сброса и после проверки интерфейса. В отчёт о прогоне указать только результат сверки и хеши. Номер, статус, ревизия, привязки, снимок текста и рисунки каждого выпуска должны совпасть.

## Сброс выполнен

Два PATCH на копии сняли вид и один конструктивный признак. GET подтвердил категорию `TRN` от группы, исходную «Нагрузку», пустое собственное описание, отсутствие словарного источника и единственный блокер `simpleDescription`. Назначение, монтаж, размеры, масса и пути рисунков совпали с исходным состоянием. Три рисунка ответили HTTP 200. Хеши состояния и текстовых снимков №611 и №612 совпали до и после. Журнал сохранён локально в `tools/logs/c155-dictionary-source/first-time-autofill-reset-1795100357008/summary.json`.

## Первый вход под менеджером

Браузерная проверка завершилась со статусом PASS. «Краткое описание» открыло выбор вида. После выбора «Тренажёр для ног» книжка предложила подходящий словарный текст для подтверждения. Оба сохранения вернули HTTP 200. Повторное открытие показало готовый шаблон, словарный текст и три связанные части. Собственная фраза осталась пустой и доступна отдельным действием. Повторного вопроса не было. Хеши состояния и текстовых снимков №611 и №612 совпали до и после. ## Ширина поля «Вид изделия»

В отдельной проверке на локальной браузерной проекции поле заняло всю доступную ширину, 245 из 245 px. Название «Тренажёр для ног» занимает 83 из доступных 209 px. Проверка сделала снимки в двух темах и завершила визуальную часть без вызовов записи. [Светлая тема](evidence/acceptance-first-time-width-light.png) · [Тёмная тема](evidence/acceptance-first-time-width-dark.png)

Сценарий пометил полное сравнение двух ответов GET как FAIL. Два дополнительных чтения подтвердили, что различались только `document.textSnapshot.at` и `textSnapshot.at`, которые вычисляются заново на каждом GET. После исключения этих временных меток ответы совпали. Сохранённые вид и выбор словарного текста, готовность, пустая собственная фраза, размеры, масса и рисунки 1066 подтверждены.
