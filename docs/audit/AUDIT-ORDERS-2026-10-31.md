## Что мешает работать

Заказ собран из кусков. Нет одного маршрута, по которому человек ведёт заказ. Отсюда три боли.

### 1. Негде изменить заказ

- У заказа нет своей формы (`salesorders.js`: `form` есть только у договора, строка 453). Поэтому внизу панели заказа нет кнопки «Изменить».
- Правка спрятана в мелкой кнопке «Изменить договор» в шапке каждого договора (`salesorders.js:224`).
- Сервер правку заказа умеет (`PATCH /salesorders/:id`). Проблема только в экране.

### 2. «Закрыть» после «Закрыть»

- Вкладка «Закрытые» показывает отгруженные и закрытые заказы вместе (`filter=done`).
- У отгруженного заказа есть кнопка этапа «Закрыть» (`salesorders.js:31`). Человек видит «Закрыть» внутри вкладки «Закрытые».
- Рядом крестик панели тоже называется «Закрыть» (`card.js:68`). Два разных действия с одним словом.

### 3. Нельзя убрать ошибочную позицию

- Позиция загрузилась не туда, договор уже в производстве. Менеджер получает 403 «Заказ уже в работе» (`incomes.service.ts:28,249-254,346`).
- Статуса «отменена» нет, есть только удаление. Перенести одну позицию отдельным действием нельзя.
- Удаление оставляет сирот: брони, задачи проектирования и работы, заявки, паспорта. Защита есть только от оплат и отгрузок (`incomes.service.ts:344`).
- Перенести договор из заказа в заказ одним действием нельзя (`POST /production-orders/assign` берёт только договоры без номера).

### Логика этапов

- Этап меняется тремя путями: кнопка следующего этапа, поле «Этап» в форме договора, этап всего заказа. Они расходятся (`stagesDiffer`).
- `PATCH /salesorders/:id` пишет любой этап в любую сторону, без причины и проверки перехода (`salesorders.service.ts:373`).
- Кнопка «Отгружен» ставит этап без документа отгрузки: остатки и накладная не создаются (`salesorders.js:31`). Подсказка `:44` говорит другое: этап поставится сам.
- Этап заказа считается по самому отстающему договору. Отгрузка сама переписывает этап, ручная правка может его перебить.

### Дубли на экране

## Как должен идти заказ

Проектирование → Производство → Готово к отгрузке → Частично отгружен (ставит система) → Отгружен → Закрыт. Отменён — ответвление до отгрузки.

### Одно место правки на каждое данное

| Данное | Где правится | Когда |
|--|--|--|
| № заказа, срок, приоритет заказа | Новая кнопка «Изменить» в панели заказа: на все договоры | До «Отгружен» |
| Заказчик, № договора, примечание | Панель договора, «Изменить» | До «Отгружен»; закрытый — админ |
| Этап | Только полоса воронки и кнопка следующего шага | Поле в форме убрать |
| Позиции: добавить, кол-во, название | Таблица позиций | См. решение 2 |
| Отмена позиции | Новая кнопка в строке, с причиной | До «Готово к отгрузке» |
| Перенос позиции, перенос договора | Новые действия с проверкой зависимостей | До отгрузки |
| Изделие | Панель одной позиции | До «Отгружен» |
| Цена, оплаты | Панель позиции | Как сейчас, по правам денег |
| Отгрузки | Блок отгрузок | Готово к отгрузке и дальше |

### Как раскидать загруженные заказы

1. Открыть список договоров без заказа.
2. Отфильтровать по заказчику.
3. Отметить договоры.
4. Нажать «В заказ…», выбрать номер или новый заказ.
5. Сопоставить позиции и поправить цены.

## Решения пользователя

Значение по умолчанию — первое.

1. Вкладка «Завершённые»: только закрытые, «Отгружен» остаётся в работе до закрытия. Иначе: отгруженные и закрытые вместе.
2. Позиции в производстве: менеджер меняет и отменяет до «Готово к отгрузке» с причиной, дальше админ. Иначе: только админ.
3. Отменённая позиция: серая строка с причиной, не считается в суммах и производстве. Иначе: уходит из заказа.
4. При отмене позиции: показать зависимости и спросить, снимать ли брони и задачи. Иначе: снимать автоматически.
5. Директор и бухгалтер: кнопки правки заказа им не показывать. Иначе: дать им права на сервере.
6. Закрытый заказ: вернуть в работу может только админ, с причиной.
