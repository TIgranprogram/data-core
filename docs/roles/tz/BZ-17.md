# ТЗ БЗ-17 — «Деньги»: видно, какая сумма кликается; в списке операций — мини-фото

**Зачем (словами пользователя, 2026-10-24):** «в Деньгах во-первых не понятно, какая сумма кликабельна, какая нет — исправить дизайнеру. При клике открывается список — можно мини-фото туда вставить, если есть».

**Роли:** дизайнер ☑ (первым — аудит и решение по виду) · frontend ☑ · backend ☐ (только если фото нет в ответе) · qa ☑

## Что сделать
1. **Дизайнер — аудит «Деньги»** (`#money`: календарь, итоги, вкладки): список всех сумм с отметкой «кликается / нет». Решение по виду кликабельной суммы — единое для приложения (например: цвет ссылки + подчёркивание пунктиром + курсор + подсветка при наведении; некликабельная — обычный текст). Записать в `docs/DESIGN.md` («Кликабельное число»).
2. **Frontend:** применить ко всем суммам «Денег» (ячейки дней `td.click`, `sum-item`, итоги строк). Ячейка с суммой, но без операций — не выглядит кликабельной. Подсказка `title` — что откроется.
3. **Мини-фото в списке операций дня** (`showOps` → `ul.q-list`): у строки, если у операции есть картинка (фото позиции заявки / изделия заказа / прикреплённый счёт-картинка), — миниатюра слева, как `thumb` в «Продукции». Нет — без пустого места.
   - Если фото нет в ответе календаря — backend добавляет поле `thumb` (url миниатюры, первое найденное) в элемент `ops[]`, без лишних запросов на каждую строку.

## Критерии приёмки
- [ ] На экране «Деньги» любой человек без подсказки отличает кликабельную сумму от некликабельной (проверка дизайнером, светлая и тёмная тема).
- [ ] Клик по каждой «кликабельной» сумме что-то открывает; по остальным — ничего и вид обычный.
- [ ] В списке операций дня у операций с фото — миниатюра; без фото — строка как сейчас.
- [ ] pwa — синтаксис ES-модулей; если трогали сервер — tsc 0 + юнит модуля.
