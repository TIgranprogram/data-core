# П155-1 — аудит действительно упрощённого паспорта

19.11.2026. Класс L: аудит и ТЗ, без изменения рабочего кода и данных.

## Запрос владельца

Два варианта: упрощённый и обычный. Сейчас приоритет упрощённому. Менеджер загружает через iLogic рисунки, габариты и доступную массу; приложение подставляет остальное. Описание — грамотные названия видимых функциональных частей (каркас, рукоятки, педали), без марок/размеров материалов и производственного BOM. Названия/категории частей и типовые описания постепенно накапливаются в справочниках; выбор от общего к частному, уже известное повторно не спрашивается. По рисунку предлагается описание, без выдуманных технических характеристик. В карточке изделия — ясное «Редактировать шаблон паспорта». Возможные ручные исключения: недостающие рисунки, размеры, масса, подтверждённые монтажные параметры, например глубина бетонирования.

Скриншот: изделие1066 «Хипс», слева 2/9 и «Сначала»: материалы, состав, вид тренажёра, мышцы, нагрузка, исполнение, монтаж; справа техническая таблица материалов. Не считать эти надписи доказательством серверной обязательности.

## Результат аудита

### Дополнение владельца: живые сценарии

Разрешено скачать копию реальных данных с сайта и поднять изолированный стенд. Прод остаётся только для чтения; сценарные записи — исключительно в копии.

1. Из карточки изделия без заказа: открыть/редактировать шаблон изделия; просмотреть и распечатать образец без расхода номера; отдельно выпустить номерной экземпляр с выбранной организацией и без заказа.
2. Из позиции заказа: выбрать её изделие и открыть правильный экземпляр; проверить правку, просмотр, печать и выпуск с контекстом позиции и фирмы.
3. Проверить каждую доступную паспортную кнопку в этих входах: название, действие, дубли, возврат, несохранённый ввод, последствия записи.
4. Оценить дизайн по заполненным состояниям на компьютере, включая обе темы. Не путать наблюдение исходного дефекта с приёмкой исправления.
5. Для номера разделить ненумерованный образец и выпуск с номером. Произвольный ввод номера при печати не является принятым решением: проверить существующий счётчик и повторную печать без нового номера.

Это расширяет аудит реальным прогоном. Реализация очереди оценивается отдельно после отчёта; готовность всех паспортов не объявляется по одному образцу.

Матрица: поле/действие → источник → реальная обязательность short/full → лишнее/авто/условное/оставить → файлы:строки → критерий исправления. Отдельно: граница шаблона изделия и экземпляра, повторный импорт и неизменность выпущенного. Правовой вывод о допустимости сокращённого документа не делается; обязательные безопасные инструкции не удаляются ради сокращения формы.

## Разделение чтения и владение

- **backend-audit (основной читатель, архитектор):** `backend/src/modules/product-passport/**`, `backend/src/common/passport/**`; точечно прямые серверные зависимости в showcase, product-photo и справочниках. Не читает pwa/iLogic. Пишет только `BACKEND-AUDIT.md`. Проверяет variant short/full, check/issue/pdf/preview/order, обязательность материалов/состава/признаков, snapshot, template/defaults, существующее средство простого описания. Небольшие воспроизведения без БД допускаются; код приложения не менять.
- **frontend-audit:** `backend/pwa/sections/passports/**`, `backend/pwa/sections/products/**`, `backend/pwa/sections/dicts/**`; путь iLogic найти rg по имени passport-images.iLogicVb и читать только загрузку метаданных и переход в книжку. Не читает серверный код. Пишет только `FRONTEND-AUDIT.md`. Проверяет перенос variant, очередь «Сначала», шаблон изделия/черновик/выпуск, кнопки, сохранение, промпты по фото, воронку и текущие справочники в UI. Реальную работу Inventor чтением кода не объявлять проверенной.
- **Координатор:** бизнес-модель, исходный скриншот, CANON/PATTERNS/PRODUCT, синтез и очередь в TZ. Не повторяет чтение зон агентов; спорные места проверяет точечно по их отчётам.
- **access при необходимости:** только GET прода/стенда по api.sh; отдельные реальные данные изделия1066 и перечень справочников. Секреты и персональные сведения в отчёты не выводить.

Агенты не одни в репозитории; чужие изменения не откатывать. Дополнительных агентов не создавать. Коммиты/выкладку не делать.
