# C161 · сервер

- `GET/PATCH /showcase/:id/passport-template` сохраняют прежний маршрут и права. Краткий шаблон хранит `{mode:'parts',partIds}` с порядком первого вхождения. Переданное клиентом `text` в режиме `parts` игнорируется. В `defaults` лежит исходное значение для CAS. `simpleDescriptionSource` возвращает `{kind:'parts',partIds,text,invalidPartIds?}`. Старое ручное `{text,partIds}` и явное `mode:'manual'` поддерживаются. [Обработчик PATCH](../../../backend/src/modules/showcase/passport-template-patch.ts#L45) · [Описание API](../../../backend/src/modules/product-passport/dto/presentation.dto.ts#L30)
- CAS сравнивает все ключи собственного значения, включая режим, посимвольный текст и порядок массива ссылок. Порядок ключей самого JSON-объекта на результат не влияет. Пустой новый выбор, неизвестный режим, отсутствующие записи и записи без имени дают 400 до `updateOne`. Сохранённый выбор со сломанной ссылкой возвращает пустую фразу и причину в готовности. [Сравнение и запись](../../../backend/src/modules/showcase/passport-template-patch.ts#L129) · [Готовность](../../../backend/src/modules/product-passport/product-passport.service.ts#L1011)
- Сборщик использует родительный падеж единственного числа, если он заполнен у каждой части. Иначе он берёт названия всех частей. Дубли отображаемых форм сверяются без учёта регистра, в тексте остаётся написание первой формы. Шаблон, проверка, PDF-предпросмотр и транзакция выпуска используют один результат сборки. [Сборщик](../../../backend/src/common/passport/simple-description.ts#L12) · [Использование при выпуске](../../../backend/src/modules/product-passport/product-passport.service.ts#L1141)
- Отдельный запрос к `passportParts` на шаблон без словарной фразы меняется с 0 на 1 при выборе частей. Если словарные предложения уже требуют формы частей, обе выборки выполняются одним запросом. PATCH делает один запрос для проверки ссылок и один для ответа с актуальным шаблоном. Чтение выданного или аннулированного по `get(readOnly)` делает 0 запросов к `passportParts` и использует источник, сохранённый в `textSnapshot`. [Выборка](../../../backend/src/modules/product-passport/product-passport.service.ts#L1241) · [Проверка числа запросов](../../../backend/src/modules/product-passport/passport-parts-presentation.spec.ts#L43)
- Старый PUT, массовое изменение и его отмена сохраняют текущий `simpleDescription` тем же выражением Mongo. Full и legacy используют прежний подробный текст. Для выданных актуальные на момент выпуска текст и источники PDF лежат в `textSnapshot` и `printSnapshot`. [Старый путь записи](../../../backend/src/modules/showcase/passport-defaults.ts#L99)
- P1 из архитектурного ревью закрыт. `POST /passports/:id/snapshot` возвращает 409 для выданного или аннулированного v1 с описанием `parts`. Для выданного ответ предлагает создать новую редакцию.
