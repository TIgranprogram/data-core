## Находки

- **P0:** нет.
- **P1:** не-GET через `apiFile` не проходит ранний выход `api()`. Запрос уходит в `raw()`. Места: `sections/qr.js:35` (POST `/qr/print`), `sections/passports/dialogs.js:67` (POST `/passports/preview`), `sections/tech-sheet.js:62` (POST технического описания). Обычные «Сохранить / создать / удалить» идут через `api()` и режутся. Не чинил: ворота ТЗ — `api()`, правка этих экранов вне крошечного блока.
- **P2:** `confirmPassword` (`api.js:186`) шлёт POST `/auth/confirm` мимо `api()`. В просмотре чужой роли `session.role !== 'admin'`, поэтому `withConfirm` (`ui/confirm-password.js:11`) сначала спрашивает пароль. Само удаление затем режет `api()`.
- **P2:** `apiQuiet` (`api.js:295`) шлёт POST `/client-errors` мимо `api()`. Это журнал сбоя, не запись карточки.
- **P2:** «Вид экрана» и ширины пишутся в браузер сразу (`prefs.js:131`), PATCH `/auth/me/prefs` уже режется `api()`. На сервер настройка не уходит.

## Риски

- Сервер по JWT остаётся админом. Суммы в JSON и зоны склада этот режим не маскирует. Так и записано в ТЗ, в эту волну не входит.
- Обход `api()` из консоли браузера по-прежнему пишет как админ. Клиентский замок только в `api()`.
- Дизайнер полосу и профиль ещё не принимал. Глазами не смотрел.
