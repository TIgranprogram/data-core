# ТЗ C011 — Полный аудит бизнес-логики «Рабочего места» (только аудит + ТЗ на правки)

**Зачем (словами пользователя):** Понять, какую бизнес-логику проект должен поддерживать; сверить документы и код; найти дыры, конфликты и «перебивающий» друг друга код; оценить гибкость для менеджеров; убрать шум с экранов; предложить, где информацию развести по вкладкам. Код не править — только аудит и техзадание на исправления.

**Класс:** XL · **Max agents:** 1 (основной читатель — analyst) · **Reviewers:** нет на этом шаге · **Проверки:** нет (аудит) · **Код:** не трогать

**Роль:** datacore-analyst. Разрешено **читать** код и экраны для сверки (не менять). Писать только в `docs/crew/C011-biz-logic-audit/`.

## Что сделать

1. **Модель бизнеса (резюме):** кто пользователи; цепочки «заявка → счёт → приход → склад → бронь/выдача → заказ/позиция → проектирование/работа → паспорт → отгрузка → деньги». Что канон, что снимок, что запрещено.
2. **Инвентарь артефактов бизнес-логики:** список файлов/модулей (путь + 1 строка «зачем») — docs, schema, service, PWA section. Отметить рассинхрон doc↔код↔экран.
3. **Проблемы:** дыры (нет сценария), конфликты (два пути делают одно по-разному), перебивающий код (дубли форм/эндпоинтов/статусов), мёртвые/лишние поля и надписи, жёсткость для менеджера (нельзя гибко поправить без админа).
4. **Взгляд менеджера:** по каждому разделу меню — «зачем сюда зашёл / что могу сделать / что лишнее / чего не хватает». Язык менеджера (без служебных кодов).
5. **Структура информации:** где нужна отдельная вкладка/экран; где убрать шум; без «мусорных» новых разделов — только осмысленное разведение.
6. **Итог — техзадание на исправления:** файл `docs/crew/C011-biz-logic-audit/FIX-TZ.md` по шаблону духа `docs/roles/TZ-TEMPLATE.md`: классы S/M/L пачками, приоритет P0/P1/P2, точные места `файл:строки` или функция, критерии «если … то …», что не трогать (CRM-схемы, контракт API). Плюс краткий `REPORT.md`.

## Формат отчёта (обязательные файлы)

### `REPORT.md` (≤ 40 строк, структурировано)
1. Резюме бизнес-логики (5–10 предложений / буллеты).
2. Топ проблем (таблица: id | суть | файл:место | критичность P0/P1/P2).
3. Ссылка на FIX-TZ.md.
4. Вопросы пользователю (новые — также дописать в конец `docs/QUESTIONS.md` с «по умолчанию», блок «C011»).

### `FIX-TZ.md` (основной артефакт)
- Пачки работ по доменам: Снабжение · Склад · Заказы · Проектирование/Работа · Продукция/Паспорта · Деньги · Навигация/вкладки · Язык менеджера.
- В каждой пачке: цель, пункты с местами кода, критерии приёмки, оценка S/M/L, зависимости.
- Отдельно: «не делать» и «нужно решение пользователя».

### `INVENTORY.md` (по желанию, если длинно)
- Таблица артефактов doc/schema/ui.
