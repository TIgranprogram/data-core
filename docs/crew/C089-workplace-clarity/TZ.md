# C089 — понятное рабочее место: очередь после паспортов

Статус: queued. Не расширять сегодняшний выпуск C086. Пожелания владельца 12.11; решения ниже — проект требований, сначала сверка бизнес-логики с analyst.

## Приоритеты и самостоятельные этапы
1. **Склад, адаптивность (M):** при изменении ширины левого фильтра слова не превращаются в столбики; количество колонок зависит от доступной ширины панели. Проверить содержимое «Сечение»: названия болтов/саморезов на снимке владельца не считать правильными характеристиками без проверки источника. Признаки фильтруются по выбранной категории. Приёмка: узкая/широкая панель, клавиатура, светлая/тёмная темы, автоматическая регрессия геометрии.
2. **Заказы → проектирование (L):** выяснить смысл нераспределённого заказа, назначения исполнителя и этапа. Общая очередь видна уполномоченному распределяющему, личная работа — назначенному проектировщику. Не приравнивать автоматически назначение и этап; согласовать правила по позициям и смешанным заказам, сохранение незавершённых работ. Приёмка: новый/назначенный/переназначенный заказ, роли, отсутствие потерь и дублей. До кода — analyst.
3. **Карта работы (L-UI):** существующую help-product-map развить в карту всего сайта с уровнями раздел → процесс → действие. Для выбранного узла входы, результат, следующий шаг и переход к работе; показывать только относящиеся связи, без общей паутины. Длинные инструкции внутри карточки. Возврат на предыдущий уровень и клавиатурная навигация. Истина связей — API/бизнес-процессы, не декоративная схема.
4. **Сегодня (L-UI):** прототип одного рабочего сценария: требует внимания / в работе / ждём других. Карточка содержит суть, причину, следующее действие; детали по раскрытию, после действия актуальное состояние. Использовать реальные разрешения и данные, не выдумывать счётчики; игровой ориентир означает интуитивность и обратную связь, не украшения ради украшений.
5. **Границы заказа/договора/изделия (L):** аудит дублированных точек редактирования и источников данных. Рабочий контекст заказа — заказ; договор доступен по связанной ссылке. Изделие — общие характеристики и шаблон; выпущенный паспорт — конкретный документ/снимок, изменения общего шаблона не должны незаметно менять ранее выданные документы. Проверить права менеджера, одинаковое сохранение и отображение из всех точек входа. Не объединять коллекции и не менять контракт без отдельного ТЗ.

## Сквозные требования
Один источник данных, общие компоненты и предсказуемое поведение; стандарт docs/UI-ACCEPTANCE.md. Для каждого этапа отдельные критерии, локальные автоматизированные сценарии и короткий отчёт. Никакой массовой переделки/миграции фреймворка. Владелец описывает пожелания; техническую подготовку, команды и проверки выполняют агенты.

## Уточнение владельца: эталон правой панели
Панель меняется плавно; автоматическое резкое раскрытие на весь экран пока не вводить. Содержимое реагирует на ширину самой панели: на узкой — одна колонка, на широкой — согласованные группы рядом. Фото не должно занимать отдельный полноширинный пустой блок, если рядом можно показать относящиеся к нему данные/действия. Не применять хаотичную masonry-раскладку: сохранять порядок шагов и клавиатуры. Проверять drag-resize на промежуточных ширинах, а не только ширину окна. Начать с passportFill и вынести общий компонент раскладки в kit, затем применять в других правых панелях. Критерий — меньше лишней вертикальной прокрутки без сжатия подписей и полей. Новая библиотека сама по себе это не решает.

## Уточнение про два сервера (ссылка на C058)
Основной рабочий сервер планируется офисный; домашний — резерв, переключения редкие. Сначала выбрать и документировать допустимую потерю времени/данных (RTO/RPO) и безопасный режим единственного писателя, затем завершать механизм. Автопереключение с нулевой потерей не считать реализованным при 15-минутном refresh. Сверить существующий C058, не создавать второй параллельный механизм. Приёмка — отключение активного узла и возврат, проверка БД/фотографий и отсутствия двух одновременно пишущих узлов. Сегодня инфраструктуру не переключать.

## Классификация и PDM
Проверить достаточность уже имеющихся категории, типа, назначения, материала, установки и состава для автоматических документов. Новые поля добавлять лишь при подтверждённом пробеле. Импорт развивать по существующему C057 CONTRACT: одна реальная сборка, стабильные идентификаторы/версии, детали/модули/метизы без дублей; заявки из потребности заказа с учётом остатков и броней, не напрямую из любой загрузки модели.

Дополнение: на широком экране открытая правая панель не перекрывает карточки основной области — обе области доступны, сетка основной области перестраивается по оставшейся ширине вплоть до одной колонки. На узком экране допустим отдельный режим панели с понятным возвратом, а не две нечитаемые колонки. Верхняя навигация компактная и остаётся доступной при прокрутке; проверить реальный scroll-контейнер, sticky, доступность заголовков/фокуса и отсутствие двойных скроллов. Критерии: открытие/закрытие/resize панели, промежуточные ширины, длинные списки, zoom200%, клавиатура; верхняя область не тратит высоту пустыми отступами.
