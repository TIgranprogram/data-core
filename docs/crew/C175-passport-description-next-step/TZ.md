# C175 — следующий шаг в кратком описании

Основание21.11: менеджер застрял в пустом выборе частей и просит готовые варианты всех существующих изделий. ПС-03/05/09: без выдуманных составов и без изменения опубликованных паспортов.

КлассM для локальной UI-правки; данные справочников отдельным доказанным планом. Владелец требует законченный путь, не ещё одно пустое предупреждение.

## UI
- Пустой linked-набор не должен скрывать доступные части без понятного действия. Явно предложить выбрать части вручную из всего справочника. Не выдавать их за автоматически подходящие; чужой весовой стек автоматически не выбирать.
- Подсказка описывает конкретную причину и действие; без расплывчатого «уточните признаки».
- Для выбранного вручную состава сохраняются обычные серверные правила, предпросмотр и отмена; никаких авто-save.
- Ссылка справочника остаётся, после дополнения можно обновить части здесь без потери текущего выбора/ручного текста. Если это требует большой новой навигации, сначала реализовать минимальную безопасную кнопку обновления в текущей панели.
- Подобрать готовый вариант сохраняет текущую штатную воронку вида/признаков, не имитирует готовность.

## Данные
Readonly аудит прод: покрытие существующих изделий видами/признаками/применимыми фразами/partIds; точные пробелы. Автозаполнение только доказанными источниками, догадки не применять. План конкретных записей до применения. Обычный выпуск кода не равен заполнению справочника.

## Приёмка
Целевые node-тесты поведения: пустые links+непустой общий справочник, действительно пустой справочник, возврат/обновление без потерь, linked-применимость, ручной режим/отмена/сохранение. Desktop realbrowser в обеих темах: исходное пустое состояние→явный выбор→preview→save/reopen и справочник→возврат. Скриншоты и UI-REVIEW в этой папке. Код без глаз = PARTIAL.
