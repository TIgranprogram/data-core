# C231. Приёмка счёта прямо на объект

## Порядок работы

1. Открыть «Заявки → Счета» и выбрать счёт поставщика.
2. Отметить полученные позиции. Под таблицей выбрать «Принять на объект». Для строк с уже назначенным заказом приложение покажет этот заказ; для остальных предложит действующие заказы. Если заказ состоит из нескольких договоров, в списке показаны оба номера.
3. Подтвердить поставку. В принятой строке появятся «На объекте» и ссылка на заказ. Оставшиеся строки этого же счёта можно позже принять туда же, на другой объект или на склад.

Прямая приёмка не создаёт складской позиции и движений. Она сохраняет факт получения и связывает заявку с выбранным заказом. Существующая запись о материале в справочнике может быть создана до приёмки, при оформлении заявки.

## Границы

- Выбор действует на отмеченные строки целиком. Если часть количества одной строки уже пришла на склад, прямой остаток оформляется отдельной позицией.
- В одном подтверждении один заказ. Строку, уже связанную с другим заказом, система не переносит автоматически.
- Оплата, финансовые снимки и существующие движения не переписываются. Ограничения на изменение базы подтверждённой оплаты без даты сохраняются.
- Для исправления факта приёмки администратор раскрывает строку и нажимает «Отменить приёмку». При прямой поставке склад не меняется.

## Контракт и хранение

`POST /api/supply/invoices/:id/receive` принимает необязательный `directOrderId` (ID записи заказа/договора из `GET /api/salesorders/lookup?filter=active`). При его наличии нужен непустой массив `requestIds` с явно выбранными строками этого счёта. Отдельного маршрута или миграции нет.

За одну транзакцию сохраняются поля `salesOrderId`, `orderLabel`, `costCenter: 'order'`, `status: 'received'`, `receivedQty`, `receivedAt`, `receivedTo: 'direct'`. Транзакция использует существующий барьер финансов счёта и блокировки архивов заказов. Повтор приёмки уже полученных напрямую строк на тот же заказ возвращает `receivedCount: 0`. Если среди отправленных строк есть недопустимая, ни одна строка этой операции не меняется. Ответ остаётся карточкой счёта с `receivedCount`. Без `directOrderId` работает прежняя складская приёмка.

## Дополнение — направления затрат

В «Принять на объект» можно выбрать «На заказ», «На офис», «На цех» или «СМР». Для СМР можно указать название объекта. Если отмеченные позиции уже связаны с заказом, форма показывает этот заказ. После приёмки назначение отображается в строке счёта.

Для направлений без заказа запрос передаёт `directCostCenter` со значением `office`, `workshop` или `smr` и необязательный `directCostObject`. Приёмка проходит той же транзакцией. Повтор того же назначения не создаёт второй факт. Изменение назначения уже принятой строки возвращает конфликт. Обычная складская приёмка действует при отсутствии параметров прямой поставки.

В расходы следующей оплаты попадает направление с заявки. Проведённые платёжные снимки остаются в истории. Для их исправления есть отдельная переклассификация факта в «Деньгах».

Проверки на Mongo `datacore-test-c231-destinations` — 15/15. Проверены три новых назначения и заказ, нулевой остаток и отсутствие складского движения, повторы, конфликт смены назначения, фильтр расходов после оплаты. TypeScript и ESLint прошли.
