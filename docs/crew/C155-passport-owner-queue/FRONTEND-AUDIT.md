## Прохождение варианта и условия выпуска

- **Проверка шаблона.** Вкладка изделия при заданном типе делает `POST /passports/check` с `{productId, mode:'template', variant:passportVariant.value}`. Готовность считает по `check.missing`, рисунки — по `requiredImages` и `imageSlots`. Книжка этот результат не получает. `products/card-blocks.js:111`, `products/card-blocks.js:121`.
- **Книжка и единичный выпуск.** Глобальный `passportVariant` инициализируется `short`, меняется в прежней анкете и плане заказа. В состоянии и шапке книжки варианта нет, `GET /passports/:id` приходит без варианта, «Выпустить» после подтверждения отправляет `POST /passports/:id/issue` без тела. В карточке черновика есть второй путь выпуска, видимый при пустом `row.missing`; его запрос тоже без варианта. Кнопка книжки перед выпуском проверяет несохранённую правку на листе, без предварительного клиентского условия из «Сначала». `passports/dialogs.js:62`, `passports/book-editor.js:28`, `passports/book-editor.js:295`, `passports.js:171`, `passports/dialogs.js:17`.
- **Предпросмотр и PDF.** `POST /passports/preview` и `GET /passports/:id/pdf` получают глобальное значение при вызове. В диалоге печати пользователь выбирает формат, печать/подпись и прочие параметры, без выбора варианта. Для прикреплённого внешнего файла клиент отправляет запрос без параметров сборки. Поэтому даже после просмотра книжки вид PDF может определяться изменением переключателя в другом экране. `passports/dialogs.js:57`, `passports/dialogs.js:66`, `passports/dialogs.js:94`, `passports/dialogs.js:119`.
- **План заказа.** Переключатель обновляет общее значение и загружает `GET .../plan?variant=...`; одиночный и групповой `POST .../issue` и `GET .../pdf` отправляют вариант. В переходе в книжку вариант теряется. В старой анкете переключатель меняет раскладку, включая дополнительные рисунки, но `loadGaps(prod.id)` без варианта. Вспомогательная цепочка `issueFromProduct` создаёт экземпляр, читает `missing`, затем делает выпуск без варианта. Текущая воронка `funnel/index.js` открывает книжку и эту вспомогательную цепочку не вызывает. `order-passport-plan.js:70`, `order-passport-plan.js:87`, `order-passport-plan.js:128`, `order-passport-plan.js:266`, `passports/fill/index.js:72`, `passports/fill/index.js:207`, `passports/funnel/api.js:10`, `passports/funnel/api.js:50`, `passports/funnel/index.js:181`.

## Повторное использование, сохранение и рисунки

- Есть разные готовые источники для переиспользования. `passportParts` задаёт кандидатов частей с фильтром по типу, `passportElements` хранит тексты для описания, пользования и осмотра; `passportKinds` позволяет выбирать элементы, `passportInstall` — способы установки. Справочники уже различают «предлагают этому типу» и более полный перечень. Тексты по типам доступны в «Тексты паспорта» / «Общие разделы паспорта». В предыдущем редакторе элемента есть переход в форму справочника с возвратом, проверкой применимости и выбором добавленного. `backend/pwa/ui/materials-spec.js:33`, `backend/pwa/ui/materials-spec.js:161`, `dicts.js:98`, `dicts.js:325`, `dicts.js:340`, `dicts.js:153`, `dicts.js:181`, `passport-texts.js:59`, `passports/elements-block.js:24`, `passports/fill/control.js:165`. Части паспорта, функциональные элементы со своими инструкциями и позиции производственного дерева сейчас различаются. Рекомендуется переиспользовать существующий справочник по смыслу и добавить понятный выбор/возврат в книжке, без объединения таблиц по схожести подписей.
- В экземпляре «Только в этом паспорте» сохраняет правки через `snapshot-field` / `snapshot-item`, числовые и прочие поля — через `PATCH /passports/:id`. «В справочник» получает цель и число затронутых изделий и требует подтверждения. Правая панель и дерево пишут в изделие даже при входе через конкретный паспорт. Код допускает явную правку уже выпущенного: кнопка «Сохранить и выпустить заново» после изменения перечитывает паспорт и открывает печать, отдельного вызова выпуска в этом действии нет. При развязке входов шаблон должен писать только источники изделия, экземпляр — только его поля/явные переопределения. Проверить ранее выпущенный PDF после изменения шаблона и повторного импорта отдельно от сознательной правки самого экземпляра. `passports/book-blocks.js:29`, `passports/book-editor.js:107`, `passports/book-editor.js:166`, `passports/book-editor.js:179`, `passports/book-editor.js:295`, `passports/book-editor.js:334`.
- Общая и узкие кнопки ИИ копируют текст в буфер. Человек прикладывает рисунок к внешнему чату вручную и переносит результат; кнопки не распознают файл в PWA и не сохраняют результат. В существующем «части по фото» запрошены колонки технической таблицы, включая материал и размер, когда они видны. Для short использовать выбор видимых частей и черновик грамотной фразы. Массу, материал/марку, скрытое устройство, нагрузку и способ крепления по внешнему виду не определять. Числа из читаемой выноски чертежа можно предложить с указанием места и подтверждением. Дополнение справочника — отдельное явное действие после проверки дублей. `passports/book-editor.js:55`, `passports/book-side-edit.js:18`, `passports/book-side-edit.js:49`, `passports/book-shared.js:30`, `passports/book-shared.js:48`, `passports/book-shared.js:99`, `passports/book-shared.js:152`.
- PWA отдаёт канон `backend/pwa/ilogic/passport-images.iLogicVb`; `tools/passport-images.iLogicVb:1` — указатель. В каноне ищется уникальный точный артикул, затем подтверждаются изделие, перезапись размеров/массы, глубины и имеющихся рисунков. Масса из свойств CAD записывается только если больше нуля. Три PNG загружаются отдельно, потом добавляются связи `overview`, `dimensions`, `foundation`; размеры в мм, доступная масса и одобренная глубина идут в `PATCH /showcase/:id`. Старые связи удаляются после добавления новых, новые проверяются перечитыванием, глубина проверяется отдельно. При ошибке добавления или PATCH предусмотрен откат новых связей.
