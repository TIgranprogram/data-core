# C240 — совмещение возможностей роли и экраны склада директора

23.11.2026. Владелец спросил о совмещении ролей и поручил «сделай как лучше грамотно»; затем подтвердил продолжение всех задач. Требуется дать директору просмотр экранов «Труборез» и «Лазер лист», сохранив понятное управление правами и разделение просмотра/изменений.

Статус: архитектурное решение до реализации. Класс M/L уточнить. Факты: users.role — одна строка; пользовательские permissions объединяются с permissions роли; custom roles имеют baseRole/appSections. Сейчас PWA main.js258 показывает ссылки stock pipe/sheet/wood только isAdmin, route-access.js canViewStock пропускает admin либо рабочую roleLabel соответствующего экрана. Одна галочка раздела stock директору эти экраны не открывает.

Предпочтение координатора: сохранить одну основную роль и выдать дополнительные явно именованные возможности/экраны через существующую модель прав. Не вводить массив нескольких базовых ролей и не менять isOwner/admin/деньги/ФОТ ради просмотра. Точное решение принимает архитектор после проверки role registry, permission validator, auth projection, route gates, stock scope и grid mutation controls.

Критерии: директор с разрешённым разделом склада видит обе ссылки и открывает оба экрана; рабочие роли сохраняют свой экран и ограничения склада; без права доступа меню и прямой URL одинаково отказывают. Просмотр сам по себе не разрешает изменение остатков, приёмку/списание, складские операции или управление ролями. Существующие серверные ACL и owner-only границы сохраняются. Настройки должны быть объяснимы владельцу и применяться после обычного обновления профиля/входа.

Не менять реальные учётки/роли на проде до точного плана. Подготовка кода и адресные проверки разрешены в рамках поручения; изменения безопасности — с архитектурной и QA-проверкой. Сначала решение и список файлов, затем отдельные scope владельцам backend/frontend. Другие задачи C237–C239 не откатывать.
