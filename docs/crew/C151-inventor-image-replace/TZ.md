# C151 — повторная загрузка рисунков из Inventor

Поручение владельца 18.11: правило открыло паспорт, но общий вид остался старым; ручная загрузка добавила новый рядом со старым, пришлось удалить прежний. Проверить и исправить сценарий, затем выложить вместе с текущими исправлениями.

## Scope и порядок

Сначала аудит факта: pwa/ilogic/passport-images.iLogicVb (загрузка/привязка/удаление прежних/открытие), modules/product-photo и product-passport/passport-product-images, effectiveImages/снимок issued, общий вход open-book/book-entry, список паспортов и книжка. Роль доступа — readonly prod 3218 (статус, свои/эффективные рисунки и productphotos purpose=passport), проверочные записи только на копии. Backend — основной читатель серверного кода, отчёт AUDIT.md; до локализации причины код не менять.

Не удалять файлы и исторические снимки. Повторная отправка заменяет целевые рисунки изделия без дублей; посторонние виды/назначения сохраняются. Ошибка загрузки не оставляет пустой набор. Уже выпущенный паспорт не получает незаметной подмены рисунков — открываемый после импорта редактор должен явно работать с обновлённым источником/новым черновиком либо явной новой редакцией.

## Факты и контракт исправления

На чтении прода 3218 уже issued №613; images и effectiveImages — собственный снимок, у изделия три ссылки passport. Эти факты не доказывают, какой PNG менеджер считал новым. Кодом подтверждены три независимых разрыва (AUDIT.md): product-вход выбирает issued при отсутствии draft; ручная зона с обещанием замены делает append; миниатюра draft списка читает собственные images вместо актуальных рисунков изделия.

1. Прямой product-вход #products?bookFor=… (включая уже установленное правило Inventor) работает с черновиком из текущего изделия. При отсутствии draft создаётся новый; выданный остаётся снимком. Обычное открытие конкретного выданного паспорта не меняется. Фирма определяется существующим createBookDraft (без случайного выбора).
2. Для imageStrip ручная загрузка/вставка в заполненный слот явно заменяет рисунки этого вида, оставляя прочие виды и файлы. Если поддерживается добавление ещё одного рисунка, оно отдельным явным действием с соответствующей подписью. Не подменять наследуемые рисунки записью в images[]: они обновляются через изделие.
3. Миниатюра draft использует тот же приоритет passport productphotos overview, что effectiveImages. Issued — собственный снимок. Витринные фото другого purpose не становятся рисунком паспорта.
4. Существующий алгоритм правила attach3 → проверка → delete прежних целевых связей сохраняется; дополнить проверкой результата после замены (именно новые linkId и по одному целевому kind). Неполный/конкурентный результат не объявлять успешным. Переключение на другой API/автоматическое удаление чужих файлов не вводить.
