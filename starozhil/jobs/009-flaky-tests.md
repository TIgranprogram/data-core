# Цель
Разобрать нестабильные юнит-тесты (Р5 плана Старожила): какие падают не каждый раз и почему — чтобы ворота выкладки не краснели зря.

# Что читать
1. `tools/logs/starozhil/flaky/FACTS.md` — программа уже прогнала весь юнит 3 раза: разделы «Флаки» и «Падают всегда».
2. Для каждого теста из «Флаки» (не больше 5): открой его файл `*.spec.ts` (путь — в строке), найди тест по названию (`search`), посмотри: время (`Date.now`, `new Date`, таймеры `setTimeout`), случайность (`Math.random`), порядок (общие данные между тестами, `beforeAll` без сброса), сеть.

# Нельзя
- Не менять тесты и код.
- «Падают всегда» не разбирать подробно — только перечислить (это не флаки, их чинит Claude).

# Итог (формат finish)
Таблица ≤ 5 строк: | Тест (файл › название) | Упал N из 3 | Вероятная причина (время / случайность / порядок / нагрузка / другое) | Где (файл:строка) |
Потом одной строкой — список «падают всегда», если есть.
Флаков нет — так и написать (пустой итог допустим).

# Как проверит Claude
Строки ссылаются на тесты из FACTS.md; причина видна в коде по файл:строка.
