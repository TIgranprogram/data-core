## 1. Картина одной страницей

**Что это.** Одно приложение «Рабочее место» для производственной фирмы: КП → заказ → проектирование → производство → снабжение → склад → отгрузка → паспорт изделия → деньги. Сервер — 72 модуля, около 41 000 строк. Сайт работает, выпуск v1.693.

**Бизнес-логика.** Все 16 звеньев цепочки существуют и работают. Слабое место — стыки: в 10 местах человек переносит данные руками (A4 §2). Три стыка дают неверную картину: ложная готовность заказа, отгрузка недоделанного, заказ из КП без цен.

**Архитектура.** Основа здоровая: циклов между модулями — один, мёртвого кода почти нет, тестов много. Долги: нет защиты от одновременной правки, 861 прямой запрос к базе без общих правил, восемь файлов растут сверх порога.

**Документация.** Была главной проблемой: вход в очередь из пяти слоёв разных дат, 82 % ссылок бэклога вели в пустоту, страница контроля отставала на 98 выпусков, восемь заданий отсутствовали на доске. Исправлено в этой задаче (раздел 3).

**Узкое место проекта — решения владельца.** 22 действия и решения ждут до трёх недель; пароль `admin` — с 21 октября.

### C068-1. Честная готовность заказа — класс M, агентов ≤ 2 (backend, qa)

- **Проблема.** `readinessChecks` считает пункт «Материалы со склада выданы» выполненным при `activeReservations === 0`. Броней не делали — пункт зелёный, заказ «готов».
- **Место.** `backend/src/modules/salesorders/order-readiness.ts:10, 24, 44–55`; тест рядом (`order-readiness.spec.ts`, если есть — дополнить, нет — создать).
- **Требование.** Добавить факт `issuedReservations` (брони заказа не `active` и не отменённые) и `stockOut` (движения расхода со ссылкой на заказ, если поле есть — проверить схему `stockmovements`). Пункт «выдано»: зелёный — есть выдача и нет активных броней; красный — есть активные брони; **третье состояние «не проверено»** — броней и выдач нет вовсе. «Не проверено» не блокирует `ready`, но показывается подсказкой «Материалы под заказ не бронировались».
- **Контракт.** В `ReadinessCheck` добавить необязательное поле `state: 'ok' | 'wait' | 'unknown'`; `ok: boolean` оставить (клиенты читают). Экран `pwa` — показать «не проверено» серым; правка вида S.
- **Не трогать.** Смену этапов заказа; отгрузку.
- **Приёмка.** Юнит: три состояния. Заказ без броней — пункт серый, текст подсказки. `tsc` 0, юнит зелёный, `node --input-type=module --check` для файла экрана.

### C049-4. Страж прав на маршруты — класс S, без агентов

- **Требование.** Юнит-тест в `backend/src/common/` обходит все контроллеры (`app.module` → метаданные Nest) и падает, если у маршрута нет ни `@Roles`, ни `@Permissions`, ни `@Public`. Белый список с причиной: `meta.controller.ts` (любой вошедший).
- **Приёмка.** Тест зелёный на текущем коде; временно снятый декоратор делает его красным.

### C068-9. Цикл `design ↔ matching` — класс S, без агентов

### C049-3. Индексы из реестра моделей — класс M, агентов ≤ 2 (backend, architect)
