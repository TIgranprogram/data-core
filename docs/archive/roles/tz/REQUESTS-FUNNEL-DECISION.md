# Заявки — воронка и счёт: решение (architect/opus, 2026-10-28)

1. **Счёт — отдельная коллекция `supplyinvoices`, в заявке `invoiceId?`.** Только поле-группа `invoiceNo` не подходит: у черновика счёта ещё нет №, сумма счёта ≠ сумма строк (доставка), нужен файл и статус. Новая коллекция CRM не трогает (она её не знает). `invoiceNo/invoiceDate/paid/paidAt` в заявках остаются **копией**, которую пишет только сервер из счёта. Поэтому CRM и календарь (`invoiceDate`) работают без правок. Схема `supplyrequests` — одно новое необязательное поле + индекс `{invoiceId:1}` (через `ensure-indexes.js`).
2. **Ворота — на сервере, но только в новых путях.** Строго: `POST /supply/invoices`, `PATCH /supply/invoices/:id`, `POST …/:id/pay`. В старом `PATCH /supply/requests/:id` — проверка только при `source=app` (поле в теле, разрешить в DTO). CRM, импорт из таблиц и `invoice.js` идут без ворот. Таблица ворот — одна константа в `supply/` (общая сервер+текст ошибки); приложение берёт её копию для чек-листа.
3. **Порядок.**
   - Шаг 1 (быстрая победа, без сервера, выложить сразу): доска по умолчанию; строка «что делать» в шапке колонки; в карточке чек-лист и одна кнопка-глагол; «Оплачено» без № и даты счёта → открыть панель на этих полях, не менять статус. Мультивыбор в «Заказать» → «Заказал у поставщика». Переименовать «+ Счёт» → «Счёт без заявок».
   - Шаг 2 (сервер): схема/сервис `supplyinvoices`, 3 маршрута с `@Roles` (оплата — денежные роли), DTO, e2e на ворота и на копирование полей. openapi, MAP, UNIFIED-DB-MAP.
   - Шаг 3 (приложение): групповое «В работу» → авто-счёт; блок «Счёт» в панели; «Счёт оплачен» на всю группу; чип «Счета» — позже.
4. **Подводные камни.**
   - Правка счёта (№, дата, сумма, плательщик) → сервер в той же операции `updateMany({invoiceId, deletedAt:null})` копирует поля в строки. Сумму делить пропорционально `lineTotal`, остаток копеек — на последнюю строку. Транзакция rs0 есть — использовать сессию.
   - Оплата: только весь счёт (`paid`+`paidAt` всем строкам). Частичная оплата — не делать; при нужде — разделить счёт (перенести строки в новый счёт).
   - Удаление счёта — мягкое (`deletedAt`); строки: `invoiceId` снять, `invoiceNo/invoiceDate` очистить, статус вернуть `requested`, если не оплачен. Оплаченный счёт удалить нельзя (400). Отмена последней строки → счёт `cancelled`.
   - Строку нельзя перенести в другой счёт, если её счёт оплачен. Ручная правка `invoiceNo` у строки со счётом с `source=app` — 400 («правьте счёт»).
   - Поставщик счёта = поставщик строк; разные поставщики → сервер делит на несколько счетов.
   - Старые заявки без `invoiceId` работают как раньше; код не должен требовать счёт для них.
   - Mongo 4.4: без `$setWindowFields`, без `$getField`; пропорции считать в приложении-сервере, не в агрегации.
5. **Вопросы аналитика — согласен со всеми тремя по умолчанию:** счёт = один поставщик; оплата — только всем счётом; старые заявки задним числом не группировать (скрипт — позже, план → `--apply`, по «да» пользователя).
