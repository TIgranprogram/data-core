# Пульт DataCore

Пульт — окно Windows с кнопками для работы с сайтом. Он заменяет ручной ввод команд в PowerShell.

Кнопки собраны по разделам. У каждой кнопки есть подсказка, отметка риска и примерное время. Ход выполнения виден справа. Полный вывод остаётся в `pult/logs/`.

Полный список кнопок: [docs/КОМАНДЫ.md](docs/КОМАНДЫ.md). Файл собирается автоматически.

## Как запустить

1. Откройте папку `pult`.
2. Дважды нажмите `Pult.cmd`.
3. Разрешите запуск от имени администратора.

Откажетесь от прав — пульт откроется с обычными правами. Все кнопки работают и так.

Ярлык на рабочий стол: «Настройка ПК → Ярлык пульта на рабочий стол».

Нужны Node.js 20+ и Git для Windows. Окно открывает Edge, его нет — браузер по умолчанию. Установка не нужна. Закроете окно — пульт сам завершится через 15 секунд, если нет идущих команд.

## Что видно в окне

| Место | Что там |
|--|--|
| Верхняя полоса | Локальное состояние (production проверяется только отдельной кнопкой «Проверить прод»), есть ли незакоммиченный код, совпадает ли GitHub, Docker, способ входа на сервер |
| Слева | Экран «Что делать сейчас», разделы по группам, поиск, значения отметок |
| Посередине | Карточки команд |
| Справа | Вкладки запусков, вывод, кнопка «Остановить», совет «Что делать» при известной ошибке. Крестик закрывает вкладку, «Закрыть все» — все завершённые. Журналы при этом остаются |

Плашка «Выкладка закрыта» значит: в `backend` или `deploy` есть файлы без коммита. Наведите на плашку — появится список файлов. Ворота выкладки остановят запуск по этой же причине.

## Что делать сейчас

Это первый экран пульта. Он сам смотрит на проект и раскладывает дела на три уровня:

| Уровень | Что сюда попадает |
|--|--|
| Сначала это | Сайт не отвечает, осмотр нашёл ✗, выкладка не прошла, на ПК нет ключа |
| Сегодня | «Начало работы» за день, GitHub не совпадает, готовый код не на сайте, проверки после выкладки |
| Рекомендуется | Запущенные стенды с кнопкой остановки. Подошёл срок: осмотр и данные раз в неделю, учебное восстановление раз в месяц. Файлы без коммита: обычно это работа Claude |

У каждого пункта есть причина и кнопка. Выполненный пункт исчезает сам. Ниже идёт список «Сделано сегодня». Самое важное дело отмечено «Начните с этого». Красное число в меню — сколько дел ждёт человека. Плановые дела и незавершённая работа Claude в него не входят.

Пульт запоминает последний запуск каждой кнопки в `logs/runs.json`. Файл свой на каждом ПК. Команды, запущенные мимо пульта, он не видит.

Уровень «Нужно от вас» — поручения Claude из `todo.json`. Это всё, что Claude сам сделать не может. У пункта с командой есть кнопка «Запустить», пункт уходит сам после успешного запуска. У ручного пункта — «Открыть» и «Сделано». Поле `after` показывает шаг только после предыдущего. Отметки хранятся в `logs/runs.json`, сам файл поручений идёт в git.

Правила — в `advisor.mjs`. Новая регулярная команда: поля `every` и `why` в `catalog.mjs`, правила менять не нужно.

## Разделы и цвета

Разделы собраны в пять групп. У каждой группы свой цвет: полоса в меню и сверху на карточке.

| Цвет | Группа | Разделы |
|--|--|--|
| Серый | — | Что делать сейчас |
| Синий | Рабочий сайт | Каждый день, Выкладка, Сервер сайта, Правка данных |
| Бирюзовый | Копии и второй сервер | Копии базы, Sportin |
| Фиолетовый | Разработка | Проверка кода, Стенды, Git |
| Оранжевый | Этот компьютер | Автозапуск, Настройка ПК, Ссылки и папки |

Цвет группы задаёт поле `color` в `GROUPS` (`catalog.mjs`), сам цвет — `--g-<color>` в `ui/style.css`.

## Автозапуск

Раздел «Автозапуск» запускает команды сам, пока пульт открыт. Умолчания — `SCHEDULE` в `catalog.mjs`:

| Команда | Когда |
|--|--|
| Начало работы | Каждый день в 09:00 |
| Ошибки с сайта за сутки | Каждый день в 18:00 |
| Осмотр сайта | Пн в 09:30 |
| Что заполнить в данных | Пн в 10:00 |
| Быстрая проверка кода | Пт в 17:00 |
| Учебное восстановление на Sportin | 1-го числа в 12:00 |

- Ритм, день и время меняются на экране. Правки хранятся в `logs/schedule.json`, у каждого ПК свои.
- ПК спал или пульт был закрыт — пропущенная команда идёт при следующем открытии, один раз.
- Команда уже шла руками после срока — повтора нет.
- Команды идут по одной и только когда ничего не идёт. Вкладка автозапуска отмечена ⏰.
- Запись на рабочий сайт на автозапуск не ставится: это проверяет тест `test/schedule.test.mjs`.
- Задачи Windows (ночной прогон, копия базы на ПК, обновление Sportin) работают и при закрытом пульте. Их карточки — в том же разделе.

## Стенды

Собственный стенд на копии получает уникальный project, volumes и БД с суффиксом `-night`. Паспорт запуска хранится в `tools/.night/stands/<id>/run.json`. Старый `dcnight` и неизвестные ресурсы не управляются. «Остановить» сохраняет базу, volumes и сеть. Полный ночной прогон создаёт отдельный новый стенд на свободных loopback-портах и останавливает только свои контейнеры; прежний стенд не пересоздаёт. Итог сохраняется локально, production transport не вызывается.

Раздел «Стенды» показывает одну карточку на стенд: статус «Запущен» или «Остановлен» и одну кнопку, которая запускает или останавливает. Статус читается из Docker, обновляется раз в минуту и после каждой команды. Новая карточка: запись в `SWITCHES` и две команды с `hidden: true` в `catalog.mjs`.

## Отметки риска

| Отметка | Значит | Перед запуском |
|--|--|--|
| Только чтение | Ничего не меняет | Ничего |
| Сайт не затрагивает | Меняет этот ПК, стенд или GitHub | Окно подтверждения только у копии на Sportin |
| Меняет сайт | Меняет рабочий сайт | Окно подтверждения |
| Опасно | Меняет рабочий сайт или данные | Окно подтверждения и ввод слова |

## Защита

- Сервер пульта слушает только `127.0.0.1`. С другого компьютера он недоступен.
- Сервер запускает только записи из `catalog.mjs`. Команду из браузера он не принимает.
- Подтверждение проверяет сервер, а не страница.
- Значения параметров берутся только из списка.
- Одновременно идёт только одна запись на сайт.
- Пароли и ключи закрываются маской в окне и в журнале.
- В списке разовых скриптов только скрипты с режимом плана (`--apply`). Скрипты `drop-*` на кнопки не выносятся.
- На кнопках нет `deploy.py --wipe`, `--drop-archive` и архива доступов без пароля.

## Как пульт остаётся актуальным

Один файл `catalog.mjs` строит кнопки, проверки сервера и справку `docs/КОМАНДЫ.md`.

Сверка `audit.mjs` смотрит папки `deploy/synology`, `remote-access`, `SRV-ERP`, `tools`, `tools/kit` и подкоманды `tools/dc.mjs`. Она находит:

- скрипт без кнопки и без причины в `NOT_ON_BUTTONS`;
- кнопку, которая ведёт на удалённый файл;
- подкоманду dc без кнопки.

| Где срабатывает | Что видно |
|--|--|
| Окно пульта | Жёлтая полоса со списком находок |
| `tools/dc.cmd check` | Строка «пульт: ОТСТАЛ» и код выхода 1 |
| Кнопка «Тесты инструментов» | Упавший тест |

Справка отстала от каталога — падает тест `справка собрана из текущего каталога`.

**Код пульта обновляется сам (2026-10-31).** Пульт помнит отпечаток своих файлов (`pult/*.mjs`, `pult/ui/*`). Изменился и ничего не идёт — пульт перезапускается на том же порту, окно перезагружается само («Пульт обновился — перезагружаю окно…»). Идёт команда — после неё. Новый запуск `Pult.cmd` при старом процессе просит его уступить порт (`/api/upgrade`). Закрывать и открывать пульт после правок Claude не нужно.

**Экран сам показывает последнюю проверку (2026-11-03).** На «Что делать сейчас» всегда видно, какая проверка была последней и чем кончилась. Замечание или сбой оставляет кнопку этой же проверки. Окно, которое снова стало видимым, обновляет состояние само. «Быстрая проверка» каждый день в 09:10, если пульт открыт; пропущенное догоняется при открытии.

## Готовые решения (проверены 2026-10-31) — брать отсюда, не писать заново

| Задача | Как запускать | Что делает | Повтор |
|--|--|--|--|
| Справочник серий из изделий | «Скрипт: записать» → `series-dict-fill` | серии, вписанные у изделий, → справочник «Серии изделий» | безопасен, 0 изменений |
| Название в договоре и фото изделий | `products-fill-defaults` | пустое «Название в договоре» ← короткое; нет фото ← фото паспорта | безопасен |
| Категории изделий и паспортов | `products-category-from-passports`, затем `passports-category-from-product` | изделию — категория его выданных паспортов; паспорт — по изделию только где право изделие (список `PRODUCT_WINS`) | безопасен |
| Обновить Sportin | «Обновить копию на Sportin» (база и фото / с кодом) | копия прода на второй сервер; SMB-цели Sportin сохраняются | безопасен |
| Копии на NAS по SMB | «Копии на NAS: установить на Sportin» / «…на домашнем сервере» | smbclient в контейнере, cron: проверка раз в минуту, отправка 04:00; место — в админке | безопасен |
| Тестовый вход на стенд | `docker exec … node scripts/stand-test-user.js` (STAND=1) | логин `stand-test`, пароль — `tools/logs/stand-login.txt` | безопасен |

Как писать новый скрипт данных: образец — `backend/scripts/products-fill-defaults.js` (план без записи → `--apply`, выгрузка для отката, запуск через stdin, проверка на стенде на копии базы: план → запись → повторный план = 0). Пункт в пульте — по разделу «Правила для Claude». Несколько шагов подряд — цепочка `after`; «Выполнить все по очереди» запускает только доступные read-only команды. Изменение сайта и другие команды с подтверждением запускаются по отдельной кнопке.

## Правила для Claude: поручения в «Нужно от вас» (todo.json)

Пользователь не должен помнить порядок, имена скриптов и перезапускать пульт. Поэтому:

1. **Один пункт — одно действие.** Несколько скриптов — несколько пунктов; порядок — полем `after` (следующий виден только после успешного предыдущего). Ручной пункт без команды помечать `"manual": true`; он показывает кнопки «Сделано» и, если указана ссылка, «Открыть».
2. **Команда с полями — значения в `params`.** Для `script-apply` / `script-plan` обязательно `"params": { "script": "<имя без .js>" }`; для `sportin-copy` — `"params": { "mode": "--code" }`, если нужен код. Без `params` у `script-apply` пульт запуск отклонит («Выберите скрипт»). Пункт закрывается только запуском со своими `params`.
3. **`why` — что изменится, на языке пользователя:** «468 изделий получат…», «Перед записью сделается копия базы». Без команд, путей, флагов.
4. **Скрипт для `script-apply`** должен работать через stdin (`remote-access/run-script.sh` — `node -`): точка входа `if (require.main === module || String(module.id).includes('[stdin]'))`, `--apply` без `--out` — выгрузка в `/tmp`. Проверить на стенде на копии базы: план → `--apply` → повторный план = 0.
5. **Новый скрипт или кнопка** — `catalog.mjs` (кнопка или причина в `NOT_ON_BUTTONS`) → `node pult/gen-docs.mjs` → `node --test pult/test/` → `tools/dc.cmd check`. Тест `todo.json: у каждой команды со скриптом указан скрипт` ловит пункт без `params`.
6. **Проверка в окне пульта** — только с перехватом `/api/run` (ничего не запускать): пункт отправляет нужные `params`, кнопки каталога работают.
7. **`added` — время постановки, не позже текущего** (местное время без зоны). Пункт закрывается запуском после `added`; время в будущем — пункт не закроется никогда (тест ловит). Пункт `deploy-release` закрывается сам, если на сайте уже этот код (`version.json` совпадает с HEAD по файлам `backend`/`deploy`).
8. Пункт, который можно отложить, ставить после срочных; срочное — первым в файле (порядок в файле = порядок на экране).

## Как добавить кнопку

1. Откройте `catalog.mjs`. В начале файла описаны поля записи.
2. Добавьте запись в нужный раздел.
3. Запись на сайт: `risk: 'prod-write'` и `confirm`. Опасная запись: `risk: 'danger'`, `confirm` и `word`.
4. Выполните `node pult/gen-docs.mjs`.
5. Выполните `node --test pult/test/*.test.mjs`.

Скрипт не нужен на кнопке — запишите его и причину в `NOT_ON_BUTTONS`.

Команда, которая ждёт ввода с клавиатуры, на кнопку не подходит: окно пульта ввод не принимает.

## Если что-то не так

| Что видно | Что делать |
|--|--|
| Окно не открылось | Откройте адрес `http://127.0.0.1:47811/` в браузере |
| «Порт занят другой программой» | Задайте переменную `PULT_PORT` с другим номером |
| Кнопка серая | Причина написана на карточке |
| Жёлтая полоса вверху | Попросите Claude обновить `pult/catalog.mjs` |
| Нужен полный вывод | «Ссылки и папки → Журналы пульта» |
