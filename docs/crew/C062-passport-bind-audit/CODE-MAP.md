# C062 — карта кода (факты, без правок)

Снято 2026-11-11 по схемам и `docs/PASSPORTS-V2.md` §3.4, §10, PRODUCT §5а, C054/C055/C056, отчёт C060. Код не менялся.

## Экземпляр — `productpassports`

`backend/src/modules/product-passport/product-passport.schema.ts`

| Поле | Строки | Смысл |
|--|--|--|

| `productId` | 58–59 | модель, необязателен |

Черновик: в `passportNumber` служебное `draft-<id>`, человеку «—» (`PASSPORTS-V2.md` §10). Выпуск `POST /passports/:id/issue` — номер, заводской, талон, снимок в одной транзакции. Повторный выпуск того же документа номер не меняет (§10). `newRevision` — номер тот же, редакция +1.

Создание: `product-passport.service.ts` `create` ~230 — без явного номера статус `draft`, номера нет. `allocate` ~188 — номер из счётчика только когда выпускают.

Заказ: `createDraftsForOrder` ~252 — один черновик на позицию с изделием; если живой (не аннулирован) уже есть, позицию пропускает. Уникального индекса нет: второй живой паспорт на ту же позицию ручным созданием возможен. `qty` в план попадает (`passport-order.ts`), но паспортов по количеству не плодит: 1 строка = 1 документ (отчёт C060).

C060 `passport-reuse.ts` `takeOverNumbers`: после аннулирования новый выпуск той же пары `incomeId`+`productId` забирает старый номер. Отчёт есть, на прод не выложен. Это не поле на продукции.

## Шаблон модели — не номер

- `products.passportDefaults` — умолчания следующего паспорта (категория, тексты, признаки). Номера паспорта там нет.
- `products.hasPassport` — флажок `boolean`, не номер (`common/catalog/product.schema.ts:50`).
- `passporttemplates` — тексты категории («Для всех» и категория). Это не экземпляр.
- Вкладка «Продукция → Паспорт» (C056): карточка шаблона + таблица выпущенных (№, дата, заказчик, заказ). `productCode` в таблице нет.

## Печать

`GET /passports/:id/pdf` собирает PDF заново из снимка. Сохранённого файла у номера нет. Прикрепить свой PDF и печатать его — в данных нет.

## Чего в карте нет (дыры под желание)

1. Обязательный `productId` при ручном выпуске — сейчас поле необязательно.
2. Файл на экземпляр и пометки «С сайта» / «Файл». `source: app` близко к «С сайта», но на экране так не сказано.
3. Запрет второго живого паспорта на один `incomeId` — только проверка в черновиках заказа, не замок.
4. Колонка заводского номера во вкладке изделия — нет. Номер паспорта в таблице уже есть.
