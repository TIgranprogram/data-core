# C160. Проверка журнала ошибок

**Вердикт: можно.** Повторная проверка зафиксированной версии C160 закрыла все три P1. Независимый прогон — 16/16 тестов, в том числе три с перехватом POST журнала. `error-http-report.test.mjs:36,53,64`.

- **Секрет в маршруте — исправлено.** Параметры маршрута проходят проверку до сборки строки, текстовый ключ контрагента скрыт, ошибочное `open=undefined` остаётся видимым. На выходе поля отчёта очищаются повторно. `core/error-context.js:18,35`, `core/errors.js:52,65`.
- **След прежнего пользователя — исправлено.** Постоянная очередь хранит копию без истории нажатий. При выходе след снимается и с отчётов в памяти. Поздний отказ отправки учитывает смену сессии. `core/errors.js:31,39,43,112`.
- **Значение поля в ответе 4xx — исправлено.** Журнал получает безопасное сообщение, статус и историю действий. Многострочный текст ответа и стек этой ошибки не копируются. Форма получает первоначальную ошибку, обычный JS Error сохраняет сообщение и стек. `core/error-context.js:43`, `core/errors.js:61,65`, `core/api.js:89`.

Обычный HTTP 400 доступен вызывающему коду и попадает в журнал один раз. Для 4xx фильтр исключает пути auth, client-errors и локальную блокировку view-as. Отправщик пользуется отдельным `apiQuiet`; новый модуль контекста не импортирует другие модули.
