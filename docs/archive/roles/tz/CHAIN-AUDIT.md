## 2. Разрывы (по важности)
1. **Счёт не виден целиком.** Нет списка счетов. Предложение: `GET /api/supply/invoices` (фильтры: статус, поставщик, заказ, период) + экран «Счета» с раскрытием.
2. **Приход по счёту — по одной заявке.** Предложение: `POST /api/supply/invoices/:id/receive` — принять все строки (или отмеченные, с кол-вом) одной транзакцией; заявки → `received`, приход с `salesOrderId` заявки.
3. **Заявка ↔ заказ слабая.** Предложение: при создании из заказа/позиции — `salesOrderId` + позиция ставятся сами; на карточке заявки — «Заказ № 21-26 поз 5»; фильтр «по заказу».
4. **«Готов к отгрузке» — ручной.** Предложение — п. 5 ниже (подсказка, не автоперевод).
5. **Договоры без заказа не собираются пачкой.** Предложение — п. 4.
6. **КП нет.** Оставить вне волн (ДМ.8, XL отдельно).

## 3. Чек-лист «Заявки 10/10»
| # | Пункт | Если … то … |
|--|--|--|
| З1 | Цена по умолчанию | Если выбрана позиция склада, то цена, ед., поставщик заполняются из `GET /api/materials/:id/price-default` серым «из последней закупки»; ручная правка не перетирается. |
| З2 | Выбор из 2–3 поставщиков | Если в истории (`/materials/:id/prices`) ≥ 2 поставщиков, то под полем — чипы «Поставщик · цена · дата» (до 3, свежие сверху); клик заполняет оба поля. |
| З3 | Из поставщика | Если выбран поставщик без позиции, то подсказка позиций из его каталога (`supplieritems`) и прошлых заявок. |
| З4 | Из заказа | Если заявка создана из позиции заказа, то заказ, позиция, заказчик, кол-во ставятся сами и видны как «Заказ № N поз M». |
| З5 | Связь видна | Если у заявки есть `salesOrderId`, то на доске и в списке — метка заказа; фильтр «По заказу» работает. |
| З6 | Из счёта | Если заявка в счёте, то № счёта, дата, поставщик берутся из счёта; в заявке не правятся (только в счёте). |
| З7 | Следующий шаг | Если заявке не хватает данных для этапа, то карточка показывает одну кнопку и чек-лист недостающего (есть — проверить на всех 5 этапах). |
| З8 | Список «Счета» | Если открыть «Счета», то видны все счета: №, дата, поставщик, сумма, оплачено, статус, заказы; фильтры статус/поставщик/период; сумма внизу. |
| З9 | Раскрытие счёта | Если раскрыть строку, то видны позиции (наименование, кол-во, цена, сумма, статус заявки), оплаты, заказы/договоры, цепочка «заявка → счёт → оплата → приход». |

## 4. Договоры → заказ
Есть: список по заказам, «+ Договор в этот заказ» (`salesorders.js:302`), выбор № с подсказкой (:349), запрет снятия при выдачах/отгрузках (PRODUCTION-ORDERS п.6).
Нет:
- фильтр «Договоры без заказа» (`productionNo` пуст) — отдельный вид списка;
- галочки + кнопка «В заказ» → панель справа: «Новый заказ (свободный №)» / «Существующий» (список № в работе) → подтверждение;
- сервер: `POST /api/production-orders/assign { orderIds[], productionNo | new:true }` — одной операцией, с историей, `productionAddedAt` по порядку выбора; договоры в другом заказе с выдачами — 409 по каждому;
- «Добавить существующий договор» из карточки заказа (сейчас только новый).

## 5. Этапы заказа до отгрузки (предложение)
Оставить `ORDER_STAGES` (без новых значений — CRM читает): new «Новый» → production «В работе» → ready «Готов к отгрузке» → partly → shipped → closed.
«Готов к отгрузке» = правило-подсказка: все позиции «К производству» сделаны (отметка «Изготовлено» по позиции) **и** проектирование done **и** нет открытых заявок под заказ. Когда правило выполнено — в карточке кнопка «Отметить: готов к отгрузке»; сам этап не меняется. Чек-лист «чего не хватает» — как в заявках.
Нужна отметка готовности позиции: `incomes.madeQty?` (новое поле data-core; `incomes` — проверить, не общая ли с CRM).
