## Чего хочет пользователь (критерий приёмки)
1. Выбор идёт сверху вниз: **категория → вид изделия (элемент/тип) → конструкция (материал, соединения: болты / сварка / цельное) → способ установки**. Каждый шаг сужает следующий.
2. В паспорт попадают **только** пункты, условия которых совпали с выбором. Пункт без условия — действительно общий для всех (гарантия, рекламации, журналы).
3. Пользователь сам делает паспорт решётки 597 в экране за ≤ 5 минут, и в PDF нет ни одного пункта из таблицы выше.
4. Партия (много размеров) — в экране: таблица «размеры» в паспорте.
5. Правка пункта «только для этого паспорта» — в экране.

## Направление (проверить analyst + opus, не догма)
- У пункта шаблона и дефекта — условия: категории, способы установки, признаки конструкции (`hasBolts`, `hasWelds`, `hasConcrete`, `hasMovingParts`, `hasWood`…). Признаки ставит воронка (и изделие по умолчанию), не человек на каждом паспорте.
- Аудит всех пунктов «Для всех» скриптом: какой пункт к каким категориям/признакам на самом деле относится (отчёт → решение пользователя → `--apply`).
- Не новые коллекции (правило 2026-10-22): `dict_values`, `passporttemplates`, `productpassports` — только добавлять поля; схема общая с kppdf.
