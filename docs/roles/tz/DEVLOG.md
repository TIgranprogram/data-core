## 2. Трудозатраты (пример, реальный прогон)
Правило: коммиты с разрывом < 2 ч — одна сессия; часы = длина сессии + 0,5 ч.
Период 2026-10-20…10-29: **680 коммитов, 27 сессий, ≈ 113 часов** (в среднем 12 ч/день, 10-25 — 17 ч; 10-29 — 2,6 ч, день не закончен).
По префиксам (часы сессии делятся поровну на коммиты): feat 49, docs 38, fix 20, chore 2, perf 1,6, refactor 1, test 1.
По разделам (скобка префикса): без скобки 46, pwa 28, passports 7,5, scripts 3,3, supply 2,4, showcase 2,3, stock 2,2, admin 2.
Погрешность (честно): ±30–40 %. Завышает: агенты работают параллельно и сессия включает ожидание/разговор, одиночный коммит = 0,5 ч. Занижает: работа без коммита (обсуждение, ожидание), разрыв > 2 ч внутри дня режет сессию. Показывать как «оценка по коммитам», не как табель. Ручная правка часов у записи — главнее. «Дом/работа» — по эстафете коммита сессии (больше 🏠 → дом); это метка места, а не времени.
Раздел: из скобки префикса; пусто — по путям файлов коммита (`backend/pwa`→pwa, `admin`→admin, `src/modules/X`→X, `docs`→docs).

## 3. Модель хранения (только data-core, без CRM, soft-delete не нужен)
- `devlog_releases`: {version ('v1.N' или 'srv-<hash>'), date, commits[] (hash), summary, deployedAt?}.
- `devlog_commits`: {hash (уникален), date, prefix, area, subject, place (home|work), sessionId, releaseVersion?}.
- `devlog_items`: {key (уникален: `commit:<hash>` | `task:<код>` | `err:<sig>`), type feature|fix|task|error, title, area, status, refs{commit, fixCommit, fixVersion, file}, createdAt, closedAt, hours?(ручные), note, manual:true/false}.
- `devlog_sessions`: {start, end, hours, commits, place} — пересчитываемый кэш.
- Ошибка→исправление: `refs.fixCommit` + `fixVersion`. Авто-подсказка: коммит `fix` с тем же разделом после первой ошибки и до последней — «предположительно»; подтверждает человек в админке.
- Статусы ошибки: new → in_progress → fixed (в vX) / not_bug. Если после fixed сигнатура появилась снова — вернуть в new («вернулась»).
- Наполнение: скрипт `backend/scripts/devlog-import.js` (идемпотентный upsert по key, только добавляет, ручные поля не затирает), вызывается в конце `release.sh` после проверок; падение импорта не валит выкладку. Ошибки: копируются из `clienterrors` группами по sig (счётчик, первая/последняя дата, версия) до истечения TTL. Задачи — из TASKS/CHECKLIST (заголовок + `[x]`).
- Откуда на сервере git? На VM репо нет (архив) — импорт запускается с машины разработчика и шлёт в API по ключу `kppd_` (эндпоинт `POST /api/devlog/import`, роль admin/машинный ключ, тело ≤ 1 МБ).

## 4. Экран (по образцу changelog / Sentry / Linear)
Вкладки: Версии | Ошибки | Задачи | Время. Версии — лента карточек по датам, значки категорий (feat/fix/docs), раскрытие списка коммитов. Ошибки — таблица: группа, раздел, сколько раз, последний раз, статус-чип, «исправлена в v1.N» ссылкой; фильтры статус/раздел/период. Задачи — список с чипами статуса и разделом. Время — график «часы по неделям» и «часы по разделам» (простые SVG-столбцы, без библиотек), переключатель «по коммитам/с ручной правкой», примечание о погрешности. Вид — по DESIGN.md админки, пустые состояния с подсказкой, язык менеджера (без хэшей на виду).

## 5. Нагрузка и безопасность
Страница и API — только admin (`@Roles('admin')`); импорт — ключ с правом admin. Серверная пагинация 50, индексы по date, key, status, area; агрегаты «время» считаются в импорте, не на запросе. ~700 коммитов = единицы МБ. Никаких тел запросов, паролей, данных клиентов: в коммитах только заголовок (subject), ошибки — message/section/action без stack (stack по умолчанию не копировать — может содержать пути). Перед импортом отфильтровать строки по шаблону секретов (`kppd_`, `password`).

## 6. Чек-лист по фазам
**S (1 день, architect+backend): хранение и импорт.** Схемы 4 коллекций + индексы; скрипт импорта из git (коммиты, релизы по версиям, сессии, часы). Приёмка: если запустить импорт дважды — число записей не меняется; если у коммита есть скобка — area заполнена; сумма часов за 10-20…10-29 в пределах 100–125 ч; в данных нет `kppd_`.
**M (2 дня, backend+frontend admin): API и вкладки «Версии» и «Время».** `GET /api/devlog/releases|sessions|stats`, admin-only. Приёмка: если зайти под не-admin — 403; если открыть «Версии» — видна последняя версия с датой и коммитами; если выбрать неделю — часы совпадают с суммой сессий; пустая база — подсказка, не ошибка.
**M (2 дня): вкладки «Ошибки» и «Задачи» + импорт ошибок и TASKS/CHECKLIST.** Приёмка: если ошибка в `clienterrors` — после импорта её группа в «Ошибки» со счётчиком; если поставить «исправлена в v1.N» — статус и ссылка видны, запись переживает 30 дней TTL; если ошибка пришла снова после fixed — статус «вернулась»; ручные пометки не затираются повторным импортом.
**L (1 день, devops+qa+designer): выкладка.** Вызов импорта в `release.sh` (не валит выкладку), `POST /api/devlog/import`, документация MAP/openapi, e2e роли, дизайн-приёмка. Приёмка: после выкладки новая версия появилась в «Версии» сама; full-проверка зелёная; в `release.sh` нет секретов.
Опционально потом: выгрузка для ИИ (`GET /api/devlog/export.json`), аналитика по периодам.
