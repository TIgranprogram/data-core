## Критерии аудита

Показать цепочку «изделие → модуль/деталь/изделие комплекса → материал → текст паспорта». Для каждого внешне похожего справочника указать назначение и необходимость. Менеджер понимает, что выбрать один раз и откуда берутся тексты. Недостающие сведения не выдумывать.

## Контракт реализации после аудита

1. Производственный состав остаётся единственным деревом ссылок и количеств. passportParts — необязательные названия для текста; productParts — назначение работ; функциональные элементы — правила пользования. Коллекции не склеиваются, старые ссылки сохраняются.
2. Очередь не требует необязательный partIds повторно после заполненного материала. Пункт «Материалы и покрытия» появляется по реальному отсутствию сведений; «Состав изделия» — по отсутствию физических позиций. Размеры и обязательные поля категории сохраняют проверки.
3. В книжке можно добавить модуль, деталь или «Изделие комплекса». Само изделие исключено; серверные проверки циклов сохраняются. Прямое новое покупное убирается из воронки изделия по правилу владельца, старые строки покупного/метизов и PDM остаются доступны без переклассификации.
4. Предложение материалов по составу содержит источники каждой строки и несопоставленной позиции. Название реальной детали не теряется из-за отсутствия слова в passportParts. Материал по похожему имени — только предложение с явным принятием; неподтверждённые данные не попадают в документ автоматически.
5. Необязательная sourceRefs у строки materialsSpec: kind, refId, name, code и path (массив объектов kind/refId/name/code/lineId исходной цепочки). Точный тип/границы нормализует backend. Старые строки без sourceRefs читаются как ручные. Метаданные проходят parse/present, UI, сохранение изделия/черновика и техническую печать; выпущенные снимки сохраняются.
6. При пустой таблице команда «Из состава» заполняет предложение без записи до «Сохранить». При заполненной показывает добавления и изменения; существующие строки, ручной текст, покрытия и размеры не заменяются молча. Повторное принятие того же предложения не дублирует строки.
7. Названия на экране: «Состав изделия» и «Описание конструкции и материалов». В строке роль подписана как необязательное название в тексте. Рядом источник из состава, при его отсутствии — ручной ввод. Книжка и техописание используют один способ принятия предложения.
8. Для листа «Состав изделия» книжка использует серверную compositionSheet, как PDF. Производственное сырьё детали не выдаётся за отдельную поставляемую позицию. Вложенное изделие показано с количеством; его материалы не смешиваются с родителем без явного принятия. Старые modules[] — резерв при отсутствии дерева у черновика; исторический выпуск не пересобирается.
