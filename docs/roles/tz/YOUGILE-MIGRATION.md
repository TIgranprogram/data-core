# ТЗ: переезд «Проектирования» из YouGile в «Рабочее место» (класс XL — данные прода)

Цель: всё, что ведётся в YouGile на доске проектирования, переезжает к нам; дальше проектировщики работают только в `#design`.
YouGile — **только чтение**, ничего там не менять и не удалять.

## Что уже есть (не делать заново)
- YouGile MCP подключён к Claude Code (`claude mcp list` → yougile ✔). Инструменты появятся в новой сессии.
- Скрипт выгрузки по API v2: `backend/scripts/yougile-export.js` (ключ из `для анализа/yougile.env` или прежнего `yougile-sync-server/.env` — тот ключ от **другой** компании, доски проектирования там нет).
- Снимки доски переписаны в `для анализа/yougile-2026-10-27/YouGile-перенос.xlsx` (72 задачи: распределение 3, в работе 6, пауза 5, завершены 58), там же `salesorders.json` (37 заказов), `lines.json` (143 позиции), `persons.json` (5 сотрудников).
- У нас: задачи `/api/design-tasks` (статусы queue/work/paused/done, срок, приоритет, исполнитель — `persons`), фото задач (`POST /api/photos/upload` → `POST /api/design-tasks/:id/photos {photoId}`), стикеры (`/api/design-stickers`, значения `PATCH /api/design-tasks/:id/stickers`), доска `/api/design-board`. Контракт — `docs/MAP.md`, решение — `docs/roles/tz/DESIGN-STICKERS.md`.
- Номера ЗНП у нас **нигде не хранятся**; номера заказов другие («11 Крыловская», «9», «115-П»). Совпадений по числу позиций нет — связь «ЗНП → наш заказ» подтверждает пользователь.

## Что взять из YouGile (через MCP)
1. Компания/проект/доска с задачами «Чертежи <артикул> ЗНП <NN-26> поз <N>»; колонки: На распределении, В работе, Приостановлены, Завершены.
2. По каждой задаче: id, номер (D-N / idTaskProject), название, колонка, описание, срок, исполнители, стикеры (приоритет и свои), подзадачи и чек-листы (с отметками), прикреплённые файлы/фото (url), даты создания/завершения, архив/удалена.
3. Сотрудники компании (имя ↔ инициалы «Ар», «АЕ»).
4. Стикеры доски (названия, состояния, цвета).
Сохранить сырую выгрузку в `для анализа/yougile-2026-10-27/mcp-export.json` (gitignored).

## Соответствие полей
| YouGile | У нас |
|--|--|
| колонка | `status`: На распределении→queue, В работе→work, Приостановлены→paused (+`pauseReason` из описания или «Перенесено из YouGile»), Завершены→done (+completedAt) |
| название | `title` (как есть) |
| ЗНП + поз | `incomeId` позиции нашего заказа — **только по подтверждённой таблице** «ЗНП → заказ»; нет пары — задача без позиции, ЗНП в `note` |
| срок | `deadline` (год 2026) |
| приоритет-стикер | `priority`: Обычный→normal, В приоритете→high, Срочно→urgent (сверить с `ORDER_PRIORITY`) |
| исполнитель | `assigneeId` — сотрудник из `persons`; нет — создать сотрудника только с «да» пользователя |
| описание, чек-листы | `note` (текстом: «Подзадачи: ☑ …/☐ …») |
| фото/файлы | скачать → `POST /api/photos/upload` → прикрепить к задаче (≤ 20) |
| свои стикеры | стикеры `designstickers` (создать такие же) + значения |
| номер D-N YouGile | в `note` первой строкой «YouGile D-41» (наши коды — свои) |

## Порядок (не перескакивать)
1. Старт координатора по CLAUDE.md. `get_usage`.
2. Выгрузка через MCP → `mcp-export.json`; отчёт: сколько задач по колонкам, сотрудники, стикеры, есть ли фото.
3. Таблица сопоставления `для анализа/yougile-2026-10-27/plan.xlsx`: задача → заказ/позиция (предложение по артикулу, ЗНП, названию позиции) → исполнитель → что запишется. Неясное — жёлтым. **Показать пользователю, получить «да».** Связь ЗНП → заказ — только от пользователя.
4. Если пользователь хочет хранить ЗНП: необязательное поле `salesorders.znpNo` (наша коллекция; ТЗ через architect, e2e) — отдельной задачей до записи.
5. Скрипт `backend/scripts/yougile-import.js`: план (по умолчанию) → `--apply --out откат.json`; повтор безопасен (метка `source:'yougile'`, `externalId` = id YouGile в `note`/поле — не создавать дубли); пишет через API (`deploy/synology/api.sh` — помни: вход на каждый вызов, лимит 5/мин, `docs/traps.md`) или на VM внутри контейнера.
6. Перед `--apply` на проде — бэкап (`bash deploy/synology/backup.sh` на VM или через release). 3 задачи, что уже есть на проде (D-2…D-4, ЗНП 55), не трогать.
7. Проверка: `/api/design-board` — числа по колонкам = YouGile; 3–5 задач глазами (`get_page_text` `#design`).
8. Итог пользователю: сколько перенесено / пропущено и почему; что делать дальше (YouGile — только чтение, работаем у нас).

## Нельзя
- Писать в YouGile, удалять там что-либо.
- Записывать на прод без показанного плана и «да» пользователя; угадывать связь ЗНП → заказ.
- Выводить ключи и пароли в чат. Ключ YouGile MCP пользователь вставил в чат 27.10 — напомнить заменить после переезда.
