# C270 — добавление и подтверждение в рабочей сетке

Класс M, только frontend, продолжение явных уточнений владельца после принятой C269. Владелец frontend, независимая приёмка designer, стенд через access. Не коммитить/не выкладывать исполнителю. Другие участники работают в репозитории: чужие изменения не откатывать. C269 принята: c7adf08a + 3feff09c; её оформление, подстрока, история, котики и единицы сохраняются.

## Требование владельца и поведение

1. Добавление металла из таблицы вместо длинной универсальной формы. Пустая координата трубы — кнопка с нейтральным прочерком и понятным доступным названием. По нажатию короткий ввод непосредственно у ячейки/в подстроке: категория, сечение, мойка, длина, марка и unit подставлены из её контекста, человек видит контекст и количество. Имя сформировано и показано, не надо заново заполнять каталог. Недостающие обязательные параметры спрашиваются явно. Не додумывать неизвестные размеры. Кнопка «Добавить материал» на native pipe/sheet открывает компактную строку добавления нового размера/формата, не общую простыню stock.js. Для sheet компактное добавление с толщиной/форматом/маркой/unit своей зоны. Все формы и количество доступны с клавиатуры, без записи от случайного клика.
2. Изменение количества существующего материала только после лёгкого подтверждения рядом с ячейкой: «было → станет» и unit, «Сохранить»/«Отмена». Enter после набора сначала открывает подтверждение; blur не пишет. Escape/Отмена отменяют без запроса, неизменённое значение не требует подтверждения. Одно pending-подтверждение на весь view, двойная отправка заблокирована, ошибка остаётся у соответствующего материала. Подстрока по сечению и ввод количества независимы. Общие wood/notes и остальные таблицы не переводить на новый режим.
3. Pending хранит materialId, unit, исходный expected и новое qty. Reload/чужое изменение не подменяет expected; при устаревании штатный409/обновление без force и тихой перезаписи. Сохранить фокус, черновик и читаемую ошибку, включая поздние ответы/уход со страницы. Single/countMode и readonly по прежним правилам.
4. «Принять на склад» в pipe-view ограничен трубами своей зоны, в sheet-view — листовым металлом своей зоны. Это трактовка фразы владельца «принять на склад — подается только труба» в контексте двух рабочих ролей, уже сообщена ему. Зона/тип подставлены; поиск, recent, черновик, прямой materialId и submit одинаково ограничены. Не менять глобальный выбранный склад. Общая приёмка без worker-context прежняя. Универсальный arrivalsBlock и generic «Создать {name,unit:шт}» в контекстной приёмке не показывать.

## Существующий контракт, не расширять API

Создание: `POST /stock/items?zoneId=<явная разрешённая native zone>`, тело только `{name,unit,categoryId,dims,materialGrade,washed,assortment}` по существующему DTO. Явный zoneId включает createOnly и409 на дубль имени; без него возможна правка/переиспользование материала, поэтому не опускать. Размеры в мм; metal/quantity/initial не отправлять. Категория из разрешённой зоны, для нового размера выбрать допустимую; обязательные имя/unit/размеры проверяются по существующему контракту. Коллизии разных materialId не сливать, неполную страницу100 не считать всем каталогом.

Создание даёт материал с нулём. В коротком вводе можно сразу указать начальный остаток в исходной unit: перед отправкой явное подтверждение, затем создание и отдельный существующий count. Нельзя делить метраж на длину. Если создание успешно, а count не удался, показать «Материал создан, остаток0» и повторять только count, не создавать дубль. Отмена до подтверждения не создаёт материал. Не удалять созданный материал автоматически. Существующий batch count использует expected.

Контекстная приёмка: необязательный worker-context `{zoneId,kind}` в существующем openStockOp/picker, `catalogueStockList(zoneId)`, категории этой зоны и pipe/sheet. Серверные ACL и схема БД не меняются. Все записи при испытании перехвачены в браузере; реальную БД не править.

## Файлы и проверки

Читать адресно: stock.js:216/279 (существующий create, не переделывать общую форму), stock-worker-grid/model/worktable, stock-grid-input, stock-ops, stock-ops-pick и их вызывающие места. Ответственность frontend: эти рабочие renderer/model/worktable/input и scoped opt-in stock-ops/pick; при необходимости отдельный helper sections с preload index, scoped kit.css и адресные тесты. Координатор: atlas/help, документы, browser сценарий. Новый общий контракт/сервер не вводить.

Дизайн по datacore-design/DESIGN: компактные группы, явный контекст, существующие токены; light/dark1440/1024, readonly2560. Отдельные kit и sections коммиты у координатора. Сохранить C269 газетную подстроку/матрицу истории, одну открытую строку, нули и котиков. Убрать мелкое текстовое задвоение «Марка: Марка не указана» при затрагивании helper.

Адресные регрессии: пустая ячейка→контекст→отмена без POST; подтверждённые create/count в исходной unit/zone; новый размер/формат, недостающие параметры,409 дубля, count failure без повторного create; изменение qty/blur/отмена/Enter/двойное сохранение/устаревший expected; reload и поздние ответы; readonly/multiple без новых путей записи. Контекстная приёмка не принимает чужую зону/тип через поиск, recent, draft или прямой ID, общий picker без контекста работает прежним образом. Синтаксис/импорты, tsc, PWA guards, design-lint и C240/C242/C269/wood совместимость. Полный backend/e2e без серверных изменений не нужен. Перед stand сообщить runtime FROZEN, после стенда правки только по найденному дефекту/уточнению владельца.
