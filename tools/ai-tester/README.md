# ИИ-тестировщик

Локальный ИИ (LM Studio на этом компьютере) ходит по «Рабочему месту» как менеджер. Он создаёт заявки, контрагентов и расходы, открывает карточки и ищет ошибки. В конце он пишет отчёт.

**Безопасно:** он работает только на **стенде этого ПК** (копия базы, `localhost:3102`). Рабочий сайт он не трогает: программа запрещает чужие адреса. Каждая запись, которую он создаёт, начинается с **«ТЕСТ-ИИ»**. В конце он сам убирает эти записи.

## Как запустить (пульт → «ИИ-тестировщик»)

Одна кнопка — **«Запустить ИИ-тестировщика»**, выберите время. Остальное он делает сам:

- первый раз на ПК настраивает LM Studio и модель (LM Studio должен быть установлен — сайт lmstudio.ai);
- запускает Docker Desktop, собирает стенд на свежей копии базы;
- работает в фоне — окно пульта можно закрыть, пульт при этом обновляется;
- отчёт разбирает Claude в начале следующей сессии (`dc start`), человеку его читать не нужно.

Остановить раньше — **«Остановить ИИ-тестировщика»**. Служебные кнопки (отчёт, проверка готовности, уборка записей) — в пульте под «Все кнопки».

## Что в отчёте

- **Ошибки сайта** находит программа, без догадок ИИ: сбой сервера, сбой страницы, отказ при сохранении, медленный ответ (больше 3 с), «undefined» на экране. Им можно верить.
- **Замечания ИИ** — то, что модели показалось неудобным или непонятным. Среди них бывают ложные: Claude проверяет их глазами.

Файлы: `tools/logs/ai-tester/<дата>/REPORT.md`, снимки экрана — `shots/`, все шаги — `steps.log`.

## Настройки

`tools/ai-tester/settings.json` создаётся при первом запуске. Файл не идёт в git.

| Поле | Что это |
|--|--|
| `baseUrl` | адрес LM Studio, по умолчанию `http://localhost:1235/v1` |
| `model` | модель; кнопка «Установить ИИ на этом ПК» ставит её по видеокарте (16 ГБ — Gemma 4 12B) |
| `stepsPerTask` | сколько шагов на одно задание (20) |
| `stand` | только `http://localhost:3102` |

Задания — список `TASKS` в `run.mjs`. Новое задание — одна строка.

## Проверка дизайна (C087)

Сценарный `run.mjs` по-прежнему получает текст экрана. Изображения проверяет отдельный `vision-review.mjs`: пульт → «Проверить снимки локальным ИИ» (до 3 файлов последнего обхода) и «Отчёт проверки снимков». Первый запуск требует работающей LM Studio и модели с поддержкой изображений. На домашнем ПК проверена уже установленная Gemma 4 12B QAT; скачивание второй модели не понадобилось.

Для агента: `node tools/ai-tester/vision-review.mjs --input <png|папка> --limit 3`; `--latest-audit` выбирает последнюю папку обхода; `--last` читает итог без модели. Время на снимок по умолчанию 90 с, верх 180 с. Только loopback HTTP, без перенаправлений, инструментов и записи на сайт. Исходные снимки не отправляются в облако этим скриптом.

Кэш по содержимому снимка, модели, локальному endpoint и версии запроса; повтор не вызывает модель. Неподдерживаемые файлы не занимают лимит изображений. Усечённый/невалидный ответ — сбой, а не «дефектов нет». `--refresh` явно повторяет анализ. Отчёты: `tools/logs/design-vision/`; замечания модели требуют подтверждения, она не принимает дизайн.

Порядок экономии и правила общих компонентов — `docs/DESIGN-WORKFLOW.md`. Пиксельное сравнение и axe — `tools/design-checks/README.md`. Суточный запуск сценарного тестировщика не включает визуальную модель на каждом шаге.
