## 2. Баг: витрина `#kit` падает (чинится одной строкой)

`sections/kit.js:69` вызывает `mobile.catArt(…)`, но объект `mobile` (`ui/kit/mobile.js:251`) не содержит `catArt` — тот экспортирован рядом (`export { mobile, catArt }`). На текущем main витрина не открывается: «Раздел не открылся…», в `clienterrors` — `TypeError: mobile.catArt is not a function`, раздел `kit`.

Почему это важно: витрина — «живой каталог» эталонов, на котором держится вся волна 0 (правило L6 «витрина = каталог»). Без неё план порядка слеп. Фикс: добавить `catArt` в объект `mobile` (или в `kit.js` импортировать `catArt` отдельно). Плюс вывод системный: **упавший экран витрины должен ронять проверку** — сейчас `dc` зелёный, а ключевой экран мёртв.

## 3. Находки с живых снимков (тёмная тема, 1600px)

### 3.1 «Сегодня»
1. **Красный заголовок «Срочно: просрочено» при пустом списке** («Нет просроченных дел») — цвет-ложная тревога. Правило: тон заголовка очереди зависит от содержимого (пусто → нейтральный).
2. **Правая колонка короче левой** — под «Деньгами» пустота до низа; сетка очередей без растяжки/masonry.
3. **Три нулевые метрики-пилюли** занимают полосу ради «всё хорошо»; при всех нулях — одна строка «Всё спокойно».
4. **Две системы счётчиков рядом**: жёлтая капсула «190» в шапке блока и правые числа 78/59/29 — согласовать один вид.
5. **Подчёркивания ссылок разнобой**: где-то вся строка, где-то слово (правило DESIGN §4.1 есть — довести до всех экранов).
6. **Третий радиус**: капсулы (пункт меню, пилюли, счётчики) поверх шкалы 7/10px — либо зафиксировать капсулу в токенах (`--radius-pill`), либо убрать.
7. **Служебное в меню**: строка версии `vW/db09` внизу меню (в «Настройки»), пункт «Склад (телефон)» — рабочий инструмент с техническим именем (см. вопросы).

### 3.2 «Заявки» (очереди)
1. **Панель фильтров читается как пятая колонка доски** — та же высота и оформление, что у очередей. Фильтрам — явный фон `--surface`, уже, отделение от доски.
2. **Фото доминирует в карточке очереди** (картинка больше текста): в «Оплачено» визуально фотогалерея. Миниатюра 40–48px; крупное фото — только где картинка = содержание (проектирование, каталог, паспорта).
3. **Счётчик и сумма колонки слиплись**: «9 15 930,00 ₽» читается одним числом. Счётчик — бейдж, сумма правее и заметнее, `tabular-nums`.
4. **Чекбокс «Выбрать» ~20px** — меньше тач-нормы 44px.
5. **Крайняя колонка обрезана без намёка на прокрутку** (нет тени/градиента у края).
6. **Два типа карточек в одной доске** (заявка-CRM с чекбоксом и кнопкой vs позиция с фото) — это два разных эталона; назвать их в kit явно, а не «как получится».
7. Поля дат в фильтре показывают англ. формат — проверить локаль стенда (в ru-браузере нативный `input type=date` даёт дд.мм.гггг; возможно, это только язык стенда).

### 3.3 «Остатки»
1. **Два сайдбара подряд** (навигация + фильтры) без явной границы — конфликт вертикалей. Панели фильтров — свой фон и рамка справа.
2. **Сетка карточек категорий сиротская**: 4 карточки при большой пустоте справа/снизу — растянуть по `auto-fill` до края или выровнять ширину.
3. **Подсказка в 5 строк серым** («→ Все позиции склада. В строке: …») — инструкция вместо устройства; одна строка + «Подробнее».
4. **Четыре стиля кнопок в одном ряду** (primary + 2 вторичные + текстовая «Ещё ▾»): «Ещё» — iconButton, вторичные — один вид.
5. **«+ Новая позиция склада» и «Принять на склад» пересекаются по смыслу** — развести подписи или собрать редкое в «Ещё ▾».
6. Счётчик фильтра «30 -» — висящий обрыв.
7. **Имя экрана «Склад» ≠ пункт меню «Остатки»** — сверить.

### 3.4 Общесистемное
- Палитра и контрасты — сильная сторона; проблемы в **применении**, не в цветах.
- **Тёмная тема: зелёные заголовки всех карточек** разбавляют сигнал зелёного (выбрано пользователем — поэтому не правка, а вопрос №1 ниже).
- ~28 видов пустых состояний — план сведения к `kit.empty` верный; добавить правило «пустота называет следующий шаг» (уже частично есть).

## 4. Видение «картотеки»: пять правил поверх плана

Решение STYLE-DECISION (карточка-«бумага» 1А, таблица-«линии» 2Б, связи-«сетка» 3А) принимаю — оно здравое и в духе проекта. Чтобы «картотека» читалась как картотека, добавляю пять правил, которых сейчас не хватает:

1. **Карточка = итог в шапке + до 5 строк + «Ещё N».** Остаток/сумму/долг видно без раскрытия, `tabular-nums`; дальше — не больше пяти строк таблицы-«линии».
2. **Цвет — только статус и действие.** Полоса-тон слева = состояние карточки; заголовки карточек — нейтральные (в тёмной теме — вопрос №1).
3. **Один счётчик — один вид.** Всегда пара «бейдж-число · сумма» с явным зазором; никаких капсул-исключений.
4. **Связи — сетка, клик двигает только панель.** Меню, шапка и список неподвижны (A6 из плана — усилить: без смены фона/рамки списка при переключении контекста).
5. **Фото — слуга, не хозяин.** 40–48px в строках и связях; крупное — только там, где изображение и есть содержание.

Быстрые победы (≈1 сессия, видны сразу): починить `#kit`; разъединить счётчик и сумму в шапках колонок; убрать красный «Срочно» при пустом списке; фильтры ≠ колонка доски; чекбокс 44px; версия и «Склад (телефон)» — из меню в настройки/переименование; одна строка подсказки в «Остатках».

## 5. Фреймворк: моё мнение

**Сейчас не переходить — согласен с CloudCode, по своим причинам:**
- продукт живой и выкладывается; миграция ~27 тыс. строк = недели риска при нулевой пользе пользователю;
- `kit` + фабрики + `data-k` + design-lint — это уже свой мини-фреймворк; `h()` в 20 строк делает то, что React даёт из коробки, без сборки и CSP-ограничений (свои шрифты, офлайн-PWA);
- беда не в технологии, а в дисциплине: на React тот же агент разведёт 14 видов карточек, если линтер прощает. Волна 0 (храповик) лечит причину, миграция — нет.

**Когда пересмотреть:** (1) появятся тяжёлые интерактивные сетки/виртуализация; (2) придут люди-фронтендеры (рынок навыков); (3) lint=0 перестанет удерживаться. Тогда путь — новые экраны по одному на Web Components/Lit, старые не трогать.

**Улучшить без фреймворка уже сейчас:** типы. Хотя бы JSDoc-типы в `ui/kit/index.js` (начато) + `// @ts-check` в фабриках — бандл не нужен, а «не та опция карточки» ловится до браузера.
