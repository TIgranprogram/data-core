## 1. Что есть сейчас (факты из кода)

- Причина «пустых списков»: каталог пуст, пока не залит прайс; поставщики в combo берутся иначе, чем везде. Проверить на проде, не гадать.

## 2. Модель данных (одна таблица, без задвоения)
Источник один — `supplieritems` (связка «материал ↔ поставщик ↔ артикул поставщика ↔ цена/дата»). `materials` и `supplyrequests` — общие с CRM, схемы не меняем.
Добавить в `supplieritems` (необязательные, аддитивно, CRM их не читает):
- `materialId` (ссылка на наш материал; null = ещё не сопоставлено), `unit`, `categoryId` (копия категории материала для фильтра), `vendorName` (название у поставщика; сейчас `name` — свести: `name` = у поставщика), `priceDate`, `inStock` (флаг), `note`, `source`: + `stock` | `manual`.
- Ключ остаётся supplierId+article+color. Позиция без артикула поставщика: ключ — `manual:<materialId>`.
- Не добавлять в `supplyrequests` ничего обязательного; SC-2 по умолчанию: `supplierItemId` необязательный.
- Один материал — много поставщиков (много строк). Цена «текущая» = последняя запись priceHistory.

## 3. Наполнение из склада и заявок (скрипт план → apply)
`backend/scripts/catalog-from-stock.js`, по образцу `catalog-from-excel`: по умолчанию план (ничего не пишет, печатает отчёт), `--apply` пишет.
1. Из заявок: уникальные пары (supplierId, article|title) среди `supplyrequests` с supplierId, не удалённые. Цена и дата — из последней заявки; в priceHistory source:'request'. materialId — из заявки, если есть.
2. Из склада: `materials` с `supplierId` и покупные (не `isSystem`, не изделия) → строка (supplierId, article материала). Без supplierId — не создаём, в отчёт «без поставщика» (пользователь назначит в экране).
3. Совпадение с существующими: по supplierId+article(+цвет); иначе по `supplier_aliases`; иначе по нормализованному названию — только в отчёт «возможные дубли», не склеивать молча.
4. Идемпотентно: повторный запуск не плодит. Бэкап/ограничение: только insert/upsert, не удаляет; прод — после «да» пользователя.
Отчёт: создано / обновлено / пропущено / без поставщика / возможные дубли.

## 4. Excel-шаблон поставщика
Лист «Прайс», строка заголовка (текущий парсер ищет «Артикул»). Колонки:
Артикул поставщика* | Название у поставщика* | Цвет | Ед. изм. | Цена | Дата цены | Группа | Наш артикул | Наше название | Примечание. (* обязательно)
Поставщик выбирается в окне импорта, не в файле (как сейчас); для общего файла — доп. колонка «ИНН поставщика» (необяз.; есть — приоритетнее выбора, ИНН «БЕЗ-ИНН-…» игнорировать).
Шаблон скачивается кнопкой «Скачать шаблон» с одной примерной строкой и листом «Инструкция». Старый шаблон (7 колонок) принимать как есть.

## 5. Импорт
- Шаги: выбрать файл → предпросмотр (уже есть `preview`) → применить. Дубль файла по хэшу — предупреждение.
- Сопоставление: поставщик (выбор или ИНН) + Артикул поставщика + Цвет → upsert. Наш материал: по «Наш артикул», иначе по `supplier_aliases`, иначе не сопоставлено (жёлтая метка).
- Предпросмотр: счётчики «новых / обновится / цена изменилась / ошибок»; таблица строк со статусом; ошибки строки (нет артикула, нет названия, цена не число, неизвестный ИНН) — подсвечены, остальные строки применяются; скачать файл ошибок.
- Цена изменилась → запись в priceHistory (source excel). Позиции, которых нет в файле, НЕ удаляются.
- Роли: admin, manager. Лимит строк 5000.

## 6. Экспорт
Шестерёнка → «Скачать Excel»: текущий фильтр (поставщик/категория/поиск) в тот же формат шаблона + «Наш артикул», «Остаток» — файл можно исправить и залить обратно. «Скачать шаблон» — пустой.

## 7. Права
Просмотр: admin, director, manager, user (как сейчас). Импорт, правка строки, привязка к материалу, удаление (soft): admin, manager. director — только просмотр и экспорт. Цены видны всем, кто видит раздел `supply`. Проверка роли — на сервере; кнопки для остальных скрыты.

## 9. Этапы
1. Прод-замеры + исправить список поставщиков и подписи (S).
2. Схема (аддитивно) + `catalog-from-stock` план → пользователь смотрит → apply.
3. Раскладка слева/справа, крошки, шестерёнка, панель строки.
4. Шаблон, импорт с предпросмотром, экспорт.
5. Права, привязка к материалу, использование каталога в форме заявки (подсказка поставщика/цены).

## 10. Критерии приёмки
- Если в заявке/на складе есть покупная позиция с поставщиком — она в каталоге после apply; повторный apply ничего не добавляет.
- Если выбрать поставщика слева — в таблице только его позиции, число совпадает с меткой слева.
- Если залить файл, где у 2 строк нет артикула — они в ошибках, остальные применены, цены записаны в историю.
- Если цена в файле другая — в карточке две записи цены с датами.
- Если скачать экспорт и залить без правок — «0 новых, 0 изменений».
- Если роль user открыла раздел — шестерёнка без импорта; прямой POST импорта → 403.
- Схемы `materials`, `supplyrequests` не изменены; CRM работает.

## 11. Риски
- Задвоение: `supplier_aliases` и `supplieritems` — две «связки»; решение: алиасы остаются источником сопоставления, каталог читает их, не копирует.
- Один материал приходит от нескольких поставщиков с разными артикулами — норма; склейка по названию только вручную.
- Ключ с «цветом» ломается, если цвет в файле то пусто, то «—»: нормализовать.
- Прод-данные: скрипт — только после «да», сначала план.
