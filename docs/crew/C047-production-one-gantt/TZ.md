## Глубже
- **Результат:** мастер видит в Ганте только производственных людей, назначает по профилю, планирует в одном месте; норма одна.
- **Сырьё:** отчёт C046 §2–§5 (файл:строка там); `persons.workTypeIds` + `common/catalog/person-work-types.ts`; `/work-tasks/people?workTypeId` (`work.service.ts:274-278`) — образец фильтра; `work-schedule.service.ts:82-86` (people, capacity); `work-schedule.js:107-109, 208` (строки, исполнитель).
- **Метод профи:** ресурсный план цеха: ресурс = человек с навыками; назначение проверяет навык; ёмкость дня — из карточки человека.
- **Внешний судья:** юнит на фильтр людей и проверку вида работ при переносе; e2e `/work-schedule` без людей без видов работ; дизайнер по изменённым экранам.
- **Смелая планка:** бухгалтер и офис не видны в Ганте ни в одном виде; перенос полосы на человека без нужного вида работ — отказ с понятной причиной.

## Чек-лист Э1 — сотрудники и виды работ (свои агенты)
- [ ] С1. `/work-schedule`: люди — только с ≥1 видом работ (`workTypeIds` или legacy `workTypeId`); `capacityHours` — из нового поля сотрудника `hoursPerDay` (пусто — 8).
- [ ] С2. `PATCH /orderline-plans/:id/steps/:stepId` с `assigneeId`: у человека нет вида работ шага → 400 «У сотрудника нет вида работ «…»». Шаг без вида работ — без проверки.
- [ ] С3. `persons`: необязательное поле `hoursPerDay` (число 1–24); `persons` — своя коллекция data-core? проверить по `docs/MAP.md`; общая с CRM — только новое необязательное поле.
- [ ] Ф1. «Сотрудники» (справочник `persons`): «Виды работ» — мульти-выбор (вместо одиночного select), «Часов в день».
- [ ] Ф2. Гант: строки «По людям» — сервер уже отдаёт только нужных; панель шага «Исполнитель» — только с видом работ шага, ссылка «Показать всех».
- [ ] Юнит + e2e, дизайнер, доки (MAP, PRODUCT «Производство»).
