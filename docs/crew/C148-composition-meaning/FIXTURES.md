## Сценарии после обновления backend

1. Предложение A: part1 имеет расчётное количество 2×3=6, part2 — 2×1=2. Одинаковое название разных деталей не должно сливать их идентичность.
2. B обходит A и C как изделия. Попытка добавить B в собственный состав должна отклоняться без изменения состава.
3. При повторном принятии предложения не дублируются partIds и связи источников. Сам просмотр предложения не записывает данные.
4. Принятие предложения A — PATCH → GET, затем техописание/PDF. Связь сырья подтверждается точным materialId, отсутствие связи rawUnmapped должно быть видно как незаполненность.
5. C сохраняет свои размеры, текст паспорта, техописание и покрытие. Пустой состав не разрешает стирать ручное описание.
6. Для выпущенного паспорта сохраняется снимок после изменения предложения/состава. Эта отдельная фикстура пока не создана, выпуск возможен только по штатным требованиям и с явной фирмой на копии.

Техническое состояние для продолжения без дублей — tools/logs/c148-fixtures-state.json. Подготовительный сценарий идемпотентен по сохранённым идентификаторам.
