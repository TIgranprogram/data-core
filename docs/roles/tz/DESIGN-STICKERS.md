2. **Фото (MVP-1, M).** Своё не делать: `POST /api/photos/upload` → `POST /design-tasks/:id/photos {photoId}`, `DELETE .../photos/:photoId` — копия `incomes.controller.ts:70–78` / `incomes.service.ts:44–58, 203`. Поле назвать **`photoIds: [ObjectId]`** (как в incomes, не `photos` — в ТЗ ошибка). Резолв url/thumb — вынести общий хелпер из incomes в `common/` (не дублировать), одним `find({_id:{$in}})` на всю доску.
3. **Права — подводный камень.** Сейчас `PATCH /design-tasks/:id` только `admin, manager` (`design.controller.ts:55`); проектировщик = `user`. Фото/стикеры/таймер: `@Roles('admin','manager','user')` + в сервисе: `user` — только если `assigneeId == me` или задача без исполнителя. Не расширять общий PATCH.
4. **Настройки стикеров — отдельная коллекция `designstickers`** (не поле в settings): удобно soft-delete, порядок, `boardKey`. Схема по ТЗ; уникальный индекс `{boardKey,key}` с `partialFilterExpression:{deletedAt:null}` (4.4 ок) → в `ensure-indexes.js`. Системные — сид идемпотентный upsert по `key`, `kind:'system'`, удалить нельзя (400), только `visible`.
5. **Значения:** `stickers: { [stickerId]: number|stateId }` (Mixed). Ключ — строковый `_id` стикера, не label. Валидация в сервисе по типу (number — конечное; state — id из `states`). Пустое значение → `$unset stickers.<id>`. Пишем точечно `$set: {'stickers.<id>': v}` — не перезаписывать объект (гонки двух вкладок). `id` проверять `oid()` перед вставкой в путь (инъекция `$`/`.` в ключ).
6. **Удаление стикера:** soft-delete стикера, значения в задачах НЕ чистить массово (без `updateMany` по проду); фронт игнорирует неизвестные ключи. Удаление `state` из списка — то же: старое значение показывать «—».
7. **API минимум:** `GET /design-stickers` (все роли доски), `POST/PATCH/DELETE /design-stickers[/:id]` (`admin`), `PATCH /design-tasks/:id/stickers {values:{…}}`, фото — 2 маршрута. DTO с `@IsObject()` для values; поля из реальных запросов (`forbidNonWhitelisted`).
8. **Доска:** `GET /design-board` добавляет `stickers` (видимые, по `order`, ≤ 4 на карточке) один раз на ответ + `stickers`/`photoIds` в задаче через projection. Без запроса на каждую карточку; `cached` — если есть, включить `designstickers` в ключи сброса. Лимит `TASKS_CAP` не трогать.
9. **Фронт:** `design-board.js` — карточка рисует стикеры по массиву из ответа (системный → поле задачи, свой → `task.stickers[id]`), без innerHTML с данными (label пишет админ!). Правая панель задачи (`sections/design.js`) — все стикеры, ввод только там; смена state с карточки — по CANON допустима как действие, не ввод.
10. **Таймер — отложить в MVP-3.** Нужны: один активный на человека (поиск по всем задачам → индекс `timeLog.userId`+`to:null`), авто-стоп при смене статуса, сутки/забытый таймер. `timeLog` в схему пока не добавлять (мёртвое поле).
11. **Фильтр по стикеру** — потом; при нём индекс на `stickers.<id>` невозможен общий — фильтровать в памяти по уже загруженной доске.
