# ТЗ C036 Ш1–Ш2 — каталог показывает всю номенклатуру; фильтр «Поставщик» и «Без поставщика»

**Зачем (словами пользователя):** «Одна база; позиция не пропадает. Все позиции, фильтр по поставщику, „без поставщика“.»
**Зачем — глаголом:** снабженец открывает каталог и видит все 415 позиций, а не 145; за 1 касание отбирает позиции одного поставщика или позиции без поставщика.

## Глубже
- **Результат:** каталог = вся номенклатура (`materials`) + предложения поставщиков (`supplieritems`). Цель Ц-«одна база».
- **Сырьё:** замер прода `SH0-MEASURE.md`: 415 материалов, 163 предложения, 145 материалов с предложением, 270 без.
- **Метод профи:** одна выборка Mongo `$unionWith` (есть в 4.4), сортировка и страницы — на сервере, без двух запросов на клиенте.
- **Внешний судья:** юнит-тест сервиса (материал без предложения попадает в `view=all`, `supplierId=none` даёт только такие); на стенде `total` при `view=all` = предложения + материалы без предложений.
- **Смелая планка:** ответ списка < 300 мс на 415 + 163 строк.

**Класс:** L · **Max agents:** 3 (backend, frontend, designer) · **Reviewers:** designer ☑ · **Max review loops:** 2 · **Проверки:** smoke (tsc + юнит supply; `node --input-type=module --check` экрана)
**Язык менеджера:** да — «Без поставщика», «Поставщика нет — цену узнать у снабжения», без `m:` и id на экране.

## Shared pack — контракт (точно, обе роли)
- `GET /api/supply/catalog/items` — новый необязательный параметр `view=all`. Без него ответ **как сейчас** (только предложения) — внешние клиенты не ломаются.
- `view=all`: строки = предложения (как сейчас, тот же вид `present()`) **плюс** материалы, у которых нет ни одного живого предложения (`supplieritems.materialId`, `deletedAt:null`).
  - Строка материала без предложения: `id: "m:<materialId>"`, `kind: "material"`, `materialId`, `materialName`, `materialArticle`, `name` = имя материала, `article` = артикул материала, `unit` материала, `categoryId` материала, `stockQty` (из `storageitems`, как сейчас), `supplierId: null`, `supplierName: ""`, `priceHint: null`, `priceDate: null`, `photos: []`, `thumb: ""`, `priceHistory: []`. У строк предложений добавить `kind: "offer"`.
  - Фильтры: `search` — по имени и артикулу материала; `categoryId` (и `none`) — по `categoryId` материала; `supplierId=<id>` — только предложения (как сейчас); `supplierId=none` — только материалы без предложения; `unmatched/noPrice/stale` — только предложения (материалы без предложения не показывать).
  - Сортировка и `page/limit/total` — на сервере, одной выборкой (`$unionWith` + `$facet` или два счёта). Mongo 4.4, без фич 5+.
- `GET /api/supply/catalog/counts` (тот, что читает `getCounts()` экрана) — добавить `noSupplier: <число материалов без предложения>`; при `view=all` счёт категорий включает материалы без предложений. Если проще — счёт категорий не трогать, только `noSupplier`.
- Только чтение. Схемы `materials`/`supplieritems` (общие с CRM) не менять.
