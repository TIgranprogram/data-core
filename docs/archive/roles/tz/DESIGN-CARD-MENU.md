# DESIGN-CARD-MENU — меню «⋯» у карточек «Проектирования»

Класс M. Исполнитель: frontend. Backend — не нужен (все эндпоинты есть). Автор: analyst, 2026-10-29.

## 1. Что есть сейчас
- `pwa/ui/design-board.js:231-244` `menuBtn(label, items, cls)` — готовый выпадающий список (клавиатура, Esc, закрытие по клику). Уже используется у заказа (стр. 269-277).
- Карточка задачи (стр. 356) и строка позиции без задачи (стр. 257): «⋯» открывает лист `statusSheet` «Куда перенести …» (стр. 51-59, `pickStatus` 210, `sheetOptions` 145). Это дубль перетаскивания (`draggable`, стр. 258/364). Жалоба верна.
- Правая панель задачи (`pwa/sections/design.js`): статус-кнопки (стр. 250-252), смена исполнителя (стр. 117-124, `askAssignee`), срок/приоритет/название/примечание (форма 270-279), фото (`.dc-photos`), стикеры, сообщения и «вопрос менеджеру» (стр. 127-133), удаление (стр. 316). Ссылка на заказ — стр. 137.
- Сервер (`design.controller.ts`): PATCH задачи — admin/manager; фото, стикеры — +user; DELETE и restore — admin/manager; сообщения `POST design-tasks/:id/notes` (kind `question`) — `design-note.controller.ts:26`. Поля: `assigneeId`, `manual.{deadline,priority}`, `photoIds`, `note`.

## 2. Решение по смене этапа
Оставить ОДНУ строку «Перенести в…» в самом низу меню, открывает прежний лист `statusSheet`. Причина: на телефоне перетаскивания нет (`isPhone()`), с клавиатуры другого пути нет (комментарий в коде стр. 51). Убирать нельзя. Отдельной кнопки «⋯» ради неё — не нужно.

## 3. Меню «⋯» карточки задачи (порядок сверху вниз)
Группа «Работа» (видна при `canEdit`, т.е. admin/manager):
1. **Назначить исполнителя…** / «Сменить исполнителя…» — быстрый вход: `askAssignee` + `PATCH {assigneeId}`. На доске исполнитель мелкий, без открытия панели не сменить. Права: admin, manager.
2. **Изменить срок и приоритет…** — маленькое окно (дата + приоритет; «как в заказе» = очистить `manual`). `PATCH`. Права: admin, manager.
3. **Задать вопрос менеджеру…** — окно с текстом, `POST notes {kind:'question'}`; на карточке появляется бейдж «Требует ответа» (`questionBadge` уже есть). Права: как у notes (проверить роль user в `design-note.controller.ts:26`; если user разрешён — показывать и ему).
4. **Добавить фото…** — выбор файла → `POST /photos/upload` → `POST :id/photos`. Права: admin, manager, user (свои/ничьи задачи).

Группа «Перейти»:
5. **Открыть заказ** — `openOrder(t.orderId)` (панель заказа). Нет `orderId` — пункта нет.
6. **Открыть в «Заказах»** — ссылка `#salesorders?open=<orderId>` (как стр. 137). Нет `orderId` — нет пункта.
7. **Копировать ссылку** — URL карточки (`?open=<id>`) в буфер, тост «Ссылка скопирована». Видна всем ролям, включая director.

Группа «Прочее»:
8. **Перенести в…** — п.2. Показывать при `canEdit`.
9. **Удалить в корзину** (danger, отдельным блоком, через `confirm`, текст как стр. 316; в тосте «Вернуть» → `POST :id/restore`). Права: admin, manager.

Не берём (с причиной):
- «Дублировать» — на позицию допускается одна открытая задача (`openIncomeId`, unique), дубль невозможен; для свободной задачи ценности нет.
- «Приложить файл/модель» — полей и эндпоинта нет (`files`, вопрос ДО-1 в `DESIGN-DISCUSSION.md`). Делать после ДО-1.
- «История» — UI и эндпоинта чтения аудита по задаче нет; бэклог, не в этом ТЗ.
- «Открыть изделие» — отдельной карточки изделия в PWA для проектировщика не подтверждено; не включать без согласования маршрута.
- Статусы «Взять в работу / Завершить / Приостановить» отдельно — это смена этапа, закрыта п.8.

## 4. Меню «⋯» карточки заказа (левая колонка, стр. 269-277)
Сейчас: Открыть · На распределение все позиции · Убрать из проектирования. Порядок и состав:
1. **Открыть** (панель заказа) — оставить.
2. **Открыть в «Заказах»** — `#salesorders?open=<orderId>` (новое, ссылка).
3. **Показать только этот заказ** / «Сбросить» — задаёт `query.orderId` (фильтр уже есть, стр. 179); чтобы на доске видеть задачи одного заказа. Новое.
4. **Копировать ссылку** — на панель заказа. Новое.
5. **На распределение все позиции** (admin, manager) — оставить; в тосте число созданных задач.
6. **Убрать из проектирования** (danger, последним, `confirm`: «Задачи останутся?» — формулировку взять из существующего `dropOrder`).
Развернуть/свернуть заказ дублирует шеврон — не добавлять.

## 5. Строка позиции без задачи (стр. 257)
Её «⋯» тоже открывает лист статусов. Заменить на `menuBtn`: «Взять в работу» (`work`), «На распределение» (`queue`), «Открыть заказ». Это не дубль перетаскивания: быстрый вход для позиции, у которой ещё нет карточки.

## 6. Права ролей
- director — только просмотр: пункты 5, 6, 7 (карточка), 2-4 (заказ); без пунктов, меняющих данные.
- user (проектировщик) — п.3 (если разрешено сервером), 4, 5, 6, 7; без назначения, срока, переноса, удаления. Если `session.canEdit` у user false — меню состоит из «Перейти» + «Копировать ссылку» + фото.
- admin, manager — всё.
Кнопка «⋯» не показывается, если в меню нет ни одного пункта для роли. Сервер права проверяет сам; интерфейс только прячет.

## 7. Критерии приёмки
- Если нажать «⋯» у карточки задачи (admin) — открывается выпадающий список из п.3, а не окно «Куда перенести …».
- Если выбрать «Перенести в…» — открывается прежний лист, перенос работает; на телефоне это единственный путь.
- Если выбрать «Сменить исполнителя» и выбрать человека — аватар на карточке меняется без перезагрузки страницы.
- Если изменить срок — на карточке новый срок; «как в заказе» возвращает срок заказа (серым «из заказа» в панели).
- Если задать вопрос — на карточке бейдж «Требует ответа», задача видна в фильтре «Вопросы».
- Если у задачи нет заказа — пунктов «Открыть заказ» и «Открыть в «Заказах»» нет.
- Если «Копировать ссылку» — ссылка вставляется и открывает ту же карточку после обновления страницы.
- Если «Удалить в корзину» — запрос подтверждения; после удаления карточки нет на доске, тост «Вернуть» восстанавливает.
- Если роль user — нет пунктов назначения, срока, переноса, удаления.
- Меню у заказа: «Показать только этот заказ» оставляет в колонках только его задачи; «Сбросить» возвращает все.
- Клавиатура: Enter открывает, стрелки/Tab ходят по пунктам, Esc закрывает и возвращает фокус на «⋯»; у каждого пункта подпись по-русски, без кодов.
- Нажатие внутри меню не открывает карточку задачи (`stopPropagation`, как в `menuBtn`).
- Проверка: `node --input-type=module --check < файл` для правленых js; smoke на экране «Проектирование» (десктоп и ширина телефона).
