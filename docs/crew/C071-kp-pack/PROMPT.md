## Что хочет владелец (его слова и решения 2026-11-11)

- «Несколько КП от разных фирм на выбранные позиции».
- Цены: одно КП основное, у остальных фирм цены **дороже на процент**, у каждой фирмы свой процент; потом можно поправить.
- Сколько фирм — **по-разному**: менеджер каждый раз отмечает фирмы галочками.
- ИИ пока не подключаем. Упор: мало действий, всё подставляется само, понятный вид по шагам.

Сегодня: «Копия для другой фирмы» — по одной, четыре действия на фирму, три несвязанные карточки. На сайте три наши фирмы, у всех есть бланк.

## Общие правила

- На прод не ходить, не выкладывать. Проверять на локальном стенде (`docker compose`, API `:3001`).
- Контракт API не ломать: новые поля — необязательные; существующие маршруты и ответы не менять.
- Mongo 4.4, без транзакций: сначала все проверки, потом создание.
- Трогать только: `backend/src/modules/offers/**`, `backend/pwa/sections/offers.js`, `backend/pwa/sections/kp.js`, новые файлы рядом с ними, `backend/test/e2e/offers*.e2e-spec.ts`, `docs/MAP.md` (строка модуля offers), `docs/openapi.json` (перегенерация), `backend/pwa/sections/help-flow-data.js` (если меняется путь менеджера). Остальное — не трогать: в паспортах и заказах работает координатор.
- На экране только русский, без служебных кодов. Ввод — в правой панели. Новых цветов и компонентов не вводить: брать готовые из `backend/pwa/ui/kit/` (правила — `docs/DESIGN.md` §0–6).
- Коммит только своих путей (`git commit -- <файлы>`). Правку `ui/kit` и `sections` в один коммит не класть — хук отклонит. Метки перед эстафетой: `Класс: L`, `Дизайнер: не принято` (приёмку вида сделает координатор), `Проверка: …`.
- После каждой части — `tools\dc.cmd check` зелёный. Синтаксис экранов — `node --input-type=module --check < файл`.

## Часть 1. Сервер: пакет КП

1. `offer.schema.ts`: необязательное поле `packId` (строка, индекс sparse). У всех КП одного пакета оно одинаковое, включая исходное.
2. Новый маршрут `POST /offers/:id/copies` (права — как у существующего `POST /offers/:id/copy`). Тело: `{ companies: [{ companyId, markupPercent }] }`, от 1 до 10 фирм, процент от −50 до 200, по умолчанию 0. DTO обязателен (`ValidationPipe` с `forbidNonWhitelisted`).
3. Поведение: взять исходное КП; для каждой фирмы создать черновик так же, как это делает существующая копия (`copy`): цены × (1 + %/100) с округлением до рубля, бланк, НДС и стандартные тексты новой фирмы, новый номер из общего счётчика, `copyOf` = исходное. Всем, включая исходное, записать один `packId` (если у исходного уже есть — использовать его).
4. Проверки до создания, ответ 400 с понятным текстом по-русски: фирма не «наша»; фирма совпадает с фирмой исходного КП или повторяется в списке; **у фирмы нет своего бланка КП** — «У фирмы „…“ нет бланка КП. Загрузите бланк: Контрагенты → Наши компании». Чужой бланк не подставлять. (Допущение координатора; владелец может изменить.)
5. `GET /offers`: необязательный фильтр `packId`; в строке списка — `packId` и `packSize` (сколько КП в пакете).
6. `GET /offers/companies`: добавить `hasBlank: boolean` каждой фирме.
7. Тесты: юнит на наценку и округление, на каждую ошибку 400, на общий `packId`; e2e — «исходное + 2 фирмы → 3 КП с одним packId, цены +3 % и +5 %».
8. `docs/openapi.json` перегенерировать (skill `datacore-verify`), `docs/MAP.md` — строка модуля.

## Часть 2. Экран: «Копии для нескольких фирм»

1. В карточке КП рядом с «Копия для другой фирмы» — действие **«КП от других фирм»**. Правая панель:
   - список наших фирм галочками (кроме фирмы этого КП); у каждой — поле «Наценка, %» (по умолчанию 0) и готовая сумма рядом: «СИЮ · +3 % · 700 400 ₽»;
   - фирма без бланка — серая, без галочки, с подсказкой «нет бланка КП» и ссылкой на «Наши компании»;
   - сверху одна строка-итог: «Получится 3 КП: …»;
   - одна главная кнопка «Создать N КП».
2. Последние выбранные фирмы и проценты запомнить для этого менеджера (как принято в проекте — посмотри, как запоминает воронка паспортов) и подставить в следующий раз.
3. После создания — карточка исходного КП с блоком **«Пакет»**: все КП пакета в ряд (фирма, номер, сумма, статус), по нажатию — открыть КП. В списке КП у строки — метка «пакет из 3».
4. В блоке «Пакет» — «Скачать все PDF» (архив одним файлом; образец — `backend/pwa/sections/order-attachments-zip.js`).
5. Корзина «В КП» (`kp.js`): список фирм брать из `/offers/companies`, умолчания — из `/offers/defaults`; срок действия привести к одному значению с формой (в разборе KP.md §4: сейчас 14 и 10 дней — взять значение формы).

## Что не делать

Воронку «Новое КП», подсказки из прошлого КП, проверку перед отправкой, ИИ — это следующие задания (KP.md, К4–К8).

## Готово, когда

- На стенде: КП на 3 позиции → «КП от других фирм» → две галочки с +3 % и +5 % → «Создать 2 КП» → в блоке «Пакет» три КП с верными суммами → «Скачать все PDF» даёт три файла на бланках своих фирм.
- Действий менеджера на пакет из трёх фирм — не больше 8 (было около 30).
- `tools\dc.cmd check` зелёный; e2e по КП зелёные; полный e2e — если Docker доступен, иначе пометка в коммите.
