# ТЗ: порядок в «Изделиях» (Фаза ИЗ, docs/TASKS.md ИЗ-3…ИЗ-15)

Класс: L · агентов ≤ 4 (backend, frontend, qa, designer) · проверка: full перед выкладкой.
Не читать: весь backend/src, openapi.json целиком, TASKS целиком. Только места ниже.
Общие с CRM: `productpassports` — поля не удалять, массовых updateMany нет. Схема `products` не меняется.

## Решения (совет архитектора, принято координатором)

1. **Категория паспорта — одна: у изделия** (`r.passportCategory.code`; ручная правка — `passportDefaults.passportCategory`, форма изделия).
   - Черновик паспорта (status = draft) с `productId`: сервер при чтении, сохранении и печати ставит категорию изделия.
   - Паспорт без изделия: выбор категории в паспорте остаётся.
   - Выданные (status ≠ draft): не менять. В списке паспортов — знак «категория отличается от изделия».
   - Снимок текста (`textSnapshot`) с ручной правкой (`editedAt`) не пересобирать.
   - Изделие без категории: в паспорте остаётся ручной выбор (иначе PDF 400).
2. **Двойные поля.** Паспорт с `productId`: поля, которые есть в изделии (name, article, габариты, вес, материалы, назначение, монтаж, описание, фото img_*, textChoices, warrantyMonths и PD_KEYS) — только чтение, подпись «из изделия», ссылка «Изменить в изделии». Сервер в снимке берёт их из изделия. В документе паспорта — копия для истории.
   Поля только паспорта не трогать: seatWidth/Height, supports, shipVolume, cert*, bom, schemeSource, данные заказа и монтажа.
   `elements`, `installationTypeId`, `isKit`, `warrantyMonths`, срок службы — в форму изделия, блок «Паспорт».
   Убрать обратную запись категории из паспорта в изделие (`passports/form.js` ~213 `_remember.defaults.passportCategory`).
3. **fullName («Длинное название»)** — не показывать и не писать: `products.js` ~359, ~441, toBody; `orders.js` ~235 → `name`. DTO оставить (старые клиенты), сервер игнорирует (`showcase.service.ts` ~286). Поиск по fullName (names.ts, product-match.ts) — оставить. fullName организаций и материалов склада — не трогать. Проверить `passport-bulk.ts`, `showcase-from-passports.ts`.
4. **Порядок блоков формы изделия** (`products.js` ~435–476):
   1) Изделие: фото, Короткое название*, Тип*, Группа, Артикул, Статус · 2) Цена (+ себестоимость) · 3) Паспорт: категория (подпись, откуда), тексты, гарантия, срок службы, тип монтажа, элементы, комплект · 4) Характеристики: габариты, вес, ед. изм., RAL · 5) Описание и материалы: материалы, назначение, монтаж, описание · 6) Дополнительно (свёрнуто): название в договоре (подсказка «пусто — берётся короткое»), серия, цвета, размеры, кто проектировал, примечание.
   Карточка справа (просмотр, ~330–400) — тот же порядок.
5. **Серия:** справочника нет, варианты — из уже введённых (`form-values.ts` ~9). Подсказка «варианты — из уже введённых серий»; пустой список — «Серий ещё нет — впишите».
6. **Выпадающие списки (ИЗ-11, ИЗ-12):** группа — только группы выбранного типа сверху (уже так), проверить массовую правку (`products.js` ~76–88) и форму паспорта: варианты зависят от выбранного выше; после выбора список закрывается (`ui/phrases.js`, `ui/suggest.js`, `ui/target-picker.js`, `passports/product-block.js`, `composition.js`).
