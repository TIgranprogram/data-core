# C136 — паспорт поставщика у покупных изделий

Класс: L. Агентов ≤ 4: backend → frontend → designer; qa — координатор. Решение — `ADVICE.md` (обязательно).
Просьба владельца 16.11.2026: у покупных изделий свой паспорт не делаем — загрузить файл поставщика и скачать; в архив паспортов заказа он попадает сам.

## Backend (только backend/src, backend/test, backend/scripts)
1. `productattachments`: поле `materialId?`; ровно одно из `productId`/`materialId`. Вид файла «Паспорт поставщика» (сид вида). Маршруты списка/загрузки/скачивания с `materialId`, роли как у вложений. DTO — все реальные поля (whitelist). Индекс `{materialId, typeId, deletedAt}`.
2. «Заменить» = старый в корзину, новый добавить; действует последний живой.
3. `materials` (общая с CRM) не менять.
4. Архив паспортов заказа (`passport-pdf.service.ts:139`, `zip.ts`): `purchasedMaterialsOfOrder` (строки → productIds → состав → materialKind='purchased', запросы `$in`). Файл как есть, имя `Поставщик_<материал>.<ext>`, один материал — один файл, суффикс при совпадении; нет файла — строка «нет паспорта поставщика: …», архив собирается; `markIssued` не вызывать.
5. Вложения заказа (`summary`, `attachments.zip`) не захватывают записи без `productId`.
6. Юнит: одно из двух полей; zip с файлом и без; материал в двух изделиях — один файл. e2e: загрузка и скачивание по `materialId`. openapi (если без Docker нельзя — пометка), `docs/MAP.md`.

## Frontend (только backend/pwa)
1. Карточка склада (`stock-card.js`) у материала вида purchased: блок «Паспорт поставщика» — Загрузить / Скачать / Заменить (как `product-attachments.js`: прогресс, понятные ошибки).
2. `stock-passport.js`: у покупного вместо полей «Для паспорта» — подсказка «Покупное: загрузите паспорт поставщика».
3. Окно архива паспортов заказа — показать «нет паспорта поставщика: …», если сервер вернул.
4. atlas-data.js и помощь — по изменениям. Проверка: `node --input-type=module --check < файл` и `node --experimental-vm-modules --test` изменённых разделов.

## Вопрос пользователю
Покупное, вписанное в заказ вручную без изделия, — не связано; записать в `docs/QUESTIONS.md`.

## Приёмка
Снимки карточки покупного (пусто, загружено), архив заказа с файлом → `evidence/`.
