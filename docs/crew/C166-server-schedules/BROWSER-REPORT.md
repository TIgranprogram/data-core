# C166 — фактический браузерный сценарий

Изолированная копия18.11, frozen `890dece6`, owned run `203791eb79f145b91aff6844`. Production и домен не менялись; все настройки записывались только в эту копию. Bridge выключен, автоисполнение заданий не запускалось.

## Основной прогон

В первой вкладке реальный PUT получил200/revision1; вторая открытая форма отправила старую revision0 и получила409/SCHEDULE_REVISION_CONFLICT, сохранив ввод. Отмена и повторное открытие, расписания данных/кода, следующие даты проверены. Отдельные GET подтвердили revision1 и неизменные main/normal/jobnull. Сняты10кадров1920/1024вобеихтемах.

Оригинальный процесс завершился FAIL только на последнем отчётном сравнении: успешный ответ содержит `code` как объект расписания кода, а коллектор ожидал null как отсутствие кода ошибки. Журнал сохранён неизменным: [result.json](evidence/result.json), независимый [readback.json](evidence/readback.json). Повторять успешный PUT ради зелёного журнала не стали. В отдельном исправленном коллекторе поле ошибки читается только при HTTP>=400; исходный прогон не переписан.

## Добор визуального контекста

Первичная дизайнерская оценка PARTIAL потребовала полной страницы с правой панелью и недостающих тем. Существующий run возобновлён без пересоздания БД/restore/build, revision1 сохранена. Дополнительный сценарий завершился exit0/5checksPASS: полная панель1024обетемы, unknown dark, конфликт light, контрольная revision1 без заданий. [Результат](evidence/supplement/result.json), четыре PNG рядом.

Для визуального светлого конфликта первый GET отдельной вкладки проецировал известную старую revision0; затем один настоящий PUT с ожидаемо устаревшей revision0 получил409. Конфигурация не изменилась. Это фикстура визуального состояния; реальная гонка двух вкладок без подмены ответа доказана основным прогоном. Браузерная сессия только stdin, прокси разрешал лишь loopback3102, точные GET/assets и утверждённые тела PUT; прочие записи запрещены. Ошибок страницы/API/assets и внешних запросов страницы нет. Фоновые CONNECT Chrome блокировались, секреты не записывались.

## Уроки среды

- Compose из Git на Windows мог содержать CRLF. Подготовка fail-closed остановилась до остановки прежнего стенда; перед overlay введена нормализация CRLF→LF с offline-проверкой фактически распакованного файла. Неудачная подготовка сохранена, данные не восстанавливались повторно поверх БД.
- После первого возврата ownedC163 helper сообщил ошибку Windows libuv уже после успешного запуска; два независимых GET подтвердили восстановленный C163. Ошибка инструмента не подменяет проверку фактического состояния.
- Визуальный вывод — [UI-REVIEW.md](UI-REVIEW.md): дизайнер принял после четырёх дополнительных кадров. Изолированные host47 и backendтесты отдельно, реальное переключение VPS этим сценарием не доказано.
