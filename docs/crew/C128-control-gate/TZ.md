# C128 — «Ворота»: единая точка учёта ведения сайта

**Зачем (владелец, 16.11):** «Система, которая контролирует, что где менялось, что проверялось, что осталось, и всегда актуальна. Единая точка входа: всё, что делается сейчас и в будущем, проходит через эти ворота — что, куда, как, по категориям». Пользуется ею Claude (и локальные ИИ); владелец видит итог.

## Устройство (решение координатора)

**1. Участки — «Карта сайта».** Единица учёта — блок/шаг `backend/pwa/sections/atlas-data.js` (уже есть: файлы кода, документы, связи). Сервер, инструменты и доки тоже получают участки (`area:` — «сервер/паспорта», «пульт», «тестировщик»…). Файл без участка — сигнал (`dc check`).

**2. Журнал участка — `tools/registry/<участок>.json`** (в git, маленькие файлы, один участок — один файл, без конфликтов между ПК):
- `changed`: последний коммит, затронувший файлы участка (считается из git, не пишется руками);
- `checks`: { тестировщик, обход, дизайн, скорость, юнит/e2e, глазами-владелец } → дата, коммит, итог (ок / N находок + ссылка на отчёт);
- `open`: открытые задачи участка (коды из TASKS/BOARD);
- `state`: **свежий** (все проверки после последнего изменения) / **устарел** (код менялся после проверки) / **не проверен**.

**3. Кто пишет — только программы, не руками:**
- коммит (хук) → участки по изменённым файлам → `changed`; задача в сообщении (C127…) → `open/closed`;
- ИИ-тестировщик, `dc audit`, design-lint, vision-review, Старожил — после прогона дописывают `checks` своих участков;
- выкладка (`release.sh`) → версия у всех участков, ушедших на сайт.

**4. Ворота — `dc gate`** (одна команда; ею начинается и заканчивается любая работа):
- `dc gate` — таблица участков: свежий / устарел / не проверен, открытые задачи, что проверить первым;
- `dc gate <участок>` — всё про участок: файлы, история изменений, проверки, задачи, документы (вместо чтения полпроекта);
- `dc gate next` — очередь для ночной смены: устаревшие участки → тестировщику/обходу/дизайну именно их (не весь сайт по кругу);
- `dc start` показывает строку из `dc gate`; ворота выкладки (`preflight.sh`) предупреждают, если уходит участок «не проверен».

**5. Экран для владельца** — пульт: «Состояние сайта» — плитки участков зелёный / жёлтый / серый, клик — что проверено и когда.

## Порядок внедрения (волны, по коммиту на шаг)
1. Участки: каждый файл `backend/` и `tools/` → участок (из atlas + правило по папкам); `dc check` — файлы без участка.
2. `tools/registry/*.json` + расчёт `changed` из git; `dc gate`, `dc gate <участок>`.
3. Запись `checks` из тестировщика, audit, design-lint, Старожила.
4. `dc gate next` → смена Старожила проверяет только устаревшее.
5. Строка в `dc start`, предупреждение в preflight, плитки в пульте.
6. Правило в CLAUDE.md: работа начинается с `dc gate <участок>`, заканчивается его обновлением (программой).

**Класс:** L (инструменты, без сайта и данных прода) · **Агенты:** без команды — Claude сам, Старожил готовит списки файлов участков · **Проверка:** тесты `node --test` для расчёта состояния, `dc check`.
