# C094 — ложная ошибка после «Готово»

12.11.2026. Класс M, общий компонент карточки. Сценарий владельца: открыть шаблон изделия 3905, ничего не менять, нажать «Готово». Карточка переходит к просмотру, но сообщает «Не удалось сохранить».

## Причина
`core/dom.js` регистрирует обработчик `h('button', { onclick })` через `addEventListener`. В `ui/kit/card.js` ветка readonly затем присваивала `cancel.onclick` ещё один обработчик, ошибочно считая это заменой первого. `const back = cancel.onclick` получал null. Первый обработчик открывал просмотр и обнулял `form`, второй обращался к `form.beforeClose` и получал TypeError. Поэтому проблема возникает даже без изменения данных.

Исправление: единый обработчик кнопки, сначала завершение `beforeClose`, затем переход к просмотру. На время записи блокируется повторное действие; ошибка оставляет форму открытой. Перед переходом проверяется, что форма ещё актуальна.

## Диагностика
`toastError` и обработчик сохранения карточки теперь передают пойманную ошибку штатному `reportError`. Раньше обещание «ошибка записана» не выполнялось для ошибок, перехваченных этими обработчиками. Сборщик удаляет секреты, не получает значения формы и подавляет повторы. Добавлен поведенческий тест регистрации до подавления повторного уведомления.

На проде диагностикой подтверждён успешный PUT шаблона 3905 с выбором установки, но новая серверная ошибка отсутствовала. Само уведомление не доказывает отказ записи. В этой правке production-данные не меняются.

Приёмка: SAVE-ERROR.md (браузер) и SAVE-ERROR-QA.md (регрессии). Backend не меняется, полный backend e2e повторять не требуется. После проверки — штатный быстрый выпуск экранов и проверка версии/доступности.
