# C148 — единый смысл состава изделия и описания материалов

Класс L; координатор уточняет объём реализации после аудита. Поручение владельца 18.11.2026: проверить «Состав изделия» и «Части у материалов», устранить дублирование по смыслу и двойной ввод. Изделие состоит из модулей и деталей; комплекс также может содержать изделия.

## Scope

- Аналитик: только релевантные разделы docs/PRODUCT.md (каталог, паспорт), docs/PASSPORTS-V2.md; результат SHOULD.md. PRODUCT пока не менять.
- Архитектор: фактические источники состава и паспортного описания, сохранение, PDF, импорты; результат AUDIT.md, код не менять. Основной читатель кода — архитектор.
- Координатор: после выжимок зафиксировать контракт исправлений, файлы исполнителей и критерии; реализация, проверки, коммит/push и выпуск.
- Ожидаются параллельные правки только AUDIT.md и SHOULD.md разными ролями. Чужие изменения не откатывать.

## Ограничения

Сохранить старые данные, ручные описания и выпущенные паспорта. Производственный состав и паспортное описание не объединять только по совпадению названий. Доступ к данным — API через роль доступа. Прод-данные не менять; проверочные записи только на изолированном стенде. Контракт публичного API сохранять.

## Чек-лист

- [ ] Аудит: где хранится каждое значение, кто заполняет и что читает паспорт.
- [ ] Бизнес-решение: единый источник, смысл названий, правила для комплексов и старых записей.
- [ ] Конкретный контракт, scope файлов и критерии реализации.
- [ ] Реализация без двойного ввода и потери ручных данных.
- [ ] Значимые тесты, стенд с заполненными сценариями, дизайнер и QA.
- [ ] Документация, коммит, push, выпуск на реальный сервер, проверка версии/health.

## Критерии аудита

Показать цепочку «изделие → модуль/деталь/изделие комплекса → материал → текст паспорта». Для каждого внешне похожего справочника указать назначение и необходимость. Менеджер понимает, что выбрать один раз и откуда берутся тексты. Недостающие сведения не выдумывать.
