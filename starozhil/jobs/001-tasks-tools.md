# Цель
Сверка старого списка задач `docs/TASKS.md`, проба: первые 30 открытых пунктов. Программа уже собрала факты по каждому пункту — твоё дело рассудить.

# Что читать
1. `tools/logs/starozhil/tasks-facts.md` — таблица «Строка | Отметка | Пункт | Факты». Читай строки файла 5–34 (это 30 пунктов) двумя частями: read_file from 5 lines 15, затем from 20 lines 15.
2. Если факты неясны — `read_file docs/TASKS.md` с номера из колонки «Строка», 3–5 строк (там полный текст пункта).
3. Для пункта без фактов можно 1 поиск `search` по самому точному слову пункта (имя файла, маршрут, название кнопки) в `backend/pwa` или `backend/src`.

# Порядок работы
Прочитал порцию (15 строк) → сразу `note` с вердиктами каждой строки порции, коротко: «стр 4: оставить — факт …». Старые ответы инструментов забываются, записи — нет. После двух порций — `finish`, таблицу собери из своих записей.

# Как судить
- «файла нет» у главного файла пункта, а пункт про его создание → «не начато».
- «коммитов N» по коду задачи и последний коммит говорит «сделано/закрыто/выложено» → «сделано, в архив».
- Пункт ждёт решения или действия владельца → «владельцу».
- Пункт дублирует другой из этих 30 → «дубль строки N».
- Иначе → «оставить».

# Нельзя
- Не выдумывать доказательства. Пиши только то, что видно в фактах или в прочитанном файле.
- Не читать другие файлы, кроме перечисленных.

# Итог (формат finish)
Таблица, одна строка на пункт:

| Строка | Пункт (6 слов) | Вердикт | Почему (факт) |
|--|--|--|--|

Вердикт — одно из: «оставить», «сделано, в архив», «не начато», «владельцу», «дубль строки N». В конце — одна строка: сколько каждого вердикта.

# Как проверит Claude
3 вердикта «сделано, в архив» — сверить по git. 3 из 3 верны → вердикты принимаются, следующая порция — новым нарядом.
