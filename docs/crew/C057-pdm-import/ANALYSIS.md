# C057 — «Загрузка из PDM»: разведка на изделии 6104.0000.0000

> 2026-11-09, координатор. PDM только читали: в хранилище и в локальный вид ничего не записано. Файлы скопированы из PDM во временную папку (`GetFileCopy`, как в программе «Раскладка 5.1.3»).
> Класс будущей работы: **XL**. Причины: новая крупная возможность; меняется устройство продукции; `products`, `materials`, `productmodules` — общие с CRM.

**Зачем (словами пользователя):** «В пульте раздел „Загрузка из ПДМ“: набрал номер → нашёл в PDM → „Загрузить на сайт“. Изделие ложится полностью: модули, детали, картинки. Потом из него делаем паспорта и документацию».

## 1. Вывод одной строкой

**Реально.** PDM читается с этого компьютера без пароля: автовход Windows, COM `ConisioLib.EdmVault`, хранилище «PDM», корень `C:\PDM`. В PDM есть почти всё для полной модели изделия. Нет двух вещей: **названий** модулей и деталей и **количеств в самом PDM**. Количества берутся из спецификации SolidWorks, это проверено. Наша схема продукции принимает модули и материалы. **Отдельной сущности «Деталь» у нас нет** — это главный пробел.

## 4. Что надо пересмотреть в нашей продукции

1. ~~**Новая сущность «Деталь» (part).**~~ **Отменено — деталь уже есть: `materials` с `materialKind:'part'`, см. раздел 5б.** Обозначение, название, сортамент → материал (ссылка), материал-марка, Д×Ш×Т, масса, RAL, картинка, файлы (DXF/PDF), источник PDM. Строка состава получает `lineType:'part'`. Деталь — одна на весь каталог: `0000.1007.0001` в двух модулях — одна запись. Без этого «полноценной модели» нет: деталь нужна для паспорта («части изделия»), техописания (C055: «Часть → Материал → Размеры»), раскроя и производства.
2. **Поле «Обозначение» и источник.** У изделия, модуля и детали: `designation` (`6104.0000.0000`) и `pdm: { vault, fileId, version, state, path, syncedAt }`. Повторная загрузка по обозначению обновляет запись, а не плодит копии.
3. **Цвета изделия.** RAL по деталям (8017 коричневый, 6018 зелёный, 1002 жёлтый). Сейчас у изделия одно поле `ralCode`.
4. **Габариты модуля.** У модуля `width/height/depth`, у изделия — `length/width/height`. В PDM у всех Д/Ш/Т. Нужна одна договорённость.
5. **Модули в CRM.** `productmodules` и `materials` — общие с kppdf (AGENTS.md п. 4). Добавлять поля можно: старый код их не читает. Схему менять синхронно с kppdf и **не ломать**.

## 5. Как будет работать «Загрузка из PDM» (предложение)

- PDM доступен только с компьютеров в сети завода (COM Windows). Сервер сайта (VM) PDM не видит. Значит, загрузку делает **программа на ПК**, кнопка — в **пульте** (`pult/`), как просил пользователь.
- Шаги: ввести обозначение → поиск в PDM → **предпросмотр**: дерево «модули → детали → метизы», что новое, что уже есть на сайте, что не сопоставилось (материал, название) → «Загрузить на сайт» → запись через наш API машинным ключом `kppd_…` (VISION #1: напрямую в Mongo нельзя).
- Сначала стенд, потом прод. Прод — только после приёмки на стенде.
- **Количества** — три способа, все проверены:
  1. **Computed BOM PDM** — из хранилища, без SolidWorks. Из Python не читается: COM отдаёт массив структур. Нужна маленькая программа на C# — PDM API под .NET это умеет. **Рекомендую**.
  2. SolidWorks API, как `read_assembly()` в «Раскладке 5.1.3». Нужен запущенный SolidWorks.
  3. xlsx-выгрузки KV/SD. Есть не у каждого изделия, зависят от инженера.
- **Картинки:** превью файлов SolidWorks — `shell_thumbnail()` в «Раскладке». Для обложки — PDF сборочного чертежа, первая страница. Запасной путь — 88 картинок из KV.xlsx.

**Этапы (предложение):**
- Э0 — решения по вопросам ниже + совет opus по устройству «Детали» (CLAUDE.md, «Автопилот», п. 4а).
- Э1 — сервер: сущность «Деталь», `designation` + `pdm`, `lineType:'part'`, импорт-эндпоинт «загрузить дерево» (идемпотентный, по обозначению). e2e на тестовой базе.
- Э2 — приложение на C# (п. 5а-6): читатель PDM (дерево, переменные, количества по Computed BOM, картинки, файлы) — только чтение. Окно: адрес сайта + вход → номер → предпросмотр (новое / уже есть и что отличается / не сопоставилось) → «Загрузить на сайт».
- Э3 — сайт: скачивание приложения (`/api/apps/pdm-loader/download`, админка «Приложения»), проверка версии; кнопка сборки в пульте разработчика.
- Э4 — карточка изделия на сайте: вкладка «Состав» показывает модули и детали с картинками; паспорт и техописание берут части из деталей.
- Э5 — 6104 на стенде глазами → прод по «да».

## 5а. Решения пользователя 2026-11-09

1. **Названия** вписывают менеджеры на сайте. Загрузка ставит пустое название; до заполнения на экране — обозначение. Запись попадает в «Требуют заполнения».
2. **Номер — только обозначение PDM.** Обозначение = артикул на сайте (`sku`). Второго номера нет.
3. **«Деталь» — заводим обязательно**, отдельной сущностью, со связями. Дальше её используют паспорт, техописание и всё, где нужно.
4. **Без дублей.** Ключ — обозначение (у деталей уникальные имена). Запись с таким обозначением уже есть → предупредить, сравнить характеристики, показать отличия и обновить из новой загрузки. Новой копии не создавать.
5. **Конфигурации** — п. 4 раздела 6.

6. **Читатель PDM — на C#, без SolidWorks** (пользователь 2026-11-09). SolidWorks стоит не у всех. Нужен только клиент SOLIDWORKS PDM: COM `ConisioLib.EdmVault`, вход Windows. Без клиента PDM хранилище не читается никак — это ограничение PDM, не наше. Количества — Computed BOM PDM (п. 5, способ 1). Картинки — превью из PDM/PDF, без SolidWorks.
7. **Приложение скачивается с сайта** (пользователь 2026-11-09): кнопка «Скачать приложение» в админке → сервер отдаёт файл (один .exe или .zip). Им пользуются и другие администраторы.

**Решение координатора к п. 6–7:** это **отдельное приложение администратора** «DataCore · Загрузка из PDM» (позже — другие кнопки для админов), а не текущий `pult/`.
- Текущий `pult/` — пульт разработчика: Node + Git + репо, кнопки выкладки, доступа к проду, бэкапов. Раздавать его нельзя: чужой ПК получит кнопки прода.
- Новое приложение: C# .NET 8, WinForms или WPF, **один .exe** (self-contained, без установки .NET), Windows x64.
- Вход: адрес сайта + логин и пароль **своего** пользователя сайта (JWT). Права проверяет сервер: загрузка — только роли «admin» (или новое право «Загрузка из PDM»). Машинный ключ `kppd_` в .exe не зашиваем.
- Сайт: `GET /api/apps/pdm-loader/download` (только admin) → файл с версией; в админке — карточка «Приложения» с кнопкой «Скачать» и номером версии. Файл собирает `release.sh` (или отдельная кнопка пульта разработчика) и кладёт на сервер.
- Приложение при входе сравнивает свою версию с сервером: устарело → «Скачайте новую версию».
- В пульте разработчика — кнопка «Собрать приложение PDM» (`dotnet publish`), по правилам `pult/README.md`.

8. **«Продвинуто» в спецификации — в ERP не заносить** (пользователь 2026-11-09). Сборка, у которой в SolidWorks стоит «Отображение дочерних компонентов в спецификации: Продвинуть» (`swChildComponentInBOMOption` = 3, Promote; в «Раскладке» — `BOM_PROMOTE`), — служебная. Она остаётся только в PDM, у инженеров. На сайт она не идёт; её дети поднимаются к родителю с учётом количества. Сюда относятся «Сборочные модули» (`SMI.6104.0001`, `SM.2001`) и «Соединения» (`S.BM08.D603.01`). Признак берём из флага «Продвинуть», а не из вида или обозначения. Computed BOM PDM учитывает этот флаг сам; при чтении дерева ссылок флаг проверять явно.

### Что добавить в номенклатуру (только новые поля — CRM не ломается, Л9)

| Поле | Что хранит | Зачем |
|--|--|--|
| `pdmCode` | обозначение PDM из имени файла, в одном написании (Л4) | точное совпадение №1. Индекс: уникальный в организации, sparse |
| `pdmAliases[]` | другие написания: `Number`, кириллица/латиница | находить по любому написанию |
| `matchKey` | **ключ характеристик**, сервер считает сам при каждом сохранении из полей ниже: `вид · тип · стандарт · размер · марка`. Пример: `fastener·болт мебельный·DIN 603·M8×110·оцинк`; `raw·лист·t1.5·AISI 304`; `raw·фанера·t21·ФСФ II-III` | совпадение №2 «по характеристикам». Индекс |
| `pdm: { fileId, version, state, path, syncedAt }` | откуда и какая версия (у деталей, модулей, изделий) | повторная загрузка, «что изменилось» |
| размер «резьба M8» | `dimensions` с типом `diameter` = 8 (тип уже есть) | метизы: M8 и длина — раздельно |

Поля, что **уже есть** и начинаем заполнять: `typeName`, `standardRef`, `materialGrade`, `assortment`, `dimensions`, `materialKind`, `weightKg` (в кг).

### Как загрузка решает «это одно и то же»

1. **`pdmCode` или `pdmAliases` совпал** → связано, без вопросов.
2. **`matchKey` совпал, кандидат один** → связано автоматически. `pdmCode` записывается в позицию, в следующий раз — шаг 1.
3. **Кандидатов несколько или совпало частично** → «Похоже: … — это он?» с выбором. Ответ запоминается в `pdmAliases` или `pdmCode`.
4. **Не найдено** → новая позиция; поля и `matchKey` заполняются из PDM.

Ключ PDM-стороны считается тем же правилом из `Сортамент` + `Материал` + размеров. Таблица приведения одна на обе стороны: `х`↔`×`, `,`↔`.` в числах, `М`↔`M`, латиница↔кириллица, «нерж.» = AISI 304, «Ст 3» = «Ст3».

### Нюанс: лист на складе ≠ лист в детали (Л13)

На складе лист — конкретный формат: «Лист AISI 304, 1,5 мм, 1250×2500» и «…1500×3000». В PDM у детали — просто «лист 1,5 мм AISI 304», формат не важен. Значит, у детали в составе — **сортамент без формата**. Предложение: позиция-сортамент «Лист AISI 304, 1,5 мм» (сырьё, `matchKey` без формата). Складские форматы ссылаются на неё как «формат этого сортамента». Себестоимость берёт цену любого формата за м². Нужен совет opus (Э0): это меняет склад.

### Правило обозначений PDM (документ «Работа с PDM», п. 1; снимок пользователя 2026-11-09)

Формат `XXXX.YYYY.ZZZZ` = изделие . модуль . деталь.

| Шаблон | Что это | Сленг |
|--|--|--|
| `XXXX.0000.0000` | изделие | городок |
| `XXXX.YYYY.0000` | модуль YYYY изделия XXXX | городковый модуль |
| `XXXX.YYYY.ZZZZ` | деталь ZZZZ модуля YYYY изделия XXXX | деталь городкового модуля |
| `XXXX.0000.YYYY` | деталь изделия XXXX вне модуля или в нескольких модулях этого изделия | городковая деталь |
| `0000.XXXX.0000` | модуль в нескольких модулях/изделиях | каталожный / базовый / стандартный модуль |
| `0000.XXXX.YYYY` | деталь YYYY модуля XXXX | — |
| `0000.0000.XXXX` | деталь в нескольких модулях и/или изделиях | каталожная / базовая / стандартная деталь |

Что даёт правило: по обозначению видно уровень и «своё или каталожное». Каталожные модули и детали (`0000.…`) — общие для многих изделий, их загружают один раз и потом переиспользуют. Своё (`6104.…`) принадлежит одному изделию. Вид (изделие / модуль / деталь) берётся из переменной PDM `Вид_изделия`; обозначение служит проверкой. Расхождение — предупреждение в предпросмотре.

**В 6104 есть обозначения вне правила** (вопросы ниже): `SMI.6104.0001`, `SM.2001` (сборочные модули), `S.BM08.D603.01` (соединение), `PI.0003` (покупное), метизы `SK08.080.PRSH` (файл латиницей, `Number` кириллицей: `СК08.080.ПРШ`), `6104.0000.S001` (брус, буква S в номере детали).
