# C171 — проверка готовности ПК

- Реализован `preflight(options, dependencies)` в `tools/document-intake/preflight.mjs`; результат содержит `ready`, `checkedAt`, `steps`, `contour`, `actor.role`.
- Проверки: Windows, 512 МБ свободного места в выбранной папке, создание PDF в памяти и обратное извлечение текста Python/PyMuPDF, реальный ответ выбранной локальной модели по JSON Schema, GET `/auth/me` и права менеджера на суммы.
- Этапы публикуются через `onStep`; причины и восстановление фиксированы, сырые исключения и токены не возвращаются.
- Только loopback модели; редиректы отключены; модель получает лишь синтетический тест без оригиналов и авторизации DataCore.
- Автоустановщик, список проверенных моделей с контрольными суммами, докачка и проверка чистого профиля Windows ещё не реализованы. Существующий `tools/ai-tester/setup.mjs` выбирает модели, но не даёт проверенного пакета C171 с контрольными суммами.
- Проверка подключена перед каждым `analyze` в Пульте; её шаги отображаются по событиям, неготовность блокирует захват документов.
- Реальная проверка выявила два несовпадения среды: современный PyMuPDF требует `pymupdf` вместо устаревшего `fitz` в probe; рассуждающей Gemma недостаточно 64 выходных токенов. Используются современный импорт с fallback и бюджет 1024, усечённые ответы по-прежнему отклоняются.
- `node --test tools/document-intake/preflight.test.mjs`: PASS, 7 тестов (21.11.2026). Реальный чистый профиль Windows не проверен.
