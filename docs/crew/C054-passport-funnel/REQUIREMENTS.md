## 2. Модель условий

### 2.1 Минимальный набор признаков (10)

Выбран под наши 5 категорий (TRN, WRK, DSP, BLG, DIO) по реальным текстам `passport-texts.v2.json` и дефектам `seed-passport-dicts.js:97-98`. Больше не вводим; новый признак — только когда найден пункт, который иначе не отделить.

|--|--|--|--|
| `bolts` | есть болтовые/резьбовые соединения | шаг 4 | дефект «ослабление резьбы»; ТО п.7 «затяжку»; монтаж п.8 «затяжка» |

| `concrete` | опоры бетонируют | способ установки | монтаж п.7 «бетон», п.8 «вертикальность стоек», фундамент |
| `anchors` | анкеры/шпильки | способ установки | монтаж п.9 «выступающие концы анкеров» |

| `moving` | подвижные части | вид изделия | ТО «люфт, подшипники»; гарантия п.12 «износ подвижных» (DIO/TRN уже по категории) |

Заметки: «цельное» = ни `bolts`, ни `welds` (отдельного признака нет). `hasConcrete/hasWood…` из ТЗ — те же коды без `has`. `polymer` и `ground` не вводим: «металл, древесина, полимеры, бетон» (ALL disposal п.4) и «полимерные детали» (п.6) переписываем нейтрально, это дешевле условия. Принцип аудита: сначала переформулировать пункт так, чтобы он был верным для всех; условие — только если нельзя.

Источник признаков — три слоя, всё сливается в одно множество `traits` при сборке (не человек на каждом паспорте):
1. Справочники: у `passportMaterials`, `passportInstall`, `passportElements` и (необязательно) `productFacetValues` — новое поле `traits` (список кодов). Пример: материал «Дерево клеёное» → `wood`; способ «Бетонирование опор» → `concrete`.
2. Явный выбор шага 4: `joints[]` ∈ {bolts, welds, solid} — на паспорте и в `products.passportDefaults`.
3. Ручной выбор подсказки «признаки этого паспорта» — не делаем (лишний шаг). Исключение — `excludeDefects` (уже есть, остаётся как ручной запасной путь, 597 его использует).

Итоговое множество пишется в снимок `textSnapshot.traits` (для объяснения «почему вошло/не вошло»).

### 2.2 Условие пункта

Одна запись `when` — простая строка, не JSON, чтобы её мог править человек в справочнике:
`bolts|welds` (любой из) · `!freestanding` (нет) · пробел = И. Пример: `concrete !freestanding`. Парсер строки в `PassportCondition` — одна чистая функция + тест; дальше работает готовый `evalCondition` (поле `traits`, `op: eq/in`, `not`).

Правило: пустое/нет `when` = пункт общий для всех (гарантия, рекламации, журналы остаются как есть). Опечатка/неизвестный код в `when` = ошибка при сохранении (не молчаливое «не показывать»).

### 2.3 Где хранить (только новые поля, существующие коллекции)

| Что | Где | Поле |

## 4. Аудит пунктов «Для всех»: скрипт → решение пользователя → `--apply`

Скрипт `backend/scripts/passport-items-audit.js` (по образцу `passport-text-dupes.js`, `customers-cleanup.js`): по умолчанию ТОЛЬКО отчёт (`tools/logs/c054/audit.json` + `.csv`), ничего не пишет.

Обходит: пункты ALL и всех категорий (json + активные версии `passporttemplates`), `passportPhrases`, `passportDefects`, `passportInstall.baseRequirements`, `passportMaterials.madeOf`, `passportStyle`.

Поля строки отчёта: `source` (template/phrase/defect/install/material/style) · `ref` (категория/раздел/№ пункта или code записи) · `text` (первые 120 знаков) · `scope` (ALL / категории / привязка C028) · `has_when` · `hits` (какие слова-корни сработали: бетон, анкер, болт, резьб, свар, шов, древес, дерев, корн, вставать, стойк, подвижн, подшипн, табличк, спортивн, перед занятием) · `suggest_traits` (предложение: `concrete`, `bolts`…) · `suggest_action` (`keep` / `rewrite-neutral` / `when:<выражение>` / `move-to:<категория>`) · `used_by` (сколько ВЫДАННЫХ паспортов категории содержат пункт в снимке; сколько черновиков) · `decision` (пусто — для пользователя).

Порядок:
1. Отчёт → в пульт-кнопку «Проверить пункты паспорта»; лежит в `tools/logs/c054/`.
2. Пользователь открывает таблицу, в колонке `decision` пишет `ok` / `when: …` / `переписать: <текст>` / `убрать` (по умолчанию пусто = не трогать). Список коротких решений ≤ 40 строк: большинство пунктов `keep` по умолчанию, спорное (с `hits`) — наверху.
3. `--apply decisions.json` (после «да» пользователя, на проде запускает он через пульт): новые версии шаблонов категорий (`saveTemplate` — версионность), поля `when/traits` в `dict_values`; для ALL v2 — патч `passport-texts.v2.json` (коммитится, не БД). Идемпотентно (повтор = 0 изменений), печатает план «до/после», выданные паспорта (`textSnapshot` у `status=issued`) НЕ трогает.
4. После `--apply` — сухой прогон «что изменилось бы в черновиках» (число пунктов минус/плюс) для сверки.

## 5. Экран

- Партия: в шаге «Комплектность» (`passport-wizard.js:154`, `form.js:147`) колонки `Обозначение · Наименование · Размер, мм · Масса, кг · Кол-во · Ед.`; вставка из Excel (выделенный диапазон) и «Шаблон» уже есть у `rowsTable` (`ui/rows-table.js`). Подсказка: «2 и более размеров = партия». Сводка габаритов партии — min/max строкой «по таблице» (как сейчас в PDF `:11`). `parseBom` сохраняет `size/mass`.
- Правка пункта «только для этого паспорта»: ✎ (есть) + «убрать пункт» + правка строк ТО/монтажа (см. §3 п.10); значок «изменён для этого паспорта» (есть).
- «Что попадёт в PDF» (шаг 8): счётчик «пунктов: N, условных: M, не вошло: K» и список «не вошло» с причиной («нужно: болты — не выбрано»). Это же — основа проверки «глазами» дизайнером.
- Нумерация: см. §3 п.9; предпросмотр в карточке (`lastNo`, `card-blocks.js:59`) считает так же, как PDF — один источник нумерации.

## 6. Критерии приёмки

Паспорт 597 — эталон (категория BLG, решётка приствольная, 34 размера).

1. Если категория BLG, вид «Приствольная решётка», материал «Сталь с порошковой окраской (лист)», конструкция «Цельное» (нет болтов и сварки), способ «Укладывается на основание» ⇒ в PDF нет ни одного из: «опоры бетонируют», «вертикальность стоек», «анкеры и шпильки», «нет корней деревьев», «вставать запрещается», «ослабление резьбовых», «трещины в сварных швах», «отсутствие крепежа», «проседания под опорами», «изготовлено из стальной трубы», «перед занятием», «спортивная обувь», «не раскачивайте». Проверка: автотест + поиск этих подстрок в тексте PDF.
2. Если способ установки «бетонирование опор» и конструкция «болты, сварка» ⇒ пункты бетона, вертикальности, дефекты резьбы и швов ВСТАЛИ (ничего не пропало лишнего).
3. Если у пункта нет `when` ⇒ он в паспорте любой категории (гарантия, рекламации, журналы, утилизация-общее): тест «разность множеств до/после аудита только в пунктах с решением».
4. Если в `when` неизвестный код или пустое после `!` ⇒ сохранение справочника отклоняется с понятным текстом.
5. Если признак `bolts/welds` не определён (шаг 4 не пройден) для категории с условными пунктами ⇒ выпуск заблокирован, в «не хватает»: «Конструкция: выберите».

10. Время: пользователь собирает паспорт 597 в экране с нуля (изделие → шаги → предпросмотр → PDF) за ≤ 5 минут и ≤ 25 кликов (замер сеансом, одним человеком, секундомер/счётчик кликов — фиксируется в REPORT).
