# C159. Данные для проверки выбора изделия

На изолированной копии `localhost:3102` проверили отсутствие строки 3 и `clientUid` в заказе `QA-C155-ORDER-1119`. Через штатный помощник отправили один `POST /api/incomes`.

```json
{
  "orderId": "6aff0bcb34de43c56e5ac570",
  "lineNo": 3,
  "title": "QA C159 — выбор изделия",
  "productId": null,
  "qty": 3,
  "unitPrice": 137,
  "clientUid": "qa-c159-photo-picker-line-1119"
}
```

`GET /api/incomes/6aff1ada34de43c56e5acb25` подтвердил `version=0`, `__v=0`, пустой `productId`, количество 3, цену 137, итог 411, прежний тестовый заказ и наследование фирмы из его шапки. Платежей 0. Поля `amount`, `companyId` и `lineType` вычисляются сервером по контракту создания. Запросы исходных строк и паспортов 611/612 в этот прогон не входили. Сырые ответы хранятся локально в `tools/logs/c159/`.

## Каталог и фотографии

- `GET /api/showcase/groups` вернул 23 узла с `id` и `parentId`. Поиск «жим» в группе `6addd76fc93bb8ea2a6e3939` вернул 25 изделий. `facets=1` вернул пустой список серий для этой выборки. `groupId` охватывает подгруппы, `series` отбирает указанную серию, `page` и `limit` ограничивают страницу.
- Изделие 1067 (`6adaff0f2a8dad6034b14522`) содержит ссылки на два обычных фото и две миниатюры. Все четыре ссылки на QA ответили 404. Карточка подходит для проверки заглушки при недоступном изображении.
- Оригинал и миниатюра изделия 1066 (`6ae1269ae36900370537a2f3`) первоначально отвечали 404. Оба файла получены через `api.sh prod GET` и скопированы по исходным путям в отдельный том `dc-2fd2723433a343191577b795-night_uploads`. Двоичные ответы повторных GET на QA совпали с рабочими файлами и ранее записанными контрольными суммами C155. Файлы 1067 оставили в исходном состоянии для проверки заглушки.
- Автопроверка отклонила прямую проверку файлов через `curl`, поскольку для доступа требуется штатный `api.sh`. Восстановление 1066 выполнено через разрешённый помощник с перенаправлением двоичного тела GET в файл средствами Bash.

## Ошибка перехода к контрагенту на рабочем сайте

`GET /api/client-errors/top?hours=24` вернул пять групп. Сообщения «Некорректный id контрагента» среди них нет. Сервер возвращает HTTP 400 для некорректного ID. Клиентский журнал фиксирует сетевые ошибки и ответы 5xx, поэтому фактические маршрут, время и значение ID этого случая по доступному журналу установить не удалось. Санитизированная сводка сохранена в `tools/logs/c159/partner-invalid-id-prod.json`.
