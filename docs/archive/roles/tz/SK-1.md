# ТЗ SK-1 — фильтры «как в магазине» (интерфейс)

**Зачем (словами пользователя):** фильтры как в интернет-магазине: крупная кнопка поиска, панель фильтров с галочками, длинные группы свёрнуты.

**Роли:** frontend ☑ (по skill `datacore-design`) · designer ☐ (после)

## Что сделать (чек-лист SK-1 в `docs/roles/tz/SKLAD.md`; первый пункт уже сделан — числа у значений убраны)
1. Свёрнутый вид: крупная кнопка-поиск; по нажатию — ввод текста + панель фильтров (слева на компьютере, выезжающая на телефоне).
2. Группы фильтров сворачиваемые: длинные (> 6 значений) свёрнуты, короткие раскрыты; значения — галочками.
3. Запись в `docs/DESIGN.md` §8 (компонент фильтра).

## Файлы
- В рабочей копии ожидаются правки: `backend/src/modules/stock/*`, `docs/openapi.json`, `docs/MAP.md` (backend, SK-4a) — не трогать.
- читать: `docs/roles/README.md`, skill `datacore-design` → `docs/DESIGN.md`, `backend/pwa/ui/facet-filter.js`, где он используется (`sections/stock.js` и др. — grep).
- менять: `backend/pwa/ui/facet-filter.js`, CSS компонента, минимально — места вызова; `docs/DESIGN.md` §8.

## Критерии приёмки
- [ ] Работает на 390 / 1024 / 1920 px (панель слева на компьютере, выезжает на телефоне).
- [ ] Группы > 6 значений свёрнуты, ≤ 6 — раскрыты; выбор галочками фильтрует как раньше.
- [ ] Ввод данных не в модальном окне (CANON / DESIGN).
- [ ] `node --input-type=module --check < файл` для каждого изменённого .js — без ошибок.

## Нельзя
- Новых видов окон без записи в DESIGN; трогать сервер.
