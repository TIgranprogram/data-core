- **frontend** не вправе: новый класс, CSS вне kit, `ui/*.js`, `--accept`. Это не просьба — L1/L3/H1 отклонят коммит. Нужен вид, которого нет, — запрос «вариант X эталона Y» координатору.

- **Каждое замечание пользователя о виде** → новое правило L/A + тест в `site-audit.test.mjs` (правило 2026-11-01 уже есть — применить к порядку).

## 7. Риски и честная оценка
- **Объём:** 27 тыс. строк, ≈ 4 730 нарушений + админка. Волна 0 — 2–3 сессии (самая важная: без неё числа врут). Волны 1–9 — по 1–2 сессии L-класса, волна 10 — 1. Итого ≈ 15–20 сессий; при лимите ≈ 14 %/день — 3–5 недель параллельно с делом.
- **Достижимо полностью:** единый словарь, 0 своих классов и стилей в `sections/`, одна карточка/кнопка/таблица/панель, храповик, при котором беспорядок не возвращается без явного «Дизайн-исключения».
- **Не достижимо полностью:** статика обходится (класс собран из переменных, `h` через обёртку) — поэтому обязателен A1 в браузере, а у аудита есть слепые зоны (экраны без данных на стенде, состояния ошибок). Особые экраны (календарь, сетки, печать, Гант) останутся исключениями. Смысл и удобство машина не проверит — это остаётся за designer.
- **Риск поломки:** перевод экрана меняет вид — каждая волна = одна выкладка, проверка обходом стенда, «Отменить» через git. Общие с CRM данные не затронуты (только вид).
- **Риск «вечного baseline»:** если число не обязано падать каждую волну, долг останется навсегда — поэтому H4.

## 8. Принцип «картотека» (RIGHT-PANEL-V2) — как его закрепить машиной
- **Устройство:** меню слева и список — неподвижны; всё про сущность — `entityPanel` справа: шапка-контекст → главный блок → карточки связей (`card M`, внутри группы — `card variant:'table'`) → история свёрнута. Клик по связи меняет только панель (`?of=…&ctx=…`, шаг истории «карточка»), список не перерисовывается.
- **Новые проверки:** **A6 «не прыгает»** — аудит кликает связь в панели и сравнивает `getBoundingClientRect` меню, шапки и списка до/после (сдвиг > 2px или перерисовка `.main` — находка). **A7 «кнопка одна»** — на экране + панели собрать подписи кнопок; одна и та же подпись-действие дважды (кроме строк таблицы) — находка; `primary` > 1 — находка. **A8 связи видны** — у каждой открытой сущности ≥ 1 карточка связи или пустое состояние «Связей нет». **L10** — `rowAction`/кнопки шага объявляются в описании раздела один раз (kit берёт их и для строки, и для панели), ручная кнопка с той же подписью — нарушение.
- **Развилки стиля (решает пользователь на витрине `#kit`, раздел «Выбор»; по 3 варианта рядом, обе темы, 390/1920):**
  1. Карточка: **А** «бумага» — рамка 1px, без тени, полоса тона 4px · **Б** «приподнятая» — без рамки, `--shadow-sm`, подъём при наведении · **В** «плоская плитка» — фон `--surface-2`, без рамки (плотнее всего).
  2. Таблица внутри карточки: **А** зебра · **Б** только линии-разделители · **В** без линий, отступы и выравнивание по сетке.
  3. Связи в панели: **А** сетка карточек minmax 240px · **Б** список-аккордеон (одна раскрыта) · **В** вкладки-фишки над главным блоком.
  Выбор фиксируется токенами (`--card-*`) и одним вариантом kit; остальные удаляются из витрины. Мой выбор по умолчанию: 1А, 2Б, 3А (спокойно, «бумага и чернила»).
- **Сверх ожиданий (без ломки сайта, по одному шагу за волной):** палитра команд `Ctrl+K` — один поиск и по записям, и по действиям («Принять по счёту 552»); «хлебные крошки связей» в шапке панели (Заказ 552 › Позиция 3 › Изделие) с возвратом на шаг; закреп правой панели и вторая панель для сравнения двух записей (≥ 1920px); быстрый просмотр по наведению на ссылку сущности (`card S` во всплывашке, без перехода); сохранённые виды списка («Мои срочные») — фильтр + колонки одним пунктом; пустые состояния с одним следующим шагом; плотность «уютно / компактно» одним переключателем для всех таблиц (токены, не классы); скелетоны той же формы, что карточка (нет прыжка при загрузке); оптимистичные действия с «Отменить» вместо подтверждений. Каждое — сначала вариант в kit и витрине, затем экран; ни одно не меняет данные и API.

## Вывод
Полный порядок достижим для видимого слоя «Рабочего места» — с закрытым списком исключений — и усилий стоит: сейчас 4 730 прощённых нарушений и открытый `--accept` значат, что каждый новый агент добавляет беспорядок быстрее, чем его убирают, а десятый вид карточки — следствие правил, которые проверяют слова в коммите, а не код. Главная ценность — не перевод экранов, а волна 0: честный kit с отметкой `data-k`, храповик и pre-commit. После неё беспорядок перестаёт расти сам по себе, а каждая следующая волна видна одним числом. Без волны 0 переводить экраны бессмысленно — через месяц всё вернётся.
