# ТЗ WAREHOUSE-ZONES — «Склады» справочником (класс L/XL; совет opus 2026-11-01)

Пожелание пользователя: склады — справочник (сейчас «Основной», «Профильная труба», «Листовой материал»; потом ещё). Администратор привязывает позиции к складу (категориями + поштучно). У роли — галочки складов. Кладовщик «Основного» НИГДЕ не видит категорий других складов (списки, мобильный склад, поиск, приёмка, выдача, брони, заявки). Работает везде без ручной подвязки в экранах.

Сейчас: `common/stock-scope.ts` (stockScopeFor, кэш из RoleService) — но применяется вручную в ~12 местах stock.controller.ts:28-223; в supply, поиске, приёмке, материалах — нет.

1. **Модель:** новая коллекция data-core `stockzones` {name, categoryIds[], includeMaterialIds[], excludeMaterialIds[], isDefault, order, deletedAt}. Общую `warehouses` (физические склады CRM) не трогать.
2. **Роль:** `Role.warehouseIds` (необязательное; пусто — весь склад). Доступ = объединение выбранных складов. `stockCategoryIds` — запасной путь, пока не перенесено; скрипт переноса план→--apply с бэкапом.
3. **Единый вход:** stockScopeFor → {categoryIds (с потомками), includeIds, excludeIds} | null (admin/owner — null); `scopeMatch(scope)` = {$or:[{categoryId:{$in}}, {_id:{$in:include}}], _id:{$nin:exclude}}; все запросы к materials/storageitems/stockmovements/reservations/supplyrequests (по позициям), categories(type material), поиск/lookup — через него; декоратор `@StockScoped()` + сервисы требуют scope аргументом. Запись по чужой позиции — 403. Позиция без категории — только складу isDefault («Основной»).
4. **Тест-перечень:** e2e — роль «Основной» обходит ВСЕ GET-маршруты stock/supply/dicts(material)/search/lookup (список из реестра Nest через DiscoveryService) — ни одного id чужой категории; новый маршрут без фильтра роняет тест.
5. **Экран:** админка «Справочники → Склады» (название, дерево категорий галочками, добавки/исключения поштучно); в роли — галочки складов; «Остатки» и stock-mobile — переключатель склада из доступных (один — скрыт); `GET /api/stock/zones` — доступные пользователю.
6. **Порядок:** M сервер (коллекция, CRUD admin, кэш, scopeMatch, тесты) → L перевод всех мест + e2e-перечень → M экран (дизайнер) → S перенос stockCategoryIds; создать три склада.
Ловушки: брони/заявки со смешанными позициями — показывать только свои строки, итоги по видимым; подкатегории раскрывать на сервере; кэш в памяти; индексы в ensure-indexes.js; Mongo 4.4.
