# ТЗ RELEASE-GATE — ворота перед выкладкой и порядок процесса

> Основание — `docs/roles/audit-2026-10-29-process.md` (номера 🔴/🟡/⚪ ниже — оттуда).

**Зачем (словами пользователя):** любая правка — кнопка, фича, удаление — проходит один порядок. Система не падает из-за мелкой правки. Порядок дешёвый по токенам.

**Класс:** L (скрипты выкладки + доки процесса) · **Max agents:** 1 (qa — проверить скрипты на стенде) · **Reviewers:** qa ☑ architect ☐ designer ☐ · **Max review loops:** 2 · **Проверки:** smoke + пробная выкладка
**Делает:** координатор сам. Скрипты — bash, без новых пакетов. Прод по умолчанию не меняется, пока шаг не проверен.

## Shared pack
- Ворота — скрипт `deploy/synology/preflight.sh`, не LLM-агент. Новый агент не создаём.
- Красное в воротах — выкладки нет. Обход — только флаг `--force-urgent` и строка в коммите «срочно: причина» (сайт уже сломан).

- Нельзя: трогать `datacore-mongo`, kppdf `:3000`, данные прода. Флаги `--data`/`--drop-archive` в `release.sh` не менять.
