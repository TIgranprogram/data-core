## Вывод

Нынешний short сокращает отдельные требования и изображения, но не образует самостоятельный простой сценарий. Он использует общий технический редактор, описание формируется до выбора варианта, дерево/модули выводятся без условия short. Переключатель не проходит единой цепью от книжки до выпуска. Поэтому скрыть несколько кнопок недостаточно.

## Справочники и автоматизация

Переиспользовать **passportParts**: название, падежи, применимость. «Каркас» уже найден; поиски «Рукоят» и «Педал» отдельных частей не дали. Словарь постепенно дополняется подтверждёнными именами, без массового заполнения предположениями.

Не считать **passportElements** словарём простых названий: он связан с правилами пользования/осмотра. Присвоение элемента только из-за видимой рукоятки может назначить чужие инструкции. Тексты-шаблоны развивать в существующем **passportPhrases**, с отдельной применимостью для краткого описания.

Выбранное серверное решение: добавочный блок краткого описания в passportDefaults изделия; готовая подтверждённая фраза главнее списка частей. Не перезаписывать products.description и не очищать материалы/full. При выпуске фиксировать готовый текст и версию представления. Удаление/объединение слов учитывает новые ссылки.

Распознавание изображения — источник предложения, не инженерных фактов. Сначала рабочие шаблоны и память изделия, затем интеграция распознавания; подтверждение пополняет изделие/словарь. Сейчас не установлено, что сайт уже сам анализирует рисунки моделью: существующий промпт не равен автоматической обработке.

## Дополнительные риски, которые нельзя пропустить

1. Предварительная проверка теряет контекст изделия для типовой фразы. Воспроизведено: текст уже выбран, проверка ещё требует тот же выбор.
2. Готовность использует short, прямой выпуск не получает variant, PDF допускает отдельный выбор. Нужен единый контракт нового экземпляра и legacy-поведения.
3. PUT умолчаний заменяет объект целиком. Частичная новая форма без слияния может стереть данные обычного варианта.
4. Связи позиции/заказа/фирмы должны проверяться сервером, а не только интерфейсом. В текущем создании клиентские значения имеют опасные приоритеты.
5. Сохранённый текст/фотоID не гарантируют побайтную неизменность PDF: часть ресурсов читается из текущих справочников. Новое представление должно явно фиксироваться; старые выпуски нельзя молча пересобирать в новом формате.
6. В правке габаритов пустое превращается в0, подпись «мм» не всегда согласована с прежней единицей. Нужна проверка отсутствия потери при изменении одного значения.
