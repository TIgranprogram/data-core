# СГД-1 «Сегодня» — требования и концепция (analyst + продуктовый дизайнер, 2026-10-27)

Сейчас (`pwa/sections/home.js`, 285 строк): плитки «на ходу», строка кнопок, строка цифр, 4 колонки-«дорожки» (Снабжение, Склад, Заполнить, Заказы, Деньги) по 2–4 таблицы-очереди. Итого до 10 таблиц — внимание рассеивается.

## 1. Концепция
«Утренний бриф»: одна лента «что горит сегодня» с действием в один клик, неделя — полосой, цифры — картинками; таблицы — только в разделах.
Не противоречит CANON §2 «Сегодня — не витрина, а список дел»: лента = список дел. Строку CANON обновить после приёмки.

## 2. Раскладка сверху вниз
**А. Шапка** — «Доброе утро, Имя · вторник, 27 октября» + колокольчик справа (число непрочитанных) + «Пульс дня» одной фразой: «3 срока горят, 2 поставки ждём сегодня, 1 вопрос вам».
**Б. Фокус — лента дня** (главное, 3–7 карточек, сортировка по срочности: просрочено → сегодня → завтра). Карточка: точка-тон, что, кто/кому, «осталось N дн.» / «просрочено N дн.», 1–2 кнопки. Источники:
- поставка обещана сегодня/просрочена — заявки `ordered|paid`, дата поставки ≤ сегодня → [Принять] [Перенести дату];
- отгрузка заказа ≤ 3 дн. — `salesorders.shipDate`, этап ≠ отгружен → [Открыть] [Отгружено];
- задача проектирования, срок ≤ 2 дн. — `designtasks` queue/work, срок → [Открыть];
- вопрос вам — `design-notes/open-questions` → [Ответить] (панель справа, без ухода);
- закончилось, а под заказ нужно — склад none + бронь → [Заказать];
- платёж сегодня (только денежные роли) — `finance/cashflow` день = сегодня → [Оплачено].
Остальное — свёрнуто: «Ещё 12 дел →». Пусто — «Сегодня всё спокойно» + ссылка на «Требуют заполнения».
**В. Неделя — таймлайн** 7 колонок (пн–вс, сегодня выделено золотом): точки-события (поставки, отгрузки, сроки дизайна, платежи), клик по дню — фильтр ленты на этот день.
**Г. Показатели** — 3–4 диаграммы SVG (по роли):
1. «Заявки по пути» — горизонтальная воронка: requested → in_progress → ordered → paid → received (`/supply/requests` counts); клик по отрезку — раздел с фильтром.
2. «Заказы в работе» — столбики по этапам + число просроченных по `shipDate`.
3. «Склад» — кольцо: в норме / мало / нет (`/stock/items` counts none/low).
4. «Деньги 14 дней» (только canMoney) — линия остатка из `/finance/cashflow`, дни ниже нуля — красным.
Для дизайнера/проектирования вместо 1 и 4: «Задачи» — кольцо queue/work/paused/done за неделю (`counts`).
**Д. Быстрые действия** — одна строка кнопок (как сейчас `today-actions`), быстрая заявка — по кнопке в правой панели, не постоянным блоком.
**390 px:** А → Б (карточки на всю ширину, кнопки 44 px) → В (горизонтальная прокрутка дней) → Г по одной диаграмме листанием; «на ходу» плитки остаются над лентой.
**1440 px:** две колонки: слева 2/3 — Б, под ней В; справа 1/3 — колокольчик-лента (сообщения) и Г столбиком. Карточка записи — пристыкованная правая панель (CANON §2 п.3).

## 3. Смелые идеи (vanilla JS + SVG)
1. **Пульс дня** — фраза-итог в шапке, собранная из чисел. **Этап 1.**
2. **Свайп-карточки** в ленте (телефон): вправо — сделано, влево — «завтра» (отложить на день, локально). Отмена — тост «Отменить». **Этап 1** (кнопки на ПК).
3. **Спарклайны** у каждой цифры — 14 дней (заявок создано, приходов). Этап 2 (нужна история по дням).
4. **«Тепловая неделя»** — фон колонки дня темнее, чем больше событий. **Этап 1** (часть В).
5. **Серия «чистый день»** — «5 дней без просрочек» маленьким значком; сбросилась — тихо. Этап 2.
6. **Колокольчик-лента**: вопросы менеджеру, новые комментарии к моим задачам, принятые поставки по моим заявкам; прочитано — запоминается. Этап 1 — только вопросы (`needsAnswer`); этап 2 — остальное (нужна отметка «прочитано» на сервере).
7. **Утро/вечер**: после 17:00 лента показывает «что на завтра», вверху — «сделано сегодня: N». Этап 2.

## 4. Сервер
Нужен один агрегирующий `GET /api/today?days=7` (решает архитектор, как собрать): `{ pulse, focus:[{kind, id, title, who, due, daysLeft, tone, actions}], week:[{date, events:[…]}], metrics:{requests, orders, stock, money?, design?}, bell:{questions, total} }`. Права — как у разделов (`session.sees`, `canMoney`): чего роль не видит — нет в ответе. Только чтение. Ограничение: один запрос < 500 мс на нашем одноядерном сервере, `fill-audit` в него не входит (тяжёлый — грузится отдельно, как сейчас).
Действия — существующими эндпоинтами (смена статуса заявки, заказа, ответ в `/design-tasks/:id/notes`).
Неизвестно (к архитектору): есть ли у заявки поле «обещанная дата поставки»; откуда «этап заказа отгружен»; какой срок у свободной задачи без заказа.

## 5. Критерии приёмки
1. Если открыть «Сегодня», то на экране не больше одной таблицы (лента-карточки, таймлайн, диаграммы — не таблицы).
2. Если у заявки дата поставки = сегодня или раньше и она не получена, то она есть в ленте с «сегодня» / «просрочено N дн.» и кнопкой [Принять].
3. Если до `shipDate` заказа ≤ 3 дн., то карточка показывает «осталось N дн.»; просрочен — тон `--danger`.
4. Если есть вопрос с `needsAnswer` к пользователю, то колокольчик показывает число; клик — список; [Ответить] открывает правую панель, ответ снимает вопрос и уменьшает число без перезагрузки.
5. Если роль не видит раздел (`session.sees` = false) или не денежная, то её карточек, событий и диаграмм нет, и запрос их не грузит.
6. Если нажать кнопку в карточке, то действие делается на месте, есть тост «Отменить», карточка уходит без моргания.
7. Если нажать на день в таймлайне или отрезок диаграммы, то лента/раздел фильтруется по нему.
8. Если дел нет, то пустое состояние с подсказкой, а не пустой блок.
9. Если ширина 390 px, то нет горизонтальной прокрутки страницы (кроме полосы дней), кнопки ≥ 44 px.
10. Если тёмная тема, то диаграммы берут цвета только из токенов (`--ok`, `--warn`, `--danger`, `--gold`, `--primary`), своих цветов в разделе нет.
11. Если открыть «Сегодня», то первое содержимое (шапка + лента) — до 1,5 с на проде; диаграммы догружаются без сдвига ленты.
12. На экране нет служебных кодов (статусы — словами, номера заказов — как у менеджера).
