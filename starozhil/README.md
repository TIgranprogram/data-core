# Старожил

> Старожил — как сотрудник, который 10 лет на одном складе: знает, где лежит каждый болт, и замечает, где людям неудобно.
> Решение координатора 2026-11-13 (поручение владельца: «техника полностью на тебе»). План работ — [PLAN.md](PLAN.md).

## Что это

Не отдельная программа, а **порядок вокруг data-core**: одна память о системе, одна очередь работы для всех ИИ, один пульт для человека.

Три дела Старожила:
1. **Помнит устройство.** Карточки знаний: модуль, правило, процесс, связь. Любой ИИ находит ответ за 1–2 чтения, а не перечитывает код.
2. **Наводит порядок.** Карточку пишут только на разобранный модуль: инвентаризация → полочка → номер. Хлам по пути — в чистку.
3. **Видит людей.** Где сотрудник теряет время (туда-обратно, пустой поиск, длинный путь) → предложение по экрану раз в неделю.

## Кто где работает

| Кто | Что делает | Что ему нельзя |
|--|--|--|
| Программы (`dc`, сборщики) | точные факты: код, схема, маршруты, git, журналы | — |
| Локальный ИИ (дом: RTX 5070 Ti 16 ГБ; работа: своя видеокарта) | ночная смена: обход сайта, снимки, черновики карточек, разбор журналов и поведения | публиковать вывод как факт; писать в прод |
| Claude по подписке | решения, код, приёмка черновиков локального ИИ | тратить подписку на рутину, которую тянет локальный |
| Владелец | бизнес-решения и кнопки «Нужно от вас» в пульте | читать код и отчёты |

## Почему так, а не «модный стек»

**Векторная база (pgvector, Qdrant).** Нужна для поиска по смыслу в больших массивах текста. Для кода лидеры отказались от неё: Claude Code и Cline ищут агентно (поиск по словам + структура проекта) — это точнее и не устаревает. У нас память — сотни карточек, а не миллионы документов; поиск по словам и ссылки находят нужное. Карточки пишутся так, что векторный индекс добавляется за день (локальная модель эмбеддингов в LM Studio + файл `sqlite-vec`). **Включаем по измерению:** если ИИ не находит нужную карточку чаще 1 раза из 10.

**Obsidian.** Это программа просмотра папки с Markdown — граф ссылок, удобно человеку. ИИ она не помогает и не мешает. Карточки пишем в его формате (заголовок-свойства, ссылки `[[…]]`) — по желанию владелец открывает папку в Obsidian и видит карту. Отдельной привязки нет.

**Отдельный продукт на Python + PostgreSQL + Celery + Redis** (`db_ai/план развития.txt`). Вторая система на одного владельца: свои копии, обновления, сбои. У нас уже есть база, API, очередь «Разбор», пульт, MCP, сторож. Независимый аудит (`db_ai/audit-report/07`) пришёл к тому же.

## Проверено пробой 2026-11-13 (Gemma 4 12B, дом)

| Как дали наряд | Итог |
|--|--|
| «Найди сам» (сверка задач, карточка модуля) | выдуманные маршруты и доказательства; пользы нет |
| Программа собрала факты → ИИ описывает словами | маршруты точные, ссылки «файл:строка» 6 из 6 верны, карточка принята за 2 мин работы Claude |
| ИИ «судит» таблицу фактов (сверка TASKS) | почти везде повторил факты; быстрее, если Claude судит таблицу сам |

**Отсюда главный закон Старожила:** факты собирает программа (`tools/starozhil/*-facts.mjs`, `prepare:` в наряде), локальный ИИ превращает их в понятный текст и находит связи, Claude принимает. Ссылки «файл:строка» в итоге проверяет исполнитель.

## Правила

- Карточка без ссылки на источник (файл, коллекция, маршрут) не принимается. У карточки — отпечаток источника; источник изменился → карточка «устарела» (`dc check`).
- Бизнес-данные в карточки не копируются — только устройство, правила, связи.
- Одна очередь работ ИИ, один исполнитель на ПК, одна модель в видеопамяти. Урок 13.11: сторож без единой очереди запустил 9 копий.
- Каждая часть имеет одну цифру успеха. Цифра не растёт месяц — часть убираем.
- Человек управляет только пультом. Новое действие для человека — пункт «Нужно от вас».
