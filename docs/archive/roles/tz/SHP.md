# ТЗ ШП — ширина боковых панелей мышкой, запоминается у пользователя

> Совещание 2026-10-24: дизайнер и архитектор. Координатор свёл их отчёты. Порядок: ШП-1 (backend) → ШП-2 (frontend) → ШП-3 (qa). ШП-4 (админка) — по желанию.

**Зачем (словами пользователя):** «Боковое меню нашего приложения: можно мышкой менять размер, и размер сохраняется у пользователя. Во всём приложении, где оно открывается».

**Роли:** дизайнер ☑ (совещание) · архитектор ☑ (совещание) · backend ☐ · frontend ☐ · qa ☐

## Решения совещания

1. **Изменяемые панели «Рабочего места».** Один общий модуль `pwa/ui/resizer.js` на все три, не три разных.

   | Панель | Переменная | Стандарт | Пределы |
   |--|--|--|--|
   | Левое меню `.sidebar` | `--sidebar-w` | 248 | 200–360 |
   | Правая панель ввода `.drawer` | `--detail-w` | `clamp(480px,40vw,760px)` | 420–min(900, 60vw) |
   | Панель фильтров `.ff-pop` | `--filter-w` (новая) | 340 | 280–520 |

   - Пока ширину не выбрали, действует стандарт.
   - Основной области всегда остаётся ≥ 480 px. Окно сузили — значение ограничивается по окну, но сохранённое **не затирается** и вернётся, когда окно расширят.
2. **Где хранить — в обоих местах:**
   - `localStorage` (ключ `dc-ui-<userId>`) — размер применяется сразу и работает без сети;
   - сервер, `users.uiPrefs` — размер переходит между ПК (дом ↔ работа).
   - После `/auth/me` значения с сервера перекрывают локальные.
   - Запись на сервер — один `PATCH` через 1 с после отпускания мыши, только если значение изменилось. Ошибку сети и 429 глушим молча.
3. **Ручка:**
   - Вид: вертикальная линия 1 px `--border`; зона нажатия 8 px. При наведении и перетаскивании — 2 px `--primary` (на тёмном меню — `--gold`). Новых токенов нет.
   - Мышь: курсор `col-resize`; при перетаскивании `body.is-resizing` (без выделения текста и `transition`).
   - Двойной щелчок — сброс к стандарту.
   - Клавиатура: фокус (`tabindex=0`, видимый `:focus-visible`), ←/→ ±16 px, Shift ±64, Home/End — min/max, Enter — стандарт.
   - Доступность: `role="separator" aria-orientation="vertical" aria-label aria-valuenow/min/max`, подсказка «Потяните, чтобы изменить ширину. Двойной щелчок — по умолчанию».
   - Реализация: pointer-события с `setPointerCapture`. Во время движения меняется только CSS-переменная (в `requestAnimationFrame`). Запись в хранилище — **только при отпускании**.
4. **Узкие экраны:**
   - ≤ 720 px — ручек нет, панели во весь экран, сохранённое не применяется.
   - 721–1100 px — меню в режиме иконок, у него ручки нет. Ручки правой панели и фильтров есть.
   - Правая панель в режиме «поверх» (< 1400 px) — ручка есть, ширина ≤ 100vw − 24 px.
5. **Права:**
   - Каждый меняет только свои настройки: id берётся из входа.
   - Ключ `kppd_` → 403 «Настройки интерфейса меняются только из входа в приложение».
6. **Не в этой волне:** кнопка «свернуть меню до иконок»; перенос темы и свёрнутых блоков формы в `uiPrefs`. Позже тем же маршрутом, если попросит пользователь.

## ШП-1 — сервер (backend)

**Что сделать**
1. `modules/user/user.schema.ts`: необязательное поле `uiPrefs` (Object, без default).
   - `users` общая с CRM, но новое поле CRM не читает.
   - Индексов нет, `ensure-indexes` не нужен.
2. `modules/auth/dto/ui-prefs.dto.ts`: `sidebarW` 200–360, `detailW` 360–1100, `filterW` 280–700. Все `@IsOptional @IsInt @Min @Max`. Лишние ключи → 400 (whitelist).
3. `PATCH /api/auth/me/prefs`:
   - `@Roles('admin','manager','user')` (и свои роли по `baseRole`);
   - если `req.user.keyScope` есть → 403;
   - запись `$set` по отдельным ключам `uiPrefs.<ключ>`, не целым объектом — чтобы разные ПК не затирали друг другу ключи;
   - ответ — `{ uiPrefs }`.
4. `toAuthUser` (`auth.service.ts`): добавить `uiPrefs: user.uiPrefs ?? {}`. Тип `AuthUserPayload`, ответы `/auth/login` и `/auth/me`.
5. Юнит (`auth.service.spec.ts` или новый spec): границы, лишний ключ — 400, `kppd_` — 403, частичная запись не стирает другие ключи. Случай в e2e auth, если файл есть.
6. Перегенерировать `docs/openapi.json`, обновить `docs/MAP.md`.

**Файлы** — менять: `src/modules/user/user.schema.ts`, `src/modules/auth/{auth.controller,auth.service}.ts`, `src/modules/auth/dto/*`, spec, `docs/MAP.md`, `docs/openapi.json`.

**Критерии приёмки**
- [ ] `PATCH {detailW: 700}` → 200; `/auth/me` отдаёт `uiPrefs.detailW = 700`.
- [ ] `PATCH {sidebarW: 300}` после этого `detailW` не стёр.
- [ ] `{detailW: 5000}`, `{foo: 1}`, строка вместо числа → 400.
- [ ] Через `kppd_`-ключ → 403.
- [ ] Старый клиент без `uiPrefs` работает как раньше.
- [ ] `tsc` 0, `npx jest src/modules/auth src/modules/user` зелёные.

## ШП-2 — приложение (frontend)

> Сначала skill `datacore-design`.

**Что сделать**
1. `pwa/ui/resizer.js`: `makeResizable(handleHost, { cssVar, prefKey, min, max, edge: 'left'|'right', label })` — всё по решениям 3–4.
2. `pwa/core/api.js` (или `core/prefs.js`):
   - чтение и запись `dc-ui-<userId>` (try/catch, как у темы);
   - `applyPrefs(uiPrefs)` → CSS-переменные на `document.documentElement` с ограничением по окну;
   - пересчёт на `resize` окна;
   - debounce 1 с → `PATCH /auth/me/prefs`.
3. `pwa/main.js`:
   - при старте — локальные значения до первой отрисовки;
   - после `/auth/me` — серверные (около стр. 330);
   - подключить ручки к меню (правый край), `.drawer` (левый край) и `.ff-pop` (правый край).
4. `pwa/ui/base.css`:
   - `.ff-pop { width: var(--filter-w, 340px) }`;
   - режим иконок: `72px` на стр. 53 и `left: 72px` на стр. 801 → переменная `--sidebar-icons-w`. Иначе сохранённые 300 px сломают узкое окно;
   - стиль `.resizer`;
   - `--detail-w` пользователя перекрывает `clamp`.
5. `sw.js` / `modulepreload` — новый модуль. Проверка: `npx jest src/pwa-guards`.
6. DESIGN:
   - §2.2 — исправить `--detail-w`: в доке `clamp(440,33vw,640)`, в коде `clamp(480,40vw,760)`. Добавить `--filter-w` и пределы;
   - §4 — компонент «Ручка ширины» `.resizer`;
   - §5 — поведение;
   - §6 — проверка на 390, 1024, 1400 и 1920 с растянутой панелью;
   - §8 — запись 2026-10-24.

**Критерии приёмки**
- [ ] Каждую из трёх панелей можно тянуть мышью, касанием и клавиатурой; двойной щелчок сбрасывает.
- [ ] Перезагрузка — ширина та же. Вход с другого браузера тем же пользователем — та же (с сервера).
- [ ] Другой пользователь в том же браузере — своя ширина.
- [ ] За одно перетаскивание уходит не больше одного `PATCH`.
- [ ] Без сети ширина сохраняется локально, ошибок на экране нет.
- [ ] На 1400 и 1920 при максимальной панели нет горизонтальной прокрутки страницы, основная часть ≥ 480 px.
- [ ] Окно сузили и расширили — ширина вернулась.
- [ ] 390 px — ручек нет. 721–1100 — у меню ручки нет.
- [ ] Обе темы.
- [ ] `node --input-type=module --check < файл` для изменённых js.
