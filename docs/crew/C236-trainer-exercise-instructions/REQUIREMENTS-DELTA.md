# C236 — дельта требований: модельная инструкция без нового справочника

23.11.2026. **Бизнес-PASS для архитектурного плана; кода и записей на прод нет.** Основание: новое требование владельца, TARGET-PLAN и последнее дополнение SOURCE-SEARCH-1069. Класс реализации **L**: серверный контракт/сборка + компьютерный интерфейс + регрессия PDF/снимков. Упрощение до M допустимо только при фактическом отсутствии межслойной правки; текущий предполагаемый объём — L. Новая сущность/библиотека не требуется.

## Доказанный пробел

У1067/1068/1069 нет выбранного use-root, пригодного для собственного модельного текста. Два найденных корня имеют иной смысл: суставная разминка и совмещённые2в1. Назначать их, чужие facets или purpose-root ради хранения инструкции нельзя. Пустой leaf не работает; единственный непустой leaf автоматически выбирается, даже isDefault=false. Два фиктивных варианта/нейтральный общий текст ради обхода не являются решением.

Следовательно, прежний план «просто записать textOverrides подходящего use-root» для этих пилотов **неисполним без подмены смысла**. Альтернативный действующий механизм, честно решающий этот пробел, по имеющимся доказательствам не установлен. Предпочтение — необязательный блок инструкции у существующего шаблона изделия.

## Путь пользователя

1. «Изделия» → точное изделие/SKU → «Шаблон паспорта» → существующий лист/раздел «Правила пользования».
2. В том же редакторе справа открыть компактный блок **«Инструкция упражнения»**. Три подписанных поля: **«Исходное положение»**, **«Движения и завершение»**, **«Задействованные мышцы»**. Значения текущего изделия уже подставлены; повторно вид/facets выбирать не нужно.
3. Заполнить проверенный текст или отредактировать ранее сохранённый. Явно сохранить в шаблон этого изделия; увидеть, что будущие образцы используют именно этот текст. Не создавать номер, экземпляр или редакцию выданного паспорта кнопкой сохранения шаблона.
4. Посмотреть short/full образцы. Блок упражнения следует в разделе пользования рядом с общими правилами, но не заменяет их. Назначение purpose остаётся кратким назначением, а не местом для длинных шагов.
5. «Удалить инструкцию» — отдельное явное действие только для этого модельного блока, с обычной защитой несохранённых изменений. Очистка не удаляет общие safety, rules, другие тексты или выбранные roots.

Это один существующий путь редактирования шаблона, а не новый раздел меню. Реализация не должна заставлять пользователя администрировать дерево фраз для каждого SKU.

## Что хранить и как применять

- В существующем модельном шаблоне/его defaults добавить **один необязательный объект** из трёх текстовых частей; рабочее имя `exerciseInstructions` уточняет архитектор. Новый справочник упражнений, категория, коллекция, товар или фиктивный root не создаются.
- Содержимое — обычный текст с абзацами, без HTML; три части имеют устойчивые смысловые ключи и сохраняют порядок. Ограничение размера явное, без тихого обрезания: ориентир — прежние4000символов на итоговый блок, точные границы/сообщение фиксирует архитектор до кода.
- Отсутствующий блок полностью совместим со старым изделием: общая готовность паспорта не начинает требовать новую инструкцию. Наличие других категорий/старых текстов не создаёт блок автоматически. Если пользователь сохраняет включённую инструкцию, все три части должны быть непустыми; неполный текст не выводить как готовую модельную инструкцию. UI объясняет, какого поля не хватает, не подставляет общие мышцы/движения.
- Начальное добавление не меняет `textChoices`, `textOverrides`, purpose, simpleDescription, elements, materials, installation, joints и числа defaults. Новый блок добавляется адресно; весь defaults не заменяется. Для1068 foundationDepth=0 не теряется как ложное значение.
- Собственный сохранённый блок — источник именно этого изделия. Переподбор признаков, общий словарь, повторная композиция и обновление чужого шаблона не перезаписывают его. Новая версия подготовленного текста предлагается для явной замены, а не молча применяется поверх ручной правки.
- Другие собственные тексты use сохраняются как отдельные источники. Новый блок не считается разрешением заменить sections.use целиком. Если обнаружено реальное смысловое дублирование с другим override, показать источники/предложить явный выбор, не удалять автоматически. Для текущих пилотов своих use-overrides нет.
- Нет необходимости вводить новый реестр источников вБД ради трёх пилотов. Версия текста, конструктивный источник и одобрение фиксируются вC236; публичный текст не содержит служебных кандидатов/условий. Автоматическое угадывание мышц/механики не добавляется.
- Сборка выдаёт три части как **один самостоятельный модельный блок** с заголовками, связанным с изделием. В short/full он попадает в use без склеивания с usageRules разных элементов. Типовые правила и ограничения остаются отдельными неизменёнными пунктами. Архитектор определяет аддитивный JSON-контракт/снимок и совместимость прежних клиентов.

## Конкурентность и выданные документы

- Сохранение использует действующий адресный expected/changes-подход шаблона, расширенный новым полем. CAS сравнивает фактический baseline этого блока; параллельная ручная правка →409 и перечитывание без потери введённого текста. Старые клиенты и операции других полей остаются совместимыми.
- Сохранение/удаление инструкции шаблона меняет только будущее содержимое шаблона/образца. Чтение/печать старого экземпляра не пересобирает его из новой карточки.
- Три уже выданных паспорта1067: те же номера, снимки текста, источникиPDF и история. Обновление действующего экземпляра — только отдельная согласованная редакция поПС-07; неизменный повтор не создаёт новую. Legacy/аннулированные/закрытые/готовые вложенныеPDF не мигрируются поПС-10.

## Пилоты и оставшийся факт1069

1067/1068: кандидаты есть; сохранение после принятия применимости/конечного текста, а не потому, что появилась новая форма. Выбор карточек по артикулам принят владельцем, папки повторно не спрашивать.

1069: найдена **собственная двойная IAM-сборка** и её встроенная миниатюра: два места, подвесные платформы и хваты. Механический разбор выполняем самостоятельно по источнику; от владельца ожидается только подтверждение **связи показанной сборки сSKU1069**, уже запрошенное. Не просить описать упражнение вместо конструктивного анализа. Пока связь не подтверждена — не объявлять кандидат утверждённой инструкцией1069 и не выполнять запись. Старый single-walker7_31 не назначается этому артикулу.

## Критерии приёмки дельты

1. Неподготовленный пилот без use-root получает модельную инструкцию через три поля без создания/изменения passportPhrases, facets и других изделий. Сохранение/повторное открытие сохраняет части и абзацы; чистое удаление убирает только модельный блок.
2. Short/full JSON и **все страницы** образцов содержат один блок с тремя заголовками; нет служебных placeholder/HTML/тихого truncate и смешения упражнений. Незавершённые три поля дают понятную ошибку, без угадывания недостающего.
3. Baseline1067: прежние11пунктов sections.use и4rules остаются по фактическим текстам/ключам;1068/1069 — прежние15пунктов. Не требовать механически15для всех. Не копировать safety внутрь пользовательского блока.
4. Контрольный четвёртый TRN и другая категория без нового блока не получают упражнение пилота; прежняя readiness без инструкции не меняется. Purpose, установка/материалы/числа/overrides/choices до/после равны, включая0.
5. Ручная замена или удаление выполняется явно; смена facets/общих текстов не затирает блок. Stale CAS→409 без перезаписи актуального текста и без полной замены defaults. Права на редактор соответствуют действующему шаблону, не расширяются.
6. Создание образца не расходует номер/не создаёт экземпляр. Снимки/номера/файлы/история выданных1067 не меняются. Отдельный путь редакции и повторная печать старого источника сохраняют ПС-05/07/10.
7. Заполненная desktop-проверка ввода/редактирования/удаления и short/full; backend/QA проверяют контракт, сборку, CAS и регрессию выданных. После принятия архитектуры — адресный scope исполнителей, без инициативного изменения остальных паспортных правил.

**Дальше архитектору:** расположение необязательного поля в существующем шаблоне, минимальный add-on expected/changes, JSON/снимок/PDF, точная граница замены ручного блока и совместимость. Публичные записи/выпуск не начинались; никакой новый справочник не объявлен обязательным.
