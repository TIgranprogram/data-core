Вход: `BRIEF.md` и выгрузка прода `tools/logs/c028/` (2026-11-06). Поправка пользователя 2026-11-07: делаем **новый инструмент**. Старую продукцию массово не чиним: изделие дополняется по ходу, когда для него делают паспорт.

## 1. Продукция в цифрах (только то, что нужно для признаков)
- **483 изделия**. Работают 3 раздела из 11: Спортивное 294, Благоустройство территории 159, Детские площадки 30. Остальные 8 разделов пустые. Изделия есть в 21 группе из 29.
- **Категория паспорта сейчас** (итоговая у изделия): WRK 174, BLG 168, TRN 98, DIO 43, **DSP 0**. У 470 изделий она задана в самом изделии (перенесена из паспортов). У 13 её угадал сервер.
- **У групп категория не задана нигде (0 из 29)**, хотя поле есть (`categories.passportCategory`). Поэтому сервер угадывает категорию по корню слова. Слово «оборудование» уводит в DIO: 13 изделий (баскетбольные стойки, мишени, вазоны) получили «Детское игровое» (`common/passport/form-values.ts:68–74`). Это ошибка кода, а не данных.
- **Группа ≠ категория.** «Спорт оборудование»: WRK 41, DIO 17, TRN 8. «Воркаут»: WRK 126, BLG 10. Детские качели, карусели, игровые комплексы и геопластика — 21 изделие в BLG. Вывод: категорию задаёт группа, изделие — только исключение.
- **Серий почти нет.** Поле `series` заполнено у 4 изделий. В названии «STREET IRON» — у 38, CHOICE SHADOW — у 2, TORUDA — у 2.
- **Заполненность изделий:** артикул 100 %, группа 100 %, фото 64 %, описание 49 %, размеры 48 %, вес 47 %, назначение 1 %, монтаж 0 %. Паспорта есть у 240 изделий (50 %).
- **Чего не хватает в 342 паспортах для выпуска** (`missing`): чертёж 339, способ установки 335, срок службы 322, пользователей одновременно 237, схема фундамента 237, элементы 226, рост и вес (TRN) 116. Способ установки из справочника задан у 7 паспортов из 342.
- **Установка по тексту паспорта:** TRN — «закладные детали» в 101 из 116, WRK — «бетонирование» в 78 из 119, у BLG способы разные. Отсюда установка по умолчанию у категории (`defaultInstallType` в seed).
- Старое не чиним в этой задаче: ИЗ-20, 27 одинаковых названий, артикулы-двойники «7_31»/«1007».

Правила шагов:
- Значение видно, только если в текущем срезе есть изделия с ним; рядом стоит число.
- Шаг пропускается сам, если в срезе одно значение или ни одного.
- Изделие без значения признака не прячется: оно попадает в строку «Признак не указан (N)».
- Признак «не шаг» (материал) в воронке не спрашивается. Его спрашивают только в «Чего не хватает», если от него зависит текст.

## 3. Устройство данных (решение)
**Одна иерархия:** Раздел (каталог, как есть) → **Группа** (несёт категорию паспорта) → **Признаки категории** → Изделие. Третьей классификации нет: «Типы изделий» (`passportTypes`, 0 записей) убираем, их поля переходят в значение признака.

| Где | Что | Поля |
|--|--|--|
| `dict_values`, `dict:'productFacets'` (новый, группа «Паспорта») | Признак | `name`, `code` (не меняется), `category` (DIO/DSP/TRN/WRK/BLG), `order`, `step` (шаг воронки), `multi`, `hint` |
| `dict_values`, `dict:'productFacetValues'` (новый) | Значение | `name`, `code`, `parentId` → признак, `order`, `words` (слова для подсказки), `purposePhraseId` → `passportPhrases`; необязательные `installTypeId` → `passportInstall`, `elementIds[]` → `passportElements`, `composition`, `coatings` (бывшие поля `passportTypes`) |
| `products.facetValueIds: ObjectId[]` | Признаки изделия. **Только data-core**, CRM не читает; индекс multikey | ссылки на `productFacetValues` |
| `categories.passportCategory` | Категория группы. Поле есть, заполнить у 29 групп (ПФ-1) | — |
| `products.passportDefaults` | Ответы воронки: категория-исключение, установка, параметры категории, элементы | без изменений |
| `passportPhrases` + новое `facetValueIds[]` | Абзац текста для изделий с этим значением признака (например, «Грузовой блок» для TRN с изменяемой нагрузкой) | `section` = ключ раздела шаблона |

- Признаки связаны по `id`, не по названию. Справочник переименуют — ссылки не порвутся (урок DICT).
- Признак привязан к категории полем `category`, группа — своим полем. Изделие видит признаки своей итоговой категории.
- Текст паспорта собирается так:
  - шаблон категории (`passporttemplates`, как сейчас);
  - абзацы фраз, у которых `facetValueIds` совпали с признаками изделия;
  - назначение — из `purposePhraseId`;
  - монтаж — по паре (категория, `installTypeId`); эти фразы уже разложены по категориям и способам.
- `passportTypes` скрыть из меню; экран `product-types.js` уходит.
- Угадывание по корню слова (`form-values.ts:66–74`) убрать. Если у группы нет категории, показать «Категория не указана» и шаг «Выберите категорию».
- Mongo 4.4: только `$in`/`$all` по массиву.

## 4. Воронка создания паспорта
Всё — в правой панели (`entityPanel`). Шаги идут сверху вниз: `filter` mode `funnel` (`stepFunnel`, `always`, `icon`). Пройденный шаг сворачивается в строку «Категория: Уличный тренажёр ✎».

**Вход А — «Новый паспорт»** (из списка паспортов):
1. **Категория** — 5 значений с числом изделий, `pick` single. Не пропускается никогда.
2. **Группа** — группы с изделиями этой категории, `pick` single, у значения миниатюра (`icon`). Пропускается, если группа одна (TRN).
3. **Признаки** — шаги категории с `step:true` по `order`, `pick` single или combo. Пропуск — по правилам §2.
4. **Изделие** — `table` (`maxHeight`) из строк `row`: фото, артикул, название, «паспортов: N».
   - Поиск по названию и артикулу идёт по всем изделиям.
   - Внизу: «Нет нужного — + Новое изделие».
   - Пусто — `empty`: «Изделий с такими признаками нет. Снимите признак или создайте изделие».

**Вход Б — «Создать паспорт»** (из карточки изделия): шаги 1–4 пропускаются. Категория берётся из изделия (своя, иначе из группы). Воронка начинается с шага 5.

5. **Чего не хватает** — только пустое, блоками `section`:
   - признаки категории без значения, с подсказкой по словам: «Похоже: Силовой — верно?»;
   - параметры категории (`requiredFields`) с умолчаниями справочника: срок службы 10/5 лет, рост 1400, вес 120;
   - способ установки — с умолчанием категории;
   - элементы;
   - рисунки (`requiredImages`).
   Каждый ответ пишется в изделие: `facetValueIds`, `passportDefaults`, картинки изделия. Всё заполнено — шаг пропускается.
6. **Тексты** — разделы шаблона категории (`section`). В разделе — `pick` только текстов этой категории и признаков изделия. Текст подставлен сам, менять не обязательно.
7. **Выпуск**:
   - номер и дата ставятся сами; поставщик по умолчанию — наш;
   - блок «Заполнить после печати» (покупатель, № заказа, адрес, монтаж, дата продажи) выпуск не держит;
   - «Выпустить PDF» доступна, когда список «не хватает» пуст; иначе рядом — что осталось, со ссылкой на шаг.

**Подсказка следующего шага:** над шагами одна строка, например «Дальше: укажите способ установки» — первый незаполненный пункт.
**Правило «не спрашивать дважды»:** ответы шагов 1–5 сохраняются в изделие. Второй паспорт того же изделия начинается сразу с шагов 6–7.

**Новое изделие по ходу** (правая панель поверх; после «Создать» — назад в воронку с выбранным изделием):
- обязательно только **название**;
- группа и категория подставлены из шагов 1–2, признаки — из шага 3;
- **артикул** ставится сам: `groupNo` + следующий номер;
- просим сразу, но не обязательно: фото (без фото PDF не выйдет), размеры, вес;
- перед «Создать» показываем `similarBox` «Похожее уже есть», чтобы не плодить дубли.

**Обязательно для PDF** — как сейчас (`passport-rules.ts:216–235`): название, дата, поставщик, размеры, вес, материалы, фото, элементы (кроме BLG), способ установки, поля категории, рисунки категории.
**После печати** — `INSTANCE_FIELD_KEYS` (`passport-rules.ts:255`) и «Заполняется после печати» (PRODUCT §5а).

## 5. Тексты: чего не хватает
Сейчас «Для всех» — 12 разделов. Своего текста у категорий: DIO 3,0 тыс. знаков, TRN 2,8, WRK 1,8, DSP 1,5, **BLG 0,9** (4 абзаца на 168 изделий). Фраз «Назначение» — 23, монтажа — 15 (3 категории × 5 способов).

| Кат. | Не хватает (темы) |
|--|--|
| TRN | назначение «Разминка суставов»; ТО грузового блока (фиксаторы, грузы не снимать) для изменяемой нагрузки; правила для совмещённых (по одному человеку на модуль) |
| WRK | назначение: шведская стенка; кольца, канат, скалодром; ГТО; зрительские места. Правила для **игровых** снарядов (не висеть на кольце и воротах, натяжение сетки, крепление щита) — сейчас текст WRK только про турники. ГТО: разметка и линейки, проверка точности. МГН: занятия с сопровождающим |
| BLG | по группам: трибуны (нагрузка, не стоять на сиденьях, перила); навесы и перголы (снег с кровли); ограждения (крепёж секций); городские качели (подвесы, осмотр); урны; велопарковки; геопластика (покрытие). Пропитка дерева уже есть |
| DIO | по видам — ГОСТ 34614.2 (качели), 34614.3 (горки), 34614.5-2024 (карусели), 34614.6 (качалки): подвесы и зазоры, зона выката, вращение, пружины; песочница — замена песка |
| DSP | ограничения (возраст 7+), правила, ТО — свой текст почти пуст |

Нормы:
- ГОСТ 34614.5-2024 «Карусели» в справочнике стоит как действующий; источник — [gostinfo](https://cn.gostinfo.ru/catalog/Details/?id=7582807).
- Номера частей 34614.2/.3/.6 сверены по [Армстандарту](https://www.armstandard.am/en/list/439).
- Редакцию 34614.2-2024 в России **не проверил**. В справочник вносить только после сверки с ФГИС Росстандарта.
