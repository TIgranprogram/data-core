Полный перечень задач
1. Правое меню заказа — только релевантное
Скрывать блоки, которые не требуют внимания/действия:
бронь, если брони нет / 0;
«списаний под заказ нет»;
пустая история изменений.
Принцип: однотипные оповещения показывать только если ситуация по этому заказу реальна и требует решения.
2. Навигация по заказу и позициям
Стрелки назад/вперёд только в левом меню — неудобно.
Задача дизайнер-агенту: пересмотреть юзабилити просмотра вложенных данных (открытие позиции, возврат, панели).
Кандидаты (дизайнер выбирает лучший):
заметные стрелки в правом меню сверху слева;
клик по позиции → снизу выезжает панель позиции; после действий — явный переход в меню заказа.
Не ломать текущую логику данных, править UX.
3. Меню и статусы: «Заказы» → логика производства
Пункт левого меню «Заказы» переименовать в «Производство».
Внутри: Заказы, затем Проектирование (потом, когда появятся, — производство/отгрузка как разделы).
Заказы в проектировании визуально отмечать в общем списке (например, толстая цветная полоса слева в строке).
Главное по статусам:
сделать явное, интуитивное место смены статуса заказа;
статусы: Проектирование → Производство → Готово к отгрузке → Отгружена;
в списке заказов всегда видны все; фильтры/счётчики должны совпадать с реальными статусами;
разобрать, откуда берётся текущий «в работе», привести к новой модели;
кнопка «перенести в производство» не должна быть единственным скрытым способом смены статуса.
Дефолтный фильтр в заказах: в работе / актуальные, затем все, затем выполненные/отгруженные.
4. Отмена, корзина, история, защита от случайных действий
Отмена не должна срабатывать мгновенно без подтверждения.
Диалог: что произойдёт, куда денется заказ, как вернуть.
Отменённое/удалённое → корзина.
Из истории действий можно попасть в корзину и восстановить.
Деструктивные действия (удалить / изменить / отменить) — подтверждение; для не-админов — подтверждение паролем.
Аудит: случайные удаления/изменения должны быть откатываемы. Сейчас корзина по заказам пустая / не работает — исправить (заказы тоже должны туда попадать, не только заявки/склад).
5. Левое меню
В малых меню фильтров подкрасить названия категорий гармоничным к зелёному цветом (без точек, чтобы отличалось от главного меню).
Допилить левое меню до конца.
6. Фильтры продукции (стандарты / резьба / длина / тип)
Логику каскадных фильтров не ломать (она хорошая).
Добавить точечный сброс параметра (резьба / тип / длина), не только «сбросить всё».
При выборе длины сразу показывать только подходящее.
Хлебные крошки выбранных параметров + крестик удаления.
Длинные списки (длина в мм, резьба и т.п.) — 2–3 колонки с явным визуальным разделением, чтобы убрать длинный скролл.
То же юзабилити — на фильтры в разделе Продукция.
7. Меню продукции слева
Разделы с выпадающими списками: категория → подкатегории.
По умолчанию свёрнуты (сейчас слишком длинный список).
8. Три названия: продукты и покупные позиции
Продукты (то, что производим):

короткое название;
длинное название;
название в заказе (как называет заказчик).
Покупные изделия (заявки / склад — детали/модули, не продукты):

короткое название;
длинное название;
название как в счёте поставщика (у разных поставщиков одно и то же называется по-разному).
Задачи агентам:

Сначала аудит всех мест, где сейчас одно поле «название».
Существующее название оформить как наши (короткое/основное — принять решение по текущим данным).
Добавить пустые дополнительные поля.
В нужных экранах показывать нужное поле:
каталог продукции → наши названия;
заказ / состав заказа / будущее КП → название в заказе (+ возможность сопоставить с нашей продукцией);
счета → название как в счёте;
заявки и склад → наши короткие/удобные названия.
В заказе при ручном вводе: позиция может называться «как у клиента», справа — выбор нашей продукции (категория → изделие).
Создание заказа: после шапки заказа сразу (или сразу после создания) должен быть перечень позиций. Сейчас на первой странице только оформление шапки — это дыра.
Кнопка/блок «заказы с этим изделием» в продукции — сейчас не находится, проверить/сделать (с учётом, что в заказе имя может быть другим, связь — через сопоставление с нашей продукцией).
Не подтягивать чужие поля в чужие экраны — после аудита зафиксировать карту «экран → какое поле названия».

9. Склад
«Скачать Excel» и массовые выгрузки — только администратор.
Быстрые фильтры сверху: ниже мин. остатка / ноль, требуют внимания, ожидают поступления.
Цвет «заказано N»: не красный как «совсем нет». Жёлтый (или другой отличимый) + текст вроде «нет (заказано 55)».
Приёмка на склад из раздела склада (как кнопка «принять» в оплаченных заявках) для ожидающих позиций. Склад не превращать в заявки — только доп. информация + действие приёмки.
Проверить и починить ошибку «принять на склад» (уходила на сервер).
10. Документация и паспорта
Паспорт создаётся у продукта (создали продукт → можно создать паспорт, лежит с продуктом).
В заказ цепляем наши продукты → паспорта уезжают вместе с ними → появляются в документации.
В документации не дублировать весь каталог продукции.
Показывать паспорта по заказам: заказ раскрывается → список паспортов, которые нужно доделать или распечатать.
У каждого — статус: готов / не готов / надо доработать.
Архив паспортов — архив: не менять, максимум печать.
Документация сейчас — точка сбора задач менеджера (уведомления — позже).
Накидать минимальный набор категорий документации для выдачи изделия (паспорта по заказам; далее акты / отгрузка / закрытие — по необходимости, не раздувать сразу).
11. Дефолтные фильтры везде
Где есть «Все / В работе / Выполнены» — по умолчанию самая актуальная для работы позиция.
Иерархия по востребованности. Применить ко всем таким фильтрам/крошкам.
12. Общее
Аудит прав на деструктивные и массовые действия.
Аудит названий (3 поля × 2 типа сущностей × все экраны).
Аудит статусов заказов и счётчиков.
Юзабилити фильтров и вложенной навигации — до комфортного уровня, логику не ломать.

ЗАДАЧИ

A. Правое меню заказа
Показывать блоки только если требуют внимания/действия. Нет брони — не показывать бронь. Нет списаний — не показывать текст «списаний нет». Пустая история — не показывать.

B. UX навигации заказа (дизайнер-агент выбирает лучший вариант и реализует)
Стрелки только в левом меню неудобны. Варианты: стрелки в правом меню сверху слева; либо клик по позиции → нижняя панель позиции с явным возвратом/переходом в меню заказа. Пересмотреть открытие/закрытие вложенных данных.

C. Отмена / корзина / история / пароль
Отмена заказа не мгновенная: подтверждение, что произойдёт, куда денется, как вернуть.
Удалённое/отменённое → корзина. Из истории действий — вход в корзину и восстановление.
Заказы тоже должны попадать в корзину (сейчас видны заявки/склад, заказы пусто, restore нет).
Удалить/изменить/отменить: подтверждение; для не-админов — пароль.

D. Три поля названия
Продукт (производим): короткое, длинное, название в заказе (как у заказчика).
Покупное (заявки/склад): короткое, длинное, название как в счёте поставщика.
Текущее существующее название оформить как наши (короткое/основное — решить по факту данных). Доп. поля добавить пустыми.
Карта отображения:
- каталог → наши имена;
- заказ / состав / будущее КП → название в заказе + сопоставление с нашей продукцией (категория → изделие справа);
- счета → имя как в счёте;
- заявки и склад → наши короткие/рабочие имена.
Создание заказа: после шапки сразу перечень позиций (сейчас только шапка — дыра).
В продукции найти/сделать «заказы с этим изделием» через связь сопоставления, не через совпадение строк названия.

E. Фильтры и меню продукции
Каскады не ломать. Добавить точечный сброс параметра (не только сброс всего). Крошки + крестик. Длинные списки (длина мм, резьба) в 2–3 колонки. При выборе длины сразу сужать список. Слева в продукции: выпадающие категории, по умолчанию свёрнуты. В малых фильтрах левого меню подкрасить заголовки категорий гармоничным к зелёному цветом, без точек.

F. Склад
Excel и массовые скачивания — только администратор.
Быстрые фильтры: мин. остаток 0/ниже, требуют внимания, ожидают поступления.
«Заказано N» не красным как «совсем нет» — отличимый цвет (жёлтый) и текст «нет (заказано N)».
Принять на склад из склада для ожидающих (как в оплаченных заявках), не превращая склад в заявки.
Починить ошибку accept-на-склад (уходила на сервер).

G. Документация / паспорта
Паспорт создаётся у продукта и живёт с продуктом. В заказ цепляем продукт → паспорт появляется в документации.
В документации НЕ список всего каталога. Группировка: заказ → паспорта к нему (доделать / распечатать). Статус готов/не готов/доработать.
Архив — только архив (печать, без правок).
Документация = точка сбора задач менеджера (уведомления позже, не в этом этапе).
Минимальный набор категорий документации для выдачи изделия; акты/отгрузка — задел, не раздувать.

H. Дефолтные фильтры везде
Всегда открывать самую актуальную рабочую выборку (в заказах — незавершённые/в работе), затем все, затем отгруженные/выполненные.
