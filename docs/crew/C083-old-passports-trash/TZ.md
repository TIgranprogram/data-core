# C083 — старые паспорта убрать в корзину (решение владельца 2026-11-11)

**Класс:** XL (данные прода) · запись на прод — **только кнопкой пульта, нажимает владелец** · исполнитель подготовки: Cursor или координатор.

## Решение владельца

«Старые паспорта удалим: главное было забрать информацию, продукцию заполнили. Оставить последнюю нумерацию, чтобы продолжить с последнего номера. Новые паспорта получаем одной кнопкой». На вопрос «в корзину или насовсем» ответ: **в корзину**.

Смысл: 329 паспортов, перенесённых из таблицы (`source` не `app` и не `ready-file`; на 11.11 всего 343, с сайта 14), пропадают из списков и вкладки «По номерам», но остаются в базе: номера заняты, любой можно вернуть. Это выданные заказчикам документы — насовсем не удалять.

## Шаг 1. Проверка без изменений (скрипт-план, только чтение)

Скрипт `backend/scripts/c083-old-passports-plan.js` по образцу `products-fill-defaults.js` (план без записи). Отчёт `docs/crew/C083-old-passports-trash/REVIEW.md`:

1. Сколько старых паспортов, по статусам и фирмам; последний номер общий и по фирмам.
2. **Что ещё не забрано в изделия:** у скольких старых паспортов есть рисунки (чертёж, схема фундамента, зона безопасности), которых нет у изделия; тексты с ручной правкой; материалы, элементы, числа, которых нет в умолчаниях изделия. Список изделий «потеряют при удалении».
3. Паспорта без изделия (на 11.11 — 8): что с ними.
4. Кто ссылается на старые паспорта: позиции заказов (`incomeId`), заказы, вложения, QR.
5. Как считается следующий номер после удаления: проверить по коду (`passport-ready.ts`, выдача номера при выпуске), что удалённые в корзину учитываются. Если нет — сначала поправить выдачу номера и покрыть тестом.

Перед шагом 1 владелец должен дожать две кнопки пульта: «назначение, элементы, установка» и «сколько человек пользуется».

## Шаг 2. Забрать недостающее

Если п. 2 отчёта не пуст — перенести рисунки и данные в изделия (план → запись кнопкой; в архиве есть образцы `backend/scripts/archive/passport-images-to-product*`, `passport-fields-to-product*`). Повторный план = 0.

## Шаг 3. Корзина

- Скрипт `--apply`: мягкое удаление (`deletedAt`), с выгрузкой списка для отката; обратный скрипт «вернуть из корзины».
- Не трогать: паспорта с сайта (`source: app`), готовые (`ready-file`), черновики в работе, паспорта, привязанные к незакрытым заказам (список — в отчёт, решает координатор).
- Проверка на стенде на копии базы: план → запись → повторный план = 0 → выпуск нового паспорта даёт номер «последний + 1» → откат возвращает всё.
- Кнопка в `pult/catalog.mjs` (`risk: 'danger'`, подтверждение словом), пункт в `pult/todo.json` с понятным «что изменится»; перед записью — копия базы.

## Готово, когда

Во вкладке «По номерам» только новые паспорта; полоска «Последний №» показывает прежний последний номер; новый паспорт получает следующий номер; поиск по старому номеру через «Корзину» находит документ.
