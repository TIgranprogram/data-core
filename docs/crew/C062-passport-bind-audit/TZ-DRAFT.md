# ЧЕРНОВИК ТЗ C062 — номер паспорта: продукция, позиция, файл

> Черновик. Код — после `TZ.md` от координатора. ПР-1 подтверждён (несколько фирм); ПР-2…5 — по умолчанию + уточнение UI 2026-11-11.

**Зачем (словами пользователя):** привязка к продукции/позиции; список номеров у изделия (несколько фирм); повторная печать тем же №; файл к номеру; **в нужных местах — выпадающие списки** для оформления паспорта и выбора номера.

**Зачем — глаголом:** менеджер выпускает паспорт изделия за один заход, видит номер в карточке продукции, печатает повторно без нового номера и при необходимости подменяет PDF своим файлом.

## Глубже
- **Результат:** номер живёт у выпущенного экземпляра; продукция показывает список номеров; позиция заказа не получает второй живой паспорт.
- **Сырьё:** схемы и поведение — `CODE-MAP.md`. Живой подсчёт «сколько паспортов на одно изделие / на одну позицию» с прода этим аудитом не снимался. Перед кодом — чтение через access, не пересказ.
- **Метод профи:** как учёт бланков строгой отчётности: номер гасится при выдаче бланка, повторная печать не берёт новый бланк, чужой скан вешается на уже выданный номер.
- **Внешний судья:** юнит «повторная печать не увеличивает счётчик»; один живой паспорт на позицию; вкладка изделия показывает номер после выпуска.
- **Смелая планка:** повторная печать — 1 нажатие, 0 новых номеров.

**Класс (после ответов):** L, если подтверждены допущения ПР-1…ПР-5 (гибрид C, файл на экземпляр, 1 строка = 1 документ, номер при выпуске). XL — если номер полем на `products`, номер на каждую штуку или номер в момент отметки «изготовлено» (общая коллекция + другое поведение счётчика). **Max agents:** L → 2 (исполнитель + qa); XL → аналитик уже сделал этот черновик, дальше architect до кода. **Проверки:** L — smoke модуля; перед выкладкой full. **Язык менеджера:** да. **Приёмка:** вкладка «Паспорт» изделия и печать из заказа.

## Решение по умолчанию (пока нет ответа)
Гибрид C из `ANALYSIS.md`: учётный объект = запись `productpassports`. `productId` обязателен на новом ручном выпуске. `incomeId` — когда есть позиция. Поле «текущий номер» на `products` не добавлять. Файл PDF — необязательное вложение экземпляра. Пометки на строке: «С сайта» / «Файл».

## Что сделать (когда черновик станет ТЗ)
1. Ручной выпуск без изделия не сохранять: выбрать продукцию из списка. Номер после выпуска — в таблице вкладки «Паспорт» (№ паспорта, заводской №, **фирма**).
2. Повторная печать того же паспорта — тот же номер (§10). C060 (аннулировать → тот же №) не ломать.
3. Второй живой паспорт на ту же позицию заказа не создавать (замок — архитектор; индекс на прод — только с «да»).
4. К номеру — прикрепить файл → печать файла; иначе PDF сайта. Метки «Файл» / «С сайта».
5. qty > 1: один документ на строку (ПР-3).
6. **Выпадающие списки** — см. ниже; без них выпуск не принимать.

## Выпадающие списки (обязательные места)

| Где | Список | Зачем |
|--|--|--|
| «Новый паспорт» / выпуск | **Изделие** (продукция) | привязка модели; без выбора не выпускать |
| «Новый паспорт» / выпуск | **Фирма** (наши компании) | несколько паспортов на одно изделие — по фирмам |
| «Новый паспорт» из заказа | **Позиция заказа** (если не из карточки позиции) | связь `incomeId`; не плодить второй живой |
| Печать / повтор | **Номер паспорта** (уже выпущенные по изделию ± фирме ± заказу) | печатать выбранный №, не новый |
| Вкладка изделия «Паспорт» | фильтр **Фирма** (если фирм > 1) | не смешивать номера разных фирм в голове |
| Прикрепить файл | к **выбранному номеру** (тот же список номеров) | файл не на шаблон модели |

Списки — `combo` / выбор из kit, язык менеджера (название фирмы и изделия, не сырой id). Пустой список — подсказка «сначала выпустите» / «выберите изделие».

## Вид
Таблица выпущенных + колонка «Фирма» + бейдж «Файл»/«С сайта»; кнопки «Печать» / «Прикрепить файл»; выпадающие — kit `combo`. Файл — правая панель карточки **экземпляра**, не шаблона.

## Критерии приёмки
- [ ] Если выпустили паспорт с изделием — во вкладке «Паспорт» есть номер, после повторного открытия он на месте.
- [ ] Если нажали «Печать» второй раз — номер тот же, следующий свободный номер не сдвинулся.
- [ ] Если прикрепили файл — печать отдаёт файл и метку «Файл»; без файла — PDF сайта и «С сайта».
- [ ] Если у изделия несколько заказов/фирм — в таблице несколько номеров с фирмой, ни один не стёрт.
- [ ] В нужных местах есть списки: изделие, фирма, позиция (из заказа), номер для печати/файла.
- [ ] Если у позиции уже есть живой паспорт — второй не появляется.
- [ ] Черновик по-прежнему без номера. Старые выпущенные паспорта не перенумерованы.
- [ ] Ничего не сломано: tsc 0, юнит модуля паспортов, `node --input-type=module --check` по изменённым экранам.

## Нельзя
- Данные прода, новая коллекция, поле номера на `products`, перенумерация выданных, уникальный индекс на проде без отдельного «да».
- Контракт списков `{items,total,page,limit}` не ломать. Новое поле — только добавление; CRM его не читает.
