# C016 — аудит «Сопоставление» (без правок кода)

**Дата:** 2026-11-03 · **Класс:** S (аудит) · **Статус:** PASS

## Зачем нужно

Позиция договора (`incomes`) должна ссылаться на изделие каталога (`showcase` / productId). Без связи:

- нельзя надёжно вести производство, брони, выдачу, паспорта и «В работе» по каталогу;
- «В производство» / assign блокируется при несопоставленных (API `unmatched`, модуль `matching`);
- менеджер не понимает, «качели из договора» = какое изделие в «Продукции».

**Что даёт:** подтверждение связи позиции ↔ изделие (или «не изделие»), массовое подтверждение уверенных подсказок, создание изделия из названия строки, очередь «что ещё не связано».

## Где в коде / UI

| Слой | Путь | Роль |
|--|--|--|
| API | `backend/src/modules/matching/` | suggest, unmatched, count, confirm, none, bulk |
| Правая панель | `pwa/sections/salesorders-matching.js` | `?of=matching&open=<договор>[.<позиция>]` — выбор изделия |
| Очередь UI | `pwa/sections/matching-queue.js` | `unmatchedTop`, плашка/флаг, `mountMatchingQueue` |
| Экран `#matching` | `main.js` NAV + `mountMatchingQueue` | вкладки «Позиции» + «Договоры без заказа» |
| Уже в «Заказах» | `salesorders.js` `list.top` | **уже** вызывает `unmatchedTop()` + `unassignedTop()` |
| Карточка/строки | `salesorders.js`, `order-lines.js`, `salesorders-unassigned.js` | бейдж «не сопоставлено», «Подобрать изделие», плашка |
| Право | `session.sees('matching')` | счётчик; писать — admin/manager |
| Проектирование (`design`) | — | **сопоставления нет** |

## Текущий флоу

1. Договор с позициями без productId / без подтверждения → состояние unmatched/auto.
2. Менеджер видит: кнопку «Несопоставленные · N» **над списком Заказов**, и/или отдельный пункт меню «Сопоставление», и/или бейдж в карточке/таблице позиций.
3. В очереди: поиск, фильтры заказ/договор/этап, «только в производстве», «Подтвердить» / «Выбрать…» / «Не изделие», bulk уверенных.
4. «Выбрать…» → правая панель: подсказки, поиск по каталогу, «+ Изделие», «Не изделие».
5. Вкладка «Договоры без заказа» на `#matching` = тот же смысл, что `unassignedTop` в Заказах (перенос договоров в заказ; без сопоставления assign режется).

## Плюсы отдельной страницы

- Явный «рабочий стол» для закрытия хвоста по всем заказам.
- Вкладки + счётчики в одном месте (позиции + без заказа).
- Фильтры и bulk без открытия конкретного заказа.

## Минусы отдельной страницы

- **Дубль:** очередь и «без заказа» уже встроены сверху в «Заказы» (`list.top`). Экран `#matching` почти копирует это же (`unmatchedTop({ open: true })` + unassigned).
- Лишний пункт меню (C011 FIX-TZ пачка 7: убрать из сайдбара).
- Менеджер уходит из контекста заказа/этапа «проектирование».
- В `design` сопоставления нет — ожидание «сверху в проектировании» сейчас не закрыто отдельным экраном.

## Рекомендация (встроить в заказы, без отдельной страницы)

1. **Убрать** пункт «Сопоставление» из левого меню (`main.js` группа «Производство»). Раздел `#matching` можно оставить как скрытый deep-link на переходный период или сразу редирект на `#salesorders`.
2. **Оставить** рабочий UI в «Заказах»:
   - сверху: кнопка/раскрытие «Несопоставленные · N» **только при N > 0** (сейчас кнопка скрывается при нуле — уже близко к идее пользователя);
   - правая панель `of=matching` без изменений (редактирование из строки/плашки заказа).
3. **«Договоры без заказа»** — только через `unassignedTop` в Заказах (вторая вкладка экрана matching не нужна).
4. **Опционально усилить «проектирование»:** на вкладке фильтра «Новые» (`filter=new`) или в шапке доски/списка всегда показывать компактную кнопку счётчика, если `inProduction` или `total > 0` — без отдельного маршрута.
5. **Не переносить** API matching; менять только навигацию и точку входа.

## Что не делать в этой волне

- Не трогать сервер `matching/*` и логику confirm/none/bulk.
- Не дублировать очередь ещё и в `design`, пока Заказы уже содержат `unmatchedTop`.
- Код в этом задании **не менялся** (только аудит).

## Решение для пользователя

Согласны убрать меню «Сопоставление» и жить из шапки «Заказов» + правой панели? После «да» — пачка S по C011 §7 п.1 (+ редирект `#matching` → заказы).
