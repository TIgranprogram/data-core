# ТИ-11 — Документация: заказ → паспорта (analyst, 2026-10-27)

## Что уже есть
- Паспорт — экземпляр у модели: `productId` необязателен (`product-passport.schema.ts:59`), эндпоинты `products/:id/passport` (controller:29–35).
- Связь с заказом: `orderNo`, `salesOrderId` (schema:~156–160); из заказа «Выпустить паспорт» их подставляет (`pwa/sections/orders.js:161`).
- Жизненный цикл `status`: draft / issued / annulled; нет поля = issued (schema:66). Это НЕ «готов / доработать».
- Список `GET /passports` (controller:53) фильтрует по `productId`, `search` (включая № заказа), `year/month`; фильтра по `salesOrderId` и группировки нет.
- «Документация» (`pwa/sections/docs.js:20`): вкладка «Паспорта» — список изделий (шаблоны, строка 25–110); «Архив паспортов» — журнал, только просмотр/печать (docs.js:112–130, `form/remove/bulk` сняты). НВ.3/НВ.4 сделаны.
## Чего нет
1. Вида «заказ → паспорта к нему».
2. Статуса готовности (готов / не готов / доработать).
3. Счётчика «паспортов у заказа» в заказе.

## Решение
Каталог не дублируем: шаблоны остаются на вкладке «Паспорта», заказы — новая третья вкладка «По заказам».
### Статус
Новое необязательное поле `readiness?: 'ready'|'notReady'|'rework'` в `productpassports` (schema после строки 67; kppdf не читает, коллекция общая — только добавление). Нет поля = для выпущенного «готов», для черновика «не готов» (считать на чтении, данные не мигрировать). `reworkNote?: string` — что доработать (необязательно). Не путать с `status`. Аннулированный: статус готовности не показываем.
### Сервер
- `GET /passports?salesOrderId=…` и `?orderNo=…` — фильтр в `passport-queries.ts` (рядом со строкой 41); `readiness` — тоже фильтр.
- `GET /passports/by-order` (новый, controller рядом со строкой 53): группы `{ orderId, orderNo, customerName, total, ready, notReady, rework, items[]}` только заказы, где есть паспорта; паспорта без заказа — группа «Без заказа». Пагинация по заказам.
- `PATCH /passports/:id` (controller:261): разрешить `readiness`, `reworkNote` — и после печати (добавить в `AFTER_PRINT_FIELDS`, `passport-consts.ts:15`). Права как у правки паспорта. Контракт: обновить `docs/openapi.json`, `MAP.md`.
- Ключ группы: `salesOrderId`, если нет — нормализованный `orderNo`. Проверить (архитектор): совпадает ли `salesOrderId` с `incomes.orderId` из `orders.js:162`.
### Экран
- `docs.js:20` TABS: добавить `['orders','По заказам']`; `tabOf` (строка 21) и `mountTab` (144) расширить. Новая секция `docs-orders.js` (список заказов-групп; раскрытие/правая панель — паспорта заказа с чипом статуса).
- Чип статуса в списке/карточке паспорта: `passports.js` колонки, `passports/card-blocks.js`; смена — кнопки в правой панели (не inline-ввод), 3 значения.
- Архив (docs.js:112): остаётся только просмотр/печать; смена `readiness` в архиве запрещена; добавить колонку-чип и фильтр.
- В заказе (`orders.js`, карточка): строка «Паспорта: N (готовы M)» → ссылка на `docs?tab=orders&open=…`.
- Язык менеджера: «Готов», «Не готов», «Доработать»; без кодов; пустое состояние: «К этому заказу паспорта ещё не выпускали — «Выпустить паспорт» в заказе».

## Критерии приёмки
1. Если выпустить паспорт из заказа, то на вкладке «По заказам» он в группе этого заказа.
2. Если паспорт без заказа, то он в группе «Без заказа», не пропадает.
3. Если у старого паспорта нет `readiness`, то выпущенный показан «Готов», черновик «Не готов»; данные не изменены.
4. Если выбрать «Доработать», то статус сохранён, видна заметка; PDF и номер не меняются.
5. Если паспорт в архиве, то есть просмотр и «PDF и печать», но нет правки, удаления и смены статуса.
6. Фильтр по статусу показывает только нужные паспорта; счётчики группы совпадают со списком.
7. Вкладки «Паспорта» (шаблоны) не показывают заказы и не дублируются; каталог изделий не копируется.
8. Права: без `seesDocs` вкладка скрыта; без `canEdit` статус только читается.
9. `GET /passports` без новых параметров отвечает как раньше (контракт); typecheck и юнит зелёные; e2e на `by-order` и PATCH `readiness`.
## Не входит
Автосмена статуса, уведомления, переносы старых данных, связь с МИ/МЦ (отдельно).
