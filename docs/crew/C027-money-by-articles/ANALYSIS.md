# C027 — «Деньги» по статьям, как в таблице директора

Источник: `для анализа/Доходы-Расходы.xlsx` (только пример вида, данные не загружаем).
Дата: 2026-11-06. Класс: XL (новый вид + новый справочник + новые виды расходов).

## 1. Как устроена таблица директора

- Один лист = **один объект/контракт** («Тихорецк»). Вверху: цена контракта, остаток по кредиту.
- Колонки: `№ · Статья · Подстатья · Янв … Дек · Итого факт · %` (процент от цены контракта), справа — план прибыли.
- Шапка (строки 4–6): **Доходы / Расходы / Прибыль** по месяцам.
- Тело: 14 **статей** (строка-итог, жирная) → под ней **подстатьи** (свёрнуты группировкой Excel, «+» раскрывает).
  У «Субподрядные работы» — третий уровень: подрядчик (ООО «Приват-Деал», Бригада № 2…) → его платежи (Аванс 1, Аванс 2, комиссия).
- Низ: ИТОГО затраты · Финансовый результат · Финансовый результат нарастающим · Отношение доходов к расходам.
- Только **факт по месяцам**, не по дням.

Статьи (14): Рабочая одежда · Расходные материалы · Инструменты · Оборудование · Налоги ·
Финансовое обслуживание (банк, кредиты, БГ) · Организационные расходы и ФОТ (гросс: зарплата, аренда, командировки, ГСМ, займы) ·
Операционные расходы и ФОТ (нет: зарплата на руки, премии, дивиденды, внештатные) · Ремонт и обслуживание ·
Переменные расходы (штрафы, сайт, маркетинг, подбор) · Материалы для площадки · Субподрядные работы · Аренда спецтехники · Транспортировка.

## 2. Что у нас сейчас (`backend/pwa/sections/money.js`, `backend/src/modules/finance/`)

| Вкладка | Что показывает |
|--|--|
| Платёжный календарь | один месяц **по дням**; строки: Поступления / Выплаты (по фирмам СИЮ/ССЮ), итог дня, остаток. Клик по сумме дня — операции. |
| Сводка | год по месяцам — **одна строка на месяц** (поступления, выплаты, итог), отдельно доли «Куда / На что / Кому тратили». |
| Прогноз, Долги | будущее и долги. |

Откуда берутся расходы (`finance.service.ts:89-135`): оплаченные заявки снабжения + оплаченные счета + ФОТ.
Категория расхода = категория материала (`categories`, `type:'material'`, **один уровень**) + «направление» (Цех/Офис/СМР/Заказы/ФОТ).

## 3. Разница

| Нужно директору | У нас | Разрыв |
|--|--|--|
| Строки = статьи, раскрываются до подстатей и операций | строки = Поступления/Выплаты | **нет вида «по статьям»** |
| Колонки = 12 месяцев + Итого + % | календарь — дни; сводка — месяцы строками | транспонировать: месяцы в колонки |
| Справочник «Статья → Подстатья» (2–3 уровня) | плоские категории материалов | **нет справочника статей** |
| Налоги, банк, кредиты, аренда, займы, дивиденды, субподряд, спецтехника | только заявки снабжения и ФОТ | **негде записать прочие расходы** |
| Отчёт по объекту (лист = контракт), % от цены контракта | фильтр только по фирме | нужна привязка расхода к объекту/заказу и фильтр |
| Финрезультат нарастающим, доходы/расходы | нет | легко посчитать |

## 4. Предлагаемый вид (вкладка «По статьям», первая в «Деньгах»)

```
Фильтры: Год ‹ 2026 ›  · Фирма [все|СИЮ|ССЮ] · Объект [все | заказ …]
              Янв     Фев   …  Дек   Итого   %
Доходы        …
Расходы       …
Прибыль       …
▸ Расходные материалы        12 300  …        (клик ▸ — подстатьи)
  ▾ Инструменты               4 500
      Рулетка                   300   (клик по сумме — список операций справа)
      Гаечные ключи           4 200
▸ Налоги …
──────────────
Финансовый результат · нарастающим · доходы/расходы
```

- Строка статьи — итог, жирная; ▸/▾ раскрывает подстатьи; клик по сумме — операции этой ячейки (правая панель, как сейчас).
- «Раскрыть всё / Свернуть всё». Пустые подстатьи скрыты.
- Нераспределённое — строка «Без статьи — заполнить →» (в очередь «Требуют заполнения»).
- Календарь по дням остаётся отдельной вкладкой (для остатка на счёте).

## 5. Шаги (после ответов)

1. Справочник «Статьи расходов» (статья → подстатья), начальный список — из таблицы директора. Связь: категория материала → подстатья (по умолчанию), заявка может переопределить.
2. «Прочий расход» — форма в правой панели (дата, сумма, фирма, подстатья, объект, комментарий) для налогов, банка, аренды, субподряда.
3. Сервер: `GET /api/finance/by-articles?year&org&order` — дерево статей × 12 месяцев (чистая функция + юнит-тесты).
4. Экран «По статьям» (skill `datacore-design`, приёмка `datacore-designer`).
5. Объект: привязка расхода к заказу (у заявок уже есть `salesOrderId`) + цена контракта → колонка «%».

## 6. Вопросы пользователю

1. Отчёт нужен по одному объекту (как лист «Тихорецк») или по всей фирме? Предлагаю: по всей фирме + фильтр «Объект».
2. Список статей и подстатей берём из таблицы директора как стартовый справочник? (Его можно править в админке.)
3. Налоги, банк, аренду, субподряд вносить новой формой «Прочий расход»?
4. Нужен ли план (бюджет по статьям) рядом с фактом — или только факт, как в таблице?

## 7. Ответы пользователя (2026-11-06)

1. **Объект:** переключатель над таблицей — «Вся фирма / По объекту». Директор ещё не решил, что ему нужно, — оба варианта.
2. **Статьи:** справочник «Статья → Подстатья», гибко правится. Уже купленные товары (заявки) **грамотно сопоставить** со статьями (план сопоставления → проверка → применение). Выбор статьи — в форме новой заявки.
3. **Прочие расходы:** отдельная страница быстрого ввода: прикрепить файл счёта, общая сумма, название, статья, фирма, дата, объект (всё, что нужно для расчёта).
4. **План:** только факт.

Порядок: 1) справочник статей + сопоставление старых заявок (data-steward, план → `--apply` по «да»); 2) страница «Быстрый расход» со счётом-файлом; 3) сервер «по статьям»; 4) экран с переключателем.
