# Команда агентов data-core — playbook координатора

Читает координатор при задаче класса M+ (не на старте). Роли получают ссылку на нужный раздел через ТЗ. Агенты между собой не общаются: всё через координатора и ТЗ. Почему так — `docs/roles/lessons-coordinator.md`.

## Приёмка вида и поведения

Обязательна `docs/UI-ACCEPTANCE.md`. Нет роли designer в среде — назначить проверяющего с инструкцией `.claude/agents/datacore-designer.md`; отсутствие роли не позволяет заменить визуальную приёмку линтером. Координатор проверяет UI-REVIEW перед меткой и выпуском.

Для Codex определена `.codex/agents/datacore-designer.toml`, ссылающаяся на единую инструкцию роли. Навыки дизайна/проверки зеркалятся в `.agents/skills/`; при изменении порядка обновлять обе копии. Новый профиль проверен как TOML; его обнаружение выполняет среда Codex, при отсутствии в текущем списке — описанный выше fallback.

## Класс задачи (решает координатор до первого агента)

| Класс | Примеры | Агентов max | Обязательны | Проверка |
|--|--|--|--|--|
| S | подпись, пункт меню, одна функция, конфиг | 0 (сам) | — | smoke |
| S/M | язык экрана: подписи, меню, заголовки, ложные метки, единообразие похожих элементов | 0–1 (сам; designer — только если меняется элемент/раскладка) | без аудита-консилиума | smoke |
| M | экран или модуль целиком; новый маршрут; скрипт данных | 2 | вид → designer; данные прода → steward или architect | smoke |
| L | сервер + экран по контракту; несколько модулей | 4 | qa; architect, если модули/общие коллекции/скорость; designer, если вид | smoke, full перед выкладкой |
| XL | новая возможность; перенос/чистка данных прода; схема общей с CRM коллекции | 5 | analyst до кода; architect + qa после; designer, если вид | full |

- **Циклы «проверка → правка»** — не больше 2 на задачу; третий — решение координатора (сделать самому / упростить / спросить пользователя).
- **Аудит L/XL:** один основной читатель (обычно architect или analyst) делает выжимку → остальным — только слепые зоны с явным списком файлов.
- **Shared pack + split:** общее для всех ролей задачи (слова пользователя, решение, контракт) — один файл ТЗ; файлы для чтения у каждой роли — свои, без пересечений. Две роли на одни файлы — только с разделом scope в ТЗ (кто что смотрит).
- **Параллельно:** роли с непересекающимися файлами — в одном сообщении; в каждое ТЗ — строка «ожидаются правки: <файлы соседа>».
- **Вторая сессия** — только worktree + готовое ТЗ + одна роль; своей «команды» и оркестратора в ней нет.
- **Отчёт роли ≤ 12 строк:** статус | сделано | файлы | проверки | риски/нужно от других. Длиннее — координатор не дочитывает. Полный текст — в `docs/crew/Cxxx/REPORT.md` (и FIX-TZ/PLAN по ТЗ), не в чат.
- **Экономия токенов** — `AGENTS.md` «Экономия токенов» (единственная копия).

## Работаем смело (урок C038, 2026-11-07)

1. **Цель, а не шаг.** Координатор держит в голове цели `docs/CONTROL.md`; ТЗ говорит, какую цель двигает.
2. **Сырьё, а не пересказ.** Начинать с живых данных (ошибки, медленные запросы, выгрузка прода), а не с чужого вывода.
3. **Как профи.** Метод лучшего специалиста области (замер, статистика, стандарт), а не «слова профи». Роли других областей — ради их методов, не ради ролевой игры.
4. **Внешний судья.** «Готово» = команда → итог, тест, `dc audit`, снимок стенда, число до/после. Слово роли доказательством не считается.
5. **Смелая планка.** Число с запасом. Трудно ≠ невозможно: 2 неудачных подхода → «нужен совет opus».

## Поток задачи

1. Класс задачи → нужен ли analyst (XL) / architect до кода (модули, данные).
2. ТЗ по `docs/roles/TZ-TEMPLATE.md` → `docs/crew/Cxxx-<коротко>/TZ.md` (точные места: файл:строки; блок «Глубже»). Новых файлов в `docs/roles/tz/` не создавать.
3. Исполнители (backend / frontend / steward) — по контракту ТЗ.
4. Проверяющие по матрице; 🔴 — назад исполнителю (≤ 2 круга).
5. Координатор: сверка пунктов ТЗ ✅/❌/➖ → коммит, пуш, выкладка, `TASKS.md`, строка на `docs/crew/BOARD.md`.

## Общие правила ролей

- Только своя зона; чужое — «нужно от <роль>: …» в отчёте.
- Читать только ТЗ и указанные места: Grep, `offset/limit`, `git diff`; `DESIGN`, `CANON`, `HISTORY`, `TASKS` целиком — нельзя.
- Застрял 2 раза → поиск в интернете (официальные доки), решение и ссылка — в уроки `docs/roles/<роль>.md` одной строкой.
- Не коммитить, не выкладывать.
- **Сверка перед отчётом:** каждый пункт ТЗ — ✅ сделано (файл) / ❌ нет (почему) / ➖ не моя зона (чья).

## Охрана своей зоны

1. Перед работой: `git status --short` по зоне. Незакоммиченное, чего нет в ТЗ («ожидаются правки»), — чужое.
2. Файл зоны изменился не тобой (changed on disk, правка не применилась) — чужое.
3. Чужое — ничего не править и не откатывать; сразу отчёт `⛔ Чужие правки: <файлы> · что в них · моя работа: …` и текст для новой сессии «Продолжи ТЗ <путь>: сделано …, осталось …».
4. Координатор с `⛔` ничего не правит, пока не выяснит у пользователя, откуда правки.

## Совет сильной модели (правило пользователя 2026-10-25)
Трудную задачу координатор сначала передаёт одному агенту с `model: "opus"` — выжимкой (суть, файл:строка, варианты, что неизвестно); тот отвечает «как действовать» (решение, порядок, подводные камни, ≤ 30 строк, код не пишет). Ответ вносится в ТЗ, дальше исполнитель (sonnet) работает по нему без самодеятельности. Роль, упёршаяся в трудное решение, не гадает: пишет в отчёт «нужен совет opus: <вопрос>». Простое — без совета, экономим токены.

## Эскалация

- Не твоя зона или неясно, чья: доделай своё, в отчёте `⚠ Нет хозяина: что · почему не моё · кто мог бы`.
- ТЗ противоречит канону (CANON, DESIGN, AGENTS «Жёсткие правила») — `⚠ Противоречие`, сам не выбирай.

## Новая роль

`⚠ Нет хозяина` второй раз по одной теме → координатор: строка в «Роли и зоны» (зоны не пересекаются) → `.claude/agents/datacore-<роль>.md` по образцу (с `model: sonnet`; проверяющим — без Edit/Write) → уроки `docs/roles/<роль>.md` и карта `docs/roles/maps/<роль>.md` → строка в таблице CLAUDE.md, если нужно → коммит. Подключается после перезапуска сессии; первая задача — небольшая.

## Требования пользователя, которые роли проверяют всегда

Ограниченный набор значений → справочник и выпадающий список (CANON §5) · тяжёлые данные — по действию, не при открытии экрана (1 ядро, туннель ~1 с) · числа размеров — узкими полями в строку с единицей в подписи · долгое действие — видно, что идёт работа · по-русски, без кодов и «v2»; ошибка говорит, что сделать. (Правая панель и «данные — только с бэкапом» — в CLAUDE/AGENTS.)

## Карта роли — без перечитывания

1. У роли своя карта `docs/roles/maps/<роль>.md` (≤ 80 строк): файл → что в нём → строки/функции, контракты, «где что менять»; сверху `коммит: <hash>`.
2. Старт: только карта + ТЗ; дальше точечно. Что изменилось — `git diff --stat <коммит карты> -- <зона>`.
3. **Конец работы — обязательно:** дописать в карту якоря `файл:строка` / «где X» по тому, что искал в этой задаче, обновить `коммит:`; в отчёте — «карта обновлена».
