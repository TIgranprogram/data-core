# C062 — сверка ожидания с паспортами после выкладки

Аналитик, 2026-11-11. Код не менялся. Источники: `ANALYSIS.md`, `TZ.md`, `REPORT*.md`, схема `product-passport.schema.ts`, `passport-bind.ts`, `passport-queue.ts` `fromIncome`, `passport-from-product.ts`, `passport-order.ts`, `passport-pdf.service.ts` `orgOf`, воронка `pwa/sections/passports/funnel/issue.js`, вкладка `products/card-blocks.js` `passportPane`. Против: PRODUCT §5а, QUESTIONS ПР-1…ПР-6.

## Вердикт

Шаблон и номер разведены верно: на изделии шаблон, номер у выпущенного паспорта, позиция заказа может держать один живой документ. Ожидание «при печати подставляется наша фирма заказа» не выполнено. Печать берёт фирму, записанную в паспорт. Компания заказа (`salesorders.companyId`, СИЮ/ССЮ) в эту запись не копируется.

## Как устроено сейчас

| Ожидание | Факт после C062 |
|--|--|
| 1. У изделия только шаблон | В данных да. Шаблон — `products.passportDefaults` и тексты категории. Номера на изделии нет. Выпущенный документ — строка `productpassports`. |
| 2. Реальный паспорт обычно на заказ | Связь необязательна. С карточки изделия выпуск идёт без заказа. С заказа или позиции пишутся `incomeId` и `salesOrderId`. |
| 3. При печати — фирма заказа, кто оформляет | Нет. PDF читает `supplierOrgId` паспорта. Воронка показывает все наши фирмы и не смотрит `companyId`. Если наша фирма одна — подставляется она, даже если у заказа записана другая. |
| 4. Выпущенные связаны с заказом и позицией | Если выпуск с позиции: заказ, номер заказа, заказчик и изделие подтягиваются. Второй живой паспорт на ту же позицию — отказ. Без позиции связи нет. |
| 5. Вкладка «Паспорт»: шаблон и история (номер, заказ, фирма) | Шаблон есть. В таблице: номер, заводской номер, фирма, «Файл»/«С сайта», дата, заказчик. Колонки «Заказ» нет. Номер заказа в данных строки есть. |

## Совпадает ✅

- Если готовят модель — правят шаблон изделия. Номер при этом не появляется.
- Если выпускают — номер, заводской номер и талон живут на экземпляре, не на изделии.
- Если у позиции уже есть живой паспорт — второй не создаётся. Одна строка заказа — один документ (ПР-3).
- Если печатают строку во вкладке — номер тот же, новый паспорт не рождается.
- Фирма не входит в поля, которые шаблон изделия копирует в черновик (`passport-from-product.ts`).
- Несколько выпущенных паспортов одного изделия в таблице не затирают друг друга.

## Дыры P0–P2

**P0. Фирма заказа не становится оформителем.**

- Воронка выпуска грузит заказ, чтобы взять номер, заказчика и позиции. `companyId` не читает. Пока фирм больше одной, список пустой: «Выберите фирму».
- Черновик с позиции берёт у заказа только номер и заказчика. Фирма — та, что прислали, либо единственная наша компания.
- Выпуск пачкой по заказу создаёт паспорт только с позицией. При двух фирмах план пишет «Выберите фирму» и не берёт компанию заказа.
- Печать ищет организацию по `supplierOrgId` паспорта. Смена компании у заказа штамп не меняет. Неверная фирма при выпуске так и печатается.

**P1. В истории изделия нет заказа.**

- Ожидание строки: номер, заказ, фирма. Сейчас заказа в колонках нет, заказчик спрятан. Номер заказа карточка изделия уже отдаёт.

**P2. Главная кнопка изделия выпускает паспорт без заказа.**

- «Выпустить паспорт» открывает воронку только с изделием. Ручной паспорт без заказа разрешён (ПР-2). Путь «обычно на заказ» с этой кнопки не предлагается.

**P2. Фирма числится полем модели при копировании паспорта.**

- Список полей копии включает `supplierOrgId`. Копия старого паспорта может унести чужую фирму. На шаблоне изделия фирмы нет.

Сверка с решённым. PRODUCT §5а: содержание паспорта берётся из изделия; номер заказа и покупатель можно вписать после печати. C062 ПР-6: фирму выбирают списком. Фразы «фирма заказа подставляется сама» в этих решениях нет. Дыра P0 — против нового ожидания, не против текста выкладки v1.692.

## Дальше (без кода)

1. Правило выпуска. Паспорт из заказа без ручного выбора фирмы получает `companyId` заказа. Ручной выбор важнее. У заказа компании нет — спросить, как сейчас. Уже выпущенный паспорт фирму с заказа заново не читает.
2. Во вкладке изделия колонка «Заказ»: номер и переход в заказ.
3. Кнопку с изделия не закрывать. Паспорт без заказа остаётся. Отдельный шаг «к какому заказу» — только если это подтвердят.
4. Вопрос пользователю — ПР-7 в `docs/QUESTIONS.md`. По умолчанию: зафиксировать фирму в момент выпуска, печать её не переспрашивает.

Если фирма заказа есть и её не меняли руками — в паспорте и в PDF она. Если фирму выбрали сами — в PDF она, не компания заказа. Если печатают старый паспорт — штамп тот, что записан при выпуске.
