## 2. Принятые правила, которые нельзя потерять

1. Работаем с новыми паспортами новых заказов. Старые паспорта к заказам массово не привязываем: решение владельца 14.11 в BACKLOG.
2. Одна позиция заказа — один паспорт и номер. Количество изделий не создаёт новые номера самовольно.
3. Наименование позиции заказчика и наименование модели различаются. В паспорте сохраняется согласованное имя позиции.
4. Фирма берётся из заказа; замена видна пользователю. Номер от смены фирмы не меняется.
5. Выпущенный паспорт допускает явную правку с историей редакций, согласно C114. Печатается последняя сохранённая редакция.
6. Изменение изделия, шаблона или справочника само по себе не переписывает выпущенный паспорт.
7. Удаление прежней редакции — существующее действие с правами, подтверждением и аудитом. Текущую удалить нельзя.
8. Смена типа/вида/изделия очищает только несовместимые данные по согласованному правилу. Не теряет ручной ввод молча.
9. Общие значения наследуются; индивидуальные значения и ручные абзацы не затираются фоновым ответом.
10. Пробелы, предупреждения и неприменимые поля — разные состояния. Необязательное поле не блокирует выпуск.

## 3. Требования к завершённому сценарию

### A. Создание и источники

- Проверить все входы: очередь, карточка заказа, «Паспорта заказа», изделие, «Новый паспорт» без заказа.
- Изделие выбирается по артикулу/названию. Нет результата → понятное действие создания; отмена возвращает в прежний контекст.
- Новое изделие после сохранения доступно повторно; повтор запроса после потери ответа не создаёт второй объект.
- Фиксировать источник каждого поля: заказ, изделие, вид, тип паспорта, справочник, ручная правка, снимок редакции.
- Сверить приоритеты с `C096/SOURCES.md` и более поздними решениями C112/C114. Конфликт документов описать, не угадывать.
- Проверить очистку значения, 0, пустую строку, отсутствие поля: очищенное вручную не возвращается незаметно из fallback.
- Умолчания применяются без отдельного подтверждения каждого поля; фактические размеры, массу и нормативные числа не придумывать.
- Материалы, части, покрытия и модули согласованы между изделием, техописанием и паспортом. Копирование из аналога требует сохранения человеком.
- Сборное изделие 3215: количество модулей, состав, рисунки и итоговые таблицы соответствуют сохранённой конфигурации.
- PDM: проверить существующий путь и доступность файла; чужой/устаревший чертёж не выбирать автоматически. Нет источника — честный пробел.
- Смена группы, вида и типа не подставляет чужие ветки. Контрольный пример: 3201 «Скамейка на цепях», чужие тексты ограждений/урн исключены.

### B. Удобство заполнения

- В каждый момент понятны заказ, изделие, фирма, готовность и одно главное следующее действие.
- Очередь заполнения, заголовок, вкладки, нижняя полоса и серверная проверка не противоречат друг другу.
- Если счётчики имеют разный охват, явно подписать охват; не подгонять числа скрытием пробелов.
- Клик по пробелу раскрывает нужный блок и ставит фокус в поле; после сохранения следующий шаг актуален.
- Скрытые поля не требуют заполнения. Ошибка показывает поле и причину, сохраняет введённое.
- Выход во вложенную карточку/справочник и возврат сохраняют ввод, выбранную позицию, фильтры и место списка.
- Неприменимое скрыто, редкое свёрнуто, известное не спрашивается повторно. Длинные подсказки заменить существующими guide.* там, где это помогает.
- На телефоне нет двойной прокрутки, обрезанных кнопок и перекрытия нижней полосой. Основные цели касания ≥ 44 px.
- Клавиатура: Tab, Enter, Escape, видимый фокус, возврат фокуса после диалога. Выбор доступен без мыши.
- Состояния: загрузка, пусто, ничего не найдено, ошибка с повтором, нет прав, сохранение, сохранено, конфликт.
- Скачивание и предпросмотр дают прогресс и честный результат. Не сообщать «распечатано» после одного скачивания.

### C. Выпуск, редакции и сбои

- Одинарный/пакетный выпуск, двойной клик, две вкладки и повтор после потери ответа не создают дублей паспортов и номеров.
- Ошибка в середине пакетного выпуска оставляет проверяемый итог по каждой позиции. Повтор обрабатывает остаток.
- Отмена/удаление позиции заказа отражаются в плане; отменённые не выпускаются и не печатаются незаметно.
- Конкурирующая правка не затирает чужую редакцию. Конфликт предлагает безопасный повтор/обновление с сохранением собственного ввода.
- Проверить 400/403/409, обрыв связи, timeout, 503 READ_ONLY и retryAfter, истечение авторизации, медленный ответ прошлого изделия.
- На ошибке кнопки разблокируются; повтор ограничен; очередь не пишет в другой объект после переключения.
- Проверить обновление приложения при открытой форме: не смешиваются несовместимые модули, ввод не пропадает без предупреждения.
- После правки выпущенного: номер прежний, revision выросла, предыдущие значения видны в истории, одиночная и пакетная печать одинаковы.
- Роли проверить интерфейсом и прямыми API-запросами по существующим правам. Скрытая кнопка не заменяет серверный запрет.

### D. Содержание PDF

- Матрица: паспорт / техописание / совместный комплект; краткий / полный; pages / print; отдельный stand, если доступен для типа.
- Проверить фирму, изготовителя, название, артикул, номер, дату, гарантию, единицы, габариты, массу, глубину Г, модули и материалы.
- Проверить применимые тексты назначения, монтажа, обслуживания, сертификаты и знак ЕАС по существующим правилам.
- Неприменимые сведения не добавлять. Не утверждать нормативное соответствие без проверки уполномоченным специалистом.
- Нет `{меток}`, undefined/null, выдуманных чисел, чужих разделов, нечитаемого текста и обрезанных размерных линий.
- Фото, общий вид, чертёж и схемы стоят в правильных местах. Замена/удаление/поворот не ломают пропорции и подписи.
- Проверить длинные названия, абзацы, таблицы на несколько страниц, кириллицу, пустые необязательные блоки, чёрно-белый режим.
- Печать/подпись включаются независимо; принадлежат выбранной фирме. Отсутствующий файл объяснён, не подменяется чужим.
- Предпросмотр не выдаёт номер и не изменяет выпущенный документ. Повторная печать не создаёт новую бизнес-редакцию.
- Прикреплённый готовый PDF не пересобирается и не получает повторный буклетный спуск автоматически.
- Пакет заказа: выбранные позиции, порядок, последняя редакция, пропуски и ошибки. Если успешных нет — понятная ошибка вместо пустого файла.
- Пропуск одного паспорта виден в UI, включая заголовки X-Skipped-Passports/X-Failed-Passports; сохранённый пакет содержит остальные.

### E. Книжка и принтер

Следовать `C096/BOOKLET-ACCEPTANCE.md`. Проверить сначала логические страницы, затем спуск, затем настройки печати.
Маркированные примеры: N=1,2,3,4,5,7,8,9,12. Добивка 0–3 позиции допустима; лишние пустые страницы содержимого — дефект.
Для N=8 проверить пары 8|1, 2|7, 6|3, 4|5 и ориентацию оборота.
Для N страниц число PDF-сторон A4 = 2×ceil(N/4), физических двусторонних листов = ceil(N/4).
В заказе каждый самостоятельный паспорт должен складываться отдельно: не смешивать половины разных паспортов.
Подготовить инструкцию именно для полученного файла: бумага, масштаб, ориентация, duplex; исключить двойной booklet.
Физический отпечаток короткого и длинного паспорта: порядок, читаемость, поля под скрепление, размеры рисунков.
Если принтер недоступен, цифровую часть закончить, физическую отметить PARTIAL. Не выдавать рендер за физическую проверку.

### F. Тексты и производительность

- Разобрать доступные результаты Старожила 006–007 и pass-*; каждую находку принять, отклонить с причиной или перенести.
- Проверить фактическое «было» перед заменой; редактура не меняет нагрузки, возраст, сроки и нормативы без решения владельца.
- Проверить формы единственного/множественного числа, единицы, согласование «изделие/изделия», подписи рисунков и таблиц.
- Сделать замеры C112: открытие документации и план 50 позиций — цель < 1 с; пакетный выпуск 50 позиций — < 10 с.
- Для каждого замера указать среду, объём данных, холодный/тёплый запуск, минимум 3 повтора, медиану и максимум.
- Отдельно замерить сборку PDF и размер скачивания. Не скрывать задержку красивым индикатором.
- Изменять производительность только после измерения узкого места. Корректность и сохранность данных важнее целевой цифры.

## 5. Безопасность и приёмка

- Стенд и прод: вход/чтение только через datacore-access у координатора, без чтения секретов. Solo запрашивает необходимые обезличенные данные.
- Запись тестовых сценариев — только в изолированном контуре; e2e только datacore-test. Не менять живые записи ради проверки.
- Правки данных владельца оформить планом. Нужное действие пользователя — существующая кнопка пульта либо отдельная проверенная кнопка и todo по правилам пульта.
- Не менять публичные маршруты, префиксы ключей, пагинацию, общие схемы CRM и семантику существующих ответов.
- Использовать datacore-design для UI, datacore-verify для проверок, datacore-docs-sync для документов, pdf для работы с PDF.
- Матрица UI: 390/1024/1600/2560, светлая/тёмная; также действующая промежуточная тема. Подробность согласно UI-ACCEPTANCE.
- Фикстуры: готовое изделие, один пробел, новое пустое, 3201, сборное 3215, длинный паспорт, заказ 50 позиций, отменённая позиция.
- Проверки с подменой API доказывают вид; сохранение/выпуск проверяются отдельно с настоящим API тестового контура.
- Детерминированный исправленный дефект закрепить тестом поведения. Не писать тесты, которые проверяют только наличие строки в коде.
- Полный PASS: нет открытых дефектов сохранения, выпуска, номера, содержания или печати; матрица пройдена; независимая приёмка получена.
- Отсутствие принтера, PDM или необходимых данных не маскировать: отдельный PARTIAL и точное оставшееся действие.
