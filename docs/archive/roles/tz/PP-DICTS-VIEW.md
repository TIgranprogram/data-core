# ПВ2. Справочники паспортов — понятные карточки и грамотные тексты (замечания пользователя 2026-10-25)

## Что сказал пользователь
1. В карточке записи сверху — то, что менеджер меняет часто (описание, мера, текст, название); внизу — редкое.
2. «Код» — непонятно, зачем его менять и что сломается. Коды, списки кодов через запятую («Элементы и материалы (коды)», «Норматив (код)», «Обязательные поля», «Поля категории»…) — вынести вниз в отдельный блок, понятно назвать, объяснить одной фразой.
3. В таблице справочника — без служебных столбцов (коды и т. п.); менеджер видит название и главное.
4. «Нормативы»: в списке — короткое обозначение («ГОСТ Р 57538-2017»), полное наименование — в карточке.
5. Тексты справочников проверить и дополнить: пустые — заполнить; лучшие универсальные формулировки; грамотно, как юрист, защищают компанию, но без нагромождения.

## Решение координатора
- **Код записи не меняется после создания** (на него ссылаются тексты, изделия, паспорта): сервер — 400 «Код нельзя менять: на него ссылаются …» при PATCH с другим `code`; экран — поле только для чтения у существующей записи. У новой записи код можно не вводить: сервер делает его из названия (латиница, `_`, верхний регистр, уникальный в справочнике).
- **Поле описания** (`dicts.defs.ts` поля справочника) получает необязательные признаки:
  - `tech: true` — служебное: не столбец таблицы; в карточке — внизу, в свёрнутом блоке «Для настройки (менять редко)», видят все, правят те же роли; у блока подпись одной фразой «Коды связывают записи между собой — меняйте, только если понимаете, на что они ссылаются».
  - Порядок полей в описании = порядок в карточке: частое — первым.
- Подсказки (`hint`) у кодовых полей переписать человеческими словами: что это и где используется (например «Элементы и материалы, к которым относится дефект — выберите из списка»). Где можно — вместо строки кодов выбор из списка записей (как галочки категорий `ui/cat-chips.js`): **сделать для `passportDefects.applies`, `passportMaterials.defects`, `passportCategories.standards`, `passportElements.standard`, `passportSortament.material`** — список названий, хранится по-прежнему строка кодов через запятую (контракт данных не меняется).
- «Нормативы»: `name` — короткое обозначение, `title` — полное наименование; если сейчас в `name` длинное — скрипт данных (см. п. тексты).

## Контракт (backend ↔ frontend)
- `GET /dicts/:key` → в `fields[]` у поля появляются `tech?: boolean`, `ref?: { dict: string }` (выбор из записей справочника `dict`, значение — коды через запятую; для одиночного — `multiple:false`), `lockAfterCreate?: boolean` (у `code`).
- Столбцы таблицы (`columns`) — без `tech`-полей.
- PATCH с изменённым `code` у существующей → 400; POST без `code` → сервер создаёт.
