# ТЗ МИ — материалы изделия таблицей, текст «изготовлено из…» собирается сам

**Зачем (словами пользователя, 2026-10-23):** сортамент, детали и покрытие пишут руками с ошибками, в изделии этих данных нет — каждый паспорт заново. Полное ТЗ (хранение, справочники, ввод, сборка текста, старые данные, печать) — `docs/TASKS.md` «Фаза МИ», пункты 1–6; здесь — решения и порядок.

**Роли:** хранитель данных ☐ (МИ.1 список) · backend ☐ (МИ.1 справочники, МИ.2, МИ.3) · frontend ☐ (МИ.2 таблица, МИ.4, МИ.5) · qa ☐ (МИ.6) · координатор — `--apply` на проде, выкладка

## Решения пользователя (2026-10-24)
- **ТЭ-4:** размеры сечений печатать. Нет размеров у строки — фраза без размеров (никаких пустых «∅×», «толщиной мм»).
- **Выпущенные паспорта не трогать** (их снимок текста печатается как был).
- **МИ.1:** справочники на проде пополнить можно — **только добавление**, бэкап до. Сначала список через хранителя данных: дубли разного написания (∅33,5 = ∅33.5, регистр, «труба» / «труба стальная», ё/е, пробелы, «х»/«×») — одно написание; чистый список показать пользователю → только после «да» `--apply`.
- Хранение — новое поле `products.materialsSpec` (только data-core; `products` общая с kppdf — схемы CRM не менять): `{ rows: [{ materialId, sizes: string[], partIds: string[] }], coatingId? }`. Паспорт берёт из изделия, в паспорте — снимок с правкой.

## Порядок
1. **МИ.1a — хранитель данных:** скрипт `backend/scripts/data-mi-dicts.js` (план по умолчанию, `--apply` — только запись новых значений; повторный запуск ничего не дублирует). Источник: тексты паспортов (`productpassports` — `materials`, `textSnapshot`), справочник «Материалы и покрытия», «Состав изделия». Итог — три чистых списка (Материалы/покрытия — дополнение с формами в родительном падеже ед./мн. и шаблоном размера; Сортамент по материалу; Части изделия) + таблица «какие написания склеены в какое». Работать **на копии** (стенд `datacoreqa` или временная БД), прод — не трогать.
2. **МИ.1b, МИ.2, МИ.3 — backend:** справочники «Сортамент» и «Части изделия» (группа «Паспорта», правят директор и админ, «Используется», запрет удаления — как у остальных), поля в «Материалах и покрытиях» (тип, формы ед./мн., шаблон размера); `materialsSpec` в `/showcase` (POST/PATCH/GET), «Взять из состава»; одна функция сборки текста (сервер, юнит: объединение размеров одного материала через «и»/запятую, части без дублей, падежи, покрытие, пустая таблица, строка без размеров). Сборка текста используется при печати только для невыпущенных паспортов.
3. **МИ.2 (таблица), МИ.4, МИ.5 — frontend:** таблица в карточке изделия и в форме паспорта (правая панель, компонент как «Комплектность»); предпросмотр текста той же логикой; «Собрать заново», ручная правка не перетирается; «Сохранить в справочник?» без дублей.
4. **МИ.6 — qa:** изделие → таблица → паспорт → PDF; старый (выпущенный) паспорт печатается как был; 375 px; доки PASSPORTS-V2, PRODUCT, DESIGN §8.

## Файлы

## Нельзя
- Менять выпущенные паспорта и схему CRM в `products`; писать на прод (кроме координатора и только после «да»); массовый разбор старых текстов без «да».
