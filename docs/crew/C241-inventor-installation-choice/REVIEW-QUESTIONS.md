# Адресные вопросы к приёмке C241

1. Импорт exactID mismatch пропускает весь существующий экземпляр. Последующие дваGET/getPresentation/syncDraft не должны подложить новый productdefault/его монтажную схему в старый паспорт.
2. `_id` не доказывает, что объект уже сохранён: create() генерирует ObjectId доfromProductDiff. Для разделения existingread/newcreate выбран явный неперсистентный контекст вызова, без нового поля наследования.
3. **Не расширять обязательность установки на все категории.** Некоторые обычные паспорта/шаблоны могут не требовать installationTypeId. Guard отсутствующего ID применим лишь в действительно применимом монтажном контексте; отрицательный контроль штатной категории без установки обязателен. Нельзя побочным исправлением заморозить productdiff у всех старых черновиков.
4. Valid собственный способ, отличающийся от нового изделия, не превращается в неизвестный: старыйснимок/изображения/номер/PDF сохраняются. Unknown/missing применимый способ не достраивается первым значением справочника; причина готовности объяснима.
5. Проверить все затронутые caller paths и регрессии, сохранить public create/template semantics. Полный unit/e2e нужен после итоговой дельты; текущий адресный прогон не заменяет независимую архитектурную приёмку.

Это список координатора для проверки, не дополнительное одобрение общего рефакторинга паспортов.
