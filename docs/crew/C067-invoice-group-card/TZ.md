# ТЗ C067 — карточка счёта на доске заявок: крупнее, действия счёта на ней (2026-11-10)

**Класс:** M · **Агентов:** 1 исполнитель (frontend) + дизайнер после · **Проверки:** `node --input-type=module --check`, `node backend/scripts/design-lint.mjs` (0 строк с табом), `npx jest src/pwa-guards`, skill `datacore-design`. **Язык менеджера.** Не коммитить, не выкладывать, backend/src не трогать.

## Слова пользователя
«Один счёт оплачиваем — у тебя в каждой позиции кнопка «Счёт оплачен». Сделай одну на счёт. Шапку счёта, карточку — чуть побольше, кнопки, которые касаются счёта, туда нормально выложи. Красиво.» Ещё: после «Счёт оплачен» счёт не переходил в «Оплачено» — счёт был черновиком (оплатить можно только выставленный; два шага путают).

## Где
- Карточка группы-счёта: `backend/pwa/ui/kit/board.js` `groupCard` (~строки 176–215), стили `ui/kit/kit.css` `.db-order.k-gfold …` (~161–170).

- Команды счёта: `backend/pwa/sections/invoice-workspace-api.js` (`writeInvoice`: issue — PATCH {issue:true}; pay — POST `/supply/invoices/:id/pay`), проверки `assertOperation`. Карточка счёта — `sections/invoice-workspace.js` (кнопки ~345).

## Что сделать
1. Kit `board`: группа может нести действия — `g.actions: [{ label, kind, run }]` (общий механизм, не только для счетов) → ряд кнопок внизу карточки группы (`actions` kit), клик по кнопке не раскрывает/сворачивает группу. Карточка группы — чуть крупнее: № счёта крупнее и переносится (уже есть перенос), поставщик и дата отдельной строкой, сумма и «позиций N» заметнее. Только эталоны kit; новые классы — в kit.css. Витрина `sections/kit.js` + DESIGN.md — если меняется эталон.
2. `requests.js` группа-счёт (есть `r.invoiceId`): действия по этапу позиций группы:
   - позиции в «В работе» (ordered, не оплачены) → «Счёт оплачен» (primary): если счёт черновик — сначала выставить (issue), затем оплатить (pay); ошибка сервера (нет №/даты/суммы/«Нашей компании», сумма не сходится) — toast с текстом сервера и предложение открыть счёт;
   - «Открыть счёт» (ghost) — всегда;
   - оплачено, не принято → «Принять» (открывает карточку счёта на приёмке, как сейчас у позиции).
   Подтверждение перед оплатой (confirmDlg: «Отметить счёт № … оплаченным? Сумма …»). После — `ctx.changed()`/обновление доски, счёт переезжает в «Оплачено».
3. У позиции, которая входит в счёт, шаг «Счёт оплачен» не показывать (он на карточке счёта). Позиции без счёта — как сейчас.
4. Справку «?» (help-flow-data.js) — поправить, если там описано «Счёт оплачен» у позиции.
