# C233 — создание заказчика и доставка договора

Реализовано в зоне tooling, без изменений backend/API и без обращений к рабочему сайту.

- Анализ подтверждённого договора допускает отсутствующего заказчика: `parties.pendingCustomer={name,inn}`. Наша компания обязана существовать. Анализ и подготовка договоров не выполняют POST.
- Подтверждение отправки защищает `pendingCustomer` как часть `parties` в `salesProof`. Перед фактической загрузкой повторно ищется точный ИНН; отсутствующий заказчик создаётся штатным `POST /organizations` с ролью customer.
- После создания, конфликта или потерянного ответа выполняется повторное чтение. Только единственная живая карточка с точным ИНН, корректным ID и без признака нашей компании допускается к привязке. Дубли и видимая удалённая карточка блокируют запись.
- API организаций скрывает корзину. Если скрытая удалённая карточка занимает уникальный ИНН, сервер отклонит создание; пустой повторный поиск приводит к остановке. Автоматического восстановления и обхода unique нет.
- Состояние отправки сохраняется до создания заказчика; полученный ID сохраняется в `salesDelivery` до загрузки оригинала. Подтверждённый черновик остаётся неизменным, повтор не становится ложным VERSION.
- Используется прежняя доставка: оригинал по SHA, `/salesorders` как договор, исходные строки manual без productId, повторное чтение карточки и оригинала. `productionAssignment='unassigned'`; производственные заказы не создаются.
- Исходящий счёт определяется по нашей компании даже до заведения покупателя и при ошибке строки. Доставка исходящих счетов не добавлена: они остаются на сверке для комплекта договора.

Проверка: `node --test tools/document-intake/analysis.test.mjs tools/document-intake/intake.test.mjs tools/document-intake/customer-creation.test.mjs` — **64/64 PASS**, exit 0.

Новые девять тестов: analyze/prepare без записи; два договора одного нового заказчика; повтор без дублей; потерянный ответ создания и параллельный конфликт; продолжение после записи файла/шапки; заказчик появился после prepare; удалённый/дубли/наша компания; неверный ИНН; отсутствие нашей компании; исходящий счёт без покупателя. Проверяется manual, отсутствие производственного заказа и SHA оригинала.

Изменённые файлы: `tools/document-intake/api.mjs`, `analysis.mjs`, `delivery.mjs`, новый `customer-creation.test.mjs`. Архитектурная приёмка и реальный повтор пачки — координатором. Коммит/запись на прод не выполнялись.
