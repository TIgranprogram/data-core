# C242 — структурный склад без миграции остатков

Вердикт: **можно по этапам**, класс XL из-за общих с CRM материалов и возможной последующей нормализации данных. На первом этапе постоянных новых полей/коллекций **не требуется**: существующих materials.dimensions/assortment/materialGrade/unit и storageitems достаточно для честной проекции и сортировки. Достоверный учёт физических кусков отсутствует; не компенсировать это вычисленными «фактами».

## Неприкосновенные границы

- `materials`/`storageitems` общие с CRM: единицы, quantity/reservedQty/free/minQuantity, движения/брони и связи не менять ради отображения. Без drop/merge/массовой перезаписи или автоматической смены unit. Рабочие API пути и `{items,total,page,limit}` сохраняются.
- Нынешний адресный снимок:503безzoneId,571в объединении4зон; дополнительные68нулевых металлических позиций не потеряны, а скрываются прежней общей проекцией. Зонные таблицы обязаны сохранять их; основной held-список по-прежнему может показывать только наличие. Деревообработка сейчас0 — проверка пустоты не заменяет заполненную приёмку на копии.
- Сохранять warehouse/category scope, mobile/рабочие ограничения и C240 readonly режимы. Никакие новые фильтры/сортировки не расширяют область данных. Не запускать новые stock/page редакторы в обход guards.

## Минимальная совместимая модель

1. Существующие `dims` аддитивно расширить height/depth из уже поддержанного массива dimensions, в мм. Прочие поля вернуть как прежде. `mergeDims` обязан сохранять нетронутые оси, их isImmutable и неизвестные расширения массива; частичная правка длины не должна стереть высоту/глубину или снять immutable других размеров.
2. Для показа/порядка добавить чистую read-only projection `sectionProfile` (имя зафиксировать в ТЗ до кода): `{shape:rect|round|unknown, widthMm?,heightMm?,diameterMm?,wallMm?,label,state:complete|incomplete|conflict|unknown,source:dimensions|assortment|mixed}`. Не записывать её в materials. При наличии противоречия structured↔строгоеassortment показать conflict и исходный текст; не выбирать молча «более красивое» значение.
3. Парсер — только ограниченное сечение из assortment для распознанной трубы: `(B,H,t)` или `(D,t)`, десятичная запятая, ×/x/х/*, Ø/⌀ и явный префикс типа. Длины, ГОСТ, марки, номер изделия из name не участвуют. Профиль40×20безстенки и40×1,5с неизвестной стороной — incomplete/conflict, не достраивать квадрат. B/H местами не менять. AISI и материал не угадывать из общего «Нержавеющая сталь»; washednull не превращать в false.
4. `quantity` всегда в исходном unit. Для трубы lengthMm — длина единицы, totalLengthM — только если unit=м либо unit=шт с доказанной длиной; выводить это явно как проекцию, не менять ledger. **Физические «целые трубы, шт» не выводить даже из целого quantity/(length/1000) без подтверждённой однородности.** Куски/неизвестная длина → «требует пересчёта»/прочерк. При необходимости аналитический эквивалент подписывать именно эквивалентом, не физическим количеством; для первого выпуска лучше не показывать его.
5. Отдельный piecesCount и новый учёт партий/кусков сейчас не вводить. Если владелец потребует достоверный физический учёт разных длин — отдельное ТЗ с приходом/списанием/бронями/CRM, не фоновое расширение C242. Листовой обрезокunitшт остаётся вшт, не конвертируется в целые листы; дерево вм/м²/шт сохраняет свои единицы.

6. Разрешить в ITEM_SORT адресные новые ключи `sectionSize`, `thickness`, `width`, `height`, `length`, `diameter` (точный перечень по утверждённым колонкам). Контракт старых sortname/quantity/... не менять. Сечение сравнивается по tuple формы: rect(B,H,t), round(D,t); формы группируются фиксированно, не сравнивать diameter с шириной как одну ось. Листы(t,W,L), дерево явно подписаннымиW/H/L.
7. Порядок: областьдоступа+зона+поиск/фасеты/статус → числовая сортировка **всего** набора → skip/limit → enrichment страницы. Unknown/conflict/incomplete идут в конец и приasc,и приdesc; ties фиксировать name→materialId. Ноль не подставлять вместо неизвестного. Кэшированные общие rows не мутировать.
8. Для размерных sort отключить attentionRank regrouping приpriority1: выбранный размерный порядок имеет приоритет. Старый name+priority1 сохранить. Объяснить это в коде/справке, проверить export тем же sort/filter/zone. Новый default для трубного контекстаsectionSizeasc; основной смешанный склад может сохранитьname, явный ?sort=name уважать, preferences не очищать.
9. Убрать GETlimit10000 как обещание полноты. Рабочие трубы/листы переводить на серверно сортируемые страницы/дозагрузку с total и zoneId, по аналогииwood. Если сохраняется сеточное представление, нельзя локально пересортировать одну страницу: нужен согласованный серверный tuple для всех записей и стабильная загрузка. Не делать N+1/полную подкачку всех карточек ради отображения.

## Новое явное уточнение владельца: нулевая номенклатура

Существующую номенклатуру соответствующей таблицы показывать и при quantity=0: строка остаётся видимой, серый статус «Нет в наличии», без ложного удаления/создания дубля. Это уточняет прежний режим основного экрана held: для принятого общего табличного режима должна быть явная полная номенклатура, а старый held=1 остаётся отдельным явно выбранным фильтром наличия; не менять контракт held для других клиентов скрытно. Нулевой остаток не равен «неизвестные размеры», бронь/ожидание поставки отражаются отдельно.

Адресный кейс: найти существующую профильную трубу80×60×3 в правильной зоне/категории поID и исходным параметрам; проверить отображение/место numeric sort доpagination и серый нулевой статус. Если запись существует, новую позицию не создавать. При нескольких совпадениях показать всеID/марку/длину/состояние и коллизию; отсутствие не восполнять предположением. Доступ проверять штатнымAPI черезaccess, не прямойMongo. В матрицуQA добавить все4таблицы снулём, ранее скрытые68ID и известную80×60×3; количества/брони не менять.

## Аддитивные стыки списка и серверного отбора наличия

**Kit — одобрено:** optional `section.list.columnsFor(P)` и `sortFor(P)` — чистые синхронные функции после завершения `await L.query(P)`/loadZones, до fetch и отрисовки. Без этих опций прежний static columns/sortDefault остаётся неизменным. Scope: `ui/kit/list.js`, `list-view.js`, адресные tests и документация section.list; отдельный коммит контракта kit от дельты stock sections.

`columnsFor(P)` возвращает новый массив column descriptors; mount использует собственную копию массива/дескрипторов и применяет прежний money-filter. Не мутировать section.list.columns, объекты соседних mount и общий кэш. После смены контекста перестроить head/rows согласованно. `st().sort = P.sort || L.sortFor?.(P) || L.sortDefault`; явный P.sort имеет прежний приоритет. В load sort сейчас захвачен **до** await query — после await/проверки seq/destroyed его требуется пересчитать перед fetch. Колонки, сорт и query для заголовка/строк/дозагрузки/экспорта должны относиться к одному принятому контексту, stale async ответ не меняет новую таблицу.

Kit-регрессии: старый раздел без опций; два mount одной секции не влияют друг на друга; zone загружается асинхронно до первого выбранного defaultsort; смена зоны/колонок/строк; явный sort не теряется; money-filter; сорт/колонки экспорта совпадают с таблицей; cache/исходный массив не изменены; append не смешивает разные контексты.

**Backend — одобрен exact контракт `GET /stock/items?availability=none|in`:** отсутствие параметра — все допустимые quantity; none — quantity===0, in — quantity>0, независимо от reserved/free. Любое явно переданное другое значение, включая пустое, даёт400; frontend снятие фильтра опускает ключ. Не вводить held=0/новое значение status и не менять held=1: фильтры сочетаются по AND, поэтому held=1+availability=none возвращает пустой набор, а не снимает наличие скрытно.

Scope адресного дополнения backend: `stock-search.service.ts::listItems` и `stock.controller.ts` ApiQuery/контракт, тесты в существующем stock suite. Валидировать query до тяжёлого чтения; отбор availability выполнять после scope/прочих фильтров, но **до** sort/skip/limit/enrichment. Не мутировать cached rows; новый ключ кэша не нужен, если фильтр применяется после общего cached набора. Существующие counts остаются до status/availability как счётчики полного доступного набора; items/total относятся к отфильтрованному availability. Ответ совместим, новые права/схемы не нужны. Backend-регрессии: zero/in/default, fullyreserved positive входит вin, свободно0 не означаетnone, invalid/empty400, ANDstatus/search/zone/held, границаpages и числовойsort, total/counts, no-ledger/no-cache-mutation и scopes. Новый UI не фильтрует нули локально после страницы. Это дополнение к frozen stageB, а не повод переписывать его сортировки/проекции.

## Полная выгрузка склада: снять скрытое ограничение10000

Одобрен минимальный optional `exportList({...,maxRows=10000,signal?,onProgress?},btn)` и `section.list.exportLimit` с передачей kit→maxRows. Для склада exportLimit=Infinity; прочие разделы сохраняют default10000 с явным предупреждением об ограничении. Новый произвольный скрытый cap для склада не вводить.

Полный режим экспортирует последовательными GETстраницами по500 с одним снимком columns/query/sort. Первый ответ задаёт целый неотрицательный total; последующие обязаны ему соответствовать. Проверять массивitems, корректный page/limit если отданы, уникальность ID(materialId/id), рост обработанного набора и ожидаемую последнюю страницу. Повторная/пустая/преждевременно короткая страница, дубльID или изменениеtotal — понятная ошибка **без скачивания частичного XLSX и без сообщения «всё выгружено»**. Не прекращать цикл только потому, что страница короче500, если объявленныйtotal ещё не достигнут. Получено ровноtotal — успех, порядок совпадает с сервернымsort.

Чтобы не удваивать память, каждую страницу сразу преобразовывать в массив значений ячеек дляXLSX, не копить одновременно полныеAPIrows и out; seenIDs хранит толькоIDs. Между страницами отдавать управлениеUI и показывать прогресс. signal проверять до/послеGET, передпостроением/скачиванием; отмена не создаётфайл. Существующий core/api.js использует собственныйAbortController, поэтому без отдельного согласования его не переписывать: допустима честная cooperativecancel, текущийGET закончится/timeout, следующие не стартуют. Kit показывает отдельное «Отменить выгрузку» на времяоперации и восстанавливает исходныеcontrols послеуспеха/ошибки/отмены.

При превышенииподдержанногоформата или невозможности сформироватьполныйфайл — явный отказ «Полная выгрузка не сформирована» безчастичногоуспеха.
