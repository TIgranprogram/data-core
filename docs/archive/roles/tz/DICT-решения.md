# DICT — решения совещания (analyst + architect + designer, 2026-10-25) — дополняют и ПЕРЕБИВАЮТ tz/DICT.md

## Контракт API (общий для backend и frontend)
- `GET /dicts/:key` — список БЕЗ `used` и `related` (кроме `passportPhrases`: его `used` оставить, считает кэшируемый ppUsage — иначе дерево «Тексты паспорта» теряет «используется»). `get()` не вызывает `list()`.
- Метаданные справочника (в ответе `GET /dicts` / описании): `sections: string[]` (русские названия разделов приложения: «Остатки», «Заявки», «Продукция», «Паспорта», «Деньги»…), `locked?: [{code|id, reason}]` — встроенные значения (удалять нельзя).
- НОВОЕ `GET /dicts/:key/:id/usage` (`@Roles('user')`, объявить РАНЬШЕ общего `:key/:id`) → `{ busy: boolean, sections: string[], tracked: boolean }` (`tracked:false` — для справочников без учёта связи, напр. «Услуги»: удаление свободно). Тяжёлый count не нужен: флаг `busy` — `countDocuments(..., {limit:1})`.
- `PATCH :key/:id` — если у справочника `refBy: 'name'` (строковая связь: persons, units, colors, metalAssortments, steelGrades, paymentForms, invoiceTypes, writeOffReasons, passportSortament) и название реально изменилось (сравнение через norm) → СНАЧАЛА каскад по данным (updateMany, якорный регэксп `^…$` как sameRe), ПОТОМ `$set` имени; сначала `checkDuplicate`; в аудит `dict.renamed {from,to,moved}`. Ответ: обычный + `moved: number`. Для `refBy:'id'` каскад ЗАПРЕЩЁН на уровне кода. Сотрудники: каскад только при смене имени/фамилии (не должности/телефона), поле `supplyrequests.requestedBy`. Размеры материалов: `products.materialsSpec.rows.sizes` через arrayFilters — отдельный тест. Причины списания: задать `usage {coll:'stockmovements', field:'reason'}`.
- `DELETE` занятого значения — только admin (проверка роли в сервисе → 403 «Удаление занятого значения доступно администратору»); менеджер может удалить только свободное. Занятое админ удаляет через `POST :key/:id/merge` (замена: ссылки переносятся на выбранное значение), в аудит `movedIds` (≤500). Встроенные (`locked`) удалять нельзя ни при каких ролях.
- Индексы не нужны (разовое действие). Откат — повторный PATCH со старым названием (идемпотентен). Проверка на тестовой БД; на прод — после бэкапа.

## Вид (designer)
- Группы меню: «Склад и продукция» · «Люди и работа» · «Заявки и оплата» · «Документы (паспорта)» (свёрнута, если активный справочник не в ней; ▸/▾) · «Контрагенты» (ссылка). h1 «Справочники», подзаголовок «Здесь меняются значения выпадающих списков: добавить, исправить, удалить. Изменение сразу видно во всех разделах».
- Правая часть: h3 название; `.hint` «Применяется в: <sections>»; справа поиск «Найти значение…», «Найти в данных…», «+ Добавить» (primary). Фильтр «Все · Дубли» только если дубли есть.
- Список: строка = название · описание (серое, `.md-hide`) · две кнопки `.btn-ghost.btn-sm` «Изменить» и «Удалить». Колонки «Используется» и стрелки раскрытия НЕТ, `relatedBox`/`card.extra`/`.dict-rel*` удалить. Встроенные: вместо «Удалить» значок 🔒 + «Встроено в программу». На 390: строка столбиком, кнопки ≥44px, навигация — один select (optgroup).
- Правка (правая панель): «Изменить: <название>» / «Новое значение»; сверху `.muted` «Используется в: …» или «Нигде не используется» (из /usage); при смене названия у занятого — `.field .warn` «Новое название сменится везде: <разделы>.»; «Сохранить» (busyBtn «Сохраняю…»), «Отмена»; «Объединить с…» — вторичная; поле `code` у нового не показывать.
- Удаление свободного (confirmDlg): «Удалить «X»?» / «Значение уйдёт в корзину. Вернуть можно из корзины.» / «Удалить» (danger) «Отмена».
- Удаление занятого (modal): заголовок ««X» используется»; «Используется в: …. Чтобы удалить, выберите, чем заменить: везде, где стоит «X», появится новое значение.»; select «Заменить на» (первый пункт «— выберите значение —»); кнопки «Заменить и удалить» (primary, выключена пока не выбрано), «Только переименовать» (закрывает и открывает правку), «Отмена»; `.warn` «Это нельзя отменить кнопкой». Не-админу вместо «Заменить и удалить» серый текст «Удаление занятого значения доступно администратору».
- Пусто: «Здесь пока ничего нет.» + «Нажмите «+ Добавить» или «Найти в данных…» — возьмём то, что уже встречается в заявках и на складе.» Не найдено: «Ничего не найдено по «…». Попробуйте другое слово.» Тосты: «Значение удалено», «Заменено: обновлено записей — N», «Название изменено везде».
