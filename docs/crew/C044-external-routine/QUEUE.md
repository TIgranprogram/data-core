# C044 — очередь больших рутинных задач для внешнего ИИ (DeepSeek и др.)

Исполнитель берёт **первую** задачу со статусом `[ ]`, выполняет её по её ТЗ, ставит `[~]` (сделано, ждёт приёмки координатора) и отчитывается. Коммит, дизайнер, выкладка — координатор (Claude).

## Общие правила (для всех задач)
1. Перед действием прочитать и принять на себя скиллы проекта (это обычные файлы, читать целиком):
   - `.claude/skills/datacore-design/SKILL.md` — если задача меняет вид (`backend/pwa`, `backend/admin`);
   - `.claude/skills/datacore-verify/SKILL.md` — всегда (как проверять);
   - `.claude/skills/datacore-docs-sync/SKILL.md` — всегда (какие доки обновить в конце);
   - роль: `.claude/agents/datacore-frontend.md` (экран) или `.claude/agents/datacore-backend.md` (сервер) — что можно и нельзя.
2. Законы: `AGENTS.md` (разделы «Жёсткие правила», «Известные ловушки»), `docs/CANON.md` §2 (вид). Только эталоны kit (`backend/pwa/ui/kit/`), новых компонентов не придумывать; нужен вариант эталона — сначала kit + витрина `#kit`.
3. Нельзя: коммитить, пушить, ходить на прод/стенд, читать `.env`, `deploy/synology/config.env`, `CREDENTIALS.md`, ключи; трогать `docs/QUESTIONS.md`, `docs/roles/maps/*`, запретную зону pwa `requests.js`, `orders.js`, `money*`, `kp*`, `offers*` (если ТЗ задачи не разрешает явно); менять существующие поля общих с CRM коллекций; `git add -A`.
4. Проверки перед отчётом (из `backend/`): `npx tsc --noEmit` = 0; `npx jest --silent` зелёный; для pwa — `node --input-type=module --check < файл` по каждому изменённому файлу (НЕ `node --check`) и `node tools/design-lint.mjs` без новых нарушений (из корня); итог — `tools/dc.cmd check`.
5. Файлы длиннее 400 строк хук не пропустит — выносить в новый модуль.
6. Отчёт — `docs/crew/C044-external-routine/REPORT-<код>.md`: что сделано (файл:строки), итоги проверок числами, допущения, что не сделано. ≤ 25 строк.
