**Цель.** Новый счёт поставщика всегда запись `supplyinvoices`. Заявки строк получают `invoiceId`. Текст `invoiceNo` остаётся номером на заявке.

**Сделать**

1. Спрятать вход «Счёт без заявок» (`requests.js:263` → `of=invoice`). Форму `invoice.js` не удалять в этом шаге: старые черновики экрана не ломать, кнопка не видна.
2. Создание с «вставить из таблицы» перенести на карточку счёта `invoice-workspace.js` (те же поля: поставщик, №, дата, наша компания, строки, «сразу на склад»).
3. «Сразу на склад» вызывает уже существующий `SupplyInvoiceService.receive` (`supply-invoice.service.ts:265`), не пачку голых `POST /supply/requests`.
4. Список «Счета» (`invoices-tab.js`) показывает и старые пачки, у которых есть общий `invoiceNo`, но нет `invoiceId` — строка «без карточки счёта», кнопка «Собрать в счёт» (создаёт `supplyinvoices` и проставляет `invoiceId`). Без кнопки старые заявки не трогать.

**Если** менеджер жмёт «+ Счёт», **то** открывается карточка `supplyinvoices`, а не форма, которая пишет только заявки.
**Если** счёт «Получено — на склад», **то** у каждой строки статус «Получено» и есть приход, повтор той же кнопки не удваивает остаток.
**Если** у старых заявок только текст номера, **то** они видны в списке счетов как «без карточки», деньги по ним не двоятся (календарь уже вычитает строки с `invoiceId` — `finance.service.ts:119`).

**Зависимость:** нет. **Не трогать:** enum статуса заявки.

## Пачка 2. Склад — приход не мимо заявки · P1 · класс M

**Цель.** Остаток растёт либо через `POST /supply/requests/:id/receive`, либо явным «приход без заявки». Открытая заявка на ту же позицию не остаётся висеть.

**Сделать**

1. В `stock-ops.js` операция `in`: если по позиции есть открытая заявка (не `received` / `cancelled`), строка не уходит в `/stock/batch`, пока человек не выбрал заявку или не нажал «Это другая поставка, заявку не закрывать».
2. Выбранная заявка закрывается как сейчас (`stock-ops.js:307`, `partial`, если количество меньше).
3. Подпись истории «Оприходована» / «Оприходовано» заменить на «Принято на склад» (`requests.js:249`, `ui/history.js:16`). Комментарий сервера `supply.service.ts:557` можно оставить служебным.

**Если** по болту есть заявка «Оплачено» и кладовщик жмёт «+ Принять» на эту позицию, **то** без выбора заявки остаток не меняется.
**Если** он отметил «другая поставка», **то** приход пишется движением, заявка остаётся открытой, в движении есть пометка.
**Если** смотрят историю заявки, **то** слово «оприходовать» на экране не встречается.

**Зависимость:** пачка 1 не обязательна. **Не трогать:** формулы остатка и брони в `stock-movements.service.ts` (общая с CRM логика количеств).
