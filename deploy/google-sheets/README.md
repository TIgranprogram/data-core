# Google-таблицы → база

## Основной способ: сервер читает таблицы сам (с 2026-10-18)

В таблицы **ничего ставить не нужно**. Сервер раз в 10 минут (и по кнопке «🔄 Синхронизировать сейчас» в админке → «Google-таблицы») читает листы через сервисный аккаунт Google — «робота» с правом только на чтение — и переносит их в базу без дублей.

| Лист | Куда в базе | Как узнаётся строка |
|--|--|--|
| Снабжение | `/api/apps/supply/requests` | по «№» |
| Реестр счетов | `/api/apps/supply/invoices` | по «№» |
| Склад (заголовок в 6-й строке) | `/api/apps/warehouse/items` | по «Наименование ТМЦ» (без учёта регистра) |
| Движение склада | `/api/apps/warehouse/movements` (поля — транслитом заголовков) | по содержимому строки |

Правила:
- Записи, созданные в приложении «Снабжение / Склад», синхронизация не трогает. Позиция склада, заведённая в приложении, связывается со строкой таблицы с тем же наименованием (фото сохраняются).
- Строку поменяли в таблице → в базе меняются только поля из колонок листа. Строку удалили → запись мягко удаляется. Пропало больше 20% строк (лист очистили) — удаление не выполняется, в итоге будет ⚠️.
- Не меняйте «№» у существующей заявки и наименование позиции склада: для базы это станет новая запись (старая удалится).
- Колонка «Фото» не переносится (Google не отдаёт картинки ячеек).

### Настройка (один раз)

1. **Google Cloud** (под владельцем таблиц):
   - https://console.cloud.google.com/projectcreate → проект `datacore`;
   - https://console.cloud.google.com/apis/library/sheets.googleapis.com → «Включить»;
   - https://console.cloud.google.com/iam-admin/serviceaccounts/create → `datacore-sheets`, роли не нужны;
   - аккаунт → «Ключи» → «Добавить ключ» → JSON → файл переименовать в `google-sa.json`.
2. **Ключ на сервер:** файл положить в `D:data-coresecretsgoogle-sa.json` (папка в .gitignore); агент копирует его на VM в `/opt/data-core/secrets/` (контейнер видит как `/app/secrets`, только чтение). Перезапуск не нужен.
3. **Доступ:** каждой таблицей поделиться с адресом робота (`…@….iam.gserviceaccount.com`, виден в админке → «Google-таблицы») — роль «Читатель», без уведомления.
4. **Подключить:** админка → «Google-таблицы» → вставить ссылку на таблицу → «Подключить» → «Синхронизировать сейчас». Итог по каждому листу виден там же.

Код: `backend/src/modules/sheets-sync/` (карта листов — `sheets-sync.mapping.ts`).

## Запасной способ: скрипт Apps Script в таблице

Используется, только если нужен режим «база → таблица» (листы-зеркала) — сервер пока только читает таблицы.

> ⚠️ **Не включайте оба способа для одной таблицы в режиме «таблица → база»**: скрипт и сервер узнают строки по-разному, получатся дубли. Если таблица подключена в админке, скрипт в ней — только в режиме «база → таблица».

Скрипт [`datacore-sync.gs`](datacore-sync.gs) раз в 10 минут (и по кнопке) переносит строки листов в единую базу. Два режима (меню **🔗 База данных**):

- **Таблица → база** (по умолчанию): таблица — главное место ввода, база получает актуальную копию **без дублей**.
- **База → таблица** (после перехода на веб-приложение, см. [../supply-app/README.md](../supply-app/README.md)): скрипт пишет листы-зеркала «Снабжение (база)», «Склад (база)» (остатки из движений, фото картинкой) и «Движение склада (база)». Исходные листы не трогаются и в базу не уходят. Листы-зеркала перезаписываются целиком — правки в них не сохраняются.

Ниже — режим «таблица → база».

| Лист | Куда в базе | Ключ строки |
|--|--|--|
| Снабжение | `/api/apps/supply/requests` | скрытая колонка «ID базы» |
| Реестр счетов | `/api/apps/supply/invoices` | то же |
| Склад (заголовок в 6-й строке) | `/api/apps/warehouse/items` | то же |
| Движение склада | `/api/apps/warehouse/movements` (поля — по заголовкам, транслитом) | то же |

Листы, которых нет в таблице, пропускаются — один и тот же скрипт ставится в каждую таблицу.

## Установка (5 минут, один раз на каждую таблицу)

> Через Gemini в таблице: чек-лист и готовые промпты — [GEMINI.md](GEMINI.md).

1. **Ключ.** Админка `https://kppdf-crm.ru/db/admin/` → «API-ключи» → «Выдать ключ»: метка `google-sheets-<таблица>`, права **«Чтение и запись»**, приложения `supply, warehouse`, срок — 90 дней или без срока. Скопируйте ключ (показывается один раз).
2. **Скрипт.** В таблице: Расширения → Apps Script → «+» → Скрипт → назовите `datacore-sync` → вставьте весь текст `datacore-sync.gs` → 💾.
3. **Ключ в код.** В самом верху скрипта строка `const DATACORE_KEY_HERE = '';` — вставьте ключ между кавычками → 💾.
4. **Запуск.** Вверху редактора выберите функцию `datacoreSetup` → ▶ Выполнить → разрешите доступ («Дополнительно → Перейти», если Google предупредит). Окон не будет: внизу откроется «Журнал выполнения» с итогом — например `Снабжение: строк 157, создано 157`.
5. Обновите вкладку таблицы — появится меню **🔗 База данных**; дальше синхронизация сама, каждые 10 минут.

Ваши существующие скрипты и меню (⚡ Снабжение, 📦 Складской учет) не затрагиваются: скрипт не объявляет `onOpen`/`onEdit`, его меню ставится отдельным триггером.

## Правила, чтобы всё работало

- **Не трогайте скрытую колонку «ID базы»** (не очищайте, не вписывайте руками). Сортировать, переставлять, копировать строки — можно: скопированная строка получит новый id.
- Пустое «Наименование» — строка не синхронизируется.
- Можно работать параллельно в таблице и в приложении «Снабжение / Склад»: записи, созданные в приложении (заявки, движения склада), скрипт не трогает и не удаляет — в таблице их просто нет (видны в режиме «база → таблица» на листах «… (база)»). Если одну и ту же строку поправили и там, и там — при следующей синхронизации победит таблица.
- Удалили строку → запись мягко удаляется в базе. (Только строки, пришедшие из таблицы.) Если «пропало» больше 20% строк (лист очистили по ошибке) — удаление **не выполняется**, в «Последней синхронизации» будет ⚠️.
- Фото из ячеек Google в базу не переносятся (Google не отдаёт картинки ячеек) — фото будут загружаться в веб-приложении «Снабжение/Склад».
