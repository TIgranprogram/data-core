# C049 — восемь независимых проверок (наблюдение, без правок)

**Класс:** L (только чтение и отчёты) · **Агентов:** 1 (внешняя модель) · **Код не правит.**

**Зачем (пользователь 2026-11-08):** второй независимый взгляд не на бизнес-логику (это C048), а на качество приложения по 8 темам. Проходить темы **по очереди, по чек-листу**, каждую — в свой файл. Координатор потом сверит находки и раздаст правки.

## Общие правила
- Перед стартом прочитать: `AGENTS.md` («Жёсткие правила», «Известные ловушки»), `docs/CANON.md`, `docs/MAP.md` — карту модулей и файлов.
- Нельзя: ходить на прод/стенд, запускать скрипты из `deploy/`, `SRV-ERP/`, читать `.env`, `deploy/synology/config.env`, `CREDENTIALS.md`, ключи; править код и доки (кроме своих отчётов); коммитить. Можно: читать код, запускать локально `npx tsc --noEmit`, `npx jest --silent` (из `backend/`), `node backend/scripts/design-lint.mjs`.
- Каждое наблюдение — место (файл:строка), сценарий «что случится», совет, важность 🔴/🟡/🟢. Без сценария — в «Сомнения».
- Не повторять уже известное: открытые задачи — `docs/TASKS.md` (Grep по теме), решения последних этапов — `docs/crew/C041…C048/`.
- Файл темы — до 80 строк: 1) что проверено (охват), 2) находки таблицей, 3) топ-3 и порядок исправления, 4) сомнения.

## Темы (по порядку; отметить `[x]` здесь же после каждой)
- [x] **1. Сохранность данных.** Удаление и корзина (soft-delete), каскады, массовые правки и «Отменить», импорты (`--apply`), конкурентная правка (`rev`, 409), общие с CRM коллекции (`docs/ARCHITECTURE.md` «Единая база»): где можно потерять или испортить данные. → `T1-data-safety.md`
- [x] **2. Безопасность и права.** RBAC (роли, `@Roles`, `session.can*` в приложении), машинные ключи `kppd_` и их scope, что видно без права на деньги, загрузка файлов, XSS через `innerHTML` в `backend/pwa`, заголовки (`main.ts`). → `T2-security.md`
- [x] **3. Скорость.** Тяжёлые запросы без индексов (сравнить с `backend/scripts/ensure-indexes.js`), N+1 в сервисах, большие ответы без пагинации, кэши, первый экран приложения (сколько запросов и КБ), замеры `ui/kit/list.js` (медленный экран). → `T3-speed.md`
- [x] **4. Надёжность и ошибки.** Что видит пользователь при сбое сети, 500, 409, офлайн (PWA, service worker); глобальные фильтры ошибок; журнал ошибок с сайта (`client-errors`); повтор запросов и идемпотентность. → `T4-reliability.md`
- [x] **5. Единый вид и удобство.** Эталоны kit против самодельных элементов (`docs/DESIGN.md`, `design-lint` baseline), правая панель для ввода, пустые состояния с подсказкой, кликабельное отличается от текста, телефон 390 / 1024 / 1920 по CSS. → `T5-ui-consistency.md`
- [x] **6. Тексты и язык менеджера.** Служебные коды и английские слова на экране, разные слова для одного (`Исполнитель/Рабочий/Сотрудник`), тексты ошибок сервера (понятны ли), помощь «?» (`help-guide-data.js`, `help-flow-data.js`) — совпадает ли с экранами. → `T6-texts.md`
- [x] **7. Архитектура и долг.** Файлы > 400 строк, циклы импортов модулей, дубли логики сервер/клиент, мёртвый код и неиспользуемые эндпоинты, DTO без валидации (ловушка `forbidNonWhitelisted` в `AGENTS.md`), `docs/ARCH-PLAN.md` — что из плана устарело. → `T7-architecture.md`
- [x] **8. Тесты и проверки.** Какие важные цепочки не покрыты юнит/e2e (заказ → работа → отгрузка, склад, деньги, паспорта), хрупкие тесты, что проверяют ворота выкладки (`deploy/synology/preflight.sh`) и что пропускают. → `T8-tests.md`
