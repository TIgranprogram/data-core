## 2. Решения
1. **Отмена заказа с объяснением.** В salesorders.js:192 перед `setStage(...,'cancelled')` — `confirmDlg('Отменить заказ № …?', 'Заказ перейдёт в «Отменён», уйдёт из «В работе». Брони и заявки не удаляются — их снимите отдельно. Вернуть можно сменой этапа.', {okText:'Да, отменить заказ', danger:true})`. Та же защита в перетаскивании на доске (:170, если колонка cancelled появится — сейчас её нет, не добавлять).
2. **Корзина заказов — готово**, добавить только: в тексте удаления (:233) уточнить «Отменённый заказ остаётся в списке; удаление — в корзину». Каскад (заявки/брони удалённого заказа) — не менять, отдельный вопрос К-2.
3. **Пароль для не-админов.** Backend: новый `POST /api/auth/confirm` {password} → `{token: короткоживущий, 120 с}` для текущего пользователя (сверка с хэшем; без записи пароля в лог). DELETE salesorders / `restore` и массовые удаления: если роль ≠ admin — заголовок `X-Confirm-Token` обязателен, иначе 403 «Нужен пароль». Минимум для ТИ-4: заказы, заявки, позиции склада, контрагенты (те же 4 раздела, что в корзине). Frontend: общий `ui/confirm-password.js` (модал с полем пароля), вызывается из ui/card.js:160 и trash.js (восстановление) для не-admin. Admin — без пароля.
4. **Вход в корзину из истории.** В ui/history.js для записей `deleted` — ссылка «В корзине — восстановить» → `go('trash')` (main.js:271); у `restored` ссылки нет. Права: как у корзины.
5. **Excel только admin.** `export: 'admin'` добавить в заказы (salesorders.js, list-блок), продукцию, контрагентов, заявки, доходы/расходы — везде, где есть данные клиентов/денег. Спец-отчёты по месту (spec-import.js:191 «Скачать отчёт») — не трогать (это отчёт пользователя по своей загрузке). Серверная защита: нет отдельного эндпоинта выгрузки — Excel строится в браузере из обычного списка; значит это ограничение интерфейса, не безопасности (честно сказать в QUESTIONS Т-А1).
6. **Счётчики заказов.** Прогнать: число на чипе = число строк после выбора чипа при любых search/priority/companyId. Если `byStage` (service:~93) считается без этих фильтров — привести к одному `filter` (без stage). Хвост и корзина (`deleted=1`) — счётчики считать по deletedAt того же режима.
7. **Откат случайных удалений (ТИ-12).** Всё удалённое — soft-delete (плагин backend/src/database), значит откат = корзина. Дополнительно: в toast «Удалено» «Отменить» уже 10 с (toast.js:20) — достаточно.

## 3. Критерии приёмки
- Если менеджер жмёт «Отменить заказ» — виден диалог с объяснением; «Нет» — этап прежний; «Да» — этап cancelled, toast с «Отменить».
- Если удаляет заказ admin — пароля нет; manager/user — окно пароля; неверный пароль → понятная ошибка, заказ на месте.
- Если запрос DELETE от не-admin без токена (curl) — 403; с токеном — 200 и запись в корзине.
- Если открыть историю заказа и удаление — видна ссылка в корзину; в корзине заказ восстанавливается и снова виден в списке «В работе»/по этапу.
- Если роль не admin — кнопки «⇩ Excel» нет в заказах/заявках/продукции/контрагентах; у admin есть.
- Если выбран чип «В работе» — число на чипе равно «N» в заголовке списка, в т.ч. при поиске и приоритете.
- Юнит: confirm-токен (истёк, чужой, нет пароля); e2e: DELETE salesorders без/с токеном. typecheck+jest зелёные.
