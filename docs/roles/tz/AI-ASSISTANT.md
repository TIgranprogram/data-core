# ИИ-1. Помощник «Рабочего места» — требования и архитектура (аналитик, 2026-10-28)

Пожелание пользователя (27.10): агент-менеджер знает данные, проверяет полноту, подсказывает; принимает документы (счёт, ЗНП Excel, PDF, фото) и раскладывает по местам; спорное — кнопками-вариантами; мини-чат, выбор модели. Вопросы — `docs/QUESTIONS.md` «ИИ-помощник».

## 1. Где живёт
- Модуль `assistant` в нашем backend (`backend/src/modules/assistant/`). Отдельный сервер **не нужен**: вся «думалка» — у Anthropic, VM только шлёт HTTPS-запрос и ждёт (I/O, не CPU). AVX, Mongo 4.4 не мешают.
- Почему не отдельно: инструменты = наши сервисы; в процессе они идут через те же guard'ы/RBAC/MoneyMask/audit без второй авторизации. Отдельный сервер = второй деплой, второй ключ, сеть до VM.
- Когда понадобится отдельный: распознавание сканов локально (OCR) или фоновое наблюдение каждые минуты на много пользователей. Не на этапах 1–3.
- Ключ `ANTHROPIC_API_KEY` — только в `.env` VM; в браузер не уходит; в лог не пишется.
- Длинный ответ — потоковый (SSE) через nginx `/db/`: проверить `proxy_buffering off` для `/db/api/assistant/stream` (правка блока `/db/` — с бэкапом). Иначе — опрос раз в 1 с.
- Новые коллекции (свои, не CRM): `assistantchats` (сообщения, user, модель, токены, $), `assistantactions` (предложенные записи: статус proposed/confirmed/rejected/expired), `assistantusage` (сумма $ за день по пользователю). Общие с CRM коллекции — схемы не трогать.

## 2. Безопасность
- Агент действует **от имени пользователя**: каждый вызов инструмента — с его JWT-контекстом (роль, `appSections`, `canSeeMoney`). Машинный ключ `kppd_` агенту не выдаётся.
- Чтение — свободно в пределах прав. Деньги: ответы инструментов проходят ту же маску, что и в API (MoneyMaskInterceptor-логика в сервисном слое, не только интерцептор — проверить архитектору).
- Запись — **только** через карточку: модель вызывает `propose_*` → сервер сохраняет `assistantactions` и показывает карточку → пользователь жмёт «Подтвердить» → сервер (а не модель) выполняет обычный эндпоинт. У модели нет инструмента, который пишет сразу.
- Карточка живёт 24 ч; повторное нажатие — идемпотентно (ключ = id действия).
- Журнал: audit-плагин пишет как обычно, автор = пользователь, метка `via: assistant`, ссылка на действие.
- Лимит: перед вызовом — проверка `assistantusage`; превышение — «лимит на сегодня исчерпан», только поиск без модели. Opus — только админ.
- Текст документов — недоверенные данные: инструкции внутри файла не исполняются (промпт + запись только через карточку).
- Секреты: инструменты не отдают `users.password*`, ключи, `config.env`; список коллекций — белый, не «любая таблица».

## 3. Инструменты этапа 1–2 (≤10)
| Инструмент | Эндпоинт / сервис | Запись |
|--|--|--|
| `today` | `GET /api/today` | нет |
| `search_counterparties` | `GET /api/counterparties?q=` | нет |
| `search_materials` | `GET /api/materials?q=` + остаток `stock` | нет |
| `list_supply_requests` | `GET /api/supply-requests?status=&q=` | нет |
| `get_sales_order` | `GET /api/sales-orders/:id` | нет |
| `finance_summary` | доходы/расходы, прогноз (`FinanceService`) — только `canSeeMoney` | нет |
| `data_gaps` | проверка полноты: без ИНН, без цены, без категории, просрочки | нет |
| `read_attachment` | файл, загруженный в чат (PDF/картинка/Excel→текст) | нет |
| `propose_supply_request` | карточка → `POST /api/supply-requests` | через карточку |
| `propose_payment` | карточка → доход/расход (счёт к оплате) | через карточку |
Точные пути сверить с `docs/MAP.md`/openapi (архитектор).

## 4. Разбор документа
1. Загрузка в чат (скрепка/перетащить/фото с телефона) → обычный upload, файл хранится у нас.
2. PDF и фото — модели как document/image; Excel (ЗНП) — сервер сам читает в таблицу-текст (библиотека — та же, что в СКЕ).
3. Модель (haiku — разбор; sonnet — сопоставление) определяет тип: счёт / ЗНП / накладная / другое.
4. Сопоставление: поставщик → `search_counterparties` по ИНН, затем названию; строки → `search_materials`.
5. Карточка «Вот что я понял → куда положу»: тип, контрагент (найден / новый), строки с сопоставлением и уверенностью, сумма, куда (заявка / расход).
6. Спорное — кнопки: «Это ООО Ромашка (ИНН …)» / «Другой — выбрать» / «Создать нового»; на строку «Похоже на: А / Б / Не то». Клик → ответ в чат → агент продолжает.
7. «Подтвердить всё» → запись; «Исправить» → правая панель обычной формы с заполненными полями.

Критерии: если ИНН в документе совпал с контрагентом — он выбран без вопроса; если два похожих — кнопки, без записи; если пользователь не нажал — в базе ничего не меняется; если сумма строк ≠ итогу — красная пометка на карточке.

## 5. Вид мини-чата (детали — designer, skill `datacore-design`)
- Кнопка «Помощник» в шапке приложения на всех экранах; открывает **правую панель** (канон: ввод — справа). На телефоне — на весь экран.
- Внутри: лента, поле ввода, скрепка, переключатель «Быстро / Обычно / Сложно», счётчик «сегодня потрачено».
- Контекст экрана: открыт заказ — помощник знает его id («что с этим заказом?»).
- Кнопки-варианты — под сообщением; карточка действия — с «Подтвердить / Исправить / Отмена».
- Без служебных кодов: «Заявка № 12», не ObjectId.

## 6. Этапы
0. Агент `.claude/agents/datacore-data-auditor.md` (sonnet, только чтение через `datacore-access`): отчёт полноты данных прода. Без кода. Даёт список проверок для `data_gaps`.
1. Модуль + чат только чтение: 8 инструментов чтения, лимит, журнал, выбор модели. Класс L.
2. Документы + карточки подтверждения + 2 `propose_*`. Класс XL (запись в общие с CRM коллекции).
3. Подсказки: при открытии «Сегодня» — 3 вывода (кэш раз в день, haiku); наблюдение — ночная проверка `data_gaps`, результат — в колокольчик. Без постоянного опроса.

## 7. Стоимость (5 человек, 22 раб. дня)
Ориентир: 20 вопросов/чел/день, ~8 тыс. токенов входа (с кэшем системного промпта и инструментов −70 %), ~600 выхода; 5 документов/день.
- Всё на sonnet: ≈ 2200 вопросов × ~0,02 $ ≈ 45 $ + документы ≈ 10 $ → **≈ 50–70 $/мес**.
- Разбор на haiku, opus редко: **≈ 30–50 $/мес**. Наблюдение раз в день — +2–5 $.
- Цены моделей 5.5 проверить на странице Anthropic перед запуском; лимит ИИ-2 держит потолок ≈ 110 $/мес.

## 8. Риски
- Галлюцинация записи → закрыто карточкой; сопоставление «не того» материала → уверенность + кнопки.
- Утечка денег роли без `canSeeMoney` → тест e2e: кладовщик спрашивает «сколько заплатили» — нет сумм.
- Промпт-инъекция из PDF → запись только через карточку, белый список.
- Отключение интернета/Anthropic → чат пишет «помощник недоступен», приложение работает.
- Персональные данные уходят в Anthropic → ИИ-6 (решает пользователь).
- SSE через туннель/nginx может буферизоваться → опрос как запасной путь.
