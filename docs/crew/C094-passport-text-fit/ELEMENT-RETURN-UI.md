# C094. Возврат из редактора функционального элемента

Проверка выполнена в отдельном Playwright Chromium на QA :3102. Использована заполненная карточка 3905. Для управляемых гонок и отказов HTTP ответы подменялись только на тестовом маршруте, записи в QA не уходили. Отдельный сценарий с настоящей записью использовал выделенное изделие категории «Благоустройство».

## Настоящее сохранение — PASS

На 375 px открыт штатный редактор справочника. Две строки введены клавишей Enter внутри «Правила пользования». Нажатие «Сохранить и вернуться» выполнило POST справочника с ответом 201 и PUT шаблона с ответом 200. Шаблон открылся снова. После перезагрузки проверено, что сервер хранит обе строки и изделие ссылается на новый элемент. Ошибок JavaScript нет.

Доказательства: [ввод двух строк](evidence/element-return/live-editor.png), [после перезагрузки](evidence/element-return/live-return-reloaded.png), [протокол HTTP](evidence/element-return/live-results.json).

## Проверка отказов и состояний

| Тема и ширина | Сценарий | Результат |
|---|---|---|
| Светлая, 375 | Открыть редактор до ответа на автосохранение. Ввести две строки, получить 500 от создания, повторить, получить 500 от привязки, повторить | PASS. В обоих случаях форма остаётся открытой и сохраняет ввод. До разрешения отложенного PUT новая связь не отправляется. Последовательность POST 500 → POST 201 → PUT 500 → PATCH 200 → PUT 200, одна созданная запись. После возврата новый элемент выбран, обе строки доступны в «Текстах элементов», готовность обновилась, прокрутка 777 → 777 px |
| Тёмная, 375 | Сменить вид на «Деталь» и сохранить | PASS. Запись создана в справочнике, связи с изделием нет, показано пояснение |
| Тёмная, 1920 | Добавить элемент, когда в шаблоне уже три | PASS. Запись создана в справочнике, четыре элемента в шаблоне не появились, показано пояснение |
| Тёмная, 375 | Снять BLG и выбрать WRK у элемента вида «Изделие / снаряд» | PASS. POST 201 с WRK, привязки нет, показано пояснение |

Панели в просмотренных состояниях не имеют горизонтального переполнения. После ошибки привязки сообщение формы использует общее «Не удалось создать запись». Ввод остаётся на месте, повтор обновляет уже созданный элемент и восстанавливает привязку.

[Форма после ошибки привязки](evidence/element-return/light-375-attach-failed.png), [возврат после повтора](evidence/element-return/light-375-saved-return.png), [лимит трёх](evidence/element-return/dark-1920-saved-return.png), [протокол браузера](evidence/element-return/browser-results.json), [отдельный протокол чужой категории](evidence/element-return/category-results.json).

**Отмена — PASS, светлая тема 1920 px.** Пока предыдущий PUT ожидал ответа, открыт редактор и введены две строки. Нажатие «Отмена» подтверждено кнопкой «Да, отменить». После возврата отложенный PUT завершился. В шаблоне сохранился незаписанный текст в реальном поле «Правила пользования» другого элемента. POST нового элемента отсутствует, ошибок JavaScript и горизонтального переполнения нет. Снимок первого прогона с открытым подтверждением относится только к диалогу, результат отмены подтверждает повтор.
