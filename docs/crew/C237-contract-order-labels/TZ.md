# C237 — договор без производственного заказа в карточке и печати

23.11.2026. Класс M, адресная правка подписей в PWA и существующей печати. Поручение владельца: на снимках договора 18/11/45 должны быть подписи «Договор», а не «Заказ».

Причина проверена explorer: projection production-orders допускает ObjectId договора как одиночную группу. При пустом productionNo UI/PDF ошибочно называют её заказом. Данные и номера не менять.

## Исполнители и границы

- Frontend: только `backend/pwa/sections/salesorders.js`, `order-attachments-zip.js`, `atlas-data.js`, `help-guide-data.js` и адресный тест в pwa. Сначала ownership/карта frontend, CANON/PRODUCT; правка подписей без новой раскладки, дизайн S. `heading` около49, панель `kind`458, крошка531, карточка513, searchRow707; PDF fallback имени attachments94–95. Общий kit уже поддерживает kind(row), его не менять. При отсутствующем productionNo — «Договор № orderNo»/«Договор»; настоящий производственный заказ — прежнее «Заказ № productionNo»/«Заказ». Сверить ссылки на самостоятельную карточку договора; маршруты не перестраивать. Atlas customercontract/salesorders и help должны описывать различие.
- Backend: только `backend/src/modules/salesorders/production-orders.service.ts`, `order-pdf.ts` и адресные spec в том же модуле. pdf около360–369 подставляет productionNo||orderNo; в OrderPdfInput добавить внутренний необязательный вид документа. Договор без productionNo: metadata/header/footer «Договор №…», подзаголовок «Позиции договора», filename «Договор_…pdf». Реальный заказ сохраняет печать «Заказ», «Производственный лист». Публичный маршрут/формат ответа не менять; безопасный default старых вызовов order-PDF — заказ.
- Координатор: доки, приёмка, коммит; QA/независимый просмотр после исполнения. Исполнители не коммитят/не выкладывают; другие агенты работают в репо, чужие правки не откатывать.

## Проверки и критерии

Два случая в UI и PDF: ObjectId договора без productionNo и существующий заказ с productionNo (включая несколько договоров). Не заменять номер договора номером заказа и наоборот. Старый маршрут печати остаётся, строки/суммы/состояния/файлы не меняются. Тесты генератора и сервиса должны проверять подпись/filename для обоих случаев; UI — heading/kind/крошки/search. typecheck, модульные тесты salesorders, PWA syntax/import и guards; браузерный снимок изменённых состояний и PDF-render. Отчёты только C237. Недоступную live-среду обозначить SKIP/PARTIAL, не объявлять прод исправленным без выкладки и проверки.

Не входит: смена схемы данных, API, создание/перенумерация заказов, перерисовка формы или переделка стандартов паспортов. Не читать весь backend/все клиентские разделы.

Уточнения по проверкам: наличие productionNo в новых подписях проверяется с trim(), как в серверной печати; пробелы не создают ложный заказ. После просмотра реального PNG coordinator расширил frontend scope на `order-footer.js`: существующий footerBar.title задаётся «Весь договор»/«Весь заказ» тем же helper, без изменения kit/действий. Остальная терминология производственных действий не перестраивается. Эти адресные исправления приняты координатором по воспроизведённым QA/визуальным фактам.
