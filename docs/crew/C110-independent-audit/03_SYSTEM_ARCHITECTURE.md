## Путь запроса (подтверждено кодом и ARCHITECTURE)

Middleware (request-id, идемпотентность) → guards по порядку `JwtAuthGuard → PermissionsGuard → RolesGuard` → глобальный `ValidationPipe` (лишнее поле = 400) → интерсепторы (`id`, контекст пользователя, аудит) → фильтры ошибок (409 при конфликте версий).
Слой данных: глобальные плагины soft-delete и audit; кэш тяжёлых списков на потоке изменений (`DataVersionService`).

| Решение | Почему выбрано (по докам) | Оценка |

| Разработка ИИ-конвейером с ролями и воротами | владелец не разработчик | работает, но дорогая по объёму документов (см. 05) |

## Связность модулей

- Циклов между модулями: 0 (после C068-9). Ф, E-12 и `backend/scripts/audit-cycles.js`.
- Прямых обращений к коллекциям в обход моделей: ~885 вызовов `.collection(`. Правило «удалённое не показывать» каждый пишет сам. Ф, E-17.
- Защита от одновременной правки (оптимистичная блокировка) подключена у изделий, материалов, категорий, организаций и счёта поставщика. У заказа, позиции заказа, заявки — нет. Ф, E-18.
- Страж «у каждого маршрута объявлены права» не найден. Ф (поиск по spec), E-19.

## Признаки незавершённости

1. Два писателя базы; переход «kppdf как клиент API» не начат, решение «остановить CRM» (2026-10-31) не выполнено. Ф, E-20.
2. Два сервера (дом и офис): обратное переключение не доведено, запасной отстаёт по версии, refresh failed. Ф, E-21.
3. Модуль `app-data` (пространства `app_*` для внешних приложений) существует, но реальных потребителей не видно. Г.
