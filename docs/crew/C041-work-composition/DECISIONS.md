# C041 — решения координатора (2026-11-07)

Пользователь: «Технику бери на себя; меня спрашивай только о бизнес-логике». Вопросы Q1–Q6 закрыты здесь, в `docs/QUESTIONS.md` не переносятся.

| № | Решение | Почему |
|--|--|--|
| Q1 | Части изделия — новое необязательное поле `products.parts[]`; маршрут остаётся в `products.workTypes[]` (+ `partRowId`, `hours`). `composition` не трогаем. | Одна правда, CRM не ломается (ADVICE п.2). |
| Q2 | Новый справочник «Части изделия» (`productParts`, механизм dicts). `passportParts` не трогаем. | Там падежи и мусор для текста паспорта. |
| Q3 | Запуск с непроверенным составом можно, с предупреждением. «Проверено» ставят менеджер и админ. | Работа не должна стоять из-за галочки. |
| Q4 | Зарплата — как сейчас: табель, ставка человека. Себестоимость работ = часы шага × ставка исполнителя; нет ставки человека — ставка вида работ; нет обеих — «нет ставки» (видно в аналитике). | Не ломаем выплаты; себестоимость считается из того, что есть. |
| Q5 | Норма часов — на 1 шт.; время позиции = норма × количество. | Так нормы переносятся между заказами. |
| Q6 | Параллельные работы — в Э2 (Гант): шаги разных частей могут идти одновременно, шаги одной части — по порядку. | Стойки и навес делают разные люди. |

## Цели пользователя, которые закрывают Э2–Э3
1. **Гант = планирование:** заказ разложен по шагам, видна занятость каждого рабочего, переназначение и сдвиг дат в 1 действие, фильтры, быстрая правка. Пересмотреть экран целиком (воронка-фильтры: Заказ → Позиция → Часть / или Рабочий).
2. **Нормы учатся сами:** факт выполнения (начало–конец шага, часы) сохраняется; в изделии появляется «Фактически: в среднем N ч / N дн. по последним K заказам» и предложение обновить норму (вручную можно править).
3. **Новые заказы получают оценку сразу:** позиция в плане берёт норму из изделия → срок позиции и заказа считаются сами → потом это пойдёт в КП («срок изготовления»).
4. **Себестоимость:** материалы (из состава) + работы (часы × ставка) по позиции и изделию.
