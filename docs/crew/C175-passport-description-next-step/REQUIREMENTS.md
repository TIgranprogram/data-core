# C175 — связи изделия с готовым паспортом

Дополнение к TZ.md по уточнению владельца21.11.2026. Основание: PRODUCT §5а/C155/C161/C163, C163/RULES КП-1…6, ПС-03/05. Это требования, не утверждение о готовности данных прода.

## Правила
1. При первичном оформлении изделия менеджер выбирает недостающие категорию паспорта, вид и только признаки, меняющие применимые тексты/части. Выбор хранится у изделия; повторный паспорт его не спрашивает.
2. **Факт** — подтверждённое поле/чертёж/состав изделия либо утверждённая связь справочника. **Выбор** — явное подтверждение менеджером одного применимого варианта. **Автосвязь** — результат правил по сохранённым фактам/выбору, без повторного ввода. **Неизвестно** — отдельное состояние с точным недостающим полем и следующим действием.
3. Единственный доказанно применимый вариант или ранее сохранённый выбор подхватывается автоматически. Несколько разных применимых вариантов требуют одного явного выбора; порядок выдачи списка не определяет победителя.
4. Существование изделия или части в каталоге не доказывает состав конкретного изделия. Название, похожая модель и фото дают предложение, но не разрешают автоматически назначить части, нагрузки, возраст, вместимость или крепление.
5. Категория каталога, нормативная категория паспорта и вид изделия — разные понятия. Если подходящей записи нет, дополнить правильный справочник; новый вид не превращать в новую нормативную категорию. Нормативы и безопасность не назначать догадкой.
6. При изменении вида/признака сохраняются совместимые ответы; несовместимая связь объясняется до записи. Свой текст и несохранённый ввод не теряются; выпущенные снимки автоматически не пересобираются.
7. Менеджеру всегда доступен следующий шаг: выбрать недостающее поле, подтвердить вариант, выбрать части вручную либо передать конкретный пробел ответственному. При отсутствии прав справочника не предлагать недоступное редактирование как единственный выход.

## Приёмка существующих изделий
- Аудит охватывает все действующие изделия постранично; сохраняет дату/контур, общий объём, число прочитанных/ошибок и ID. «100% проверено» допустимо лишь при полном совпадении счётчиков и нуле непрочитанных записей.
- Каждое изделие имеет один основной исход: готово автоматически; нужен явный выбор; не хватает факта; не хватает словарной связи/записи; конфликт/недоступный источник. Дополнительные причины сохраняются отдельно, без двойного счёта изделий.
- Для пробела указаны точное поле/словарь, источник подтверждения, предлагаемая запись или связь и способ проверки. План применения отделён от результатов применения; неопределённые характеристики остаются неизвестными.
- После доказанного заполнения: открыть шаблон short → увидеть применимый текст/части → образец → повторное открытие без повторного выбора. Контрольная проверка другого вида не получает чужие части.

## Приёмка нового изделия
Если сохранены категория/вид/нужные признаки и применимая словарная связь существует, short сразу получает соответствующие текст и части. Если связи нет, карточка изделия показывает адресную незавершённость и доступное действие; паспорт не становится первым местом обнаружения пробела. Необязательные BOM/материалы/full-поля short не блокируют.

## Граница текущего исправления
UI сейчас: объяснить пустой связанный список, дать явный ручной выбор из всех частей, обновление справочника без потери ввода и штатный подбор по виду/признакам. Это устраняет тупик, но не доказывает готовность всех вариантов.
Полноценное завершение: полный аудит покрытия → доказанный план словарных записей/связей → применение через разрешённый API → проверка всех изменённых изделий и нового изделия. Если карточка создания не выполняет правила выше, требуется отдельный согласованный подэтап реализации и регрессии, а не объявление UI-подсказки полным решением.
