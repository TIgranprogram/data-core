# C239 — реализация рисунков Пульта

23.11.2026. Код frozen, коммит не выполнялся. Backend, публичные API, PWA и реальные данные исполнитель не менял. Независимая QA/приёмка координатором остаются отдельным шагом.

## Что реализовано

- `tools/document-intake/extract-images.py`: PyMuPDF читает нативные PNG/JPEG с bbox/xref; связь с единственным SKU номерной текстовой ячейки по вертикальному пересечению и правой колонке. Порядок ресурсов не используется. Изображения без доказанной строки исключаются с предупреждением. Есть лимиты страниц/ресурсов/размера; чужие инструкции из PDF не исполняются, внешние модели не вызываются, upscaling нет.
- `tools/document-intake/images.mjs`: `prepareDocumentImages` / `sendDocumentImages`; исходник через защищённый `findReview` / `getReviewOriginal`, повторный SHA после извлечения, owner/target/version и API-карточка защищённого оригинала. Единственный живой договор определяется по legal.sourceSha256; строки — уникальным SKU исходного sourceLine, с проверкой ID/родителя/количества и неизменного sourceLine.
- Подготовка не делает POST. Предпросмотр сверяет уже имеющиеся фотографии и показывает «Уже прикреплён». Fingerprint охватывает source/версию черновика/актора/контур/legalVersion/строки/изображения, а не изменчивую отметку текущих привязок. Подтверждение живёт15минут в локальном `.intake/image-confirmation.json`, без JWT.
- Отправка: один список photos за проход, только variant=original без parentPhotoId/удаления, точные ASCII-имена `dcimg-<PDF SHA>-<image SHA>.<ext>`. Reuse подтверждается GET метаданных и фактических байтов, не только именем. Один asset используется для нескольких позиций.
- Журнал `documents/c239-images-<PDF SHA>.json`: uploadStarted сохраняется до POST, photoId — до attach. После потерянного upload следующий запуск восстанавливает найденный original по имени и байтам. Если uploadStarted есть, а original не найден, повтор останавливается, не создавая файл вслепую. AUTH не скрывается; при явном отказе авторизации новой загрузки uploadStarted снимается. Параллельный перенос позиции не гарантируется атомарно: действует утверждённый ограниченный single-writer сценарий.
- Перед upload и каждым attach повторно проверяются источник/родитель/архив. `POST /incomes/:id/photos` дописывает photoId, прежние фото не удаляются/не переставляются; последующий GET проверяет их сохранность. Каталог и productId не меняются.
- `pult/document-intake.mjs`: actions `imagesprepare` / `imagessend` защищены входом, revision, форматом arrivalId/confirmationId, busy и текущим tokenProvider. `pult/server.mjs`: static нового UI-модуля и включение обоих actions в прежний gate перезапуска/опасной команды.
- `pult/ui/document-intake-images.js`: «Рисунки…» у PDF в отчёте → миниатюры/источник/позиция/размер/уже прикреплено → отдельная кнопка «Загрузить рисунки». Состояние «всё уже прикреплено» блокирует ненужную отправку. Данные выводятся DOM-текстом; preview допускает только ограниченные PNG/JPEG data URL. Существующие классы/панель, без нового CSS и компонентов.
- Внутренние модули добавлены в NOT_ON_BUTTONS; `pult/docs/КОМАНДЫ.md` перегенерирован штатным `node pult/gen-docs.mjs`.

## Границы результата

Поддержана однозначная таблица «номер+SKU слева, иллюстрация справа», а не произвольная вёрстка PDF. Неоднозначное оформление требует отдельной сверки. Полноразмерный исходный PDF остаётся первичным документом; рисунки КП являются иллюстрациями, не доказательством точного изготовленного вида.

Реальная догрузка C239 сделана агентом access отдельно и описана в BACKFILL-REPORT. Данный исполнитель не объявляет её своим live-прогоном Пульта: нужна отдельная read-only проверка нового предпросмотра в сессии владельца. После автообновления Пульта рабочий вход может потребовать повторного ввода владельцем; пароль не читался/не сохранялся.
