## Как проверять дальше

Пульт: «Проверки выпуска» собирает types/unit/imports/design, инструментальные, PWA и Nightshift tests. Он не обращается к production и не запускает Docker/E2E. «Полная проверка» — отдельный уникальный QA-контур. Ворота — preflight.sh; выпуск — release.sh/рабочая remote-access обёртка. После публикации — doctor и read-only post-check через datacore-access.

Mongo и backend T23 находятся только во внутренней сети. Два loopback-порта доступны через шлюз с двумя фиксированными TCP-направлениями. Это исправляет отличие реального Docker от fake-тестов, не открывая приложению выход наружу. Остановка не удаляет сети или тома.

## Данные и ограничения

Production Mongo, существующие local/legacy контейнеры и CRM не изменялись тестами. Существующие бизнес-дубли не объединялись. Копия на ПК подтверждена; цепочка и расписания копий вне сервера требуют проверки пользователем, не считать их доказанными только по бэклогу.

Установка Nightshift на другом новом Windows-ПК не проверялась. Проверена новая чистая virtualenv текущего ПК. Нагрузочные, chaos/fuzz/visual и другие stub suites исключены из green gate; это будущие возможности, не тесты сайта.

Read-only обход не доказывает каждую UI-кнопку. Основные операции покрыты backend E2E, новые финансовые действия дополнительно локальной фикстурой. PDF-содержимое и полная матрица всех ролей остаются отдельными проверками.

Из прежних эксплуатационных рисков не скрыты: давний общий пароль admin, публичный /uploads, внешние копии и учебное восстановление. Пароли и бизнес-данные меняет пользователь через существующие пункты пульта; в этом выпуске они не менялись.
