# ТЗ ОШ2 — «Что-то пошло не так»: сбор ошибок, понятные сообщения, один индикатор загрузки

**Зачем (словами пользователя, 2026-10-23):** вместо «Что-то пошло не так» — понятно, что не получилось и что делать; причины ошибок — найти и починить.

**Роли:** backend ☐ (ОШ2.1) · frontend ☐ (сборщик + ОШ2.4 + ОШ2.5) · qa ☐ · координатор — выкладка, затем ОШ2.2/ОШ2.3 по данным с прода

## Волна 1 (сейчас, до выкладки)

### ОШ2.1 — сервер (backend, по skill `datacore-new-module`)
- Модуль `client-errors`: `POST /api/client-errors` — только вошедший (JWT; ключ `kppd_` — 403), без `@AppSection`. Отдельный rate-limit: 20/мин на пользователя; сверх — 204 молча (не 429, чтобы клиент не зацикливался).
- Тело (DTO, все строки обрезаются по длине, лишние поля → 400 как везде): `message` ≤ 500, `name` ≤ 100, `stack` ≤ 4000, `section` ≤ 60 (`#раздел`), `action` ≤ 120 (что делал: «Сохранить паспорт», «загрузка списка»), `kind` (`action` | `background` | `unhandled`), `status?` (HTTP-код, если ошибка запроса), `url?` ≤ 200 (путь API без query), `version` ≤ 40, `ua` ≤ 300. **Данные форм не принимаются.**
- Запись: коллекция `clienterrors` (только data-core), `userId`, `role`, `createdAt`, TTL-индекс 30 дней; ключ группировки `sig` = хэш `name+message(без чисел/id)+section+url`. Плюс строка в журнал сервера `[client-error] sig section message`.
- `GET /api/client-errors/top?hours=24` (admin): `{items:[{sig, count, users, lastAt, message, name, section, action, url, status, version, sampleStack}]}` по убыванию count.
- Реестр коллекций админки (`kind:'core'`), `ensure-indexes` (TTL и `{sig:1, createdAt:-1}`), MAP, openapi, юнит (DTO, rate-limit, top).

### Сборщик и ОШ2.4 — приложение (frontend, skill `datacore-design`)
- `pwa/core/errors.js`: `reportError(err, {kind, action})` → `POST /client-errors` (молча, без повторов при сбое; одинаковый sig — не чаще 1 раза в 30 с; без сети — до 20 в памяти, отправить при появлении сети). Подключить: `window.onerror`, `unhandledrejection`, ошибки `api()` (кроме 401/403/404/409/400 с текстом — это не сбой, а ответ; 5xx, сеть, разбор JSON — сбой), падение отрисовки раздела.
- Показ (ОШ2.4):
  - **фоновые** (загрузка списков, счётчиков, подсказок) — не всплывают: в месте блока «Не загрузилось · Повторить»;
  - **действие человека** — «Не удалось <действие>: <причина по-русски>. <что сделать>» (например «Не удалось сохранить паспорт: нет связи с сервером. Проверьте интернет и нажмите ещё раз»); одинаковые — не чаще 1 раза в 30 с;
  - ответ 500 — «Сбой на сервере (код <errorId>) — мы уже знаем, попробуйте ещё раз»;
  - вышла новая версия (service worker нашёл обновление / ответ с другой версией) — плашка «Вышла новая версия — Обновить», без самопроизвольной перезагрузки.
- ОШ2.5: один компонент индикатора `ui/busy.js` — «Загружаю …» в блоке, кнопка «Сохраняю…» (заблокирована), через 10 с — «Долго… Повторить». Заменить разрозненные варианты там, где это 1–2 строки; полный переход — список мест в отчёт (что не перевёл).
- DESIGN §4 (компонент), §8.

### Контракт (общий для backend и frontend)
`POST /api/client-errors` `{message, name?, stack?, section?, action?, kind, status?, url?, version?, ua?}` → 204. `GET /api/client-errors/top?hours=24` (admin) → `{items:[…]}`.

## Критерии приёмки
- [ ] Ошибка JS в разделе → запись в `clienterrors` с разделом и действием, без данных форм; 30 одинаковых за минуту → не больше 20 записей и одной всплывашки.
- [ ] Фоновая ошибка — «Не загрузилось · Повторить» в блоке, без всплывашки; действие — понятная фраза.
- [ ] `top` — только admin; `kppd_` на POST — 403.
- [ ] tsc 0, юнит модуля, pwa `--input-type=module --check`, `pwa-guards`.

## Нельзя
- Отправлять данные форм, пароли, токены; всплывать на каждую фоновую ошибку; коммитить (кроме координатора).
