# Вердикт: Nightshift (tests_ai_tiit) vs Пульт

**Дата:** 2026-11-03 · **Координатор** · **Статус: закрыто**

## Что это

| Вещь | Где | Для кого |
|--|--|--|
| **Пульт** | `pult/` + ярлык «Пульт DataCore» на столе | Вы: кнопки каждый день |
| **dc night** | `tools/night.mjs` через пульт | Полный прогон (типы, юнит, e2e, обход) на своём стенде |
| **Nightshift** | `tests_ai_tiit/nightshift/` | Отдельный Python-harness (T22): безопасный стенд + профили local/night |

## Решение

1. **Не доделывать** Nightshift как «второе приложение с кнопками/GUI».  
   `gui/server.py` — заглушка (раздача папки на :8080). AI/scheduler и suites chaos/load/visual — `not_implemented`, вне ворот выпуска (CONTROL).
2. **Не сливать** Nightshift и Пульт в один продукт.  
   Кнопка «Пакет выпуска: собрать показатели» гоняет pytest Nightshift. «Полная проверка», «Большая проверка сайта» и стенд идут через `dc`.
3. **Польза сейчас:** пользоваться **Пультом**. Nightshift оставить как есть для ИИ/ворот (doctor + local/night уже зелёные 76/76 и два night-профиля).

## Когда вернуться к Nightshift

- Нужен второй чистый Windows-ПК (установка ещё не проверена) — тогда только `uv sync` + doctor, без GUI.
- Появится явная боль «кнопки пульта мало» — тогда **одна** кнопка в пульте на `nightshift doctor` / `run --profile local`, не отдельный ярлык.

## Не делать

- Второй ярлык «Nightshift» на стол.
- Доводка GUI/AI-loop «чтобы было красиво».
- Объединение кодовых баз pult + nightshift.
