## 2а. 🔴 ФИ. Пересчёт остатка («Пересчитать (сколько лежит)») — исправить логику (замечание пользователя 2026-10-21)
Случай: «Болт M10x100 DIN 933»: приход +931 (30.09), бронь 750, пользователь собрал бронь, ввёл «сколько лежит» = 931 → «Корректировка −931 инвентаризация» → остаток 0, свободно −750. Ожидалось: остаток не должен был упасть до 0. Похожий случай — «Гайка DIN 934» (−1963, потом отмена).
Что известно из кода (`backend/pwa/sections/stock.js`, `move(…,'adjust')`): поле «Фактический остаток» предзаполнено текущим учётным; `delta = введённое − r.quantity`, шлётся `type:'adjust', qty:delta`. Предпросмотра delta нет; бронь не учитывается; непонятно, «сколько лежит» — вместе с бронью или без.
- [x] ФИ.0 Воспроизвести на копии/стенде (не на проде): позиция остаток 931, бронь 750 → пересчёт; записать, что вводится, какой delta уходит и что считает бэкенд (`stock.service`, обработка `adjust`: знак, округление, «qty — дельта или целевой остаток?»). Найти причину −931: ошибка ввода/UI, или бэкенд трактует `qty` иначе. Не гадать — показать цепочку «ввод → delta → результат».
- [x] ФИ.1 Формулировки: поле «Сколько лежит на полке всего (вместе с забронированным)»; подсказка с тремя числами: по учёту / в брони / свободно. Бронь физически лежит на складе — входит в «всего».
- [x] ФИ.2 Предпросмотр до сохранения: «По учёту 931 → станет 931 (изменений нет)» / «будет корректировка −X, свободно станет Y». Кнопка «Сохранить остаток» неактивна без изменений.
- [x] ФИ.3 Защиты: введённое < брони → красное предупреждение «Меньше, чем в брони (750): свободно станет −N. Сначала снимите/выдайте бронь» и подтверждение отдельной кнопкой; изменение > 50% от учётного или итог 0 при ненулевом — «Уверены?». Ввод с пробелами/запятой (`1 681`, `931,5`) разбирать верно; не предзаполнять поле так, чтобы дописывание цифр давало «931931» (выделять значение при фокусе).

## 2в. ЗЧ. Список «Заказчик» в заявке — один источник, без «ИП Саходжи, Академия благоустройства» (замечание пользователя 2026-10-21)
Что выяснено (код):
- Поле «Заказчик / участок (текстом)» (`backend/pwa/sections/requests.js:142`, `orderLabel`, тип combo) берёт варианты из `GET /supply/lookups` → `supply.service.ts` ~385: `customers = distinct(orderLabel по ВСЕМ заявкам) ∪ settings «supply.sheetLists».customers` (список «Заказчики» из Google-таблицы).
- То есть «ИП Саходжи» и «ИП Саходжи, Академия благоустройства» — это два разных текста, когда-то введённых в заявки (или пришедших из таблицы). Каждый введённый вручную текст сам становится вариантом навсегда.
- Справочник «Контрагенты» (`partners.service.ts → customers()`, берёт `salesorders.customer` + организации type customer) и поле «Заказчик» в «Заказах» (`orders.js`, `incomes.service.ts` ~205) — отдельные списки. В «Справочниках» этот список не редактируется — поэтому его там не найти. Это не ваша ошибка понимания, а недоработка: три источника вместо одного.
- Запятая — просто часть текста: «заказчик, объект» вписан в одно поле, хотя для объекта есть «Объект СМР / уточнение».
