# ТЗ C009 — Единая номенклатура (источник истины)

**Класс:** XL (договор + заявки + каталог; общие с CRM `materials` / `supplyrequests`)  
**Статус:** аудит 2026-11-03 — договор и фазы; код после подтверждения порядка.

## Договор (как должно быть)

| Слой | Что это | Коллекция |
|--|--|--|
| **Номенклатура** | Одна позиция «что покупаем/храним» (метиз, лист, фанера…) | `materials` (+ остаток `storageitems`) |
| **Продукция** | Что делаем сами | `products` — **не** смешивать |
| **Оферта поставщика** | Как поставщик называет и по какой цене предлагает | `supplieritems` → ссылка `materialId` |
| **Факт закупки** | Что реально купили (без НДС) | `materialprices` → пишет `lastPrice` / `lastSupplierId` на позицию |
| **Снимок заявки** | Что попросили в этот раз | `supplyrequests` (название + materialId + supplierId + priceHint) |

**Не задвоение имён:** каталог — не вторая номенклатура, а «позиция + поставщик + цена».  
**Автозаявка:** выбрали позицию → подставить **последнюю закупку** (`price-default`), прайс каталога — только подсказка. Цена в заявке **с НДС**, факт закупки — **без НДС** (не копировать слепо).

**Фильтры (10×100):** поля уже есть (`dimensions`, `assortment`, `materialGrade`) + разбор названия (СКФ.7). Новая таблица «поля фильтров» не нужна; нужно **заполнение** и удобный ввод.

## Фазы

1. **S** — записать договор в PRODUCT + data-model (без кода).
2. **M** — заявка: выбор позиции → автоподстановка последнего поставщика/цены + подсказка прайса.
3. **M** — каталог: связать строки без `materialId`; не плодить дубли имени.
4. **L** — наполнить сортамент/размеры скриптом; фильтры склада.
5. **XL осторожно** — необязательная ссылка заявки на строку каталога (только синхронно с CRM).

## Риски

Общие с CRM: `materials`, заявки. Не писать прайс в `pricePerUnit`/`supplierId` без решения. Не удалять материалы из каталога.
