# ТЗ C042-A — аудит: два живых одинаковых сервера, автосинхронизация, кнопка «Переключиться»

**Зачем (пользователь 2026-11-07):** «Два живых сервера, абсолютно идентичные. В любой момент захотели — переключились и работаем с другим. Кнопки „переключиться на другой сервер“ до сих пор нет, автосинхронизация не работает. Аудит, проверить, исправить.»
**Зачем — глаголом:** администратор нажимает одну кнопку — через ≤ 5 минут все работают на втором сервере (Sportin) с теми же данными, без потерь; обратно — так же.

**Роль:** datacore-architect (только чтение, код не пишет). **Класс:** XL (аудит до кода).

## Глубже
- **Результат:** карта «что есть / что сломано / чего нет» по переключению и синхронизации + план исправления с чек-листом.
- **Сырьё:** HISTORY 2026-10-31 (вкладка «Серверы», режим чтения, `HA_SELF`, Idempotency-Key; копия на Sportin через `SRV-ERP/refresh-copy.sh --code`; `backuptargets` пуста); AGENTS.md п.10 (сервера одинаковые, отличия — `.env`; второй сервер — `SRV-ERP/`).
- **Метод профи:** активный/резервный (active-passive): непрерывная репликация данных (Mongo replica set между площадками или периодический снапшот + oplog), фото/файлы (rsync), единая точка входа (nginx на VPS переключает upstream), защита от двух «главных» (fencing), режим чтения на резервном, проверка готовности перед переключением, откат.
- **Внешний судья:** каждое «есть» — файл:строка; каждое «сломано» — как воспроизвести/что видно.

## Что исследовать
1. `grep -rn "HA_SELF\|failover\|switchover\|readOnly\|read-only\|servers" backend/src --include=*.ts | head -50`; вкладка «Серверы» в админке (`grep -rn "Серверы" backend/admin`).
2. `SRV-ERP/` целиком (список файлов, README, refresh-copy.sh), `deploy/` — синхронизация, бэкапы (`backup.sh`, `backuptargets`), туннель VPS → VM (`deploy/synology/README.md` «Публичный доступ»).
3. Как данные попадают на второй сервер сейчас: вручную `refresh-copy.sh` или по расписанию? Фото `uploads`? Как часто?
4. Как пользователи сейчас попадают на сервер: `kppdf-crm.ru/db/` → VPS nginx → туннель → VM. Что нужно, чтобы VPS вёл на Sportin.
5. Что мешает «кнопке»: права, доступы, отсутствие репликации, режим чтения, CRM kppdf на той же базе (AGENTS п.4 — CRM работает с той же базой! на втором сервере CRM есть?).
6. Риски: два пишущих сервера одновременно, потеря записей между последней синхронизацией и переключением, расхождение версий кода.
