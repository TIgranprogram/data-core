# ТЗ NAV — меню по смыслу, «Документация» вместо «Паспортов», левая панель фильтров

**Зачем (словами пользователя):** «Заказы», «Проектирование», «Продукция» — отдельные пункты, не смешанные. Раздела «Паспорта» в меню нет: паспорт — свойство изделия (печать из «Продукции» и из заказа), шаблон привязан к одному изделию. Новый раздел «Документация» (подраздел «Паспорта» — шаблоны; вкладка «Архив паспортов» — ≈235 старых, только просмотр/печать). Слева постоянная панель фильтров — в «Остатках» и «Продукции».

**Класс:** XL (меню/права/общая коллекция `products`) · **Max agents:** 5 · **Reviewers:** qa ☑ architect ☑ designer ☑ · **Max review loops:** 2 · **Проверки:** full
**Язык менеджера:** да · **Приёмка:** сайт глазами: меню (десктоп, 390), «Остатки», «Продукция», «Документация», карточка изделия.

## Shared pack — решения аналитика (по умолчанию, вопросов к пользователю нет)
**(а) Меню** (`main.js:56`, `:157`). Порядок и группы:
| Группа | Пункт (id → подпись) | Кто видит |
|--|--|--|
| — | home «Сегодня» | все |
| Снабжение | requests «Заявки» | по `sees` |
| Склад | stock «Остатки» | по `sees` |
| Продажи и выпуск | salesorders «Заказы» · design «Проектирование» · products «Продукция» · **docs «Документация»** | по `sees`; docs — ещё `session.canEdit` (как было у «Паспортов») |
| Деньги | orders · money · payroll | как сейчас (`canMoney`) |
Название группы «Продажи и выпуск» (не «Заказы» — совпадало с пунктом и создавало путаницу). «Контрагенты» — как есть (только в «Справочниках»).
Права: `sees(id)` = `user.sections` (галочки роли, `roles.appSections`). Новый id `docs` добавить в `backend/src/common/app-sections.ts` (иначе нельзя отметить у роли). Старый id `passports` ОСТАЁТСЯ в `APP_SECTIONS` (его проверяют `@AppSection('passports')` на `/passports*` и `/showcase*`, менять контроллеры не надо), подпись → «Документация (паспорта, шаблоны)». В `main.js` пункт `docs` виден, если `sees('docs') || sees('passports')` (роли, где отмечены паспорта, ничего не теряют, миграция ролей не нужна). Внутри `products.js` (:228, :248) проверку `sees('passports')` заменить на тот же `seesDocs()`.
Маршруты: `#docs` — новый экран (вкладки «Паспорта» | «Архив паспортов»; вкладка в адресе `?tab=`); `#passports?open=ID` ОСТАЁТСЯ рабочим (ссылки из `products.js:127`, заказов, истории) — как скрытый экран пункта docs: `OWNER.passports='docs'`, `ptext/ptextview/ptnode → 'docs'` (`main.js:59–60`), `NAV` без `passports`. Открытие карточки паспорта по `#passports?open` рисует «Архив паспортов» с этой карточкой.
**(б) Данные — шаблон на изделие без новых таблиц и без миграции.** Уже есть `products.passportDefaults` (`showcase/passport-defaults.ts`: `passportCategory`, `elements`, `materialIds`, `installationTypeId`, `textChoices` — выбор текстов воронкой, размеры/гарантия) — «Выпустить паспорт» подставляет его в новый паспорт. Это и есть «шаблон паспорта изделия». `passporttemplates` (по категории, тексты разделов) остаётся как общие тексты категории и НЕ получает `productId`. Итог: «шаблон изделия» = `passportDefaults` + тексты категории; правится в «Документация → Паспорта» (список изделий, статус «шаблон есть / нет», правка той же формой воронки `funnelBox` и тех же `PD_KEYS`, что в `products.js:67–92`, сохранение `PUT /showcase/:id/passport-defaults`). Печать изделия без заказа и из заказа берёт его. Backend не меняется (опц. шаг B1 ниже). Свои тексты только для одного изделия (`ownSections`) НЕ вводим — вне задачи.
**(в) Архив.** Без флага и без правки данных: «Архив паспортов» = существующий экран `passports` (`/passports`, коллекция `productpassports`) только на чтение/печать: без «Новый паспорт», «Выпустить», «Аннулировать», массового изменения и «Изменить номер»; остаются просмотр карточки, «⇩ PDF и печать…», «⇩ PDF пакетом», «Создать копию» убрать (копия = новый паспорт, он создаётся из изделия), «Привязать к изделию» оставить (директор/админ, полезна для старых). В архив попадают и новые выпущенные паспорта (это журнал выпуска). Метка «старый» — у записей с `source` не `app` (в схеме `product-passport.schema.ts:221`: `sheet:Pasports` = перенос). Фильтр-чип «Старые (≈235)» = query `legacy=1` → в сервисе `source != 'app'` (шаг B1, только чтение; DTO query: проверить whitelist, `AGENTS.md` «ловушки»).
**(г) Левая панель** (общий механизм `pwa/ui/list.js`, опция `L.sidebar`):
- Десктоп ≥ 1101: колонка слева от таблицы, ширина 280 px (фикс., `--filter-w` по умолчанию 280 вместо 340; ресайзер `makeResizable` не навешивать), всегда открыта, `position: sticky; top: 0`, своя прокрутка; таблица/галерея сдвинута вправо (`grid-template-columns: 280px minmax(0,1fr)`). 721–1100: 240 px. Правая панель-карточка (drawer) открывается поверх, левая остаётся.
- Телефон ≤ 720 (390): панели нет, в шапке списка кнопка «Фильтры · N» (N = число выбранных); по нажатию — полноэкранный лист слева (существующий стиль `.ff-pop` на мобильном, `min(340px,88vw)`, затемнение `.ff-shade`, крестик, Esc), кнопка «Показать» внизу.
- Состав сверху вниз: поиск (`searchBox`, плейсхолдер «Название, размер, стандарт…») → «Категории» (бывшие плитки `L.tiles`, теперь списком с числом `n`, один выбор, повторный клик снимает) → признаки/фильтры → «Сбросить всё» (виден, если что-то выбрано).
- **«Остатки»** (`sections/stock.js:81–95`): категории из `/stock/categories` (`categoryId`) · «Состояние» (К закупке / Нет на складе / В брони / В норме, `status`, с числами `resp.counts`) · признаки `ft` из `ui/facet-filter.js` (тип / резьба / длина / стандарт — группы значений; `grade`, `section`, `thickness`). Убрать `toolbarExtra: facetFilter` (выпадающую панель) и плитки над таблицей; `facetFilter` получает режим `inline` (тело `.ff-body` рисуется в колонке, без `pop/shade/btn`; на телефоне — как лист).
- **«Продукция»** (`sections/products.js:176–200`, `/showcase`): поиск `q` (наименование, артикул, серия) · «Раздел / Группа» (`groupId`, из `/showcase/groups`: сначала разделы, затем группы с подписью раздела; верхние «Благоустройство» и т. п. — заголовки-разделы) · «Серия» (`series`, значения из `/showcase/form-values`) · «Состояние»: Все / Черновики (нет цены, `status=draft`) / Архив (`status=archived`) — если `/showcase` не отдаёт `status` в query, фильтр делается на сервере (шаг B2, иначе пункт «Состояние» не показывать). Цену/габариты НЕ фильтруем (нет требований).
