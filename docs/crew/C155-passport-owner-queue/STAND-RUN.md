# П155-1. Прогон на изолированном стенде

19 ноября 2026 года, `http://localhost:3102/app/`. Паспорт Docker подтвердил отдельную БД, собственные тома и внутреннюю сеть. Доступ с хоста через loopback-прокси. База из `datacore-2026-11-18_031040.tgz`, готовность API подтверждена. Прогоны выполнены под обычным менеджером.

Образ backend `452dcf7431e4`, собран 18 ноября в 12:07 UTC. API `0.1.0`. Шесть файлов PWA, включая книжку, её входы и план паспортов, совпали с `ab7f4fc7` по контрольным суммам Git. На стенде `/app/version.json` отвечает 404, в метаданных образа нет ревизии Git.

## Первый прогон

- PASS по поиску 1066, отказу выпуска неполного паспорта и двум темам. FAIL по входу в шаблон, очереди, отдельному действию для образца, выпуску 3209 и обоим входам из заказа. У заказа два ожидания истекли, сопоставление контекста осталось непроверенным. [Детали первого прогона](evidence/baseline/qa-results.json)
- Кнопка шаблона создала один черновик 1066 `6afed9deb9cf5ab0e5869472` без заказа. GET после прогона подтвердил отсутствие официального номера. Скачивание двух PDF дало HTTP 200 и сохранило состояние черновика. Запросы выпуска 1066 и 3209 вернули 400. Первый ответ указал материалы, фото и чертёж. Второй указал три недоступных файла рисунков. Черновик 3209 остался без номера и заказа.
- Резервный черновик 1208 остался без изменений. Сценарий остановил запросы записи настроек учётной записи и отправки клиентской ошибки.

## Второй прогон

- PASS по поиску, отказу выпуска неполного 1066, обоим входам из заказа и работе элементов интерфейса в двух темах. FAIL по входу в шаблон, очереди и действию для образца. SKIP для успешного выпуска 3209. [Результат второго прогона](evidence/qa-results.json)
- В карточке заказа две позиции одного изделия открыли разные правильные паспорта. Проверены просмотр, редактор, PDF и возврат к позиции. В плане заказов заблокированная строка открыла существующий черновик с верными идентификаторами заказа, строки и изделия.
- Выпуск 3209 снова вернул 400 по трём рисункам. Этот черновик и единственный черновик 1066 остались без номера и без заказа. В обоих случаях API подставляет рисунки изделия из `effectiveImages` поверх собственных `images` черновика. В первом наборе копирования оказались собственные `images` и файлы карточек. Они доступны по HTTP, а три собственных PNG 3209 декодируются функцией backend. Для реально выбранных рисунков сеть прогона показала локальные 404. Из-за отсутствующего эффективного рисунка обложки оба снимка тем получились без фото.

## Проверка выпуска 3209 после восстановления рисунков

- PASS. Черновик с уже указанной фирмой выпущен на стенде без заказа и позиции. Единственный успешный POST вернул HTTP 200 и присвоил один новый номер, 613. Остальные паспорта этого изделия сохранили номера и статусы. [Результат проверки выпуска](evidence/qa-standalone-results.json)
- Короткий PDF скачан дважды с HTTP 200. Сценарий подтвердил PDF в обоих ответах. Контрольный GET подтвердил тот же номер 613. Изделие 1066 осталось с единственным черновиком без номера. После восстановления рисунков PDF 1066 повторно не формировался. [PDF 3209](evidence/qa-06-standalone.pdf) · [Повторное скачивание](evidence/qa-06-standalone-repeat.pdf)
