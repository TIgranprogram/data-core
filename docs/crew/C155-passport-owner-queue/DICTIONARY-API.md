## Предлагаемые привязки и формулировки

- Включить «Каркас» в короткий список `TRN` после согласования. Для 1066 уже подтверждены категория `TRN` от группы и исходное задание с каркасом. У смежной части «Несущая рама» сейчас `TRN,WRK,BLG,DIO`. Это подтверждает наличие такого конструктивного понятия в словаре, но слишком широко для автоматической привязки. Для `WRK` сначала проверить каркасные комплексы и полосу препятствий. Для `BLG` — каркасные навесы, городские качели и трибуны. Для `DIO` — каркасные игровые комплексы. Их уместно привязать к конкретным видам в новых ветках, когда состав подтверждён. Для `DSP` сначала нужна классификация по снарядам. Общее поле `categories` меняет также короткий список частей в таблице материалов, поэтому его расширение требует отдельной проверки полного варианта.
- Кандидаты TRN и 1066. Начальный выбор — «Тренажёр для ног» и подтверждённая нагрузка, если классификация однозначна. У 1066 вид в карточке отсутствует, хотя назначение «Ноги» ранее подтверждено. Поэтому для 1066 нельзя полагаться только на вид. На QA вариант можно привязать к TRN и подтверждённым признакам либо использовать фразу конкретного изделия. Состав из каркаса, рукояток и педалей подтверждать по рисунку конкретного изделия. «Гриф» предлагать лишь в вариантах с подтверждённым грифом, а не на основании категории или сходного названия.
- Кандидаты WRK, BLG и DIO. Начать с отдельных видов с однозначным набором видимых частей. Для турника проверить стойки и перекладины, для скамьи — опоры, сиденье и условную спинку, для качелей — раму, подвес и сиденье, если это соответствует выбранному виду и рисунку. Ветки с несколькими действительно возможными составами оставлять на выбор. У типа с недостатком сведений оставить один вопрос о конструкции. Привязки DSP целесообразно начать со снарядов, пока виды отсутствуют.
- Проверить на QA «Изделие состоит из {parts}» для одного каркаса. Сейчас подстановка выбирает родительный множественного при его наличии и без количества выводит «из каркасов». До отдельного правила числа использовать явную проверенную фразу, например «Тренажёр включает каркас, рукоятки и педали» для подтверждённой конструкции. Критерии приёмки — автоматическая подсказка только при однозначном совпадении, видимый выбор при нескольких вариантах, отсутствие угадывания состава, массы, нагрузки и свойств крепежа. Короткие описания и новые привязки остаются планом QA до поддержки рабочим API.

## Словарная фикстура 1066

На изолированной копии `2fd2723433a343191577b795` подтверждены вид «Тренажёр для ног», значение «Две платформы для ног и рукоятка», корень и лист краткого описания. Контрольный GET шаблона вернул `ready:true` и текст «Тренажёр состоит из каркаса с рукояткой и двух платформ для ног.» Источник — словарь, лист `6afef7ee3b40fac6985f630f`. Собственная краткая фраза отсутствует, ранее выбранное назначение «Ноги» сохранилось. Все три оригинала эффективных рисунков доступны на стенде с совпадающим SHA-256.

В рабочей выгрузке и в исходной копии отмечены разные способы монтажа. В собственных настройках изделия «На закладные детали», в выбранном тексте «Анкерное крепление», которое задаёт «Анкеры на фундамент». Для сквозной проверки на QA собственное поле согласовано с уже выбранным анкерным текстом. Рабочее изделие требует подтверждения фактического способа владельцем. Глубину, нагрузку и другие параметры при подготовке фикстуры не дополняли.

Журналы `stand-qa/2026-11-19T13-21-33-833Z-19556/`, `stand-1066-mount.*.json` и `stand-1066-effective-media.json` находятся в `tools/logs/c155-dictionary-source/`. Менеджер читает шаблон и получает 403 для счётчиков паспортов. Исходные счётчики сохранены отдельным GET администратора QA.

У резервного черновика 3209 восстановлены чертёж и схема фундамента с HTTP 200 и совпадающим SHA-256. Исходное фото обложки не удалось получить через два публичных пути после таймаута. Резервная фикстура остаётся неполной. [Исходные контрольные суммы](STAND-RUN.md)
