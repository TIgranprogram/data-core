# C169 — атомарная загрузка нового счёта поставщика

Дополнение scope после обнаружения разрывов C157. Не воспроизводить цепочку отдельных create request → create invoice → PATCH без общей квитанции.

## Контракт

- `POST /api/supply/invoices/intake`: `{uid,sourceSha256,fileId,supplierId,payerCompanyId,no,date,currency:'RUB',gross,vatMode,vatRate?,vatAmount?,lines:[{rowKey,title,qty,unit,unitPrice,amount}]}`. Печатный номер полностью, дата ISO, деньги в копейках при сверке. Только новый явно доказанный источник.
- `GET /api/supply/invoices/intake/:uid`: чтение результата/квитанции после повтора. Ответ `{uid,sourceSha256,invoiceId,requestIds,payloadHash}`; возвращать только после проверки действующего счёта, строк, сумм и файла. В обычной карточке счёта доступны его исходные реквизиты.
- Одной транзакцией сохранить счёт, все строки и ключи импорта. Уникальные sparse UID и businessKey на SupplyInvoice (коллекция только data-core); в общей SupplyRequest новых полей не добавлять, использовать существующие поля и стабильный clientUid.
- Тот же UID/hash → тот же результат; UID с другим payload, удалённый дубль, старая или новая редакция того же ключа → 409 с объяснением, не обновлять старую запись. Индекс отсутствует → 503 до первой мутации.
- До транзакции сверить доступ, роли сторон и ИНН, реально существующий PDF/SHA; зарезервировать original от удаления существующим sourceProtected механизмом. Scope категорий/склада не обходить. Валюты кроме RUB пока остаются исключениями, без выдуманного курса.
- Перед созданием искать все legacy/удалённые совпадения «поставщик/наша компания/полный нормализованный номер/дата» и источник SHA; неоднозначные не объединять автоматически. Нормализация полного номера сохраняет суффиксы.
- Строки и итог должны согласоваться, НДС проверять существующим финансовым helper. Сохранять исходные цены/суммы и единицы. Никаких оплат, складских движений, принятия/производства, автоматического подбора материалов или новых организаций.
- Квитанция должна быть доступна только тому, кому виден весь счёт и деньги. Контроллер до динамического invoices/:id, новый POST исключить из общего response-cache IdempotencyMiddleware (гарантия — предметная транзакция).

## Ownership и приёмка

Backend исполнитель: только `backend/src/modules/supply/` (новый адресный сервис/DTO/контроллер + регистрация в существующем модуле, поля/индексы SupplyInvoice), точечный exclude в app.module и адресные тесты. Photos — экспорт сервиса только если нужен, согласовать с upload исполнителем. Engine подключает этот контракт отдельно.

Тесты: strict DTO, суммы/НДС/пустые строки/неверные стороны, недостающий индекс, параллельный повтор, потерянный ответ, изменённый payload, legacy/удалённый дубль, ограниченные права, повреждённый PDF, rollback после сбоя строки. Число счетов/строк/оригиналов неизменно при повторе, оплаты/склад нулевые.
