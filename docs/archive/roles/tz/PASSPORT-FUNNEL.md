# ПВ. Паспорта «воронкой» и порядок в справочниках «Паспорта» (задание пользователя 2026-10-25)

Статус: аудит (analyst, data-steward, architect, designer — параллельно) → решение координатора → ТЗ исполнителям.

## Что сказал пользователь (суть)

1. **Старые паспорта не ценность.** Их тексты не беречь и не копировать в справочники как есть. Важно только создание **новых** паспортов.
2. **Выпущенный паспорт живёт сам.** После выпуска текст отделяется (снимок), правка справочника его не трогает. Справочник работает только с **изделиями** («Продукция») и новыми/черновыми паспортами.
3. **Путь «от изделия»:** выбрал изделие → оно тянет категорию и всё заполненное → поля паспорта заполнены сами → видно, чего не хватает, — внимание туда. Менять — в изделии (паспорт-шаблон хранится с изделием). Клон изделия целиком с поправками — быстрый способ сделать похожее. Копирование разделов у другого изделия — позже.
4. **Воронка:** 2–4 выбора — и паспорт почти готов. Каждый выбор отсекает лишнее: категория → раздел (например «Монтаж») → 2–3 варианта (анкерное / бетонирование / …) → при нужде подкатегория → один текст. Не 15 текстов, а 1–3 варианта на шаге. Если вариант один — подставляется сам.
5. **Универсальные тексты:** на вариант — один лучший универсальный текст (подходит любому изделию этой категории); не нравится — правка в справочнике.
6. **Галочки категорий у текста:** к каким категориям относится (благоустройство, спортплощадка, воркаут, …) + «Для всех». Так фильтры настраиваются в справочнике и ошибок меньше. У категорий благоустройства (воркаут и т. д.) — свой объём описания.
7. **Дубли — убрать.** В «Готовых текстах» 4 «Бетонирование опорных стоек», почти все пустые; «Анкерное крепление» 4, заполнено 2. Тексты, совпадающие по смыслу (пара предложений по-другому), — объединить: лучший вариант в одном месте, остальные удалить.
8. **Менеджер — минимум движений, максимум результата.** Интерфейс справочников паспортов (и общий, если так лучше) можно менять.

## Решение координатора (2026-10-25) — по отчётам `PASSPORT-FUNNEL-{analyst,architect,data-steward,designer}.md`

Основа — решение архитектора (`-architect.md`, «Правки по файлам»), логика шагов — аналитика (`-analyst.md`), вид — дизайнера (`-designer.md`). Где расходятся — так:
1. **Одно место для текстов разделов** — дерево в `passportPhrases` (подпись в справочниках: «Тексты паспорта»). «Назначение» берётся **только** из дерева; поле `purpose` у элементов в сборку раздела «Назначение» не идёт (так исчезает «Предназначено для: Предназначено для…»), в форме элемента скрыть. `passportInstall` — физический способ (схемы, рисунки, основание); `montage` — запасной путь, первая строка-дубль «Установки» удаляется чисткой.
2. **Вопросы П1–П4** — по умолчанию аналитика (пользователь может поправить).
3. **Спорные хранителя:** 1 — в корзину; 2 — убрать (одно место); 3 — убрать дубль норматива; 4 — не трогать, в справочнике метка «пусто», пользователь допишет.
4. **Клон изделия** (нужен пользователю): `POST /showcase/:id/clone` — копия изделия со всеми полями, фото, `passportDefaults` (с `textChoices`), `materialsSpec`; новое имя «… (копия)», артикул — автоартикул группы (или пусто); кнопка «Клонировать» в карточке изделия.
5. Скрипт хранителя `passport-dicts-cleanup.js` — имя принято.

### Контракт (backend ↔ frontend, фиксируется здесь)
- Узел дерева (`dict_values`, dict `passportPhrases`): `{ id, name, parentId|null, section ('purpose'|'installation'|… — у корня), text?, categories: 'TRN,WRK' , allCategories: bool, order: number, required: bool, isDefault: bool, installTypeId? }`. Корень = раздел (без текста), лист = есть `text`. Глубина ≤ 4.
- `GET /passports/funnel?category=TRN` → `{ sections: [ { id, name, section, required, order, children: [узел с children…] } ] }` — только узлы этой категории или «Для всех», по `order`, без корзины. Один запрос, кэш по версии `dict_values`.
- Выбор: `textChoices: { [rootId]: leafId }` — в `products.passportDefaults.textChoices` и в паспорте `textChoices` (DTO!). Сборка текста: лист выбора → текст раздела; итог пишется и в `purpose` / `installationMethod` (их читает kppdf).
- Автовыбор: если на уровне один подходящий вариант — сервер и форма ставят его сами; `isDefault` — подставляется, пока не выбран другой.
- `missing` паспорта: `choice:<rootId>` для обязательного раздела без выбора.
- Черновик пересобирается при открытии, если справочник новее `textSnapshot.at`; выпущенный — снимок, не меняется.
