# Товары, состав, снимки, производство — разбор (аналитик, 2026-10-26)

## 1. Что есть сейчас
| Таблица | Что хранит | Кто пишет | Связи |
|--|--|--|--|
| `products` («Продукция», модуль showcase/product) | наше изделие: `name` (одно), `sku`, `kind` good/service/work, цены, `composition[]`, `productModuleIds[]` | оба | категория, фото |
| `productmodules` | узел CRM: `name`, `article`, `materials[]`, `workTypes[]` (часы, дни), `composition[]` | в основном kppdf | материалы, виды работ |
| `materials` | ВСЁ закупаемое и сырьё: `materialKind` raw/part/fastener/purchased/other; у `part` свой `composition[]` | оба | категория, поставщик |
| `storageitems` | остаток на складе (зона, кол-во, бронь) | оба | `productId` ИЛИ `materialId` |
| `salesorders` + `incomes` | шапка заказа + строки (позиция = строка `incomes`: `title`, цена, `productId` необяз.) | data-core | заказ ↔ изделие |
| `productpassports` | паспорт: копия полей (name, article, размеры, `materials` строкой), `productId`, `orderNo` строкой | data-core | изделие; к позиции заказа ссылки нет |
| `worktypes` | виды работ (часы, дни, цвет на Ганте) | оба | — |
| kppdf: `orders`, `quotations` (КП) | строки с `productId` + снимок `productName`, `unitPrice` | kppdf | изделие |
| kppdf: `workers`, `workcenters`, `techprocesses`, `productionorders`, `ordertasks`, `workorders`, Гант в `orders` | производство: работник (`grade`, ставка, `workTypeIds`), задача (вид работ, работник, план/факт часов) | kppdf | заказ, изделие, вид работ |

Путаница:
- Два способа состава: старые `productModuleIds` / `materials[]` / `workTypes[]` и новый `composition[]` (lineType material/module/product). Оба живы.
- `materials` смешивает три смысла: покупное изделие, сырьё, деталь. Паспортный «материал» — вообще строка в паспорте.
- Два заказа: наши `salesorders`+`incomes` и CRM `orders`. КП в data-core нет.
- Название одно (`name`/`title`). Короткое имя позиции вычисляется кодом (`shortProductName`), не хранится.
- Остаток дублируется: `products.stockQty`, `materials.stockQty` и `storageitems.quantity`.
- Паспорт знает заказ только строкой `orderNo`.

## 2. Целевая схема (одна)
- **Продукция** = `products`. Что делаем и продаём. Поля: `name` (короткое, как сейчас), `fullName`, `orderName` (как в заказе по умолчанию). Отдельно — потому что у неё цена продажи, паспорт, КП.
- **Модуль/узел** = `productmodules`. Повторяемая сборка внутри изделий. Отдельно — один узел в многих изделиях; к узлу крепятся виды работ и часы.
- **Покупное изделие / сырьё / деталь** = `materials` (по `materialKind`). Поля: `name` (короткое), `fullName`, `invoiceName` (как в счёте). Новую таблицу НЕ заводить: общая с CRM, на неё ссылаются склад и заявки.
- **Позиция склада** = `storageitems`. Где и сколько лежит. Единственная истина остатка.
- **Состав (BOM)** = только `composition[]` в продукции, модуле, детали. Уровни: продукция → модуль/продукция → деталь → сырьё/покупное. Старые поля — только чтение.
- **Позиция заказа/КП** = строка `incomes` (у нас), `items` в kppdf. Ссылка `productId` + снимок: название, цена, кол-во.
- **Паспорт** = снимок изделия + название из позиции заказа. Нужна ссылка на позицию (`incomeId`).
- **Проектирование → производство**: `designorders` (есть) → техпроцесс изделия (виды работ, часы) → задачи по позиции заказа (вид работ, работник, план/факт часов, даты = Гант) → работники с категорией (`grade`) и видами работ. Таблицы уже есть в kppdf — брать их, не придумывать свои.

## 3. Живое и снимок
- Ссылка (меняется сама): справочники, категории, состав, остатки, виды работ, работники.
- Снимок (копия на момент): позиция заказа (название, цена), КП (уже так в kppdf), напечатанный/выданный паспорт (уже так: `textSnapshot`, ревизии).
- Сейчас не так: позиция `incomes` — только `title`, нет снимка цены каталога и отметки «отличается от каталога». Паспорт не ссылается на позицию заказа.

## 4. Готовность к производству
- Позволяет: `worktypes` общие; у модуля есть `workTypes[]` с часами; в kppdf готовы `workers`, `ordertasks`, техпроцесс.
- Мешает: позиция заказа у нас — строка `incomes`, у CRM — элемент `orders.items`; задачу привязать не к чему единому. Два состава. Нет стабильного id позиции, кроме `_id` строки `incomes`.
- Дёшево сейчас (только необязательные поля): `fullName`/`orderName` у `products`; `fullName`/`invoiceName` у `materials`; `incomeId` у паспорта; `productName`/`catalogPrice` снимком в `incomes`.
