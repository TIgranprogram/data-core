# Приложение «Склад · Снабжение»

**Адрес:** `https://kppdf-crm.ru/db/app/` — ПК и телефон, ставится иконкой («Установить приложение» / «На экран Домой»). Кнопка «← CRM» — назад в CRM; в шапке CRM есть кнопка «Склад · Снабжение». Код — [`backend/pwa/`](../../backend/pwa/) (vanilla JS, без сборки), отдаётся backend по `/app/`.

**Данные общие с CRM kppdf** ([docs/UNIFY-SUPPLY-WAREHOUSE.md](../../docs/UNIFY-SUPPLY-WAREHOUSE.md)): что внесено здесь — видно в CRM, и наоборот; Google-таблицы подтягиваются туда же.

| Экран | Что умеет | Где лежит |
|--|--|--|
| Снабжение | заявки: поиск, фильтры, создание и правка, «Оприходовать на склад» (приход + статус «☑️ Получено») | `supplyrequests` (поставщик и наша компания — `organizations`) — API `/api/supply` |
| Склад | позиции: остаток / в брони / свободно, приход, бронь, снятие брони, списание, корректировка, фото, история | `materials` + `storageitems` (склад по умолчанию) + `stockmovements` + `reservations` — API `/api/stock` |

- **Вход** — логином сотрудника (общие пользователи CRM и базы). Менять данные могут роли admin и manager, смотреть — все.
- **Офлайн:** приложение открывается из кэша, изменения копятся в очереди и досылаются сами. Дублей нет: у каждой операции `clientUid`, сервер не проводит её дважды.
- **Остаток** — число в `storageitems` (как в CRM); каждое движение пишется в журнал.
- Перехода «в день Х» больше не нужно: приложение, CRM и таблицы работают с одними данными. Правило: если одну и ту же строку поменяли в Google-таблице, при синхронизации побеждает таблица.

## Проверено (локально, реальные таблицы через робота Google, 2026-10-18)

Синхронизация: 157 заявок, 252 позиции + остатки, 142 движения, 20 организаций; повтор — 0 изменений; все записи проходят схемы CRM (0 ошибок). Приложение: оприходование заявки №161 → позиция заведена, остаток 5, заявка «Получено»; бронь 2 → в `storageitems` CRM: остаток 5 / бронь 2; запись «как из CRM» (+10, новая заявка) → видна в приложении (15 / своб. 13).
