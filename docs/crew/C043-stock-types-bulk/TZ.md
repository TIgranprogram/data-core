# ТЗ C043 — «Остатки»: плитки типов в 2 раза меньше, правильные типы, «Изменить выбранные» (тип, категория, группа)

**Зачем (пользователь 2026-11-07, после v1.599):** «Иконки типов слишком большие — уменьшить раза в два, чтобы и карточки уменьшились, а то долго листать. Названия типов перепроверить: „Алюминиевый“ — что алюминиевый? Внутри соединитель. Хочу выбрать несколько позиций и поменять им тип, категорию, группу — как в продукции „изменить выбранные“, — чтобы я сам исправлял неправильное на ходу.»
**Зачем — глаголом:** кладовщик видит все типы категории на одном экране без прокрутки; ошибочный тип исправляет сам: отметил 5 позиций → «Изменить выбранные» → «Тип: Соединитель» → готово.

**Важно:** проверить на v1.600 (C039 уже уменьшил плитки в раскрытой категории и сгруппировал типы) — замер «до» делать на v1.600, не на v1.599.

## Глубже
- **Результат:** компактные плитки; тип = существительное, а не прилагательное; ручная правка типа/категории/группы пачкой, ручной тип важнее вычисленного.
- **Сырьё:** тип вычисляется из имени — `core/facets.js` `index()` → `_f.type` (первое слово); «Прочее» в C039 = 19 огрызков (`docs/crew/C039-type-groups/REPORT.md`); плитки — `sections/stock-types.js`, `ui/kit/kit.css` `.k-expand`; массовые действия склада — `sections/stock.js:161` `bulk.extra` (сейчас «без „Изменить выбранные“»); эталон массовой правки — продукция (`grep -rn "Изменить выбранные" backend/pwa`); сервер позиции — `PATCH /stock/items/:id` (`stock.controller.ts:131`), `PATCH /materials/:id`.
- **Метод профи:** вычисляемое значение + ручное переопределение (override) с приоритетом; правило извлечения: пропустить прилагательные и материалы (алюминиевый, оцинкованный, нержавеющий…) → первое существительное; прогон по реальным именам (как `tools/c039-types.mjs`, данные — через datacore-access в `tools/logs/`, не в git).
- **Внешний судья:** `tools/c039-types.mjs` до/после: «Прочее» с 19 → ≤ 5 типов, 0 типов-прилагательных; юнит на правило; размер плитки типа на 1024: высота ≤ 50 % от текущей (замер JS на стенде).
- **Смелая планка:** все типы категории «Метизы» видны без прокрутки на 1024×768.

**Класс:** L · **Агенты:** frontend (sonnet), backend (sonnet, только если нужен серверный путь массовой правки), designer · **Проверки:** smoke; full — если менялся `backend/src`.

## Чек-лист
- [ ] 1. Плитки типов: иконка и карточка в ~2 раза меньше (вариант kit «card XS»/«compact» или параметр размера в существующем `card S` — решить по kit, витрина `#kit`); не менять плитки категорий верхнего уровня.
- [ ] 2. Правило типа: пропуск прилагательных/материалов в `facets.js`; таблица исключений рядом с `TYPE_FAMILIES`; отчёт до/после по реальным именам.
- [ ] 3. Ручной тип: необязательное поле позиции `typeName` (в `materials` — общая с CRM коллекция: только **новое необязательное** поле, схема `stock/schemas/` и копия kppdf — синхронно по AGENTS «ловушки»; если менять схему CRM нельзя без kppdf — хранить в `materials.facetOverrides` или своей коллекции, решение записать в отчёт); `index()` берёт `typeName`, если задан.
- [ ] 4. «Изменить выбранные» на «Остатках»: тот же эталон, что в продукции; поля: Тип (выпадающий список существующих типов + ввод нового), Категория, Группа/признаки (что есть в форме позиции). Один запрос пачкой, если есть bulk-маршрут; нет — серверный `PATCH /stock/items/bulk` {ids, set} (≤ 500, audit).
- [ ] 5. То же действие — в «Каталоге номенклатуры» для строк с позицией (переиспользовать).
- [ ] 6. Проверки: `--check`, design-lint 0, pwa-guards, юнит правила; дизайнер; full при правке сервера.

## Нельзя
Менять существующие поля общих с CRM коллекций; массово править данные прода скриптом (правит пользователь кнопкой «Изменить выбранные»).
