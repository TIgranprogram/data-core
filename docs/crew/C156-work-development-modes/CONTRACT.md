# C156 — контракт локального режима и разделение файлов

Стабильная работа: фиксированный `https://kppdf-crm.ru/db/app/`, без локальных UI/прокси/API-переключателей.
Разработка: существующий owned-run, локальный `/app/`, только его БД/тома/внутренняя сеть. Недоступность не переключает адрес.

## Метаданные на экране

PWA-файл `backend/pwa/development.json` в Git содержит только `{}`. Для owned-разработки compose подменяет его отдельным **только читаемым** bind-файлом из gitignored runDir. Рабочий production-файл остаётся `{}`. Инфраструктурный исполнитель владеет генерацией/монтированием, frontend — только stub и чтением.

Форма локальных публичных метаданных (без URI БД, паролей, токенов, персональных данных и абсолютных путей ПК):

```json
{
  "mode": "development",
  "origin": "http://localhost:3102",
  "data": { "backup": "datacore-2026-11-18_031040.tgz", "snapshotAt": "2026-11-18T03:10:40", "restoredAt": "2026-11-18T12:00:00Z" },
  "code": { "branch": "main", "head": "...", "dirty": true, "builtAt": "2026-11-19T12:00:00Z" }
}
```

snapshotAt — дата снимка из имени архива, restoredAt — реальное восстановление, builtAt — только после успешной сборки/ready. Недоказанное значение null, не подменять временем восстановления. Дополнительный отпечаток/статус устаревшей backend-сборки допустим, если привязан к реальному image/build; текущий HEAD нельзя выдавать за уже собранный backend.

Frontend читает метаданные **только на loopback** и только с того же origin, no-store; `mode` и `origin` должны совпадать. На production нет запроса метаданных, баннера и fallback. Статический `{}` не объявляет произвольный локальный backend безопасной разработкой. Файл метаданных не кэшируется SW; после переключения аккаунта отметка окружения остаётся, потому что принадлежит серверу, а не пользователю.

Баннер: «Разработка · копия данных от …», при неизвестной дате это явно указать. В подсказке — архив/восстановление/сборка. Без кодов/секретов и отдельной анкеты окружения.

## Владение исполнителей

**Инфраструктура:** `tools/work-modes.mjs`, `tools/work-modes.test.mjs`, `tools/night.mjs`, `tools/night-stand.mjs`, `tools/night/compose.yml`, при необходимости `tools/night-owner.mjs`; `pult/catalog.mjs`, `pult/docs/КОМАНДЫ.md`. НЕ меняет backend/pwa и корневые docs/AGENTS/CLAUDE. Режимы CLI start/check; рабочая ссылка — существующий run.open. Три кнопки видимы без «служебных». Git-кнопки переиспользовать, не делать автоматических commit/stash/merge/push и загрузку новой БД при каждом запуске.

**Frontend:** `backend/pwa/development.json` (stub), `backend/pwa/core/development-mode.js`, точка bootstrap `backend/pwa/main.js`, общая оболочка/стили при необходимости, SW и его тесты, import/preload-регистрация. НЕ меняет паспортные sections, инструменты или каталог пульта. Только отображение режима, без настройки API. Проверки парсинга/отсутствия запроса на production — осмысленные guard-тесты.

**Координатор:** C156 docs, `pult/README.md`, Git-инструкции AGENTS/CLAUDE, BACKLOG/BOARD/CONTROL/MAP/ARCHITECTURE при затрагивании соответствующих правил. После C156 — отдельный C155 контракт и код.

Уточнение scope инфраструктуры: минимальная переносимая реализация открытия браузера в `pult/server.mjs` и регистрация тестов в `tools/run-all.mjs` разрешены. Автоматический git pull в пульте запрещён при работающем локальном backend/owned-стенде: bind-PWA иначе обновится без пересборки backend. Ручное обновление явно, после него запуск разработки выполняет refresh. Финансовые/production-права пульта не менять.

Любые общие файлы вне списка согласовать через координатора. Исполнители не одни в репозитории, чужое не откатывать. Не создавать новых агентов и не коммитить.
