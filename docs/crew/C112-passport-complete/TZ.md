# ТЗ C112 — паспорт: грамотный документ при минимуме ввода

**Зачем (владелец, 2026-11-14):** «Довести до состояния, что создание паспорта полностью реализовано. Воронка экономит время: менеджер сосредоточен на том, что делает. Проверить связи и автозаполнение, отказоустойчивость, узкие места. Тексты пробежать локальными моделями. Цель — грамотные паспорта минимальным заполнением: вводим только то, чего на сайте нет, — чертежи или данные.»
**Зачем — глаголом:** менеджер выпускает паспорт позиции заказа, вводя только отсутствующее на сайте; всё известное сайт подставляет сам и показывает, откуда взял.

### Э1. Автозаполнение (минимум ввода)
- **А1 (В1).** Умолчание типа паспорта считается заполненным: в паспорт идёт значение по умолчанию, поле помечено «по умолчанию — из типа паспорта», правка по желанию. Кнопка «Принять» убирается. Сервер: `passport-gaps` и выпуск не считают такое поле пробелом. Контракт API не ломать: поле ответа добавить, не менять.
- **А2 (В2).** Изделия с убранным вариантом: скрипт-план «было → станет» (ближайший действующий вариант по ключу/названию), неясные — списком владельцу. Запись — кнопкой в пульте после его «да» (`pult/todo.json`), с копией базы. Сервер при удалении варианта из справочника — запрет, если на него ссылаются изделия (409 с числом изделий).
- **А3 (В3).** Подсказка «Похоже: … — верно?» для назначения и элементов работает в анкете воронки и в панели заказа; принятая — сохраняется в изделии (один раз на изделие, не на каждый паспорт).
- **А4 (В7).** Фото изделия из карточки подставляется в «Общий вид» автоматически, с пометкой источника и кнопкой «Заменить».
- **А5 (В8).** Материалы: если у изделия есть состав (спецификация) — предложить таблицу материалов из него в анкете («Взять из состава»), без ухода в другой раздел.
- **А6.** Габариты и масса: если изделие загружено из PDM (`apps/pdm-loader`, глубина Г — коммит `daa75e9f`) — Д×Ш×В и масса подставляются сами. Проверить на изделии 6104; нет данных — пробел остаётся.
- **А7.** Правило экрана: у каждого подставленного значения видно, откуда оно («из изделия», «из вида», «по умолчанию»). Источники — `docs/crew/C096-passport-system-audit/SOURCES.md`; расхождения с таблицей — в отчёт.

### Э2. Воронка: внимание на одном деле
- **Ф1 (В4).** Внизу анкеты — постоянная полоса: «Осталось N: <что> →» и «Выпустить». Кнопка неактивна с причиной словами; активна — главная. Заполненные разделы свёрнуты (есть), открыт только раздел с первым пробелом.
- **Ф2 (В5).** Список изделий — на всю высоту панели, одна прокрутка, без горизонтальной.
- **Ф3 (В6).** Подписи: один термин «тип паспорта»; фраза «Дальше: …» без двойных двоеточий — через `core/grammar.js`.
- **Ф4.** После выпуска — следующий шаг кнопками: «Печать…» и, если паспорт из заказа, «Следующая позиция» (следующая незаполненная).
- **Ф5.** Замер касаний: «карточка заказа → PDF готового изделия» и «→ PDF изделия с одним пробелом». Число — в отчёт; цель ≤ 3 и ≤ 5.

### Э3. Отказоустойчивость и узкие места
- **Р1 (В9).** Скрипты правки данных: общий помощник записи повторяет при 503/`READ_ONLY` по `retryAfter` (до 5 раз), итог честный: «записано / повторено / не записано». Тест помощника.
- **Р2.** Анкета при обрыве связи и `READ_ONLY`: очередь сохранения (`fill/save-queue.js`) сама повторяет после `retryAfter`; пользователь видит «сохраню, когда сервер вернётся», ввод не теряется. Тест очереди.
- **Р3.** Двойное нажатие «Выпустить готовые» и выпуск из двух вкладок: номера не дублируются, второй запрос получает понятный отказ. e2e: два параллельных `POST /passports/order/:id/issue`.
- **Р4.** Картинка: битый или слишком большой файл отклоняется при загрузке с понятным текстом, а не при выпуске («рисунок не читается»). Тест.
- **Р5.** Печать заказа: один паспорт не собрался — остальные печатаются, список несобранных с причиной (сейчас — проверить e2e).
- **Р6 (В10).** Выкладка не ломает открытую вкладку: несовпадение версий модулей → мягкая перезагрузка раздела, а не красная ошибка. Проверить `sw.js` и загрузчик разделов; правило в `pwa-guards`, если его нет.
- **Р7 (В11).** «Документация» открывается < 1 с на стенде с копией базы: `/showcase` для списка — только нужные поля и порция; `/passports/next-numbers` — не на открытии раздела. Замер до/после в отчёт.
- **Р8.** Заказ на 50 позиций: план паспортов `GET /passports/order/:id/plan` < 1 с; выпуск пачкой < 10 с. Замер на стенде.
