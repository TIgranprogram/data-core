# ТЗ C260 — Склады через API (первый срез ухода от kppdf)

**Программа:** [C259 PLAN-SLICES](../C259-crm-api-client-plan/PLAN-SLICES.md) · L-259  
**Класс:** L · **Max agents:** 2 (backend + qa) · **Проверки:** smoke на срез; **full перед выкладкой**  
**Старт кода:** только после пункта «лимит свежий» + явной фразы владельца «старт C260»

## Зачем
Старая CRM пишет склады в Mongo напрямую. C260 переводит **только** сценарий складов (`warehouses`: создать / правка / снятие / один `isDefault`) на API data-core. Остаток, движения, бронь, приход — **не** этот срез (C261–C265 отдельно).

## Глубже
- **Результат:** kppdf не пишет `warehouses`; откат — флаг назад.
- **Сырьё:** PLAN-SLICES C260; сейчас есть только `GET /api/stock/warehouses`.
- **Судья:** tsc + jest stock; флаг вкл/выкл; без правки чужих коллекций.

## Что сделать (когда стартуете код)
1. POST/PATCH (и снятие) складов у хозяина `stock` / `stock-writes`.
2. Флаг сценария: вкл = только API; выкл = снова прямой Mongo у CRM.
3. Места записи kppdf по складам — только чтение, список в REPORT.
4. Не трогать `storageitems` / движения / зоны как замену складам.

## Критерии приёмки
- [x] API пишет `warehouses`; сценарий с флагом откатывается
- [x] Другие shared не менялись
- [x] smoke зелёный; full — перед выкладкой, не в этом коммите обязательно

## Нельзя
- C261–C265 в том же коммите / «заодно»
- Снимать Mongo `readWrite` у пользователя `kppdf`
- Прод без отдельного «да» на выпуск
- `replaceOne` / `save()` всего документа shared
