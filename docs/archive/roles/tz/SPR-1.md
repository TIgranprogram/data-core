# ТЗ SPR-1 — справочники вместо свободного текста; форма «Новая позиция склада»

**Зачем (словами пользователя, 2026-10-23):** «открыл новую позицию склада — нет выпадающих списков: сортамент, марка стали… их 10–30, пусть будут в справочниках и выбираются из списка, тогда не будет разного написания и фильтры заработают правильно. Списки — пусть грузятся постепенно, чтобы сайт не вис. Толщина, длина, ширина — компактно, большие поля не нужны. Проверь все такие места и сделай справочники по категориям, как у нас принято».

**Роли:** аналитик ☑ · архитектор (проверка итога) ☑ · backend ☑ · frontend ☑ · qa — по итогу · дизайнер (проверка итога) ☑

Правило — `docs/CANON.md` §5 и `docs/roles/README.md` «Постоянные требования пользователя».

## Часть А — аналитик: аудит всех форм
1. Пройти поля всех форм «Рабочего места» (`backend/pwa/sections/*.js`, `form: { fields … }`, а также `ui/*` с полями ввода) и админки. Найти поля со свободным текстом (`max:`, без `type: 'select'|'combo'` или со статичным списком в коде), у которых по смыслу ограниченный набор значений.
2. Для каждого: раздел/форма · поле (key) · есть ли уже справочник (Grep в `backend/src/modules/dicts/dicts.defs.ts`, `/supply/lookups`, `units`, `color_references`) · предложение: «новый справочник <ключ> в группе <раздел>» / «взять существующий <ключ>» / «оставить текстом — почему».
3. Результат — таблица в разделе «Аудит полей» этого файла (ниже). Вопросы пользователю — в `docs/QUESTIONS.md`.
4. Код не трогать.

## Часть Б — backend: справочники металла
1. В `backend/src/modules/dicts/dicts.defs.ts` — два справочника в группе склада (как у соседних `simpleList` этой группы): `metalAssortments` «Сортамент / сечение» (подсказка «Труба 40×20×2, лист 2 мм…») и `steelGrades` «Марки стали» (Ст3, 09Г2С, AISI 304…). Счёт «используется в N» — по `materials.assortment` / `materials.materialGrade` (как `usage` у соседей).
2. Скрипт `backend/scripts/seed-metal-dicts.js`: собрать уникальные непустые значения `materials.assortment` и `materials.materialGrade` (без учёта регистра и пробелов, одно написание — самое частое) → в `dict_values` (`dict: metalAssortments | steelGrades`), только добавляет, существующие не трогает; по умолчанию «план», запись — `--apply`. Запускает на проде координатор.
3. Ничего в схемах `materials` не менять (общая с CRM). Значение в позиции остаётся строкой — справочник даёт список для выбора и фильтров.
4. Тест на справочники (как `dicts.passport-usage.spec.ts`, если уместно). `tsc`, jest `src/modules/dicts`, eslint.

## Часть В — frontend: форма позиции склада
1. `backend/pwa/sections/metal.js` (`metalFields`): «Сортамент / сечение» и «Марка стали» → поле с выпадающим списком (`type: 'combo'`) из справочников `metalAssortments` / `steelGrades`; **варианты грузятся при первом открытии поля** (не при открытии формы) — если в `ui/form.js` combo не умеет ленивые варианты, добавить это в общий компонент (`options` — функция или промис, загрузка по первому фокусу, кэш). Можно вписать своё значение.
2. Толщина, длина, ширина — компактно в одну строку: узкие поля (`span: 1`, единица в подписи «мм» / «м»), без длинных подсказок под каждым — одна общая строка-подсказка под строкой.
3. Фильтры «Остатков» по марке/сечению (`grade`, `section` в `stock.js` / `facet-filter.js`) — варианты из тех же справочников (если фильтр сейчас собирает их из данных — оставить, но без дублей разного написания).
4. По скиллу `datacore-design`; новое в виде — строка в DESIGN §8. Проверка: `node --input-type=module --check`, `npx jest src/pwa-guards`.

## Критерии приёмки (qa)
- [ ] В форме новой позиции склада сортамент и марка стали выбираются из выпадающего списка с поиском; варианты подгружаются при открытии поля; своё значение вписать можно.
- [ ] Справочники «Сортамент / сечение» и «Марки стали» видны в «Справочниках», заполнены значениями из склада (скрипт: план → `--apply`).
- [ ] Толщина / длина / ширина — в одну строку, узкие поля, на 390 px — без горизонтальной прокрутки.
- [ ] Аудит полей (часть А) — таблица заполнена.
- [ ] tsc 0; юнит dicts и pwa-guards зелёные; синтаксис изменённых pwa-файлов.

## Нельзя
Менять схему `materials` и другие общие с CRM коллекции; запускать скрипты на проде; коммитить.
