# C116 — Справочники: меню, поиск, фильтры и эталонный вид

Дата: 14.11.2026. Статус: ТЗ подготовлено, реализация не начата.

**Просьба владельца:** исправить меню, поиск и фильтры «Справочников», привести внешний вид к эталонам проекта.
**Результат:** сотрудник быстро находит справочник, отбирает нужные записи и понимает, как снять ограничения.
**Класс реализации:** M, один раздел. До двух агентов одновременно: исполнитель и проверяющий. Независимая приёмка — designer; поведенческие критерии проверяет QA последовательно. До двух циклов замечаний. Если требуется изменение серверного контракта — отдельно описать причину и расширение задачи.

## Глубже

- Сырьё: снимок владельца `SOURCE.png` рядом с ТЗ; текущий `#dicts`; исходники перечислены ниже.
- Снимок показывает длинную навигацию и плотную строку заголовка, пояснения, поиска и действий. Это исходное состояние, не эталон.
- Подтверждено чтением кода: `renderTable()` возвращает пустое состояние до создания фильтра качества. При нулевой выдаче управление фильтром исчезает.
- Подтверждено чтением кода: открытие паспортных подгрупп определяется общим `here`; выбор одного справочника раскрывает все паспортные подгруппы. Поиска по названиям справочников в меню нет.
- Не объявлять прочие дефекты воспроизведёнными до проверки браузером. В частности, проверить гонку загрузки при быстром переключении.
- Метод: сравнить действующие kit-компоненты и их поведение, исправить причины, проверить заполненные состояния.
- Внешний судья: целевые тесты поведения, геометрия и доступность, снимки и независимый `UI-REVIEW.md`.
- Планка: после ввода названия справочник выбирается одним нажатием; сброс ограничений — одно действие; нулевая выдача никогда не блокирует управление.

## Границы и принятые решения

1. Работать с `#dicts`, включая его навигацию к специальным редакторам. Глобальное меню и глобальный поиск приложения не переделывать.
2. Сохранить существующие справочники, ключи, права, маршруты и назначения. Не объединять категории, группы и разделы изделий.
3. Поиск в меню ищет **справочник**. Поиск справа ищет **записи выбранного справочника**. Это два независимых состояния.
4. «Найти в данных…» — существующий подбор кандидатов на добавление. Не превращать его в третью поисковую строку и не менять импорт.
5. «Эталонный вид» означает текущие `DESIGN.md`, токены и kit. Не копировать цвета снимка, не создавать новую тему.
6. Фильтры вводить только по существующим данным. Никаких фиктивных переключателей «Активные/Архивные» без соответствующего контракта.
7. Это исправление интерфейса, а не чистка данных. Прод не изменять. Коммит и выкладка исполнителю не поручены.

## Что сделать

### 1. Меню справочников

- Над навигацией добавить kit.searchBox с подписью «Найти справочник» и очисткой.
- Искать по названию пункта и его смысловой группе, без учёта регистра и крайних пробелов. Совпадение группы показывает её доступные пункты.
- В результатах сохранять названия групп. На время поиска раскрывать группы с совпадениями; очистка возвращает прежнее раскрытие.
- Пустой результат меню: «Справочник не найден», действие очистки. Список записей справа при этом не очищается.
- Привести заголовки групп и их раскрытие к единому navList. Сохранить смысловые группы и четыре паспортные подгруппы.
- При первом входе раскрыть группу текущего пункта. При выборе раскрывать нужную группу, а не все паспортные подгруппы.
- Ручное раскрытие сохранять в пределах текущего посещения раздела, включая обновление списка. Постоянное хранение не требуется.
- Активный пункт различим фоном, маркером и доступным состоянием; длинные подписи читаемы. Число справа — общий размер справочника, не число результатов поиска.
- Выбор, скрытый поиском меню, не меняется автоматически. Скрытые правами пункты не появляются в поиске.
- Прямой вход `#dicts?d=...`, переход к контрагентам и специальным редакторам сохраняются.
- На телефоне использовать адаптивный общий выбор справочника с поиском. Пункты и группы остаются доступны; отдельной обрезанной колонки нет.

### 2. Поиск записей

- Видимая подпись «Поиск в справочнике», подсказка «Название, код или описание». Область поиска должна соответствовать реально доступным полям.
- Сохранить существующую нормализацию, поиск по нескольким словам, латинским кодам и специальным словам покрытий. Не заменять её простым поиском только по имени.
- Поиск пересекается со всеми активными фильтрами по правилу И. Изменение запроса не сбрасывает фильтры.
- Очистка крестиком очищает только запрос; «Сбросить всё» — запрос и фильтры текущего списка.
- При смене справочника сбрасывать запрос и фильтры записей; строка поиска меню остаётся независимой.
- После сохранения записи в том же справочнике сохранять условия отбора. Если запись перестала подходить, это нормальное исчезновение из выдачи.
- Быстрые переходы A → B → C не должны подменять C запоздавшим ответом A. Проверить также ошибку запоздавшего запроса.
- Существующую задержку 150 мс сохранять, если замер не требует изменения. Не отправлять сетевой запрос на каждый символ при полном локальном наборе.
- Проверить полноту набора `items`: поиск не должен молча работать только по первой странице. Если контракт ограничивает набор, описать необходимое решение отдельно.

### 3. Фильтры и состояния

Панель отбора находится вне заменяемой таблицы. Она остаётся видимой при загрузке, ошибке и нулевой выдаче, сохраняя понятные доступные действия.

| Контекст | Фильтр | Источник и правило |
|--|--|--|
| Обычный справочник | Все / Дубли | Существующий `qualityFilter` и `dupeCounts`, без изменения бизнес-правила дубля |
| Группы изделий | Раздел | Существующая связь с разделом; варианты из справочника связей, значение «Без раздела» для незаполненных |
| Записи с поддержанным `kind` material/coating | Вид: Все / Материалы / Покрытия | Только если это реальное поле конкретного справочника; не определять вид по названию |
| Специальные редакторы текстов, шаблонов и складов | Их собственные фильтры | Сохранить существующие; не накладывать универсальные фильтры таблицы на редактор |

- Это минимальный объём фильтров по принятому допущению: владелец не перечислил конкретные поля. Дополнительные фильтры — предложение в отчёте.
- Разделы сравнивать по устойчивому идентификатору; если API даёт только имя, зафиксировать ограничение до реализации такого фильтра.
- При отсутствии дублей «Дубли · 0» остаётся понятным состоянием; не сбрасывать выбранный фильтр молча после обновления данных.
- Показывать «Найдено N из M»: M — полный доступный набор текущего справочника, N — пересечение условий. Не подменять этим счётчики меню.
- Активные фильтры видимы, каждый можно снять. «Сбросить всё» доступно при любом активном условии, в том числе с нулевой выдачей.
- Отличать «Справочник пока пуст» от «По выбранным условиям ничего не найдено». Во втором состоянии предлагать сброс, в первом — добавление только при наличии прав.
- Сортировка «По номеру / По названию» сохраняется и не выдаётся за фильтр. Сброс отбора не меняет выбранную сортировку.

### 4. Визуальный вид

- Разнести шапку на логические строки: заголовок и действия; пояснение «Применяется в»; поиск и фильтры.
- Заголовок, пояснение и поле поиска не конкурируют за одну сжимаемую строку. Длинное пояснение переносится.
- Основное действие — «Добавить»; «Найти в данных…» второстепенное, с понятным пояснением назначения. Права видимости сохранить.
- Использовать `layout.split`, `navList`, `toolbar`, `searchBox`, `select`, `qualityFilter`, `table`, `section`, `actions`, `empty`.
- Сопоставить с действующими эталонами в `#kit`; записать названия и снимки сравнения. Доступ manager к `#kit` не расширять ради проверки.
- Шрифты, контраст, отступы, размеры кнопок, поля и состояния — из токенов. На компьютере базовые элементы 36 px, компактные действия 30 px; на телефоне зоны касания от 44 px.
- Не растягивать короткие кнопки действий по строке; названия и описания получают основную ширину. Длинный текст доступен полностью через установленный общий паттерн.
- Сохранить адаптивную таблицу `k-table-stack`, замки встроенных записей, предупреждения дублей, цветовые образцы.
- Скролл навигации не обрезает последний пункт; поиск меню доступен при прокрутке. Вся страница не прокручивается горизонтально.
- Создание и изменение остаются в правой панели. Новые формы и изменение полей записи в задачу не входят.
- Если kit не поддерживает необходимое состояние — расширить общий компонент и витрину, затем подключить раздел. Частный CSS допустим только для раскладки.

## Разрешённые изменения

Основные: `dicts.js`, `dicts-search.js`, `dicts-sort.js`. Общие компоненты/стили — только необходимое расширение и регрессия второго потребителя. Тесты — в принятом месте проекта. Документы — карта, помощь и затронутые дизайн-правила по docs-sync. Новые модули PWA требуют обновления modulepreload штатным скриптом.

Серверные схемы, контракт API, данные, права, миграции, глобальную тему и редакторы паспортов не менять. Соседние задачи C115 и другие изменения не откатывать; при параллельной работе использовать отдельный worktree.

## Порядок выполнения и проверки

1. Зафиксировать исходную ветку, изменения и воспроизводимые дефекты. Запустить `tools/dc.cmd atlas справочники`; записать план в CHECKLIST.md рядом.
2. Подготовить заполненные тестовые данные: обычные категории, 100+ записей, длинное имя/описание, код GALV_HOT, дубли одного материала, одинаковые имена разных материалов, группы с разделом/без него, материалы/покрытия, встроенная запись, пустой набор.
3. Исправить навигацию, независимые поиски, отбор и защиту загрузки. Затем привести раскладку к kit.
4. Добавить поведенческие тесты: поиск + фильтр → 0 → сброс; независимость двух поисков; сброс при смене справочника; сохранение условий после reload; раскрытие нужной подгруппы; поздний ответ не меняет текущий экран.
5. Проверить нормализацию кода и русских слов, пробелы, несколько слов, очистку и полный объём поиска. Сохранить существующее правило дублей.
6. Пройти admin и manager: видимые пункты, разрешённые действия, отсутствие скрытых полей оплаты. Существующие сценарии добавления, правки, удаления занятой записи и отмены проверить только в изолированном контуре.
7. Проверить специальные экраны и возврат к обычному списку: не остаются чужие фильтры, заголовки и кнопки.
8. Проверки по datacore-verify: tsc и юнит; синтаксис изменённых ES-модулей через `node --input-type=module --check`; `dc check` для карты/импортов. Результаты с командами сохранить. Full/e2e перед выпуском — по правилам проекта, выпуск в эту задачу не входит.
9. Проверить обе темы на ширинах 390, 1024, 1920, 2560 px. Для каждой — заполненный список и открытое меню/фильтр. Дополнительно нулевая выдача, длинные подписи, фокус клавиатуры, правая панель.
10. Сначала геометрия/доступность, затем открыть и оценить снимки. Для общей правки компонента проверить минимум ещё одного потребителя. Детерминированный дефект закрепить тестом или точечным правилом `tools/site-audit.mjs`.

Доступ к стенду/проду — только datacore-access по AGENTS; прод только чтение. Нет стенда или данных — честный PARTIAL. Макет с подменой API доказывает раскладку, но не сохранение данных.

## Критерии приёмки

- [ ] Найден и выбран справочник из свёрнутой группы; очистка восстанавливает меню; права соблюдены.
- [ ] Выбор одного паспортного справочника не раскрывает автоматически все подгруппы.
- [ ] Два поиска независимы; название, код и доступное описание находятся по принятой нормализации.
- [ ] Фильтры применимы выбранному справочнику; поиск и фильтры работают совместно.
- [ ] Нулевая выдача сохраняет фильтры и сброс; N/M корректны; сортировка отделена от отбора.
- [ ] Быстрое переключение не показывает данные предыдущего справочника.
- [ ] Специальные редакторы, прямые ссылки, права и действия записи не сломаны.
- [ ] Нет горизонтальной прокрутки страницы, наложений и недоступных пунктов на четырёх ширинах в обеих темах.
- [ ] Клавиатура: Tab, Enter, Escape в раскрываемом выборе, видимый фокус; у полей есть доступные и видимые подписи.
- [ ] Проверки пройдены; снимки просмотрены; независимый дизайнер подтвердил конкретную версию.
- [ ] Карта/помощь обновлены вместе с поведением; REPORT и UI-REVIEW содержат доказательства и ограничения.

## Артефакты исполнителя

`CHECKLIST.md` — шаги и состояние; `REPORT.md` — до 20 строк, PASS/FAIL/PARTIAL, изменения, проверки, риски, допущения; `UI-REVIEW.md` — версия, данные, матрица тем/ширин/состояний, ссылки на просмотренные снимки, сравнение с kit. Снимки — в подпапке `evidence/`.

ТЗ не является результатом приёмки. Статус реализации на момент подготовки: не начата.
