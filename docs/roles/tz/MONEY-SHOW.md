# ТЗ MONEY-SHOW — «Деньги» к показу финдиректору (волна 1)

> Аудит: `docs/crew/C021-money-audit/AUDIT.md` · данные прода: `REPORT.md` · вид: `DESIGNER.md`.

**Зачем:** сегодня визит финансового директора — раздел «Деньги» должен выглядеть честно и аккуратно: ясно, что это факт оплат, не банк; цифры читаются; пустые состояния с подсказкой.

**Класс:** L · **Max agents:** 4 (frontend, backend при метриках, qa, designer) · **Reviewers:** qa ☑ designer ☑ · architect ☐ · **Max review loops:** 2 · **Проверки:** smoke  
**Язык менеджера:** да · **Приёмка:** глазами вкладки Сводка и Календарь (сценарий ниже)

## Shared pack

- На проде сейчас: приход 0, 186 позиций без цены, старт 01.11 остатки 0, расход ноября 158 575 ₽.
- Сценарий показа (координатор / пользователь): открывать **Сводку**; **Прогноз не открывать**, пока остатки нулевые или нет цен.
- Данные прода (цены, остатки, счета) — **менеджеры** по `REPORT.md`; код их не выдумывает.
- Волна 1 **не** делает: банк, CSV календаря, прибыль по заказу, правку шапки заказа, JWT, View-as.

## Сценарий показа (текст для встречи)

1. «Деньги считают оплаты заказов и оплаченные счета поставщикам — без второй таблицы.»
2. Сводка: «Поступлений в базе пока нет: в заказах не вписаны цены / нет платежей. Расходы по оплаченным счетам видны.»
3. Если старт учёта с нулевыми остатками: «Минус на календаре — от нуля на дату старта, это не выписка банка.»
4. «Требуют заполнения» — очередь, чтобы календарь был полным.

## Что сделать

### A. Frontend вид (`datacore-frontend`) — обязательно сегодня

Файлы: `backend/pwa/sections/money.js`, `money-forecast.js`, CSS раздела (существующие классы / kit), точечно `help-flow-data.js` если врёт про прогноз.

1. **Сводка — главный экран встречи.** Над цифрами одна понятная фраза, если приход за период = 0 и есть отгрузки без цены / без платежей (формулировка менеджера, без кодов API).
2. **Убрать или сильно упростить «шесть плиток» календаря**, если они дублируют одни суммы разными словами («поступило / сальдо / итог») и спорят с иерархией DESIGN (см. DESIGNER.md).
3. Календарь: вместо пустой клетки показывать **«0»**; та же честная фраза про отсутствие поступлений, когда метрики нулевые.
4. Заменить `Итого (Total)` / английское на русское («Итого за …» / «Итого за период»).
5. Единый словарь слов: поступления · выплаты · итог (не плодить синонимы на одном экране).
6. Полоски/акценты: ноль прихода не красить как «успех» (зелёная полоса на нуле — убрать или нейтральный тон).
7. Прогноз: если остаток на старте 0 и expectedIncome 0 — не выглядеть как «кассовый разрыв компании»; подсказка «остаток от нуля на дату старта, не банк» (или скрыть вкладку до заполнения старта — решение исполнителя по DESIGNER, согласовать с координатором если спор).

### B. Backend метрики (`datacore-backend`) — если успеваем в той же волне

Файлы: `backend/src/modules/finance/finance.service.ts`, `forecast.ts` (+ спеки).

1. **Календарь / шапка периода:** «счета к оплате» и просрочка не должны быть 0, когда прогноз на сегодня показывает N просроченных (сейчас расхождение: календарь ноября «к оплате 0», прогноз 33 шт.). Выровнять отбор `pending` с периодом/«на сегодня».
2. Не ломать контракт ответа cashflow; только поля/логику отбора, юнит `cashflow.spec` / `forecast.spec`.

### C. Не в этой волне

Шапка заказа с частичными платежами; CSV сводки; прибыль по заказу; частичная оплата поставщику; банк; правка данных прода скриптом.

## Критерии приёмки (qa)

- [ ] Сводка: нет английского Total; при нулевом приходе — понятная фраза, не «успешный» зелёный ноль.
- [ ] Календарь: нули видны как «0»; нет пустых клеток вместо нуля.
- [ ] Плитки не дублируют одну сумму тремя названиями (или убраны).

- [ ] Если делали B: при наличии просроченных счетов шапка/метрики календаря их отражают согласованно с прогнозом (юнит зелёный).
