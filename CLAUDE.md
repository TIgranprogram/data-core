@AGENTS.md

## Для Claude Code

- Начинай с `docs/MAP.md`, точечно открывай файлы модуля. Для широкого поиска — Grep/Glob, не чтение каталогов целиком.
- Перед задачей из бэклога загляни в `docs/TASKS.md`: там уже есть контекст, файлы и критерий готовности.
- Используй скиллы проекта (`datacore-verify`, `datacore-new-module`, `datacore-docs-sync`, `datacore-deploy`) вместо выдумывания процесса.

## Перед правкой вида — обязательно

- Любая правка интерфейса (`backend/pwa`, `backend/admin`: новый экран, окно, форма, кнопка, CSS) — **сначала skill `datacore-design`** (он ведёт в `docs/DESIGN.md`). Без него не начинать: так появилось модальное окно «+ Счёт» вместо правой панели (2026-10-20).
- Ввод данных — только в правой панели; новых видов окон/компонентов без записи в DESIGN не вводить.

## Экономия токенов (правило пользователя 2026-10-20 — обязательно)

- **Проверка по размеру правки, не «всё подряд»** (подробно — skill `datacore-verify` §0):
  только `backend/pwa/` или `backend/admin/` → `node --input-type=module --check < файл` изменённых файлов (простой `node --check` не ловит ошибки ES-модулей), без typecheck/юнит/e2e и **без пересборки QA** (стенд монтирует pwa/admin как папки — достаточно обновить страницу);
  `backend/src/` → `tsc` + юнит **только затронутого модуля** (`npx jest src/modules/<имя>`); полный юнит + e2e — **один раз перед выкладкой/коммитом**, не после каждой правки.
- **Снимки экрана — только по просьбе пользователя.** Если без снимка правда не обойтись — сначала спросить разрешения одной строкой (зачем). Текст/числа — через `get_page_text`/JS.
- **Тесты — только там, где есть риск поломки** (меняли код и есть предположение, что могло сломаться). Полные прогоны записываются в `docs/TEST-LOG.md` (дата, коммит, итог); если код с последней записи не менялся — не повторять.
- **Вывод команд — коротко:** всегда `| tail -N` / `grep`; git — без простыней (`core.safecrlf=false` уже стоит).
- **Не перечитывать** файлы, которые уже в контексте; большие — по `offset/limit` или `grep`.
- **Рутину — дешёвому агенту** (Agent, `model: "haiku"` или `"sonnet"`): прогон тестов и разбор ошибок, проверка доков/ссылок, массовые однотипные правки, сбор данных. Себе — решения, дизайн, сложный код. Агенту давать полный бриф: файлы, что сделать, критерий «готово», «не коммитить».
- **Крупное — в очередь** (TASKS «🧰 Большие задачи»), не в рабочий разговор.
- **Лимиты плана (правило пользователя 2026-10-21):** смотреть `get_usage` в начале и после каждой задачи; каждую законченную задачу — сразу коммит + пуш, не дожидаясь конца лимита. Недельный > 85 % или 5-часовой > 80 % — без параллельных сессий и агентов, только мелкие задачи. Когда лимиты есть — можно оркестратор (параллельные сессии).
