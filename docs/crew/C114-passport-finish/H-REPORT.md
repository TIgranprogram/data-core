- Воронка паспорта из карточки: кнопка «Выпустить паспорт» (`card-blocks.js:146`) открывает `openPassportFunnel({productId})`. Воронка сама ведёт к первому пробелу (`funnel/index.js:187-200`, `focusGap`).
- Общий аудит «Требуют заполнения» (`fill-audit.service.ts`, экран `fill.js`): для изделий там только `product-check` (пометка после переноса каталога, строка 145). Заполненности самого изделия там нет.
- Эталоны для полос и чипов уже есть: `miniChart` с type bar (`ui/kit/blocks.js:41`, `kit.css:599`), `stageBar`, `headStats`, `badge`, `hint`, `section`, `row`, `actions`. Новые компоненты не нужны.

## 2. Чего нет
1. Единой заполненности изделия («заполнено N из M»). Три разрозненных источника: паспортные пробелы (сервер), строки техописания (экран), состав (экран, без оценки).
2. Серверной проверки полноты техописания (`techsheet-gaps`) — D-REPORT, шаг 4.
3. Порядка «что заполнить первым». `passport-gaps` отдаёт пробелы в порядке правил, а не по пользе.
4. Входа «одним кликом» из карточки в нужное поле. Есть только «Выпустить паспорт», она открывает воронку целиком.
5. Состояния «готово» в списке изделий (`products.js`) и в плане заказа для техописания.
6. Учёта того, что изделие стоит в заказе (`row.orderLines`): такие изделия надо заполнять раньше.

## 3. Модель «рейтинга» (поля, вес, порядок)
Принцип: вес поля = сколько дверей оно открывает. Считает сервер одним ответом, экран только рисует.
Вес 5 = без него остальное не определено; 4 = тексты паспорта и техописание; 3 = закрывает выпуск; 2 = улучшает документ; 1 = для порядка.

| Пункт | Источник | Что открывает | Вес |
|--|--|--|--|
| Тип паспорта (category) | passport-gaps | паспорт; без него другие пробелы не определены | 5 (всегда первым) |
| Вид изделия (kind), назначение (purpose) | passport-gaps | паспорт (тексты), техописание | 4 |
| Обязательные поля паспорта (field, install, elements) | passport-gaps | выпуск паспорта | 3 |
| Габариты, вес | products.dimensions, weight | паспорт, техописание, склад | 3 |
| Состав (части, материалы) | materialsSpec + composition | техописание, паспорт «Материалы», закупка | 3 |
| Рисунки (image) | passport-gaps | печать паспорта | 2 |
| Признаки (facet) | passport-gaps | тексты паспорта по группе | 2 |
| Монтаж | products.installation | техописание, паспорт | 2 |
| Цена, фото, примечание | products | КП, витрина | 1 |

Множитель срочности: x2, если изделие есть в открытых заказах (`orderLines`); x1,5, если уже есть выпущенные паспорта (правка нужна для переиздания). Пункты с умолчанием (`defaulted`) в счёт «M» не входят: они уже подставлены.

Порядок: сначала `required` по убыванию веса, затем остальные; при равных весах — в порядке воронки паспорта (шаги совпадут с тем, что менеджер увидит). Один пункт = один вопрос воронки.

Заполненность: N = пунктов без пробела, M = всех применимых (паспорт + техописание). Процент не показывать: менеджеру понятнее «заполнено 9 из 14».

Серверная форма: `passport-gaps` не расширять (он закрыт тестами и воронкой). Новый `GET /showcase/:id/fill-queue` собирает `passport-gaps` + `techsheet-gaps` (D-REPORT шаг 4) + габариты, вес, монтаж и возвращает список пунктов: ключ, название, цель (паспорт / техописание / оба), вес, обязательность, шаг, плюс done и total. Файлы: новый `product-passport/product-fill-queue.ts` (+ spec), строка в контроллере.

## 6. Риски и проверки
- Нагрузка: `passport-gaps` ходит в справочники (фразы, признаки, виды). Для списка изделий (шаг 7) справочники читать один раз на запрос, не на каждое изделие.
- Один источник правды: пробелы паспорта берутся только из `productGaps`; своих правил в экране не писать, иначе блок разойдётся с воронкой.
- Приёмка вида после шага 4: снимки карточки изделия (пусто / частично / всё готово; 390 и 1920; обе темы) и `design-lint` по новому файлу. Без стенда — PARTIAL.
- Витрина `#kit`: новый вариант не нужен, блок собран из готовых эталонов. Если появится новый вариант `row` с кнопкой — показать в витрине.
