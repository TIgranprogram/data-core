## 1. Модель условий
- **Формат хранения — строка** `when` (как у аналитика: пробел = И, `a|b` = ИЛИ, `!a` = НЕ; только коды признаков, без категорий — категория уже решается версией шаблона). **В сборщике — структура**: одна чистая функция `parseWhen(s) → PassportCondition` над полем `traits` (`{all:[{any:[{field:'traits',op:'eq',value:'bolts'}]},{not:…}]}`); дальше работает готовый `evalCondition` (`passport-compose.ts:77`). Своего второго вычислителя нет.
- Совмещение: у блока уже есть `condition`; если есть и `when` — `{all:[condition, parseWhen(when)]}`. `legacyTemplateToBlocks` (`:181`) кладёт `condition` из `when[i]`.
- Где хранить:
  - «Для всех» v2 — **в коде** `passport-texts.v2.json` (сейчас единственный источник ALL v2, `service:442`); версии категорий — `passporttemplates.sections[]`. Поля раздела: `ids: string[]`, `when: (string|null)[]` параллельно `paragraphs` (kppdf и PDF v1 читают только `paragraphs`). Один помощник `sectionItems(sec)` склеивает массивы; разная длина — ошибка сохранения и падение spec.
  - Дефекты — `dict_values.passportDefects.when` (берётся, если `applies` И `when`). `excludeDefects` остаётся.
  - `passportStyle` — `when` (тот же парсер), пусто + категория пуста ⇒ в отчёт аудита.
  - **`baseRequirements` и монтаж — без `when`.** Условием служит сама запись способа установки. Поломка 4 — правка данных: переписать «Свободностоящий» + новая запись «Укладывается на основание» (`traits: freestanding`). Префикс `[when]` в строке не делать: v1 PDF напечатает его как текст.
  - `madeOf` — без `when`: отдельные записи материала по форме (лист / труба), данные, не код.
  - `passportPhrases` — оставить `facetValueIds/groupIds`, `when` не добавлять сейчас.
- Проверка `when` при записи: справочники — валидатор в `dicts.defs` (по образцу `dicts.passport-phrases.ts`), шаблоны — в `saveTemplate`, JSON — spec. Неизвестный код ⇒ 400 с текстом «Неизвестный признак: …».

## 2. Устойчивый код пункта (главное)
- **Заморозить нынешние номера как коды**: в JSON и при `--apply` записать `ids` = `p1…pN` по текущему порядку. Ключ блока = `ids[i] ?? 'p'+(i+1)`. Итог: все ключи совпадают с сегодняшними ⇒ снимки, правки `snapshot-item`, замена пункта категорией, `slot` воронки (`passport-v2-text.ts:62`) — без миграции.
- Новый пункт получает новый код (`p7w`, `mounting.atTree`), удалённый — не сдвигает остальные. Номер в PDF и `ids` больше не связаны.
- Категория без `ids` (старые версии в БД) — прежнее «первые N по позиции» = `p1…pN`; это совпадает с замороженными кодами.
- Правки при «Обновить текст»: `snapshot()` перед записью берёт из старого снимка пункты `edited` и `hiddenItems`, накладывает по `section/key`; пропавший ключ ⇒ `textSnapshot.lostEdits[]` + предупреждение в карточке. Отдельного поля для правок не нужно.
- `hiddenItems: string[]` (`"mounting/p7"`) — в `productpassports` + в DTO эндпоинта `snapshot-item` (флаг `hide`), не в общем Create DTO.

## 3. Признаки
- 10 достаточно; лишних нет. `metal` почти всегда истинен, но нужен для деревянных BLG. Не добавлять `solid`, `polymer`, `ground`. Список кодов + русские подписи — одна константа `PASSPORT_TRAITS` в коде (экран, валидатор, аудит).
- Источники: `traits` у `passportElements`, `passportMaterials`, `passportInstall` (не у `productFacetValues` — позже, если понадобится) + `joints[]` ∈ {bolts, welds, solid} на паспорте и в `products.passportDefaults` (копия в `passport-from-product.ts`, `MODEL_FIELDS`).
- **Три состояния**: `joints` не задан ⇒ `bolts/welds` «неизвестно». Пункт с `bolts`/`!bolts` при «неизвестно» не выводится, а в `missing` — «Конструкция: выберите» (выпуск заблокирован, `passport-rules.ts`). Иначе `!bolts` молча станет истиной.
- В снимке: `textSnapshot.traits[]`, `textSnapshot.traitsFrom` (откуда каждый) и `textSnapshot.excluded[]` (`{section,key,when}`) — для «не вошло и почему» и воспроизводимого PDF. PDF печатается только из снимка, `when` при печати не вычисляется.
