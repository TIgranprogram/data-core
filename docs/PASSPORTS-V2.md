### 1.2 Наш паспорт сейчас (для сравнения)
Титул + гарантийный талон · 1 Описание · 2 Техданные (табл. 1) · 3 Монтаж · 4 Гарантия · 5 Хранение (табл. 2) · 6 Перевозка · 7 Контроль и ТО (табл. 3, 4) · Прил. 1 габариты · Прил. 2 зона безопасности/монтаж · Прил. 3 комплектность.
**Один шаблон на все категории** (`passporttemplates`), описание собирается из трёх свободных полей (`materials`, `installationMethod`, `purpose`), варианты для них — агрегат уже выданных паспортов (`/passports/phrases`).

### 1.3 Чего у нас нет (разрыв)
1. **Основные сведения по ГОСТ**: изготовитель отдельным блоком, дата выпуска, **дата ввода в эксплуатацию** (пустая строка для владельца), **назначенный срок службы**, идентификационные сведения.
2. **Ограничения пользователя**: возраст от–до, рост, вес, макс. число пользователей, макс. высота падения, площадка под установку.
3. **Функциональные элементы** и всё, что из них следует: описание, предназначение, правила пользования по элементам.
4. **Правила эксплуатации / поведения / информационный стенд.**
5. **ТО по периодам** (перед вводом, ежедневно, ежеквартально, ежегодно) и **таблицы дефектов с картинками** по материалам.
6. **Ремонт, утилизация, рекламации, свидетельство о приёмке**, журнал ремонта.
7. **Монтаж по способу установки**: грунт, бетон, щебень, уклон, моменты затяжки, покрытие; схемы опор и скважин.
8. **Инструкция по сборке** для разборных изделий.
9. **Шаблоны по категориям** — сейчас уличный тренажёр и скамейка получают одинаковые тексты.
10. **Перечень нормативов как данные** (со статусом и датой проверки), а не текст внутри абзацев.

### 1.4 Чего НЕ брать (плагиат и ошибки аналога)
- **Тексты не копировать.** Берём только структуру (перечень разделов задан ГОСТ, он общий) и *смысл требований* из ГОСТ/ТР. Все абзацы пишем своими словами, со своей логикой подачи; проверка — §6.2.
- Оформление аналога (лого, обложка, сетка таблиц, условные картинки дефектов) не повторять — свой дизайн (§3.7).
- Ошибки аналога, которые не переносить: «Предназначение» (лучше «Назначение»), «отчищена» (очищена), «ударопоглащающего», «страдающее ортопедическими» (страдающим), «следует обратится», «течении», точка с запятой после точки («равновесия.;»), п. 7: «ремонт при ширине трещины **более** 8 мм», хотя в 6.4 допустимо **не более** 8 мм — противоречие; в 6.1 «Пример графика — Приложение Б ГОСТ Р 52301» и тут же собственное «Приложение Б» (габариты) — путаница ссылок; ссылка на СНиП 12-03-2001 как на обязательный документ (см. §2).

## 3. ТЗ

### 3.1 Термины
- **Категория паспорта** — набор правил для вида изделия (какие разделы, тексты, картинки, нормативы, поля обязательны). Не путать с категорией каталога; связь — таблица соответствия (уличный тренажёр → «Тренажёр уличный»).
- **Блок текста** — абзац/пункт типовой части с областью применения: «для всех» или список категорий, + условия (элемент, материал, способ установки).
- **Функциональный элемент** — горка, платформа, сетка, турник, брусья, скамья для пресса, качели, балансир и т. д.; несёт свои тексты (описание, назначение, правила пользования, ТО).
- **Снимок** — копия собранных текстов в выданном паспорте (правка справочника не меняет выданные паспорта; как сейчас версии шаблона).

### 3.2 Категории (стартовый набор — на утверждение)

|--|--|--|--|--|

Каждая категория в справочнике хранит: **наследование от «Для всех»**, список и порядок разделов (вкл/выкл), обязательные поля, обязательные рисунки (вид + «если …»), нормативы, значения по умолчанию (срок службы, гарантия, возраст, климат −45…+40 и т. п.).

### 3.3 Справочник «Паспорта» (в разделе «Справочники», группа «Паспорта»)
Подсправочники (каждый — таблица слева + карточка в правой панели, как остальные справочники, DESIGN §4):
1. **Категории паспортов** — §3.2.
2. **Разделы и тексты** — дерево «раздел → пункты»; у пункта: текст с переменными, область (все / категории), условия (элемент / материал / способ установки / «разборное»), обязательность (обязательный / по умолчанию вкл / по выбору), порядок. Предпросмотр «как в паспорте» для выбранной категории.
3. **Функциональные элементы** — название, категории, тексты: «в описании», «назначение», «правила пользования» (список шагов), «что проверять при ТО», норматив-часть (например горка → ГОСТ 34614.3), картинка-иконка.
4. **Материалы и покрытия** — металл (сталь, порошковая окраска), оцинковка, дерево клеёное/массив, фанера ламинированная, HPL, пластик (полиэтилен рото), канат армированный, нержавейка… У каждого: текст «изготовлено из…» (род/падеж учтены), ремонт, **дефекты** (→ п. 6).
5. **Дефекты** — элемент/материал, дефект, **картинка (наша)**, мера, период (ежедневно / квартал / год), допуск (например «трещина ≤ 8 мм»). Собирает таблицы ТО автоматически по материалам изделия.
6. **Способы установки** — бетонирование опор, анкеры на фундамент, на закладные, свободностоящее, на покрытие. У каждого: тексты монтажа, требования к основанию/бетону/щебню, обязательные рисунки (схема опор, схема скважин/разметки).
7. **Нормативы** — обозначение, наименование, статус, дата проверки, ссылка, категории. Тексты ссылаются на норматив по коду `{std:R57538}` — переименование/замена в одном месте.
8. **Переменные** — список подстановок (только чтение, для подсказки): `{name} {article} {code} {serialNo} {ageFrom} {ageTo} {heightMin} {heightMax} {weightMax} {maxUsers} {fallHeight} {siteL}×{siteW} {serviceLifeYears} {warrantyMonths} {tempMin} {tempMax} {manufacturer} {std:…} {fig:overview} {tab:defects-daily}`.

**Дубли в выпадающих списках (сейчас):** варианты «Материалы / Установка / Назначение» — это все разные строки из выданных паспортов (`phrases()` группирует по точному тексту) ⇒ один смысл в 3–5 написаниях (пробелы, кавычки, точка в конце, падеж). Решение:
- нормализация для сравнения (пробелы, «ёлочки», ё/е, точка в конце, регистр) + отчёт «группы похожих» (как `customers-cleanup.js` — сначала отчёт);
- перенос канонических вариантов в справочники 3/4/6 через «Объединить» (как в справочниках);
- в форме — **только значения справочника**; свой текст можно вписать, при сохранении вопрос «Добавить в справочник?» (manager+).

### 3.5 Создание паспорта (правая панель, мастер)
1. **Модель** (поиск по артикулу/названию, фильтры: категория, серия, элемент) → подтягиваются все поля и картинки модели. Или «Новая модель».
2. **Категория** (чипы) — если не пришла из модели.
3. **Элементы** — чипы с иконками, фильтр по категории; **материалы** — чипы; **способ установки** — список; «разборное» — переключатель.
4. **Ограничения и техданные** — числовые поля с подсказкой нормы категории (например тренажёр: рост ≥ 140 см).
5. **Экземпляр** — дата, номер изделия, заказчик/объект, поставщик (как сейчас).
6. **Проверка** — список «не хватает»: обязательные поля, тексты, **рисунки по виду** (с кнопкой «Загрузить» прямо в строке) и предупреждения по нормативам.
7. **Предпросмотр** — собранный текст по разделам; любой абзац можно поправить *для этого паспорта* (в снимок; кнопка «перенести правку в справочник» — director/admin).

Цель по скорости: паспорт по существующей модели — **≤ 1 мин** (3–5 кликов); новая модель простой категории (МАФ) — ≤ 5 мин; ДИО — ≤ 15 мин при наличии картинок.

### 3.6 Рисунки — обязательные и по местам
| Вид (`kind`) | Где в паспорте | Обязателен | Что загружать |
|--|--|--|--|
| `overview` | титул | все | фото/рендер изделия, светлый фон, ≥ 1500 px |
| `overview_callouts` | раздел «Описание», Рисунок 1 | DIO, DSP, WRK (если элементов ≥ 2) | схема с выносками названий элементов (или генерация подписей поверх — этап 2) |
| `nameplate` | там же, выноска «место таблички» | DIO | крупно место шильдика |
| `dimensions` (1–4) | Прил. «Габариты» | все | виды с размерами |
| `safety_zone` | Прил. «Габариты» (зона приземления / безопасности) | DIO, DSP, TRN, WRK | план с зоной и размерами площадки |
| `foundation` | Прил. «Схемы установки опор» | если способ = бетонирование / фундамент | разрез: покрытие, грунт, бетон, щебень, размеры |
| `holes` | Прил. «Схема скважин / разметки» | если бетонирование опор | план с координатами |
| `assembly` (N) | Прил. «Инструкция по сборке» | если `isKit` | пошаговые рисунки |
| `bom_item` | Прил. «Комплектность», колонка «Изображение» | если `isKit` | миниатюры деталей |
| `defect` | таблицы ТО | из справочника «Дефекты» | **наши** фото/рисунки дефектов (не из аналога) |

Правила вёрстки: нумерация рисунков и таблиц **сквозная, автоматическая**; в тексте ссылки через `{fig:…}`/`{tab:…}` (номер подставляет сборщик); подпись «Рисунок N — …» под рисунком; рисунок ставится **сразу после абзаца, где на него первая ссылка**, или на следующую страницу целиком, если не помещается (не разрывать подпись); приложения — в порядке первой ссылки; отсутствующий необязательный рисунок — раздел/ссылка выпадает без «дыр».

### 3.7 Дизайн PDF (свой, узнаваемый)
- Своя обложка: крупное фото изделия, название, артикул, категория цветной плашкой (цвет категории из справочника), возраст/рост пиктограммой, логотип и торговая марка поставщика, ЕАС — только если `certificate.hasEac`.
- Блок «Коротко» на 2-й стр.: 4–6 плиток (возраст, рост, пользователей, высота падения, срок службы, гарантия).
- Правила пользования — пиктограммы «можно / нельзя» (свой набор SVG) + текст; удобно вынести на информационный стенд → отдельная кнопка «PDF для стенда (A3)».
- Таблицы ТО — чек-лист с колонками «Элемент · что проверить · норма · мера», картинка дефекта — миниатюра.
- Шрифт ГОСТ тип А оставляем (уже есть), но заголовки разделов — с цветной линейкой категории; колонтитул: обозначение · № паспорта · стр. N/M.
- Буклет A5 и A4 «в печать» — как сейчас.
Интерфейс (формы, справочник) — **только через skill `datacore-design` / `docs/DESIGN.md`**: ввод в правой панели, новых видов окон нет.

### 3.8 Права и аудит
Справочник «Паспорта»: смотреть manager+, менять director/admin (как шаблон). Каждая правка блока — версия + запись в аудит (`record-history`). Выданный паспорт хранит снимок текста и версию; «Пересобрать по новому справочнику» — явное действие с показом разницы.

## 6. Проверки качества текста
### 6.1 Чек-лист блока текста
- [ ] Своими словами, одна мысль — один пункт; нет «и т. д.» в требованиях.
- [ ] Числа — через переменные, а не вписаны (возраст, вес, срок).
- [ ] Ссылки на нормативы — только `{std:…}`, статус «действует».
- [ ] Термины единообразны: «эксплуатант (владелец)», «назначенный срок службы», «зона приземления» (ДИО) / «зона безопасности» (прочее).
- [ ] Род/число согласованы с названием изделия (проверить на 3 названиях разного рода).
### 6.2 Анти-плагиат
- Не открывать аналог при написании абзаца; писать по смыслу требования ГОСТ.
- Автопроверка: скрипт сравнения каждого нашего блока с текстом аналога (`pdftotext`) — 5-словные шинглы, совпадение > 15 % → блок переписать. Аналог хранится вне репозитория (только для проверки).
