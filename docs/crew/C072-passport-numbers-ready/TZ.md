# C072 — паспорта: список по номерам и «Добавить готовый паспорт» (П12 + П13)

**Класс:** L (сервер + экран) · **Агентов:** ≤ 4 (backend → frontend → designer, qa) · **Дата:** 2026-11-11 · **Приоритет владельца №1.**
**Основание:** `docs/crew/C070-passports-kp-focus/PASSPORT-FIRMS.md` — пункты 3 и 4 (места в коде там; прочитать первым).

## Решения владельца (2026-11-11)

- Номера паспортов — **один общий ряд** на все фирмы.
- «Хочу видеть паспорта по нумерации, фильтровать по номеру, видеть, какой последний».
- Готовый паспорт (сделан отдельно, есть файл): номер **на выбор** — сайт предлагает следующий свободный, его можно заменить на номер из файла; занятый номер — отказ.
- Готовый паспорт прикрепляется к **изделию** (обязательно) и к **заказу** (по желанию); фирма обязательна.

## Часть A. Сервер (backend) — `backend/src/modules/product-passport/**`

1. **Список** (`GET /passports`): необязательные параметры `numberFrom`, `numberTo` (числа, по числовой части номера); в строке списка — название фирмы (`supplierOrgName` или как принято рядом) и признак источника печати `printSource: 'file' | 'site'`. DTO запроса: сначала собрать реальные поля, которые шлёт экран сейчас (ловушка `forbidNonWhitelisted`, AGENTS «Известные ловушки»).
2. **Последние номера** (`GET /passports/last-numbers`): общий последний номер и последний по каждой нашей фирме: `{ last, byFirm: [{ orgId, name, last, count }] }`. Если похожий маршрут уже есть (полоска «Последний №», `numbers-strip.js`) — расширить его, новый не заводить.
3. **Готовый паспорт** (`POST /passports/ready`, права — как у выпуска): тело `{ productId, supplierOrgId, salesOrderId?, incomeId?, number?, fileId | загрузка файла как принято в «Прикрепить PDF» }`.
   - Проверки до записи, ответы 400/409 по-русски: изделие есть; фирма — наша; номер не занят («Номер 612 уже у паспорта „…“»); на позицию заказа ещё нет действующего паспорта (правило `assertOneLive`) — иначе 409 с названием паспорта.
   - Запись: паспорт сразу в статусе «выпущен», с номером, фирмой, изделием, заказом, файлом печати; **обязательные поля категории не проверяются** (документ уже готов); пометка источника `source: 'ready-file'`.
   - Номер не передан — следующий из общего счётчика.
4. **Печать пачкой** («Печать всех» по заказу, «PDF пакетом»): паспорт с прикреплённым файлом сейчас в пачку не попадает (`passport-pdf.service.ts:129-140, 202-212`). Склейки PDF в проекте нет — новую библиотеку не добавлять. Сделать: ответ пачки сообщает список пропущенных («отдельным файлом: № …»), чтобы экран показал их ссылками.
5. Тесты: юнит на каждую проверку и на выдачу номера; e2e — «готовый паспорт: создать, найти по номеру, занятый номер — 409». `docs/openapi.json` перегенерировать, `docs/MAP.md` — строка модуля.

## Часть B. Экран (frontend) — `backend/pwa/sections/docs.js`, `backend/pwa/sections/passports/**`

1. **Вид «По номерам»** в списке паспортов: таблица kit — №, дата, фирма, изделие, заказ, источник («Файл» / «С сайта»), статус; сортировка по номеру (новые сверху); поиск по номеру; фильтр фирмы; отбор «№ от — до». Переключатель видов рядом с нынешней галереей; выбранный вид запоминается.
2. **Полоска номеров** сверху: «Последний № 612 · СпортИН-ЮГ — 610 · СпортСтрой-Юг — 612».
3. **«Добавить готовый паспорт»** — вторая кнопка рядом с «Новый паспорт». Правая панель, шаги по `docs/PATTERNS.md` П-1, пройденный шаг сворачивается в строку «…: значение ✎», сверху «Дальше: …»:
   1) Файл (PDF) → 2) Фирма (если заказ выбран раньше — подставлена) → 3) Изделие (поиск; из карточки изделия — подставлено) → 4) Заказ — «без заказа» одним нажатием → 5) Номер: предложен следующий, можно изменить; занят — подсказка под полем → «Сохранить паспорт».
   Та же панель открывается из карточки изделия (вкладка «Паспорт») и из «Паспорта заказа» — с подставленными изделием и заказом.
4. «Печать всех» по заказу: паспорта-файлы показать под кнопкой ссылками «отдельным файлом: № …».
5. Помощь «?» (`help-flow-data.js`) — дополнить путь.
