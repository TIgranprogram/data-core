# C188 — защита записи договорного комплекта

Единица защиты — договор. Обычная операция в Mongo-транзакции занимает шапку условным обновлением `activeArchiveVersion: null` с увеличением `passportGuard`. Фиксация и возобновление занимают тот же документ. Для нескольких владельцев helper удаляет повторы и сортирует ID. При конкуренции Mongo повторяет транзакцию, а активная архивная версия даёт `409 ORDER_ARCHIVED`. По связи с позицией проверяется её договор. При перепривязке проверяются обе стороны.

| Область | Пути записи |
| --- | --- |
| Договор | Правка шапки и кэш-полей строк, юридическая карточка с резервированием оригинала, подбор изделий, корзина/возврат, изменение производственного номера, перенос и этап группы. Выдачи и отгрузки проверяются внутри операции переноса. |
| Строки и деньги | Создание, правка, перемещение, отмена/возврат, корзина/возврат, старые и новые платежи, служебная выдача paymentId и изменение фотосписка. До записи проверяются предыдущий и целевой договоры. |
| Паспорт | Создание, выбранный источник, обычная правка, выпуск и отзыв, снимок текста, PDF и редакции, удаление/возврат, массовая правка и её отмена, включая прежние паспорта с единственным salesOrderId. При открытии архивного документа служебная отметка печати не меняет запись. |
| Inventor | Применение проверяет затронутых владельцев до записи изделия, паспортов и набора изображений. Архивная позиция исключается по действующему маркеру. |
| Отгрузки | Создание, изменение, удаление и восстановление проверяют договор. Выданные количества и этап пересчитываются в этой же транзакции. |
| Файлы | Выбор вложения и изменение вложений строки используют защиту владельца. Архивные вложения получают постоянный archiveProtected, удаление и уборка мусора проверяют его условной записью. У оригиналов photos фиксация помечает все ссылки на общий storageUrl как sourceProtected. Старые версии и их файлы хранятся отдельно. |
| Склад | Резерв по списку/спецификации, редактирование и перепривязка резерва, выдача, снятие и снятие группы, FIFO-снятие, движения по договору/позиции, пакет, сторно, исправление списания. Возврат поставки проверяет связанный договор через ссылку движения на заявку. Операции с общим материалом остаются доступными. |
| Снабжение | Создание/правка заявки, фотографии, корзина/возврат, приёмка, откат приёмки вместе со сторнирующими движениями. Изменения строк через счёт поставщика проверяют затронутые заявки, включая перенос/слияние и массовую смену состояния оплаты. |

## Производственная группа

Группа вычисляется по текущим действующим договорам. Все архивированы — группа архивная. Добавление или перенос открытого договора делает группу открытой. Содержимое ранее зафиксированной версии доступно по прежним orderId/version. Группа без действующих договоров не получает статус архива.

## Проверки на отдельной MongoDB 4.4 rs0

`c188-archive-writers.e2e-spec.ts` вызывает публичные HTTP-маршруты Nest под администратором. Для конкуренции тест исполняет второй реальный запрос между подготовкой файлов и финальной проверкой, либо фиксирует договор непосредственно перед записью. Контроль проверяет количество версий, маркер и содержимое зависимых документов. Есть отдельные случаи для позиции, старой оплаты, добавления строки, массовой отмены изменения паспорта, Inventor, отгрузки, удаления фото через другой ID, связанной заявки и склада. Для смешанной группы проверяется повторный расчёт после включения нового договора.

- Договоры, позиции, отгрузки, паспорта, вложения и фото — 104 набора, 1022 юнит-теста.
- Склад и снабжение — 32 набора, 397 юнит-тестов.
- Юридические операции, договоры и предложения после включения единой транзакции — 27 наборов, 153 юнит-теста.
- После защиты смешанного набора паспортов — 79 наборов, 818 юнит-тестов. Выборки юнит-тестов пересекаются.
- Финальный HTTP-прогон — 16/16. Массовая правка и её отмена с архивным паспортом возвращают 409 до изменения первого открытого паспорта. Запрос для отдельного открытого паспорта меняет значение.
- TypeScript — код выхода 0. ESLint по новой защите склада и снабжения — код выхода 0.

## Границы

Внешние писатели DataCore и административные таблицы описаны в CONTRACT.md и отчёте отдельной роли. Заказы работ, конструкторские задачи и планы строк проверяет координатор. Прямые записи сторонней CRM в общую базу находятся вне маршрутов DataCore. Чтение старой зафиксированной версии и её файлов опирается на сохранённый комплект. Проверки ограничены отдельной локальной БД. Общую приёмку ПС-08 проводит координатор.
