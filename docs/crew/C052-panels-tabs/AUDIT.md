## 3. Что добавить в эталон kit
- card.tabs: (row, ctx) => [{ key, label, count?, tone?, title?, when?, blocks: () => [узлы] }] в ui/kit/card.js showView (после шапки, stats, top). Собирать на готовых headTabsCard и tabs({fill}), новых компонентов нет. Вкладка с when:false или пустая скрыта (как defs.filter у договора). Содержимое строится лениво при первом открытии (как panes).
- Над вкладками остаются: фото, stats, одна короткая группа-сведения из card.view, headStrip, кнопки (actionsInHead). Остальные группы view переезжают во вкладку: grp получает ключ вкладки, например grp(Цена, price), либо вкладка сама зовёт readonlyGroups(rows).
- Общая логика: открытая вкладка запоминается на раздел (pref tab:раздел); ctx.openTab(key) и ?tab= (обобщить событие so-open-tab, salesorders.js:329-341); после ctx.setRow вкладка не сбрасывается.
- Счётчики count — для списков (Заказы, Обсуждение, Заявки, Позиции). tone — только для состояния: warn — нужно действие (не оплачено, нет паспорта), danger — просрочено, ok — готово. Не красить ради красоты.
- Телефон 390: fill уже даёт 2 ряда (kit.css:658). Потолок — 5-6 вкладок, названия до 12 знаков, высота ряда ≥ 44 px проверить. Больше — группировать.
- «Вид панели» («⋯»: одна/две колонки) для панелей с вкладками не действует: пункт скрывать; внутри вкладки один столбец.
- Где вкладки не подходят — раскрывающиеся section(): КП, расход, движение, 1-2 блока. Редкое внутри вкладки (отмена задания, история цен, «Другие варианты») — тоже section.
- Автопроверка: правило в design-lint / site-audit — панель с более чем 6 блоками в extra/view без tabs = находка, чтобы «портянка» не вернулась.
