## Уже существующий безопасный способ записи

Координатор адресно проверил existingUI `book-template.js`: `PATCH /showcase/:id/passport-template?variant=short|full`, тело `{expected,changes}`. Для `changes.textOverrides` сравниваются только затронутые rootID с текущими `defaults.textOverrides[root] ?? null`, а не заменяется весь passportDefaults. Цель обязана быть реальным OID корня; текст не длиннее4000символов. `off:true` перекрываетtext, поэтому для инструкции не применять off и не удалять чужиеoverride.

Концептуальная форма существующего CAS для случая, когда архитектор подтвердит корректный существующий root и применимый текст:

```json
{
  "expected": { "textOverrides": { "<реальный принятый use rootId>": null } },
  "changes": { "textOverrides": { "<тот же rootId>": { "text": "<подтверждённая инструкция именно этой модели>" } } }
}
```

Это описание контракта, **не исполняемый payload**: реального пригодного rootID сейчас нет. Перед записью перечитать defaults и использовать действующий UI-helper expected/changes; если возникнет существующий override, сохранить его какbaseline и согласовать новую редакцию, не затирать. При409 остановиться и перечитать; не отправлять весьстарыйdefaults повторно.

## Сохранность общих правил и приёмка

- Не подменять sections.use целиком. Baseline1067 —11 общих пунктов плюс4rules; baseline1068/1069 —15пунктов и пустыеrules. Сравнивать тексты/ключи каждого фактического baseline-пункта, а не механически требовать15везде. Четыре правила1067 изLEG_TRAINER сохранить; новый текст не должен их подавить/переписать.
- Не копировать общие правила в собственный override: это создаёт две расходящиеся копии. Модельная инструкция должна добавляться отдельным применимым источником. Должны остаться ограничения, осмотр передзанятием, одежда/обувь и остальные исходные безопасности.
- Перед отправкой проверить длину полного подтверждённого блока≤4000 безтихогоtruncate. Сохранять три подзаголовка «Исходное положение», «Движение», «Задействованные мышцы» и абзацы. Медицинские эффекты/нагрузки/повторы не добавлять.
- На изолированной копии проверить short/full JSON и образцы безвыпуска номера: назначение, новаяинструкция, все прежние safety/rules, отсутствие влияния на четвёртый непилотный TRN. Выданные паспорта автоматически не пересобирать; текущие3выданных1067 остаются неизменными снимками.

## Следующий шаг архитектору

Дополнительная проверка координатором builder: leaf требует непустойtext; единственныйleaf выбирается автоматически дажеприisDefault=false. Поэтому нейтральныйroot с пустымleaf не работает. Два искусственныхleaf ради обхода автовыбора не предлагаются; справочник под это не менять.

Следующий предметный выбор аналитика/архитектора: необязательное модельное `exerciseInstructions` с тремя частями либо доказанный корректный существующий источник без назначения чужихfacets. Решение должно сохранять все baseline safety/rules и выданные снимки. Новая библиотека упражнений этим шагом не создавалась; готового безопасного targetдляwrite пока нет.

На проде не выполнено ни одного PATCH/POST/DELETE; существующие тексты и справочники сохранены.
