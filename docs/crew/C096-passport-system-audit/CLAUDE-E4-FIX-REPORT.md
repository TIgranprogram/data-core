## Изменения
| Находка | Что сделано | Где |
|--|--|--|
| 1. Частичный успех скрывался | Сессия создания знает, что запись создана, а заполнение не закончено (`partial()`). В форме воронки при этом показывается предупреждение: «Изделие «…» уже создано… «Создать и продолжить» продолжит эту же запись». Рядом кнопки «Открыть созданное изделие» и «Создать другое изделие». Уход из формы: диалог «Изделие уже создано» вместо «ещё не сохранены». Форма откладывается, следующий «+ Новое изделие» возвращает её с той же записью (PATCH, не POST) и с текущим выбором воронки (`setContext`). «Взять это» у похожего спрашивает подтверждение и говорит, что созданное останется. При закрытии панели — сообщение о созданном. В старой форме паспорта закрытие карточки после такого сбоя предлагает «Выбрать это изделие», при отказе сообщает, что оно осталось. Ничего не удаляется, создать другое изделие можно. | `create-session.js`, `new-product.js`, `funnel/index.js` (`leaveStage`, `openNew`, `choose`), `form-fields.js` (`partial`), `product-block.js` (close) |
| 2. Единственная группа | `pickSteps.effective(key)`: выбранное значение или единственное значение автоматически пропущенного шага. При нуле значений или при изделиях без группы (`none > 0`) — null. Воронка передаёт форме эту группу, и признаки переносятся. Другая группа их по-прежнему не наследует (`facetsForGroup`). | `pick-steps.js`, `funnel/index.js` (`creationContext`) |
| 3. Фильтр → своя категория | Из `initial` полной формы убран `pdCategory: code`. Категория идёт по группе. Своя — только при явном выборе в поле «Категория паспорта», подсказка поля это объясняет. Раздел-подсказка `type` из фильтра остался: это видимое поле. | `product-block.js` |
| 4. Категория воронки ≠ категория группы | Если группа нового изделия не встречается в выбранной категории (`pickSteps.valuesOf('group')`), перед созданием спрашивается «Группа из другой категории?». Отмена ничего не создаёт и не трогает ввод. После создания шаги воронки переходят на фактическую категорию изделия, сообщение объясняет причину. Категория не записывается. | `new-product.js`, `funnel/index.js` (`followCategory`) |

Сервер, API, схемы и справочники не менялись. Тело POST/PATCH изделия прежнее: служебное `_sel` срезается до запроса.

## Ограничения и что дальше
- Нужен сценарий входа браузера на стенд (отдельная задача access). Затем:
  1. Новое изделие в «Качелях» → видно предупреждение → «Назад» → «+ Новое изделие» → в «Продукции» одна запись.
  2. Категория с одной группой + признаки.
  3. Категория А + группа другой категории (подтверждение, обновлённые шаги).
  4. Старая форма: фильтр X + группа Y → у изделия нет своей категории.
  
  Каждый сценарий — снимки 390/1920 в обеих темах, потом `datacore-designer`, потом коммит с «Дизайнер: принято».
- Группы «другой категории» определяются по группам, в которых в этой категории уже есть изделия. Новая группа категории без изделий тоже вызовет вопрос: это осторожно, данных о категории группы без сервера нет.
- Закрытие карточки изделия после сбоя: общее окно kit может сначала спросить о несохранённом (его текст не менял). После него наш диалог говорит правду.
- Вспомогательный загрузчик тестов `funnel/test-vm.mjs` лежит в `pwa/`, импортами приложения не используется (импорт-проверка зелёная).
