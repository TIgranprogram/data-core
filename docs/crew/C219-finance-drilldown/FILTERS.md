# C219. Связанные денежные операции

В сводке по статьям и списке операций учитываются датированные фактические поступления и выплаты, доступные текущей роли. Прогноз показывает будущие обязательства отдельно. Расчёт себестоимости позиции проходит через `GET /work-facts/cost?incomeId=…` и остаётся производственным расчётом.

| Фильтр | Что попадает |
|---|---|
| Производственный заказ | Связанные факты по всем договорам с этим номером производства |
| Договор заказчика | Оплаты позиций, платежи поставщикам, прочие расходы и выплаты с подтверждённой аналитической связью с договором |
| Позиция заказа | Поступления по позиции и расходы снабжения со связью. Для новых оплат поставщиков сохраняется снимок позиции. Для старого факта без позиции в снимке используется связь действующей исходной заявки при совпадении договора. Перенос аналитики в другой договор убирает прежнюю позицию из операции |
| Сотрудник | Фактические выплаты ФОТ этому получателю. Доступ соответствует правам на ФОТ и разделу «ФОТ» |

Прочий расход пока привязывается к договору. Расход заказа без связи с позицией остаётся виден на уровне договора. Не распределяем выплаты по заказам из длительности задач и не считаем начисление денежной выплатой.

`GET /finance/operations` и `GET /finance/by-articles` принимают `salesOrderId`, `productionNo`, `salesOrderLineId`, `personId`, точные `counterparty` и `doc`. При `facets=1` возвращаются `facets.orderLines` (после выбора заказа, договора или позиции) и `facets.people`, с доступными идентификаторами и подписями. Список вариантов строится по тем же видимым фактам и остальным фильтрам. При детализации список и итоги используют одно условие.

В платёжном календаре, прогнозе, сводке и старой детализации применяются ограничения исходных разделов, ФОТ и области заявок. Календарь переносит начальный остаток по тому же набору доступных операций. В частичном счёте итог по всей валютной сумме не выдаётся, расходы показываются по видимым строкам.

Проверено локально. TypeScript и ESLint прошли. 108 юнит-тестов, 71 проверка API на отдельных тестовых MongoDB, включая совпадение сводки и строк, неизменность снимка оплаты, факты и список сотрудников для менеджера и бухгалтера, календарь при ограниченной области склада и сценарии оплаты счетов поставщиков.
