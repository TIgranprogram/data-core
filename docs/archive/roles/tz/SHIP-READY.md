# ТЗ SHIP-READY — «Отгрузка: предлагать только то, что можно» + паспорта

**Класс:** L · backend + frontend параллельно · затем designer · **Проверки:** backend — tsc 0, юнит, e2e shipments; frontend — `node --input-type=module --check`.
Источник: `docs/audit/AUDIT-SHIPMENT.md` (читать целиком). Ниже — решения координатора; где расходятся с аудитом — действуют эти.

## Решения координатора (вопросы аудита 1–4)
1. Частичной готовности нет: задание `worktasks` — на всю позицию.
2. Позиция «со склада» — готова, если по ней выдана бронь (как в аудите).
3. Паспорт отгрузку не блокирует — только статус и подсказка.
4. **Сервер отгрузку НЕ блокирует (без 400 и без `force`)**: на проде заданий «В работе» пока нет, запрет остановил бы работу. Правило — только подсказка и выбор по умолчанию на экране.
5. Позиция изготавливаемая, но **не запускалась в работу** (нет worktask) — `canShip: true`, `missing: []`, `work: null` (старые заказы ведутся без «В работе»); позиция с worktask не в статусе done — `canShip: false`, `missing: ['Ещё в работе: <текущий шаг>']`, ссылка на карточку `#work?open=<id>`.

## Контракт (только добавляем поля, старые не меняем)
`GET /api/salesorders/:id/shipments` — каждая строка `remaining[]` получает:
`canShip: boolean`, `kind: 'make'|'stock'|'other'`, `missing: string[]` (по-русски, для экрана), `links: [{label, href}]`, `passport: {id, status} | null`, `work: {id, code, status, currentStep} | null`; в корне — `shippable: number` (сколько строк можно отгрузить).
Расчёт — `backend/src/common/text/shipment-ready.ts` (чистая функция + загрузка пакетом, без N+1). `order-readiness.ts` — пункт «Изготовлено» (все запущенные задания заказа done; нет заданий — пункт не показывается).
