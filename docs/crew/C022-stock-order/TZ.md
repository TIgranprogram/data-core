# ТЗ C022 — Склад: порядок раздела + воронка «Новая позиция»

> Координатор · 2026-11-04 · класс **L** · max agents **4** · review loops ≤ 2 · проверки: smoke; full перед выкладкой

**Зачем (слова пользователя):** привести в порядок раздел «Склад»; аудит по пунктам; особенно «Новая позиция склада» — нелогичные поля; по выбору в выпадающих списках отсеивать лишнее, оставлять нужное для заполнения. Координатор — решить грамотно и сделать.

**Язык менеджера:** да · **Приёмка глазами:** `#stock` → «+ Позиция» / «Новая позиция склада»: категория метизов / трубы / листа; на экране только уместные поля.

## Shared pack

- Решение координатора (черновое, аналитик уточняет матрицу):
  1. Форма новой позиции — **воронка полей**, не одна простыня. Сначала категория (+ ед.), затем блок «Металл» только если категория = труба/лист (`metalKind` уже есть на сервере).
  2. Поля металла: труба ≠ лист ≠ «не металл». Ширина и мойка не рядом «на всякий случай».
  3. Три названия (короткое / длинное / в счёте) — оставить; длинное и «в счёте» можно свёрнутым блоком «Ещё названия».
  4. СКФ.6/7 (покупные отдельно, признаки полями) — **не в этой волне** (XL в BACKLOG); здесь только UX формы и явные баги раздела.
  5. Медленный `GET /stock/items` на проде (5× за сутки, до ~325 с в логе) — в аудит архитектора (слепая зона), правка скорости — отдельным пунктом FIX, если найдена быстрая причина без смены схемы CRM.
- Контракт API не меняем без отдельного решения. Общая коллекция `materials` — поля только необязательные.
- Паттерн скрытия полей: `mount` + `f.field(k).hidden` как в `order-lines.js:60–74`.
