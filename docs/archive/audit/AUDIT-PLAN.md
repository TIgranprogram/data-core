# Аудит сайта и раздела «В работе» — план и метод (2026-10-29)

Запрос пользователя (2026-10-29): раздел «В работе» (карточки работ двигаются по этапам); весь сайт — «воронкой» слева направо с хлебными крошками; убрать дубли и лишние кнопки; единый вид и одинаковое поведение; правая панель с адаптивной раскладкой (переключатель в «⋯», выбор сохраняется); сайт стал медленно грузиться; пересмотреть архитектуру.

## Почему аудит не будет поверхностным

1. **Перечень собирает скрипт, а не глаза.** `node backend/scripts/ui-inventory.mjs` → `ui-inventory.md`: все 136 файлов приложения, каждая кнопка, подпись, подсказка, запрос к API, способ открытия записи (правая панель / окно / переход). Повторный запуск после переделки показывает, что изменилось.
2. **Дубли ищутся по данным.** §2 перечня — одна подпись в нескольких файлах; §3 — один запрос к API из нескольких файлов. Каждая строка получает вердикт: «одно понятие — одно слово», «общий модуль» или «лишняя загрузка».
3. **Полнота проверяется.** Каждый файл `sections/*.js` обязан иметь строку в чек-листе `AUDIT-UI.md`. Проверка — скриптом (см. ниже), пропуск = аудит не принят.
4. **Три области — три читателя, без пересечения.**
   | Область | Кто | Файл | Что читает |
   |--|--|--|--|
   | Бизнес-логика «В работе», воронка сайта | аналитик | `AUDIT-PRODUCTION.md` | `backend/src`, docs |
   | Вид, поведение, дубли, правая панель | дизайнер | `AUDIT-UI.md` | `backend/pwa`, перечень |
   | Скорость, архитектура | архитектор | `AUDIT-ARCH.md` | `main.js`, `core/`, `sw.js`, сервер |
5. **Скорость меряется, а не оценивается.** Одна метрика до/после: время готовности экрана входа и время до списка «Заказы». Замер 2026-10-29 (v1.340, экран входа, кэш): 54 модуля, 740 КБ кода, готовность 2,4 с — модули ждут друг друга цепочкой.
6. **Переделка — пачками.** Каждая пачка: что меняется, риск, как проверить; после пачки — перечень заново, дизайнер принимает, выкладка.

## Итог аудита (2026-10-29)

Отчёты: [AUDIT-PRODUCTION.md](AUDIT-PRODUCTION.md) (аналитик), [AUDIT-UI.md](AUDIT-UI.md) (дизайнер), [AUDIT-ARCH.md](AUDIT-ARCH.md) (архитектор). Полнота: все `sections/*.js` в чек-листе (один пропуск — `bulk-edit.js` — найден проверкой и дописан).

**Главное:**
1. **Скорость.** Тормозит старт, а не данные. Подозрение — `sw.js`: каждый файл ждёт сетевую проверку версии (стр. 97–102), страница — только после сети (80–94), после выкладки кэш стирается целиком (41–43). Сначала 15-минутный замер (готовая строка — AUDIT-ARCH §1.1), потом правка.
2. **«В работе».** Справочник «Виды работ» есть, маршрут есть только у модуля изделия; у изделия, состава и сотрудника (несколько видов) — нет; заданий в работу нет. Нужна новая коллекция `worktasks` (наша) и новые необязательные поля в общих с CRM `products`, `persons`, `worktypes`.
3. **Вид и поведение.** 12 дублей (Д1–Д12), окна ввода вместо правой панели (оплата, выплата, прайс, приёмка заявки), разнобой слов (словарь 17 строк), два «⋯» в одной панели.
4. **Доски.** Перетаскивание было сломано CSS (копия карточки уходила под доску) — исправлено 2026-10-29. Код перетаскивания продублирован: `ui/board.js` и `ui/drag.js` — свести в один.
