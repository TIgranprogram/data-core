## 2. Текущая модель (как связано сейчас)

`incomes` (позиция) —productId→ `products` (изделие). У изделия: `composition[]` (материалы/изделия/модули, у строки `_id`), `workTypes[] {workTypeId, lineId?, note?}` (плоский маршрут), `materialsSpec`, `facetValueIds`. Запуск создаёт `worktasks` (1 на позицию, замок `openIncomeId`), в нём копия маршрута `route[]` (+`plan` по шагу). Исполнитель — один на задание. Часов и денег нет. Часы людей живут в `payroll_timesheets` отдельно, вручную.

## 3. Общие с CRM — не ломать

- `products` (общая): наши поля `workTypes`, `facetValueIds`, `baseProductId` — «CRM не читает» (комментарии в схеме). Новые поля добавлять так же, необязательными; `composition` не менять по смыслу — его читает CRM и экран «Состав» (`composition.js`).
- `productmodules`, `materials`: только читать.
- `incomes`, `salesorders` — data-core (не CRM `orders`), но колонки не удалять; новые — необязательные.
- `worktasks`, `worktypes`, `persons`: worktypes/persons имеют CRM-поля (`hourlyRate` TZ-COST-301, `workTypeId` у персон) — старое поле `workTypeId` не трогать.
- Новые данные — **новые коллекции** data-core, без чтения CRM.

## 4. Находки и слепые зоны

1. Самое важное: **«часть» нигде не является первичной сущностью.** `composition` — спецификация материалов, `passportParts` — слова паспорта, `route[].lineId` — ссылка на строку `composition`. Стойки/навес/наполнение пергол в данных нет.
2. Маршрут уровня изделия плоский и общий для всех заказов — для «в заказе изменить» негде хранить правку (сейчас правка маршрута при запуске молча меняет изделие, `work-launch.js:71`).
3. Исполнитель и часы привязаны не к шагу, а к заданию — для Ганта «сотрудник × шаг» и для денег нужна привязка к шагу.
4. `worktypes.hourlyRate` лежит без использования; `defaultDurationHours`/`days` — оценка для Ганта, не норма на единицу.
5. Не измерено на проде: покрытие маршрутами (по помощи/докам маршруты введены вручную — вероятно единицы изделий).
