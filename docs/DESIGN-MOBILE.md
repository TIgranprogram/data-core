# DESIGN-MOBILE — стандарт «Мобильный рабочий экран»

Дополняет [DESIGN.md](DESIGN.md) и [CANON.md](CANON.md). Только токены `var(--…)` и эталоны kit «mobile» (`backend/pwa/ui/kit/mobile.js`). Новых компонентов и inline style нет. Первый экран по стандарту — склад ассистента кладовщика (2026-11-01).

**Решение пользователя 2026-11-01:** мобильные экраны — только в нашем приложении (PWA, установка на главный экран Android), отдельного Android-приложения/APK не делаем.

**Без системной клавиатуры (решение пользователя 2026-11-01):** клавиатура телефона на мобильном экране не открывается никогда (она закрывает пол-экрана). Числа — только своей крупной цифровой панелью на экране (0–9, «стереть», «+10»); выбор позиции — по шагам из списков (раздел → группа → позиция) или QR; полей ввода текста нет (`inputmode="none"`, без фокуса на input). **Исключение — заявка на новую позицию** («Принять» → «Подать заявку на новую позицию»): одно текстовое поле `mobile.textField`, системная клавиатура разрешена.

## 1. Когда применять
- Рабочий (кладовщик, производство) на Android-телефоне, на ходу, в перчатках, со слабым зрением.
- Роль видит только свой мобильный экран. Меню, шапка приложения и боковые панели скрыты.
- Экраны разных ролей выглядят одинаково. Различаются только шаги и функции.
- Обычные экраны (стол менеджера) этот стандарт не затрагивает.

## 2. Размеры и доступность
- Базовый текст ≥ 18 px, заголовок шага ≥ 24 px жирный, число (количество, остаток) ≥ 40 px. (2026-11-03: склад чуть плотнее — было 20/28, чтобы больше строк на экране.)
- Мелкого текста нет. Подсказка ≥ 16 px.
- Кнопка списка ≥ 56 px, главная (primary) ≥ 64 px. Зона касания ≥ 48×48 px.
- Расстояние между соседними кнопками ≥ 12 px. Отступ от края экрана ≥ 16 px.
- Контраст текста ≥ 7:1 (AAA), крупного и кнопок ≥ 4.5:1. Границы и фокус ≥ 3:1.
- Тёмная и светлая тема работают обе. Цвет не единственный признак: ошибка — иконка и слово.
- Иконка всегда с подписью. Жестов (свайп, долгий тап, двойное нажатие) нет.
- `:focus-visible` и `aria-label` на каждой кнопке. Системный масштаб шрифта не ломает вёрстку.
- Ширина 360–412 px без горизонтальной прокрутки.
- Все размеры — CSS-переменные семейства «mobile» (меняются в одном месте).
- Как настоящее приложение: заметный `:active` (вдавливание и затемнение) сразу; `touch-action: manipulation` и прозрачный tap-highlight (без задержки и масштаба по двойному тапу); на главных действиях `navigator.vibrate(10)`.
- Кнопка действия занята до ответа (`is-busy`), второе нажатие не шлёт запрос (`clientUid`). Запрос ≤ 15 с, по таймауту — «Сервер долго отвечает. Повторите.».
- Скорость: список > 100 строк рисуется порциями по 50 (догрузка при прокрутке); справочники (склады, категории, отделы) — кэш на сеанс; главный экран рисуется сразу, лента — скелетом, затем данные.

## 3. Устройство экрана
- Шапка закреплена (тело скроллится, шапка и низ не прыгают): слева «Назад», справа шаг «2/4» компактно (aria-label «Шаг 2 из 4») и, на главном экране, шестерёнка «Настройки». Заголовок-вопрос — только где без него неясно. Слева большая кнопка «Назад» (≥ 56 px, с текстом).
- Один вопрос на экран. Одно главное действие на экран.
- Главное действие внизу, во всю ширину, в зоне большого пальца. Вторичное — выше, слабее.
- Подсказка «что сделать» — только пока главная кнопка неактивна; иначе её нет.
- Ни один шаг не падает: сбой запроса — крупная ошибка с «Повторить»; неожиданная ошибка экрана — «Что-то пошло не так. Повторить» вместо белого экрана.
- Долгое действие: на кнопке «Сохраняю…», повторное нажатие заблокировано.
- «Выполнено» (склад): без отдельного экрана — крупное уведомление ≥ 3 с («Выдано: Болт М8 · 20 шт») и возврат на главный экран; новая запись — сверху ленты.
- Прокрутка только вертикальная. Главная кнопка закреплена внизу.

## 4. Шаблоны шагов
- **Поиск или скан позиции:** поле поиска ≥ 56 px, кнопка «Сканировать» (когда есть камера), результаты: название, остаток крупно, единица.
- **Количество:** число ≥ 40 px по центру, «−»/«+» ≥ 64 px, быстрые «+10», единица и остаток; больше остатка — «На складе только N шт.».
- **Выбор из списка:** строки-кнопки ≥ 56 px, выбранная — галочка и рамка; больше 7 пунктов — поиск сверху.
- **Кому / на что:** сначала два крупных варианта («На заказ» / «На производство»), затем список заказов или людей; недавние — сверху.
- **Подтверждение:** сводка 3–4 строки («Болт М8 · 20 шт · на заказ 1245»), главная кнопка-глагол («Выдать»).
- **Ошибка:** крупный заголовок по-русски, одна строка причины, что делать; «Попробовать снова» и «Назад»; без кодов.

## 5. QR (следующий шаг)
- Кнопка «Сканировать» над ручным поиском, с иконкой и подписью; показывается, только когда сканер готов (заглушек нет).
- Запрос камеры словами: «Нужна камера, чтобы считать код». Крупная рамка, «Наведите на код», вспышка — кнопка с подписью.
- Успех — короткая вибрация и следующий шаг. Не нашлось — «Код не найден», «Сканировать ещё раз» / «Найти вручную».
- Нет доступа к камере — объяснение и сразу ручной поиск. Ручной поиск доступен всегда.

## 6. Тексты
- Язык рабочего; кнопка начинается с глагола: «Выдать», «Принять», «Дальше», «Назад», «Ещё раз».
- Заголовок шага — вопрос: «Сколько выдать?», «Кому выдать?».
- Без кодов, ID, аббревиатур и английских слов. Заказ — номер и название. Предложения ≤ 20 слов.

## 7. Офлайн и повтор
- Без связи — постоянная строка «Нет связи. Данные сохранены на телефоне».
- Операция без связи уходит в очередь: «Сохранено, отправится при связи», счётчик «Ждут отправки: N», после связи — «Отправлено».
- Отказ сервера не теряет операцию. Двойное нажатие не создаёт дубль.

## 8. Чек-лист приёмки (дизайнер и «Большая проверка»)
1. Экран собран только из эталонов kit «mobile», без своих классов и inline style.
2. Один вопрос и одно главное действие на экране.
3. Главная кнопка внизу, во всю ширину, высота ≥ 64 px.
4. Кнопки и строки ≥ 48 px, зазор ≥ 12 px.
5. Шрифт ≥ 16 px везде, текст ≥ 18 px, число ≥ 40 px.
6. Контраст проходит в обеих темах.
7. Нет иконок без подписи и жестовых действий.
8. На 360 и 412 px нет горизонтальной прокрутки.
9. Видны «Шаг N из M» и «Назад».
10. Тексты по-русски, без кодов; ошибка говорит, что делать.
11. Есть состояния: загрузка, пусто, ошибка, офлайн, «Выполнено».
12. Меню и шапка приложения скрыты.

Правила для `tools/site-audit.mjs` (экраны мобильного семейства): видимый текст ≥ 16 px; кликабельное ≥ 48 px, главная ≥ 64 px; ровно одна главная кнопка; зазор ≥ 12 px; без горизонтальной прокрутки на 360/412; нет кнопок только-иконкой; нет inline style и классов вне kit; нет латиницы/ID в тексте; контраст ≥ 4.5:1 в обеих темах.

## 9. Эталоны kit «mobile»
| Эталон | Назначение | Параметры |
|--|--|--|
| screen | каркас: закреплённая шапка (Назад, шаг n/of, шестерёнка «Настройки»), тело, закреплённый низ | title, back, step {n, of}, gear, body, foot, footHint |
| tiles | крупные плитки по 2 в ряд; с рисунком (категории: иконка из справочника, иначе ui/cat-art.js `catArt(название)`) или только подпись (отделы) | items [{value, label, art}], onPick, selected |
| feed | лента операций плитками «дата · что · количество · ед.», не кликабельна; loading — скелет | items [{date, text, qty, unit, kind}], loading |
| dateChoice | дата без клавиатуры: «Сегодня / Вчера / Другая дата» (список 30 дней) | onChange → {el, value()} |
| bigButton | главная и вторичная кнопка | label, icon, tone/kind, disabled, busy, hint |
| choice | выбор из списка; > 100 строк — порциями по 50 | items [{value, label, hint}], onPick, selected |
| textField | текст заявки (многострочное поле; только для заявки на новую позицию) | label, placeholder → {el, value()} |
| qty | ввод количества: число 40 px и своя цифровая панель (0–9, запятая, ⌫, Очистить, +10), без системной клавиатуры | value, unit, max, hint → {el, value()} |
| drill | пошаговый выбор без поля ввода: раздел → позиция; больше 30 строк — буквенный указатель; extra — «Сканировать», когда готово | levels [{title, load(path)}], onPick, extra, empty → {el, up()} |
| scan | экран камеры для QR: крупная рамка, «Наведите на код», «Отмена»; найден — вибрация и onCode; нет камеры — ошибка и ручной выбор. scanSupported() — кнопку «Сканировать QR» показывать только если true | onCode(text), onCancel, hint → {el, stop()} |
| done | «Выполнено» | text/summary, again, home |
| error | крупная ошибка | title, reason, action, onRetry, onBack |

Новый вариант эталона — сначала в витрине `#kit`, затем на экране. Новый мобильный экран — ТЗ по этому стандарту, собирается только из эталонов семейства.
