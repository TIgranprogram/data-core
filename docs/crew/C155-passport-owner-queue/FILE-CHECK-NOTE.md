# П155-1. Три рисунка при выпуске на QA

На stand06 у самостоятельного экземпляра 3209 карточка показала `missing=[]`, а выпуск вернул 400 по трём рисункам даже после восстановления файлов с совпадающим SHA. **Карточка учитывает наличие ссылок. Выпуск дополнительно читает и декодирует файлы.** Access установил причину этого прогона. Восстановили файлы из собственных images экземпляра, а проверка использовала другие photoId из effectiveImages изделия. Для черновика рисунки изделия замещают собственные рисунки экземпляра соответствующего вида. Восстановление фактических файлов и повтор выпуска ведёт координатор. Основание — `backend/src/modules/product-passport/product-passport.service.ts:179`, `:827`, `:835`, `:854`, `passport-product-images.ts:21`.

| Что различается | Основание |
|---|---|
| Статическая раздача читает `uploads` относительно рабочей папки процесса. Серверная проверка сначала учитывает `UPLOAD_DIR`, а при отсутствии этой настройки использует рабочую папку. Если разрешённые абсолютные пути отличаются, восстановление файла по HTTP может затронуть только первую папку. | `backend/src/main.ts:132`, `backend/src/common/uploads/safe-path.ts:8` |
| Для каждого обязательного вида нужен действующий `photoId`, запись в `photos` с `deletedAt:null` и её исходный `storageUrl`. В этой проверке нет фильтра по владельцу, признаку главного фото или организации. URL должен начинаться с `/uploads/`, содержать разрешённые ASCII-символы и пройти проверку пути. URL прокси с префиксом, параметры, пробел, кириллица или процентное кодирование могут нормально открываться по HTTP и быть отвергнуты как значение `storageUrl`. | `backend/src/modules/product-passport/passport-image-files.ts:31`, `:33`, `backend/src/common/uploads/safe-path.ts:4`, `:17` |
| Файлу недостаточно открываться статически. Тот же процесс должен суметь прочитать его и декодировать через Sharp в JPEG. Ошибка чтения или декодирования превращается для выпуска в общую причину «повреждён или пропал». Перед каждым использованием проверяется подпись файла, ошибки чтения и декодирования убираются из кэша. Локальный результат по id хранится лишь на время одного вызова. | `backend/src/modules/product-passport/passport-image-files.ts:14`, `:18`, `:22`, `:35`, `:37` |

Различные пути статической раздачи и серверного чтения — отдельный риск конфигурации. На stand06 подтверждено расхождение между собственными и фактически используемыми рисунками. Аудит не устанавливает дефект продовой инфраструктуры.
