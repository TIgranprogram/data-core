## Адресное внимание architect
- При конкурентном confirm складской callback гарантирует отказ pending partial до движения/qty, но старое `stock.createItem` выполняется до stock.move-транзакции: если материал не был привязан, одновременный confirm теоретически может оставить новую карточку каталога, созданную до отказа callback. При уже активном pending отказ идёт ДО createItem (проверено); source qty/аналитика/склад не меняются. Для абсолютной атомарности создания каталога при этой редкой гонке нужен отдельный session-aware API stock.createItem (вне текущего владения stock). Это не денежный факт и не дубль Photo/счёта.
