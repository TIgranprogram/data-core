# Выкладка с работы (вход на домашний сервер через VPS)

> ⚠️ **Папка секретная.** В `secret/` лежит ключ «рабочий ПК» — с ним можно зайти на домашний сервер.
> Переносите папку только флешкой (или своим зашифрованным диском). **Не отправляйте почтой, в мессенджерах,
> не кладите в облако и в git** (`secret/` в `.gitignore`). Потеряли флешку — сразу отзовите ключ (ниже).

## Как это работает

```
рабочий ПК ──ssh, порт 22──► VPS kppdf-crm.ru ──туннель──► домашний сервер (tiit) ──► release.sh как дома
             ключ «рабочий ПК»   (ключ умеет только          (ключ работает только
                                  пропустить дальше)          через этот туннель)
```

- На VPS ключ **не даёт консоль** и пускает только в один туннель (`127.0.0.1:4222`). nginx и sshd на VPS не менялись.
- На домашнем сервере ключ принимается **только из туннеля** (`from="127.0.0.1"`), не из сети.
- Туннель держит сам домашний сервер: строка `datacore-ssh-tunnel` в расписании (crontab) пользователя `tiit`,
  как и туннель сайта. Сервер выключен → с работы не зайти (и сайт тоже не работает).
- Выкладка — тот же `deploy/synology/release.sh`, что дома: бэкап → новые файлы (старые → `*.prev-<время>`) →
  сборка → перезапуск только data-core → проверка. CRM kppdf не трогается.

## Что в папке

| Файл | Зачем |
|--|--|
| `secret/datacore_work` (+`.pub`) | ключ «рабочий ПК» — **секрет** |
| `ssh_config` | вход `datacore-vm` (через `datacore-jump` = VPS) |
| `known_hosts` | «паспорта» VPS и сервера — чтобы не подсунули чужой сервер |
| `setup-work-pc.sh` | разовая настройка рабочего ПК |
| `check.sh` | проверка связи (ничего не меняет) |
| `deploy.sh` | выкладка |

## На рабочем ПК (один раз)

1. Поставить **Git для Windows** (https://git-scm.com) и приложение **Claude** (вкладка Code).
2. Скачать проект: в Git Bash `git clone https://github.com/TIgranprogram/data-core.git /d/data-core`
   (или скопировать папку проекта с домашнего ПК).
3. Скопировать эту папку с флешки **поверх** `D:\data-core\remote-access\` (нужна подпапка `secret/`).
4. В Git Bash:
   ```bash
   bash /d/data-core/remote-access/setup-work-pc.sh
   ```
   В конце должно быть «Всё на связи».

Домашние секреты (`deploy/synology/config.env`, `CREDENTIALS.md`, `.env`) на работу **не нужны**.

## Как выложить

Скажите Claude: **«выложи»**. Он проверит, закоммитит правки и запустит:
```bash
bash remote-access/deploy.sh
```
Проверить связь в любой момент: `bash remote-access/check.sh`.

Код между домом и работой переносится через GitHub как обычно (`git pull` / `git push`) — выкладка от GitHub не зависит.

## Как отозвать доступ (если потеряли флешку, сменили работу)

Попросите Claude **дома**: «отзови ключ рабочего ПК». Он сделает (ключ подписан `datacore-work-pc`):
```bash
# на VPS (через домашний сервер) и на самом сервере — убрать строку ключа
ssh tiit@192.168.1.52 'sed -i "/datacore-work-pc/d" ~/.ssh/authorized_keys; ssh root@<vps> "sed -i \"/datacore-work-pc/d\" ~/.ssh/authorized_keys"'
# по желанию — выключить и сам туннель: crontab -e на сервере, удалить строку datacore-ssh-tunnel, затем pkill -f "autossh.*4222"
```
Бэкапы до добавления ключа: `~/.ssh/authorized_keys.bak-datacore-work-20261021` (на VPS у root и на сервере у tiit),
`~/crontab.bak-datacore-work-20261021` на сервере. Новый ключ — попросить Claude дома сделать заново.

## Если что-то не так

| Что видно в `check.sh` | Что делать |
|--|--|
| 1. VPS — НЕТ | на работе закрыт порт 22. Проще всего — раздать интернет с телефона и выложить через него. |
| 2. Вход — НЕТ, `Connection refused` / `open failed` | дома сервер выключен, нет интернета или туннель упал (поднимается сам за 1–2 минуты) |
| 2. Вход — НЕТ, `Permission denied` | ключ отозван или папка скопирована без `secret/` |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | **не продолжать** — сервер подменён или переустановлен; разбираться из дома |
