## Что сделать
1. По DATA.md выделить 15–25 частых сценариев (кто — роль, что, сколько раз за 30 дней, серии). Для каждого пройти путь в коде: сколько экранов, кликов, полей заполняет человек; что из этого система уже знает (прошлые заявки, склад, заказ, справочники).
2. Для каждого сценария — предложение одним из способов: умолчание / подстановка из прошлого / массовое действие / шаблон или «повторить» / автоматика на сервере / напоминание или очередь «Требует внимания» / убрать лишний шаг. Без новых больших разделов и без внешних сервисов.
3. Оценить: выгода (минут в неделю = частота × сэкономленное время, допущение — явно), риск для данных (низкий / средний / высокий), класс (S/M/L), что сломается у CRM kppdf (общие коллекции `supplyrequests`, `materials`, `stockmovements`… — `AGENTS.md` «Жёсткие правила» п. 4).
4. Отдельно — рутина самих разработчиков и администратора не нужна; только люди, которые работают в приложении (менеджер, снабжение, склад, трубарез, лазер, бухгалтер, директор, проектировщик).
