# Единая локальная проверка

В пульте: **Тесты кода и экранов → Все локальные проверки**. Запуск ручной, расписание не создаётся.
Перед первым запуском доступна кнопка **Готов ли компьютер к проверкам**.
**Итог локальной проверки** показывает статус и путь к последнему отчёту без повторного тестирования.

Один прогон последовательно проверяет окружение, типы, юнит, импорты PWA/admin, design-lint, циклы модулей, пульт и инструменты проверки вида.
Копии этих проверок через `dc check` внутри прогона нет. Браузер проверяет HTML-фикстуру: подписи, геометрию и axe.
Это проверка инструментов, а не текущих экранов приложения.

Журналы: `tools/logs/local-checks/<запуск>/REPORT.md`, `summary.json` и отдельный `.log` каждого выполняемого этапа.
Отчёт сохраняется после каждого этапа. Незавершённый отчёт имеет статус RUNNING; указатель last обновляется только после завершения.
Вывод каждого процесса ограничен последними 2 МБ. Максимум: юнит 15 минут, типы/пульт/инструменты 3 минуты, модель 5 минут, остальные этапы 1 минута.
Блокировка исключает два одновременных запуска оркестратора; исчезнувший процесс освобождает блокировку при следующем запуске.

Статусы: PASS — этап выполнен, FAIL — ошибка или таймаут, SKIP — этап недоступен/не выполнен полностью.
Общий итог: FAIL при любой ошибке, иначе PARTIAL при любом пропуске, иначе PASS.
Коды выхода: 0 PASS, 1 FAIL, 2 PARTIAL или сбой оркестратора. При частичном отчёте нельзя заявлять полную проверку.
Пропуск Docker не мешает тестам без БД. При отсутствии зависимостей этап пропускается явно, установки автоматически не запускаются.

## Для координатора

На другом рабочем ПК Git переносит код и кнопки, но не установленные зависимости, журналы или настройки LM Studio.
Нужны Node.js, Git, зависимости backend и tools/design-checks, установленный Edge (или DESIGN_BROWSER).
Проверка готовности ничего не устанавливает. Docker для прогона без БД необязателен; отсутствие даст SKIP.
Локальная модель нужна только при явно переданных снимках; используются настройки этого ПК, обязательного облака нет.
Журнал первого запуска появится только после проверки на этом ПК; кнопка последнего итога до этого сообщает ошибку отсутствующего отчёта.

Для заданных изображений: `node tools/local-checks.mjs --baseline <принятый.png> --current <новый.png> --vision-input <снимок-или-папка>`.
Параметры необязательны. Модель использует существующие настройки и кэш `vision-review`; только loopback, максимум 3 изображения.
Результат модели — гипотезы; PASS этого этапа означает выполненный анализ, не отсутствие дефектов. Различие PNG означает необходимость просмотра.
Старые снимки не подбираются автоматически. Эталон автоматически не утверждается. Без изображений эти этапы SKIP.

Обход реального сайта, e2e с БД и приёмка человеком отмечены SKIP с причинами.
Стенд и база автоматически не запускаются: изоляция БД и доступ требуют отдельного подтверждённого процесса проекта.
Новый запуск не читает .env, не входит в API сайта, не отправляет данные в облако и не изменяет расписания.
