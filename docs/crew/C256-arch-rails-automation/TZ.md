# ТЗ C256 — Автоматика рельсов архитектуры

**Программа:** [BEYOND](../C246-architecture-modularity/BEYOND-CHECKLIST.md) · [LOCKS](../C246-architecture-modularity/LOCKS.md)  
**Зачем:** закрытые решения не разъедутся: агент увидит красный сигнал до коммита, а не «потом переделаем».  
**Класс:** M · **Можно стартовать до C255** (аддитивно, не ломает рантайм) · **Проверки:** unit скрипта; ручной прогон; при возможности крючок в `dc check`

## Что сделать
1. Расширить `backend/scripts/audit-cycles.js`: кроме взаимных пар — обнаружение циклов длины ≥3 (или явный отчёт «длинных» при `-v`).
2. Короткая инструкция в скрипте / REPORT: код выхода ≠0 при любой находке (пары или длинные).
3. Подключить проверку в удобное место без ломки CI: пункт в skill `datacore-verify` §0 и/или `tools/dc.mjs check` (если дёшево).
4. Не менять бизнес-код модулей.
5. Обновить LOCKS: строка L-256.

## Критерии
- [ ] длинный цикл ловится на искусственном фикстурном примере или документированном способе проверки
- [ ] на текущем дереве: 0 пар (и 0 длинных, или явный белый список в REPORT)
- [ ] REPORT.md · карта backend обновлена

## Нельзя
- ESLint-границы доменов целиком (это C255).
- Переписывать модули «чтобы скрипт позеленел» без отдельного ТЗ.
- Прод, выкладка обязательная.
