# C155 — реализация интерфейса

| Пункт | Состояние |
|---|---|
| B1. Шаблон изделия | Книжка использует GET/PATCH проекции изделия, собственные значения проверяются при сохранении. Входы `templateFor` и `bookFor` ведут в шаблон. Маркер локальной среды использует существующую шапку книжки. |
| B2. Вариант и данные | Переключатель варианта в книжке. Short показывает готовую словарную фразу из проекции. Воронка задаёт только вопросы из списка непройденных веток, справа доступна своя формулировка и ссылки на справочники. Полный вариант сохраняет доступ к составу и материалам. «Сначала» показывает препятствия из ответа API, рекомендации идут отдельно. |
| B3. Образец и выпуск | Образец открывает обычные страницы, буклет выбирается отдельно. Самостоятельный выпуск подтверждает фирму и удерживает ключ запроса при повторе. |
| B4. Заказ и история | Заказ использует точные три идентификатора позиции либо существующий id паспорта. Выпуск и план передают версию. Книжка показывает ранее созданные экземпляры без изменения формата. |
| B5. Проверки | 137 тестов PWA с Chrome, 347 проверок Jest, синтаксис 31 изменённого ES-модуля, импорт-проверка 352 файлов, новых замечаний design-lint 0. Chrome с локальной фикстурой прошёл в двух темах. Приёмка на изолированной копии остаётся открытой. |

## Входы для QA

- `#products?open=<productId>&templateFor=<productId>` — карточка и шаблон. `#products?bookFor=<productId>` — прежняя ссылка. Открытие сразу делает один GET шаблона. Для уже подобранного short дополнительные данные воронки не запрашиваются.
- `#docs?tab=templates&of=doctpl&open=<productId>` — «Открыть шаблон» или «Образец без номера». `#docs` → «Новый паспорт» → выбрать изделие → книжка. Фирма спрашивается только при выпуске.
- `#docs?tab=orders&of=orderpass&open=<orderId>` — план версии 1. У существующей позиции открывается её экземпляр по id. Для новой позиции кнопка «Создать черновик паспорта» в блоке «Документы» передаёт изделие, заказ и позицию. Готовый черновик использует сохранённый вариант.
- `#docs?tab=archive&of=passarchive&open=<passportId>` — просмотр старых паспортов и печать по сохранённым данным. Запросы просмотра, печати старого экземпляра, PDF заказа и ZIP содержат `readOnly=1`.
- В short сервер выбирает подходящую фразу. Если есть варианты и требуется ответ, появляется один список «Вариант краткого описания». Сохраняется только выбор словарной ветки. Если вид изделия отсутствует и фраза не определена, доступен выбор вида. В «Своей формулировке» можно сохранить фразу и части только для данного изделия. Ссылки на справочники открываются отдельно, после правки «Обновить» перечитывает шаблон.

Локальный Chrome 1440×900 с фикстурой проверил первый GET, неизвестный критерий, переключение вариантов, сохранность ввода после отмены, запрос последовательных страниц, подтверждение фирмы и переход на возвращённый экземпляр. Устранён цикл импорта, воспроизводившийся при холодном открытии книжки. Зависимости книжки и печати загружаются по действию. Preload оболочки сократился на 30 модулей относительно промежуточного списка этой работы. Замер качества PDF, реальных данных, работающего окружения и истории на копии ещё нужен.

На снимке тёмной темы подпись общей зоны загрузки на листе выглядит тусклой. На приёмке проверить читаемость и вставку в свободный слот с реальным рисунком.

После просмотра дизайнером подпись внизу книжки для старого или выпущенного паспорта поменялась на «Просмотр и печать доступны в этом окне». Chrome с локальной фикстурой подтвердил исходный режим редактирования, открытие старого экземпляра и смену подписи после выпуска. На копии подпись подтверждена у выпущенного паспорта №611 в тёмной теме. [Снимок](evidence/dictionary-panel/issued-dark.png)

## Подготовка приёмки

| Состояние | Действие и ожидаемый результат |
|---|---|
| Изделие 1066 с рисунками Inventor, старым выпуском и заполненными габаритами | Открыть из карточки и по старой ссылке. Видны исходные данные, тип, рисунки, вариант и метка локальной среды. GET шаблона без записи в паспорта или счётчик. Переключить full и вернуться в short. |
| Изделие без BOM и материалов, с применимой словарной фразой | Открыть short и образец сразу. При неоднозначном выборе ответить только на фактический вопрос воронки. Отдельно проверить свою формулировку и возврат к справочнику, отказ от закрытия и повторное открытие. Пустые материалы отсутствуют в обязательных причинах short. |
| Изделие с отсутствующим видом или критерием фразы | Выбрать вид или вариант из справочника. Сохранить, закрыть, открыть через прежний вход и проверить запомненный ответ. Изделие с известными значениями пропускает эти вопросы. |
| Изделие с бетонированием и неполной безопасной инструкцией | Видно фактическое препятствие и действие для заполнения. После сохранения готовность обновляется. Проверить отдельно рекомендацию без обязательного статуса. |
| Две свои фирмы, самостоятельный выпуск | Образец и отдельный буклет оставляют число экземпляров и счётчик прежними. Отмена выбора фирмы оставляет шаблон. Затем выбрать фирму и выпустить. Повтор того же запроса возвращает исходный id/номер, скачивание сохраняет номер. |
| Две точные позиции одного изделия, разные фирмы | Открыть черновик или выпустить из каждой позиции. Сверить id позиции, заказа, фирмы и экземпляра. Выбрать другой вариант в плане и проверить, что существующий вариант не меняется. Смешанный PDF использует варианты выданных записей. |
| Исторический выпуск и исторический черновик | Сравнить номер, содержимое и печать старого выпуска. Проверить отсутствие кнопок перевода и изменения в книжке прежней записи. |

Снимки для перечисленных состояний — при фактическом прогоне в светлой и тёмной теме компьютера. Результат — `UI-REVIEW.md` после браузерных действий, сверки с API и просмотра файлов. Остановить сценарий после первого несоответствия, записать маршрут, состояние и действие.
