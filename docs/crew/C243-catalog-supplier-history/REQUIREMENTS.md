## Причина противоречия

Это два разных факта, а не доказанная потеря поставщика:

| Представление | Источник | Реальный смысл |
|---|---|---|
| Материал в общей таблице | supplier-catalog.service.ts:materialFilter()/offerMaterialIds() и materialRow() | Материал не имеет живого supplieritems, связанного materialId; supplierId=null, priceHint=null в этой проекции не утверждают отсутствия закупок |
| Фильтр supplierId=none и counts.noSupplier | Тот же список materials без deletedAt=null предложений | «Без предложений», а не «никогда не закупали/поставщик неизвестен» |
| Карточка материала | supplier-catalog-card.js:summaryOf(materialId) → GET /materials/:id/summary; suppliersBlock/pricesBlock | История и сводка материала: закупки и/или прайс, с отдельным источником цены purchase/catalog. DNS может быть в истории при отсутствии активного предложения |
| Поля priceHint/priceDate таблицы | Предложение supplieritems; для materialRow принудительно null | Цена **предложения**. Исторические 85 299 из карточки не превращаются автоматически в действующее предложение |

Материал представлен строкой id=m:<materialId>, а карточка берёт сводку по настоящему materialId. Следовательно, различие таблицы/карточки объясняется их проекциями; по локальному коду нельзя объявить конкретную закупку DNS неправильной или восстановить предложение. Отбор существующего поставщика остаётся отбором предложений, а не всех его исторических закупок.

## Минимальная принятая дельта

1. Badge таблицы для kind=material: **«Нет предложения»** вместо «Поставщика нет». Подсказка: «Нет действующего предложения в каталоге. Поставщики и цены прошлых закупок могут быть в карточке».
2. Пункт фильтра **«Без предложений»** вместо «Без поставщика»; сохранить supplierId=none/noSupplier как совместимые API-ключи. Фильтр/счётчик/хлебная крошка/пустая выдача объясняют отсутствие живого предложения. Название колонки при необходимости уточнить до «Поставщик предложения», а цены — «Цена предложения, ₽»/«Дата цены предложения», чтобы тире не отрицало историю.
3. Подсказка карточки для материала без предложения: **«Предложения в каталоге нет. Чтобы добавить предложение, загрузите прайс или свяжите его строку с этой позицией»**. Не утверждать «цены нет» и «поставщика нет». Существующие блоки «Поставщики»/«История цен» сохраняются; отдельное «Последняя закупка» не требуется для устранения подписи.
4. Быстрые отборы «Без цены»/«Цена устарела» относятся к предложениям. Уточнить «Предложения без цены»/«Цена предложения устарела» либо дать однозначную подсказку; не расширять их незаметно на материалы/исторические цены. В PRODUCT §2 координатор обновляет термин «Без поставщика» до «Без предложений».
5. Не заполнять supplierId/priceHint из истории в прежних полях: это меняет смысл сортировки, заказа и выбора поставщика. Материал без предложения при «В заявку» не получает DNS автоматически только из этой косметической правки. Ранее предусмотренная подстановка последней закупки на этапе самой заявки остаётся самостоятельным действующим правилом PRODUCT, без новой связи каталога.

Основная минимальная дельта — frontend-тексты и соответствующая документация. Менять базу/создавать supplieritems/пересчитывать историю/обновлять последний прайс для этого не нужно. Если обнаружится другое содержание materialRow или иная реальная связь5608549, сначала зафиксировать расхождение по ID, не маскировать подписью дефект данных.

## История, деньги и сохранённые случаи

- Цена предложения и цена закупки имеют разные источники и даты. Действующая цена не означает «последняя закупка». В карточке сохраняются source purchase/catalog и фактические даты.
- PRODUCT §2: последняя закупка materialprices/lastPrice без НДС, заявка — цена с НДС. Скриншот85 299 сам по себе не устанавливает НДС/валюту/единицу. Не копировать это число в priceHint или общую текущую цену без проверки.
- Не сравнивать/не агрегировать разные единицы, валюты и налоговые базы как одну цену. Не выводить «дороже/дешевле» по несопоставимым значениям. Если исторической записи не хватает базы — сохранять исходное значение и обозначать источник/неизвестность, без расчётного восстановления НДС.
- Предложение со старой ценой, предложение без цены и удалённое предложение — разные состояния. deletedAt!=null не даёт живого предложения, но его удаление не уничтожает историю закупки.
- Подмена пустого значения нулевой ценой запрещена. Права на денежные данные сохраняются: скрытое сервером null не означает «закупок не было»; не восстанавливать цену дополнительным запросом.
- Существующие URL supplierId=none, фильтры flag/noPrice/stale, сортировки и сохранённые входы остаются совместимыми. Переименование не меняет набор выбранных материалов/предложений.

## Если отдельно понадобится последняя закупка в таблице

Это необязательная вторая дельта. Нужны отдельные поля/колонки «Последняя закупка: поставщик, дата, цена, unit/валюта/налоговая база, источник/ID». Подставлять их в supplierName/priceHint запрещено. Проекция на сервере пакетная по IDs страницы, без summary-запроса для каждой строки и без N+1. Критерий последнего события — подтверждённая действующая закупка по фактической дате, не просто дата обновления и не совпадение названия; при равенстве стабильный ID. Даты/статусы/отмены/удаление и цена за единицу должны быть приняты до исполнения. Без этого минимальную правку не задерживать и новую проекцию не обещать.

## Критерии приёмки

| Случай | Ожидаемый результат |
|---|---|
|5608549 без живого предложения, с DNS в истории | Таблица «Нет предложения»; фильтр «Без предложений» включает материал; карточка сохраняет DNS/закупку/дату/85 299 в исходной базе после access-сверки; никакого противоречивого отрицания |
| Материал без предложений и истории | Тот же статус отсутствия предложения; карточка честно показывает пустую историю, не выдумывает поставщика/цену |
| Одно или несколько живых предложений | Существующие строки/поставщики/цены и выбор заказа сохранены; материал не попадает в «Без предложений» |
| Предложение без цены или с устаревшей ценой | Оно остаётся предложением своего поставщика; состояния цены не названы отсутствием поставщика |
| Только удалённое предложение и прошлая закупка | Входит в «Без предложений», история закупки сохранена; удалённое предложение не восстановлено |
| Цены разных unit/валют/НДС | Источник/база не смешиваются; никакого нового прайса и пересчёта без доказательств |
| canMoney=false, старый URL/сортировка | Права/скрытые суммы и прежний отбор сохранены; новая формулировка не меняет контракт |
| Заполненная таблица и карточка в обеих темах | Badge/фильтр/подсказки читаемы, одинаково объясняют смысл; исторический поставщик не воспринимается текущим предложением |

Это не блокирует установленный по коду семантический дефект подписи, но не позволяет объявить данные скриншота проверенными по API.
