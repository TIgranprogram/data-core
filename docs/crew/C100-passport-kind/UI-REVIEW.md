# C100 — приёмка вида (дизайнер), 2026-11-13

Вердикт: **Дизайнер: принято** (с 4 мелкими правками; снимки только в одной ширине ~720 px панели, 390/1024 и светлая тема не смотрены).

Просмотрено: evidence/kind-from-group-23_2.png, evidence/no-kind-3207.png; diff fill/control.js, index.js, paint.js, kit.css; REPORT-frontend.md.

Сценарии: вид из группы — строки «Подпись: значение ✎», источник серым, «подставлено» у назначения — ок. Вида нет — выбор «Вид изделия» с пояснением — ок. Правило C099 соблюдено, новых классов вне kit нет (одно правило `.k-stack > .link-btn` в kit.css:141 — по левому краю, токены не нужны).

Находки (мелкие):
1. no-kind: под выбором «Вид изделия» сразу идёт жёлтая плашка и вопрос «Что это за изделие» — два вопроса про одно. Плашка читается как ошибка. Прятать вопрос про элементы, пока вид не выбран, или без жёлтой плашки (control.js elementsEditor, sideNote).
2. control.js kindEditor, hint: «Свои значения изделия главнее» — непонятно менеджеру. Лучше: «Если в самом изделии задано иначе — будет по-вашему».
3. kind-from-group: «Назначение вида: Информирование» (paint.js kindNote) дублирует строку «Назначение: Информирование» ниже; «подставлено» не говорит откуда. Убрать «Назначение вида» из серой подписи; у назначения писать «из вида».
4. paint.js filledLink: подпись «из группы…» оторвана от строки зазором как отдельный блок. Свернуть в один плотный блок (меньший зазор), чтобы подпись читалась частью строки. Пункт «Не задавать у изделия» в списке — переименовать в «Сбросить вид (брать из группы)».

Язык менеджера: «из группы «…»», «из вида «…»», «своё» — понятно, кодов нет. Эталоны kit использованы (field, select, link, hint, stack).
