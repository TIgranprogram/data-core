## 0. Главное (что мешает завтра)

1. Три разных «категории» на одном экране: фильтр «Категория изделия» (product-block.js:67), «Категория паспорта» (form.js:66), «Раздел каталога» (form.js:115). Первая молча ставит вторую (product-block.js:69). Третья нужна только для списков.
2. Кнопка «Сбросить» у строки «Категория задана в изделии» (product-block.js:31, 38–43) НЕ убирает ручную категорию из изделия: меняет только эту форму. Затем «Запомнить» запишет её обратно.
3. «Запомнить для следующих паспортов» ВСЕГДА пишет категорию в изделие (form.js:207), даже если её не меняли. Группа перестаёт управлять категорией изделия, и этого никто не видит.
4. Фото в PDF: подпись только по виду («Габаритные размеры»), своей подписи в форме нет; видов «сверху / сбоку / 3D» нет; приложения «Схемы установки», «Монтаж», «Общий вид и элементы» — по 1 рисунку на лист.
5. Обложка: «Общий вид» растягивается на весь остаток обложки (passport-pdf-v2-cover.ts:85–87); печатается только первая картинка вида (overview[0]), остальные молча теряются.
6. Форма нового паспорта при открытии длинная: открыты «Описание» (4000 знаков) и «Картинки», воронка текстов — все шаги подряд.

## 1. Путь «новый паспорт» шаг за шагом

Порядок на экране (form.js:100–156), новый паспорт:
1. Плашка «Готовность к выпуску» (липкая, wire-form.js:134): «Осталось сделать: N» + чипы-ссылки. Не двоится, хорошо.
2. Блок «Изделие»: подсказка, фильтр категории, поиск, «+ Создать изделие», список (до 60), «Изделия нет в Продукции — взять из прошлого паспорта».
3. «Паспорт: категория и тексты»: категория (сегмент), воронка текстов, «Нормативы категории».
4. Свёрнуто: «Данные изделия», «Состав и материалы», «Ограничения и техданные», «Сертификат», «Комплектность», «После печати», «Свой текст», «Ещё картинки».
5. Открыто: «Выпуск» (дата, поставщик, гарантия), «Описание (раздел 1)» (для нового не свёрнуто, form.js:133), «Картинки» (общий вид + обязательные категории).
6. Кнопка «Сохранить черновик» (wire-form.js:140). Пока изделие не выбрано — отключена, причина видна строкой «Сначала выберите изделие» (product-block.js:22). Это хорошо.

## 2. Автозаполнение: кто кого перебивает

Порядок в applyProduct (product-block.js:114–156) и wireForm.defaults (wire-form.js:41):
1. Поля изделия (имя, артикул, раздел, размеры, вес, описание) — подставляются, если не правили руками.
2. Категория: своя у изделия (passportDefaults) > группа > раздел > справочник (form-values.ts:61–66). Не перебивает, если человек уже сам нажал сегмент.
3. passportDefaults: элементы, материалы, способ установки, тексты, числа, гарантия.
4. Таблица материалов изделия → таблица паспорта.
5. Умолчания категории (срок службы, гарантия, fieldDefaults) — только в пустое или серое.
6. Прошлый паспорт изделия — только в пустое; без имени, артикула, категории, комплектности, монтажа/назначения, текстов, материалов. Картинки — через _copyFrom, в пустые виды.
Правленное руками не затирается нигде. Серый цвет и подпись «из изделия / из группы / из прошлого паспорта» есть.

### Где выбор теряется или подставляется «не то»

2.1 Смена категории после выбора изделия стирает ВСЕ шаги воронки, и подставленные из изделия тоже (funnel.js:150), без сообщения. Логично (шаги привязаны к категории), но человек не поймёт, почему «Монтаж» снова пуст. Нужна строка-toast «Выбор текстов сброшен — категория другая».
2.2 Фильтр категории в списке изделий пишет в «Категория паспорта» (product-block.js:69). Если у выбранного изделия категории нет, останется категория от клика по фильтру; строка «Категория не задана…» (product-block.js:33) при этом есть, но «Воркаут» уже стоит. Проверить глазами.
2.3 «Запомнить»: (а) пишет категорию всегда (form.js:207) и закрепляет как «ручную»; (б) «Сбросить» в сводке ничего не удаляет на сервере; (в) поле показывается, только если правили поля из DEFAULT_KEYS, а текст «Да — категория, состав, ограничения, срок, гарантия» не говорит, что категория группы перестанет действовать.
2.4 Поставщик: комментарий form.js:160 обещает «у модели свой — подставится при выборе», но initial уже кладёт самого частого поставщика (не серым), а прошлый паспорт идёт «только в пустое». Итог по коду: поставщик из прошлого паспорта изделия НЕ подставляется. Проверить глазами на изделии с нетипичной компанией.
2.5 Описание: description изделия (текст из «Продукции») кладётся в «Описание 1.1» как подставленное; собираемое поле считает его «ручным» и перестаёт пересобираться при смене материалов и монтажа (ui/form.js:229–234); при сохранении паспорт помечается «изменено вручную: description» (form.js:186). Проверить глазами. Предложение: не подставлять description изделия.
2.6 Прошлый паспорт подставляет числа и картинки (габариты, фундамент…) молча. Если изделие переделано, схемы старые. У чисел подпись «из прошлого паспорта» есть, у картинок нет (wire-form.js:100, api.set без src).
2.7 «Сменить» изделие (product-block.js:62): подставленное остаётся в форме. В подсказке этого нет.

### Ручная категория изделия: заметность
Сейчас это одна приглушённая строка «Категория задана в изделии · Сбросить» в сводке — легко пропустить. Предложения:
- Рядом с сегментом «Категория паспорта» плашка-источник: «задана в изделии» / «из группы» / «выбрана вручную» (компонент badge, токены, не новый цвет).
- «Сбросить» переименовать «Взять из группы» и очищать passportDefaults.passportCategory (PUT passport-defaults). Если не делать — убрать кнопку.
- «Запомнить»: отдельная опция «Закрепить категорию за изделием», по умолчанию «нет».

## 3. PDF и фото

### Как сейчас (код)
- Страница A5. Виды: overview, dimensions, safety (=safety_zone), mounting, overview_callouts, nameplate, foundation, holes, assembly (+ служебный bom_item).
- Обложка: overview[0] вписывается в ширину и всю оставшуюся высоту; подписи нет; вторая картинка вида не печатается.
- Приложения (passport-pdf-v2-refs.ts:44–51): «Общий вид и элементы» — 1 на лист; «Габариты и зона безопасности» — 2 на лист; «Схемы установки опор» — 1; «Скважины» — 1; «Монтаж» — 1; «Сборка» — 2. Рисунок вписывается в ширину и в (высота листа ÷ число на листе).
- Рисунок «по месту» (ссылка fig:вид в тексте): ширина колонки, высота до целого листа (layout.ts:63).
- Подпись: «Рисунок N — подпись»; подпись = caption картинки, иначе название вида (KIND_TITLE): «Габаритные размеры», «Зона безопасности», «Схема установки опор».
- Своей подписи в форме нет: caption приходит только из импорта; formImages (passport-images.js:21) caption не хранит, так что пересохранение паспорта из импорта стирает подписи. Проверить на импортированном паспорте.

### Предложение раскладки
Вариант A (рекомендую): лист «Виды изделия» 2×2 с фиксированными подписями: «Габаритные размеры», «Вид сверху», «Вид сбоку», «Общий вид 3D». Клетка ≈ ¼ листа A5, подпись 9 pt по центру. Пустая клетка не печатается; одна картинка — на ½ листа. Нужна группа в APPENDIX_GROUPS с perPage 4 и режимом «сетка»; в layout.ts сетки нет — серверная работа, не P1.
Вариант B (малый риск): оставить стопку, perPage: 2 для foundation / holes / mounting / callouts — каждая картинка ½ листа; подпись по виду как сейчас. Схемы с цифрами могут стать мелкими — решает пользователь по готовому PDF.
Размеры по смыслу: общий вид ⅓–½ листа; чертёж с размерами ½; фундамент/скважины ½ (если мелко — 1); обложка — оставить воздух, не весь остаток.

### Какие виды нужны
Добавить в KINDS_V2 (форма) и PASSPORT_IMAGE_KINDS (сервер): view_top «Вид сверху», view_side «Вид сбоку», view_front «Вид спереди» (по желанию), view_3d «Общий вид (3D)». Вид safety в форме называется «Зона безопасности — вид сверху с размерами площадки» (passport-kinds.js:9) и путается с «Вид сверху» — переименовать «Зона безопасности (площадка вокруг)». В форме под миниатюрой — поле «Подпись (необязательно)», по умолчанию — название вида.
