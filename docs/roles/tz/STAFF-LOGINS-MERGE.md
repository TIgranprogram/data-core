## Жалоба пользователя
«Управление → Сотрудники»: 6 человек, у всех «нет входа». Люди, которым я делал вход и роли, здесь не видны. Похоже на задвоение.

## Аудит (координатор, 2026-10-29)
Задвоения записей нет. Есть **две таблицы с разным смыслом**, и связь между ними не заполнена:

| Таблица | Что это | Кто заводит | Где используется |
|--|--|--|--|
| `persons` | сотрудник (человек, ФИО, должность, зоны) | пришли из CRM kppdf | зоны, «Ответственный» заявки (`supplyrequests.responsibleId`) и договора (`salesorders.responsibleId`), исполнитель проектирования (`designtasks.assigneeId`), зарплата |
| `users` | вход на сайт (логин, пароль, роль) | админка «Пользователи» | вход, права, кому слать уведомления |

- Связь — одно поле `persons.userId` (`backend/src/modules/zones/zones.service.ts:119-126`). Сейчас у всех `persons` оно пустое → «нет входа».
- Экран «Сотрудники» строится только по `persons` (`zones.service.ts:136-152`). Вход без сотрудника нигде не виден.
- Связать можно только в карточке сотрудника: выпадающий список входов (`backend/pwa/sections/staff.js:88-98`). Из списка зон и из «Пользователей» — нельзя.
- Следствие: уведомления зоны идут по `persons.userId` (`zone-routing.ts:38-42`). Нет связи → всё уходит директору.
- `persons` и `users` — общие с CRM (AGENTS п.4): пишем только `persons.userId` / `persons.zoneCodes`, новые поля — только необязательные.

**Решение (по канону):** главная запись человека — `persons`. Вход — свойство сотрудника. Таблицы не сливаем физически (их читает kppdf); на экране — один список.
