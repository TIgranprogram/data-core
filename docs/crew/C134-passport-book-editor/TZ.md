# C134 — Редактор паспорта «как в PDF» из заказа

Класс: L · Агентов: ≤ 3 (datacore-frontend → datacore-designer; backend — только если п. 5 упрётся в сервер) · Проверка: smoke; full перед выкладкой.

## Что сказал пользователь (2026-11-16)
С правкой паспортов «полный бардак». В заказе, блок «Документы» → «Изменить паспорт» открывает **большое окно**.
В окне паспорт выглядит **как PDF**: те же страницы, тот же порядок, те же данные. Любое поле — сразу правится на месте.
Остальные страницы правки паспорта пользователю не интересны (не удалять, просто не вести туда из заказа).

Ответы пользователя:
1. При сохранении текста — выбор: «Только этот паспорт» или «В справочник (все изделия этой категории/источника)».
2. Паспорт выпущен → после правки кнопка «Сохранить и выпустить заново»: номер тот же, PDF обновляется.
3. Страницы — **А5, как в PDF** (один к одному), листаются вертикально в окне; окно широкое (почти весь экран).

## Где что
- Кнопка: `backend/pwa/sections/order-line-more.js:54` (сейчас уводит в `docs` → карточка паспорта). Заменить на открытие нового окна.
- Раскладка PDF (что на какой странице, порядок блоков): `backend/src/modules/product-passport/passport-pdf-v2*.ts` (`-cover.ts` обложка; остальные — разделы). Повторить раскладку в HTML, а не рисовать картинкой.
- Данные паспорта: `GET passports/:id` (снимок `snapshot`).
- API правки уже есть (`product-passport.controller.ts:452–515`):
  - `PATCH passports/:id/snapshot-item`, `POST …/snapshot-item/promote`, `POST …/snapshot-item/target` — пункты разделов;
  - `PATCH passports/:id/snapshot-field`, `POST …/snapshot-field/promote`, `…/sources`, `…/target` — описание, назначение, правила, обслуживание, монтаж;
  - `PATCH passports/:id` — шапка (название, фирма и т. п.);
  - `POST passports/:id/issue` — выпуск.
- Образец текущего редактора строк и окна выбора «этот паспорт / справочник»: `backend/pwa/sections/passports/card-blocks.js`, `field-edit.js`, `dialogs.js`. **Переиспользовать** их логику сохранения, не писать заново.

## Что сделать (datacore-frontend)
1. Новый модуль `backend/pwa/sections/passports/book-editor.js` (+ CSS в существующий файл стилей раздела): окно на весь экран, сверху — название, номер, статус, кнопки «Скачать PDF», «Сохранить и выпустить заново» (если выпущен) / «Выпустить», «Закрыть».
2. Внутри — страницы А5 (пропорции 148×210, белый лист с тенью), в порядке PDF: обложка (фирма, «ПАСПОРТ № …», название, номер изделия, картинка), затем разделы с заголовками и пунктами как в PDF, таблицы обслуживания, монтаж.
3. Каждое текстовое поле — правится на месте (клик → поле ввода по месту, текущий текст). Наведение показывает, что можно править. Строки «вписаны вручную» — жёлтая подсветка, как сейчас.
4. Сохранение поля → короткий выбор «Только в этом паспорте» / «В справочнике» (для справочника — подтверждение с числом затронутых изделий, как в C132). Где источник не поддерживает справочник — только первый вариант, без лишней кнопки.
5. Выпущенный паспорт: правки доступны; после правок активна «Сохранить и выпустить заново» → `issue`. Если сервер не даёт перевыпустить выпущенный — остановиться и описать в отчёте (координатор решит, нужен ли backend).
6. Картинки — только показ (замена — не в этой задаче).
7. Кнопка в заказе (`order-line-more.js:54`) открывает это окно; после закрытия строка заказа обновляет статус паспорта.
8. Язык менеджера: без служебных кодов, понятные подсказки. Компьютерный интерфейс — главный; мобильный не приоритет.
9. Обновить `atlas-data.js` / `help-guide-data.js` (шаг «Изменить паспорт»).
