# ТЗ БЗ-18 — порядок в «Справочниках»: убрать лишнюю «аналитику связей», скорость; аудит командой

**Зачем (словами пользователя, 2026-10-24):** «в справочники запихнута какая-то аналитика, что к чему привязано — по-моему лишнее, проверить! Пример: выбрал сотрудника — раскрывается список, и вместо инфы именно про сотрудника даёт, что он делал. А справочник подгружает ГРУДУ таблицы. В общем, привести в порядок справочники совместно с аудитом команды агентов».

**Роли:** аналитик ☑ · архитектор ☑ · хранитель данных ☑ · дизайнер ☑ · frontend ☑ · backend ☑ · qa ☑

## Что сейчас (для понимания)
- `pwa/sections/dicts.js`: клик по строке раскрывает «где используется» (`GET /dicts/<d>/<id>` → `related`: позиции, заявки…), колонка «Используется» (счётчик `used` по каждой строке — `d.usage()` в `src/modules/dicts/dicts.service.ts` считается по нескольким коллекциям при каждом открытии; кеш есть только для `passport*`).
- Именно это пользователь видит как «что сотрудник делал» и «грузит груду таблиц».

## Что сделать
1. **Аудит (параллельно, только отчёты):**
   - аналитик — по каждому справочнику: что человеку нужно увидеть при выборе строки (сотрудник — ФИО, должность, телефон, активен; материал — поля и т. п.); нужна ли информация «где используется» и где ей место (рекомендация по умолчанию: только в карточке справа, в блоке «Используется: N — показать», по кнопке; в раскрытой строке — данные самой записи, либо раскрытие убрать);
   - архитектор — какие запросы делает экран при открытии и раскрытии, сколько коллекций читает `usage()`/`related`, сколько мс; предложение: счётчики считать лениво/кешировать по версиям (как `passport*`) или не считать в списке;
   - хранитель данных — дубли и мусор в справочниках (сотрудники, цвета, организации, единицы, категории), план объединения (план → `--apply`, на проде — только по «да»);
   - дизайнер — вид экрана: таблица выбранного справочника, карточка справа, что лишнее/сливается.
2. **Координатор** сводит отчёты в решения (спорное — в `docs/QUESTIONS.md` пользователю) и дописывает сюда «Решение».
3. **Backend:** список справочника — без тяжёлых подсчётов по умолчанию (или из кеша версий); `related` — только по явному запросу из карточки; защита «используется — удалить нельзя» и «Объединить с…» остаются (проверка `used` — при удалении/объединении, на сервере).
4. **Frontend:** клик по строке → карточка записи (её поля), не список связей; «Где используется» — свернутым блоком в карточке, грузится по кнопке; колонку «Используется» — по решению (оставить из кеша или убрать).
5. **QA:** время открытия «Справочников» и выбранного справочника до/после (число запросов, мс) — в TEST-LOG.

## Критерии приёмки
- [ ] Выбрал сотрудника — вижу данные сотрудника, а не список его заявок/операций.
- [ ] «Где используется» доступно, но только по кнопке в карточке.
- [ ] Открытие справочника — без чтения всех связанных таблиц (по числу запросов/времени — заметно быстрее, цифры в TEST-LOG).
- [ ] Удалить используемое значение по-прежнему нельзя; «Объединить с…» работает.
- [ ] План чистки дублей от хранителя — в `docs/DB-AUDIT.md`, спорное — в QUESTIONS.
- [ ] tsc 0, юнит `dicts` зелёный, pwa — синтаксис ES-модулей.
