## Граница текущего законченного шага
Очередь первичной идентификации проверяет ровно3доказанные причины: отсутствует/недоступна группа каталога, не определён действующий вид изделия с учётом наследования, не определён применимый тип паспорта с учётом существующих приоритетов/MAF→BLG. Подпись возле фильтра объясняет этот состав. Это не счётчик всей готовности паспорта. Применимые конструктивные уточнения/словари C175 остаются отдельным проверяемым остатком, пустые произвольные признаки не считать ошибками.

## Сервер
- GET /api/showcase принимает needsIdentification=1, возвращает обычный публичный envelope; существующие запросы совместимы. Строка содержит identificationIssues[{key,label}] с конкретными человеческими причинами. Истина общая для фильтра/представления/total.
- Фильтрация ДО пагинации/count/facets, совместима с поиском/группой/серией/status; исправленные исчезают после reread. Клиент не выкачивает весь каталог.
- Учитывать живые kinds/groups/родителей и канонические passportCategoryFor/resolveKinds. Не сравнивать только null own. Не делать N+1 и не грузить изображения/BOM всех продуктов. Допустим только компактный scalar projection для вычисляемого фильтра + один общий metadata context, затем текущая paginated find/count.
- Никаких записей при GET. Mongo4.4. APIпуть/права/старые поля не менять.
- Existingbulk merges passportDefaults; проверить точечную pd.kindId/pd.passportCategory запись и partial/undo/сохранность issued, другие defaults не затирать.
