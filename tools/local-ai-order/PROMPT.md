# Инструкция для локального ИИ: сбор заказа в JSON

Ты готовишь данные для импорта заказа в CRM «Рабочее место» (ООО СпортИН-ЮГ).

## Вход

Тексты из файлов папки заказа: ТЗ, контракт, ВОР, ЛСР, КП, НМЦК. Часть файлов может быть чужой/лишней.

## Выход

Только JSON (без markdown), схема:

```json
{
  "orderNo": "краткий № договора или «⚠ изменить …»",
  "productionNo": "",
  "customer": "заказчик",
  "companyName": "СИЮ",
  "title": "предмет / объект одной строкой",
  "paymentForm": "б/р, без аванса",
  "productionDeadline": "ГГГГ-ММ-ДД или пусто",
  "deliveryDeadline": "ГГГГ-ММ-ДД или пусто",
  "shipDate": "",
  "notes": "ИКЗ, адрес, важное",
  "lines": [
    { "title": "наименование изделия", "unit": "шт", "qty": 1, "unitPrice": null }
  ],
  "skipped": ["что сознательно не включили и почему"]
}
```

## Правила

1. В `lines` — только то, что мы изготавливаем/поставляем как изделия (ограждение, стойки, секции, калитки, ворота, сетки, воркаут, стойки волейбольные…). Не стройработы, не бетон, не щебень, не электрика, не сети связи.
2. Кол-во и ед. из ВОР/спецификации. Цену ставь только если явно есть в смете/КП на эту позицию; иначе `null`.
3. `productionNo` всегда `""` (номер заказа выдаст сайт: последний + 1).
4. `companyName`: обычно `СИЮ` (СпортИН-ЮГ).
5. Чужие объекты в той же папке (другой адрес, другой заказчик, КП ДПС/навес не по этому объекту) — в `skipped`, не в `lines`.
6. Нет обязательного поля — заглушка с префиксом `⚠ изменить`.
7. Не выдумывай позиции, которых нет в документах.
