# C096 — независимая проверка нового изделия (внешний Claude)

**Формат сдачи обязателен:** полный отчёт только в `CLAUDE-E4-REVIEW.md`. Ответ в чат — максимум 3 строки: итог, путь к файлу, блокер (если есть). Не пересказывать отчёт в чат.

Задача только чтением, без кода, API-записей, деплоя и повторного full-прогона. Работай в отдельном worktree или читай текущие файлы без изменений: координатор правит Э4.

Прочти AGENTS.md, docs/PATTERNS.md, C096/E4-TZ.md и DECISIONS.md. Узкий scope: `pwa/sections/passports/funnel/new-product.js`, `funnel/index.js`, `products/form-fields.js`, `products/data.js`, `passports/product-block.js`; серверные источники только при конкретном вопросе.

Проверь независимую таблицу происхождения: общее изделие → passportDefaults → черновик → выданный снимок; отдельно номер, дата, заказ и данные экземпляра. Для нового изделия установи, какие связанные поля уже спрашивает passportFill и где сохраняет. Ищи реальные пропуски: скрытая подстановка чужих данных, потеря черновика при возврате, перенос старых признаков после смены группы, повтор POST после частичного успеха, несовместимая категория.

Результат — только `CLAUDE-E4-REVIEW.md` в этой папке: максимум 5 доказанных находок с файл:строка и воспроизведением; отдельно неподтверждённые риски. В начале отчёта зафиксируй время, HEAD, `git diff --stat` по scope и SHA256 проверенных файлов. Не внедрять универсальную платформу, не предлагать все CRUD. Код координатора в процессе: перед окончательным выводом сравни хеши, перечитай лишь изменившиеся строки и обнови версию проверки. Если файлы продолжают меняться, пометь вывод предварительным; промежуточный код не принимать за итоговый. Отсутствие новых находок — допустимый итог. Координатор не ждёт ручного запуска и продолжает реализацию.
