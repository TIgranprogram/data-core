## Текущий результат

- Черновики обновляются из изделия и справочников с переносом ручных абзацев по устойчивым ключам. Несовместимость даёт 409 без частичной записи и номера; карточка получает `syncWarning`, печать конфликтного черновика блокируется.
- Новая редакция собирается до единственного сохранения. Условная запись защищает ручные изменения и выданный снимок от запоздавшей синхронизации. Отдельная приёмка CAS — [E1-REVIEW.md](E1-REVIEW.md).
- Форма блокирует только действительно наследуемые поля; возврат из карточки изделия сохраняет ручной ввод. Умолчания принимаются явно, гарантия 12 месяцев больше не выдумывается. Исправлена потеря первого клика после сертификата.
- PDF переносит длинные абзацы/строки без лишних страниц. Новые размеры помечаются `sizeLayout: 2`, исторические issued автоматически не меняются. Проверены порядок книжки и добивка для N=1,2,3,4,5,7,8,9,12.
- Карта помощи показывает источники, потребителей и последствия изменений. Мобильная версия использует читаемый список связей вместо мелкой схемы.
- Новое изделие из паспорта переходит к применимым сведениям. Повтор после успешного POST и сбоя следующего шага продолжает тот же ID. Смена группы не переносит прежние признаки; возврат из вложенной полной карточки сохраняет весь черновик.
- Смена категории требует подтверждения очистки выбранных/ручных текстов; отмена ничего не записывает. Ошибка сохранения оставляет ввод и очередь на экране с явным повтором или отменой. Запоздалый ответ от прошлого изделия не подставляет его данные.

Реальный QA-предпросмотр имеет неполный набор рисунков; готовым паспортом к выпуску не считается. Расхождение размеров таблицы и чертежа исправлено только в новой QA-копии; повторная сверка A5/A4 PASS (1097×176×2000 мм). Полной матрицы ролей не было: проверен фильтр разделов компонента. OpenAPI экспортирован на изолированной test-БД:502 пути, содержимое без изменений.

Каталог и нормативные категории физически не объединялись; решения — [DECISIONS.md](DECISIONS.md). Предыдущие этапные отчёты ниже сохраняют историю, не текущий статус.

Потеря ответа первого POST до получения ID отдельно не воспроизводилась; локальный resume покрывает подтверждённое создание и последующие шаги, внутренние HTTP-повторы используют существующую идемпотентность.
