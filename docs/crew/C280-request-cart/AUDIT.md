# C280 · Аудит

Эталон: https://mb1.ru/catalog/shveller/. В категории сразу видны характеристики, единица, количество и действие добавления. Из этого берём быстрый набор по строкам и отдельную сверку. В DataCore витрина опирается на собственную номенклатуру. Розничные цены, доставка поставщика и аккаунт магазина к сценарию не относятся.

Существующие входы: одиночная заявка, загрузка из таблицы, пакетная форма расчёта закупки. Новый вход дополняет их. Корзина привязана к идентификатору материала, а не к названию: два одинаковых названия не означают один товар. Экспорт использует штатный xlsx-write.js.

Контракт: POST /supply/requests/bulk, manager/admin, до 200 позиций. Результат — обычные заявки requested. Маршрут заранее проверяет наличие и складской доступ, затем пишет по строкам. Ключ по строке строится из ключа пакета и materialId. В текущем сервере нет транзакции на весь пакет и уникального индекса для legacy clientUid. Повтор неизменённого снимка покрывает последовательное восстановление, но не даёт гарантии от двух параллельных запросов на сервере. Для дальнейшего выпуска отдельно оценить атомарный пакет или серверную квитанцию с ключом владельца и тестами конкуренции.

Excel скачивается из подтверждаемой корзины отдельно от записи. Количество числовое; название, единица и артикул текстовые; цен и финансовых данных нет. Для почты и мессенджеров в будущем нужен самостоятельный этап.

Источники: supply.controller.ts, supply.service.ts, dto.ts, supplier-catalog.js, order-bulk.js, requests.js, xlsx-write.js.
