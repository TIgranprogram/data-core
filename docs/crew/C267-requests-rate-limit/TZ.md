# C267 — доска заявок после HTTP 429

24.11.2026, класс M (поведение общего компонента, без нового оформления).
Жалоба: «Заявки → Доска → Заказать — Не загрузилось / Слишком много запросов — подождите минуту», без кнопки повтора.
Доступ подтвердил 2×429 на `/supply/requests` в версии C266; одиночный запрос сейчас успешен. Причина расходования лимита по агрегированному журналу пока не доказана. БД и серверные лимиты не менять; выпуск отдельно.

## Подтверждённые дефекты
- `ui/kit/board.js:fetchCol`: один повтор строго через 1100 мс, без учёта ответа сервера и без повторной проверки актуальности после ожидания.
- `board.js:load`: `failBlock(e, null)` — отказавшую колонку нельзя перечитать кнопкой.
- `core/api.js:errorOf`: заголовки Retry-After/Retry-After-short/Retry-After-long не передаются вызывающему коду.
- Общий `list.js:destroy` не вызывает уничтожение доски; отложенные запросы могут продолжиться после ухода.

## Готово, когда
- При 429 доска ждёт указанное сервером время (обычный/именованные Retry-After, секунды и HTTP-date); не подменяет минутное окно секундой. После этого максимум один автоматический повтор, затем видимая кнопка «Повторить» только нужной колонки.
- При отсутствии заголовка 429 — безопасный явный повтор; без бесконечных быстрых повторов. Остальные ошибки не получают новую политику повторов; записи никогда автоматически не повторяются этим исправлением.
- Пока ждём, существующее содержимое не пропадает без необходимости; запросы устаревшего фильтра/уничтоженной доски не отправляются после ожидания, результаты не меняют новый экран.
- Переключение/уход не оставляет таймеры и обработчики. Повторное применение того же запроса не плодит новую загрузку (если это подтверждается диагностикой).
- Регрессия: таймер/срок, repeated429, устаревший фильтр, уход, повтор одной колонки, успешные соседние колонки, фильтры/таблица. Прогон на заполненном стенде, искусственные429 только в перехвате браузера, без перегрузки прода.
- Smoke, UI-REVIEW независимого designer, отчёт и отдельный коммит; чужие WIP не включать.

## Исполнитель и границы
Frontend: `backend/pwa/core/api.js`, при необходимости небольшой чистый helper в `core/`, `ui/kit/board.js`, `ui/kit/list.js` (только destroy), тесты этих изменений. Новые импорты — обновить preload. Пользовательские подписи/семантика заявок, backend и стили вне задания.
Координатор: диагносценарий, стенд/доказательства, DESIGN/карта при изменении поведения, BACKLOG/отчёт. Доступ: api.sh и только чтение. Designer: UI-REVIEW после.

## Источники
- Фактические границы сервера: app.module.ts — short 10/1000мс, long 100/60000мс; менять их не поручено.
