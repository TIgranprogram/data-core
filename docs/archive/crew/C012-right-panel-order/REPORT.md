# C012 — правая панель и карточка заказа

Проверено по коду 2026-11-03. Стенд и снимки не открывались. КП PDF, `offers` и `docs/audit/AUDIT-KP.md` как образец вида не использовались.

План правок: [FIX-TZ.md](FIX-TZ.md). Колонки заказа: [ZONES-MAP.md](ZONES-MAP.md).

## Вердикт

Оболочка правой панели **одна**. Её меняют в одном месте — и это доходит до всех карточек, которые открывает приложение.

Внутренность заказа **своя**. Она не пользуется колонками. Директор видит длинную простыню: сначала повтор шапки, внизу договоры с вкладками. Кусков заказа («слон на части») на первом экране нет.

Второй ящик заводить не нужно. Нужно дописать ту же оболочку, чтобы карточка отдавала несколько блоков с зоной, и собрать заказ из уже существующих эталонов.

## 1. Переиспользуемый вид — есть

Смена раскладки зон в `ui/card.js` (`arrange`) и в `ui/panels.css` (`.dz-*`) применится ко **всем** карточкам, которые идут через этот API.

| Что | Где | Живые экраны |
|--|--|--|
| Ящик: шапка, тело, подвал, «⋯», ширина | `backend/pwa/ui/card.js` `openCard` (шапка ~17–34, сборка ~98–160, меню вида ~162–183) | Да. Единственный вызов ящика: `backend/pwa/main.js` ~495–527 (`open=` / `new=`, параметр `of`) |
| Колонки main / side / wide | `card.js` `arrange` ~152–160; стили `backend/pwa/ui/panels.css` ~409–426 | Да, но только если в карточке есть хотя бы две непустые зоны |
| Выбор вида | «⋯» шапки, настройка `panelLayout`: пусто = одна колонка, `two`, `wide` (`card.js` ~55–56, `core/prefs.js` ~21) | Да, на все карточки сразу |
| Вход в любую запись | `ui/side-form.js` `openSide` → адрес `of` + `open` → тот же `openCard` | Да |
| Эталон содержимого `kit/panel.js` `panel()` | Рисует второй `aside.drawer` **без зон** | **Нет.** Только витрина `sections/kit.js` ~119 |

`design-requests.js:22` называет функцию `openCard`, но это переход на `of=prodreq`. Дальше открывается настоящий ящик.

Группы внутри панели, которые уже общие: `kit.section` (сворачиваемый блок), `kit.row`, `kit.table`, `readonlyGroups`. Хороший пример содержимого — карточка счёта `invoice-workspace.js` ~77–84 и шаги заявки `request-step.js`. Карточка заказа эти эталоны не использует.

### Исключения со своей разметкой

Оболочка та же. Внутри — свой HTML, зоны почти не заданы. Правка `arrange` их не разложит по колонкам, пока они отдают **один** узел.

| Место | Своя разметка | Зона |
|--|--|--|
| `salesorders.js` `details` ~380–391, `contractGroup` ~242–351, `readinessBlock` ~122–146, `produceBlock` ~354–360 | `.so-sec`, `.so-grp`, `.section-title`, вкладки, широкие таблицы | весь `extra` = `wide` (`:529`) |
| `order-design.js` ~12–58, `order-work.js` ~26–72 | `.spec-list` / `.spec-row`, свой заголовок | внутри вкладки договора |
| `order-reservations.js`, `order-shipments.js`, `issuedBlock` `salesorders.js` ~181–194 | списки и таблицы склада и отгрузок | вкладки «Склад» / «Отгрузки» |
| `design.js` `card.extra` ~252–265 | `.db-blocks`, свои свёртки | зона не задана → main |
| `products.js` ~117–119 | один `div` (варианты, файлы, состав, заказы) | `extra` = `side` |
| `stock.js` ~279, `orders.js` ~218, `staff.js` ~155 | один дополнительный блок | `extra` = `side` |
| Формы `form.build`: `invoice.js`, `composition.js`, `passport-tree.js`, `kp.js` | своё тело формы | тот же ящик; вид КП не копировать |
| `side-form.js` | сразу режим правки, просмотр пустой | колонки не участвуют |
| `kit/panel.js` | второй ящик без колонок | только витрина |

Остальные `section.card` (заявки, паспорта, контрагенты, справочники и др.) идут через `openCard`. Зон у них нет: всё в main, фото — side, история — wide. Если фото и истории нет, «две колонки» ничего не меняют (`arrange` ~158: меньше двух зон — снова одна лента).

## 2. Как устроена панель сейчас

Порядок блоков в просмотре (`card.js` ~118–146): воронка (`top`) → фото → цифры (`stats`) → кнопки → поля (`view`) → `extra` → история.

Зона по умолчанию — main. Фото — side, история — wide. Свой выбор: `card.zones` или `data-zone` на узле. `data-zone` в разделах **никто не ставит**. `extra` — всегда один узел, его детей по колонкам не разнести.

Вид по умолчанию — **одна колонка** (`layoutNow`, пустая настройка). Колонки включаются только из «⋯».

Ширина панели по умолчанию: `clamp(480px, 40vw, 760px)` (`screens.css:18`). Колонки в CSS считаются по **ширине панели**, не окна (`panels.css` ~420–426):

- уже 460 px — одна лента, порядок main → wide → side;
- от 460 — сетка 3:2;
- от 680 — 1:1.

В `DESIGN.md` §4 (строка про раскладку) написаны другие пороги: 760 и 1100. Код и канон расходятся.

На 1440 px панель около 576 px: даже выбранные «две колонки» дают 3:2, не равные. На 390 панель на весь экран, колонок нет — так и должно быть.

## 3. Карточка заказа — что видит директор

Клик по заказу открывает `salesorders.card` (`salesorders.js` ~503–531). Заголовок хороший: «Заказ № …» (`heading` ~70). Тип «Заказ» есть.

Дальше по ленте:

1. Воронка всего заказа (`top` ~519, `stage-bar.js`). Это этап **заказа**, не части.
2. Четыре цифры: договоры, позиции, сумма, оплачено (`stats` ~507).
3. Кнопка следующего этапа и «Изменить заказ» (`actions` ~520–527).
4. Те же факты ещё раз полями: договоры, заказчик, компания, срок, приоритет, «что дальше», «не распределено» (`view` ~508–517).
5. Только потом `extra` = wide (`details` ~380–387): плашка «не сопоставлено», таблица «К производству», «Готовность к отгрузке», блок «Договоры».

`details` не делит блоки по зонам. В режиме «две колонки» wide вливается в main, side пуст, зон меньше двух — вид снова одна лента. В режиме «две и широкий низ» слева шапка и повтор полей, **правая колонка пустая**, снизу вся простыня договоров.

Группа договора (`contractGroup` ~242–351) — рамка `.so-grp`, не сворачиваемая секция kit. Вкладки: Позиции, Проектирование, Работа, Склад, Отгрузки, Паспорта. Пока вкладку не откроют, этапа части не видно.

Строка позиции (`:290–294`) — номер, фото, название, количество, отгружено, цвет, деньги. Клик уводит в карточку позиции `orders.js` ~217. Там деньги, отгрузка, изделие. Этапа изготовления и ответственного нет. Кнопка «назад» подписана «Заказ № …», а в номер подставлен **номер договора** (`orders.js:220`, `r.orderNo`).

Проектирование (`order-design.js` ~37–44): «D-… · статус» или «нет задачи». Исполнителя нет.
Работа (`order-work.js` ~49–56): «W-… · шаг» или «не запущена». Исполнителя нет.
Ответственный есть только в карточке **договора** (`salesorders.js` ~609), не на куске и не на заказе.

Готовность (`readinessBlock` ~122) — проверки всего заказа. На части она не раскладывается. Прячется, когда этап уже «готов / отгружен / закрыт» (`:385`).

Итог для директора: объём не спрятан, фокуса нет. Важное (части, сделано ли, кто ведёт) лежит в конце и за вкладками. Неважное (повтор заказчика и сумм) — в начале.

## 5. Целевой поток (словами)

Список заказов → карточка «Заказ № …». Сразу видно, на каком этапе заказ и что сделать одним шагом. Ниже — части: название, сколько, этап этой части, сделано или нет, кто ведёт или «нет ответственного». Договоры не прячут части во вкладки: подпись договора тихая, у строки.

Справа — справка: заказчик, срок, компания, деньги (если роль их видит). Снизу, свёрнуто — склад, отгрузки, паспорта, полная таблица с суммами.

Клик по части оставляет тот же смысл: сначала этап и человек, потом деньги. Назад — к этому заказу, подпись с номером заказа, не договора.

Язык менеджера: без кодов D-/W- в первой строке. Код можно вторым серым текстом у ссылки на задачу.

Объём не запрещён. Он сложен: открыто то, что решает «где заказ», закрыто то, что нужно редко.
