## Штатный план для утверждения координатором

1. Перед записью повторить GET договора, проверить отсутствие документа с тем же SHA/номером/датой, перечитать `legalVersion`. Любое неизвестное состояние сначала выяснить чтением.
2. Оригинал: `POST /api/photos/intake/c169-<sha>?sha256=<sha>`, multipart поле `file`. `api.sh` уже поддерживает `--form 'file=@<абсолютный-путь>;type=application/pdf'`; JWT остаётся внутри скрипта. Применять одну учётную запись api.sh для upload/receipt.
3. Перечитать `GET /api/photos/intake/c169-<sha>` → `{uid,sha256,fileId,storageUrl}`; сверить SHA, затем GET `/api/photos/:fileId`. UID глобально уникален, привязан к аккаунту и SHA; несовпадение/удалённое состояние даёт409. Повтор тех же байтов возвращает ту же квитанцию; потеря ответа требует чтения, а не другого UID.
4. `PATCH /api/salesorders/<id>/legal` с JSON ниже. В `legal` передать полный перечитанный комплект с неизменными прежними документами, issues, планом и статусами; добавить только один `customer_invoice`. Все прежние значения сохранять, служебные не-DTO поля исключить. `lineRefs` допустимо оставить пустыми: новые строки/сопоставления не создаются. При необходимости привязать только доказанные существующие IDs исходных строк, без каталога.

```json
{
  "version": 0,
  "clientUid": "c234-customer-invoice-<sha>",
  "reason": "Добавление исходящего счёта по явному основанию в оригинале; поручение владельца C234",
  "legal": {
    "...": "точная копия текущего legal по DTO",
    "documents": [
      { "...": "все прежние документы неизменно" },
      {
        "uid": "c169-<sha>",
        "kind": "customer_invoice",
        "number": "44",
        "date": "2026-11-18",
        "revision": "1",
        "fileId": "<из квитанции>",
        "sourceSha256": "<sha>",
        "gross": 1352400,
        "vatRate": 22,
        "vatAmount": 243875.41,
        "currency": "RUB",
        "lineRefs": []
      }
    ]
  }
}
```

Для45/46 заменить номер, суммы, SHA, ID договора по таблице. `clientUid` в пределах100 символов (приведённый префикс плюс64 SHA укладывается). Сервер сравнивает CAS `legalVersion`, хранит receipt по clientUid+hash, запрещает изменение/удаление старых оригиналов. При привязке сервер читает физический файл, пересчитывает SHA и устанавливает `sourceProtected=true`. Повтор неизменного запроса с тем же clientUid идемпотентен; новый clientUid при неясном ответе не применять.

5. После PATCH перечитать договор и фото: ровно2 документа, прежний договор неизменен; customer_invoice верного номера/даты/суммы/SHA, legalVersion=1. Проверить productionAssigned=false, отсутствие productionNo/productId и изменения строк/платежей/склада. Ни `/supply/invoices`, ни создание salesorders/incomes, ни оплата не нужны.
