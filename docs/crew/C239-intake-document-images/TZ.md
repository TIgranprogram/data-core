# C239 — извлечение и загрузка рисунков из КП через Пульт

23.11.2026. Владелец: «да давай загрузку настроим и догрузим фото». Класс M/L уточнить после плана. Статус: анализ источника и существующего механизма фото.

Исходник: КП-0001 от 11.11.2026, SHA `5e903b1cb097e679dfefe586b37ce817d15f860aba366296cc7ce52df752361c`. Оригинал уже приложен к договору 18/11/44, ID `6b03d14cb607f46540f3a9f2`, файл `06ecf934fdaec9012b0030e2`. Связь КП и договора подтверждена владельцем и девятью исходными позициями в C234.

Цель: подготовить повторяемое извлечение иллюстраций из исходного PDF и загрузку к соответствующим **исходным позициям договора**, сохраняя оригинал. Каталог изделий и его сопоставление владелец выполняет сам; фотографии каталога не менять, новые изделия не создавать.

Первый шаг: проверить реальные изображения/координаты/подписи в PDF, отсеять логотипы, QR, печати и технические элементы; построить доказанный план «страница/рисунок → исходная строка → ID позиции». При неоднозначности не назначать картинку автоматически. Проверить существующие `POST /photos/upload`, `POST /incomes/:id/photos` и использование фото в карточке/печати. Прямую запись выполняет только access через api.sh после проверки плана координатором.

Требования к реализации Пульта: анализ/предпросмотр без записи, явный проверяемый список изображений и позиций перед отправкой; идемпотентный повтор после сбоев и защита чужих фото/контуров/версий; исходный PDF и sourceLine не изменяются. Точный UX/зона и архитектура фиксируются перед кодом. Слепое правило «N-я картинка = N-я строка» запрещено.

## Решение и зона исполнителя

Принят [ARCH-PLAN.md](ARCH-PLAN.md), ограниченный single-writer путь без изменения backend/API. Один GET photos, только оригиналы без parentPhotoId/удаления; reuse подтверждается байтами, неизвестный upload с пустым recovery останавливает повтор. Нельзя обещать глобальную exactly-once/атомарный перенос позиции. Текущее backfill выполняет access отдельно через API по [manifest.json](manifest.json), 8 уникальных файлов и 9 связей.

Worker tooling: `tools/document-intake/images.mjs`, новый внутренний PDF-extractor Python и их тесты; `tools/document-intake/index.mjs` только export; `pult/document-intake.mjs` только новые защищённые actions; новый `pult/ui/document-intake-images.js` и точечное подключение в document-intake.js; `pult/server.mjs` только static mapping нового UI-модуля; `pult/ui/style.css` только при нехватке существующих классов; `pult/catalog.mjs` только NOT_ON_BUTTONS для внутренних утилит. Backend/PWA и чужие изменения не трогать. Применить datacore-design, текущие компоненты/панель без нового языка интерфейса.

UI: кнопка «Рисунки…» у существующей строки PDF → imagesprepare с arrivalId/revision → миниатюры и исходные строки/номер договора/предупреждение о низком разрешении в существующем отчёте → явное «Загрузить рисунки» с confirmationId. JWT — только текущий tokenProvider, сессии в файлы не писать. Preview data URLs только разрешённых image/png|jpeg, лимиты размера/количества, текст только через DOM textContent. Анализ не делает POST к сайту; отправка проверяет выбранный контур/актора/версию/хеш плана заново.

Извлечение: защищённый getReviewOriginal, SHA исходника, нативные изображения без upscaling; bbox рисунка + точный код SKU текстовой ячейки, строго единственное совпадение. Логотипы/QR/штампы не назначать. Несколько картинок в одной строке/неразличимые коды/нет доказанной строки → понятное замечание. Поддержку нового формата не угадывать.

Привязка к сайту: искать единственный действующий договор с legal.documents sourceSha256 данного PDF, далее неизменные sourceLine/rowKey/SKU/qty/title; уже загруженный через другой аккаунт исходник не загружать повторно. Существующие фотографии сохранить. Stable originalFilename как у backfill: `dcimg-<fullDocSHA>-<fullAssetSHA>.<ext>` (ASCII, не rowID); один asset может иметь несколько lineID. Локальный journal на PDF/asset с сохранением uploadStarted до POST и photoID до addToSet. После неизвестного исхода нельзя повторять upload вслепую. Перед/после attach проверить родителя и источник строки; не менять главное фото/каталог/документы.

Проверки исполнителя: prepare без POST, source mismatch/actor/contour/stale hash, 8 assets→9 links и reuse двух строк, original/variants, unknown upload recovery/no recovery, duplicate originals, повтор attach и сохранение прежних фотографий; Pult action/token/revision и UI preview/confirm. Отчёт C239/IMPLEMENTATION.md, не коммитить и не выкладывать. Независимые QA/визуальная приёмка после freeze.

Приёмка: после догрузки перечитать позиции и файлы, проверить соответствие, размеры/хеши по допустимому формату, сохранность всех прежних фото и документов, отсутствие новых товаров/заказов/платежей. Проверить повтор без дублей и отображение картинок в позициях/печатном листе. Реальные записи ограничены подтверждёнными картинками данного КП; другие документы проверяются на копии/обезличенном наборе.
