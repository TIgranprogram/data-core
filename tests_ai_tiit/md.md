# PLM AI Copilot с серверной оркестрацией

## Идея

Это рабочая архитектурная схема: **AI-агент с инструментами и серверной оркестрацией** (`tool-using AI agent / agentic workflow`).

Для PLM-проекта точное название может быть таким:

> **PLM AI Copilot с серверным набором инструментов, оркестрацией сценариев и панелью управления.**

Также подходят термины:

- AI-платформа с tool calling;
- агентная система;
- оркестрация инструментов;
- backend-driven AI;
- AI copilot для PLM;
- операционная панель агента / control plane;
- semantic layer.

## Как работает система

```text
Пользователь или ИИ
        ↓
Пульт управления / чат / API
        ↓
Оркестратор сценариев
        ↓
Серверные инструменты и скрипты
        ↓
PLM-база, документы, ERP, CAD, Excel
        ↓
Структурированные результаты
        ↓
ИИ выполняет аналитику и формирует ответ
```

Пользователь может нажать кнопку «Проверить структуру изделия». Серверный сценарий:

1. получает номер изделия;
2. извлекает текущую BOM;
3. находит предыдущую версию;
4. сравнивает состав;
5. проверяет отсутствующие атрибуты;
6. выявляет незакрытые изменения;
7. проверяет связанные документы;
8. возвращает ИИ компактный структурированный результат.

Пример результата:

```json
{
  "product": "ABC-100",
  "current_revision": "C",
  "previous_revision": "B",
  "added_components": 12,
  "removed_components": 3,
  "missing_attributes": 5,
  "open_change_orders": 2,
  "risk_level": "medium",
  "issues": [
    "У компонента X отсутствует материал",
    "Изменение ECO-204 не прошло финальное согласование"
  ]
}
```

ИИ получает не весь архив, а точечные данные и формирует аналитический вывод.

## Почему это экономит токены

Большие объёмы работы выполняются обычными программами и базами данных:

- SQL-запросами;
- Python-скриптами;
- ETL-процессами;
- правилами валидации;
- сравнением версий;
- поиском по индексам;
- вычислением статистики;
- проверкой связей в графе данных.

ИИ получает только необходимые данные, найденные отклонения, агрегаты, короткие выдержки и результаты расчётов.

Это называется **предварительная детерминированная обработка данных** или **pre-computation**. Модель не заменяет базу данных и не должна выполнять работу SQL-движка. Она выступает как интеллектуальный слой, который:

- понимает запрос пользователя;
- выбирает нужный инструмент;
- интерпретирует результаты;
- объясняет выводы;
- предлагает следующие действия.

## Что такое пульт управления

### Пульт для человека

Веб-интерфейс с кнопками:

- Проверить BOM;
- Сверить версии;
- Найти незакрытые изменения;
- Проверить комплектность документации;
- Найти риски проекта;
- Сформировать предложение;
- Сравнить клиента с типовыми проектами.

Возможные названия: **операционная панель**, **dashboard**, **control panel**, **cockpit**, **workbench**, **PLM command center**.

### Пульт для ИИ

Внутренний набор функций, которые модель вызывает через API:

```text
get_product_structure()
compare_revisions()
find_open_changes()
validate_document_set()
calculate_implementation_scope()
generate_offer_data()
```

Такой набор называется **tool registry**, **набор инструментов агента**, **function calling API** или **agent tools**.

Лучше, чтобы человек и ИИ использовали одни и те же серверные функции: кнопка в интерфейсе и команда ИИ тогда запускают одну и ту же проверенную операцию.

## Разделение функций

### Детерминированный уровень

Выполняет операции, где ответ должен быть точным:

- поиск;
- фильтрация;
- сортировка;
- расчёты;
- сравнение;
- проверка обязательных полей;
- контроль версий;
- проверка сроков;
- формирование агрегатов.

Здесь следует использовать код, SQL и правила, а не ИИ.

### Интеллектуальный уровень

Выполняет задачи, где требуется понимание:

- классификация требований;
- интерпретация ТЗ;
- объяснение рисков;
- сопоставление потребностей клиента с возможностями PLM;
- подготовка предложения;
- формирование вопросов;
- аналитический вывод.

### Уровень управления

Определяет:

- какой сценарий запустить;
- какие инструменты разрешены;
- какие параметры передать;
- нужно ли подтверждение человека;
- можно ли изменить данные;
- как записать результат в журнал.

## Пример для PLM-проекта

Запрос пользователя:

> «Подготовь предложение для клиента, у которого 15 000 изделий, много изменений и отсутствует единый контроль документации».

ИИ вызывает серверные функции:

```text
analyze_customer_profile()
count_products()
analyze_change_orders()
check_document_completeness()
estimate_migration_volume()
calculate_implementation_scope()
find_matching_case_studies()
```

Сервер возвращает структурированные результаты. Затем ИИ формирует:

- описание текущей ситуации;
- выявленные проблемы;
- предлагаемую PLM-архитектуру;
- состав модулей;
- этапы внедрения;
- предварительные трудозатраты;
- список допущений;
- вопросы для клиента;
- коммерческое предложение по шаблону.

Это также можно назвать **Server-augmented AI** — ИИ, усиленный серверными вычислениями и корпоративными данными.

## Рекомендуемая структура проекта

```text
plm-ai/
├── control-panel/       # кнопки и интерфейс
├── agent-api/           # связь с языковой моделью
├── orchestrator/        # сценарии и маршрутизация
├── tools/               # серверные функции
│   ├── bom_tools/
│   ├── revision_tools/
│   ├── change_tools/
│   ├── document_tools/
│   └── proposal_tools/
├── data-connectors/     # PLM, ERP, CAD, Excel, документы
├── rules-engine/        # точные проверки и бизнес-правила
├── knowledge-base/      # проверенные материалы
├── audit-log/           # журнал действий
└── evaluation/          # тестирование качества
```

## Главный принцип

> **ИИ не ищет всё сам. Он понимает задачу, вызывает точечные серверные инструменты, получает структурированные данные и делает аналитический вывод.**

Это дешевле по токенам, быстрее, точнее и безопаснее, чем заставлять модель каждый раз самостоятельно просматривать всю базу документов.

## Как реализовать самообучение

Самообучение лучше реализовать не через бесконтрольное изменение самой модели, а через постепенное улучшение:

- библиотеки серверных инструментов;
- бизнес-правил;
- схем данных;
- шаблонов;
- базы подтверждённых примеров;
- маршрутов выполнения;
- специализированных PLM-модулей.

Так система будет становиться сильнее, но останется управляемой и проверяемой.
