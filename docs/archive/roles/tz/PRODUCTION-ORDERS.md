# ТЗ: Объединённый заказ производства (договоры с одним «№ заказа»)

Класс L · агентов ≤ 4 (backend → frontend → qa) · решения пользователя 28.10.2026 · совет opus — ниже.

## Суть
`salesorders` = **договор** (`orderNo` — «№ договора»). `productionNo` («№ заказа», вид N-ГГ) объединяет договоры: все договоры с одинаковым `productionNo` (в пределах `deletedAt: null`) — **один заказ**. Договор без № — отдельный «заказ, нет №». Позиции — `incomes` (orderId → договор, `lineNo` — № внутри договора; **не трогать и не перенумеровывать**).

## Решения пользователя
1. Список «Заказы» — одна строка на заказ (объединённый); договоры без № — по одному.
2. В карточке заказа позиции сгруппированы по договорам (заголовок группы: «Договор 109-П · заказчик · этап · срок»). Порядок договоров — по дате входа в заказ (новые — в конец).
3. **Сквозной № позиции** по заказу (1..N: договоры по порядку входа, внутри — по lineNo). Используется **везде**: экран, код позиции «21-26-5» (бронь/выдача/подписи склада, проектирование, паспорт). Вычисляется на сервере, в БД не хранится.
4. Блок **«К производству»**: одинаковые позиции всех договоров суммируются (ключ `productId`; нет — нормализованное название (trim, нижний регистр, пробелы, ё→е) + `unit`; разные unit не складывать). Для запуска в работу: «все лавочки по заказу такому-то». Только просмотр; строка показывает, из каких позиций (сквозные №) собрана.
5. Этап/срок: у каждого договора свои (правятся в договоре). В заказе: срок — самый ранний из договоров (красный, если просрочен), этап — самый отстающий, при расхождении пометка «разные этапы» и список по договорам. Кнопка следующего этапа в заказе — **«ко всем договорам»** с подтверждением (меняет только договоры, отстающие от целевого).
6. Убрать договор из заказа (очистить/сменить productionNo) **нельзя**, если по нему есть выдачи со склада (`stockmovements.salesOrderId`, не отменённые) или отгрузки (`shipments.orderId`) — 409 «Договор уже в работе: есть выдачи/отгрузки».
7. Номер договора — справка: в группе карточки, в истории.

## Сервер (datacore-backend) — `backend/src/modules/salesorders/`
- Поле `productionAddedAt?: Date` в `sales-order.schema.ts`; ставить при установке/смене `productionNo` (create/update), снимать при очистке. Порядок договоров: `productionAddedAt ?? createdAt`, затем `_id`.
- Индекс `{ productionNo: 1, deletedAt: 1 }` + строка в `backend/scripts/ensure-indexes.js` (MODELS, если нужно).
- Правило 6 в update.
- `GET /api/production-orders` — список `{items,total,page,limit,counts}`; агрегация `$match` (те же фильтры, что list(): filter active/done по этапу договора, search, companyId) → `$group` по ключу `productionNo || _id` → поля: `key`, `productionNo|null`, `orderIds[]`, `orderNos[]` (по порядку входа), `customers[]` (уникальные), `companyNames[]`, `lineCount`, `amount`/`paidAmount` (только `canMoney`, как в list), `deadline` (самый ранний shipDate→productionDeadline→deliveryDeadline), `stage` (отстающий по порядку ORDER_STAGES), `stagesDiffer`, `priority` (самый срочный). Сортировки: `productionNo` (год, затем N числом, без № в конце — как в list()), `deadline`, `customer`, `-createdAt`. Счётчики этапов — по объединённым. Роли/@AppSection — как у salesorders. Логику положить в отдельный файл `production-orders.ts` (чистые функции: порядок договоров, сквозная нумерация, суммирование «К производству», этап/срок) + юнит-тесты.
- `GET /api/production-orders/:key` (key = productionNo или id договора без №) — `{ key, productionNo, orders: [карточка договора как сейчас card() — шапка + lines с полем seqNo], toProduce: [{ key, productId, title, unit, qty, seqNos[] }], deadline, stage, stagesDiffer }`.
- `POST /api/production-orders/:key/stage { stage }` — этап всем отстающим договорам (через существующую смену этапа договора, с историей).
- Сквозной № в `lines-lookup` (`seqNo`, `productionNo`) и в `lookup?lines=1`; `lineCode` на клиенте = `productionNo-seqNo`, нет productionNo — `orderNo-lineNo`.
- Номер отгрузки: при общем productionNo номера договоров совпадут → формат `ОТГ-<productionNo>-<orderNo>-<seq>`, без productionNo — `ОТГ-<orderNo>-<seq>` (старые номера не трогать).
- `design-present.ts` — заголовок задачи «Чертежи <арт> № 21-26 поз <seqNo>»; паспорт из очереди — №позиции сквозной, если есть productionNo (посмотреть `product-passport/passport-queue.ts`).
- Не ломать `/api/salesorders` (контракт). Обновить `docs/MAP.md`, перегенерировать `docs/openapi.json` (skill datacore-verify §).
- Проверки: `npx tsc --noEmit`, `npx jest --silent`, e2e новые в `test/e2e/production-orders.e2e-spec.ts` (2 договора с одним №, сквозная нумерация, суммирование, запрет снятия при выдаче, этап «ко всем»).

## Экран (datacore-frontend) — `backend/pwa/sections/salesorders.js`, `ui/target-picker.js`
- Раздел «Заказы»: список — с `/production-orders` (строка: «№ 21-26» / «нет №», заказчики, договоры «109-П, 110-П» мелко, поз., срок, этап (+ «разные»), сумма). Открытие → карточка заказа (`/production-orders/:key`): шапка (№, срок, этап, кнопка этапа «ко всем договорам»), блок «К производству» (таблица: №, изделие, кол-во, ед., из позиций), затем группы по договорам — существующий вид позиций договора, № позиции = сквозной. Кнопки договора (отгрузить, позиция, спецификация, отменить) — в заголовке группы договора.
- Создание: «+ Договор» с полем «№ заказа» (подсказка-список существующих № в работе + «Взять свободный №»).
- Правка договора — прежняя форма договора (открыть из группы).
- `lineCode` = `${productionNo}-${seqNo}` при наличии.
