# ТЗ SK-7a — состав изделия копится из выдач (сервер)

**Зачем (словами пользователя):** что выдали со склада под позицию заказа с изделием — предлагается в состав изделия, человек подтверждает; себестоимость — по ценам закупки.

**Роли:** backend ☑ · frontend — SK-7b (после)

## Что сделать (решение — `docs/roles/tz/SKLAD.md` §8 «Состав из выдач»; правила — «Аналитика SK-2» §4; критерии §6 SK-7; решения СК-1, СК-2, СК-3)
1. `GET /api/stock/composition-suggest?salesOrderLineId=` → позиция заказа, изделие (`incomes.productId`; нет изделия → пустое предложение с причиной), по каждому материалу: нетто выдач под позицию (функция `common/issued-net.ts` — уже есть) ÷ количество изделий в позиции = на одно изделие; текущее значение в составе изделия; разница (добавить / изменить / совпадает); цена из последней закупки (как в коде уже считают «последнюю цену», сверить) — только canSeeMoney (MoneyMask).
2. `POST /api/stock/composition-suggest/accept` `{salesOrderLineId, materialIds?}` → пишет в состав изделия через существующий сервис состава (`products.composition`, CompositionLineService — сверить); повтор не удваивает (пересчёт от суммы выдач, СК-2); ничего не удаляет из состава.
3. Предложение не хранится — каждый раз считается заново. Новый `stock/stock-composition.service.ts`. Права: чтение — как у склада, запись — как правка изделия.
4. Юнит: деление на количество, возврат и отмена, повтор accept, позиция без изделия. openapi (вручную), MAP.

## Критерии приёмки
- [ ] Выдали 20 кг под позицию с 4 изделиями → предложение 5 кг на изделие; возврат 4 кг → 4 кг; отменённое не считается.
- [ ] accept дважды — значение то же, не 2×.
- [ ] Цены — только деньговым ролям.
- [ ] `products` (общая с CRM) — схему не ломать, только необязательные поля.
- [ ] `npx tsc --noEmit` = 0; jest затронутых модулей зелёный.

## Нельзя
- Писать в состав без явного accept; удалять строки состава; данные прода.
