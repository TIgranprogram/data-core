# ТЗ KP-1 — Коммерческие предложения, этап 1: сохранение, статусы, PDF с фонами

**Класс:** L · backend + frontend параллельно · затем designer · **Проверки:** backend — `npx tsc --noEmit` 0, юнит, e2e offers; frontend — `node --input-type=module --check < файл`.
Источник: `docs/audit/AUDIT-KP.md` §4–6 (этап 1). Ответы пользователя по умолчанию (`docs/QUESTIONS.md` КП): «Оплачено» вручную; старые КП CRM не переносим; подпись и печать — в фоне; фоны — выбор из загруженных.
Не делаем на этапе 1: заказ из КП (этап 2), перетаскивание блоков (этап 3), версии/дубликат/НДС-скидка (этап 4).

## Данные — новая коллекция `commercialoffers` (НЕ `quotations` — это CRM)
`number` (счётчик `CommercialOffer`, префикс «КП», как в `showcase.service.ts:512`), `date`, `validUntil`, `companyId` (наша компания), `customer` (текст) + `counterpartyId?`, `title?`, `status` `draft|sent|accepted|paid|rejected|cancelled` (по умолч. draft), `items[]` {`productId?`, `productName`*, `productSku?`, `description?`, `color?`, `size?`, `photoUrl?`, `quantity`*, `unit` (по умолч. «шт»), `unitPrice?`, `total`}, `total`, `prepaymentPercent?`, `productionDays?`, `deliveryDays?`, `terms?` (текст), `notes?`, `bg1Id?`, `bg2Id?` (фоны), `orderId?` (на этап 2), `statusHistory[] {status, at, by}`, мягкое удаление (как у других core-моделей).
Переходы: `draft→sent→accepted→paid`; `rejected|cancelled` из любого, кроме `paid`; `sent` требует цену у каждой строки. `paid` — правка запрещена (400 по-русски).

## Backend (исполнитель datacore-backend)
- Новый модуль `backend/src/modules/offers/` по skill `datacore-new-module`: `offer.schema.ts`, `offers.service.ts`, `offers.controller.ts`, `dto.ts`, `offer-pdf.ts`, spec-и. Регистрация: `app.module.ts`, реестр `collections-admin.controller.ts`, `common/app-sections.ts` — секция `{ id: 'offers', label: 'КП' }`, права как у `salesorders` (admin/manager; чтение — у кого секция).
- API `/api/offers`: `GET` (`{items,total,page,limit}`, фильтр `status`, `q` по номеру/заказчику, `sort=-date`, в ответе `counts` по статусам), `GET :id`, `POST`, `PATCH :id`, `DELETE :id` (мягко), `POST :id/status {status}`, `GET :id/pdf` (`application/pdf`, `Content-Disposition` имя `КП-<номер>.pdf`, через RFC 5987 для кириллицы), `GET /offers/backgrounds`, `POST /offers/backgrounds` (multipart png/jpg ≤ 5 МБ, имя, `page: 1|2`), `DELETE /offers/backgrounds/:id`. Фоны — своя маленькая коллекция `offerbackgrounds` {name, page, file, isDefault}; файлы — как фото в uploads (смотри, как сделано у фото изделий).
- Стартовые фоны: скопировать `D:\kppdf\kppdf-8.0\data\from-kp3\media\kp\kp-1str.png` и `kp-2str.png` в `backend/assets/offers/` (в git). Если в `offerbackgrounds` пусто — встроенные считаются фонами по умолчанию (страница 1 / страница 2+), без сида в БД.
- PDF `offer-pdf.ts` — pdfkit по образцу `shipments/shipment-pdf.ts` (шрифты `fontDir()`; для текста КП можно обычный шрифт, если есть, иначе тот же). А4 595.28×841.89. Фон 1 — на стр. 1, фон 2 — на стр. 2+ (нет фона 2 — белая). Фон вписывать в А4 целиком; PNG 2.6 МБ — перед вставкой перекодировать в JPEG (sharp, q≈82, кэш в памяти по id), чтобы PDF был лёгким.
  Безопасные зоны (доля высоты): стр. 1 — текст от 20 % до 72 %; стр. 2+ — от 4 % до 70 %. Таблицу и текст за зоны не выводить.
  Порядок на стр. 1: «№ КП-… от дд.мм.гггг», «Для: <заказчик>», «Действительно до …», таблица (№, Фото — если есть, Наименование + арт./цвет/размер, Кол-во, Ед., Цена, Сумма), «Итого», условия (предоплата %, срок изготовления/доставки дн., `terms`), примечание.
  Таблица переносится: строка не разрывается, на новой странице повтор заголовка; «Итого» не остаётся одно (перенести с последней строкой). Фото строки — из `photoUrl` (uploads; нет файла — без фото, без ошибки).
- Тесты: юнит — переходы статусов, расчёт `total`, разбивка строк по страницам (40 строк → ≥ 3 стр., ничего ниже нижней зоны) — вынеси расчёт раскладки в чистую функцию; e2e `test/e2e/offers.e2e-spec.ts` — CRUD, статус, 400 на `sent` без цены, PDF отдаёт `%PDF`.
- `POST /showcase/kp` не трогать (обратная совместимость).
- Доки: `docs/MAP.md` (строка модуля), `docs/data-model.md` (коллекции). openapi перегенерирует координатор.
- Не трогать: `backend/pwa/**`, коллекции CRM.

## Frontend (исполнитель datacore-frontend, skill `datacore-design`)
- Новый раздел `backend/pwa/sections/offers.js` — «КП» в меню (`main.js`: NAV, группа «Продукция» рядом с «Продукция», SEC_OF `offers: 'products'`, загрузчик). Список: № КП, дата, заказчик, сумма, статус (чип), фильтр-чипы по статусам со счётчиками, поиск. Пусто — «КП ещё нет. Добавьте изделия из «Продукции» кнопкой «В КП» или нажмите «+ КП»».
- Карточка/форма — правая панель (CANON: ввод только справа). Поля со `*` (через `required` в `ui/form.js`): наша компания, заказчик, дата, срок действия, строки (название*, кол-во*, ед., цена, цвет, размер). Ещё: предоплата %, срок изготовления, срок доставки, условия, примечание, выбор фона стр. 1 и стр. 2 (список с сервера, по умолчанию встроенные).
- Кнопки: «Сохранить», «Скачать PDF» (`GET /offers/:id/pdf`, через существующий способ скачивания файлов с токеном), смена статуса словами: «Отправлено клиенту», «Принято клиентом», «Оплачено», «Отклонено», «Отменить КП» (подтверждение). Статусы на экране — по-русски: Черновик, Отправлено, Принято, Оплачено, Отклонено, Отменено.
- `sections/kp.js`: корзина «В КП» из «Продукции» остаётся, но «Сформировать» теперь создаёт КП на сервере (`POST /offers`), очищает корзину и открывает его в правой панели. Старая печать HTML — убрать (мёртвый код не оставлять), если сервер ответил; старый сервер без `/offers` (404) — оставить прежнюю печать.
- `help-flow-data.js` — шаг «КП» (как сделать КП, как скачать PDF). CSS — только новые классы `.of-*`.
- Не трогать: `backend/src/**`.

## Приёмка
- [ ] КП создаётся, сохраняется, видно в списке со статусом; без обязательных полей не сохраняется, поле подсвечено.
- [ ] PDF — А4, фон 1 на стр. 1, фон 2 на стр. 2+; 40 строк — таблица на нескольких страницах, ничего не наезжает на подпись и печать.
- [ ] «Отправлено» без цены — понятная ошибка; «Оплачено» — правка закрыта.
- [ ] Проверки зелёные. Не коммитить. Отчёт ≤ 10 строк.
