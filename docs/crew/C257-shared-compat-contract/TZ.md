# ТЗ C257 — Контракт совместимости shared с CRM

**Программа:** [BEYOND](../C246-architecture-modularity/BEYOND-CHECKLIST.md) · после желательно C254  
**Зачем:** гарантии владения ограничены data-core; нужен явный контракт полей/запретов, чтобы фичи не ломали CRM и наоборот.  
**Класс:** M · **Код:** документация + лёгкие тесты/сверка схем; **не** перевод CRM на API  
**Старт:** можно черновик контракта параллельно с C251–C254 (только docs); тесты — после C254 или по готовности слоя

## Что сделать
1. Список shared-коллекций (materials, storageitems, stockmovements, reservations, warehouses, supplyrequests).
2. Файл контракта (например `docs/crew/C257-shared-compat-contract/CONTRACT.md`): обязательные поля, что data-core не удаляет/не переименовывает без синхрона с kppdf, запреты.
3. По возможности — автоматическая сверка ключевых полей схемы data-core vs зафиксированный список (без чтения секретов kppdf).
4. Ссылка из ARCHITECTURE «Единая база» и LOCKS L-257.

## Критерии
- [ ] CONTRACT.md принят координатором
- [ ] есть способ проверить «не сломали совместимость» одной командой или чек-листом в CONTRACT
- [ ] CRM→API не начат

## Нельзя
- Править код kppdf.
- Менять схемы shared «для красоты».
