# C156 — «Работа» и «Разработка» на двух компьютерах

19.11.2026. Класс L: локальная инфраструктура, пульт и обозначение тестового окружения. Максимум три субагента одновременно. Сервер Synology не изменять, выкладку и миграцию не выполнять.

## Выбранная схема (зафиксирована до реализации)

**Работа:** открывать существующий проверенный сайт `https://kppdf-crm.ru/db/app/`. Интерфейс, API и файлы одного origin, актуальные рабочие данные только в главной Synology. Локальные файлы/ветка/незакоммиченное этот интерфейс не меняют. Локальный стабильный фронтенд к удалённому API не создавать.

**Разработка:** текущая папка/ветка запускается существующими owned-инструментами `tools/night*.mjs` на `http://localhost:3102/app/`, с отдельными БД/томами/сетью. При запуске пересобрать backend из текущего кода, сохранить имеющуюся копию; PWA/admin — bind текущей папки. Если подходящей копии нет, явно сообщить, не подключаться к рабочей БД. Обновление данных — отдельная существующая операция восстановления копии, без молчаливой подмены среды. Показать постоянное «Разработка · копия данных от …» на локальном экране.

**Передача:** Git хранит код и документацию. Проверить branch/dirty/origin перед началом; готовое — проверки/commit/push; WIP — отдельная опубликованная codex/wip-ветка только своих безопасных файлов, запись ветки/остатка в BACKLOG. Пароли/локальные настройки/БД/uploads не переносить Git. На втором ПК действия выполняются существующими кнопками Git, без автоматического слияния или stash чужих изменений.

## Границы и роли

- Координатор: схема, источники, docs, приёмка, Git. Не читает секреты и не входит в API.
- Инвентаризатор: tools/night*, pult, Git-инструменты, compose; только INVENTORY.md, не паспортный код.
- Инфраструктурный исполнитель после инвентаризации: конкретные tools/pult/compose, принадлежащие C156; не backend/src и не passport UI.
- Исполнитель отметки разработки: только bootstrap/core PWA и штатные компоненты; не паспортные файлы и не инфраструктура. Точный scope назначается после инвентаризации.
- Access: единственный вход, только api.sh; прод только GET, тестовые изменения только изолированная копия.
- Проверяющие: QA инструментов и изоляции; дизайнер для нового видимого элемента. Полный аудит одних файлов повторно не запускать.

В репозитории работают другие роли. Чужие изменения не откатывать. Новых агентов исполнителям не создавать.
