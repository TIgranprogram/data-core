# ТЗ C249 — Граница finance ↔ supply + fontDir

**Программа:** [C246/CHECKLIST](../C246-architecture-modularity/CHECKLIST.md) · этап 3  
**Зачем:** finance импортирует частные файлы `supply/*.ts`; `fontDir` сиротой тянет чужие модули к паспортам/печати.  
**Класс:** M · **Зависит:** желательно C248 · **Проверки:** tsc + юнит finance/supply/print-затронутых

## Что сделать
1. Список импортов `finance` → `supply/*` (кроме публичного сервиса при DI).
2. Нужное общее (суммы счетов и т.п.) — чистая функция в `common/` **или** метод `SupplyService` через Nest DI. Доменные правила снабжения — у `supply`.
3. Прямых импортов файлов из `supply/` в `finance` = 0 (кроме `SupplyModule`/`SupplyService`).
4. **`fontDir`:** вынести путь/резолвер шрифтов в `common/print` (или существующий print-хелпер). Импортеры паспортов/PDF — только оттуда. Не класть бизнес-правила паспортов в `common/`.
5. Ответы календаря и смысл печати без изменения.

## Критерии
- [ ] Grep частных импортов `supply/` из finance — 0
- [ ] Grep `fontDir` вне `common/print` (определение) — 0; потребители импортируют из common
- [ ] tsc + юнит зелёные
- [ ] REPORT: таблица «было → стало»

## Нельзя
- Резать весь supply.service «заодно».
- Складывать правила финансов/паспортов в `common/`.
