# C165 · атомарный приход с новой позицией

При приёмке заявки без `materialId` сервер вызывает `stock.createItem` до транзакции движения. Ошибка записи движения, изменение привязки заявки или статуса счёта после этого вызова оставляет в каталоге материал и ячейку с нулём. Повтор по имени может скрыть след первого отказа. Случай указан в [TASKS](../../TASKS.md).

Владелец кода — backend, стык `supply` → публичный фасад `stock` принимает архитектор. QA проверяет HTTP на отдельной MongoDB 4.4. Область — `supply.service.ts`, `stock.service.ts`, `stock-catalog.service.ts` и регрессии цепочки снабжения. Транзакция переиспользует складскую блокировку имени и действующую проверку связей заявки и счёта. Правила прямой поставки, приёмки из существующей карточки, финансового замка, C265 и совместимости с CRM сохраняются. Общие схемы Mongo остаются прежними.

- [x] HTTP 500 на базе `05941614` оставил одну карточку после управляемого отказа вставки движения. Исправленный кандидат подтвердил откат каталога, ячейки, заявки и границы счёта.
- [x] Материал, ячейка, движение и заявка используют одну транзакцию. Проверка нового материала и повторное применение области проходят в ней же. QR создаётся после успешного commit.
- [x] Повтор после отказа, повтор старой части, две одновременные приёмки, поздняя привязка счёта, полный и частичный приход проверены. Чужой сохранённый ключ получает `409` до изменения заявки, остатка или артикула. Своё движение идентифицируется по заявке, материалу и ключу.
