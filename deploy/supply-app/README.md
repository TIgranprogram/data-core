# Веб-приложение «Снабжение / Склад» и переход с Google-таблиц

**Адрес:** `https://kppdf-crm.ru/db/app/` — открывается на ПК и телефоне, ставится иконкой («Установить приложение» в браузере / «На экран Домой»). Код — [`backend/pwa/`](../../backend/pwa/) (vanilla JS, без сборки), отдаётся самим backend по `/app/`.

| Экран | Что умеет |
|--|--|
| Снабжение | заявки: поиск, фильтр по статусу, создание и правка, фото с камеры, «Оприходовать» (приход на склад + статус «☑️ Получено») |
| Склад | позиции: остаток / в брони / свободно, приход, бронь, снятие брони, списание, корректировка, фото, история движений |

- **Вход** — логином сотрудника. Учётки заводит администратор: админка → «Пользователи» → роль **manager** (фото может загружать только admin/manager).
- **Офлайн:** без сети приложение открывается из кэша, изменения копятся в очереди («в очереди: N») и досылаются сами при появлении связи. Дублей не будет — у каждой записи свой `uid`.
- **Остатки** считаются из журнала движений (`warehouse/movements`), а не хранятся числом.

## Данные

| Коллекция | Что |
|--|--|
| `/api/apps/supply/requests` | заявки снабжения |
| `/api/apps/warehouse/items` | позиции склада (ТМЦ); `fromMovements: true` — остаток только из движений |
| `/api/apps/warehouse/movements` | движения: `in` приход, `reserve` бронь, `unreserve` снятие брони, `out` списание, `adjust` корректировка, `opening` начальный остаток |

## Переход «сразу при запуске» (делается один раз)

1. **Последняя синхронизация из таблиц.** В каждой таблице: меню **🔗 База данных → Синхронизировать сейчас**. После этого в таблицы больше не вводим.
2. **Перенос остатков в движения** (ключ: админка → «API-ключи», «Чтение и запись», приложение `warehouse`; после перехода ключ отозвать):
   ```bash
   DATACORE_KEY=kppd_… node deploy/supply-app/cutover.js --base https://kppdf-crm.ru/db/api
   DATACORE_KEY=kppd_… node deploy/supply-app/cutover.js --base https://kppdf-crm.ru/db/api --apply
   ```
   Первая команда только показывает план. Скрипт идёт ~90 запросов в минуту (лимит API — 100), 250 позиций ≈ 6 минут. Повторный запуск безопасен: уже перенесённое пропускается.
3. **Таблицы — в зеркало.** В каждой таблице: **🔗 База данных → Режим: база → таблица**. Теперь каждые 10 минут скрипт пишет листы «Снабжение (база)», «Склад (база)», «Движение склада (база)» — только для чтения и отчётов; исходные листы скрипт не трогает и в базу больше не отправляет.
4. **Сотрудники работают в `https://kppdf-crm.ru/db/app/`.**

Откат: **Режим: таблица → база** в меню — таблица снова главная (но изменения, сделанные в приложении, в исходные листы не вернутся; их видно на листах «… (база)»).

## Проверено (локальный контур, 2026-10-18, копия реальных данных: 157 заявок, 242 позиции)

Приложение: заявка → оприходование → бронь → списание (50 → 45 / 20 / 25), фото с превью; офлайн при остановленном сервере — после восстановления ровно 1 заявка, 1 позиция, 1 движение; мобильный вид; service worker в Edge: 8 файлов в кэше, перезагрузка без сети. Переход: 208 начальных остатков, дублей 0, повтор — 0 изменений. Зеркало: 159 / 244 / 93 строк, остатки из движений совпадают с приложением.
