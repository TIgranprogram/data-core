# C089-Карта — интерактивное устройство рабочего места

Статус: готово к выполнению после C092 и текущего выпуска. Класс L-UI, max agents 3, review loops2.
Пользовательский результат: человек открывает «? → Работа с сайтом», выбирает область, видит связи и переходит к делу без длинной инструкции.

## Основа и границы
Читать AGENTS, CANON, DESIGN/skill, UI-ACCEPTANCE; точечно help.js, help-guide-data.js, help-product-map.js, ui/kit/guide.js. Связи сверить по PRODUCT/MAP и C057 CONTRACT, не придумывать по рисунку.
Существующая схема изделия — основа, не отдельный второй справочник. Сайт и бизнес-данные не дублировать, новую библиотеку/фреймворк не добавлять.
Владение: backend/pwa/sections/help*, общий guide kit при необходимости, тесты и документы этого этапа. Home/Сегодня, сервер, PDM-импорт и другие формы не менять.

## Поведение
1. Первый уровень — крупные понятные области из действующего меню/прав роли: заказы, продукция/состав, проектирование, снабжение/склад, производство/отгрузка, деньги/документы. Число видимых узлов ограничивать, подробности внутри.
2. Клик/Enter на области открывает её процессы; следующий клик — карточку конкретного процесса. Крошки и «Назад» сохраняют понятный путь, без бесконечной вложенности.
3. Карточка процесса: зачем нужен; откуда данные; что человеку заполнить; что подставляется; куда идёт результат; одно главное доступное действие.
4. Связи показываются для выбранного узла. Hover может подсвечивать, но клик/клавиатура/касание дают тот же результат. Не показывать общую паутину всех стрелок одновременно.
5. Длинные описания — в деталях. Краткая подпись и направление связи понятны без цвета. Данные сущности хранятся в одном месте, карта показывает ссылку и назначение.
6. Переходы используют реальные существующие маршруты и права. Нет доступа — понятное объяснение, не неработающая кнопка. Не обещать ещё не реализованные функции как действующие.
7. На 390px — последовательные уровни/список связей без горизонтального скролла; на широком — упорядоченная схема. Масштабирование не должно быть обязательным для чтения.

## До кода
Аналитик сверяет компактную таблицу узлов: id, родитель, название, вход, выход, маршрут, права, источник истины. Сохраняет MAP-CONTRACT.md здесь. Это ограниченная проверка бизнес-связей, не новый аудит всего репозитория.
Разработчик использует guide/kit, сначала один эталон на существующем пути «Заказ → распределение → проектирование». После приёмки распространяет по таблице.

## Приёмка
- Менеджер и директор видят допустимые разделы; запрещённые данные не раскрываются.
- Из карты доступны заказ, изделие, паспорт и склад существующими маршрутами.
- Проверены три уровня, крошки/возврат, клавиатура, touch-sized targets, длинные подписи и пустые/недоступные связи.
- Обе темы,390/1024/1920, открытая правая панель. Нет вертикальных букв/пересечений стрелок с текстом; контраст по DESIGN.
- Сценарные тесты графа проверяют отсутствующие ссылки/циклы вложенности, не копируют реализацию CSS.
- Приёмка дизайнера по UI-ACCEPTANCE с заполненными состояниями. Проверки по DESIGN-WORKFLOW без второго полного прогона тем же кодом.
- Отчёт MAP-REPORT.md: PASS/FAIL/PARTIAL, снимки/сценарии, незакрытые пункты. Коммит только своих файлов, выкладка координатором после готовности.

Не трогать текущий выпуск и чужие изменения: отдельный worktree, совместить общие kit-изменения с координатором.
