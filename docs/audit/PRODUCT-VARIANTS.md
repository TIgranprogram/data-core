# Варианты изделия — аудит (analyst, 2026-11-01)

Запрос пользователя: менеджер не создаёт новые изделия случайно; «чуть другое» = вариант того же изделия (цвет, длина, ширина), свой артикул и параметры; вариант получают клоном.

## Что есть сейчас
- Изделие — `products` (общая с CRM), схема `backend/src/common/catalog/product.schema.ts:23–75`. `sku` уникален в организации (:75). Есть `copiedFromProductId` (:49), `dimensions`, `ralCode`, `weightKg`.
- `series` — поле только data-core, CRM его не читает (`showcase.service.ts:56–57`); фильтр и фасет по серии (:125–152). Это ближе всего к «семейству», но смысл — коммерческая серия, не «вариант».
- Клон: `POST /showcase/:id/clone` (`showcase.controller.ts:159–163`, `showcase-clone.ts`). Копирует поля, фото, состав, `passportDefaults`; имя «… (копия)», артикул — следующий в группе. **`copiedFromProductId` клон НЕ ставит** — связь с исходным теряется.
- Артикул группы: номер группы `categories.groupNo` + 2 знака (`showcase-sku.ts`), до 99 на группу. У варианта своего вида артикула (`3404.2`) нет.
- Менеджер в заказе (`pwa/sections/order-lines.js:15,38,118,133`): поиск в «Продукции»; не нашёл — тип «Новое изделие» → заявка проектировщику (`product-requests`), он привязывает к существующему или создаёт. Это уже защита.
- Дыра: сопоставление позиций заказа (`salesorders-matching.js:75–78`) — кнопка создаёт изделие сразу по названию строки, без проверки «похожее есть».
- Кнопки в карточке (`products.js:163,171`): «Присвоить артикул группы», «Клонировать».

## Данные (стенд-копия datacore-night)
- Изделий 480; с серией 4 (одна серия «CHOICE SHADOW»); клонов 0; заявок на новое изделие 0.
- Одинаковых названий 27, в них 72 изделия («Качели» ×10, «Урна» ×6, «Игровой комплекс» ×5, «Скамья» ×3). Это кандидаты в семейства вариантов (или дубли — решать по артикулу/размерам).

## Чего нет
- Связи «вариант → основное изделие» и списка вариантов в карточке.
- Подсказки «похожее уже есть» при создании изделия.
- Выбора варианта при добавлении позиции в заказ.

## Предложение (минимально, без поломки CRM)
- Новое необязательное поле `products.baseProductId` (ObjectId, только data-core, как `series`). CRM лишнее поле не мешает. Пусто — изделие основное; задано — вариант. Варианты одного уровня (у варианта нет своих вариантов).
- Клон «Сделать вариант» = текущий клон + `baseProductId` (= основное исходного) + `copiedFromProductId`; имя без «(копия)», а «<имя> — <что отличается>»; артикул — `<артикул основного>.<n>` (как задумано в DESIGN-DISCUSSION: `3404.2`). Уникальность `sku` сохраняется.
- Паспорт: вариант при клоне получает копию `passportDefaults` (уже так). Наследование «вживую» не делать в первом шаге: копия проще, CRM и печать не меняются. Отличия (размеры, цвет, вес) правятся в варианте.
- Менеджер: поиск изделия → у найденного список вариантов (основное + варианты, с размерами/цветом) → выбрать; нет нужного — «Сделать вариант» (клон, правка параметров в правой панели). «Новое изделие» остаётся только через заявку проектировщику.
- Подсказка «похожее уже есть»: при создании изделия и в сопоставлении — поиск по словам названия (`tokensFilter`), показать до 5 совпадений с кнопками «Взять» / «Сделать вариант».
