## Доставка обновления запасного сервера

Два задания обновления остались queued и завершились таймаутом. Точечное чтение, отдельно разрешённое владельцем, выявило причину: `/var/lib/datacore/switch` принадлежала root и имела1777. Служба UID1000 не могла удалить завершённый root-owned request. Защищённая outbox правильно отказалась затирать чужую заявку.

Владелец разрешил единственное изменение владельца этой папки. Скрипт сверил точный mount/канонический путь, отсутствие симлинков/current, взял flock и сопоставил request/last-id. Выполнен только нерекурсивный chown1000:1000;1777 сохранён. База, файлы документов и настройки защиты не менялись.

На время согласованного импорта расписания приостановлены штатным CAS: revision0→1. Исходный график сохранён: данные каждые15мин включены, код выключен. После отмены ручного импорта соседним координатором разрешено восстановление исходного графика через expectedRevision1. Восстановление выполнено штатным API: revision2, данные каждые15мин включены, код выключен; ближайшее nextData11:24:56МСК. Независимый GET и реальное автоматическое задание проверяются отдельно.

Урок: sticky1777 не заменяет правильного владельца каталога. Установщик должен согласовать владельца со службой; нельзя исправлять проблему chmod777, рекурсивным chown или удалением неизвестного request. Статус «мост жив» не доказывает доставку задания.
