## Что сделать
**Ч1. Таблица «Тексты этого изделия»** — последний блок шаблона (после «Эксплуатация и гарантия»/«Другие тексты»):
- Строки: каждый текст, который войдёт в паспорт этого изделия и НЕ является общим текстом «Для всех» из кода: выбранные/подставленные варианты воронки (раздел → вариант → текст) и тексты элементов. Колонки: Раздел · Текст (2 строки, «Развернуть») · действия «Изменить» / «Убрать из паспорта» / «Вернуть».
- «Изменить» — свой текст только для этого изделия (правка справочника не нужна, справочник не меняется); «Убрать» — раздел не печатается у этого изделия. Хранить в `products.passportDefaults` (новое необязательное поле, например `textOverrides: { [id раздела]: { text?: string, off?: true } }`) — схема изделия общая с CRM? Проверь `docs/ARCHITECTURE.md` «Единая база»: поле только добавляется, CRM его не читает.
- Сборка паспорта (`buildV2Text`) учитывает переопределения: свой текст вместо варианта; «убрано» — раздел не выводится. Выданные паспорта не меняются (у них снимок).
- Только эталоны kit (`table`, `button`, `section`); ввод — в правой панели (это уже правая панель шаблона).
**Ч2. Один номер на изделие в договоре**
- Сейчас разберись: что происходит при повторной печати/выпуске паспорта по той же позиции договора — новый номер? Опиши в отчёте 3–5 строк.
- Правило: позиция договора (`incomeId`) + изделие (`productId`) → один номер. Повторный выпуск/перепечатка берёт номер уже выданного паспорта этой пары (новый номер не расходуется). Количество > 1 в позиции — оставить как есть сейчас (если сейчас на каждую штуку свой номер — не ломать; правило «один номер» — на пару позиция+изделие+штука, опиши решение).
- Нумерация «без дыр» (C054) не ломается. Юнит-тест на правило.
