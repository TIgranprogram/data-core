# ТЗ SK-4a — остатки склада: остаток / в брони / свободно (сервер)

**Зачем (словами пользователя):** открыл склад — сразу видно, сколько есть, сколько занято бронью, сколько можно взять; что заканчивается и что в брони — сверху.

**Роли:** backend ☑ · qa ☐ (после) · frontend — следующим ТЗ (SK-4b)

## Что сделать
1. Проверить, что список остатков (`stock/stock-search.service.ts`, маршрут в `stock.controller.ts`) отдаёт у каждой позиции `qty` (остаток), `reserved` (в брони, активные брони), `free` = qty − reserved. Нет — добавить (агрегация одним запросом, не N+1).
2. Необязательные параметры списка: признак «заканчивается» (поле позиции `minQty`/как уже принято в коде — сверить; нет порога — не выдумывать, взять существующее правило «мало»), фильтр/сортировка «сначала заканчивается и в брони». Если у запроса есть DTO с whitelist — новые поля сразу в DTO; старые клиенты не должны получить 400 (AGENTS «ловушки»).
3. История позиции: последние 5 движений по позиции — проверить, есть ли маршрут (`stock-movements`), если нет — параметр `limit` у существующего списка движений по позиции.
4. Юнит на расчёт `free` и сортировку. openapi (`docs/openapi.json` — перегенерировать по skill `datacore-verify`), `docs/MAP.md`.

## Критерии приёмки
- [ ] В ответе списка остатков у позиции есть `qty`, `reserved`, `free`; `qty = reserved + free` (при брони больше остатка — `free` = 0, не минус).
- [ ] Сортировка/фильтр «заканчивается и в брони — сверху» работает; без параметров ответ как раньше.
- [ ] Последние 5 движений позиции доступны одним запросом.
- [ ] `npx tsc --noEmit` = 0, `npx jest src/modules/stock` зелёный.
